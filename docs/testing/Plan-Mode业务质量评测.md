# Plan Mode 业务质量评测与上线门禁

Plan Mode 的代码链路已加入证据保留、计划绑定、冲突提问和结果警告，但这些机制不能证明外部模型在任意领域都理解正确。上线前必须在真实 Provider 的测试环境完成本页自动回归，并由两名评审检查同一轮运行的合成样例输出。Mock 测试只验证确定性逻辑，不计作真实模型质量通过。

## 当前确定性保障

- `PlanningSessionService` 从安全上下文中抽取最多 20 张明确事实卡片，每条证据最多 220 字符，保留来源路径、事实类别和来源类型（项目源码/用户材料）；受保护路径、凭据和含提示注入语句的内容不会成为卡片。超出卡片上限和摘要覆盖范围会形成警告。
- 同一份事实卡片随用户、计划 ID 和上下文版本绑定。最终生成再次检索文件时，仍将计划阶段那份卡片交给 Provider 和结果组装器，避免答案变化造成事实证据漂移；用户确认答案单独标注且优先。
- `PlanQuestionFilter` 根据明确标签和事实类别过滤常见的重复问题，冲突值、复合问题、变更选择或主题不吻合的问题会保留。过滤采用保守的规则匹配，不宣称能判定任意中文问题的语义相关性。
- 相同材料字段出现互相矛盾的显式值时，服务器将其转成计划必问项；最终二次检索发现的服务器歧义会与 Provider 返回合并，即使 Provider 返回空数组也不会被清除。
- 最终响应提供独立的 `warnings`，前端显示上下文覆盖和解析提醒；受保护路径或疑似凭据不会通过这个字段输出。

当前冲突检测能可靠覆盖“同名显式字段、不同取值”这类情况。比如代码配置与业务文档用完全不同措辞表达的语义冲突，仍需真实模型评测和人工确认，不能仅靠字符串规则证明。

## 在测试环境运行真实 Provider 评测

使用隔离的测试 API 和专用测试账号。评测只提交脚本内置的合成输入，不扫描本机目录，也不读取本机密钥或生产配置。不要把账号凭据写进脚本、文档或命令历史：

```powershell
$env:PLAN_EVAL_BASE_URL = 'http://127.0.0.1:9000'
$env:PLAN_EVAL_EMAIL = '<测试账号邮箱>'
$env:PLAN_EVAL_PASSWORD = Read-Host '测试账号密码' -MaskInput
node scripts/plan-quality-eval.mjs
```

脚本使用平台部署配置的默认 Provider/模型，在登录后依次调用上下文准备、Plan 和最终优化接口。普通模式只打印每个样例的实际 Provider/模型、问题数量、已知事实重复数、必问遗漏数、无关问题数、同类重复数、模板正确性、最终事实缺失数和延迟，不打印提示词、文件正文、用户回答或凭据。出现接口错误、使用 Mock Provider 或任一断言失败时，退出码非零。

样例涵盖：软件代码与订单方案混合输入、科研数据字典已知事实、科研地区缺失、教育、商业分析、写作、运营、法律写作、软件任务附带研究文档、跨文件审批阈值冲突，以及完整翻译任务不应多问。自动门槛为：无已知事实重复、无明显离题问题、无重复确认维度、必问项不遗漏、关键事实出现在最终提示词、冲突在 Plan 中可见、模板符合主要目标，且需求完整时不额外发问。

为评审外部模型实际输出，可在同一测试环境运行：

```powershell
node scripts/plan-quality-eval.mjs --review
```

`--review` 会额外打印这些合成用例对应的问题和最终提示词，输出会对常见凭据格式做脱敏；只应用该模式检查脚本固定的合成样例，不要改成真实用户材料。

## 生产放行门禁

发布候选版本必须在目标 Provider 和目标模型上运行：

```powershell
node scripts/plan-quality-eval.mjs --release
```

`--release` 除要求全部自动断言通过外，还会检查 [`plan-mode-human-review.json`](./plan-mode-human-review.json)：至少两名评审者、评审日期和全部样例的三项结论都必须填写为 `PASS`，分别表示问题相关、事实保真、没有重复询问已知信息。模板初始值为 `PENDING`，不能把未评审记录当作通过。自动与人工任一未完成，发布门禁都失败。

若评审发现问题，应先修复并重新运行同一批样例；不可通过降低断言或直接把评审结果改成 `PASS` 来放行。记录每次模型版本、服务端提交版本、评测日期、自动汇总和评审人。用户取消率与最终再次编辑率需在获得适当同意的产品遥测中持续观察，不能从合成样例推算。

当前仓库没有本次真实 Provider 的执行结果，也没有两名评审完成的质量记录。因此代码级问题已有防护和回归用例，但 Plan Mode 的真实语义准确性上线条件仍是未通过状态。生产上线前不得把本功能标记为已完成验收。
