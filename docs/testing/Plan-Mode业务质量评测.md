## 当前确定性保障

- `PlanningSessionService` 从安全上下文中抽取最多 20 张明确事实卡片，每条证据最多 220 字符，保留来源路径、事实类别和来源类型（项目源码/用户材料）；受保护路径、凭据和含提示注入语句的内容不会成为卡片。超出卡片上限和摘要覆盖范围会形成警告。
- 同一份事实卡片随用户、计划 ID 和上下文版本绑定。最终生成再次检索文件时，仍将计划阶段那份卡片交给 Provider 和结果组装器，避免答案变化造成事实证据漂移；用户确认答案单独标注且优先。
- `PlanQuestionFilter` 根据明确标签和事实类别过滤常见的重复问题，冲突值、复合问题、变更选择或主题不吻合的问题会保留。过滤采用保守的规则匹配，不宣称能判定任意中文问题的语义相关性。
- 相同材料字段出现互相矛盾的显式值时，服务器将其转成计划必问项；最终二次检索发现的服务器歧义会与 Provider 返回合并，即使 Provider 返回空数组也不会被清除。
- 最终响应提供独立的 `warnings`，前端显示上下文覆盖和解析提醒；受保护路径或疑似凭据不会通过这个字段输出。

当前冲突检测主要覆盖“同名显式字段、不同取值”这类情况。2026-10-01 真实验收确认标准选项可以消除旧冲突，但自然语言自定义确认仍可能被重复追问，新增取值也可能与旧值错误配对；不能将字段检测等同于完整的决策解析。不同措辞表达的语义冲突仍需真实模型评测和人工确认。

## 在测试环境运行真实 Provider 评测

优先使用支持当前图形验证码的浏览器入口。先启动本地测试 API 和 Vite 前端，使用专用测试账号；下面的地址必须是前端同源地址，且该入口只允许本地服务。默认 CLI 只提交脚本内置的合成输入，不扫描本机目录，也不读取本机密钥或生产配置：

```powershell
$env:PLAN_EVAL_BASE_URL = 'http://127.0.0.1:5175'
node scripts/plan-business-acceptance.mjs
```

浏览器入口使用临时 Chrome，操作者在页面正常完成登录与验证码，不把账号凭据交给脚本。随后读取平台已发布默认模型，依次调用上下文准备、Plan 和最终优化接口。会产生正常模型用量和优化历史；响应为 Mock 或检查失败时不能计为真实质量通过。终端只打印模型、计数、检查状态、延迟和 Request ID，完整合成输入的脱敏问答与结果保存到每次独立的 `tmp/plan-business-acceptance/<runId>/`，已有证据文件拒绝覆盖。

原 `scripts/plan-quality-eval.mjs` 的 11 个样例与检查函数由浏览器入口复用。该旧脚本的直接登录路径不支持当前图形验证码，不应直接作为现有环境的登录入口，更不能通过关闭验证码来让评测通过。它的原始自动断言保留用于对照，本轮已发现误报和漏报，见下方真实验收记录；布尔检查全部通过也不能自动代表业务正确。

样例涵盖：软件代码与订单方案混合输入、科研数据字典已知事实、科研地区缺失、教育、商业分析、写作、运营、法律写作、软件任务附带研究文档、跨文件审批阈值冲突，以及完整翻译任务不应多问。自动门槛为：无已知事实重复、无明显离题问题、无重复确认维度、必问项不遗漏、关键事实出现在最终提示词、冲突在 Plan 中可见、模板符合主要目标，且需求完整时不额外发问。

评审时读取同一运行目录中各样例的 `plan`、`answers`、`refinedQuery` 和 `final`，并核对 Provider、Request ID 与提交版本。合成样例答案只是验收夹具，不能当成真实用户的业务选择。若另行验收真实项目材料，应控制授权文件范围，详细正文只留本地受控证据，不能直接公开整个临时目录。

## 生产放行门禁

发布候选版本必须在目标 Provider 和目标模型上完成真实运行，并核对同一轮人工评审。仓库原 CLI 保留了以下门禁参数，但其登录入口尚需适配验证码，所以不能将下列命令描述为当前环境已经可直接完成的发布验收：

```powershell
node scripts/plan-quality-eval.mjs --release
```

`--release` 除要求全部自动断言通过外，还会检查 [`plan-mode-human-review.json`](./plan-mode-human-review.json)：至少两名评审者、评审日期和全部样例的三项结论都必须填写为 `PASS`，分别表示问题相关、事实保真、没有重复询问已知信息。模板初始值为 `PENDING`，不能把未评审记录当作通过。自动与人工任一未完成，发布门禁都失败。

若评审发现问题，应先修复并重新运行同一批样例；不可通过降低断言或直接把评审结果改成 `PASS` 来放行。记录每次模型版本、服务端提交版本、评测日期、自动汇总和评审人。用户取消率与最终再次编辑率需在获得适当同意的产品遥测中持续观察，不能从合成样例推算。
