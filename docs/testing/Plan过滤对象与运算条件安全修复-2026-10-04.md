# Plan 过滤对象与运算条件安全修复（2026-10-04）

## 1. 本轮结论与范围

已复现并修复两项确定缺陷：过滤时删除运算符造成不同条件被合并，以及按类别唯一值把甲对象的事实当成乙对象的答案。同时加固提醒归并、问题元信息和常规排版问题的委派边界。

本轮选择 47 个后端测试类：46 类、528 项通过；另一类本机 HTTP 并发测试在 Java 回环连接初始化阶段产生 5 个错误，尚未完成。最后三个定向测试类共 88 项通过。这里不将受阻检查写成通过，也不将离线服务链路检查写成真实外部模型验收。

接口、前端、本地文件索引、数据库模型和迁移均未改动。本轮不增加独立模型调用，不扩大上下文预算，保留现有安全、所有权、受控重试及历史逻辑删除链路。

## 2. 可复现的缺陷

新增 `PlanScopeSafetyRegressionTest` 从实际问题过滤和提醒归并入口复现；首轮 16 项检查中 15 项失败。第二批元信息和提醒反例共 21 项检查中有 5 项失败，随后逐项修复，保留失败记录。

| 场景 | 修复前的错误 | 修复后的行为 |
| --- | --- | --- |
| 金额 `>50000` 与 `<50000`、`>=50000` | 删除标点后被视为相同题目 | 分别保留，交换顺序不改变保留范围 |
| 金额 `=50000` 与 `!=50000` | `!` 被当作普通感叹号删除 | 保留相反条件，不因一个条件确认而消除另一个 |
| 金额 `1.5` 与 `15` | 小数点被删，条件被误合并 | 保留数值差异 |
| 甲医院格式为 CSV，乙医院格式缺失 | DATA_FORMAT 只有一个已知值，于是两题都被过滤 | 继承甲医院事实，只问乙医院 |
| 年龄组已知，城乡分组未知 | 同属 POPULATION，已知值跨属性复用 | 年龄与城乡分别判断 |
| 正文格式已知，附表格式未知 | OUTPUT_FORMAT 唯一值被当作全部交付物答案 | 附表问题继续保留 |
| 基线期间已知，随访期间未知 | TIME_RANGE 唯一值跨阶段复用 | 随访问题继续保留 |
| 同题干的提示新增跨院共享选择 | 只比较题干，整题被去重或按已知格式删除 | 完整元信息不同且有额外选择时保留 |
| 常规提纲题携带未成年人样本选择 | 排版委派只看题干，可能吞掉真实专业选择 | 保留样本问题；纯章节排版仍可委派 |

复现记录在本地 `tmp/plan-scope-safety-20261004/`。仓库内的[回归证据](./evidence/Plan过滤对象与运算条件安全修复-2026-10-04.json)只保存测试名称、计数、代码散列及安全错误类别，不复制 JVM 系统属性、用户资料或凭据。

## 3. 核心代码修改

### 3.1 运算符与提醒比较

- `PlanDecisionIdentity.exactTextKey` 不再删除所有标点。全半角、空白和句末问号可以规范化；比较符、小数点、路径符号及完整数值不能删除。沿用现有文字大小写不敏感的匹配口径，不宣称解决所有区分大小写的代码语义。
- `PlanDecisionIdentity.subject` 与 `PlanAmbiguityMerger.normalize` 保留 `!=` 中的 `!`。
- 最终提醒列表只额外合并排版差异，不用相似度阈值批量删除提醒。该步骤保留大小写，并在既有展示上限之前执行。
- “尚未选定／未决定”等有限未决状态句可以归入同一完整对象的问题；新年份、新对象、新条件及复合子句继续保留。

### 3.2 事实按对象与属性限定

新增内部工具 `PlanningFactScope`，将明确标签中的对象、属性及条件与问题中的范围比较。只有同一范围存在一个明确值、且没有不确定或冲突值时，才继承事实。空范围不能回答命名对象的问题。

来源事实卡片与需求正文统一解析标签和取值，避免把“数据格式：CSV”和裸值“CSV”误当成两种不同取值。对象名中的“标准”“研究”等字样不能被全局删除。没有足够依据识别范围时保留问题。

`PlanQuestionFilter` 的问题身份同时包含题干、问题类型、自定义输入能力、提示、选项标签／说明／答案／推荐依据和填写示例；模型生成的 ID 不作为决定是否重复的依据。额外说明显式引入另一选择时，不因题干已有答案而删掉整题。

### 3.3 常规问题委派边界

维持现有规则：纯章节组织、已要求的伪代码组织和测试工程核查由执行 Agent 处理。先核对完整问题元信息，包含新样本、权限、阈值、超时等实际选择时继续保留；用户主动要求选择章节结构时也继续提问。

扩大回归曾暴露三处兼容问题：地区问法的范围匹配不一致，以及“新增／修改核心逻辑”“不新增业务”等描述错误绕过既定决定。已收窄分支并恢复原有断言；没有修改旧测试预期来获得通过。

## 5. 尚未完成的事项

- 本机 HTTP 检查错误为 `Unable to establish loopback connection`，底层 `UnixDomainSockets.connect0` 抛出 `Invalid argument: connect`。已定位到 Java NIO 初始化阶段，未证明该环境故障的完整根因，也不为通过测试更换核心依赖或修改并发功能。
- 范围匹配仍是有限文字关系，不是通用语义证明。无标签自然语言业务规则保留既有有限主题判断；复杂别名、省略主语、跨句指代及跨行业改写需继续做保留集和专业评审。
- 额外选择无法安全拆分时，可能保留整道复合题；不能用“删掉所有问题”换取零重复。后续应逐决定核对，并量化重复率和误删率。
- 本轮未调用真实外部模型、未做下游作品对照或完整代码＋办公目录验收。模型长尾耗时、跨行业业务质量及双人专业门禁仍按[闭环评测方案](./提示词实际交付质量闭环评测.md)和[待办事项](../待办事项.md)执行。

因此，本轮可以认定上述确定缺陷已完成代码修复及定向回归，不能认定 Plan 整体上线验收完成。
