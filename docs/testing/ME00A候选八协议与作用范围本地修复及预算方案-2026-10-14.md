## 2. 精准归因与本轮修改

| 原件／症状 | 归属及证据 | 定向修复与保留的保护 |
| --- | --- | --- |
| 178 的 `ambiguities` 使用对象数组 | 增强模型违背字符串协议；首次系统指导对字符串与关联对象的区分还不够明确 | 明确非空字符串数组与 `ambiguityReferences` 的对象位置。原件经生产 Provider 回放仍被拒绝，三次预算和非法类型校验保留；没有宽泛转字符串 |
| 五份相同回答各发送一遍状态、委托与边界 | 平台请求组装重复，未充分区分拟议设计委托和既有参数未确认 | 模型执行表述 20→4，仅合并自身命名且完全相同的独立表述；保留全部 `sourceQuestionIds`。全部五份原回答和五个 `UNRESOLVED` 状态仍在服务端；模型投影新增 `designDelegated`，只表示可提拟议设计，不确认取值或授权 |
| 179 已要求方法部分正文，仍因“方法与空表”拒绝 | 平台局部交付校验误拒绝。原件直接驱动 `DraftDeliveryContract` 可复现 | 只在实质方法正文已成立、同一方法部分并列交付空表且无禁正文要求时允许；仅交空表、方法提纲或方案，以及“不提供正文”仍拒绝。此修复不使整份 179 响应自动合法 |
| 180 的专业缺口同时成为需用户先答的问题 | 模型响应矛盾，重复／模糊的请求状态可能诱发，不能唯一归咎下游 | 将委托与未确认分开表达；`ASSESSMENT_DECISION_CONFLICT`、合法枚举、缺口实质字段及独立重要未知保护保留。实际原件仍被生产校验回放拒绝，没有删问题或伪造 USER_DECISION |
| 两名评审分歧题省略“评分”后反复提问 | 平台同对象委托识别遗漏 | 在有委托依据时接受同一评审的完整题干；新条件、独立研究／新增指标，以及 hint、选项、示例中的资料和授权选择继续保留 |
| 182 将提示词与对应产物写为二选一 | 歧义首先出现在增强原件，平台此前继续传播；不能归为纯下游能力问题 | 从当前肯定研究主题或同对象有效确认取得评价来源，指导落实实际评分对象；已明确只评价提示词时拒绝替换为产物。明确双对象、独立主题、引用／未来研究和有效改选分别处理，不扩大为所有研究默认评价提示词 |
| 禁虚构被跨子句误判为禁例 | 平台 `ExampleContract` 的否定匹配跨分号；新组合输入在调用模型前即可复现 | 禁令与请求按对应子句识别；禁虚构示例限制资料性质，不能直接取消真实／符号示例。原文明确禁例和格式冲突仍优先；“其他／额外数据”的禁止继续约束新示例 |
| 工具空跑、失败原件丢失或空作品当完成 | 评测工具错误／风险 | 题号必须完整命中冻结输入；失败 HTTP 和非 JSON 正文保留，空作品及截断记未完成。新增 `compliance` 轨只验证复制正文的约束合规，不伪称原始／增强收益对照 |

新增模型元数据只服务内部请求，不进入最终正文；`sourceQuestionIds` 与 `designDelegated` 纳入现有协议名泄漏校验，用户明确要求解释对应字段的场景继续允许。敏感值检测、受保护路径、动态约束和确认范围有相应回归，权限、工作区、逻辑删除与历史路径未移除。

专业设计补全目前只确认委托状态、来源与可实施建议指导已经传递；类别、评分尺度、分歧规则及统计条件是否在真实作品中充分落实，仍需下一阶段核验。根因归属和策略采用遵循[主方案第 6.3.1 节](../14-提示词增强与Plan最小干预优化方案.md#attribution-and-strategy-evaluation)，不为单个下游失败叠加长指令。
