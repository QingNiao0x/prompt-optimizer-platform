## 数据保护与复现

`AnalyticsLocalDatabaseAcceptanceTest` 每个用例创建随机租户、普通账户、管理员账户、工作区及身份；密码在运行时生成并通过生产 PasswordEncoder 哈希，不写入文档或日志。初始化管理员和用户密码的 ApplicationRunner 被替换，防止测试事务启动前改动已有账户。

所有测试写入都在同线程事务内，结束后回滚；`@AfterTransaction` 检查测试租户、账户、身份、工作区、成员、优化会话、优化记录和审计事件均没有残留。测试专用 SQL 仅放在 `src/test/resources/mapper/analytics`，不进入生产包。运行前需已初始化本地数据库；缺少表或字段时应报错，不自动迁移。

在 `services/api` 执行：


不在命令行传入或输出数据库密码；沿用本地已有的安全配置。此命令不适用于生产库。

在 `apps/web` 执行：

## 核查内容

| 场景 | 验证内容 |
| --- | --- |
| 完整业务链路 | 登录 → 两次页面访问 → 准备上下文 → 创建 Plan → 确认并增强 → 复制结果 → 退出；普通账户准确产生 8 条事件 |
| 上下文绑定 | 准备上下文、Plan 与最终增强保持相同原始提示词和项目描述，使用服务端返回的 contextId、版本和 planId |
| 统计一致性 | 访问次数为 2，去重访问、活跃、实际使用和注册账户数各为 1，关键操作排行为 4，操作日志总数为 8 |
| 日期边界 | 今日、昨日、本周、本月、上月、自定义；上海时区、包含结束日期、数据库查询左闭右开；边界前后 1 微秒与闰日 |
| 去重与空日 | 同一账户多次访问累计 PV，UV 去重；日均活跃包含零活跃日期；无匹配账户返回零 |
| 筛选和分页 | 账户与事件过滤；两页记录不重复、总数与页数一致；非法日期、倒序日期、UUID、事件、页码和页容量返回 400 |
| 真实权限 | 未登录 401；普通用户 403；管理员登录后被撤权或禁用，旧会话也不能访问三个管理员统计接口 |
| 来源与安全 | 审计事件包含 requestId、设备、IP 和独立登录关联 ID；客户端不能伪造服务端业务事件或他人身份，不信任未配置代理的转发头 |
| 敏感数据 | 不记录原始提示词、测试密码、认证 Session ID 或 CSRF Token；测试失败时不自动打印登录请求正文 |
| 浏览器回归 | 宽屏、平板、手机、长文本、空数据、多记录、深浅主题、日期选择、分页与首页；设置页宽度保持原值 |

这里的“提交优化”沿用已有业务口径：在增强编排执行前记录提交事件，不能解释为“模型成功完成次数”。关键操作不包含登录、退出和页面访问，因此 8 条操作日志与 4 次关键操作并不矛盾。月度使用图沿用最近 12 个月口径，不等同于顶部日期筛选范围。

## 本次发现和修复

1. **未提交的筛选草稿串入分页和排行请求。** 以前用户修改账号或事件类型后，即使没有点击查询，翻页也会读取新输入，导致概览和明细属于不同条件。现在只有概览查询成功后才保存已生效筛选快照；分页和排行使用该快照。查询失败继续保留原快照。
2. **旧明细请求可能覆盖新查询结果。** 为日志和排行分别增加请求序号，新查询使旧响应失效，避免旧账号数据晚到后覆盖当前页面。
3. **部分查询失败容易被看作无数据。** 日志和排行分别显示错误状态，保留成功的概览，并可通过重新查询恢复。

上述修复仅调整前端请求状态和失败展示；后端生产代码、接口字段及统计 SQL 未作修改。

- `AnalyticsLocalDatabaseAcceptanceTest` 同时显式关闭投递，继续禁止自动迁移、替换启动初始化器并核查事务回滚。
