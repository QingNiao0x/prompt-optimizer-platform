# 统计页面密度、模型来源与联系方式回归

## 本轮范围

本轮实现三项后台优化：紧凑指标卡片、素材/文章模型调用分类、排行与关键操作日志的当前联系方式。不扩展访客审计、业务事件口径或充值功能，不执行数据库迁移和生产部署。

## 实现与数据口径

### 指标卡片

- `AdminAnalyticsPage.vue` 的五张账号摘要在宽屏同排展示，活跃账号不再占两列导致平均日活落到下一行。
- 功能指标按宽度使用 5/4/3/2/1 列，桌面卡片最小高度 118px、手机 112px，说明文字与大数允许自然换行，不用省略或固定高度隐藏指标口径。
- 沿用当前主题变量、Element Plus 控件、加载/错误/空状态；联系方式增加后的宽表格在内部横向滚动，所有屏宽提示完整字段的查看方式。
- 修正原页面仍提及“仅访问日期”“登录、访问”的过期说明，页面访问继续不采集、不保存、不统计。

### 模型调用对账

根因在 `ModelCallAnalyticsMapper.xml`：采集端和应用服务已支持 `image.analyze`、`image.plan`、`image.generate`、`text.polish`、`context.vision`，但 SQL 安全投影只保留旧五类操作，新增操作被归入 `unknown`。不是只有提示词优化发起过模型调用，也不是需要新增浏览器埋点。

- `ModelCallObservation.operations()` 提供采集、管理员筛选与 SQL 共用的不可变操作代码表；SQL 逐项使用 `#{}` 参数绑定，不允许正文或任意外部代码进入投影。
- 按操作/来源的 Token 排行、调用明细及其计数继续共用同一筛选与投影。失败响应已经报告的有效 Token 不回滚，未知用量不伪装为零，Mock/明确未发送的调用继续不进入消耗排行。
- 排行在按操作分组时显示业务模块、中文名称及原始 operation；按模型来源分组时不猜测其唯一业务模块。明细始终显示模块和 operation。
- 素材操作归入“素材转提示词”，`text.polish` 归入“文章祛AI味”，上下文调用独立标记，未知记录显示“未分类／未知操作”。
- 已保存真实 operation 的旧记录会在查询时恢复分类，无需修改原始审计数据；原始字段本身已是 unknown 或未采集的调用无法倒推。
- 请求级成功率仍仅归并 `prompt.optimize` 与 `plan.generate`，页面明确说明这一范围；没有将其他工具的并行调用套用为顺序修复流程。

### 账号联系方式

现有 `GET /api/v1/admin/analytics/usage-ranking` 与 `/operations` 的每行在 `displayName` 后增加 `phone`、`email`，字符串或 null。前端对应表格在显示名称后展示手机号、邮箱；null、缺字段、空白统一显示“未绑定”。

- 从 `user_identity` 当前 `local`、`ACTIVE` 绑定读取 `normalized_identifier`，多绑定按创建时间及主键选首个，与账号设置读取规则一致。
- 已撤销身份、第三方资料邮箱、旧账号邮箱副本、已逻辑删除账号的联系方式不作为当前绑定返回。
- 采用标量投影而非展开身份 JOIN，避免多邮箱使排行操作数、日志条数和分页重复。账号筛选、排序及统计口径保持原有规则。
- 联系方式表示查询时的当前绑定，不是事件发生时快照；只供管理员业务查询，不复制进审计事件、模型对账或指标标签。
- 权限继续经过管理员服务与 Spring Security，未登录 401、普通账号 403。
