## 2. 修复内容与功能保护

| 路径 | 实现 | 保留的边界 |
| --- | --- | --- |
| 直接增强、Plan 确认、历史再次增强 | 结果组装通过 `enhanceValidated` 进入真实 Provider 的有限修复流程 | 四要素、待确认事项、凭据、已确认答案和平台约束继续校验；最终成功后才保存一次历史 |
| Plan 生成 | 完整校验问题、选项和推荐理由后，执行原有推荐证据校准，再检查至多一个推荐 | 不删除合法候选答案，不自动替用户选择；重复 ID、过量、超长及敏感内容仍拒绝 |
| 修复预算 | OpenAI 兼容适配器的解析与应用校验合计最多三次调用 | 同一选定模型及路由；网络、429、鉴权与不可预期异常不新增自动重试；不叠加 Plan 外层重试 |
| 不可模型修复的错误 | 服务端固定冲突证据、元数据与确认决定缺失不重复调用模型 | 继续失败并保留稳定错误语义，不伪造成功 |
| 诊断与用量 | 固定原因码与代码字段路径进入安全日志及修复提示；业务校验拒绝时保留已知 Token 用量 | 不把被拒绝的正文、真实凭据或用户文件内容写入诊断日志；未知用量不估算 |
| 明确规则保留 | 用户明确要求时，从相关正式文档或用户资料保留同句代号、业务含义、适用条件和来源 | 支持“代号表示规则”和“规则；规则代号为 X”；不跨句拼接，不从代号推算数字，维持直接 4 条、Plan 20 卡预算 |
| 资料相关性 | 新的明确规则保留路径只按业务正文匹配任务 | 文件名或摘要相关不能提升正文无关的规则；代码、示例、夹具、指令及疑似凭据不提升为规则 |

既有接口字段、权限红线、Plan 所有权和快照绑定、租户/工作区隔离、逻辑删除、模型选择与前端交互沿用原路径。本次没有数据库迁移、依赖升级或前端生产代码修改。

## 5. 额外质量发现与结论边界

本轮修复保护了既有能力和校验，但不能把接口及所列规则检查通过解释为所有生成内容均正确。冒烟人工抽查还发现两项现有质量缺口，未在本次修改范围内扩大修复：

1. Pro 文档 Plan 确认 sample 2（响应 `f09433c4-3d15-4cee-975d-7704f0581d66.json`）完整保留用户“缺失具体条件继续待确认”的回答，却返回 `ambiguities=[]`。迟到处置与志愿者同步方式仅剩泛化提醒，具体未决列表覆盖不足。没有证据可将其唯一归因于模型遗漏或既有提醒归并；相关归并逻辑本次没有修改。
2. 同一样本的活动方案被原有模板关键词规则选择为 `BUG_FIX`；模型未提供验收段落时，组装器补入软件故障验收句。来源为 `PromptTemplateRegistryImpl` 的“失败提示/异常”匹配和原有默认验收补全。本次没有修改这些逻辑；Flash 同类样本虽然也是该模板，但模型自己返回了正确活动验收清单。

这些发现与本次修复的因果关系未证实，保留为额外质量证据，不能据此宣称正式上线语义验收已经通过。

单次 HTTP 连接/读取超时继续有效；覆盖上下文处理和全部修复的端到端总截止时间仍未实现，慢响应加修复在理论上仍可能超过浏览器 70 秒窗口。本轮实测延迟单独记录，不作为所有时段的保证。本测试也没有覆盖长期持续负载、多应用实例完整 HTTP 负载、全部模型路由、所有上传格式或所有业务领域。
