# 文章祛AI味单次策略与交互改进

日期为2026年11月9日。本轮覆盖用户提供的数字化文章、三种文体、两种改写幅度和独立文章工作台。

## 对照原件

原始截图、原文及三份辅助转录、仓库v3指导快照和哈希位于 [证据目录](./evidence/text-polish-v4-2026-11-09/baseline.json)。截图是本次用户输出的原件。转录依据截图可见文字及差异重建，空格和标点可能有偏差，精确比较须回到截图或获取历史记录的实际JSON。

截图可确认文体标签分别为自然流畅、轻松交流、正式清晰，显示模型为DeepSeek-V4.1-Flash，显示来源为基于原文。高级设置处于折叠状态。实际depth、modelId、供应商routeKey、upstreamModel、温度、requestId、来源模式及运行指令版本均缺少请求证据，baseline.json保留null。

仓库基线为text-polish-v3，默认幅度LIGHT、默认温度0.2，实际输出Token上限取min(8000,配置值)。这些配置默认值不能替代截图运行值。本次未访问生产环境或读取用户私有历史来猜测绑定关系。

## 实现与采用状态

TextPolishInstructions保留v3原文，并提供text-polish-v4候选。候选按所选文体和幅度组合指导，区分逐字保护、语义保护和可调整表达，明确段内拆句、重复含义合并及抽象表述改写，加入商务、通知和叙事示例。示例与真实材料明确分开，允许保留已自然的正文。

OpenAiTextPolishProvider在正常请求入口选择指导。通过Spring配置 `app.text-polish.strategy-version=text-polish-v4` 可定向启用候选，缺省仍选v3，未知版本在Spring注入阶段失败。启动日志记录实际选择的版本。运行配置应在验收服务启动前固定，正在运行的操作不动态切版本。

本轮没有真实模型调用。依照仓库正文策略采用规则，v4当前只完成工程实现，尚未证明实际作品收益，默认继续v3。原有JSON正文契约、服务端身份/来源绑定、历史、模型目录和保真检查继续由原链路执行。

页面将改写幅度移至常显位置，说明两种幅度含义，在结果摘要中显示结果实际使用的幅度。默认仍为LIGHT。差异展示先按句子和换行对齐，再细化到Unicode字符片段，保持空白、换行和完整文本。全次LCS共享500000格预算，超出预算对剩余区间展示块差异，限制长文计算成本。

## 验证入口

后端命令在services/api执行，使用Java21和仓库Maven设置。

```powershell
mvn -s ../../.mvn/settings.xml '-Dtest=OpenAiTextPolishProviderTest,TextPolishServiceTest,TextPolishModelServiceTest,TextPolishControllerSecurityTest' test -q
```

前端命令在apps/web执行。

```powershell
npm test -- src/features/textpolish/diff.test.ts src/stores/textPolish.test.ts
npm run build
$env:PROMPT_OPTIMIZER_E2E_PORT='5187'
npm exec playwright test -- text-polish.spec.ts text-polish-history.spec.ts --output=../../tmp/text-polish-v4-browser --reporter=list
```

后端定向18项通过，包含候选三文体×两幅度的6个受控HTTP请求。前端单测19项通过，包含正文无损重建、空文本、空白、Unicode、长文预算和词级修改。生产构建通过，有现有Rollup注释和chunk大小警告。浏览器22个不同用例最终均通过，覆盖桌面和窄屏。首轮18通过、4失败，历史复制用例因关闭按钮已中文化而定位失败，新用例先遇到下拉框标签歧义、随后遇到Element Plus隐藏输入层拦截点击。历史2项修正为当前中文按钮后通过，新用例2项通过下拉框键盘操作和可见单选标签操作后通过。这是定向复跑后的结果，未声称单次全量22项全绿。页面截图已人工检查，无横向溢出。

受控HTTP响应和浏览器API响应使用夹具，仅验证工程链路。它们不证明真实文体质量。首次Maven命令因PowerShell逗号参数解析失败，在给-Dtest参数加引号后执行通过。浏览器夹具未模拟账号设置请求，测试期间出现该接口的本机代理连接错误，文章相关断言已通过。

## 真实作品验证的后续条件

先获取截图对应的实际请求或由用户历史导出核对原件，冻结模型路由、上游模型、温度、幅度及输入。逐项对照v3和v4，先覆盖当前模型三种文体。补充含目的/承诺/条件的正文和本来自然的负对照，检查语义、表达收益和文体兑现。每次只改变指导、幅度或参数中的一个因素。

现有48/50次评测为已结算历史批次，本轮新调用额度尚未明确，不使用旧批次余额。开展新的真实调用前须按仓库预算规则冻结本轮额度，失败、协议修复及付费评审一并计数。真实对照有收益且无新增严重退步后，才决定是否采用v4。用户未要求的第4项留空，本轮未自行扩展为部署或全模型矩阵。
