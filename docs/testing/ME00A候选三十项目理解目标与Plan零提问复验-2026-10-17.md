# 候选三十：项目理解目标与 Plan 零提问复验

本节点解决“先熟悉项目”被识别为开发／重构，继而要求用户提供具体开发功能的问题。用户原题两轮真实 Plan 的**模型原响应均为零问题**，一轮真实页面自动增强和一次独立直接增强成功，复制／历史核对通过。混合开发题仍存在提问必要性缺口，独立增强发生上游读取超时；不能据此宣布所有 Plan、502 或质量门禁通过。

## 1. 范围、价值与已有证据

用户要求以高级全栈 Java 开发工程师身份先熟悉 JeecgBoot 布病系统，已给出 Vue3／TypeScript、Spring Boot3、PostgreSQL（原文 pgsq）、Redis、Maven，以及前后端新旧模块名称和患者治疗修改时须同步的规则。本次没有附件，示例关闭，固定原测试账号。

当前任务是项目理解。技术栈和“重构后的模块”属于用户描述的现状；今后修改须同步是条件规则，不意味着当前要求开发。错误问题迫使用户创造一个未委托的任务，增加输入并可能改变最终交付，因此纳入 ME-01-A／ME-03-A 的任务身份与重要提问修复。

前置只读探针发现：完整原题被识别为 FEATURE_DEVELOPMENT；“JeecgBoot构建的系统”也触发功能开发，“重构后的新模块”触发重构；单独“请熟悉项目”则没有被识别为明确目标。探针不是用户 Plan 原响应的精确回放。此前候选二十九只验证已知框架问题不应在过滤前触发 assessment 冲突，没有验证上述分类与 Plan 提问。

## 2. 代码归因与最小修复

| 路径 | 查明的职责／问题 | 本节点处理 |
| --- | --- | --- |
| PlanningContextController → PlanningSessionService | 准备安全摘要和引用，不生成“具体功能”问题 | 保留原实现；复用安全过滤、所有权与版本检查 |
| TaskIntentResolver | 工程动作正则把“构建的系统”“重构后的模块”当成当前命令，首个错误目标影响任务线索 | 工程动作区分既成状态与未来条件；保留同句后续真正动作；项目阅读识别为有效目标 |
| TaskDeliveryProfile／模板注册中心 | 缺少项目理解画像，错误开发模板会要求实现方案／代码 | 新增内部 PROJECT_UNDERSTANDING，沿用公开 GENERAL；阅读、核对和事实边界替代未委托的开发要求，不强制长报告 |
| Plan 请求组装 | taskIntent 和画像指导进入模型输入 | 复用既有请求链传递正确画像，不增加分类模型或模型调用 |
| PlanQuestionFilter／TaskQuestionScope | 原过滤未完整区分项目理解与开发目标题 | 仅在明确项目理解且无实现目标时过滤要求另给开发功能的问题；检查题干、提示、候选和示例，授权／范围冲突／独立条件／复合问题继续保留 |
| OptimizationPlanningServiceImpl | 非空问题时可能继续展示模型的“没有功能无法开始”摘要 | 确定越界问题被移除后，剩余问题摘要对准当前阅读范围；空题复用已有直接生成流程 |
| 直接增强 assessment 检查 | 共享的越界功能问题若未先排除仍可诱发一致性误拒 | 与 Plan 共用当前任务判断；安全、数量与格式检查仍先执行，不伪造 USER_DECISION |

“先熟悉，再实现登录”保留实际实现目标；明确开发、重构、测试和 requests 隐式代码交付继续使用原路径。没有修改公开模板枚举、Controller 契约、重试次数、敏感值检测、权限、逻辑删除、会话归属或动态约束。

## 5. 复制、历史与实际内容检查

原题一份 Plan 及一份直接结果均保留熟悉项目目标、新旧目录对应与患者治疗修改须同步的条件，没有要求用户先提出具体功能。原始模型响应、平台响应和复制正文分别保存。资料未核实时没有声称已经读完源码；平台本身仍只生成提示词。

第一轮来自真实页面点击 Plan 主按钮并自动增强。复制脚本初版使用错误的按钮名称“复制”，实际可访问名称是“复制提示词”；该工具失败不算产品失败，也未重做增强。补充脚本将**同一份未改动的已保存真实 API 结果**放入现有结果组件后点击正确按钮，读取原生剪贴板。两份正文仅允许 CRLF 换行差异，与 API／同账号历史的正文、sections、ambiguities、appliedConstraints 一致。该补核不冒充完整历史导航恢复或完整编辑 E2E。[原题 Plan 原生复制核验](./evidence/me00a-candidate30-exploration-2026-10-17/results/PROJECT-READ-PLAN-ENHANCE/native-copy-check.json)

账号历史从 1484 增至 1486，仅新增两条成功优化记录；超时不伪造成功历史。没有执行下游实际项目阅读／代码实现，没有新增双独立 AI 评审，不能据此关闭下游作品质量门禁。

仍观察到正文中的通用事实边界、角色与初稿指导等冗余，沿用已有未关闭组装问题，不在本节点扩展追加更多禁令。两轮零问题只能证明冻结题目与 Flash 的本次结果，不能保证任意措辞和所有模型都零问题。
