# 自然增强目标作品优先与通用策略复验

本轮针对“口径与通用规则挤占作品内容”的反馈修改共享生成指导。产品提交为371c8d50：新增NATURAL/3，冻结NATURAL/2；没有新增按职业、具体题目或场景关键词命中的生成分支。查询、消息、PPT和源码只作为冻结的验证样例，不作为产品策略条件。

## 1. 定位与修改

默认自然模式的实际入口为DocumentOptimizationController → NaturalEnhancementService → NaturalPromptProvider，并不调用PromptRewriteStrategy、旧模板或MockPromptEnhancementProvider。因此，单改旧GAP_GUIDANCE不能说明自然模式的症状已修复。

核实后的处理如下：

- 自然指导围绕原始提示词中的动作、对象和目标作品展开，优先沿用范围、格式、篇幅和已提供的具体上下文。补充直接写为可执行要求，常规组织、检索和已委托的方法设计由执行者完成。
- 比较定义及证据要求只用于确实依赖统计计算、数据排名或研究判断的内容，跟随相应判断简要说明。未知实际参数、用户保留选择、授权及真实来源冲突仍按原状态处理。
- Plan共用相同职责边界，保留重要用户决定；不因执行者尚未选择普通组织方式就制造前置问题。没有新增三题上限、按题号删题或猜测填答。
- 参考Mock保留完整任务、使用实际背景的做法，以及EffectiveTaskViewFactory区分原任务、事实、委托和未决的机制；自然Provider继续独立，未接入旧模板组装。
- 旧链GAP补充了背景、任务、输出、约束各自承载具体内容的职责。原RESEARCH_GUIDANCE将某项AI评测的同信息对照、评分和随机化要求带入一般研究任务，现收敛为适用的主题、发现、证据与拟议方法指导；兼容forPrompt入口不再默认追加研究指导。当前任务已有评价对象与有效确认保护仍由既有来源机制负责。
- 框架继续只组织适用信息。自然模式在正文形成后记录参考标记；旧链明确先按任务及上下文写内容，再用框架组织。没有新增框架、职业分类或关键词正则。

上述为公共机制修复。具体哪一句指导导致某次模型输出仍不能仅凭源码确定，本轮真实对照把整份生成指导作为一个受控策略变化，不作逐句因果断言。

## 2. 版本、保护与离线检查

新请求使用NATURAL/3，旧NATURAL/1、NATURAL/2继续使用冻结指导；第二版与上次提交的指导逐字核对一致。第二版起均要求任务理解记录，升级没有放松来源、敏感信息或固定边界校验。历史再次增强按保存的字符串版本分发，编辑、逻辑删除及权限边界保持原行为。

新增V18只维护版本注释，V1—V17未改动，未应用Flyway迁移。前端的chainVersion为字符串，没有新增页面、样式或浏览器端生成策略。

本轮11个受影响Java测试类的最后报告去重合并223项通过，包含新旧版本Provider协议、历史分发、任务与受众保护、模板／框架、自然服务和入口。测试曾复现兼容入口错误注入实验指导；一次旧短语断言不匹配在保留原保护表达后复验通过。策略文字检查不能代替真实语义效果，223项也不是全仓库或完整浏览器验收。
