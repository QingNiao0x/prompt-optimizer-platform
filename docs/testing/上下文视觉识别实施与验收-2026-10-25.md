# 上下文视觉识别实施与验收（2026-10-25）

本次完成 JPEG／PNG 和指定 PDF 页的视觉识别工程实现：本地文字层优先，用户逐页预览、遮挡并同意后，通过已接入的大模型转录，再进入既有临时索引。无需独立 OCR 服务器。限定合成材料的真实链路已验证；不代表通用 OCR、全部模型或正式发布验收通过。

## 实现范围

- `TemporaryDocumentIndexService` 收齐文件后先本地检查，进入 `AWAITING_CONFIRMATION`，等待期间不调用模型、摘要或 Embedding。新请求的 `visionRequested` 不构成外发同意；旧客户端省略时保持本地提取行为。
- `ContextVisualDocumentExtractor` 逐页协调文字层与视觉结果；`ContextPageRasterizer` 使用 PDFBox、共享 EXIF 方向校正和重新编码，在实际外发像素上施加黑色遮挡。PDF 不以原生 Base64 冒充图片。
- `ContextVisionProvider` 与图像创作业务分开，复用平台目录、既有视觉能力登记、服务器密钥、公共 HTTP 并发与 `context.vision` 用量审计。每页一次尝试，无自动重试或隐式供应商切换。
- 转录、表格和模型解释分段标明来源，疑似凭据在索引、摘要、Embedding 之前过滤；临时文档的创建、查询、预览、确认、删除和检索使用服务端用户、租户、工作区范围。
- 未选扫描页、失败页或预算不足均标记遗漏，成功页继续可用；遮挡页不会重新加入原文字层。原件结束清理，审阅期间私有保留，索引沿用 2 小时滑动有效期。
- 前端使用现有 Element Plus、Pinia 与样式变量，提供页码、私有预览、拖动／数字遮挡、共享模型选择及紧邻提交按钮的隐私确认。审阅、上传或识别期间禁止提前分析／生成，避免提交空文件集合。
- 新增 V41 仅更新 `image_prompt_model_capability` 表注释，说明上下文与图像模块共享视觉配置；未回改既有迁移。已在本机数据库应用。

接口扩展：`GET /api/v1/context/documents/vision-models`、`GET /{documentId}/pages/{page}`、`POST /{documentId}/vision`；预览使用身份校验与 `Cache-Control: no-store`。详见[使用与配置](../development/图片与PDF上下文识别使用说明.md)。

## 结果与根因

合成素材包括中文 PNG、JPEG、两页扫描 PDF、文字层＋扫描页的混合 PDF，以及上方含测试代号的遮挡图片。核对采购报告交付物、样本数 128、阈值 27、人工复核、不得删除历史数据，以及纸张／墨盒／文件夹的原始数量和单价。PDF、图片均为自制材料，不包含真实个人信息。

1. **首批**：两款模型的 PNG／JPEG／遮挡图片均可进入索引，遮挡代号未出现。扫描／混合 PDF 的表格页被解析器拒绝，其他成功页和文字层保留为 PARTIAL；“仅本地提取”保留混合 PDF 第一页并明确标记扫描页遗漏，零视觉调用。
2. **协议根因**：实际响应把 `tables` 返回为二维行列数组，数据完整，但原解析器只接受 Markdown 字符串数组。这是协议定义与平台兼容断点，不能据此认定视觉模型不懂表格。修复明确字符串类型，并有限兼容二维原值矩阵；不猜测表头、不补空单元格、不接受任意更深结构。保存的真实合成响应进入离线测试。
3. **修复后**：两款模型各完成扫描 PDF 两页、混合 PDF 扫描页、普通 PNG，共 8 次调用，6 份文件均 READY，指定字段全部出现。混合 PDF 的预算 5000、阈值 27 与视觉表格共同保留。
4. **Plan 与增强**：引用同一份已识别扫描 PDF，充分需求返回零个问题。最终仍交付“写采购报告”的优化提示词，保留 128、27、三项单价、人工复核和不得删除历史数据，不擅自生成报告或改成补材料任务。两个阶段没有新增 `context.vision` 调用。
5. **真实页面竞争**：首次已确认并正确识图，但浏览器在后台索引加入文件集合前可点击分析，提交空列表而返回 EMPTY。原件保留，不计为全流程通过。修复处理期间的按钮及提交校验后，只发送一次识别确认，分析为 COMPLETE，阈值 27 存在，遮挡代号不存在。新增有延迟的桌面／移动测试验证此边界。

候选版本的单次视觉 HTTP 耗时：Flash 6 次为 1139～2230 ms，MiniMax 4 次为 1988～9514 ms；这些是少量合成样本范围，不是稳定 P50／P95 或吞吐承诺。Flash 普通 PNG 使用 862 输入＋105 输出 Token；两页 PDF 单页约 1237 输入，表格页约 181 输出。MiniMax 的单页输入计量明显不同，应按实际端点与材料密度核算费用。没有在本次实现中承诺大模型一定比独立 OCR 更便宜。
