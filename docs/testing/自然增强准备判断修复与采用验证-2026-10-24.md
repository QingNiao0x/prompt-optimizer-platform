# 自然增强准备判断修复与采用验证

本轮按用户要求修正准备阶段判断，停止扩充场景模板。对象为自然增强与自然 Plan；结构化模式、前端、数据库和权限策略不在修改范围。默认仍为 NATURAL/31，候选为36。结果以本轮[决策原件](./evidence/natural-preparation-routing-2026-10-24/decision.json)及阶段记录为准。

## 1. 根因与修复

35及31把 `response.basis != EXPLICIT` 当成是否继续生成正文的开关。保存的科研失败原件已识别五项 CURRENT 动作，却把回应分为 UNSPECIFIED，于是直接构造保留原文的结果。该分类描述是否要求独立成果，不能代表是否有当前动作、是否应增强或执行材料是否齐全。

35又在准备阶段产生资料责任清单，后续必须保留每个 USER_DECISION 或显式纠正；引文存在并不证明该分类正确，容易把任务执行资料变成用户欠缺清单。

36调整如下：

1. 所有合法的动作准备记录均进入正文阶段，不根据 EXPLICIT、INHERENT、UNSPECIFIED 返回原文或关闭生成。充分需求仍允许少改，但不把确定性透传计为补全收益。
2. 只复用原有动作范围准备，不产生35的 dependencies／executionResponsibilities，不维护第二套用户资料责任表。
3. taskScope作为辅助解释保留在输入中，完整原始提示词、项目上下文、对话及全部真实题答仍传递。最终 task 在正文或 Plan 阶段统一形成，服务器不把准备误判覆盖回最终目标或成果。
4. 沿用阶段响应及来源、题答、正文覆盖保护。原始资料缺失的事实、访问禁止和保留决定不因模型分类而撤销；执行者可完成的检索、阅读、梳理、设计不自动转为 Plan 问题。
5. 仅对确实影响执行的未知集中说明待确认事项／需补充材料，限制依赖它的部分；不把增强阶段未见材料断言成现实没有，不把熟悉后等待改成提交文档。

没有职业关键词分支、行业模板、新模型阶段或额外常态审阅。十二框架沿用可选组织参考，不作为路由或质量指标。31、35和旧历史各自的指导及解析不回改；是否切换默认另依质量证据判断。

涉及 `NaturalPromptPreparationRoutingInstructions`、`OpenAiCompatibleNaturalPromptProvider`、`NaturalPromptInstructions`、`NaturalPromptStageInstructions`，以及新增 `NaturalPreparationRoutingProviderTest`。

## 3. 真实验证边界

用户授权“真实评测自行选择次数”，本轮选定新增48次上限：开发24、内部留出24，失败和协议修复均计数，不做质量重试。历史闭批累计1828单列，不重开旧入口、不转旧余额。

先回归旧失败及正常变体，再检查同信息作品；未解决严重退步时不打开内部留出。候选与判据冻结后才能读取封存题目。协议要求作品阶段的原始提示词、31和36使用相同执行材料、模型及参数；复用旧结果时记录原批次、资料、哈希及时间，不冒称本轮重跑。留出作者接触过共同机制与历史失败，属于内部留出，不是外部用户或专业评审。

模型自报通过、字段齐全、篇幅增加和 HTTP 成功都不作为质量提升。候选采用必须有目标错误及实际修改负担下降，且无新增严重意图、事实、授权或硬要求退步；没有达到则保留31。

## 5. 采用结论及剩余边界

**不采用36，默认保持31。** 工程路由修复及受影响验证完成；整体语义质量目标未完成。本轮没有进行生产部署、日常后端重启、提交或推送。

按用户要求先旧案例后新题：由于开发回归出现未解决严重退步，作品执行暂停，内部留出未开启。不读取封存题面、不补跑作品、不通过反复采样挑选成功结果。48次中未用28次在本轮关闭后释放，原件及执行入口锁定；累计实际1848＝历史1828＋本轮20。

因此本轮不能声称降低了用户修改量、改善实际作品或跨场景稳定提升。用户后续仍使用31的既有行为；36的路由修复只存在于候选路径。

定位进一步说明：准备分类不应控制能否生成，这个确定性缺陷已在候选中解除；它不足以修复正文对未见资料的推断和对动作的擅自扩展。准备和正文中的来源引文、Coverage只证明条目可追溯及实际引用存在，不保证所有原始限制都已被识别、语义没有变化。后续若继续，应先审查当前正文指导及最终任务记录为何允许这些变化，复用上述失败原件核查原始要求与新增内容的关系；不能继续盘点每个任务的资料、堆同义禁令、为科研或分页单独加规则。该方向尚未实施或验证，不记为已完成能力。
