# 自然增强需求检查清单

2026-11-14整理，用于后续自然增强的开发和回归。质量判定采用[分层验收规范](../../自然增强分层验收与独立对照规范.md)。

## 材料与来源

[cases.json](./cases.json)是19条案例及逐项检查的维护入口，包含10条用户提供的Qoder案例、5条已有平台合成回归案例、1条用户真实日期反馈及3条开发助手补充的合成案例。全部标记为已见，集合归属为开发或回归。各条`evaluationStatus`仅表示本次整理状态，本包尚未进行新一轮增强或作品评测。

Qoder案例提取自用户本机`C:/Users/Administrator/Desktop/Qoder增强.docx`，记录文档SHA-256、正文段落范围及实际展示的参考输出。参考输出的遗漏、歧义或新增内容记录在`referenceOutput.reviewNotes`，审阅标准来自用户原始要求及适用材料。

Q01、Q02、Q06、Q07的图片通过DOCX内条目名及SHA-256定位，回放这些完整图片场景需要原DOCX。图片已查看，当前清单记录其用途。本包收录Q10的[报告附件截图](./materials/report-appendices.png)，图中为字段占位及版式示意。Q10可使用该截图核对四项附件与栏目。原文提及的业务源码、调查数据和协查函模板未提供，文件路径只作为定位线索。增强结果新增的具名类、方法和字段须核实实际材料依据。

历史案例通过相对路径、案例ID和文件SHA-256引用既有完整输入，回放时读取其中的上下文与全部实际题答。合成代码、日志、题答继续使用原件。用户真实问题与合成复现分别标注来源，原历史评测结论可从各条`historicalObservation`追溯。

## 使用方法

1. 选择与改动相关的案例，读取`rawPrompt`及`actualMaterials`。先确认材料可用情况，记录实际提供给增强及执行阶段的内容。材料缺失时保留相应验证缺口。
2. 按`mustPreserve`与`reviewChecks`逐项核对动作、对象、条件、否定、格式及决定权，记录实际正文片段。按含义核对，允许等义表达。
3. 核查每项新增内容是否落在`allowedDesign`的合理空间内，并说明作用。这些设计是可接受示例，合理替代方案照常审阅。
4. 根据`openDecisions`核查未知的状态。Plan仅询问用户掌握或保留且会实质改变结果的决定。已回答的待定参数按实际回答继续处理。
5. 记录表达改善、有用补全、正确保留或退步。每项判断附输入依据、优化正文原句和具体作用或错误。根据风险安排下游作品抽查，并注明执行效果验证状态。

此清单是评测资料。案例内容、Qoder参考结果和检查项保存在离线材料中，运行时生成指导继续从产品入口维护。准备真实调用时按既有授权核对具体外发材料，原DOCX和引用的业务文件不因纳入清单而自动取得外发授权。

## 审阅记录字段

每次实际评测将审阅记录写入该次独立证据目录，引用本清单的版本或提交号。

| 字段 | 填写要求 |
| --- | --- |
| 输入 | 案例ID、材料实际可用情况、完整题答、模型及指导版本 |
| 要求核对 | 检查项ID、对应优化正文片段、保留/遗漏/改变/待验证及依据 |
| 改善 | 表达改善或有用补全的原句、新句及具体作用 |
| 正确保留 | 已充分表达的要求与原范围，注明少改或不改的依据 |
| 退步 | 实际错误、严重程度、受影响条件及发生阶段 |
| 用户修改 | 需要补、删、改的具体句子或文件，披露是否有真实用户参与 |
| 执行效果 | 抽查范围、作品原件、结果及未验证内容 |
