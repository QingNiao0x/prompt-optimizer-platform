# 索引阶段计时与容量优化

## 第一阶段

基线为 8ca270a7。新增目录供给等待、元数据查询、小文件预读、识别、解码分块、词表生成、写入及最终清理计时，记录首批提交、最大事务、待写字节/词关联峰值。活动时间可重叠，readMs/readBytes 仅统计小文件预读，decodeMs 包含流读取和解码分块等待，不宣称纯 CPU 时间。预扫描 scanMs 沿用现有计量。浏览器准备时间仍在端到端计时内。

真实 Edge 原生句柄执行 API src 子目录，1115 文件、1113 全文、2 二进制跳过。基线 20.792 秒，计时候选 19.606 秒。两轮全文及尾部 1113/1113，完整词表、符号、引用摘要相同。仅一次前后对照用于观测，不作为稳定性能提升结论，脚本沿用的 stableImprovement 布尔值不能替代多轮验收。

候选总计 19.587 秒，其中写入等待 16.296 秒，预扫描 0.465 秒。小文件预读活动累计 1.652 秒，目录供给等待 1.266 秒，词表生成 0.834 秒，识别 0.132 秒，解码分块 0.193 秒。24 次写入，最大 1.119 秒，首批提交约 0.975 秒，待写估算峰值 4,328,688 字节。该样本主要耗时在写入等待，活动时间不得相加。根目录尚需新候选验证。

46 项索引器单元测试和类型检查通过。失败的受限浏览器启动原因为系统沙箱下 Edge 崩溃，使用经授权的独立浏览器配置复验通过。

证据见 evidence/index-stages-2026-11-17。脚本复现应使用独立 tmp 输出目录，冻结候选，不能覆盖本轮证据。

## 第二阶段

于 2026-11-18 完成实现与本轮声明范围验证。

独立库写入 formatVersion=2 的词表，移除每个词重复的项目 ID，保留全部词项及关联。查询同时兼容旧前缀词和新词，合并后沿用原候选排序及限额。读取恢复完整外部词项格式。写入核对项目归属。旧共享库继续使用原编码，独立旧记录在覆盖时逐条使用新格式，旧逻辑容量估算可能仍偏保守。

项目逻辑容量按实际词编码计算，待写内存预算继续包含完整词项。2 GiB 预算保持有效。contentComplete 与 incompleteReasons 区分逻辑预算、扫描限制、文件限制及读取失败。READY 保留历史处理结束语义，界面对未完整正文提供明确状态、原因和继续入口。空文件不构成正文缺失。

真实 Edge 使用原生目录句柄及生产 Worker，在 E:\MyProject\prompt-optimizer-platform 根目录执行。冻结 23,494 文件、546,930,542 字节，前后输入指纹一致。23,192 份正文全文及尾部全部一致，16 个零字节文件、286 个按既有规则忽略文件，失败为零。41,976 片段、271,264,180 字符、27,067,761 词关联核对一致。README、索引器源码、Java 应用入口均检索命中。逻辑索引 920,549,608 字节，未触及容量或扫描上限，contentComplete=true。

浏览器结束阶段站点估算占用约 1007 MiB。逻辑字节和浏览器物理估值分别记录，二者不等同。浏览器物理配额异常沿用现有事务回滚及恢复机制。完整性检查在索引耗时之后进行。

本轮索引耗时 1,489.659 秒，约 24 分 50 秒。写入等待 1,392.629 秒，约占总计 93.5%，1,967 次提交。首批提交约 9.156 秒，预扫描约 8.254 秒。该完整运行早段同时进行过浏览器回归及构建，因此不用于性能比较。此前根目录容量失败的交付集合也不同。stableImprovement=false，后续连续管线与批次优化仍需执行。

此前测试在 15,400 文件时被环境中断，保留 interrupted-report.json。续跑发现独立测试桶已过保留期限，resumed-report.json 记录失败。最终新建独立测试配置重新完整执行，report.json 为最终结果。验证脚本对测试自建配置目录进行清理，用户浏览器配置不在清理范围内。

105 项相关单测、Chrome 9 项和 Edge 9 项真实存储回归、类型检查及生产构建通过。新回归覆盖新旧词表混用、全部词项恢复、覆盖更新和跨项目写入拒绝，原有回归覆盖隔离、迁移、批次提交、失败恢复及回滚。最终仅修正仓库两处缩进，未改变测试候选语义。构建仍提示既有依赖注释和大产物警告。

证据在 evidence/index-capacity-2026-11-18，包含冻结清单、脚本、最终报告及中断/恢复失败原件。root 样本中无容量降级，其他设备或更大项目仍可能触及策略与实际浏览器配额。后续按方案进入统一源码入口及连续读写优化。
