# 自然增强信息状态共同机制与未见作品验收

批次在2026-10-22启动并冻结，2026-10-23完成评审收口；文件名沿用启动日期，历史原件不回改。

本轮按用户授权完成共同机制候选、开发回归、冻结未见题及同信息实际作品比较。**候选未达到采用条件，默认继续 NATURAL/4；不能宣布已获得稳定质量提升。** 代码通过受影响检查与候选值得采用是两项不同结论。

## 实现与冻结边界

- NATURAL/25 从第四版替换上下文与任务记录说明，要求保留来源、对象、条件和确定程度，避免把资料缺口提升为现实事实。它在开发题中仍出现“资料未提供→目前没有”，已停止采用。
- NATURAL/26 同样从第四版出发，把可编辑任务指令与需保真的材料事实分开，选入的材料事实采用保留范围与条件的完整来源原句。没有职业、场景关键词分支，没有新增模型分析或质量重试，也没有恢复自然模式固定约束。
- 两个候选沿用第四版响应协议、全部实际题答、来源及组装前后正文覆盖保护；Plan指导逐字保持第四版。第四版与既有候选指导冻结，未更改默认或前端开关。
- 复用两类测试及历史失败响应，最终 **314 项受影响 Java 测试和 clean package 通过**。测试只验证版本和保护契约，不证明语义等价。
- V31/V32 仅为前向数据库注释迁移，未执行；未改表结构、旧迁移、业务删除或身份隔离。产品提交 `e48ab32d`。

## 先冻结，再比较

[任务协议](./evidence/natural-information-state-2026-10-22/task-protocol.json)在真实调用前冻结总额160、开发与采用条件。第一开发批30次，第二开发批30次，未见批49次，**总计109次：增强39、Plan2、作品68，含3次协议修复、0次质量重试**。剩余51次未使用，不能通过扩大采样把失败变成通过；旧闭批余额未转入。全部批次已关闭，临时服务已停止。

未见题由未读候选指导和开发题的协作代理先行封存；主实现者在候选26代码、参数和判据冻结后才首次开封。题目包括物品状态提取、场地推荐、二手书回复、照料日程、充分表达润色和真实Plan代收说明。出题者及评审者均为内部AI协作，不是外部专业独立评测，不据此声称统计显著或跨模型普遍有效。

同一材料、模型与参数下比较原始／第四版／候选；原始臂也拿到完整材料和真实答复。未见阶段每份固定提示词下游执行两次，全部首稿保留；Plan使用同一真实计划绑定同一完整答复，不伪造题号。两版确认后均未交付，故只得到32份作品，缺失的4份增强作品不计通过。

## 观察到的收益与退步

| 阶段 | 观察结果 | 判断 |
| --- | --- | --- |
| 25开发集 | 内部记录保留“资料未提供”，正文却写成“目前没有”，并把“一段”放宽为“一段或几小段”；作品传播了状态错误 | 不采用25，内部记录正确不能代替正文正确 |
| 26开发集 | 六份候选正文保留要求；进度题正文和作品保留来源范围，第四版本次丢失范围。其余否定、未知、独立条件和JSON守护题未见同类退步 | 只支持进入未见评测，不算普遍收益 |
| 未见直接增强 | 两版均交付5题；借书润色两版正文逐字相同，物品JSON作品语义一致，二手书作品均保留主要事实 | 不能把更长或复述更多材料计作质量胜出 |
| 未见照料作品 | 26的一次作品把“今天托盘为空”用于周三安排；另一次增加“5分钟内做不完就顺延浇水” | 出现新的时间范围或执行条件变化，不符合无新增严重退步要求 |
| 未见Plan确认后 | 两版最终均为RESULT_INVALID，增强作品缺失 | 完整交付条件未满足，不能用其他题抵消 |

两份匿名评审均认为场地推荐在两次作品中优于第四版：候选避免压缩预约截止条件以及不必要的投影追问。但只有这一题达到重复收益，低于本轮预先冻结的至少两题要求。借书润色与物品提取持平；二手书相对原始作品有来源保真收益，但第四版也有，不能当成候选升级收益。

只对三臂共同完成的五道直接题汇总（各10份作品），两名评审均给出最少修改项数：原始9、第四版6、26为3。候选总修改量较少，却出现第四版没有的严重条件错误：26为1—2项、第四版0项，差异在于“今日托盘状态进入周三栏”被判轻微还是严重。两名评审均认为应修改，也都把另一次擅自顺延浇水判为严重。**不能用少改几处轻微问题抵消新增严重错误。** Plan的漏交付及其原始作品不混入不等分母。详见[匿名评审与采用决定](./evidence/natural-information-state-unseen-2026-10-22/adoption-decision.json)。

开发集进度作品两版均有多段排版。原始请求为“一段”，主审将此保守列为需修改的格式问题；匿名作品审阅将其视为可接受短消息排版。该分歧保留，按严格口径两版各增加一项修改，不影响26开发阶段相对改善，也不能用于抬高未见收益。

## 失败发生在哪一层

25开发题的资料范围错误发生在模型生成正文中，组装及历史没有改写正文。26改善了该题，但未见作品仍可能把当日事实扩大为未来安排，说明完整引用不能保证执行者正确解释时间与条件。26正文允许将托盘待查看事项写入清单，可能增加把当前状态排成日常任务的风险；错误首次出现在下游不证明下游是唯一根因，本轮没有隔离验证这一因果关系。

未见题的协议失败独立记录：物品题26首次返回跨行覆盖引用，拆为单行引用后成功；代收题第四版两次及26首次只引用同文答复的第一个来源编号，遗漏其余真实题答来源；26修复后又在增强阶段返回非空Plan影响记录，仍被拒绝。三份重复答复是本次预先允许的绑定方式，会增加模型维护来源编号的负担，不能把该结果外推为所有Plan都失败。不能直接删除来源保护或跨阶段检查来放行；24的非权威诊断兼容也不解决这些已知字段问题。

内部任务理解仍有残余误分类，例如把“明确尚未开始”概括为缺口中的“状态未定”，或把原文已要求的条件完整性当成新增补充。其正文未必错误，须与用户实际收到的正文和作品分别评价。

## 采用与运行状态

候选26没有满足事先冻结的完整交付、无新增严重退步及至少两题重复作品实质改善条件，**不切换默认、不部署候选，不把本轮写成质量目标已达成**。这次完成的是实现、验证及采用判断；稳定提升的目标仍未达成。

34份成功增强与历史一致，自然固定条款未追加，内部任务记录未泄露到历史响应。未见作品24项格式／长度检查通过，但它们没有发现上述语义错误，不能替代质量判断。仅运行隔离本机评测服务，未重启日常服务、未部署生产、未推送Git。

本轮不再追加场景禁令或为相同假设扩采。若后续继续，现有原件应作为回归：优先分开处理实际题答来源和阶段协议的交付失败，再独立验证“来源事实在正文及下游是否被改变”。已开封题不能再声称未见，已验证的局部收益不能替代新留出结果。
