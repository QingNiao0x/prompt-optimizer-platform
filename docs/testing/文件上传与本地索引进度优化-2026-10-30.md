# 文件上传与本地索引进度优化（2026-10-30）

> 后续已执行两项真实补验：办公文档上传与解析通过本轮样例，整项目首导暴露存储配额失败，普通浏览器补验亦未跑完。下面保留本轮初始改动的历史证据，最新结论以[真实项目首导与文档上传验收](./真实项目首导与文档上传验收-2026-10-30.md)为准。

## 范围与结论

针对首次导入 `E:\MyProject\prompt-optimizer-platform` 慢、界面数量容易误解及没有明确百分比的问题，修改浏览器本地索引、FileList 预检、上传进度与显示。没有修改后端、模型指导、Plan、动态约束或索引的全文检索规则。

基准代码来自工作区修改前的 `b5cbf16a` 前端索引实现；比较时另一个会话已有后端与文档修改，未回退或提交这些修改。本次改动未提交、未发布。

已完成：

1. 根目录 `.gitignore` 范围可见、可关闭；在打开子目录和文件前排除项目声明忽略的内容。保留未跟踪源码及 `docs/testing`，不截断文件尾部或检索词。
2. 预统计只枚举句柄；处理阶段使用同一范围计算真实百分比。小文件至多 6 路预读，并复用采样与正文缓冲；大文件保持流式读取，数据库写入保持原有顺序和批次上限。
3. 分开统计完整、跳过、未完整、失败及范围排除。空文件刷新后不再变成“完整全文”；容量不足的部分文件不再被正常指纹永久复用。
4. 文档上传显示字节百分比；即使浏览器没有发送上传进度事件，成功分片也能推进进度。解析、排队和索引阶段单独说明，不把处理进度的 40% 当成文件上传比例。
5. FileList 预检显示进度并定期让出主线程，未扫描文件单独说明；项目规则在办公文档分流及上传确认前应用。上传仍需原有确认，文件不因索引而自动发送到模型。

- 六次的片段正文、完整检索词、符号和导入信息组成的规范化 SHA-256 均相同；固定查询的实际检索结果 SHA-256 也相同。

- 新版同轮索引耗时较低，但三轮波动明显；检索有快有慢，不能据此承诺所有设备固定提速、检索更快或全项目导入需要多少秒。第一批试测同样内容完整，约 1.5 秒的新旧差异很小；最终表是最后代码重新对照的结果，未通过重试挑选胜出样本。
- 此对照不包含浏览器选择整个根目录后的预统计，也不等于 2 万余份材料或百万文件的完整首导。最明确的负载改善是提前避免处理项目已声明排除的临时目录。

## 使用与后续边界

刷新工作台并重新选择目录即可加载新 Worker；刷新会按既有产品约定清空当前上下文选择，未保存内容先保存。只改前端，无需重启 Java 后端。若所需资料位于 `.gitignore` 排除范围，取消“按根目录 .gitignore 排除文件”后重新索引或增量更新。

只支持所选根目录的项目规则，未实现嵌套 `.gitignore` 或 Git 跟踪例外；这一限制已体现在开关名称和设计文档。完整浏览器首导耗时仍需在目标设备、实际约 2 万文件范围验证。多值检索词写入仍占较多时间，后续可在同范围基准下优化写入调度；不得减少词表、截断尾部、强制只读 Git 已跟踪文件来换速度。
