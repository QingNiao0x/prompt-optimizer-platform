# 自然增强阶段协议与框架独立对照

本批实现用户批准的四项改进：分层验收、阶段协议解耦、语义证据与形式检查分开、开发与保留题隔离。默认保持 NATURAL/4；协议通过不代表正文质量提升。结果另见 `results-summary.md`（完成后新增），本文件及判据在调用前冻结。

## 候选与采用边界

| 对照 | 唯一改动 | 主要观察 |
| --- | --- | --- |
| 21 对 4 | 增强／Plan专用响应，服务端生成确定性索引和关联 | 首轮可用、最终交付、协议修复、语义不退步与用量 |
| 22 对 21 | 框架标签从必填变可选 | 不因诊断标签拒绝有效正文，正文与作品无严重新增退步 |
| 23 对 22 | 移除十二框架映射指导 | 是否有可观察的实际收益，保留一般任务组织指导 |

模型仍需给出实际要求、来源原句、补全依据和正文引用；服务器不替它补写不存在的语义证据。Plan保留同题全部独立依据、未提问未知及全部实际题答，旧4响应不通过删除非法字段放行。源码新增候选不等于采用或部署。

## 输入、预算及公平性

- 新增授权原话“授权新增最多96次实际调用”，旧闭批余额不转移。计划67次主调用，最多96次，所有失败及协议修复计数，不做质量重试或付费模型评审。
- 开发／回归4题，Plan2题（充分无需问、重要未知），其中1题绑定真实Plan及全部实际题答后分别生成；内部留出3题在候选源码冻结之后合并。独立协议详见 `protocol.json`。
- 三份留出由未参与候选编码的同团队代理编写，候选作者与测试作者未预览。不是外部用户、领域专家或统计独立的盲测；查看后不再声称未见。
- 原始、4、21、22、23作品使用相同材料、题答、模型、参数及工具边界。生成与作品按固定轮转顺序执行，不挑最好一次。失败臂计交付失败，不让其他臂凭空获得语义胜利。
- 执行仅限本机9003隔离进程、既有合成账号；不应用Flyway，不创建账号，不接管日常端口。模型密钥只在既有服务端环境，认证信息不进入证据。

## 判断方法

先做来源与实际题答保护、第四版字节一致性、严格格式和历史一致性检查，再审阅正文和同信息作品。按原定交付、事实、要求、执行可行性及用户需改什么判断；允许正常设计差异，充分输入持平可通过，但不算质量增益。

采用须有与对应假设一致的实质收益且无新增严重退步。不把HTTP200、token变少、长文本或单次速度当作语义改进。严重问题保留原件并定位，停止该假设的扩大采样，不改本批源码、题目或判据凑通过。人工用户验收未进行时明确标为待完成。

运行脚本、输入、指导、产品源码及运行副本均由 `source-manifest.json` 绑定，每次上游调用前核对。批次结束新增闭批文件，之后任何再次调用都会拒绝。历史闭批、评分及失败记录不回改。
