下面按“20分钟介绍安排”和“一页式交接清单”两部分给出，可直接用于新同事入职介绍，也可作为小组内部交接规范。

---

## 一、20分钟介绍安排

**目标**：让新同事听完能说清三件事——交接什么时候做、交接什么、怎么确认交接完成。

| 时间 | 环节 | 讲什么 | 怎么讲 |
|---|---|---|---|
| 0–2分钟 | 开场：为什么交接要标准化 | 交接不清的常见后果：信息断档、责任模糊、返工；小组交接的基本原则：**先清单、后口头，先确认、后接手** | 用一个真实小案例开场（如某次交接漏了外部联系人，导致问题延迟处理），不点名、不展开细节 |
| 2–6分钟 | 交接的三种场景与触发时机 | ①常规交接：同事休假、调岗、离职；②项目交接：项目阶段转换、负责人变更；③临时交接：突发请假、紧急顶岗。每种场景的启动时点和最晚完成时点 | 用时间轴画三种场景，强调“**交接不是离开那天才做**”，常规交接至少提前2个工作日启动 |
| 6–11分钟 | 交接内容五类 | ①工作事项：在办任务、待办、截止时间；②资料文件：存放位置、命名规则、权限；③系统与账号：哪些系统、什么权限、谁审批；④外部关系：客户、供应商、协作方联系人及注意事项；⑤风险与例外：容易出错的点、历史遗留问题 | 逐类讲，每类配1个“漏了会怎样”的反例；现场展示清单对应栏目，让新同事知道每类落到哪一项 |
| 11–15分钟 | 交接流程四步 | ①交接人填清单并备齐资料；②双方逐项过清单，当面确认；③接手人复述关键事项并试操作；④双方及组长签字，清单归档 | 用流程图讲四步；重点讲第③步“复述+试操作”，说明这是防止“以为懂了”的关键动作 |
| 15–18分钟 | 确认标准与常见问题 | 什么叫交接完成：清单无空项、关键系统能独立登录操作、待办有明确下一步、风险点已口头说明；常见问题：只交文件不交背景、账号权限没转、外部联系人没介绍 | 列3–4条“不合格交接”的表现，让新同事判断；说明组长在交接中的审核责任 |
| 18–20分钟 | 清单使用说明与答疑 | 清单放在哪里、每次交接怎么复用、填完后交给谁；留1–2个问题现场答 | 现场发一页清单（纸质或共享文档），指着栏目快速过一遍；未答完的问题记下会后回复 |

**讲解方式建议**：全程配一页流程图和一页清单投影；每个环节不超过4分钟，避免逐条念清单；开场案例和“漏了会怎样”的反例是让新同事记住的关键，不要省略。

## 二、一页式交接清单（可复用）

> 使用说明：每次交接复制一份，交接人先填，双方逐项确认后勾选；不适用的项填“不适用”，不留空。完成后双方及组长签字，归档到小组共享目录。

### 基本信息
| 项目 | 填写 |
|---|---|
| 交接类型 | □常规（休假/调岗/离职） □项目交接 □临时顶岗 |
| 交接人 / 接手人 | ______ / ______ |
| 组长 | ______ |
| 启动日期 / 计划完成日期 | ______ / ______ |

### A. 工作事项
- [ ] 在办任务清单已提供（任务名、当前进度、下一步、截止时间）
- [ ] 待办事项已逐条说明，每条有明确责任人和时间
- [ ] 周期性工作已说明（周报、月报、例会、巡检等）及下次时间
- [ ] 紧急/高优先级事项已单独标注并口头强调

### B. 资料与文件
- [ ] 文件存放位置已告知（共享盘/文档库/本地路径）
- [ ] 命名规则和版本管理方式已说明
- [ ] 关键文件已确认接手人可打开、可编辑
- [ ] 纸质资料/实物已清点移交（如有）

### C. 系统与权限
- [ ] 需使用的系统清单已列出
- [ ] 账号/权限已申请或已转移，接手人已实际登录验证
- [ ] 审批流中的待处理事项已说明处理方式
- [ ] 密码/密钥按小组规定移交，未通过聊天工具明文发送

### D. 外部关系
- [ ] 客户/供应商/协作方联系人清单已提供（姓名、单位、事项、联系方式）
- [ ] 关键联系人已由交接人当面或邮件介绍
- [ ] 沟通中的敏感事项和注意事项已口头说明

### E. 风险与例外
- [ ] 易错点、历史遗留问题已逐条说明
- [ ] 当前已知风险及应对措施已确认
- [ ] 尚不明确的事项已记录，并明确谁在何时跟进

### F. 确认与签字
- [ ] 接手人已复述关键事项，交接人确认无误
- [ ] 接手人已对关键系统完成一次独立操作
- [ ] 清单无空项（不适用项已注明）
- [ ] 遗留问题清单已附后，每条有责任人和期限
