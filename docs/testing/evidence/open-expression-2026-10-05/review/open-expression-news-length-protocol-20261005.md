# 新闻稿实际执行的冻结口径

- 输入和资料与接口验收 cases.json 一致，均为合成产品信息，不允许补造事实。
- 原始、直接增强、Plan 增强分别独立执行；同一执行模型使用相同温度、输出预算和资料。
- 正文600–800字，两个备选标题不计入正文。保留两种计数：汉字数、非空白可见字符数。原需求没有严格定义“字”，本轮保守通过要求两种计数都在600–800区间，不在看到输出后改口径。
- 只排除经审核的两个标题行、纯格式标题和Markdown标记，正文数字、拉丁字母等仍计入非空白字符数。记录每份正文及被排除标题，便于复核。
- 必须保留：清笺产品名、2026-10-20受控内测、开发人员/研究生/机关办公人员三类受众、需求明确化/结合资料/结构化输出三项价值、只生成提示词不执行代码/报告、不承诺必胜或专业意见、反馈入口为内测页面。
- 不编造负责人引语、数字成绩、自动写作/代码执行、公开商业发布、真实医院/法律结论、外部报名链接或电话邮箱。
- 失败和不足篇幅全部保留；人工复核为AI辅助核查，不等同专业人员或独立人工评审。单轮小样本不能证明稳定胜率。
- 本轮不调用TokenHub，不改变其预算、重试、超时或配置。
