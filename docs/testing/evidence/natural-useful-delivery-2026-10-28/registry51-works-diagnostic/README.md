# 51 实际作品的有限匿名诊断

本目录只准备零调用工具，不冻结或启动批次，不改变默认31，也不将 Plan 失败改判通过。所有旧失败保持原判。仅在三个新作品阶段全部 `CLOSED` 且公开结果被 closure 哈希锁定后，才由 root/基础设施明确运行：

`node materialize.mjs --materialize-closed`

- `registry51-query-works`：Q01 两份新作品，复用旧原始/31各两份。
- `registry51-content-works`：U02/U03 原始、31、51各两份，共12份。
- `registry51-code-works`：C01/C02 两份新作品，复用旧原始臂各两份。

工具逐题核对实际执行请求除提示词外的 system、模型参数、预算及完整材料一致，读取原准备中的公开材料和复用引用，不打开 traces、内部草稿、账号或封存题。每份重复单独随机分配标签；种子和映射只写到 `tmp/natural-useful-delivery-2026-10-28/registry51-works-diagnostic/coordinator/map.json`，禁止给独立评审。已有输出拒绝覆盖或重新抽标签。

公开 `packets/` 只提供原需求、同一原材料、每份完整作品或匿名失败状态及原先声明的通用审阅标准。隐藏版本、优化提示词、作业/阶段、执行次序、tokens和耗时；原作品文本逐字保留，截断和空响应也保留并标记，绝不选择最好的一次。HTTP200不等于作品合格。

旧基线与新请求时间不同、实际模型权重不可核实；两次重复不证明统计稳定。作品诊断不能消除提示词层面已知保真失败，也不能自动作为采用或发布结论。

代码检查沿用 `checkers/run-code-results.mjs registry51-code-works`（必须在作品闭批后另行调度，本准备不运行）。其检查交付白名单、双入口日期边界、导入部分成功及反馈、未改文件、独立边界与既有/新增测试实际行为；受限 VM执行，不将模型源码直接交给宿主执行。

离线自测：`node self-test.mjs`。仅检验完整文本/失败/截断保留、元数据白名单和固定随机种子行为，不读取新作品或创建匿名包。
