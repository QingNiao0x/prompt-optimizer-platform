# EH01 工程题答案卡（不得向增强器或执行器提供）

## 事先确定的范围

原始需求是修改现有 Vue/TypeScript 工程，交付可应用的完整文件 JSON 包。不能退化为审阅建议、伪代码、重建界面或要求先补一个后端。它没有授权修改旧模块、活动报名、押金、合成数据、类型、错误码、依赖或其他文件。

允许在指定的九个当前链路文件中选择最小必要修改，算法、辅助局部函数、注释和具体组织开放。参考修复只是检查器自测用例，不是唯一允许写法；不要求使用某种过滤形式或完全移除所有缓存，只要求提交前基于最新仓库正确检查。不能按改动文件数、输出长度或术语给分。

## 业务事实与预期行为

- 当前链路：两个页面分别调用各自 composable，共用 createLoanDesk，再调用 domain/availability，余量下限由 domain/quantity 处理。业务主链为五层，所有工程内部依赖是真实相对导入。
- 港湾相机库存 8；已确认 2、已领取 1，共占用 3，可新建 5。草稿 3、已归还 2、已取消 1 不占用；山坡相机的已确认 3 不能扣港湾库存。
- 山坡相机库存 4、有效占用 3，余量 1；港湾三脚架库存 6、有效占用 4，余量 2。港湾没有配置音箱库存，不能把缺配置当成可借 0 而静默继续。
- 修改 L101 时排除自己的 2 份，只扣 L102 的 1 份，因此该单可保存的整单数量上限是 7。保存为 7 后是 7，不是 2+7；其他单不变，原单版本由 1 到 2，用途 trim。
- 新建 5 份可以成功，产生已确认单，版本 1、用途 trim，之后当前新建余量是 0。新建 6 份应失败且不写仓库。
- number 类型的正安全整数有效。小数、非有限值、0、负数、超安全整数及运行时字符串等无效，使用 INVALID_QUANTITY。合法数量超过最新上限使用 INSUFFICIENT_STOCK。
- 看过余量后通过仓库加入其他有效单，新建或修改提交都必须重新读取。新建原余量 5、再占用 4 后申请 2 必须失败；修改原上限 7、再有其他有效占用 6 后保存为 2 也必须失败。
- 只有 CONFIRMED 可修改；COLLECTED、DRAFT、RETURNED、CANCELLED 保持只读。不存在借用单和缺库存保留已有业务错误。
- 失败不改变仓库、状态或版本；两个页面保留刚输入的数量和用途。成功后反馈、版本和余量按既有交互刷新。
- 旧台账 availabilityFor 和活动名额 availabilityFor 有不同值域与业务范围，不能合并或套用器材口径；押金预览默认记录仍显示 160.00 元，且仍是只读。

## 事先确定的检查分组

每组 0 或 1，共 10 组。组内检查用于同一个业务要求，任何实质失败使该组为 0。正常等价写法可通过，不要求参考代码文本相同。

1. 地点与器材隔离：B01、B02、B03 的余量、总量与占用正确。
2. 业务状态与纯计算：B04、B15 正确排除不占用状态、支持排除当前单、余量非负且不修改输入快照。
3. 修改整单语义：B05、B06 排除自身，能保存上限 7，只更新目标单，保持状态、trim 和版本递增。
4. 新建与超量：B07、B08 合法上限可交付、超量不写入，成功后余量正确。
5. 两条服务路径的数量校验：B09、B10 拒绝无效数量，使用既有错误码，不写入。
6. 最新仓库校验：B11、B12、U10，不能用预览缓存放行新建或修改，页面失败草稿及手动刷新可用。
7. 既有边界：B13、B14、U08，只读状态、缺配置和不存在单号继续按原边界工作。
8. 真实组件链路：U01、U02、U03、U05、U07、U09，两个页面展示、事件提交、成功反馈、上下文切换与现有页面导航可用。
9. 失败时的数据与编辑保留：U04、U06 及相关 B 检查，失败不改仓库、状态或版本，不清空输入，并给已有可读错误。
10. 输出与误改：合法 JSON 文件包，只改原始需求允许的现有路径，无新增文件/依赖；X01、X02 的独立旧逻辑、活动逻辑和押金保持可用。

X03 是隔离环境自检，不单独算业务得分。若检查器失效或宿主能力泄漏，停止作品执行，按基础设施问题报告，不能判作品通过。

## 严重标记与归因

任一入口仍按错误余量放行/拒绝、跨地点或跨器材混算、修改重复扣自身、预览过期仍放行、失败写入或丢稿、破坏只读边界、修改未授权模块，均另列严重标记。分数不能抵消这些问题。

将原始需求、增强响应、平台组装与复制文本、实际下游输入、完整 JSON 作品和检查结果分别保存，才能判断遗漏来自增强、平台组装还是下游执行。编译成功、工程导入成功和 HTTP 成功本身不证明完成。单题失败也不能直接归因为模型能力。

## 执行与工具边界

在可信检查器目录执行：

```text
node checker.mjs <作品JSON绝对路径> <已有apps/web依赖目录>
```

检查器只读可信工程、既有编译依赖和作品 JSON；作品文件不写入产品目录，配置和 npm 脚本不执行。替换内容在内存编译，执行发生于无宿主函数/对象注入的 VM。Vue SFC 的导入类型解析也仅允许虚拟工程文件系统。

结果 stage=artifact 表示输出包或修改范围不符，stage=compile 表示源码编译失败，stage=runtime 表示实际执行/业务检查。检查器本身或依赖异常应显示 infrastructureError 并单列排除，不能等同于作品业务失败。

真实 Vue runtime 和预编译模板用于内存宿主树，事件和响应由实际组件运行。该检查不覆盖真实浏览器布局、CSS 几何或端到端视觉效果，不能写成浏览器 UI 验收已完成。
