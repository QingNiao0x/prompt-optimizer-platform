# 实际工作台、复制与交付范围验收

本目录只处理合成项目与公开通用需求。固定账号凭据、Cookie、CSRF会话与私有服务器日志留在仓库忽略的tmp；不得复制到证据。真实模型调用由根任务冻结作业及传输层计数，不在浏览器脚本中另行直连模型。

## 本机无模型捕获

`capture.mjs <cases.json> --canonical` 启动自有5184，走真实文件夹选择器、Worker与IndexedDB，再在最终业务请求处返回明确的409。身份及模型目录是受控模拟，因此这些原件只证明浏览器实际构造的请求和索引/召回，不证明模型质量。

- `captures/` 是初次六题完整捕获；`captures-r2/` 是并列相对路径修复后的最终六题，均保留。
- `capture/r2-C01/` 保留交付范围路径碎片导致召回旧模块的失败；`offline-diagnosis.json`说明初次未保存DTO及新增系统设置Mock遗漏的工具错误。
- 有项目的题均索引全部79文件，其中72份同词噪声和同名旧目录参与索引。无附件题没有选项目，不用脚本伪造更充分的输入。

## 真实增强

`live-browser.mjs <冻结阶段> <GEN作业ID>` 默认只预检；追加`--execute`才会按冻结作业发送一次业务请求。需先由基础设施在9014启动相应新阶段并正常登录。脚本核对固定服务端身份、真实UI请求与冻结DTO逐项相等，然后保留实际生成阶段、页面显示、剪贴板和真实历史一致性证据。`real/`只存四类安全原件，不携带会话。

本目录的真实增强使用临时受控版本入口，不能推断日常默认入口已经切换。普通入口验证使用明确冻结的`entrypoint: DEFAULT`作业，仍需事先记录部署和实际运行版本。

## Plan两段协议

`capture-plan.mjs <当前新阶段> <rN>` 使用同一固定账号真实登录状态和完整79文件项目。浏览器先将实际材料发送到确定性的`/api/v2/context/planning`，保存完整准备请求、真实摘要与contextId/version；之后在`/api/v2/optimizations/plan`前拦截，不发模型。

Plan请求只携带引用，材料保留在真实服务端短期上下文中；不能把普通OptimizationRequest当Plan请求，也不能删掉材料再称同信息。引用按实际expiresAt过期，后续如需重新准备，另存明确的新登记与绑定，不修改原捕获或静默复用失效引用。

## 作品合同

两个代码需求的可写范围句已在原始提示词与共同执行system中逐字一致。C01允许按需修改既有回归测试，C02禁止修改测试，二者都禁止新增文件或改其它文件。运输JSON要求`files`，可选`summary`仅承载简短说明；说明有无不作为收益。无执行工具不得声称已经运行。

`build-code-work-bundle.mjs`在增强结果后准备作品作业；未完成BODY_GENERATION的31先记产品门失败，不继续付费执行明显的原文加源码作品。模型、参数、执行材料和合同按臂一致。`checkers/`分别检查原有十项行为、四项独立边界、文件范围及相关回归测试的实际有效性；历史上轮三文件协议FAIL不改判。
