## 二、流程图说明

### 1. 预约事件进入分析池
- 输入：2026年第一季度预约事件记录。
- 关键动作：按预约事件编号识别一次预约；标记渠道为电话、网页或窗口。
- 注意：一个患者可多次预约，事件数不等于人数。

### 2. 渠道归并
- 输入：同一预约可能存在的电话与网页操作事件。
- 关键动作：先定义首次渠道和变更渠道；将操作事件归并为预约事件。
- 注意：不能把操作次数当成预约量；主统计单位未定前，事件口径与去重患者口径分别展示，不混同。

### 3. 状态分类
- 输入：ARRIVED、CANCELLED、UNKNOWN。
- 关键动作：
  - ARRIVED：记录为到诊。
  - CANCELLED：记录为取消；不附加临床解释。
  - UNKNOWN：进入待核验池；不直接计为爽约，不解释为患者责任。
- 注意：UNKNOWN原因未细分，需来源核查。

### 4. 观察窗口与最终状态判定
- 输入：预约就诊时间、取消时间、状态更新时间。
- 关键动作：等待观察窗口和最终状态判定规则明确。
- 当前处理：窗口未确定前，只展示待核验事件；不将尚未到期的预约算入爽约率；不因到期自动视为最终状态。

### 5. 取消免责边界
- 输入：取消时间与就诊时间。
- 关键动作：并列呈现旧流程24小时与新会议草稿12小时两种口径。
- 当前处理：不擅自采用任一项；不按文件修改时间断定新规则生效；争议单独呈现。

### 6. 指标展示
- 输入：已归并预约事件、状态分类、待核验事件。
- 关键动作：
  - 展示数量、占比和限制说明。
  - 小渠道样本少时保留数量与限制说明。
  - 无完整数据不报告显著渠道差异。
- 注意：不计算真实医院指标；不将UNKNOWN计入爽约。

### 7. 人工复核与隐私边界
- 输入：待核验事件、来源系统字段、状态更新时间。
- 关键动作：人工复核UNKNOWN来源；检查渠道归并；确认取消规则适用口径。
- 注意：不展示患者、医生可识别信息或敏感诊疗明细；医生代码仅作流程角色示例。

### 8. 报告输出
- 输入：口径表、流程图、采集字段建议、讨论目录。
- 关键动作：标注合成材料与方法草案；明确专业评审后才能应用。
- 注意：不宣称任何方案已提高疗效；不提出减少患者服务权益的建议。

## 三、合成数据采集字段建议

| 字段类别 | 建议字段 | 用途 | 备注 |
|---|---|---|---|
| 预约标识 | 预约事件编号 | 区分一次预约 | 合成编号，不含患者可识别信息 |
| 患者去重标识 | 合成患者标识 | 支持去重患者口径 | 仅用于统计去重，不展示可识别信息 |
| 渠道 | 首次渠道、变更渠道、渠道变更时间 | 渠道归并与比较 | 电话、网页、窗口；先定义首次与变更 |
| 时间 | 预约就诊时间、取消时间、状态更新时间 | 观察窗口与取消免责边界 | 医院本地时区；当前无时区转换证据 |
| 状态 | 到诊状态 | 分类ARRIVED、CANCELLED、UNKNOWN | UNKNOWN不直接计为爽约 |
| 来源 | 来源系统、记录来源 | 核查UNKNOWN与登记质量 | 实施前需合规评估 |
| 操作事件 | 操作事件编号、操作类型、操作时间 | 区分操作次数与预约量 | 不能把操作次数当成预约量 |
| 科室 | 科室类型 | 控制科室影响 | 本题只有一个门诊，不推断跨科室 |
| 流程角色 | 医生代码 | 流程角色示例 | 不是个人绩效评估范围 |
| 复核 | 复核状态、复核备注 | 人工复核待核验事件 | 不记录敏感诊疗明细 |

说明：拟议采集表可以增加状态更新时间、取消时间和来源系统字段，实施前仍需合规评估；不能写成已经建表或已获得数据授权。
