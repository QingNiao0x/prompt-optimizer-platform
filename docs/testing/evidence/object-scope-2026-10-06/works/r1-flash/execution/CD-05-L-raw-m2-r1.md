# 提示词整理工具对照研究方案

## 1. 研究问题

本研究比较三种提示词整理条件对下游任务输出的影响：原始需求直接输入、直接增强提示词、交互式计划确认后生成提示词。研究不评价任何产品绝对优劣，只回答：在相同初始材料下，不同整理方式是否带来可区分的结果差异；当计划确认组额外获得已确认业务事实时，该信息增量是否被误判为模型能力。

## 2. 实验设计

**任务集**：二十个任务，覆盖开发方案类与写作交付类。开发任务要求下游模型只输出方案、不修改仓库；写作任务要求交付文本。跨任务不采用代码测试通过率作为统一质量指标。

**条件与分组**：

- **A 原始组**：下游模型直接接收原始需求与初始材料。
- **B 直接增强组**：下游模型接收由同一初始信息生成的优化提示词，不接触计划确认组后续回答的业务选择。
- **C 计划确认组**：系统先提问，实验操作者按预先制定答案卡作答，再生成最终提示词。记录每个问题、选项、推荐依据和答案；错误推荐被答案纠正后仍计入交互阶段风险。
- **D 信息量匹配对照**：获得与 C 组相同的已确认事实，但不经历本平台问答过程。用于分离“新增信息”与“交互组织方式”的效应。

A、B、D 三组均不得接触 C 组在交互阶段才产生的业务选择。

**重复与随机化**：每个条件对每个任务独立重复三次，共 240 次下游生成。每次重复开启隔离会话，随机化任务顺序，记录模型版本、日期和参数。失败后的重试不得替代第一份失败样本；工具失败和首轮失败均保留。

**材料标签**：任务材料保留真实实现、用户说明、测试示例与待办四类来源标签。人工评分前不得删除不利的测试污染反例。

## 3. 盲评与评分

两名盲评者独立评分。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可查看任务事实，但不得查看另一名评审的先前评分。分歧处理与一致性评价方式尚未确定，列入预注册待确认清单。

评分覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。一个错误可能同时影响多个维度，评分表记录主错误和关联维度，避免同一问题多次计成独立失败。工具生成速度作为过程指标单独记录，不进入质量分；无计费日志时不估算真实 Token 成本，不以字符数换算费用。

## 4. 统计与限制

候选统计方法依赖分数是否有序、是否连续及是否重复测量。方案仅规定选择流程：先确认评分尺度性质，再确定模型，不预先锁定显著性检验。即使三个条件给出相似结论也不构成研究完成证据；人工评阅与可复核任务标准为必需环节，专业领域判断尚需专家参与。

## 5. 预注册

交互式计划确认的最大轮次和终止规则尚未确定，两名评审的分歧处理与一致性评价方式尚未确定。两者均列入附表预注册待确认清单，不默认补全。
