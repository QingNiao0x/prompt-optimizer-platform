## 一、口径梳理

### 1.1 基础口径（可直接采用）

| 口径项 | 定义 | 依据 |
|---|---|---|
| 预约事件 | 以预约事件编号为唯一标识的一次预约记录 | current-brief.md |
| 事件数≠人数 | 同一患者可多次预约，事件数不等于患者人数 | current-brief.md |
| 预约渠道 | 电话、网页、窗口三类，已明确，不再增删 | current-brief.md |
| 到诊状态 | ARRIVED、CANCELLED、UNKNOWN 三类 | current-brief.md |
| UNKNOWN 含义 | 原因未细分，可能来自设备同步延迟、现场漏登记或记录缺项 | current-brief.md |
| 时间字段 | 预约取消时间与就诊时间均为医院本地时区；当前汇总表无时区转换证据 | current-brief.md |
| 取消状态含义 | 仅表示系统记录到用户主动取消，不附加临床解释 | current-brief.md |
| 渠道操作事件 | 电话与网页可能记录同一预约的不同操作事件，渠道比较须先定义首次渠道和变更渠道，不能把操作次数当预约量 | current-brief.md |
| 医生代码 | 仅为流程角色示例，不纳入个人绩效评估 | current-brief.md |
| 科室范围 | 仅一个门诊，不推断跨科室、跨医院或全市表现 | current-brief.md |

### 1.2 待确认口径（影响任务目标，当前缺失业务决定）

| 待确认项 | 影响 | 当前处理方式 |
|---|---|---|
| 预约未到诊的观察窗口与最终状态判定时点 | 决定一个预约事件何时可归为最终状态；窗口未确定前，尚未到期的预约不得计入爽约率 | 只展示待核验事件，不将未到期预约算入爽约 |
| 渠道比较的主统计单位（预约事件或去重患者） | 决定渠道对比的分母和解读方式 | 两者并列呈现，不混同，不默认选择 |
| 取消免责边界（旧24小时 vs 新12小时） | 影响取消事件是否计入爽约的口径 | 差异单独呈现，不擅自采用任一取值 |

### 1.3 取消规则差异（须并列呈现，不采用任一取值）

| 来源 | 内容 | 状态 |
|---|---|---|
| legacy-note.md 旧流程说明 | 提前24小时取消不计爽约 | 旧版说明 |
| legacy-note.md 所载新会议草稿 | 建议提前12小时取消不计爽约 | 尚未批准 |

两份材料的适用口径和审批状态按本题说明核对，不能只凭文件修改日期断定新规则生效。


## 二、流程图说明（文字版）

### 2.1 预约事件状态流转（基于现有字段）

```
预约创建（电话/网页/窗口）
        │
        ▼
  记录预约事件编号
        │
        ├──► 状态 = CANCELLED（系统记录到用户主动取消）
        │         │
        │         ▼
        │    取消时间与就诊时间均为本地时区；当前无时区转换证据
        │         │
        │         ▼
        │    是否计入爽约：取决于取消免责边界（24h/12h 待定）
        │
        ├──► 状态 = ARRIVED（到诊）
        │
        └──► 状态 = UNKNOWN（原因未细分）
                  │
                  ▼
        可能来源：设备同步延迟 / 现场漏登记 / 记录缺项
                  │
                  ▼
        不得直接计为爽约；须标注为待核验
```

### 2.2 观察窗口未确定时的处理流程

```
预约事件
    │
    ▼
是否已超过观察窗口？
    │
    ├── 观察窗口未定义 ──► 全部标注为“待核验”，不进入爽约率计算
    │
    └── 观察窗口已定义（当前未定义）──► 按窗口判定最终状态
```

### 2.3 渠道比较流程（主统计单位未定时）

```
电话 / 网页 / 窗口 三类渠道
        │
        ▼
须先区分：首次渠道 vs 变更渠道（电话与网页可能记录同一预约的不同操作事件）
        │
        ▼
主统计单位未定 ──► 预约事件口径与去重患者口径并列展示，不混同
```


## 三、拟议数据采集字段建议

以下为拟议采集字段，实施前仍需合规评估；不表示已经建表或已获得数据授权。

### 3.1 现有字段（来自当前汇总）

| 字段 | 说明 |
|---|---|
| 预约事件编号 | 唯一标识一次预约 |
| 预约渠道 | 电话 / 网页 / 窗口 |
| 到诊状态 | ARRIVED / CANCELLED / UNKNOWN |
| 预约取消时间 | 医院本地时区 |
| 就诊时间 | 医院本地时区 |

### 3.2 建议补充字段（用于核验与流程分析）

| 建议字段 | 用途 | 备注 |
|---|---|---|
| 状态更新时间 | 判断 UNKNOWN 是否可能为同步延迟 | 拟议，需合规评估 |
| 取消时间 | 核对取消免责边界（24h/12h 差异） | 已有字段，需确认记录完整性 |
| 来源系统 | 区分电话、网页、窗口的原始记录系统 | 拟议，需合规评估 |
| 首次渠道 / 变更渠道标记 | 区分同一预约的多次操作事件，避免把操作次数当预约量 | 拟议，需合规评估 |
| 待核验标记 | 标识观察窗口未到期或 UNKNOWN 未核查的事件 | 拟议，用于报告展示 |

### 3.3 明确不采集的字段

| 不采集 | 原因 |
|---|---|
| 患者姓名、证件号、联系方式等可识别信息 | 隐私边界，分析仅需合成汇总 |
| 医生个人标识用于绩效 | 医生代码仅为流程角色示例，不纳入个人评估 |
| 诊断、处方、医嘱、分诊优先级、治疗明细 | 超出本题范围 |

| 边界项 | 要求 |
