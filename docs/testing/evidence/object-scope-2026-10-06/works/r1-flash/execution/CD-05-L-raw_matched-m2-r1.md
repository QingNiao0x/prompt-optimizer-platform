# 提示词整理工具对照研究方案

## 1. 研究问题

本研究比较三种提示词准备条件对下游任务输出质量的影响：原始需求直接输入、直接增强提示词、交互式计划确认后生成提示词。研究不评价任何产品绝对优劣，只考察在相同初始材料下，不同提示词整理方式是否带来可观察的输出差异。交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答，再生成最终提示词，不是静态任务分解列表。

## 2. 实验设计

### 2.1 条件与分组

设四个条件组：

- **A组（原始组）**：下游模型直接接收原始需求与初始材料。
- **B组（直接增强组）**：下游模型接收由同一初始信息生成的优化提示词，不经历交互问答。
- **C组（计划确认组）**：系统先提问，操作者按答案卡作答，系统据此生成最终提示词后交给下游模型。
- **D组（信息量匹配对照）**：下游模型接收与C组相同的已确认事实，但不经历本平台问答过程，用于区分新增信息与交互组织方式各自的影响。

A、B两组不得接触C组在交互阶段才确认的业务选择。D组获得与C组等量的已确认事实，但不经历问答交互，以排除“多得到答案”本身对结果的混淆。

### 2.2 任务与重复

固定二十个任务，覆盖开发方案类与写作交付类。开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本。跨任务不采用代码测试通过率作为统一质量指标。每个条件对每个任务独立重复三次，开启隔离会话，随机化执行顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本，首轮失败必须保留。

### 2.3 材料与来源标签

所有条件获取相同初始材料。任务材料保留真实实现、用户说明、测试示例与待办等来源标签，不在人工评分前人为删除不利的测试污染反例。

### 2.4 盲评

两名盲评者独立评分。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源。评审可查看任务事实，但不能查看另一名评审先前评分。

## 3. 主要指标

评分同时覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。工具生成速度作为过程指标单独记录，质量分作为结果指标。没有计费日志时不估算真实Token成本，不把字符数直接换算为实际费用。

一个错误可能同时影响多个维度，评分表记录主错误和关联维度，避免将同一问题多次计成不同独立失败。

## 4. 统计与限制

候选统计方法依赖分数是否有序、是否连续和是否重复测量。本方案只规定选择流程：先检查分数分布性质，再根据重复测量结构选择相应方法，不在变量尚未确定时锁定某个显著性检验。

即使三个条件给出相似结论也不是研究完成证据。方案安排人工评阅与可复核任务标准，专业领域判断尚需专家参与。

## 5. 预注册待确认项

交互式计划确认的最大提问轮次和终止规则尚未预注册，不指定3轮或5轮。两名盲评者的分歧处理与一致性评价方式尚未确定，不预设平均、共识或第三评审。此两项列入附表待确认清单，待确定后补充预注册。
