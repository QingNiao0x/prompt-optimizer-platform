# 1. 研究方案主文

## 研究问题

本研究比较三种提示词准备方式对下游任务输出质量的影响：原始需求、直接增强、交互式计划确认增强。核心问题不是“某产品是否更好”，而是：在相同初始信息下，不同整理方式是否改变下游输出的需求保真、业务规则遵守、输出可用性、阅读负担和执行边界；当交互式确认带来新增业务事实时，收益应归因于新增信息还是交互组织方式。

## 实验设计

采用四组对照。原始组接收原始需求与初始材料。直接增强组接收由同一初始信息生成的优化提示词，不接触计划确认组后来回答的业务选择。计划确认组由系统先提问，实验操作者按预先制定答案卡作答，再生成最终提示词；记录每个问题、选项、推荐依据和答案，错误推荐被答案纠正后仍计入交互阶段风险。信息量匹配对照获得与计划确认组相同的已确认事实，但不经历问答过程，用于分离新增信息与交互组织方式的影响。

二十个任务覆盖开发方案与写作交付两类，每任务每条件独立重复三次，共 240 个下游输出。重复会话隔离，随机化顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本。两名盲评者独立评分，评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可查看任务事实，但不能看另一名评审先前评分。

任务材料保留真实实现、用户说明、测试示例与待办来源标签，不在人工评分前人为删除不利的测试污染反例。开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本，因此跨任务不能用代码测试通过率作为统一质量指标。

## 主要指标

结果指标为五维质量分：需求保真、业务规则、输出可用性、阅读负担、执行边界。过程指标仅记录工具生成速度，不进入质量比较。没有计费日志时不估算真实 Token 成本，不把字符数换算成实际费用。一个错误可能同时影响多个维度，评分表记录主错误和关联维度，避免同一问题多次计成不同独立失败。

统计方法选择流程：先确认分数是否有序、是否连续、是否重复测量，再据此选择候选检验；在变量性质未确定前不锁定某个显著性检验。即使三个模型给出相似结论也不是研究完成证据，需安排人工评阅与可复核任务标准，专业领域判断尚需专家参与。

## 限制

本研究为尚未执行的方案，无准确率、显著性、成功案例数量和用户结论。资料均为合成演练资料，不代表真实单位、患者、当事人、市场或平台运行数据。未决条件见预注册待确认清单。


# 2. 变量与分组附表

## 2.1 分组定义

| 组别 | 接收信息 | 是否经历交互问答 | 信息量口径 |
|---|---|---|---|
| A 原始组 | 原始需求 + 初始材料 | 否 | 仅初始信息 |
| B 直接增强组 | 同一初始信息生成的优化提示词 | 否 | 仅初始信息 |
| C 计划确认组 | 初始信息 + 问答确认后生成的最终提示词 | 是 | 初始信息 + 已确认事实 |
| D 信息量匹配对照 | 初始信息 + 与 C 组相同的已确认事实（以非交互方式注入） | 否 | 初始信息 + 已确认事实 |

比较逻辑：A 与 B 比较整理方式本身；C 与 D 比较交互组织方式；B 与 D 比较新增信息量；A 与 C 的差异不得单独解释为模型能力，须结合 D 组分解。

## 2.2 固定参数

| 参数 | 值 | 状态 |
|---|---|---|
| 任务数 | 20 | 已定 |
| 每条件独立重复 | 3 | 已定 |
| 盲评者 | 2 名，独立评分 | 已定 |
| 总下游输出数 | 20 × 4 × 3 = 240 | 已定 |
| 会话隔离 | 每次重复开启隔离会话 | 已定 |
| 随机化 | 条件顺序随机化 | 已定 |

| 失败处理 | 首轮失败保留，重试不替代 | 已定 |

# 3. 评分表及失败记录模板

## 3.1 五维评分表

| 维度 | 定义 | 评分范围 | 评分类型 |
|---|---|---|---|
| 需求保真 | 输出是否完整覆盖原始需求中明确要求的内容 | 1–5 | 有序离散 |
| 业务规则 | 输出是否遵守任务给定的业务约束和规则 | 1–5 | 有序离散 |
| 输出可用性 | 输出是否可直接用于后续工作，无需二次整理 | 1–5 | 有序离散 |
| 阅读负担 | 输出结构是否清晰，冗余和无关内容是否受控 | 1–5 | 有序离散 |
| 执行边界 | 输出是否在授权范围内，未越权执行或遗漏必要边界说明 | 1–5 | 有序离散 |

评分锚点：1=严重缺陷，输出不可用；3=基本可用但有明显问题；5=无明显缺陷。评分类型为有序离散，是否连续需在预注册阶段确认。

## 3.2 失败记录模板

| 字段 | 说明 |
|---|---|
| 样本编号 | 任务编号-组别-重复序号 |
| 失败类型 | 工具失败 / 首轮失败 / 下游输出质量失败 |
| 主错误描述 | 最主要的一个错误 |
| 主错误维度 | 需求保真 / 业务规则 / 输出可用性 / 阅读负担 / 执行边界 |
| 关联维度 | 同一错误同时影响的其他维度 |
| 是否重试 | 是 / 否 |
| 重试样本编号 | 若重试，记录新样本编号 |
| 首轮失败是否保留 | 是，必须保留 |
| 备注 | 其他说明 |

## 3.3 盲评规则

| 规则 | 说明 |
|---|---|
| 匿名化 | 不展示产品名称、标志、生成来源 |
| 等量任务信息 | 评审可查看任务事实，但各组展示的信息量一致 |
| 独立评分 | 两名评审不能查看对方先前评分 |
| 分歧处理 | 待预注册确认 |
