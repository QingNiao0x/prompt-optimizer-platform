### 待确认项（仅保留真正影响任务目标的业务决定）

1. **未到诊观察窗口**：一个预约事件在就诊时间后多久可归为最终状态？窗口未定前，尚未到期的预约只展示为待核验，不计入爽约率。
2. **取消免责边界**：取消在就诊前多少小时发生可视为免责取消？该边界与下方“取消提前量规则争议”相关，但需机构明确批准。
3. **渠道比较主统计单位**：以预约事件为主，还是以去重患者为主？两者口径不同，结论可能不同。
4. **取消提前量规则**：旧流程说明为24小时，新会议草稿建议12小时且尚未批准。两份材料权威性未建立，不能按文件修改时间断定新规则生效。报告需将争议单独呈现，不擅自采用其中一项。

## 二、流程图说明

### 2.1 预约事件生命周期（运营视角）

```
预约创建
  │
  ├─ 渠道记录：电话 / 网页 / 窗口
  │     └─ 注意：同一预约可能有多次操作事件
  │           须定义“首次渠道”和“变更渠道”
  │
  ▼
预约变更（可选）
  │
  ├─ 取消：系统记录到用户主动取消
  │     └─ 取消时间与就诊时间均为医院本地时区
  │     └─ 是否免责取决于“取消免责边界”（待确认）
  │
  ▼
就诊时间到达
  │
  ├─ ARRIVED：到诊
  ├─ CANCELLED：已取消
  └─ UNKNOWN：原因未细分
        └─ 可能来自设备同步延迟、现场漏登记或记录缺项
        └─ 缺少来源核查时，不解释为患者责任
  │
  ▼
观察窗口（待确认）
  │
  ├─ 窗口内：待核验事件，不纳入爽约率
  └─ 窗口结束：可归为最终状态
        └─ 未到诊且非免责取消 → 爽约（定义待确认）
```

### 2.2 渠道比较流程

```
原始预约事件
  │
  ├─ 步骤1：识别同一预约的多次操作事件
  ├─ 步骤2：定义首次渠道与变更渠道
  ├─ 步骤3：确定主统计单位（事件 / 去重患者）——待确认
  ├─ 步骤4：按渠道汇总
  │     └─ 小样本渠道：保留数量与限制说明
  └─ 步骤5：比较到诊、取消、UNKNOWN 分布
        └─ 不报告显著差异，除非数据完整且口径一致
```

### 2.3 取消规则争议处理流程

```
取消提前量规则
  │
  ├─ 旧流程说明：提前24小时取消不计爽约
  ├─ 新会议草稿：建议提前12小时，尚未批准
  │
  ▼
不按文件修改时间断定新规则生效
  │
  ▼
报告中将两种口径并列展示
  │
  ▼
等待机构明确批准后，再统一应用
```
