# 合成门诊预约到诊与爽约运营分析方案（二〇二六年第一季度）

> 本方案为内部运营资料分析与写作方案，仅用于讨论预约到诊与爽约情况。全部内容基于合成材料，标注为方法草案，须经专业评审后方可应用。不涉及诊断、处方、分诊优先级、医嘱或个体治疗，不包含真实患者或医生可识别信息。


## 一、口径梳理

### 1.1 分析对象与时间范围

| 项目 | 口径 |
|---|---|
| 研究对象 | 某合成门诊在二〇二六年第一季度的预约事件 |
| 数据来源 | 合成门诊预约汇总字典及流程材料（materials/hospital_operations/current-brief.md） |
| 预约事件标识 | 预约事件编号，可区分一次预约 |
| 患者与事件关系 | 一个患者可以多次预约，事件数不等于人数 |
| 时间基准 | 预约取消时间与就诊时间均用医院本地时区；当前汇总表没有时区转换证据，不得自行推断转换 |

### 1.2 预约渠道口径

| 渠道 | 口径说明 |
|---|---|
| 电话 | 已明确为三类渠道之一，不再询问 |
| 网页 | 已明确为三类渠道之一，不再询问 |
| 窗口 | 已明确为三类渠道之一，不再询问 |

**关键边界（来自 current-brief.md）：** 电话预约与网页预约可能记录相同一次预约的不同操作事件。渠道比较必须先定义"首次渠道"和"变更渠道"，不能把操作次数当成预约量。

**待确认项（影响渠道比较分母与结论表述）：** 比较电话、网页、窗口三类渠道时，主统计单位用预约事件还是去重患者，当前尚未决定。在未确定前，渠道比较不得混同两种单位，也不得默认采用其中一种。

### 1.3 到诊状态口径

| 状态 | 定义 | 分析处理 |
|---|---|---|
| ARRIVED | 系统记录已到诊 | 计入到诊 |
| CANCELLED | 系统记录用户主动取消 | 单独统计，不计入爽约；不得附加临床解释（不意味着治疗结束、病情缓解或不再需要服务） |
| UNKNOWN | 到诊状态未知 | **不得直接计为爽约**；原因未细分，可能来自设备同步延迟、现场漏登记或记录缺项；在缺少来源核查时，不能解释为患者责任 |

### 1.4 爽约判定口径（受未决条件约束）

**已知事实：**
- 观察窗口决定一个预约事件何时可以归为最终状态。
- 窗口未确定前，只应展示待核验事件，不应将尚未到期的预约算入爽约率。
- 不能因到期就自动视为最终状态。

**资料差异（并列呈现，不擅自采用任一取值）：**

| 来源 | 内容 | 状态 |
|---|---|---|
| materials/hospital_operations/legacy-note.md | 旧流程说明：提前24小时取消不计爽约 | 旧版草稿 |
| materials/hospital_operations/legacy-note.md | 新会议草稿建议：提前12小时，尚未批准 | 未批准草稿 |

两份材料的适用口径和审批状态应按本题说明核对，不能只凭日期决定，也不能按文件修改时间直接断定新规则生效。

**待确认项（影响爽约率分母、待核验事件范围及报告结论口径）：** 预约未到诊的观察窗口和取消免责边界应如何定义，当前尚未决定。在未确定前，爽约率不得计算为最终结论，只能以"待核验事件"形式呈现。

### 1.5 统计单位口径

| 单位 | 适用场景 | 限制 |
|---|---|---|
| 预约事件 | 以事件编号计数 | 事件数不等于人数 |
| 去重患者 | 以患者唯一标识去重计数 | 与事件数不可混同 |

**待确认项：** 主统计单位尚未选择。在未确定前，报告中凡涉及渠道比较、到诊率、爽约率等指标，须同时注明所用单位，或暂缓出具结论性比较。

### 1.6 指标定义草案（待上述未决条件确定后方可计算）

| 指标 | 分子 | 分母 | 当前状态 |
|---|---|---|---|
| 到诊率 | 状态为 ARRIVED 的事件数（或患者数） | 纳入统计的预约事件总数（或去重患者总数） | 分母口径待定 |
| 取消率 | 状态为 CANCELLED 的事件数（或患者数） | 同上 | 分母口径待定 |
| 待核验率 | 状态为 UNKNOWN 且尚未超出观察窗口的事件数 | 同上 | 观察窗口待定 |
| 爽约率 | 超出观察窗口且状态仍为 UNKNOWN 的事件数（须经来源核查确认非登记缺项） | 同上 | **当前不得计算**，观察窗口与取消免责边界均未确定 |

**缺失值与不确定性说明：**
- UNKNOWN 状态的原因没有细分，无法区分设备同步延迟、现场漏登记或记录缺项。
- 当前汇总表没有时区转换证据，跨时区比较不可行。
- 小渠道样本较少时，百分比波动大，应保留数量和限制说明；没有完整数据不能报告显著的渠道差异。


## 二、流程图说明

### 2.1 预约事件状态流转（基于已知事实）

```
预约事件创建
    │
    ├── 记录首次渠道（电话/网页/窗口）
    │
    ├── 可能发生渠道变更（电话↔网页可能记录同一预约的不同操作事件）
    │        │
    │        └── 需定义"首次渠道"与"变更渠道"，不得将操作次数计为预约量
    │
    ├── 状态更新
    │        ├── ARRIVED ──────────────→ 计入到诊
    │        ├── CANCELLED ────────────→ 单独统计，不计入爽约
    │        └── UNKNOWN ──────────────→ 进入待核验池
    │                                        │
    │                     ┌──────────────────┴──────────────────┐
    │                     │                                     │
    │             观察窗口未确定                          观察窗口确定后
    │                     │                              （当前不适用）
    │                     │                                     │
    │             仅展示为待核验事件                    须经来源核查区分：
    │             不计入爽约率                          · 登记缺项/同步延迟 → 修正记录
    │                                                   · 确认为未到诊 → 按既定规则判定
    │
    └── 取消时间与就诊时间均为医院本地时区；无时区转换证据，不做跨时区推断
```

### 2.2 流程说明要点

1. **渠道识别环节：** 同一预约事件可能因电话与网页操作产生多条记录。分析前须先按预约事件编号归并，再定义首次渠道与变更渠道。操作次数不等于预约量。
2. **状态判定环节：** UNKNOWN 状态在观察窗口未确定前，一律归入"待核验事件"，不进入爽约率计算。
3. **取消环节：** CANCELLED 仅表示系统记录到用户主动取消，不附加任何临床解释。
4. **时间环节：** 所有时间字段以医院本地时区为准；当前汇总表没有时区转换证据，不得自行推断或转换。


## 三、合成数据采集字段建议

> 以下为拟议采集表字段，实施前仍需合规评估；不能写成已经建表或已获得数据授权。

### 3.1 基础字段

| 字段名 | 类型 | 说明 | 是否必需 |
|---|---|---|---|
| 预约事件编号 | 字符串 | 唯一标识一次预约 | 必需 |
| 患者匿名标识 | 字符串（去标识化） | 用于去重患者统计；不得包含可识别信息 | 必需 |
| 预约创建时间 | 日期时间（本地时区） | 用于确定事件归属季度 | 必需 |
| 就诊时间 | 日期时间（本地时区） | 用于观察窗口计算 | 必需 |
| 到诊状态 | 枚举：ARRIVED / CANCELLED / UNKNOWN | 当前状态 | 必需 |
| 状态更新时间 | 日期时间（本地时区） | 用于判断状态是否为最终状态 | 建议增加 |
| 取消时间 | 日期时间（本地时区，可空） | 仅 CANCELLED 状态填写 | 建议增加 |
| 来源系统 | 枚举：电话系统 / 网页系统 / 窗口系统 | 用于识别操作事件来源 | 建议增加 |

### 3.2 渠道归并字段

| 字段名 | 类型 | 说明 | 是否必需 |
|---|---|---|---|
| 首次渠道 | 枚举：电话 / 网页 / 窗口 | 按预约事件编号归并后确定；定义规则待业务确认 | 必需（用于渠道比较） |
| 变更渠道 | 枚举：电话 / 网页 / 窗口（可空） | 记录是否存在渠道变更及变更后渠道 | 建议增加 |
| 操作事件计数 | 整数 | 同一预约事件下的操作记录数，用于识别重复记录 | 建议增加 |

### 3.3 待核验与复核字段

| 字段名 | 类型 | 说明 | 是否必需 |
|---|---|---|---|
| 待核验标记 | 布尔 | 状态为 UNKNOWN 且观察窗口未确定或未超窗时标记为待核验 | 必需 |
| 核验结果 | 枚举（可空）：登记缺项 / 同步延迟 / 确认未到诊 / 其他 | 人工复核后填写 | 建议增加 |
| 核验时间 | 日期时间（可空） | 人工复核完成时间 | 建议增加 |
| 核验人匿名标识 | 字符串（去标识化） | 用于追溯，不含个人可识别信息 | 建议增加 |

### 3.4 明确不采集的字段

- 患者姓名、身份证号、联系方式、住址等可识别信息
- 医生姓名、医生个人绩效相关字段
- 诊断、处方、医嘱、分诊优先级、治疗明细等临床信息
- 任何受保护路径或凭据信息（.env、密钥、Token 等）

## 五、人工复核及隐私边界清单

### 5.1 人工复核清单

| 序号 | 复核事项 | 复核内容 | 触发条件 |
|---|---|---|---|
| 1 | UNKNOWN 状态来源核查 | 区分设备同步延迟、现场漏登记、记录缺项；不得直接归为患者责任 | 任何 UNKNOWN 状态事件进入分析 |
| 2 | 电话与网页重复记录归并 | 核查同一预约事件编号下的多条操作记录，确认首次渠道与变更渠道 | 渠道比较分析前 |
| 3 | 取消时间与就诊时间时区核验 | 确认均为医院本地时区，无跨时区转换需求 | 涉及时间计算前 |
| 4 | 观察窗口适用性核验 | 确认观察窗口是否已由业务方正式确定；未确定前不得计算爽约率 | 任何爽约相关计算前 |
| 5 | 取消免责边界核验 | 确认采用24小时还是12小时规则，须有正式审批依据 | 取消相关统计前 |
| 6 | 统计单位核验 | 确认渠道比较使用预约事件还是去重患者 | 渠道比较结论出具前 |
| 7 | 小样本渠道核验 | 样本量过小的渠道不报告显著差异，保留数量和限制说明 | 渠道比较分析时 |
| 8 | 数据授权与合规核验 | 拟议采集表新增字段（状态更新时间、取消时间、来源系统）实施前须合规评估 | 建表或数据采集前 |

### 5.2 隐私边界清单

| 边界 | 要求 |
|---|---|
| 患者信息 | 仅使用匿名标识，不采集、不展示姓名、身份证号、联系方式、住址等可识别信息 |
| 医生信息 | 医生代码仅为流程角色示例，不追加医生排行榜，不利用服务时间做个体能力评价 |
| 临床信息 | 不采集、不分析诊断、处方、分诊优先级、医嘱、治疗明细 |
| 取消行为解释 | 不将取消状态附加临床解释（不意味着治疗结束、病情缓解或不再需要服务） |
| 整改建议边界 | 不默认采取罚款、降低预约资格或公开患者记录；优先考虑清楚提示取消规则、核对登记质量与便捷改约 |
| 短信提醒 | 如后续要求短信提醒方案，须另行确认通知授权和退订流程；本次不扩成实施任务 |
| 受保护路径 | 禁止读取或输出 .env、**/*.pem、**/*.key、生产环境配置 |
| 敏感操作 | 删除或覆盖文件、数据库结构迁移、升级核心依赖、生产环境部署须先获得人工确认 |
