**数据来源：** materials/hospital_operations/current-brief.md 所载合成汇总信息；无真实患者信息，无完整逐条数据。

### 1.2 流程图说明（文字版）

```
预约事件产生
    │
    ├─ 记录首次渠道（电话/网页/窗口）
    │        │
    │        └─ 同一事件编号后续出现不同渠道 → 标记为变更渠道
    │
    ├─ 到诊状态记录
    │        ├─ ARRIVED → 到诊
    │        ├─ CANCELLED → 需核对取消时间与就诊时间差
    │        │        ├─ 差值 ≥ 免责边界 → 不计爽约（边界待确认）
    │        │        └─ 差值 < 免责边界 → 是否计爽约（边界待确认）
    │        └─ UNKNOWN → 待核验，不直接计为爽约
    │
    └─ 观察窗口判断
             ├─ 已过观察窗口 → 可归为最终状态
             └─ 未过观察窗口 → 待核验事件，不计入爽约率分母
```

**流程说明要点：**
- 电话与网页可能记录同一预约的不同操作事件，渠道统计时以预约事件编号为归并键，先定义首次渠道和变更渠道，不把操作次数当成预约量。
- UNKNOWN 状态可能来自设备同步延迟、现场漏登记或记录缺项，在缺少来源核查时不能解释为患者责任。
- 取消状态表示系统记录到用户主动取消，不意味着治疗结束或病情缓解；分析报告不给取消行为附加临床解释。

## 三、拟议数据采集表字段建议

**合规前提：** 以下为拟议字段，实施前需完成合规评估；未写成已建表或已获数据授权。

| 字段名 | 类型 | 用途 | 是否含敏感信息 |
|---|---|---|---|
| 预约事件编号 | 脱敏ID | 唯一标识一次预约，归并渠道操作 | 否（脱敏后） |
| 患者脱敏编号 | 脱敏ID | 区分去重患者（若Q3选择患者口径） | 否（脱敏后） |
| 首次渠道 | 枚举：电话/网页/窗口 | 渠道比较的基准 | 否 |
| 变更渠道标记 | 布尔/枚举 | 识别同一事件下的渠道变更 | 否 |
| 预约创建时间 | 日期时间（医院本地时区） | 判断事件时间顺序 | 否 |
| 就诊时间 | 日期时间（医院本地时区） | 计算取消提前量、判断观察窗口 | 否 |
| 到诊状态 | 枚举：ARRIVED/CANCELLED/UNKNOWN | 核心结果变量 | 否 |
| 状态更新时间 | 日期时间（医院本地时区） | 判断观察窗口是否已过 | 否 |
| 取消时间 | 日期时间（医院本地时区，可空） | 计算取消提前量 | 否 |
| 来源系统 | 文本 | 核查 UNKNOWN 来源（设备/现场/记录） | 否 |

**说明：**
- 所有字段均不含患者姓名、联系方式、医生姓名、诊断、处方等可识别或敏感诊疗信息。
- 患者脱敏编号仅用于去重统计，不用于个体追踪或绩效评价。
- 医生代码不在采集范围内；不追加医生排行榜或个体能力评价。
