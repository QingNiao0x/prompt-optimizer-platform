# 合成医院门诊预约运营分析方案（二〇二六年第一季度）

> 用途：内部运营分析讨论稿，仅针对预约到诊与爽约情况。  
> 数据性质：合成汇总数据，无真实患者信息，无完整逐条数据。  
> 本方案不涉及诊断、处方、分诊优先级、医嘱或个体治疗，不计算真实医院指标，不建议减少任何患者服务权益。


## 一、口径梳理

### 1.1 基础统计单位

| 口径项 | 当前状态 | 说明 |
|---|---|---|
| 预约事件 | 可区分一次预约 | 一个患者可多次预约，事件数 ≠ 人数 |
| 患者去重 | 未确定是否作为主统计单位 | 渠道比较时是否使用去重患者，尚待业务决定 |
| 主统计单位 | **待确认** | 预约事件与去重患者不得混同；在未确定前，报告应分别标注，不默认采用其一 |

### 1.2 到诊状态口径

| 状态 | 口径 | 是否可计为爽约 |
|---|---|---|
| ARRIVED | 系统记录到诊 | 否 |
| CANCELLED | 系统记录用户主动取消 | 否，且不得附加临床解释 |
| UNKNOWN | 原因未细分，可能来自设备同步延迟、现场漏登记或记录缺项 | **不得直接计为爽约** |

### 1.3 取消规则口径（存在差异，并列呈现）

| 来源 | 取消提前量 | 审批状态 |
|---|---|---|
| 旧流程说明（legacy-note.md） | 提前24小时取消不计爽约 | 旧版草稿/历史说明 |
| 新会议草稿 | 建议提前12小时 | **尚未批准** |

> 两份材料的适用口径和审批状态应按本题说明核对，不能只凭日期决定。报告须将差异单独呈现，不擅自采用其中一项。

### 1.4 观察窗口口径

| 口径项 | 当前状态 |
|---|---|
| 预约未到诊的观察窗口 | **尚未确定** |
| 取消免责边界 | **尚未确定** |

> 观察窗口决定一个预约事件何时可归为最终状态。窗口未确定前，只展示待核验事件，不应将尚未到期的预约算入爽约率。

### 1.5 渠道口径

| 口径项 | 说明 |
|---|---|
| 渠道类别 | 电话、网页、窗口三类，已明确 |
| 首次渠道与变更渠道 | 电话与网页可能记录同一预约的不同操作事件，渠道比较必须先定义首次渠道和变更渠道，不能把操作次数当成预约量 |
| 渠道比较主统计单位 | 待确认（见1.1） |

### 1.6 时区口径

| 口径项 | 说明 |
|---|---|
| 取消时间与就诊时间 | 均用医院本地时区 |
| 时区转换证据 | 当前汇总表没有时区转换证据，分析中不得假设已做转换 |


## 二、流程图说明（文字版）

### 2.1 预约事件状态流转（基于现有资料）

```
预约创建（电话/网页/窗口）
        │
        ▼
   ┌─────────────────────────┐
   │ 等待就诊                │
   └─────────────────────────┘
        │
        ├─── 用户主动取消 ────► CANCELLED（不附加临床解释）
        │
        ├─── 到诊记录 ────────► ARRIVED
        │
        └─── 无到诊记录 ──────► UNKNOWN（原因未细分）
                                     │
                                     ▼
                          待核验事件（观察窗口未确定前，
                          不归为最终状态，不计入爽约率）
```

### 2.2 渠道记录流程注意点

- 电话预约与网页预约可能记录同一预约的不同操作事件。
- 渠道比较前必须先定义"首次渠道"和"变更渠道"。
- 操作次数 ≠ 预约量，不得将多次操作记录重复计入预约事件数。

### 2.3 取消规则流程注意点

- 旧流程：提前24小时取消不计爽约。
- 新草稿：建议提前12小时，尚未批准。
- 在规则未定前，涉及取消免责边界的统计应同时标注两种口径，或标注"规则待定"。


## 三、拟议数据采集字段建议

> 以下为拟议采集字段，实施前仍需合规评估；不表示已经建表或已获得数据授权。

### 3.1 预约事件基础字段

| 字段名 | 建议类型 | 用途 | 是否含敏感信息 |
|---|---|---|---|
| 预约事件编号 | 文本/去标识化 | 区分一次预约 | 否 |
| 预约创建时间 | 日期时间（本地时区） | 计算提前量 | 否 |
| 预约就诊时间 | 日期时间（本地时区） | 判断观察窗口 | 否 |
| 预约渠道（首次） | 枚举：电话/网页/窗口 | 渠道分析 | 否 |
| 预约渠道（变更后） | 枚举：电话/网页/窗口，可空 | 渠道变更分析 | 否 |
| 到诊状态 | 枚举：ARRIVED/CANCELLED/UNKNOWN | 状态统计 | 否 |
| 状态更新时间 | 日期时间（本地时区） | 判断状态时效 | 否 |
| 取消时间 | 日期时间（本地时区），可空 | 取消提前量计算 | 否 |
| 来源系统 | 文本 | 区分记录来源，辅助UNKNOWN核查 | 否 |

### 3.2 不建议纳入的字段

| 字段 | 原因 |
|---|---|
| 患者姓名、证件号、联系方式 | 可识别信息，本次分析不需要 |
| 医生姓名、医生代码 | 医生代码仅为流程角色示例，不属个人绩效评估范围 |
| 诊断、处方、医嘱、治疗明细 | 超出本题范围，涉及临床信息 |
| 科室类型（跨科室） | 本题材料只有一个门诊，不推断跨科室表现 |

### 3.3 字段采集注意事项

- 状态更新时间与取消时间字段为拟议新增，实施前需合规评估。
- 来源系统字段用于辅助UNKNOWN状态核查，不用于推断患者责任。
- 所有时间字段应明确记录为医院本地时区，并保留时区转换证据（如未来涉及跨时区）。


## 四、运营讨论报告目录（草案）

### 合成门诊预约到诊与爽约情况运营分析报告（二〇二六年第一季度·讨论版）

**报告属性标注**：合成材料与方法草案，明确专业评审后才能应用；不宣称任何方案已提高疗效。

#### 1. 分析范围与数据说明
- 1.1 分析对象：合成门诊二〇二六年第一季度预约事件
- 1.2 数据性质：合成汇总数据，无真实患者信息，无完整逐条数据
- 1.3 不适用范围：临床判断、个体治疗、医生绩效、跨科室推断

#### 2. 口径与定义
- 2.1 预约事件与患者去重的关系（事件数 ≠ 人数）
- 2.2 到诊状态定义：ARRIVED / CANCELLED / UNKNOWN
- 2.3 UNKNOWN状态的处理原则：不直接计为爽约
- 2.4 取消规则差异：旧24小时 vs 新草稿12小时（并列呈现，标注审批状态）
- 2.5 观察窗口与取消免责边界：**待业务决定**
- 2.6 渠道比较的主统计单位：**待业务决定**
- 2.7 时区口径：本地时区，无转换证据

#### 3. 数据质量与待核验事项
- 3.1 UNKNOWN状态的可能来源（设备同步延迟、现场漏登记、记录缺项）

- 3.3 状态更新时间缺失对观察窗口判断的影响

#### 5. 流程问题清单

- 5.3 渠道变更记录不完整（首次渠道与变更渠道未定义）
- 5.4 观察窗口未定义导致状态判定延迟
- 5.5 时区转换证据缺失

#### 6. 改进建议（运营层面）
- 6.1 清楚提示取消规则（在预约确认环节明确告知）
- 6.2 核对登记质量（减少UNKNOWN状态）
- 6.3 便捷改约流程（降低取消后不再预约的情况）
- 6.4 明确观察窗口与取消免责边界的业务决定
- 6.5 明确渠道比较的主统计单位

## 五、人工复核及隐私边界清单

### 5.1 人工复核清单

| 复核项 | 复核内容 | 复核目的 |
|---|---|---|
| UNKNOWN状态抽样 | 抽取部分UNKNOWN事件，核对来源系统记录 | 区分设备延迟、漏登记、记录缺项，不归责于患者 |
| 渠道变更记录 | 核对电话与网页渠道是否存在同一预约的重复操作记录 | 避免操作次数被误计为预约量 |
| 取消时间完整性 | 核对CANCELLED事件是否均有取消时间记录 | 确保取消提前量可计算 |
| 状态更新时间 | 核对各状态是否有明确的状态更新时间 | 支持观察窗口判定 |
| 时区一致性 | 核对取消时间与就诊时间是否均为本地时区 | 避免时区混淆导致提前量计算错误 |
| 取消规则适用 | 核对涉及取消免责边界的统计是否同时标注两种口径 | 避免擅自采用未批准规则 |

### 5.2 隐私边界清单

| 边界项 | 要求 |
|---|---|
| 患者可识别信息 | 不采集、不展示姓名、证件号、联系方式 |
| 医生信息 | 医生代码仅为流程角色示例，不追加医生排行榜或个体能力评价 |
| 诊疗明细 | 不包含诊断、处方、医嘱、治疗明细 |
| 取消行为的临床解释 | 不将取消状态解释为治疗结束、病情缓解或不再需要服务 |
| UNKNOWN状态归责 | 不将UNKNOWN解释为患者责任 |
| 短信提醒 | 如后续要求短信提醒方案，需另行确认通知授权和退订流程；本次不扩成实施任务 |
| 数据授权 | 拟议采集表实施前需合规评估，不写成已经建表或已获得授权 |
