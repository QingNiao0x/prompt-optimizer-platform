# 提示词整理工具对照研究方案（未执行）

## 一、研究问题与目标

本研究比较三种提示词整理条件对下游任务输出的影响：原始需求（A组）、直接增强（B组）、交互式计划确认增强（C组），并增设信息量匹配对照（D组）。目标不是评价某家产品绝对优劣，而是区分“相同初始信息下的整理方式差异”与“额外获得已确认答案带来的信息量差异”。实验尚未运行，本方案不报告任何准确率、显著性、成功案例或用户结论。

## 二、设计

固定二十个任务，每条件独立重复三次，两名盲评者独立评分。所有工具获取相同初始材料。A组接收原始需求与初始材料；B组接收同一初始信息得到的优化提示词；A、B两组不得接触C组后来回答的业务选择。C组按预先制定答案卡进行提问—作答—生成最终提示词，并记录每个问题、选项、推荐依据和答案；错误推荐被答案纠正后仍计入交互阶段风险。D组获得与C组相同的已确认事实，但不经历本平台问答过程，用于减少“新增信息”与“交互组织方式”之间的混淆。

每个条件的三次重复开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本，首轮失败与工具失败均须保留。

## 三、材料与任务边界

任务材料保留真实实现、用户说明、测试示例与待办等来源标签，评分前不得删除不利的测试污染反例。开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本。因此跨任务不能用代码测试通过率作为统一质量指标，质量判断以人工评阅和可复核任务标准为主。专业领域判断尚需专家参与，三个模型给出相似结论也不构成研究完成证据。

## 四、评价指标

评价同时覆盖需求保真、业务规则、输出可用性、阅读负担和执行边界。工具生成速度作为过程指标，质量分作为结果指标；没有计费日志时不估算真实Token成本，不把字符数直接换算为费用。一个错误可能同时影响完整性与可执行性，评分表记录主错误和关联维度，避免同一问题被多次计为独立失败。

## 五、盲评与统计

评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可看任务事实，但不得看另一名评审先前评分。候选统计方法依赖分数是否有序、是否连续和是否重复测量；本方案只说明选择流程，不在变量尚未确定时锁定某个显著性检验。

## 六、限制与待确认

本研究尚未执行，无伦理审批、无引用出处、无统计显著性可报告。交互式计划确认的最大轮次和终止规则尚未预注册，不指定3轮或5轮，不把建议写成已确认参数。两名盲评者的分歧处理及一致性评价方式仍未确定，不预设平均、共识或第三评审。上述两项影响C组执行边界与评分汇总，须在预注册清单中先行确认后方可运行。
