# 提示词整理工具对照研究方案

## 一、研究问题

本研究考察同一初始需求材料下，三种提示词整理条件对下游任务输出质量的影响：原始需求直接使用、直接增强提示词、交互式计划确认后生成提示词。核心问题不是比较产品优劣，而是区分两类收益来源：新增业务信息本身带来的收益，与交互式组织方式带来的收益。为此设置信息量匹配对照，使计划确认组获得的已确认事实在信息量上可被单独分离。

## 二、实验设计

**任务与材料。** 固定二十个任务，覆盖开发方案类与文本交付类。每个任务保留四类来源标签：真实实现、用户说明、测试示例、待办事项；测试示例中的污染反例在评分前不得人为删除。开发类任务要求下游模型只输出方案、不修改仓库；写作类任务要求交付文本。因此跨任务不使用代码测试通过率作为统一质量指标。

**四个条件。** 条件A（原始组）接收原始需求与初始材料。条件B（直接增强组）接收基于同一初始信息生成的优化提示词，不接触计划确认组后续回答的业务选择。条件C（计划确认组）先经历系统提问，实验操作者按预先制定答案卡作答，系统再生成最终提示词；记录每个问题、选项、推荐依据和答案，错误推荐被答案纠正后仍计入交互阶段风险。条件D（信息量匹配对照）获得与条件C相同的已确认事实，但不经历问答过程，用于分离新增信息与交互组织方式的混淆。

**重复与隔离。** 每个条件对每个任务独立重复三次，共240次生成。每次重复开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本；工具失败和首轮失败均保留在记录中。

## 三、盲评与指标

两名盲评者独立评分，互不知晓对方评分。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源。评分覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。一个错误可能同时影响多个维度，评分表记录主错误和关联维度，避免同一问题重复计为独立失败。

工具生成速度作为过程指标单独记录，质量分为结果指标。无计费日志时不估算真实Token成本，不以字符数换算费用。

## 四、统计与限制

统计方法的选择流程为：先确认评分是否有序、是否连续、是否重复测量，再据此选定检验方法；在变量性质未确定前不锁定具体显著性检验。即使三个条件给出相似结论，也不构成研究完成证据；需人工评阅与可复核任务标准，专业领域判断尚需专家参与。

本方案尚未运行，不含准确率、显著性、成功案例数量或用户结论。交互式计划确认的最大轮次与终止规则、两名盲评者的分歧处理与一致性评价方式均未确定，列入预注册待确认清单，不预设默认值。

## 附表一：变量与分组

| 条件 | 初始信息 | 交互问答 | 已确认事实注入 | 重复次数 | 会话隔离 |
|---|---|---|---|---|---|
| A 原始组 | 原始需求+初始材料 | 否 | 否 | 3 | 是 |
| B 直接增强组 | 同一初始信息生成的优化提示词 | 否 | 否 | 3 | 是 |

**固定量：** 任务数20；每条件每任务重复3次；盲评者2名；评分维度5项。

**记录字段（条件C）：** 问题文本、选项列表、系统推荐依据、操作者答案、是否纠正推荐、最终提示词、交互轮次、终止原因。

**记录字段（全部条件）：** 模型版本、日期、参数、生成耗时、失败状态、首轮失败标记、重试次数。
