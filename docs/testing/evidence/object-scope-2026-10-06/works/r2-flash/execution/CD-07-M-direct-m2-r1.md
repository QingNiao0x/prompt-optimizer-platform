### 1.3 爽约的操作性定义（仅用于讨论，不冒充已选方法）

- **已到诊**：状态为 ARRIVED。
- **已取消**：状态为 CANCELLED。
- **待核验**：状态为 UNKNOWN，或观察窗口未到期，或取消时间与就诊时间的间隔落在24小时与12小时之间（该区间受取消免责边界争议影响）。
- **爽约候选**：状态为 UNKNOWN 且观察窗口已到期且经登记质量核查确认非系统/登记问题。**UNKNOWN 不直接计为爽约。**


## 二、流程图说明

### 2.1 预约事件状态流转（基于现有资料可确认部分）

```
预约事件产生（电话/网页/窗口）
        │
        ▼
  记录首次渠道与变更渠道（渠道比较前必须定义）
        │
        ▼
  到诊状态记录
   ├── ARRIVED ──────────────► 到诊
   ├── CANCELLED ────────────► 取消（记录取消时间）
   │                              │
   │                              ▼
   │                    与就诊时间比较取消提前量
   │                    ├── ≥24小时：旧流程不计爽约
   │                    ├── ≥12小时且<24小时：新旧规则争议区间
   │                    └── <12小时：待核验（是否计爽约取决于采用哪版规则）
   │
   └── UNKNOWN ──────────────► 待核验
          │
          ▼
   观察窗口是否到期？
   ├── 未到期 ──► 待核验事件，不纳入爽约率
   └── 已到期 ──► 登记质量核查
                 ├── 系统/登记问题 ──► 数据质量修正，不计患者爽约
                 └── 确认未到且未取消 ──► 爽约候选（需结合取消免责边界）
```

### 2.2 渠道比较流程（操作次数≠预约量）

```
原始操作事件流（电话/网页/窗口）
        │
        ▼
按预约事件编号归并
        │
        ▼
定义首次渠道（该预约事件第一次出现的渠道）
定义变更渠道（同一预约事件后续出现的不同渠道）
        │
        ▼
按主统计单位分别汇总：
  ├── 口径A：按预约事件数（去重后的事件）
  └── 口径B：按去重患者数（一个患者多次预约只计一次）
        │
        ▼
并列展示，不合并、不默认选定
```

### 3.2 采集表使用说明

- 状态更新时间和取消时间为拟新增字段，用于支撑观察窗口和取消提前量的计算。
- 来源系统字段用于核查电话与网页操作事件是否属于同一预约事件。
- 登记方式字段用于区分 UNKNOWN 是数据质量问题还是真实未到诊。
- 所有字段均不含患者姓名、联系方式、诊断、处方等可识别或敏感信息。
