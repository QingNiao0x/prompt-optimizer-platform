# 提示词整理工具对照研究方案

## 1. 研究方案主文

### 研究问题

本方案研究三种提示词准备条件对下游任务输出质量的影响：原始需求条件、直接增强条件、交互式计划确认增强条件。交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答，再生成最终提示词，不是静态任务分解列表。研究不评价任何产品的绝对优劣，只比较条件间差异。

### 实验设计

采用四组对照设计。原始组接收原始需求与初始材料。直接增强组接收由同一初始信息生成的优化提示词。计划确认组经历问答过程，记录每个问题、选项、推荐依据和答案，再生成最终提示词。信息量匹配对照获得与计划确认组相同的已确认事实，但不经历问答过程，用于区分新增信息与交互组织方式各自的影响。

二十个任务、每个条件独立重复三次、两名盲评者已确定。每个条件的三次重复开启隔离会话，随机化顺序并记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本。

任务材料保留真实实现、用户说明、测试示例与待办这几种来源标签；不能在人工评分前人为删除不利的测试污染反例。开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本，因此跨任务不能用代码测试通过率作为统一质量指标。

评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可看任务事实，但不能看另一名评审先前评分。

### 主要指标

质量分是结果指标，覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。工具生成速度是过程指标，单独记录，不与质量分混算。没有计费日志时不能估算真实 Token 成本，不能把字符数直接换算成实际费用。

评分表记录主错误与关联维度，避免同一问题被多次计成独立失败。保留工具失败和首轮失败记录。

### 限制

实验尚未运行，没有准确率、显著性、成功案例数量和用户结论。候选评价统计方法依赖分数是否有序、是否连续和是否重复测量；方案可说明选择流程，不应在变量尚未确定时锁定某个显著性检验。即使三个模型给出相似结论也不是研究完成证据；方案应安排人工评阅与可复核任务标准，特别说明专业领域判断尚需专家参与。

## 2. 变量与分组附表

| 条件 | 接收信息 | 是否经历问答 | 是否获得已确认事实 | 重复次数 | 随机化安排 |
|---|---|---|---|---|---|
| 原始组 | 原始需求与初始材料 | 否 | 否 | 3 | 隔离会话，随机化顺序，记录模型版本、日期和参数 |
| 直接增强组 | 同一初始信息生成的优化提示词 | 否 | 否 | 3 | 同上 |
| 计划确认组 | 原始需求与初始材料 + 问答记录（问题、选项、推荐依据、答案）+ 最终提示词 | 是 | 是 | 3 | 同上 |
| 信息量匹配对照 | 原始需求与初始材料 + 相同已确认事实（不经问答） | 否 | 是 | 3 | 同上 |

说明：原始组和直接增强组都不能偷看计划确认组后来回答的业务选择。信息量匹配对照用于减少新增信息与交互组织方式之间的混淆。错误推荐被答案纠正后仍应计入交互阶段风险。

## 3. 评分表及失败记录模板

### 评分维度

| 维度 | 定义 | 评分范围 |
|---|---|---|
| 需求保真 | 输出是否忠实反映原始需求中明确提出的目标与约束 | 待定（有序/连续待确认） |
| 业务规则 | 输出是否遵守任务材料中直接说明的业务条件与边界 | 待定 |
| 输出可用性 | 输出是否可直接用于下游任务，无需额外澄清或返工 | 待定 |
| 阅读负担 | 输出长度、结构与冗余是否合理，不因过度压缩丢失必要信息 | 待定 |
| 执行边界 | 输出是否明确区分方案与执行，不越界修改仓库或交付非文本产物 | 待定 |
