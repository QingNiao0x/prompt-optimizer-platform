# 提示词整理工具对照研究方案（未执行）

## 一、研究问题与目标

本研究比较三种提示词整理条件对下游任务输出的影响：原始需求（A组）、直接增强（B组）、交互式计划确认增强（C组），并增设信息量匹配对照（D组）。目标不是评价某家产品绝对优劣，而是分离“新增已确认信息”与“交互组织方式”两类效应。所有工具获得相同初始材料；A、B组不得接触C组后续回答的业务选择。

## 二、设计

固定二十个任务，每条件独立重复三次，隔离会话，随机化顺序，记录模型版本、日期与参数。两名盲评者独立评分，不暴露工具名称、标志与生成来源。C组由系统先提问，实验操作者按预先制定答案卡作答，再生成最终提示词；须记录每个问题、选项、推荐依据和答案，错误推荐被答案纠正后仍计入交互阶段风险。D组获得相同已确认事实，但不经历本平台问答过程，用于减少新增信息与交互组织方式的混淆。

任务材料保留真实实现、用户说明、测试示例与待办来源标签；人工评分前不得删除不利的测试污染反例。开发任务只要求下游模型输出方案，不实际修改仓库；写作任务交付文本。跨任务不得以代码测试通过率作为统一质量指标。

## 三、主要指标

评价覆盖需求保真、业务规则、输出可用性、阅读负担、执行边界。质量分为结果指标，生成速度为过程指标。无计费日志时不得估算真实Token成本，不得将字符数换算为费用。一个错误可同时影响完整性与可执行性，评分表记录主错误与关联维度，避免同一问题重复计为独立失败。失败与首轮失败必须保留，重试不得替代第一份失败样本。

## 四、分析与限制

统计方法依分数是否有序、连续及是否重复测量选择，方案只说明选择流程，不预先锁定显著性检验。实验尚未运行，无准确率、显著性、成功案例或用户结论。三个模型结论相似不构成研究完成证据；专业领域判断尚需专家参与。人工评阅与可复核任务标准须保留。

## 五、待确认

交互式计划确认最大轮次与终止规则尚未决定，不得默认补全；两名评审分歧处理与一致性评价方式尚未决定，不得默认补全。两项均影响预注册与执行，须在正式运行前明确。
