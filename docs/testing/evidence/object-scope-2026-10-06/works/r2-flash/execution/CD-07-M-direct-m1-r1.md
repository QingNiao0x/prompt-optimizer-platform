# 合成门诊预约到诊与爽约分析方案（讨论稿）

### 1.2 指标定义（并列口径，不默认补全）

| 指标 | 分子 | 分母 | 缺失值处理 | 时间边界 | 状态 |
|---|---|---|---|---|---|
| 到诊率 | ARRIVED 事件数 | 已到期且状态明确的预约事件数 | UNKNOWN 单列，不并入分子或分母 | 观察窗口内 | 分母口径待确认 |
| 取消率 | CANCELLED 事件数 | 已到期且状态明确的预约事件数 | 同上 | 观察窗口内 | 分母口径待确认 |
| 爽约率 | **不直接定义**：UNKNOWN 不得计为爽约 | — | UNKNOWN 仅作待核验事件展示 | 观察窗口未定前不计算 | 待确认 |
| 待核验事件量 | UNKNOWN 事件数 | 全部预约事件数 | 保留原始数量 | 观察窗口未到期 | 可展示 |
| 渠道分布 | 各渠道事件数 | 全部预约事件数 | 小渠道保留数量与限制说明 | 全季度 | 可展示，不报告显著差异 |

### 1.3 渠道比较口径（必须先定义，不能把操作次数当预约量）

| 概念 | 定义 | 说明 |
|---|---|---|
| 首次渠道 | 一次预约中最早记录的操作渠道 | 需在数据中标记 |
| 变更渠道 | 同一预约后续操作发生的渠道 | 电话与网页可能记录同一次预约的不同操作事件 |
| 操作事件数 | 所有渠道操作记录条数 | **不得**直接当作预约量 |
| 预约量 | 按预约事件编号去重后的数量 | 与操作事件数区分 |

> 渠道比较主统计单位（事件 vs 去重患者）尚未决定，本方案并列展示两种口径，不默认采用其一。

## 二、流程图说明

### 2.1 预约事件生命周期（文字流程）

```
[预约创建]
   │
   ├─ 渠道记录：电话 / 网页 / 窗口
   │     └─ 同一预约可能产生多条操作事件 → 标记首次渠道与变更渠道
   │
   ▼
[预约状态]
   │
   ├─ ARRIVED（已到诊）
   ├─ CANCELLED（系统记录用户主动取消）
   │     └─ 取消时间与就诊时间均为医院本地时区
   │     └─ 取消不代表治疗结束、病情缓解或不再需要服务
   └─ UNKNOWN（原因未细分）
         └─ 可能来自设备同步延迟、现场漏登记或记录缺项
         └─ 缺少来源核查时，不解释为患者责任
   │
   ▼
[观察窗口]
   │
   ├─ 窗口未确定前：只展示待核验事件
   └─ 窗口到期后：可归为最终状态
```

### 2.2 渠道比较流程

```
原始操作事件
   │
   ├─ 按预约事件编号分组
   ├─ 标记首次渠道（最早操作）
   ├─ 标记变更渠道（后续操作）
   └─ 去重后得到预约量
         │
         ├─ 口径 A：以预约事件为主统计单位
         └─ 口径 B：以去重患者为主统计单位
               └─ 两种口径并列，待确认后选用
```

### 2.3 关键边界

- 观察窗口未确定前，不将尚未到期的预约算入爽约率。
- UNKNOWN 不直接计为爽约。
- 小渠道样本较少时保留数量和限制说明，不报告显著渠道差异。
- 医生代码仅为流程角色示例，不用于个人绩效评估或排行榜。
- 本题材料只有一个门诊，不推断跨科室、跨医院或全市运营表现。
