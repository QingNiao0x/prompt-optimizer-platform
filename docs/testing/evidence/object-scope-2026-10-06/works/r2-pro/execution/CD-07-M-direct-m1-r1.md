**口径说明：**
- 分母必须与分子在同一时间边界和状态定义下一致。
- UNKNOWN 不直接计为爽约，单独列示并标注原因未细分。
- 观察窗口未确定前，只展示待核验事件，不将尚未到期的预约算入爽约率。
- 渠道比较必须先定义首次渠道和变更渠道，不能把操作次数当成预约量。
- 小渠道样本较少时保留数量和限制说明，不报告显著的渠道差异。

### 1.3 流程图说明（文字版）

```
[预约事件产生]
    │
    ├─ 渠道记录：电话 / 网页 / 窗口
    │       │
    │       └─ 若同一预约有多次操作事件 → 需定义首次渠道与变更渠道
    │
    ├─ 状态记录：ARRIVED / CANCELLED / UNKNOWN
    │       │
    │       ├─ ARRIVED → 到诊
    │       ├─ CANCELLED → 记录到用户主动取消，不附加临床解释
    │       └─ UNKNOWN → 原因未细分（设备同步延迟、现场漏登记、记录缺项等）
    │
    ├─ 时间记录：取消时间、就诊时间（医院本地时区）
    │       │
    │       └─ 当前汇总表无时区转换证据 → 需核查
    │
    └─ 观察窗口判定
            │
            ├─ 窗口未确定 → 只展示待核验事件
            └─ 窗口确定后 → 可归为最终状态
```

**流程问题清单：**

| 编号 | 问题 | 影响 | 当前处理 |
|---|---|---|---|
| P1 | 观察窗口未定义 | 无法判断预约事件何时可归为最终状态 | 待确认，不默认补全 |
| P2 | 取消免责边界未定义 | 无法区分“免责取消”与“爽约” | 待确认，不默认补全 |
| P3 | 旧流程24小时与新草稿12小时存在差异，新草稿尚未批准 | 取消提前量口径不一致 | 单独呈现争议，不擅自采用 |
| P4 | 渠道比较统计单位未定（事件 vs 去重患者） | 影响分母和渠道分布解读 | 待确认，不默认补全 |
| P5 | 电话与网页可能记录同一次预约的不同操作事件 | 操作次数可能被误当预约量 | 需先定义首次渠道与变更渠道 |
| P6 | UNKNOWN 原因未细分 | 无法判断责任归属 | 不解释为患者责任，单独列示 |
| P7 | 汇总表无时区转换证据 | 时间边界可能不一致 | 需核查，不假设已转换 |
| P8 | 无完整逐条数据 | 无法做逐条核验和显著性检验 | 仅做汇总层面讨论，不报告显著差异 |
