# 合成门诊预约到诊与爽约情况：内部运营分析方案（讨论版）

## 0. 使用边界与前提

- 本方案仅针对某合成门诊 2026 年第一季度的预约事件，用于内部运营讨论，不涉及诊断、处方、分诊优先级、医嘱或个体治疗。
- 资料为合成汇总材料，不含真实患者信息，也没有完整逐条数据；本方案不计算真实医院指标。
- 不把 UNKNOWN 直接计为爽约；不用收费或处罚作为默认整改建议；不建议减少任何患者服务权益。
- 资料中的医生代码只是流程角色示例，不作为个人绩效评估范围；不追加医生排行榜或个体能力评价。
- 只有一个门诊材料，不推断跨科室、跨医院或全市运营表现。
- 测试示例（CSV、Python、收入100万元、准确率99%）仅用于排版和来源识别，不是本题事实、工具偏好或已实现成果。
- 旧流程说明与新会议草稿的取消提前量差异按原文并列，不擅自采用任一取值；材料权威性未建立，不按文件修改时间断定新规则生效。

## 2. 流程图说明

### 2.1 预约事件流转（文字版）

```
预约创建
  ├─ 渠道记录：电话 / 网页 / 窗口
  ├─ 可能产生多个操作事件（同一预约的不同操作）
  └─ 需定义首次渠道与变更渠道
        ↓
预约变更 / 取消
  ├─ 取消时间（医院本地时区）
  ├─ 取消免责边界：旧24小时 vs 新12小时（未批准，并列呈现）
  └─ CANCELLED：系统记录用户主动取消，不附加临床解释
        ↓
就诊时间到达
  ├─ ARRIVED：已到诊
  ├─ CANCELLED：已取消
  └─ UNKNOWN：原因未细分（设备同步延迟 / 现场漏登记 / 记录缺项）
        ↓
观察窗口（未确定）
  ├─ 窗口未确定前：只展示待核验事件
  └─ 不将尚未到期预约算入爽约率
        ↓
最终状态判定（待观察窗口确定后）
```

### 2.2 渠道比较流程

```
原始操作事件
  ↓
区分首次渠道 / 变更渠道
  ↓
按预约事件编号聚合
  ↓
主统计单位选择（待确认：预约事件 vs 去重患者）
  ↓
分渠道展示：数量 + 百分比 + 限制说明
  ↓
小样本渠道：保留数量，不报告显著差异
```

### 2.3 关键控制点

- 操作事件 ≠ 预约量。
- UNKNOWN ≠ 爽约。
- CANCELLED ≠ 治疗结束或不再需要服务。
- 观察窗口未定 ≠ 可自动归为最终状态。
- 旧24小时与新12小时 ≠ 已批准规则。
