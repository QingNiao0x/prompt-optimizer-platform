# 提示词整理工具对照研究方案

## 1. 研究问题

本研究考察提示词整理工具对下游任务输出的影响，区分两种可能的作用路径：一是仅凭相同初始信息进行提示词优化（直接增强），二是在优化前通过交互式计划确认获取额外业务信息（交互确认）。核心问题为：在初始信息相同的前提下，直接增强是否优于原始需求；在信息量匹配的前提下，交互确认是否优于直接增强。前者检验整理工具本身的增益，后者分离新增信息与交互组织方式各自的作用。

## 2. 实验设计

采用四组对照：原始组（A）接收原始需求与初始材料；直接增强组（B）接收基于同一初始信息生成的优化提示词；计划确认组（C）先经交互式问答、按预先制定答案卡作答后生成最终提示词；信息量匹配组（D）不经历问答过程，但获得与C组相同的已确认事实，用于控制新增信息量。A、B两组不得接触C组问答中暴露的业务选择。

固定二十个任务，覆盖开发方案类与写作交付类。每个条件独立重复三次，共240次下游生成。重复间开启隔离会话，随机化任务顺序，记录模型版本、日期与参数。失败样本保留，重试不替代首份失败输出。

## 3. 材料与流程

任务材料保留来源标签：真实实现、用户说明、测试示例、待办事项。不利的测试污染反例不得在评分前人为删除。C组记录每个问题、选项、推荐依据与操作者答案；错误推荐被答案纠正后仍计入交互阶段风险。D组以结构化事实清单形式获得C组最终确认的信息，不展示问答过程。

## 4. 评价指标

两名盲评者独立评分，评分时仅见匿名化下游输出与等量任务信息，不暴露工具名称、标志或生成来源，亦不可见对方评分。评分维度为：需求保真、业务规则、输出可用性、阅读负担、执行边界。每项采用有序等级分（如1–5），并记录主错误与关联维度，避免同一问题在多个维度重复计为独立失败。开发任务只评方案质量，不执行代码测试；写作任务评文本交付质量，不套用代码通过率。

工具生成速度作为过程指标单独记录，不纳入质量分。无计费日志时不估算Token成本，不以字符数换算费用。

## 5. 统计与限制

统计方法的选择取决于最终评分分布的有序性、连续性与重复测量结构，方案不预设特定显著性检验。分析流程为：先检查评分者间一致性，再按任务类型分层汇总，比较A与B（初始信息相同）、C与D（信息量匹配）及B与D（交互组织方式）的差异。专业领域判断需专家参与，模型输出相似不构成研究完成证据。
