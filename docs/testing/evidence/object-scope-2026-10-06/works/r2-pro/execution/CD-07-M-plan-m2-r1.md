# 合成门诊预约到诊与爽约运营分析方案（讨论版）

本方案仅用于二〇二六年第一季度合成门诊预约事件的内部运营分析讨论。分析对象为预约事件，不涉及诊断、处方、分诊优先级、医嘱或个体治疗。所有表格仅展示合成汇总信息，不包含患者、医生的可识别信息或敏感诊疗明细。

---

## 一、口径梳理

### 1.1 核心概念边界

| 概念 | 口径定义 | 依据/说明 |
|---|---|---|
| 预约事件 | 以预约事件编号为唯一标识的一次预约记录。一个患者可多次预约，事件数不等于人数。 | current-brief.md 第1段 |
| 患者人数 | 去重后的患者数量。当前主统计单位未定，不得与事件数混同。 | 用户明确规则；current-brief.md 第1段 |
| 预约渠道 | 电话、网页、窗口三类，已明确，不再询问。 | 用户明确规则 |
| 首次渠道 | 同一预约事件或同一患者首次被记录到的渠道。需在渠道比较前定义，当前未定义。 | current-brief.md "分支与边界"第1条 |
| 变更渠道 | 同一预约事件或同一患者后续操作中出现的不同渠道记录。电话与网页可能记录相同一次预约的不同操作事件，不能把操作次数当成预约量。 | current-brief.md "分支与边界"第1条 |
| 到诊状态 | ARRIVED、CANCELLED、UNKNOWN 三类。UNKNOWN 原因未细分，不得解释为患者责任。 | current-brief.md 第3段；"分支与边界"第3条 |
| 爽约 | 当前未定义。观察窗口未定，不能因到期就自动视为最终状态；UNKNOWN 不得直接计为爽约。 | 用户明确规则；current-brief.md "分支与边界"第4条 |
| 取消免责边界 | 旧流程说明提前24小时取消不计爽约；新会议草稿建议提前12小时，尚未批准。两者并列呈现，不擅自采用任一取值。 | legacy-note.md；用户明确规则 |
| 观察窗口 | 决定一个预约事件何时可归为最终状态。当前尚未定义，窗口未确定前只展示待核验事件。 | current-brief.md "分支与边界"第4条；用户明确规则 |
| 时区 | 预约取消时间与就诊时间均用医院本地时区。当前汇总表没有时区转换证据。 | current-brief.md 第4段；用户明确规则 |

### 1.2 统计单位边界

| 统计场景 | 可用单位 | 当前状态 |
|---|---|---|
| 预约量 | 预约事件数 | 可用，但需注明事件数≠人数 |
| 到诊率/爽约率 | 预约事件数或去重患者数 | **未定**，不得默认补全 |
| 渠道比较 | 预约事件数或去重患者数 | **未定**，且需先定义首次渠道与变更渠道 |

### 1.3 状态判定边界

| 状态 | 可判定条件 | 当前限制 |
|---|---|---|
| ARRIVED | 系统记录到诊 | 可直接使用 |
| CANCELLED | 系统记录用户主动取消 | 不附加临床解释；取消时间与就诊时间均为本地时区，但汇总表无时区转换证据 |
| UNKNOWN | 可能来自设备同步延迟、现场漏登记或记录缺项 | 不得计为爽约；不得解释为患者责任；需来源核查 |
| 最终状态 | 观察窗口到期且状态明确 | 观察窗口未定，不能因到期自动视为最终状态 |

### 1.4 流程图说明（文字版）

```
预约事件产生
    │
    ├── 记录渠道（电话/网页/窗口）
    │       │
    │       └── 同一预约可能有多条渠道操作记录
    │             → 需定义首次渠道与变更渠道（当前未定义）
    │
    ├── 记录到诊状态（ARRIVED / CANCELLED / UNKNOWN）
    │       │
    │       ├── ARRIVED → 可计入到诊
    │       ├── CANCELLED → 记录取消时间；取消免责边界未定（24h vs 12h 并列）
    │       └── UNKNOWN → 待核验；不得计为爽约
    │
    └── 观察窗口判定（当前未定义）
            │
            ├── 窗口未到 → 待核验事件，不计入爽约率
            └── 窗口已到且状态明确 → 可归为最终状态（需先定义窗口）
```

## 二、流程问题清单

| 编号 | 问题 | 影响 | 当前状态 | 依据 |
|---|---|---|---|---|
| Q1 | 预约未到诊的观察窗口应如何定义？ | 决定一个预约事件何时可归为最终状态；窗口未定前只能展示待核验事件，不能计算爽约率 | **未定，不得默认补全** | current-brief.md "分支与边界"第4条；用户明确规则 |
| Q2 | 取消免责边界应如何定义？ | 决定 CANCELLED 事件是否计入爽约 | **未定**。旧流程说明提前24小时取消不计爽约；新会议草稿建议提前12小时，尚未批准。两者并列，不擅自采用 | legacy-note.md；用户明确规则 |
| Q3 | 渠道比较时主统计单位应使用预约事件还是去重患者？ | 影响渠道到诊率/爽约率的计算分母与解读 | **未定，不得默认补全** | 用户明确规则；current-brief.md 第1段 |
| Q4 | 首次渠道与变更渠道如何定义？ | 电话与网页可能记录相同一次预约的不同操作事件；不定义则渠道比较会把操作次数当成预约量 | **未定** | current-brief.md "分支与边界"第1条 |
| Q5 | UNKNOWN 状态的来源核查流程是什么？ | UNKNOWN 可能来自设备同步延迟、现场漏登记或记录缺项；无核查流程则无法判断是否可转为 ARRIVED 或 CANCELLED | **未定** | current-brief.md "分支与边界"第3条 |
| Q6 | 当前汇总表是否有时区转换证据？ | 预约取消时间与就诊时间均用医院本地时区，但汇总表没有时区转换证据；影响取消时间与就诊时间比较的准确性 | **未定，需核验** | current-brief.md 第4段；用户明确规则 |

## 三、拟议数据采集表（合成数据字段建议）

以下字段为拟议采集内容，**实施前需合规评估**，不能写成已经建表或已获得数据授权。表格仅展示合成汇总信息，不包含患者、医生的可识别信息或敏感诊疗明细。

### 3.1 预约事件基础字段

| 字段名 | 类型 | 说明 | 必要性 |
|---|---|---|---|
| 预约事件编号 | 字符串 | 唯一标识一次预约 | 必需 |
| 患者去重标识 | 字符串（脱敏） | 用于去重患者数；不得包含可识别信息 | 必需（用于人数统计） |
| 预约渠道 | 枚举：电话/网页/窗口 | 记录该事件被记录的渠道 | 必需 |
| 渠道记录类型 | 枚举：首次/变更 | 需先定义首次渠道与变更渠道规则（Q4未定） | 条件必需 |
| 预约创建时间 | 日期时间 | 医院本地时区 | 必需 |
| 就诊时间 | 日期时间 | 医院本地时区 | 必需 |
| 到诊状态 | 枚举：ARRIVED/CANCELLED/UNKNOWN | 当前记录状态 | 必需 |
| 状态更新时间 | 日期时间 | 记录状态最后一次变更的时间；用于观察窗口判定 | 必需 |
| 取消时间 | 日期时间（可空） | 仅 CANCELLED 状态填写；医院本地时区 | 条件必需 |
| 来源系统 | 字符串 | 记录该事件数据的系统来源，用于核查 UNKNOWN 状态 | 必需 |
| 时区标识 | 字符串 | 确认时间字段均为医院本地时区；当前汇总表无时区转换证据，需补充 | 必需 |

### 3.2 观察窗口与取消边界辅助字段

| 字段名 | 类型 | 说明 | 必要性 |
|---|---|---|---|
| 观察窗口到期时间 | 日期时间（可空） | 需先定义观察窗口规则（Q1未定） | 条件必需 |
| 取消提前量 | 数值（小时） | 取消时间与就诊时间的差值；用于判定是否在免责边界内。免责边界未定（Q2未定），当前仅采集原始值 | 条件必需 |
| 待核验标记 | 布尔 | 观察窗口未到或状态为 UNKNOWN 时标记为待核验 | 必需 |

### 3.3 合规说明

- 以上字段仅为拟议方案，**实施前需合规评估**（current-brief.md "分支与边界"第9条）。
- 患者去重标识必须脱敏，不得包含患者姓名、证件号、联系方式等可识别信息。
- 医生代码仅作为流程角色示例，不纳入个人绩效评估范围，不追加医生排行榜（current-brief.md "分支与边界"第7条）。
- 不采集诊断、处方、医嘱或治疗明细。
