# 合成医院门诊预约到诊与爽约情况内部运营分析方案

**文档状态**：讨论版草案  
**分析对象**：某合成门诊二〇二六年第一季度预约事件  
**数据性质**：合成汇总信息，无真实患者信息，无完整逐条数据  
**用途边界**：仅用于运营流程讨论，不涉及诊断、处方、分诊优先级、医嘱或个体治疗


## 一、口径梳理

### 1.1 基础口径表

| 口径项 | 定义/说明 | 依据 |
|---|---|---|
| 分析期间 | 二〇二六年第一季度（2026-01-01 至 2026-03-31，医院本地时区） | 任务说明 |
| 分析对象 | 某合成门诊的预约事件 | 任务说明 |
| 预约事件编号 | 可区分一次预约；同一患者可多次预约，事件数 ≠ 人数 | current-brief.md |
| 预约渠道 | 电话、网页、窗口三类，已明确，不再询问 | current-brief.md；用户确认 |
| 到诊状态 | ARRIVED、CANCELLED、UNKNOWN 三类 | current-brief.md |
| UNKNOWN 含义 | 原因未细分；可能来自设备同步延迟、现场漏登记或记录缺项，不得解释为患者责任 | current-brief.md |
| CANCELLED 含义 | 系统记录到用户主动取消；不意味着治疗结束、病情缓解或不再需要服务，不得附加临床解释 | current-brief.md |
| 时区 | 预约取消时间与就诊时间均用医院本地时区；当前汇总表没有时区转换证据 | current-brief.md；用户确认 |
| 爽约定义 | 尚未确定。不得将 UNKNOWN 直接计为爽约；观察窗口未确定前，不应将尚未到期的预约算入爽约率 | current-brief.md；待确认项 |

### 1.2 渠道比较的统计单位口径

电话预约与网页预约可能记录相同一次预约的不同操作事件。渠道比较必须先定义"首次渠道"和"变更渠道"，不能把操作次数当成预约量。

| 口径项 | 状态 | 说明 |
|---|---|---|
| 首次渠道 | 待定义 | 一次预约在系统中最早记录的渠道 |
| 变更渠道 | 待定义 | 同一预约事件后续操作中出现的不同渠道 |
| 渠道比较主统计单位 | **待确认** | 使用预约事件还是去重患者，当前尚未决定，不得默认补全 |

**渠道比较的临时处理原则**（在统计单位确认前）：
- 按预约事件编号去重后统计预约量，不按操作次数统计；
- 如一个预约事件在多个渠道出现操作记录，单独列为"多渠道操作事件"，不强行归入单一渠道；
- 渠道间比较时同时报告事件数和去重患者数（如数据可得），并标注统计单位未最终确认。

### 1.3 取消免责边界的资料差异

| 来源 | 内容 | 状态 |
|---|---|---|
| legacy-note.md（旧流程说明） | 提前24小时取消不计爽约 | 旧版，权威性未建立 |

### 1.4 爽约率的计算前提（待确认项）

| 待确认项 | 影响 | 当前处理 |
|---|---|---|
| 预约未到诊的观察窗口如何定义 | 决定一个预约事件何时可归为最终状态 | 窗口未确定前只展示待核验事件，不计算最终爽约率 |
| 取消免责边界（24小时 vs 12小时） | 决定 CANCELLED 事件是否计入爽约分母或分子 | 两版口径并列，不默认采用 |
| 渠道比较主统计单位（事件 vs 患者） | 决定渠道比较的分母 | 不默认补全，报告中标注 |

### 1.5 指标定义（草案，待上述待确认项明确后启用）

| 指标 | 分子 | 分母 | 前置条件 |
|---|---|---|---|
| 预约到诊率 | 状态为 ARRIVED 的预约事件数 | 观察窗口内已到最终状态的预约事件总数 | 观察窗口已定义 |
| 取消率 | 状态为 CANCELLED 的预约事件数 | 同上 | 同上 |
| 待核验率 | 状态为 UNKNOWN 且尚未超过观察窗口的预约事件数 | 全部预约事件数 | 观察窗口已定义 |
| 渠道预约量占比 | 某渠道预约事件数（按事件编号去重） | 全部渠道预约事件总数 | 统计单位已确认 |

**明确排除的指标**：
- 不将 UNKNOWN 直接计为爽约；
- 不按操作次数计算预约量；
- 不计算医生个人绩效指标（医生代码仅为流程角色示例，非个人绩效评估范围）；
- 不推断跨科室、跨医院或全市的运营表现（本题材料只有一个门诊）。


## 二、流程图说明

### 2.1 预约事件状态流转（基于现有资料可确认的部分）

```
[预约创建] → [等待就诊] → [就诊时间到达]
                              |
              +---------------+---------------+
              |               |               |
          [ARRIVED]     [CANCELLED]      [UNKNOWN]
          已到诊          已取消          状态未知
              |               |               |
              ↓               ↓               ↓
         最终状态        最终状态?      待核验状态
                     （是否计爽约取决    （原因未细分：
                       于取消免责边界）   设备同步延迟/
                                         现场漏登记/
                                         记录缺项）
```

**流程说明**：
1. 预约创建时记录预约事件编号和渠道（电话/网页/窗口）。
2. 同一预约事件可能在多个渠道产生操作记录（如电话预约后网页改约），此时渠道归属需按"首次渠道/变更渠道"规则处理，该规则尚未定义。
3. 就诊时间到达后，系统记录到诊状态。ARRIVED 为已到诊；CANCELLED 表示系统记录到用户主动取消；UNKNOWN 表示状态未明确，原因未细分。
4. UNKNOWN 状态在观察窗口未确定前，只能标记为"待核验"，不得归入任何最终状态。
5. CANCELLED 是否构成"爽约"，取决于取消免责边界（24小时 vs 12小时），该边界尚未确定。

### 2.2 渠道操作事件与预约事件的区分

```
[操作事件层]  电话操作 → 网页操作 → 窗口操作
                  \         |         /
                   \        |        /
                    ↓       ↓       ↓
[预约事件层]      （同一预约事件编号下的多次操作）
                         |
                         ↓
              按预约事件编号去重后统计预约量
                         |
                         ↓
        渠道归属需定义"首次渠道"和"变更渠道"规则
```

**说明**：电话预约与网页预约可能记录相同一次预约的不同操作事件。分析时必须在操作事件层和预约事件层之间做区分，不能把操作次数当成预约量。


## 三、合成数据采集字段建议

以下为拟议采集表字段，**实施前仍需合规评估；不能写成已经建表或已获得数据授权**。

### 3.1 预约事件主表字段

| 字段名 | 类型 | 说明 | 必要性 |
|---|---|---|---|
| 预约事件编号 | 字符串（脱敏/合成ID） | 唯一标识一次预约，用于去重 | 必需 |
| 患者合成编号 | 字符串（脱敏/合成ID） | 用于识别同一患者多次预约，不包含可识别信息 | 必需 |
| 预约创建时间 | 日期时间（医院本地时区） | 预约首次创建时间 | 必需 |
| 预约就诊时间 | 日期时间（医院本地时区） | 计划就诊时间 | 必需 |
| 首次渠道 | 枚举：电话/网页/窗口 | 需先定义"首次渠道"规则 | 待规则确认 |
| 变更渠道 | 枚举：电话/网页/窗口/无 | 需先定义"变更渠道"规则；同一事件在多个渠道有操作时记录 | 待规则确认 |
| 到诊状态 | 枚举：ARRIVED/CANCELLED/UNKNOWN | 当前状态 | 必需 |
| 状态更新时间 | 日期时间（医院本地时区） | 状态最后变更时间，用于判断观察窗口 | 建议增加 |
| 取消时间 | 日期时间（医院本地时区，可空） | 仅 CANCELLED 状态填写；用于计算取消提前量 | 建议增加 |
| 来源系统 | 字符串 | 记录数据来自哪个系统（如电话系统/网页系统/窗口终端），用于识别多渠道操作 | 建议增加 |

### 3.2 渠道操作事件表字段（用于区分操作次数与预约量）

| 字段名 | 类型 | 说明 | 必要性 |
|---|---|---|---|
| 操作事件编号 | 字符串（合成ID） | 唯一标识一次渠道操作 | 必需 |
| 关联预约事件编号 | 字符串（合成ID） | 关联到预约事件主表 | 必需 |
| 操作渠道 | 枚举：电话/网页/窗口 | 本次操作的渠道 | 必需 |
| 操作时间 | 日期时间（医院本地时区） | 操作发生时间 | 必需 |
| 操作类型 | 枚举：创建/修改/取消/查询等 | 区分操作性质 | 建议增加 |

### 3.3 采集表使用注意事项

- 以上字段均为合成数据，不包含患者姓名、身份证号、联系方式、医生姓名等可识别信息；
- 患者合成编号仅用于同一患者多次预约的关联分析，不得用于追溯真实个人；
- 来源系统字段用于识别同一预约事件在不同渠道的操作记录，是定义"首次渠道/变更渠道"的数据基础；
- 状态更新时间和取消时间为建议增加字段，用于支持观察窗口和取消提前量的计算，当前汇总表可能不具备这些字段。

## 五、人工复核及隐私边界清单

### 5.1 人工复核清单

| 复核项 | 复核内容 | 复核时机 |
|---|---|---|
| 观察窗口定义 | 确认预约未到诊的观察窗口和取消免责边界，需业务负责人确认 | 计算爽约率前 |
| 取消免责边界 | 确认采用24小时还是12小时，或维持并列呈现 | 报告定稿前 |
| 渠道统计单位 | 确认渠道比较使用预约事件还是去重患者 | 渠道比较分析前 |
| 首次渠道/变更渠道规则 | 确认同一预约事件多渠道操作时的渠道归属规则 | 渠道比较分析前 |
| UNKNOWN 状态核查 | 对 UNKNOWN 事件进行来源核查（设备同步/漏登记/缺项），不直接归因于患者 | 报告发布前 |
| 数据完整性 | 核对汇总表是否包含状态更新时间、取消时间、来源系统等字段；如缺失，标注为数据限制 | 分析开始前 |
| 小样本渠道 | 检查各渠道样本量，样本较少时保留数量和限制说明，不报告显著渠道差异 | 渠道比较分析时 |
| 资料差异呈现 | 确认24小时与12小时两版口径并列呈现，不擅自采用其中一项 | 报告撰写时 |

### 5.2 隐私边界清单

| 边界项 | 要求 |
|---|---|
| 患者可识别信息 | 表格只展示合成汇总信息，不包含患者姓名、身份证号、联系方式、住址等 |
| 医生可识别信息 | 不包含医生姓名、工号；医生代码仅为流程角色示例，不用于个人绩效评估 |
| 敏感诊疗明细 | 不包含诊断、处方、医嘱、检查结果等临床信息 |
| 取消行为解读 | 不将取消行为与病情缓解、治疗结束或不再需要服务关联 |
| UNKNOWN 归因 | 不将 UNKNOWN 状态解释为患者责任 |
| 改进建议边界 | 不默认采取罚款、降低预约资格或公开患者记录；优先考虑清楚提示取消规则、核对登记质量与便捷改约 |
| 短信提醒 | 如后续要求短信提醒方案，需另行确认通知授权和退订流程；本次不扩展为短信实施任务 |
| 数据授权 | 拟议采集表实施前需合规评估，不视为已建表或已获数据授权 |
