# 提示词整理工具对照研究方案

## 一、研究问题

本研究比较三种提示词整理方式对下游任务输出的影响：原始需求（A组）、直接增强（B组）、交互式计划确认增强（C组），并设信息量匹配对照（D组）。研究不评价任何产品绝对优劣，只考察不同整理方式在受控条件下的输出差异。

核心问题：在相同初始材料下，直接增强与交互式计划确认是否比原始需求产生更符合任务要求的输出；当C组因问答获得额外业务事实时，该收益有多少来自新增信息、多少来自交互组织方式。

## 二、实验设计

**任务与重复**：固定二十个任务，每任务每条件独立重复三次，共240次运行。三次重复使用隔离会话，随机化运行顺序，记录模型版本、日期与参数。失败后的重试不替代第一份失败样本。

**四组条件**：
- A组：原始需求＋初始材料。
- B组：由同一初始信息生成的优化提示词。
- C组：系统先提问，实验操作者按预先制定答案卡作答，再生成最终提示词；记录每个问题、选项、推荐依据与答案，错误推荐被纠正后仍计入交互阶段风险。
- D组：获得与C组相同的已确认事实，但不经历问答过程。

A、B两组不得接触C组后来回答的业务选择。D组用于区分新增信息与交互组织方式的效应。

**材料**：所有工具获取相同初始材料，保留真实实现、用户说明、测试示例与待办四类来源标签；人工评分前不得删除不利的测试污染反例。

**盲评**：两名盲评者独立评分，看到匿名化下游输出与等量任务信息，不展示产品名称、标志与生成来源，不查看另一名评审先前评分。

## 三、主要指标

评价覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。质量分为结果指标；生成速度为过程指标，单独记录，不换算为费用。无计费日志时不估算真实Token成本。

一个错误可能同时影响多个维度，评分表记录主错误与关联维度，避免同一问题重复计为独立失败。

跨任务不设统一质量指标：开发任务只要求下游模型输出方案、不修改仓库；写作任务交付文本，故不以代码测试通过率作为统一标准。

## 四、限制

实验尚未运行，无准确率、显著性、成功案例数量或用户结论。统计方法依分数是否有序、连续及是否重复测量选择，不在变量确定前锁定检验。三个模型结论相似不构成研究完成证据；专业领域判断尚需专家参与。交互式计划确认的最大轮次与终止规则、盲评者分歧处理及一致性评价方式均未确定，见预注册待确认清单。
