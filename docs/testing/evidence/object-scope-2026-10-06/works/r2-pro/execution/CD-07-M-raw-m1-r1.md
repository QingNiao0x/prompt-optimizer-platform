### 口径使用要点

1. **事件口径优先用于流程量描述**：在渠道主统计单位未决定前，可先以预约事件展示总量与状态分布，但不得据此直接比较渠道优劣。
2. **UNKNOWN 单列**：报告中将 ARRIVED、CANCELLED、UNKNOWN 并列展示，UNKNOWN 不并入爽约。
3. **取消规则争议单列**：旧流程说明与新会议草稿的24小时/12小时差异，作为独立争议项呈现，不按文件修改时间断定新规则生效。
4. **观察窗口未定前**：只展示待核验事件，不将尚未到期的预约算入爽约率。
5. **取消状态解释边界**：CANCELLED 仅表示系统记录到用户主动取消，不意味着治疗结束、病情缓解或不再需要服务；报告不附加临床解释。
6. **UNKNOWN 原因边界**：可能来自设备同步延迟、现场漏登记或记录缺项；缺少来源核查时，不解释为患者责任。

## 二、流程图说明

### 2.1 预约事件流转（文字版）

```
预约产生
  ├─ 渠道记录：电话 / 网页 / 窗口
  │    └─ 注意：同一预约可能有多个操作事件，需区分首次渠道与变更渠道
  ├─ 预约事件编号生成
  └─ 进入观察窗口
        ├─ 窗口内到诊 → ARRIVED
        ├─ 窗口内主动取消 → CANCELLED
        │    └─ 是否免责：取决于取消提前量规则（24小时 vs 12小时，待确认）
        ├─ 窗口结束仍无最终状态 → UNKNOWN
        │    └─ 原因未细分：设备同步延迟 / 现场漏登记 / 记录缺项
        └─ 窗口未到期 → 待核验事件，不纳入爽约率
```

### 2.2 渠道比较流程

```
确定比较目的
  ├─ 若比较预约量 → 需先定义首次渠道和变更渠道
  ├─ 若比较到诊行为 → 需先决定主统计单位（事件 / 去重患者）
  └─ 输出时：
        ├─ 保留各渠道数量
        ├─ 小样本渠道附限制说明
        └─ 无完整数据时不报告显著渠道差异
```

### 2.3 取消规则争议处理流程

```
取消时间记录
  ├─ 旧流程说明：提前24小时取消不计爽约
  ├─ 新会议草稿：建议提前12小时，尚未批准
  └─ 处理方式：
        ├─ 不擅自采用其中一项
        ├─ 在报告中单列差异
        └─ 待权威性建立后再确定免责边界
```

### 2.4 人工复核节点

```
数据准备
  → 状态更新时间核验
  → 取消时间与就诊时间时区核验
  → 来源系统字段核验
  → 首次渠道/变更渠道判定复核
  → UNKNOWN 来源抽查
  → 小样本渠道限制说明复核
  → 报告发布前合规与专业评审
```
