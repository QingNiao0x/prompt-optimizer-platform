### 1.3 流程图说明（文字版）

```
[预约事件产生]
    │
    ├─ 渠道记录：电话 / 网页 / 窗口
    │       └─ 同一预约可能产生多个操作事件
    │               └─ 需区分：首次渠道 vs 变更渠道
    │
    ├─ 状态流转：
    │       ├─ ARRIVED（已到诊）
    │       ├─ CANCELLED（系统记录用户主动取消）
    │       └─ UNKNOWN（原因未细分：同步延迟/漏登记/缺项）
    │
    ├─ 时间字段：
    │       ├─ 预约取消时间（医院本地时区）
    │       └─ 就诊时间（医院本地时区）
    │
    └─ 观察窗口（未确定）
            ├─ 窗口内：仅展示待核验事件
            └─ 窗口结束后：方可归为最终状态
                    └─ 爽约判定规则（未确定）
                            ├─ 旧：提前24小时取消不计爽约
                            └─ 新草稿：提前12小时，尚未批准
```

**流程问题清单：**

| 编号 | 问题 | 影响 | 当前处理 |
|---|---|---|---|
| P1 | 观察窗口未定义 | 无法判定事件何时为最终状态，爽约率无法计算 | 仅展示待核验事件，不计算爽约率 |
| P2 | 取消免责边界未定（24h vs 12h） | 影响取消是否计入爽约 | 两版并列呈现，不擅自采用 |
| P3 | 渠道比较主统计单位未选（事件 vs 去重患者） | 影响渠道比较的分母和解释 | 暂不开展渠道比较 |
| P4 | UNKNOWN 原因未细分 | 无法区分技术原因与行为原因 | 不将 UNKNOWN 解释为患者责任 |
| P5 | 同一预约多操作事件 | 操作次数不等于预约量 | 须先定义首次渠道与变更渠道 |
| P6 | 无时区转换证据 | 跨时区数据不可比 | 仅按医院本地时区理解 |
| P7 | 汇总表无完整逐条数据 | 无法做个体级追踪 | 仅做汇总层面讨论 |
| P8 | 医生代码仅为流程角色示例 | 不得用于个人绩效评估 | 不生成医生排行榜 |
