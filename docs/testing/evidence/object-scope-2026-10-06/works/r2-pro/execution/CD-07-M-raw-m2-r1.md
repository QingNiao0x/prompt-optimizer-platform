# 合成门诊预约到诊与爽约情况内部运营分析方案（二〇二六年第一季度）

> 适用对象：运营分析、门诊流程管理、数据质量核验相关岗位  
> 材料性质：合成资料，方法草案，需经专业评审后方可应用  
> 分析范围：仅限预约事件层面的运营流程与数据质量，不涉及诊断、处方、分诊优先级、医嘱或个体治疗


## 一、口径梳理

### 1.1 主统计单位（待确认项）

| 项目 | 说明 |
|---|---|
| 可选口径 A | 预约事件数：以预约事件编号为统计单位，一次预约计一条 |
| 可选口径 B | 去重患者数：以患者标识去重后统计 |
| 当前状态 | 资料未决定渠道比较时采用哪种主统计单位 |
| 影响 | 同一患者多次预约时，两种口径下的渠道分布、到诊率、取消率会不同 |
| 建议处理 | 报告同时保留两个口径的说明；渠道比较章节在业务决定前不单独下结论 |

### 1.2 到诊状态口径

| 状态值 | 运营口径 | 是否计入爽约 |
|---|---|---|
| ARRIVED | 系统记录已到诊 | 否 |
| CANCELLED | 系统记录用户主动取消 | 否，不计为爽约 |
| UNKNOWN | 到诊状态未知，原因未细分 | **不得直接计为爽约**，列为待核验 |

UNKNOWN 的可能来源（资料已列明，仅作核验方向，不作归因结论）：
- 设备同步延迟
- 现场漏登记
- 记录缺项

### 1.3 取消免责边界（待确认项）

| 来源 | 内容 | 状态 |
|---|---|---|
| 旧流程说明（legacy-note.md） | 提前24小时取消不计爽约 | 旧版，权威性未建立 |
| 新会议草稿 | 建议提前12小时，尚未批准 | 草稿，未生效 |

**差异提示**：两份材料对取消免责提前量不一致（24小时 vs 12小时）。本方案不擅自采用其中任何一项。在业务决定前：
- 报告只展示两档口径下的取消事件分布，不计算最终爽约率；
- 涉及取消免责边界的章节标注"待业务确认"。

### 1.4 观察窗口（待确认项）

| 项目 | 说明 |
|---|---|
| 问题 | 一个预约事件何时可以归为最终状态，当前未定义 |
| 影响 | 观察窗口未确定前，尚未到观察截止点的预约不能计入爽约率 |
| 处理 | 报告将"观察期内状态未最终确定"的事件单列为待核验，不并入任何到诊或爽约结论 |

### 1.5 渠道口径

| 项目 | 说明 |
|---|---|
| 渠道类别 | 电话、网页、窗口（已明确，不再询问） |
| 关键边界 | 电话预约与网页预约可能记录同一次预约的不同操作事件 |
| 处理 | 渠道比较必须先定义"首次渠道"和"变更渠道"，不能把操作次数当成预约量 |
| 当前状态 | 首次渠道与变更渠道的定义规则尚未在资料中给出，列为待确认项 |

### 1.6 时区口径

| 项目 | 说明 |
|---|---|
| 已知 | 预约取消时间与就诊时间均用医院本地时区 |
| 风险 | 当前汇总表没有时区转换证据 |
| 处理 | 报告标注"时间字段按医院本地时区理解，未做跨时区转换核验"；如后续涉及跨系统数据合并，需补充时区来源核查 |

### 1.7 样本量限制口径

| 项目 | 说明 |
|---|---|
| 已知 | 预约事件量不同会影响百分比波动 |
| 处理 | 小渠道样本较少时，报告保留事件数量并附加限制说明；没有完整数据不能报告显著的渠道差异 |


## 二、流程图说明（文字版）

### 2.1 预约事件状态流转（基于已知资料）

```
[预约创建] → [等待就诊] → [就诊时间到达]
                              │
              ┌───────────────┼────────────────┐
              │               │                │
         [ARRIVED]      [CANCELLED]        [UNKNOWN]
          已到诊          用户主动取消       状态未知
              │               │                │
              ▼               ▼                ▼
         计入到诊       不计入爽约         列为待核验
                       （取消不附加        （不得直接计为
                        临床解释）          患者责任）
```

### 2.2 流程说明要点

1. **预约创建**：通过电话、网页或窗口任一渠道产生预约事件编号。
2. **渠道记录边界**：同一预约可能在不同渠道留下操作记录，分析前需区分首次渠道与变更渠道，否则渠道分布会被操作次数污染。
3. **取消事件**：CANCELLED 仅表示系统记录到用户主动取消，不表示治疗结束、病情缓解或不再需要服务。分析报告不得给取消行为附加临床解释。
4. **UNKNOWN 事件**：进入人工复核队列，核验方向为设备同步、现场登记、记录缺项三类，不预设为患者责任。
5. **观察窗口**：未定义前，所有未到最终判定时点的预约均标注"待核验"，不进入爽约率计算。
6. **取消免责边界**：24小时与12小时两档并存，报告分别展示，不合并。


## 三、拟议数据采集字段建议

> 说明：以下为拟议采集字段，实施前仍需合规评估；不表示已经建表或已获得数据授权。

### 3.1 预约事件基础字段

| 字段名 | 建议内容 | 用途 | 是否含敏感信息 |
|---|---|---|---|
| 预约事件编号 | 合成编号 | 唯一标识一次预约 | 否（需去标识化处理） |
| 患者去标识化编号 | 合成患者标识 | 区分事件数与人数 | 是，需去标识化 |
| 预约渠道 | 电话/网页/窗口 | 渠道分布分析 | 否 |
| 首次渠道标记 | 是/否 | 区分首次渠道与变更渠道 | 否 |
| 预约创建时间 | 医院本地时区 | 预约提前量分析 | 否 |
| 就诊时间 | 医院本地时区 | 观察窗口判定 | 否 |
| 到诊状态 | ARRIVED/CANCELLED/UNKNOWN | 核心状态字段 | 否 |
| 状态更新时间 | 医院本地时区 | 判断状态记录时点 | 否 |
| 取消时间 | 医院本地时区，可空 | 取消提前量计算 | 否 |
| 来源系统 | 如预约系统/登记系统/同步日志 | 核验 UNKNOWN 来源 | 否 |

### 3.2 数据质量核验字段（建议补充）

| 字段名 | 建议内容 | 用途 |
|---|---|---|
| 状态来源标识 | 系统自动/人工录入 | 区分 UNKNOWN 产生环节 |
| 最后同步时间 | 医院本地时区 | 排查设备同步延迟 |
| 登记点标识 | 去标识化的登记点编号 | 定位漏登记环节，不指向个人 |

### 3.3 明确不采集的字段

- 诊断信息
- 处方信息
- 分诊优先级
- 医嘱内容
- 医生个人绩效标识
- 患者联系方式（本次分析不需要）

## 五、人工复核及隐私边界清单

### 5.1 人工复核清单

| 复核项 | 复核内容 | 复核目的 |
|---|---|---|
| UNKNOWN 状态核验 | 逐条核对 UNKNOWN 事件的来源系统、同步日志、现场登记记录 | 区分设备延迟、漏登记、记录缺项，不归因于患者 |
| 取消时间核验 | 核对取消时间是否早于就诊时间、记录是否完整 | 计算取消提前量，不用于处罚 |
| 渠道记录核验 | 同一预约事件是否存在多个渠道操作记录 | 区分首次渠道与变更渠道，避免操作次数混入预约量 |
| 状态更新时间核验 | 核对状态更新时间与就诊时间的先后关系 | 判断事件是否已过观察窗口 |
| 时区一致性核验 | 核对各来源系统时间字段是否均为医院本地时区 | 避免时区混用导致状态误判 |

### 5.2 隐私边界清单

| 边界项 | 要求 |
|---|---|
| 患者标识 | 仅使用去标识化编号，不展示可识别信息 |
| 医生信息 | 医生代码仅作为流程角色示例，不用于个人绩效评估，不追加医生排行榜 |
| 诊疗明细 | 不采集、不展示诊断、处方、分诊优先级、医嘱内容 |
| 取消行为解释 | 不将取消行为与病情、治疗效果、服务需求关联 |
| 患者责任认定 | UNKNOWN 状态在核验前不认定为患者责任 |
| 处罚措施 | 不默认采用收费、罚款、降低预约资格、公开患者记录等措施 |
| 短信提醒 | 如后续要求短信提醒方案，需另行确认通知授权和退订流程；本次不扩展为短信实施任务 |
| 数据授权 | 拟议采集表实施前需合规评估，不写成已建表或已获授权 |
