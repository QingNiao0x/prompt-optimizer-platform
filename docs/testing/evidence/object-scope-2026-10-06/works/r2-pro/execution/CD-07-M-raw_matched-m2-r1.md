# 合成医院门诊预约运营分析方案（二〇二六年第一季度）

> 本方案仅用于内部运营资料分析与写作，不涉及诊断、处方、分诊优先级、医嘱或个体治疗。分析对象为合成门诊预约事件，不含真实患者信息，不计算真实医院指标，不建议减少任何患者服务权益。


## 一、口径梳理

### 1.1 基础口径

| 口径项 | 定义 | 依据/说明 |
|---|---|---|
| 预约事件 | 以预约事件编号唯一标识的一次预约记录 | current-brief.md：预约事件编号可区分一次预约 |
| 分析对象 | 合成门诊二〇二六年第一季度全部预约事件 | 任务设定 |
| 事件数 ≠ 人数 | 一个患者可多次预约，事件数不等于患者人数 | current-brief.md 明确 |
| 预约渠道 | 电话、网页、窗口三类，已明确，不再追问 | current-brief.md 明确 |
| 到诊状态 | ARRIVED / CANCELLED / UNKNOWN 三类 | current-brief.md 明确 |
| UNKNOWN 含义 | 原因未细分，可能来自设备同步延迟、现场漏登记或记录缺项 | current-brief.md：不能解释为患者责任 |
| 时区 | 预约取消时间与就诊时间均为医院本地时区；当前汇总表无时区转换证据 | current-brief.md 明确 |

### 1.2 状态判定口径

| 状态 | 判定口径 | 备注 |
|---|---|---|
| ARRIVED | 系统记录到诊 | 直接采用 |
| CANCELLED | 系统记录到用户主动取消 | 不附加临床解释；不意味着治疗结束或病情缓解 |
| UNKNOWN | 到诊状态未知 | **不得直接计为爽约**；须列为待核验事件 |

### 1.3 爽约口径（待业务决定，不默认补全）

| 口径项 | 当前状态 | 说明 |
|---|---|---|
| 观察窗口 | **尚未确定** | 决定一个预约事件何时可归为最终状态；窗口未确定前，只展示待核验事件，不将尚未到期的预约算入爽约率 |
| 取消免责边界 | **尚未确定** | 旧流程说明提前24小时取消不计爽约；新会议草稿建议提前12小时，尚未批准。两份材料权威性未建立，须并列呈现，不擅自采用任一取值 |
| 主统计单位 | **尚未确定** | 比较渠道时使用预约事件还是去重患者，尚未选择，不能混同 |

### 1.4 渠道比较口径

| 口径项 | 定义 | 依据/说明 |
|---|---|---|
| 首次渠道 vs 变更渠道 | 电话预约与网页预约可能记录相同一次预约的不同操作事件；渠道比较必须先定义首次渠道和变更渠道 | current-brief.md：不能把操作次数当成预约量 |
| 小样本限制 | 预约事件量不同会影响百分比波动；小渠道样本较少时应保留数量和限制说明 | current-brief.md：没有完整数据不能报告显著的渠道差异 |

### 1.5 排除口径

| 排除项 | 说明 |
|---|---|
| 医生个人绩效 | 资料中医生代码仅为流程角色示例，不追加医生排行榜，不利用服务时间做个体能力评价 |
| 跨科室/跨医院推断 | 本题材料只有一个门诊，不推断跨科室、跨医院或全市运营表现 |
| 临床判断 | 不给出任何临床判断或医疗建议 |
| 收费/处罚建议 | 不以收费或处罚作为默认整改建议 |


## 二、流程图说明（文字版）

### 2.1 预约事件状态流转（基于现有资料可核查部分）

```
预约创建（电话/网页/窗口）
        │
        ▼
   [预约事件进入系统]
        │
        ├──► 系统记录 CANCELLED ──► 归入"主动取消"类
        │         （取消时间与就诊时间均为医院本地时区）
        │
        ├──► 系统记录 ARRIVED ──► 归入"到诊"类
        │
        └──► 系统记录 UNKNOWN ──► 归入"待核验"类
                  │
                  ▼
         [观察窗口未确定，暂不归入最终状态]
                  │
                  ▼
         待核验事件清单（不进入爽约率计算）
```

### 2.2 流程说明

1. **预约创建**：渠道为电话、网页、窗口三类之一。同一预约可能存在多个渠道操作事件，渠道归属需先定义"首次渠道"与"变更渠道"。
2. **状态记录**：系统记录到诊状态为 ARRIVED、CANCELLED 或 UNKNOWN。
3. **UNKNOWN 处理**：在观察窗口未确定前，UNKNOWN 事件一律列为待核验，不自动归入爽约。
4. **取消规则**：旧流程（提前24小时取消不计爽约）与新会议草稿（提前12小时，尚未批准）存在差异，报告中并列呈现，不按文件修改时间断定新规则生效。
5. **爽约判定**：仅在观察窗口与取消免责边界经业务确认后，方可对满足条件的未到诊事件进行爽约归类。当前方案不执行该归类。


## 三、拟议数据采集字段建议

> 以下字段为拟议采集建议，实施前仍需合规评估；不写成已经建表或已获得数据授权。

### 3.1 现有字段（来自当前汇总表）

| 字段名 | 说明 | 用途 |
|---|---|---|
| 预约事件编号 | 唯一标识一次预约 | 主键，区分事件 |
| 预约渠道 | 电话/网页/窗口 | 渠道分析 |
| 到诊状态 | ARRIVED / CANCELLED / UNKNOWN | 状态分类 |
| 预约取消时间 | 医院本地时区 | 取消规则核验 |
| 就诊时间 | 医院本地时区 | 观察窗口核验 |

### 3.2 建议补充字段（拟议，需合规评估后实施）

| 字段名 | 说明 | 用途 | 备注 |
|---|---|---|---|
| 状态更新时间 | 到诊状态最后一次更新的时间戳 | 判断 UNKNOWN 是否为延迟同步 | 需确认来源系统 |
| 取消时间 | 用户发起取消的时间（与就诊时间同本地时区） | 核验取消提前量 | 需确认与现有"预约取消时间"是否同一字段 |
| 来源系统 | 记录该状态/事件的操作系统标识 | 核查 UNKNOWN 是否来自特定系统同步问题 | 需确认系统清单 |
| 首次渠道 | 该预约事件首次记录的渠道 | 渠道比较主口径 | 需业务确认定义 |
| 变更渠道 | 该预约事件后续发生渠道变更的记录 | 区分操作次数与预约量 | 需业务确认定义 |
| 患者去重标识 | 用于去重患者的匿名标识（非可识别信息） | 若业务决定以去重患者为主统计单位时使用 | 需隐私合规评估 |

### 3.3 不建议采集的字段

| 字段 | 原因 |
|---|---|
| 患者姓名、证件号、联系方式 | 隐私边界，本分析不需要 |
| 医生姓名/工号 | 不涉及个人绩效评估 |
| 诊断、处方、医嘱信息 | 超出运营分析范围 |

## 五、人工复核及隐私边界清单

### 5.1 人工复核清单

| 复核项 | 复核内容 | 复核目的 |
|---|---|---|
| UNKNOWN 状态事件 | 逐条核查 UNKNOWN 事件的来源系统、状态更新时间、现场登记记录 | 区分设备同步延迟、现场漏登记、记录缺项；不得直接归为患者责任 |
| 取消时间与就诊时间 | 核查取消时间是否早于就诊时间、提前量是否可计算 | 为取消规则核验提供依据（当前不判定爽约） |
| 渠道归属 | 核查同一预约事件是否存在多个渠道操作记录 | 区分首次渠道与变更渠道，避免操作次数当成预约量 |
| 时区一致性 | 核查取消时间与就诊时间是否均为医院本地时区 | 确认无时区转换偏差 |
| 预约事件编号唯一性 | 核查编号是否唯一、是否存在重复或缺失 | 确保事件计数准确 |

### 5.2 隐私边界清单

| 边界项 | 要求 |
|---|---|
| 不展示患者可识别信息 | 表格只展示合成汇总信息，不含患者姓名、证件号、联系方式等 |
| 不展示医生可识别信息 | 医生代码仅为流程角色示例，不追加医生排行榜或个体能力评价 |
| 不展示敏感诊疗明细 | 不包含诊断、处方、医嘱、分诊优先级等临床信息 |
| 去重患者标识 | 若需去重，使用匿名标识，不引入可识别信息 |
| 短信提醒等扩展需求 | 如后续要求短信提醒方案，需另行确认通知授权和退订流程；本次不将提醒需求扩成实施任务 |
| 拟议采集字段 | 状态更新时间、取消时间、来源系统等字段实施前需合规评估，不写成已建表或已获授权 |
