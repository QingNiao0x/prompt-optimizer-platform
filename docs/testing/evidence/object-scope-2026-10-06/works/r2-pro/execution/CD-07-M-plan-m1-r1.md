### 1.2 流程图说明（文字版）

```
[预约事件产生]
      │
      ▼
[记录首次渠道] ──→ 电话 / 网页 / 窗口
      │
      ▼
[可能发生渠道变更操作] ──→ 记录变更渠道，不合并为同一操作次数
      │
      ▼
[预约时间到达 / 取消 / 未到]
      │
      ├── ARRIVED ──→ 到诊
      ├── CANCELLED ──→ 记录取消时间（医院本地时区）
      └── UNKNOWN ──→ 待核验，不直接计为爽约
      │
      ▼
[观察窗口判定] ──→ 未决：窗口未确定前只展示待核验事件
      │
      ▼
[最终状态归类] ──→ 未决：不能因到期自动视为最终状态
      │
      ▼
[爽约率计算] ──→ 仅在窗口与最终状态判定明确后执行
```

**流程边界说明：**
- 电话与网页可能记录同一预约的不同操作事件，渠道比较必须先定义首次渠道和变更渠道。
- UNKNOWN 状态在缺少来源核查时，不能解释为患者责任。
- 取消状态不意味着治疗结束、病情缓解或不再需要服务。
- 观察窗口未确定前，只应展示待核验事件，不应将尚未到期的预约算入爽约率。
