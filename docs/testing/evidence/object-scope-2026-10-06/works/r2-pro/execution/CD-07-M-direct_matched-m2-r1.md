# 合成门诊预约到诊与爽约情况内部运营分析方案

**分析对象**：某合成门诊二〇二六年第一季度预约事件
**资料性质**：合成汇总数据，无真实患者信息，无完整逐条数据
**用途**：内部运营讨论，不涉及诊断、处方、分诊优先级、医嘱或个体治疗


## 一、口径梳理

### 1.1 基础口径表

| 口径项 | 定义/取值 | 依据 |
|---|---|---|
| 分析期间 | 2026年第一季度（2026-01-01 至 2026-03-31，医院本地时区） | 任务设定 |
| 分析对象 | 预约事件（预约事件编号唯一标识一次预约） | current-brief.md |
| 预约渠道 | 电话、网页、窗口（三类已明确，不另行询问） | current-brief.md |
| 到诊状态 | ARRIVED、CANCELLED、UNKNOWN | current-brief.md |
| 时区 | 预约取消时间与就诊时间均为医院本地时区；当前汇总表无时区转换证据 | current-brief.md |
| 患者与事件关系 | 一个患者可多次预约，事件数≠人数 | current-brief.md |
| 渠道操作与预约量关系 | 电话与网页可能记录同一预约的不同操作事件；渠道比较须先定义首次渠道和变更渠道，不能把操作次数当成预约量 | current-brief.md |

### 1.2 状态判定口径

| 状态 | 判定方式 | 备注 |
|---|---|---|
| ARRIVED | 系统记录到诊 | 直接采用 |
| CANCELLED | 系统记录用户主动取消 | 不附加临床解释（不推断治疗结束、病情缓解或不再需要服务） |
| UNKNOWN | 到诊状态未知 | 原因未细分；可能来自设备同步延迟、现场漏登记或记录缺项；**不得直接计为爽约**，不得解释为患者责任 |

### 1.3 爽约口径（须与未决项挂钩）

爽约率的分子与分母取决于两个**尚未决定**的参数，本方案不擅自取值：

| 未决项 | 当前状态 | 对口径的影响 |
|---|---|---|
| 预约未到诊的观察窗口 | 暂不确定；不能因到期自动视为最终状态 | 决定一个预约事件何时可归入最终状态；窗口未确定前，尚未到期的预约只展示为待核验事件，不计入爽约率 |
| 取消免责边界（提前24小时 vs 提前12小时） | 旧流程说明24小时；新会议草稿建议12小时，尚未批准 | 决定CANCELLED事件中哪些可豁免不计爽约；两份材料权威性未建立，须并列呈现，不按文件修改时间断定新规则生效 |
| 渠道比较主统计单位（预约事件 vs 去重患者） | 暂不确定 | 决定渠道比较的分母是事件数还是人数；两者不能混同 |

### 1.4 渠道比较口径

- 电话与网页可能记录同一预约的不同操作事件，**不能把操作次数当成预约量**。
- 渠道比较前必须先定义：
  - **首次渠道**：预约首次进入系统的渠道；
  - **变更渠道**：同一预约后续操作发生的渠道。
- 在首次渠道与变更渠道未定义、主统计单位未选定之前，渠道间比较仅展示事件数与去重患者数的并列描述，不做显著性判断。
- 小渠道样本较少时，保留数量并附加限制说明；没有完整数据不能报告显著的渠道差异。

### 1.5 流程图说明（文字版）

```
预约事件进入系统
      │
      ├── 记录首次渠道（电话/网页/窗口）
      │
      ├── 可能发生渠道变更操作（电话↔网页）
      │        └── 须单独标记变更渠道，不并入首次渠道计数
      │
      ├── 到诊状态记录
      │        ├── ARRIVED ──────────────→ 到诊
      │        ├── CANCELLED ────────────→ 取消（不附加临床解释）
      │        │        └── 是否豁免爽约取决于取消免责边界（未决）
      │        └── UNKNOWN ──────────────→ 待核验（不直接计为爽约）
      │
      └── 观察窗口（未决）
               ├── 窗口内：待核验事件，不计入爽约率
               └── 窗口外且状态仍非ARRIVED：按已确认规则判定
```

**流程说明要点**：
1. 渠道记录与到诊状态记录是两个独立环节，渠道操作次数不等于预约量。
2. UNKNOWN状态在观察窗口未确定前，一律列为待核验，不进入爽约分子。
3. CANCELLED是否豁免爽约，取决于取消免责边界（24小时/12小时未决），报告中并列呈现两种口径下的结果差异，不选定其一。

## 三、拟议数据采集表（合成数据采集字段建议）

以下为**拟议**采集字段，用于后续分析；**不是已建表或已获授权的声明**。实施前仍需合规评估。

### 3.1 预约事件基础字段

| 字段名 | 类型 | 说明 | 是否当前已有 |
|---|---|---|---|
| 预约事件编号 | 字符串 | 唯一标识一次预约 | 已有 |
| 患者去重标识 | 字符串（合成/脱敏） | 用于去重患者数，不含可识别信息 | 已有（合成） |
| 预约创建时间 | 日期时间（医院本地时区） | 首次进入系统时间 | 已有 |
| 首次渠道 | 枚举：电话/网页/窗口 | 预约首次进入系统的渠道 | 需从操作记录中定义提取 |
| 变更渠道 | 枚举：电话/网页/窗口/无 | 同一预约后续操作发生的渠道；无变更则标记“无” | 需从操作记录中定义提取 |
| 预约就诊时间 | 日期时间（医院本地时区） | 计划就诊时间 | 已有 |
| 到诊状态 | 枚举：ARRIVED/CANCELLED/UNKNOWN | 系统记录状态 | 已有 |
| 状态更新时间 | 日期时间（医院本地时区） | 状态最后变更时间，用于观察窗口判定 | 建议增加 |
| 取消时间 | 日期时间（医院本地时区）/空 | CANCELLED时记录；用于计算取消提前量 | 建议增加 |
| 来源系统 | 枚举/字符串 | 记录该事件状态的系统来源，用于核查UNKNOWN原因 | 建议增加 |

### 3.2 渠道操作事件字段（用于区分操作次数与预约量）

| 字段名 | 类型 | 说明 |
|---|---|---|
| 操作事件编号 | 字符串 | 每次渠道操作的唯一标识 |
| 关联预约事件编号 | 字符串 | 关联到预约事件 |
| 操作渠道 | 枚举：电话/网页/窗口 | 本次操作发生的渠道 |
| 操作类型 | 枚举：创建/变更/取消/其他 | 区分首次创建与后续变更 |
| 操作时间 | 日期时间（医院本地时区） | 操作发生时间 |

### 3.3 采集表使用说明

- 以上字段用于**区分预约事件与渠道操作事件**，避免把操作次数当成预约量。
- 状态更新时间和取消时间为建议增加字段，用于支持观察窗口和取消提前量的判定；实施前需合规评估，不能写成已经建表或已获授权。
- 所有字段不含患者姓名、身份证号、联系方式、医生姓名等可识别信息；患者去重标识为合成或脱敏值。
- 当前汇总表无时区转换证据，采集时须确认各字段均为医院本地时区，不做跨时区换算。

## 七、已知事实、用户确认信息与必要假设的区分

| 类别 | 内容 |
|---|---|
| **已知事实（资料可核查）** | 渠道三类；到诊状态三类；事件数≠人数；电话与网页操作事件可能对应同一预约；UNKNOWN不直接计为爽约；时区为医院本地时区且无转换证据；旧24小时与新12小时差异并列；医生代码非绩效范围；仅一个门诊 |
| **用户确认信息** | 不询问渠道范围；观察窗口暂不确定；主统计单位暂不确定；取消免责边界不擅自采用 |
| **必要假设（仅限方案编写所需，不冒充事实）** | 无。所有影响指标计算的未决项均以“待确认”状态保留，不默认补全 |
