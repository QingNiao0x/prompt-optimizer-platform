### 1.2 流程图说明（文字版）

**预约事件状态流转（基于现有资料可确认的部分）**：

```
预约创建（渠道：电话/网页/窗口）
    │
    ├── 患者主动取消 → CANCELLED（记录取消时间）
    │        │
    │        └── 是否在免责窗口内取消？
    │                 ├── 窗口内 → 不计爽约
    │                 └── 窗口外 → 计入爽约（窗口定义待确认）
    │
    ├── 到诊 → ARRIVED
    │
    └── 未记录到诊 → UNKNOWN
             │
             └── 观察窗口是否已过？
                      ├── 未过 → 待核验事件，不纳入爽约率
                      └── 已过 → 需来源核查后另行归类（不得直接计为爽约）
```

**渠道操作事件与预约事件的关系（文字说明）**：

电话预约与网页预约可能记录相同一次预约的不同操作事件。分析渠道时，必须先区分：
- **预约事件层面**：以预约事件编号为准，一次预约只计一次；
- **操作事件层面**：同一预约可能在多个渠道留下操作痕迹，操作次数不等于预约量。

若需比较渠道，须先定义"首次渠道"（按时间顺序最先记录的渠道）和"变更渠道"（后续操作对应的渠道），并在报告中明确采用哪种定义。**当前尚未决定渠道比较的主统计单位（预约事件还是去重患者），不得默认补全。**

## 五、人工复核及隐私边界清单

### 5.1 人工复核清单

| 复核项 | 复核内容 | 复核目的 |
|---|---|---|
| UNKNOWN 状态核查 | 对 UNKNOWN 状态的预约事件，逐条核查来源系统记录，确认是设备同步延迟、现场漏登记还是记录缺项 | 避免将 UNKNOWN 误归为患者责任或爽约 |
| 取消时间与就诊时间核对 | 核对取消时间是否早于就诊时间，是否存在记录异常 | 保证取消提前量计算准确 |
| 渠道操作事件去重 | 对同一预约事件编号在多个渠道出现操作事件的情况，核对时间顺序，确认首次渠道与变更渠道的判定 | 避免操作次数被当成预约量 |
| 观察窗口到期事件 | 对已过观察窗口但仍为 UNKNOWN 的事件，逐条标记为待核验 | 防止未核验事件被纳入爽约率 |
| 时区一致性 | 核对所有时间字段是否均为医院本地时区，有无混入其他时区数据 | 保证时间口径一致 |

### 5.2 隐私边界清单

| 边界项 | 要求 |
|---|---|
