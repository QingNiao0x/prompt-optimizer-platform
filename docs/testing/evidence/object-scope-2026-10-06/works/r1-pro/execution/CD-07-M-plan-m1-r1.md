# 合成门诊二〇二六年第一季度预约到诊与爽约分析方案（讨论稿）

> 本方案仅用于内部运营讨论，对象为某合成门诊二〇二六年第一季度的预约事件汇总资料。资料不含真实患者信息，也不含完整逐条数据。本方案不涉及诊断、处方、分诊优先级、医嘱或个体治疗，不计算真实医院指标，不建议减少任何患者服务权益。

### 1.1 事实、确认信息与待定项分层

| 层级 | 内容 | 来源/状态 |
|---|---|---|
| 已知事实 | 预约事件编号可区分一次预约；一个患者可多次预约，事件数不等于人数 | current-brief.md |
| 已知事实 | 预约渠道为电话、网页、窗口三类 | current-brief.md；用户确认 |
| 已知事实 | 到诊状态为 ARRIVED、CANCELLED、UNKNOWN，UNKNOWN 原因未细分 | current-brief.md |
| 已知事实 | 取消时间与就诊时间均用医院本地时区；当前汇总表无时区转换证据 | current-brief.md；用户确认 |
| 已知事实 | 电话与网页可能记录同一预约的不同操作事件 | current-brief.md |
| 已知事实 | 旧流程说明：提前24小时取消不计爽约；新会议草稿建议提前12小时，尚未批准 | legacy-note.md |
| 待确认 | 预约未到诊的观察窗口如何定义 | 用户明确尚未决定 |
| 待确认 | 取消免责边界采用24小时还是12小时 | 用户明确不得默认补全 |

| 必要假设（仅用于方案结构，不用于计算） | 汇总表字段命名与状态取值按 current-brief.md 所列三类状态理解 | 方案性假设，需数据核对 |

### 1.2 指标口径表（讨论版，参数留空）

| 指标 | 分子 | 分母 | 时间边界 | 缺失值处理 | 当前状态 |
|---|---|---|---|---|---|
| 预约事件量 | 窗口内预约事件编号去重计数 | — | 待定：按预约创建时间或就诊时间 | 事件编号缺失则单列 | 可先展示数量 |
| 到诊率 | ARRIVED 事件数 | 已归为最终状态的预约事件数 | 观察窗口待定 | UNKNOWN 不计入分子，分母是否纳入待定 | 待窗口确认 |
| 取消率 | CANCELLED 事件数 | 已归为最终状态的预约事件数 | 观察窗口待定 | 同上 | 待窗口确认 |
| 爽约率 | 待定：是否仅指未取消且未到诊 | 已归为最终状态的预约事件数 | 观察窗口待定 | UNKNOWN 不得直接计为爽约 | 待定义 |
| 待核验事件量 | UNKNOWN 事件数 | — | 窗口未确定前单独展示 | 不并入爽约 | 可先展示数量 |
| 渠道分布 | 按首次渠道/变更渠道分别计数 | 预约事件数或去重患者数（待定） | 待定 | 渠道缺失单列 | 待主单位确认 |
| 取消提前量分布 | 按取消时间与就诊时间差值分桶 | 有取消时间的事件数 | 医院本地时区 | 时区无转换证据，需标注 | 待免责边界确认 |

**口径一致性要求：**
- 所有比率的分母必须来自同一时间边界和同一最终状态判定规则。
- UNKNOWN 在窗口未确定前只展示为待核验事件，不进入爽约率分子。
- 事件数与人数不得混用；若未选择主统计单位，所有渠道比较只展示数量与限制说明，不报告百分比差异。
- 时区未转换前，取消提前量分桶需标注“本地时区，未做转换核验”。

### 1.3 渠道比较的前置定义

| 定义项 | 说明 | 状态 |
|---|---|---|
| 首次渠道 | 一次预约中最早记录的操作渠道 | 需在采集表中标记 |
| 变更渠道 | 同一预约后续操作涉及的渠道 | 需在采集表中标记 |
| 操作事件 | 电话或网页可能对同一预约产生多次操作记录 | 不得直接计为预约量 |
| 主统计单位 | 预约事件或去重患者 | 待确认，不得混同 |

## 二、流程图说明（文字版）

```
[预约创建]
    │
    ├─ 记录：事件编号、患者去重标识（合成）、首次渠道、创建时间
    │
    ▼
[预约变更/操作]
    │
    ├─ 记录：变更渠道、操作时间、来源系统
    │
    ▼
[就诊时间到达]
    │
    ├─ 状态：ARRIVED / CANCELLED / UNKNOWN
    │
    ▼
[观察窗口判定]
    │
    ├─ 窗口未确定：仅展示待核验事件，不判最终状态
    │
    ├─ 窗口确定后：归为最终状态
    │
    ▼
[指标计算]
    │
    ├─ 到诊率、取消率、爽约率（爽约定义待定）
    │
    └─ 渠道比较（主单位待定，小样本保留数量与限制说明）
```

**流程问题清单：**

| 编号 | 问题 | 影响 | 当前处理 |
|---|---|---|---|
| P1 | 电话与网页可能记录同一预约的不同操作事件 | 渠道比较可能把操作次数当预约量 | 先定义首次渠道与变更渠道 |
| P2 | UNKNOWN 原因未细分 | 无法区分同步延迟、漏登记、记录缺项 | 只展示待核验事件，不解释为患者责任 |
| P3 | 观察窗口未确定 | 尚未到期预约可能被误算入爽约率 | 窗口未确定前不判最终状态 |
| P4 | 取消免责边界存在24小时与12小时差异 | 取消率与爽约率口径不一致 | 并列呈现，不擅自采用 |
| P5 | 汇总表无时区转换证据 | 取消提前量分桶可能偏差 | 标注本地时区，未做转换核验 |
| P6 | 主统计单位未选择 | 事件数与人数混用会导致分母不一致 | 待确认，不混同 |
| P7 | 小渠道样本量少 | 百分比波动大，不能报告显著差异 | 保留数量与限制说明 |
| P8 | 医生代码仅为流程角色示例 | 不得用于个人绩效评估 | 不追加医生排行榜 |
| P9 | 科室类型可能影响行为，但只有一个门诊 | 不能推断跨科室、跨医院表现 | 限定在本合成门诊 |
| P10 | 拟议采集表涉及状态更新时间、取消时间、来源系统 | 实施前需合规评估 | 不写成已建表或已获授权 |
