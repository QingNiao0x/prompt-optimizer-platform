# 提示词整理工具对照研究方案

## 1. 研究问题

本研究考察提示词整理方式对下游任务输出的影响，比较三种条件：原始需求直接输入、经直接增强后的提示词、经交互式计划确认后生成的提示词。研究不评价任何产品绝对优劣，只回答一个核心问题：在相同初始材料下，不同提示词整理路径是否带来可区分的结果质量差异；若存在差异，差异主要来自新增确认信息，还是来自交互组织方式本身。

## 2. 实验设计

**任务集。** 固定二十个任务，覆盖开发方案类与文本写作类。开发任务要求下游模型只输出方案、不实际修改仓库；写作任务要求交付文本。跨任务不使用代码测试通过率作为统一质量指标。

**条件与分组。** 设四个条件：

- **A 原始组**：接收原始需求与初始材料，不做提示词增强。
- **B 直接增强组**：接收由同一初始信息得到的优化提示词，不接触计划确认组后来回答的业务选择。
- **C 计划确认组**：系统先提问，实验操作者按预先制定答案卡作答，再生成最终提示词。记录每个问题、选项、推荐依据和答案，不只保存最终提示词；错误推荐被答案纠正后仍计入交互阶段风险。
- **D 信息量匹配对照组**：获得与 C 组相同的已确认事实，但不经历本平台问答过程。用于区分“新增信息”与“交互组织方式”的贡献。

A、B 两组不得接触 C 组后续确认的业务选择；C、D 两组在已确认事实层面信息量相同，差异仅在是否经历问答交互。

**重复与随机化。** 每个条件对每个任务独立重复三次，共 20 × 4 × 3 = 240 次下游生成。每次重复开启隔离会话，随机化任务顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本；工具失败和首轮失败均保留。

**材料与来源标签。** 所有条件获取相同初始材料。任务材料保留真实实现、用户说明、测试示例与待办等来源标签；不在人工评分前人为删除不利的测试污染反例。

## 3. 评价方案

两名盲评者独立评分。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可以查看任务事实，但不能查看另一名评审先前评分。

评分同时覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。一个错误可能同时影响多个维度，评分表记录主错误和关联维度，避免将同一问题多次计成不同独立失败。

工具生成速度作为过程指标单独记录，质量分作为结果指标。没有计费日志时不估算真实 Token 成本，不把字符数换算为实际费用。

## 4. 统计与推断

候选统计方法依赖分数是否有序、是否连续、是否重复测量。本方案只规定选择流程：先确认评分分布性质与重复测量结构，再据此选择检验方法；不在变量尚未确定时锁定某个显著性检验。即使三个条件给出相似结论，也不构成研究完成证据；需结合人工评阅与可复核任务标准判断，专业领域判断尚需专家参与。

## 5. 限制

本研究为尚未执行的对照设计，不含实验结果。交互式计划确认的最大轮次与终止规则、两名评审的分歧处理与一致性评价方式、信息量匹配对照的具体呈现格式均待预注册确认，不预设具体参数。研究结论仅适用于本任务集、本模型版本与本次评分口径，不推广为产品能力认证。
