# 提示词整理工具对照研究方案

## 1. 研究问题

本研究考察三种提示词准备条件对下游任务输出质量的影响：原始需求直接输入、直接增强提示词、交互式计划确认后生成提示词。核心问题不是“哪家产品更好”，而是：在相同初始材料下，交互式计划确认是否带来可归因于交互组织方式本身的质量变化，而非仅因操作者额外回答了业务问题而获得更多信息。

## 2. 实验设计

**任务集。** 固定二十个任务，覆盖开发方案类与写作交付类。开发任务要求下游模型只输出方案、不修改仓库；写作任务要求交付文本。跨任务不采用代码测试通过率作为统一质量指标。

**条件与分组。** 四个条件，每个条件对每个任务独立重复三次，共 240 份下游输出。

- **A 原始组**：下游模型直接接收原始需求与初始材料。
- **B 直接增强组**：接收由同一初始信息生成的优化提示词，不接触计划确认组的后续回答。
- **C 计划确认组**：系统先提问，实验操作者按预先制定的答案卡作答，再生成最终提示词。记录每个问题、选项、推荐依据和答案；错误推荐被答案纠正后仍计入交互阶段风险。
- **D 信息量匹配对照**：获得与 C 组相同的已确认事实，但不经历本平台问答过程。用于分离“新增信息”与“交互组织方式”的效应。

A、B 两组不得接触 C 组后来回答的业务选择；D 组仅获得事实，不获得问答过程。

**会话与记录。** 每个条件的三次重复开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本；工具失败和首轮失败均保留。

**材料标签。** 任务材料保留真实实现、用户说明、测试示例与待办等来源标签；不得在人工评分前删除不利的测试污染反例。

## 3. 盲评与指标

两名盲评者独立评分，看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可查看任务事实，但不能看另一名评审的先前评分。

评分同时覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。一个错误可能同时影响多个维度，评分表记录主错误和关联维度，避免同一问题多次计成不同独立失败。

工具生成速度作为过程指标单独记录；质量分为结果指标。没有计费日志时不估算真实 Token 成本，不把字符数换算为实际费用。

## 4. 统计与限制

候选统计方法依赖分数是否有序、是否连续及是否重复测量，方案在变量确定后按选择流程确定，不预先锁定某个显著性检验。即使三个条件给出相似结论也不构成研究完成证据；安排人工评阅与可复核任务标准，专业领域判断尚需专家参与。

**主要限制**：交互式计划确认的最大轮次与终止规则尚未预注册；两名评审的分歧处理与一致性评价方式尚未确定。两者均列入待确认清单，不默认补全。


## 附表 A：变量与分组

| 变量 | 类型 | 取值/说明 |
|---|---|---|
| 条件 | 自变量，四水平 | A 原始 / B 直接增强 / C 计划确认 / D 信息量匹配对照 |
| 任务 | 固定因素 | 20 个，开发方案类与写作交付类混合 |
| 重复 | 重复测量 | 每条件每任务 3 次，隔离会话 |
| 模型版本、日期、参数 | 记录变量 | 每次会话记录 |
| 交互轮次、问题、选项、推荐依据、答案 | 过程记录 | 仅 C 组；错误推荐被纠正仍记录 |
| 工具失败、首轮失败 | 事件记录 | 所有条件保留，重试不替代首份失败样本 |
| 生成速度 | 过程指标 | 单独记录，不进入质量分 |
| 五维评分 | 结果指标 | 需求保真、业务规则、输出可用性、阅读负担、执行边界 |
| 主错误与关联维度 | 评分记录 | 防止同一错误重复计分 |

**分组信息对照**：A、B 组仅获得初始材料；C 组获得初始材料＋问答过程＋确认事实；D 组获得初始材料＋确认事实（无问答过程）。C 与 D 的对比用于分离信息增量与交互组织方式；A 与 B 的对比用于分离原始需求与直接增强；B 与 D 的对比用于在相近信息量下观察交互组织方式效应。
