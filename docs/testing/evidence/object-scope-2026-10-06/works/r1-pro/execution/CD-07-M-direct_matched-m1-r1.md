# 合成门诊 2026 年第一季度预约到诊与爽约分析方案（讨论稿）

> 本方案仅用于内部运营讨论，基于合成材料与方法草案，不涉及诊断、处方、分诊优先级、医嘱或个体治疗，不计算真实医院指标，不建议减少任何患者服务权益。所有表格仅展示合成汇总信息，不含患者、医生可识别信息或敏感诊疗明细。

### 1.2 流程图说明（文字版）

```
[预约事件产生]
      |
      v
[记录首次渠道] —— 电话 / 网页 / 窗口
      |
      v
[可能发生渠道变更操作] —— 同一预约的不同操作事件
      |
      v
[记录到诊状态] —— ARRIVED / CANCELLED / UNKNOWN
      |
      +--> ARRIVED：到诊
      |
      +--> CANCELLED：系统记录用户主动取消；不附加临床解释
      |         |
      |         v
      |   [判断取消提前量] —— 24h 或 12h 争议未决
      |
      +--> UNKNOWN：原因未细分（设备同步延迟/现场漏登记/记录缺项）
                |
                v
          [待核验，不直接计为爽约]
      |
      v
[观察窗口] —— 未确定；窗口未到只展示待核验
      |
      v
[最终状态判定] —— 窗口+免责边界确定后才可归为爽约
```

## 二、流程问题清单

| 编号 | 问题 | 材料依据 | 状态 |
|---|---|---|---|
| P1 | 电话与网页可能记录同一预约的不同操作事件，渠道比较不能把操作次数当预约量 | current-brief.md | 已明确，需先定义首次/变更渠道 |
| P2 | 取消状态仅表示系统记录用户主动取消，不意味治疗结束或不再需要服务 | current-brief.md | 已明确，报告不得附加临床解释 |
| P3 | UNKNOWN 可能来自设备同步延迟、现场漏登记或记录缺项，不能解释为患者责任 | current-brief.md | 已明确 |
| P4 | 观察窗口未确定前只展示待核验事件，未到期预约不算入爽约率 | current-brief.md | **待确认** |
| P5 | 旧流程 24 小时取消不计爽约 vs 新会议草稿 12 小时，尚未批准 | legacy-note.md | **争议，不擅自采用** |
| P6 | 预约事件量不同影响百分比波动，小渠道样本少应保留数量与限制说明 | current-brief.md | 已明确 |
| P7 | 医生代码仅为流程角色示例，不能追加排行榜或个体能力评价 | current-brief.md | 已明确 |
| P8 | 科室类型可能影响预约提前量和到诊行为，但只有一个门诊，不推断跨科室 | current-brief.md | 已明确 |
| P9 | 拟议采集表可增加字段，实施前需合规评估，不能写成已建表或已授权 | current-brief.md | 已明确 |
| P10 | 改进建议优先清楚提示取消规则、核对登记质量、便捷改约，不默认罚款/降资格/公开记录 | current-brief.md | 已明确 |
| P11 | 短信提醒需另行确认通知授权和退订流程，本次不扩成发送短信实施任务 | current-brief.md | 已明确 |
| P12 | 报告应标注合成材料与方法草案，专业评审后才能应用，不宣称提高疗效 | current-brief.md | 已明确 |
| P13 | 主统计单位用预约事件还是去重患者尚未决定 | 任务待确认项 | **待确认** |

## 三、拟议数据采集字段建议

> 以下仅为建议字段，**未声称已建表或已获授权**；实施前需合规评估。

| 字段类别 | 建议字段 | 说明 |
|---|---|---|
| 事件标识 | 预约事件编号 | 区分一次预约 |

| 渠道 | 首次渠道、变更渠道、渠道变更时间 | 支持首次/变更渠道定义 |
| 状态 | 到诊状态、状态更新时间、状态来源系统 | 支持 UNKNOWN 来源核查 |

| 观察 | 观察窗口截止时间、是否到期、是否待核验 | 窗口未定，先留空 |
| 来源 | 来源系统、记录版本 | 支持来源核查 |
| 合规 | 合规评估状态、授权状态 | 实施前填写 |
