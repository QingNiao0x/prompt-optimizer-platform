## 一、口径梳理

### 1.1 核心统计单位

| 口径项 | 当前状态 | 说明 |
|---|---|---|
| 预约事件 | 可用 | 预约事件编号可区分一次预约，作为事件级统计的基础单位 |
| 去重患者 | 不可用 | 一个患者可多次预约，事件数不等于人数；当前资料未提供患者去重标识，无法按患者统计 |
| 渠道比较主统计单位 | **待确认** | 用预约事件还是去重患者作为主统计单位，尚未决定，本方案不默认采用任何一项 |

### 1.2 到诊状态口径

| 状态 | 运营含义 | 分析处理 |
|---|---|---|
| ARRIVED | 系统记录已到诊 | 计入到诊事件 |
| CANCELLED | 系统记录用户主动取消 | 单独统计，不附加临床解释；不视为治疗结束或病情缓解 |
| UNKNOWN | 原因未细分 | **不计为爽约**；列为待核验事件，单独展示 |

**关键边界**：UNKNOWN 可能来自设备同步延迟、现场漏登记或记录缺项，不能解释为患者责任。在来源核查完成前，UNKNOWN 不进入爽约分子。

### 1.3 爽约的当前可操作性定义

由于观察窗口和取消免责边界尚未确定，本方案**不给出爽约率数值**，仅定义爽约的构成条件框架：

- 爽约的判定需要同时满足：
  1. 预约事件已过观察窗口（窗口时长**待确认**）；
  2. 到诊状态经核验后确认为"未到诊且未取消"（当前 UNKNOWN 不满足此条件）；
  3. 取消行为不满足免责边界（提前量标准**待确认**，见 1.4）。
- 在以上条件未确定前，报告中只展示"待核验事件"和"已确认取消事件"，不计算爽约率。

### 1.4 取消免责边界的规则差异

| 来源 | 提前取消要求 | 审批状态 |
|---|---|---|
| 旧流程说明（资料B） | 提前24小时取消不计爽约 | 旧版，现行状态未明确废止 |
| 新会议草稿（资料C） | 建议提前12小时 | **尚未批准** |

**处理方式**：两份材料的权威性未建立，报告须将差异单独呈现，不按文件修改时间推断新规则生效，不擅自采用其中一项。在运营讨论中，将两种口径分别标注为"旧流程口径（24小时）"和"草稿口径（12小时，未批准）"，供决策者明确选择后再行计算。

### 1.5 渠道口径

| 渠道 | 口径说明 |
|---|---|
| 电话 | 电话渠道产生的预约事件 |
| 网页 | 网页渠道产生的预约事件 |
| 窗口 | 窗口渠道产生的预约事件 |

**关键边界**：电话预约与网页预约可能记录相同一次预约的不同操作事件。渠道比较必须先定义"首次渠道"和"变更渠道"，不能把操作次数当成预约量。当前资料未提供操作日志或渠道变更记录，因此渠道维度仅按预约事件编号关联的最终记录渠道进行展示，并标注"渠道归属口径待确认"。

### 1.6 时间口径

- 预约取消时间与就诊时间均使用医院本地时区。
- 当前汇总表没有时区转换证据，分析中不进行任何时区换算。
- 观察窗口（预约事件何时可归为最终状态）**尚未确定**，窗口未确定前只展示待核验事件，不将尚未到期的预约算入爽约。

### 2.2 流程中标注的待确认节点

| 节点 | 待确认内容 | 影响 |
|---|---|---|
| 观察窗口 | 预约事件何时可判定为最终状态 | 决定 UNKNOWN 何时可以进入核验流程 |
| 取消免责边界 | 24小时（旧）还是12小时（草稿，未批准） | 决定 CANCELLED 中哪些属于免责取消 |
| 渠道归属 | 首次渠道与变更渠道的定义 | 决定渠道比较的统计口径 |
| 统计单位 | 预约事件还是去重患者 | 决定渠道比较和整体分析的主单位 |

以下问题基于现有资料可直接识别，按流程环节分组：

| 编号 | 问题 | 依据 | 影响 |

## 三、拟议数据采集表

以下字段为**拟议**采集内容，用于支持后续运营分析。实施前需完成合规评估，当前不视为已建表或已获得数据授权。

### 3.1 预约事件基础字段

| 字段名 | 类型 | 说明 | 采集目的 |
|---|---|---|---|
| 预约事件编号 | 文本 | 唯一标识一次预约 | 事件级统计基础 |
| 预约创建时间 | 日期时间 | 医院本地时区 | 分析预约提前量 |
| 预约就诊时间 | 日期时间 | 医院本地时区 | 判断观察窗口 |
| 预约渠道 | 枚举（电话/网页/窗口） | 最终记录渠道 | 渠道维度分析 |
| 首次渠道 | 枚举（电话/网页/窗口） | **拟新增**，需定义采集规则 | 区分首次渠道与变更渠道 |
| 渠道变更记录 | 文本/列表 | **拟新增**，记录渠道变更历史 | 避免操作次数误计为预约量 |
| 到诊状态 | 枚举（ARRIVED/CANCELLED/UNKNOWN） | 当前状态 | 状态分布分析 |
| 状态更新时间 | 日期时间 | **拟新增**，医院本地时区 | 判断状态是否为最终状态 |
| 取消时间 | 日期时间 | **拟新增**，医院本地时区，仅 CANCELLED 状态填写 | 计算取消提前量 |
| 来源系统 | 文本 | **拟新增**，记录数据写入系统 | 核查 UNKNOWN 来源 |

### 3.2 待核验事件补充字段

| 字段名 | 类型 | 说明 | 采集目的 |
|---|---|---|---|
| UNKNOWN 来源核查标记 | 枚举（未核查/同步延迟/漏登记/记录缺项/其他） | **拟新增**，需人工核查后填写 | 区分 UNKNOWN 的具体原因 |
| 核查时间 | 日期时间 | **拟新增** | 记录核查动作 |
| 核查人员角色 | 文本（非个人姓名） | **拟新增**，仅记录角色 | 流程追溯 |

### 3.3 明确不采集的字段

| 不采集内容 | 原因 |
|---|---|
| 患者姓名、证件号、联系方式 | 隐私边界，本分析不需要 |
| 医生姓名、医生个人绩效数据 | 资料A明确医生代码仅为流程角色示例，不追加个人评估 |
| 诊断、处方、医嘱、分诊优先级 | 超出运营分析范围 |
| 敏感诊疗明细 | 资料约束明确禁止 |

## 五、人工复核及隐私边界清单

### 5.1 人工复核清单

| 编号 | 复核项 | 复核内容 | 复核目的 |
|---|---|---|---|
| R1 | UNKNOWN 状态来源 | 逐条核查 UNKNOWN 事件属于设备同步延迟、现场漏登记还是记录缺项 | 决定是否可转为 ARRIVED 或确认未到诊，不默认归责患者 |
| R2 | 取消时间与就诊时间先后 | 核查 CANCELLED 事件的取消时间是否早于就诊时间 | 排除数据录入错误 |
| R3 | 渠道归属 | 核查电话与网页渠道是否存在同一预约的重复操作记录 | 避免操作次数误计为预约量 |
| R4 | 观察窗口内事件 | 核查就诊时间尚未到达或刚到达的预约是否被误归为最终状态 | 防止未到期预约进入爽约统计 |
| R5 | 取消免责边界适用 | 在决策确定前，核查取消事件在24小时口径和12小时口径下的不同归类 | 呈现规则差异对结果的影响 |
| R6 | 时区一致性 | 核查取消时间与就诊时间是否均为医院本地时区 | 排除时区混用导致的先后关系错误 |

### 5.2 隐私边界清单

| 编号 | 边界项 | 要求 |
|---|---|---|
| PR1 | 患者身份信息 | 不采集、不展示患者姓名、证件号、联系方式、住址等可识别信息 |
| PR2 | 医生身份信息 | 医生代码仅作为流程角色示例，不展示医生姓名，不追加医生排行榜 |
| PR3 | 敏感诊疗明细 | 不展示诊断、处方、医嘱、分诊优先级、治疗内容 |
| PR4 | 个体行为归因 | 不将取消或 UNKNOWN 状态解释为患者个人责任或临床行为 |
| PR5 | 小样本渠道 | 小渠道样本较少时保留数量并标注限制，不报告显著渠道差异 |
| PR6 | 短信提醒授权 | 如后续涉及短信提醒，须另行确认通知授权和退订流程，本次不实施 |
| PR7 | 报告发布 | 报告标注合成材料与方法草案，专业评审后才能应用 |
