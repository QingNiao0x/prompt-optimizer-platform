# 合成门诊预约运营分析方案（二〇二六年第一季度）

> 用途：内部运营讨论稿，仅分析预约到诊与爽约相关流程与数据口径。不含临床判断、诊断、处方、分诊优先级、医嘱或个体治疗。所有数据均为合成汇总信息，不涉及真实患者或医生可识别信息。


## 一、口径梳理

### 1.1 核心统计单位

| 口径项 | 当前状态 | 说明 |
|---|---|---|
| 预约事件 | 可作为基础计数单位 | 预约事件编号可区分一次预约；一个患者可多次预约，事件数不等于人数 |
| 去重患者 | 是否作为主统计单位 | **待确认**。比较渠道时使用预约事件还是去重患者作为主统计单位，当前尚未决定，不得默认补全 |
| 渠道操作次数 | 不得作为预约量 | 电话与网页可能记录同一次预约的不同操作事件；渠道比较必须先定义首次渠道和变更渠道 |

**使用原则**：在未确定主统计单位前，报告应同时保留"预约事件数"口径，并对涉及去重患者的任何结论标注"统计单位待确认"。不得混同两个口径。

### 1.2 到诊状态口径

| 状态值 | 运营分析口径 | 备注 |
|---|---|---|
| ARRIVED | 已到诊 | 系统记录到诊 |
| CANCELLED | 已取消 | 系统记录到用户主动取消；不附加临床解释，不推断病情变化或不再需要服务 |
| UNKNOWN | 待核验 | 可能来自设备同步延迟、现场漏登记或记录缺项；**不得直接计为爽约**，不得解释为患者责任 |

**爽约的判定前提**：只有当一个预约事件已过观察窗口、且经人工核验确认"未到诊且未取消"后，方可归入爽约。当前观察窗口未确定，因此本季度所有 UNKNOWN 状态均以"待核验"列示，不进入爽约率计算。

### 1.3 取消免责边界

| 来源 | 内容 | 状态 |
|---|---|---|
| 旧流程说明（legacy-note.md） | 提前24小时取消不计爽约 | 旧版口径 |
| 新会议草稿 | 建议提前12小时取消不计爽约 | **尚未批准** |

**处理方式**：两份材料存在差异，权威性未建立。报告须将24小时与12小时两个口径并列呈现为"待审批事项"，不得按文件修改时间或新旧顺序自行采用其中一项。在未确定前，取消相关分析仅按"已取消"事实统计，不判定是否构成爽约。

### 1.4 观察窗口

| 口径项 | 状态 |
|---|---|
| 预约未到诊的观察窗口 | **待确认**。当前尚未决定，不得默认补全 |
| 窗口未确定前 | 只展示待核验事件，不将尚未到期的预约算入爽约率 |

### 1.5 时区口径

预约取消时间与就诊时间均使用医院本地时区。当前汇总表没有时区转换证据。分析中所有时间字段按医院本地时区理解，不进行跨时区换算；如后续发现数据来源含不同时区，需先补充转换证据再行合并。

### 2.2 渠道归属流程（文字说明）

1. 一次预约事件可能通过电话、网页或窗口创建。
2. 同一预约可能在不同渠道产生多个操作记录（如电话创建后网页修改）。
3. 渠道比较前必须定义：
   - **首次渠道**：预约事件创建时记录的渠道；
   - **变更渠道**：后续操作发生的渠道。
4. 在"首次渠道"与"变更渠道"定义未确定前，渠道维度仅展示按预约事件编号去重后的创建渠道分布，并标注"操作次数不等于预约量"。


## 三、拟议数据采集字段建议

以下字段用于支持后续运营分析，均为合成数据。实施前需经合规评估，不视为已建表或已获授权。

### 3.1 预约事件基础字段

| 字段名 | 建议类型 | 用途 | 是否含敏感信息 |
|---|---|---|---|
| 预约事件编号 | 文本/去标识化ID | 区分一次预约 | 否（需去标识化） |
| 患者去标识化编号 | 文本/去标识化ID | 识别同一患者多次预约（仅用于去重统计） | 是，需去标识化处理 |
| 预约创建时间 | 日期时间（医院本地时区） | 计算提前预约时长 | 否 |
| 预约就诊时间 | 日期时间（医院本地时区） | 判断是否已到观察窗口 | 否 |
| 预约渠道（创建） | 枚举：电话/网页/窗口 | 渠道分布分析 | 否 |
| 首次渠道标记 | 布尔/枚举 | 区分首次渠道与变更渠道 | 否 |
| 变更渠道记录 | 枚举（如有） | 识别多渠道操作 | 否 |

### 3.2 状态与时间字段

| 字段名 | 建议类型 | 用途 | 是否含敏感信息 |
|---|---|---|---|
| 到诊状态 | 枚举：ARRIVED/CANCELLED/UNKNOWN | 状态分类 | 否 |
| 状态更新时间 | 日期时间（医院本地时区） | 判断状态记录时点 | 否 |
| 取消时间 | 日期时间（医院本地时区，可空） | 计算取消提前量 | 否 |
| 到诊登记时间 | 日期时间（医院本地时区，可空） | 核验到诊记录 | 否 |
| 来源系统 | 文本（如预约系统/现场登记系统） | 追踪 UNKNOWN 来源 | 否 |
| 数据同步标记 | 布尔/枚举 | 识别同步延迟 | 否 |

### 3.3 采集注意事项

- 患者去标识化编号仅用于同一患者多次预约的去重统计，不得用于个体行为画像或患者责任判定。
- 医生代码如出现在数据中，仅作为流程角色示例，不纳入个人绩效评估，不追加医生排行榜。
- 所有字段在实施采集前需完成合规评估，包括数据授权、存储期限和访问权限。

## 五、人工复核及隐私边界清单

### 5.1 人工复核清单

| 复核项 | 复核内容 | 触发条件 |
|---|---|---|
| UNKNOWN 状态核验 | 逐条核查 UNKNOWN 事件：是否设备同步延迟、现场漏登记或记录缺项 | 所有 UNKNOWN 事件 |
| 取消时间核验 | 核对取消时间是否早于就诊时间，是否存在记录异常 | 所有 CANCELLED 事件 |
| 渠道归属核验 | 同一预约事件是否存在多渠道操作记录，确认首次渠道 | 渠道分析前 |
| 观察窗口核验 | 判断预约事件是否已过观察窗口（窗口口径确定后） | 爽约判定前 |
| 时区核验 | 确认所有时间字段均为医院本地时区，无跨时区混入 | 数据合并前 |

### 5.2 隐私边界清单

| 边界项 | 要求 |
|---|---|
| 患者信息 | 仅使用去标识化编号；不展示任何可识别患者信息；不公开患者记录 |
| 医生信息 | 医生代码仅作流程角色示例；不纳入个人绩效评估；不追加医生排行榜；不利用服务时间做个体能力评价 |
| 诊疗明细 | 不包含诊断、处方、医嘱、分诊优先级或个体治疗信息 |
| 取消行为 | 不附加临床解释；不推断病情缓解或不再需要服务 |
| 数据发布 | 仅限内部运营讨论；标注合成材料；专业评审后方可应用 |
| 短信提醒（如后续提出） | 需另行确认通知授权和退订流程；本次不扩为实施任务 |
