## 二、流程图说明

### 2.1 预约事件状态流转（文字版）

```
预约创建
  │
  ├─ 渠道记录：电话 / 网页 / 窗口
  │     └─ 若同一预约出现多渠道操作事件 → 标记“首次渠道”与“变更渠道”（规则待确认）
  │
  ▼
预约存续
  │
  ├─ 用户主动取消 → CANCELLED
  │     └─ 是否免责取决于取消提前量规则（24h vs 12h，待确认）
  │
  ├─ 到诊 → ARRIVED
  │
  └─ 观察窗口到期后仍无明确到诊/取消记录 → UNKNOWN
        └─ 单独列为“待核验事件”，不计入爽约
```

### 2.2 分析流程

```
步骤 1：确定统计单位（事件 / 去重患者）——待确认
步骤 2：确定观察窗口与取消免责边界——待确认
步骤 3：按渠道归集预约事件，区分首次渠道与变更渠道
步骤 4：状态分类
        ├─ ARRIVED
        ├─ CANCELLED（按免责规则细分）
        ├─ UNKNOWN（待核验）
        └─ 窗口未到期（待核验）
步骤 5：计算口径
        ├─ 到诊率 = ARRIVED / 已到期且状态明确的事件
        ├─ 取消率 = CANCELLED / 已到期且状态明确的事件
        └─ 爽约率 = 未到诊且非免责取消 / 已到期且状态明确的事件
步骤 6：渠道比较
        └─ 小样本渠道保留数量与限制说明，不报告显著差异
步骤 7：输出讨论版报告
```

### 2.3 流程问题清单

| 编号 | 问题 | 影响 | 当前处理 |
|---|---|---|---|
| P1 | 观察窗口未定义 | 无法判断预约事件是否已到期，爽约率分母不稳定 | 待确认；窗口未定前只展示待核验事件 |
| P2 | 取消免责边界未定义 | 24h 与 12h 两版规则冲突，无法统一计算免责取消 | 待确认；争议单独呈现，不擅自采用 |
| P3 | 渠道比较统计单位未定 | 事件数与去重患者数结果可能不同 | 待确认；两种口径可并列展示，但需标注主口径未定 |
| P4 | 同一预约多渠道操作事件 | 可能把操作次数误当预约量 | 需先定义首次渠道与变更渠道 |
| P5 | UNKNOWN 原因未细分 | 无法区分同步延迟、漏登记、记录缺项 | 单独列为待核验，不解释为患者责任 |
| P6 | 无时区转换证据 | 跨时区分析不可行 | 仅使用医院本地时区，不做转换推断 |
| P7 | 小渠道样本量少 | 百分比波动大，易误读 | 保留数量与限制说明，不报告显著差异 |
| P8 | 旧流程与新会议草稿冲突 | 规则适用性不明 | 单独呈现争议，等待审批状态明确 |
