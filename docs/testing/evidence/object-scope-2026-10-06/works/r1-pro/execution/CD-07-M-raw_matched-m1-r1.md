## 二、流程图说明

建议用泳道图或线性流程描述预约事件从产生到最终状态判定的路径，节点如下：

1. **预约产生**：患者通过电话、网页或窗口发起预约，生成预约事件编号。
2. **渠道记录**：记录首次渠道；若后续发生渠道变更，单独记录变更渠道，避免同一预约被重复计为多次预约量。
3. **预约确认**：系统记录预约时间、就诊时间（均为医院本地时区）。
4. **状态更新**：
   - 到诊 → ARRIVED；
   - 主动取消 → CANCELLED，记录取消时间；
   - 状态未知 → UNKNOWN，原因未细分，可能来自设备同步延迟、现场漏登记或记录缺项。
5. **观察窗口判定**：窗口未确定前，事件处于待核验状态，不进入爽约率分子或分母。
6. **最终状态归类**：窗口和取消免责边界明确后，再区分到诊、免责取消、非免责取消、爽约、仍未知。
7. **汇总输出**：按选定主统计单位（事件或去重患者，待确认）和渠道归因口径汇总。

流程图中应标注：UNKNOWN不得直接流向爽约；CANCELLED不附加临床解释；观察窗口未定前只展示待核验事件。

## 三、合成数据采集字段建议

以下为拟议采集字段，实施前仍需合规评估；不能写成已经建表或已获得数据授权。

| 字段类别 | 建议字段 | 说明 |
|---|---|---|
| 事件标识 | 预约事件编号 | 区分一次预约，不含患者可识别信息 |
| 时间字段 | 预约创建时间、就诊时间、取消时间、状态更新时间 | 均标注医院本地时区；状态更新时间用于识别同步延迟 |
| 渠道字段 | 首次渠道、变更渠道、渠道变更时间 | 用于定义首次渠道和变更渠道，避免操作次数当预约量 |
| 状态字段 | 到诊状态（ARRIVED/CANCELLED/UNKNOWN）、取消来源 | UNKNOWN原因未细分，采集时保留来源系统字段 |
| 来源系统 | 来源系统标识、同步批次 | 用于核查设备同步延迟或记录缺项 |
| 流程角色 | 医生代码（仅流程角色示例） | 不用于个人绩效评估 |
| 科室字段 | 科室类型 | 本题仅一个门诊，不用于跨科室推断 |
| 合规字段 | 数据授权状态、脱敏标识 | 实施前需合规评估 |

采集表只展示合成汇总信息，不包含患者、医生的可识别信息或敏感诊疗明细。

   - 标注合成材料与方法草案；
   - 明确需专业评审后才能应用；
   - 不宣称任何方案已提高疗效。

2. **背景与范围**
   - 分析对象：某合成门诊2026年第一季度预约事件；
   - 不涉及诊断、处方、分诊优先级、医嘱或个体治疗。

3. **口径与定义**
   - 事件单位、渠道范围、到诊状态、爽约口径、取消口径；
   - 观察窗口待确认；
   - 主统计单位待确认；
   - 取消免责边界争议并列呈现。

4. **流程梳理**
   - 预约产生、渠道记录、状态更新、观察窗口判定、最终状态归类；
   - 标注UNKNOWN不得直接计为爽约。

5. **待确认项与争议**
   - 观察窗口和取消免责边界；
   - 主统计单位选择；
   - 旧24小时与新12小时差异，不擅自采用。

6. **拟议数据采集表**
   - 字段建议与合规评估提示；
   - 不写成已建表或已获授权。

7. **讨论版分析框架**
   - 在口径确定后，可按渠道、状态、时间维度汇总；
   - 小渠道样本少时保留数量和限制说明；
   - 无完整数据不报告显著渠道差异。

8. **人工复核与隐私边界**
