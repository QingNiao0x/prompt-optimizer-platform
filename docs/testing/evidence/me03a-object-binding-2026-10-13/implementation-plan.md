# ME-03-A 研究评价对象局部生成指导

本节点获得主线授权实施最小生成指导，不新增真实模型调用，不改变回答状态投影文件。现有预算 169＝基线 70＋候选 99，候选余额 1，不足以验证新增强与下游作品链路。

## 失败依据

候选五 Q05 Flash Plan 的 trace 165 已收到 `RESEARCH_TOPIC=Plan问答对提示词质量的影响`，但模型仅在背景保留主题，TASK 评分步骤没有指定实际待评对象；平台保留这一含糊。trace 166 的作品首次将准确性与可执行性明确写成评价“回答”。同信息 direct 的 trace 168/169 明确评价提示词。对象漂移首现下游，不将它改记为平台篡改；单次差异不证明某句指导的因果效果。

## 最小实现

- `TaskMeaningContract.java`：沿用 `anchors` 中已有 `RESEARCH_TOPIC`，新增内部 `evaluationGuidance()`，无锚点时为空。指导通过已有锚点的原文区间保留来源，只要求模型在原任务确实包含比较、评审或评分时，把主题中明确的目标落实到 TASK 原对应步骤：实际待评对象/产物、评审接收的材料、各维度作用的对象；原要求有盲法时才对应盲评材料。
- `PromptRewriteStrategy.forTask`：追加这段仅本请求适用的内部生成指导；普通无研究锚点任务保持原输出。兼容 `forPrompt` 不猜测来源。
- 不改变 `EffectiveTaskView.ModelInput`、Anchor、HTTP 或历史结构；不新增模型调用、在线裁判和语义通过字段。现有 `TaskMeaningContract.validate` 仍仅声称覆盖受众误作研究对象，不能冒充新增评分语义校验。
- 不修改 `OptimizationResultAssembler`。最终正文应由模型在原评分步骤内完成局部补全，不增加平台尾注或固定“提示词质量”默认值。用户明确评价下游作品时沿用其目标；尚未明确的主辅关系和参数保持原状态。

入口已核对：`EffectiveTaskView.modelInput()` 第 39—42 行传入原锚点；OpenAI 兼容 Provider 第 592—593 行传递 `forTask` 与任务视图，其他对应调用第 618 行同样消费 `forTask`。当前改动只扩展此内部策略内容。

## 本地验证

1. Q05 原始输入：指导引用实际 RESEARCH_TOPIC 区间；原文区间能回切原主题，AUDIENCE 不成为评价来源。
2. 同时存在写作受众、研究主题及评分要求：局部指导要求绑定材料和指标对象，不自行指定评分尺度、参数或主要/辅助对象。
3. 用户确实评价最终下游作品：仍引用该主题，不注入固定“评价提示词质量”的值。
4. 普通邮件、翻译以及只有受众没有研究主题：无新局部指导；兼容入口不伪造锚点。
5. 多个现有研究主题：各自的原文区间保留，不合并不同来源对象。

单元检查只证明来源、适用范围和指导传递，不证明模型理解或作品评分对象已修复。现有受众/对象、充分原文、Provider 请求与评估结构相关检查用于兼容回归。
