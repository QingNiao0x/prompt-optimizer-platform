# 上传稳定性验收原件

- `candidate.json`：基线提交和实际生产源码 SHA-256；模型调用为 0。
- `controlled-network.json`：Chrome/Edge 各 ABBA 四轮、12 MiB 同文本、分片返回额外延迟 80ms 的真实 HTTP 结果。性能及完整性断言通过，但合并故障试验未触发轮询错误，因此原始 `passed:false` 保留。
- `independent-faults-and-lan.json`：分别触发完成响应丢失和轮询连接重置，4 例恢复通过；附无人工延迟的单轮对照。浏览器分别登录同一固定合成账号，不复制 Cookie；按文档 ID 查询与刷新后查询通过。
- `workbench-http.json`：7 个格式样本、3 个负例、桌面/手机警告及授权路径真实 HTTP 结果；全文/首尾/单元格/页序等具体检查见 JSON。
- `checks.json`：不同测试数量、原日志摘要与 SHA-256；不把重复运行算成新增覆盖。完整日志仅在本机 `tmp/upload-stability-20261031`，不提交私有登录资料。
- `first-tool-failure.json`：对照脚本初次未转换 TypeScript 的工具失败，不能记作产品结果。
- `live-harness.mjs`：从仓库根目录运行；依赖隔离 19000 后端、固定合成账号及既有正常登录助手；`UPLOAD_SUPPLEMENT=true` 运行独立故障/本机对照。仅本机授权环境使用，不创建账号、不自行调用模型。运行前应确保端口空闲并保留旧原件，不能覆盖历史报告。
- PNG：真实工作台的桌面/手机文档覆盖提示。仅合成材料，不含项目私有源码。

采用结论及未覆盖边界见[报告](../../../文档上传并发与跨浏览器稳定性验收-2026-10-31.md)。项目大目录的历史完整扫描在独立报告中，本轮没有把它重新跑一遍，不能将文档上传速度等同于源码本地索引速度。
