# 提示词整理工具对照研究方案

## 1. 研究问题

本研究比较三种提示词准备条件对下游任务输出的影响：原始组、直接增强组、交互式计划确认增强组。研究问题为：在相同初始任务材料下，三种条件在下游输出质量上是否存在差异；当计划确认组获得额外确认答案时，质量变化中有多少可归因于新增信息本身，多少可归因于交互式问答的组织方式。

交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答，再生成最终提示词，不是静态任务分解列表。原始组接收原始需求与初始材料；直接增强组接收由同一初始信息得到的优化提示词；两组均不得接触计划确认组后来回答的业务选择。计划确认组记录每个问题、选项、推荐依据和答案，不只保存最终提示词；错误推荐被答案纠正后仍计入交互阶段风险。信息量匹配对照获得相同已确认事实，但不经历本平台问答过程，用于减少新增信息与交互组织方式之间的混淆。

## 2. 实验设计

采用二十个任务，每个条件独立重复三次，共四个条件：原始组、直接增强组、计划确认组、信息量匹配对照组。每次重复开启隔离会话，随机化顺序并记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本。

任务材料保留真实实现、用户说明、测试示例与待办等来源标签，不得在人工评分前删除不利的测试污染反例。开发任务要求下游模型只输出方案、不实际修改仓库；写作任务要求交付文本，因此跨任务不能用代码测试通过率作为统一质量指标。

计划确认组的交互轮次上限与终止规则尚未确定，进入预注册待确认清单，不默认任何轮次。二十个任务、每条件三次独立重复、两名盲评者及信息量匹配对照保持已定。

## 3. 盲评流程

两名盲评者独立评分。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源。评审可查看任务事实，但不得查看另一名评审先前评分。评分表记录主错误与关联维度，避免同一问题被多次计成独立失败。分歧处理与一致性评价方式尚未确定，不默认平均分、共识分、第三人仲裁或具体一致性统计量，进入预注册待确认清单。

## 4. 主要指标

工具生成速度是过程指标，质量分是结果指标。质量分覆盖需求保真、业务规则、输出可用性、阅读负担和执行边界五个维度。没有计费日志时不估算真实 Token 成本，不把字符数换算为实际费用。候选统计方法依赖分数是否有序、是否连续和是否重复测量；方案只说明选择流程，不在变量未确定时锁定某个显著性检验。

## 5. 限制

实验尚未运行，没有准确率、显著性、成功案例数量或用户结论。即使三个模型给出相似结论也不构成研究完成证据；专业领域判断尚需专家参与。本方案不评价任何产品绝对优劣。所有资料为合成演练资料，不代表真实单位、患者、当事人、市场或平台运行数据。
