## 二、流程图说明

### 2.1 预约事件状态流转（讨论版）

```
[预约创建]
    │
    ├─ 渠道记录：电话 / 网页 / 窗口
    │       └─ 若同一预约存在多操作事件 → 需标记首次渠道与变更渠道
    │
    ▼
[预约存续]
    │
    ├─ 用户主动取消 → CANCELLED
    │       └─ 取消时间与就诊时间均为医院本地时区
    │       └─ 是否计入爽约取决于“取消免责边界”，当前未决定
    │
    ├─ 到诊 → ARRIVED
    │
    └─ 状态未知 → UNKNOWN
            └─ 可能来自设备同步延迟、现场漏登记或记录缺项
            └─ 不直接计为爽约，不解释为患者责任
            └─ 观察窗口未确定前，只展示为待核验事件
```

### 2.2 分析流程（讨论版）

```
[合成汇总表]
    │
    ▼
[口径确认]
    ├─ 统计单位：预约事件 / 去重患者 → 待确认
    ├─ 观察窗口：未决定 → 只展示待核验事件
    └─ 取消免责边界：未决定 → 争议单独呈现
    │
    ▼
[分组展示]
    ├─ 按渠道：电话 / 网页 / 窗口
    ├─ 按状态：ARRIVED / CANCELLED / UNKNOWN
    └─ 小样本渠道保留数量与限制说明
    │
    ▼
[讨论版报告]
    ├─ 标注合成材料与方法草案
    ├─ 不报告显著渠道差异（无完整数据）
    └─ 专业评审后才能应用
```

### 2.3 渠道归属判定流程（讨论版）

```
[同一预约的多条操作事件]
    │
    ▼
[判定首次渠道]
    │
    ▼
[判定变更渠道]
    │
    ▼
[以预约事件为统计单位时：按首次渠道归集]
[以去重患者为统计单位时：需另行定义归集规则 → 待确认]
    │
    ▼
[禁止：把操作次数当成预约量]
```
