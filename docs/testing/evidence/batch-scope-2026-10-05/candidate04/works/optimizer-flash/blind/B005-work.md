# 提示词整理工具对照研究方案

## 1. 研究问题

本研究比较三种提示词准备条件对下游任务输出质量的影响：原始需求直接输入、基于同一初始信息直接增强、交互式计划确认增强。交互式计划确认指系统先提问，实验操作者按预先制定答案卡作答，再生成最终提示词，而非静态任务分解列表。研究不评价任何产品绝对优劣，仅考察条件间差异。

## 2. 实验设计

### 2.1 任务与条件

固定二十个任务，覆盖开发方案与写作交付两类。开发任务要求下游模型只输出方案、不实际修改仓库；写作任务要求交付文本。跨任务不采用代码测试通过率作为统一质量指标。

设四个条件：

- **A 原始组**：接收原始需求与初始材料。
- **B 直接增强组**：接收由同一初始信息生成的优化提示词。
- **C 计划确认组**：先经交互式问答，操作者按答案卡作答后生成最终提示词。
- **D 信息量匹配对照**：获得与 C 组相同的已确认事实，但不经历本平台问答过程。

A、B 两组不得接触 C 组后续回答的业务选择。D 组用于分离“新增信息”与“交互组织方式”的效应，防止把多获得答案带来的收益误判为单纯模型能力。

### 2.2 重复与随机化

每个条件对每个任务独立重复三次，共 240 次下游生成。每次重复开启隔离会话，随机化执行顺序，记录模型版本、日期与参数。失败后的重试不得替代第一份失败样本；工具失败与首轮失败均保留。

### 2.3 材料与记录

任务材料保留真实实现、用户说明、测试示例与待办等来源标签，不得在人工评分前人为删除不利的测试污染反例。C 组记录每个问题、选项、推荐依据与答案，不只保存最终提示词；错误推荐被答案纠正后仍计入交互阶段风险。D 组记录所获事实清单及来源对应关系。

## 3. 盲评与指标

两名盲评者独立评分。评审看到匿名化下游输出与等量任务信息，不展示产品名称、标志和生成来源；可查看任务事实，但不得查看另一名评审先前评分。

评分同时覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。一个错误可能同时影响多个维度，评分表记录主错误与关联维度，避免同一问题多次计成不同独立失败。工具生成速度作为过程指标单独记录，不并入质量分；无计费日志时不估算真实 Token 成本，不以字符数换算费用。

## 4. 统计与限制

候选统计方法依赖分数是否有序、是否连续及是否重复测量，方案仅规定选择流程，不预先锁定显著性检验。即使三个模型给出相似结论也不构成研究完成证据；需安排人工评阅与可复核任务标准，专业领域判断尚需专家参与。

本研究为方案设计，实验尚未运行，不含准确率、显著性、成功案例数量或用户结论。


## 附表一：变量与分组

| 条件 | 初始信息 | 交互问答 | 获得确认事实 | 最终提示词来源 |
|---|---|---|---|---|
| A 原始组 | 原始需求＋初始材料 | 否 | 否 | 原始需求直接输入 |
| B 直接增强组 | 同一初始信息 | 否 | 否 | 优化提示词 |
| C 计划确认组 | 原始需求＋初始材料 | 是，按答案卡作答 | 是 | 问答后生成 |
| D 信息量匹配对照 | 原始需求＋初始材料 | 否 | 是，与 C 组相同事实 | 基于事实清单生成 |

固定因素：二十个任务、每条件三次独立重复、两名盲评者、相同初始材料、相同下游模型版本与参数记录要求。
