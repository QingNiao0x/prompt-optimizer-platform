# 提示词整理工具对照研究方案

## 1. 研究问题

本研究比较三种条件对下游任务输出的影响：原始需求、直接增强、交互式计划确认增强。核心问题为：在相同初始信息下，不同提示词整理方式是否导致下游输出在需求保真、业务规则、输出可用性、阅读负担和执行边界五个维度上产生可测量差异；当计划确认组额外获得已确认事实时，该收益中有多少来自新增信息本身，多少来自交互式问答的组织方式。

比较条件定义如下。原始组接收原始需求与初始材料，不附加整理。直接增强组接收基于同一初始信息生成的优化提示词，不接触计划确认组后来回答的业务选择。计划确认组经历系统提问、实验操作者按预先制定答案卡作答、再生成最终提示词的完整过程；该组记录每个问题、选项、推荐依据和答案，错误推荐被答案纠正后仍计入交互阶段风险。信息量匹配对照获得与计划确认组相同的已确认事实，但不经历本平台问答过程，用于分离新增信息与交互组织方式的影响。

## 2. 实验设计

采用二十个任务，每个条件独立重复三次，共二百四十次下游生成。每个条件的三次重复开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试单独记录，不替代第一份失败样本。任务材料保留真实实现、用户说明、测试示例与待办等来源标签，人工评分前不删除不利的测试污染反例。开发任务要求下游模型只输出方案、不实际修改仓库；写作任务要求交付文本；跨任务不采用代码测试通过率作为统一质量指标。

## 3. 主要指标

工具生成速度作为过程指标记录，质量分作为结果指标。质量分由两名盲评者按五个维度独立评分：需求保真、业务规则、输出可用性、阅读负担、执行边界。评分表记录主错误与关联维度，避免同一问题被多次计成独立失败。没有计费日志时不估算真实 Token 成本，不把字符数换算为实际费用。候选统计方法依赖分数是否有序、是否连续和是否重复测量，方案仅说明选择流程，不在变量未确定时锁定某个显著性检验。

## 4. 盲评流程

评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源。评审可查看任务事实，但不能查看另一名评审先前评分。两名评审的分歧处理与一致性评价方式尚未决定，待预注册阶段明确。

## 5. 限制

实验尚未运行，无准确率、显著性、成功案例数量或用户结论。专业领域判断尚需专家参与，即使三个模型给出相似结论也不构成研究完成证据。交互式计划确认的最大轮次和终止规则尚未决定，影响计划确认组流程设计与预注册内容。信息量匹配对照虽获得相同已确认事实，但不经历问答过程，无法完全复现交互中的澄清顺序效应；该限制在结果解释中须明确标注。

# 附表一：变量与分组

| 条件 | 初始信息 | 是否获得确认答案 | 是否经历问答过程 | 重复次数 | 会话隔离 | 记录内容 |
|---|---|---|---|---|---|---|
| 原始组 | 原始需求与初始材料 | 否 | 否 | 3 | 是 | 原始输入、下游输出、过程指标 |
| 直接增强组 | 同一初始信息生成的优化提示词 | 否 | 否 | 3 | 是 | 优化提示词、下游输出、过程指标 |
| 计划确认组 | 原始需求与初始材料 | 是 | 是 | 3 | 是 | 每个问题、选项、推荐依据、答案、最终提示词、下游输出、过程指标 |
| 信息量匹配对照 | 原始需求与初始材料 | 是 | 否 | 3 | 是 | 已确认事实清单、最终提示词、下游输出、过程指标 |

注：原始组与直接增强组均不得接触计划确认组后来回答的业务选择。信息量匹配对照的已确认事实与计划确认组最终确认结果一致，但不经历本平台问答过程。

# 附表二：评分表及失败记录模板

## 评分表

| 字段 | 说明 | 值域 |
|---|---|---|
| 任务编号 | 二十个任务的唯一标识 | 1–20 |
| 条件 | 四组之一 | 原始组/直接增强组/计划确认组/信息量匹配对照 |
| 重复序号 | 该条件下的第几次重复 | 1–3 |
| 评审编号 | 盲评者标识 | 评审A/评审B |
| 需求保真 | 输出是否忠实于原始需求 | 待定（有序/连续尺度预注册时确定） |
| 业务规则 | 是否遵守任务隐含的业务约束 | 同上 |
| 输出可用性 | 输出是否可直接用于后续工作 | 同上 |
| 阅读负担 | 输出是否冗余或难以定位关键信息 | 同上 |
| 执行边界 | 是否明确说明可做与不可做事项 | 同上 |
| 主错误 | 本次输出最主要的问题 | 自由文本，关联下方维度 |
| 关联维度 | 主错误影响的维度 | 多选：需求保真/业务规则/输出可用性/阅读负担/执行边界 |
| 备注 | 其他观察 | 自由文本，可空 |
