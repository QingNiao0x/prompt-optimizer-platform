# 合成门诊预约到诊与爽约情况内部运营分析方案

**适用范围**：合成门诊二〇二六年第一季度预约事件。本方案仅用于运营流程分析，不涉及诊断、处方、分诊优先级、医嘱或个体治疗，不计算真实医院指标，不建议减少任何患者服务权益。


## 一、口径梳理

### 1.1 基础统计单位

| 口径项 | 当前状态 | 说明 |
|---|---|---|
| 预约事件编号 | 可用 | 可区分一次预约；一个患者可多次预约，事件数不等于人数 |
| 患者去重口径 | 待确认 | 比较渠道时使用预约事件还是去重患者作为主统计单位，尚未决定 |
| 首次渠道与变更渠道 | 待定义 | 电话与网页可能记录同一预约的不同操作事件，渠道比较必须先定义首次渠道和变更渠道，不能把操作次数当成预约量 |

### 1.2 到诊状态口径

| 状态 | 口径 | 分析处理 |
|---|---|---|
| ARRIVED | 系统记录已到诊 | 计入到诊事件 |
| CANCELLED | 系统记录用户主动取消 | 单独统计取消事件；不附加临床解释，不意味着治疗结束、病情缓解或不再需要服务 |
| UNKNOWN | 原因未细分 | **不得直接计为爽约**；可能来自设备同步延迟、现场漏登记或记录缺项，须列为待核验事件 |

### 1.3 爽约认定口径

| 口径项 | 当前状态 |
|---|---|
| 爽约定义 | 仅当预约事件已过观察窗口且到诊状态经核验仍非 ARRIVED、非 CANCELLED 时，方可讨论是否构成爽约 |
| 观察窗口 | **待确认**——预约未到诊的观察窗口和取消免责边界尚未决定，不得默认补全 |
| 取消免责边界 | **待确认**——存在两份材料差异（见 1.4），不得擅自采用其中一项 |
| UNKNOWN 处理 | 在缺少来源核查时，不能解释为患者责任；观察窗口未确定前只展示待核验事件，不将尚未到期预约算入爽约率 |

### 1.4 取消规则差异（须单独呈现，不得擅自采用）

| 来源 | 内容 | 状态 |
|---|---|---|
| 旧流程说明（legacy-note.md） | 提前24小时取消不计爽约 | 旧版，权威性未建立 |
| 新会议草稿（legacy-note.md 所载） | 建议提前12小时取消，尚未批准 | 草稿，未批准 |

**处理方式**：报告中须将上述差异单独呈现，标注“旧版草稿”与“正式说明”分开，不能按文件修改时间直接断定新规则生效。在权威口径确定前，爽约认定相关指标仅以“待核验事件”形式呈现，不产出最终爽约率。

### 1.5 时区口径

| 口径项 | 当前状态 |
|---|---|
| 取消时间与就诊时间时区 | 均用医院本地时区 |
| 时区转换证据 | 当前汇总表没有时区转换证据，分析中不得假设已做转换 |

### 1.6 渠道口径

| 渠道 | 口径说明 |
|---|---|
| 电话 | 已明确，不再询问需分析哪些渠道 |
| 网页 | 已明确 |
| 窗口 | 已明确 |
| 渠道比较前提 | 必须先定义首次渠道和变更渠道；小渠道样本较少时保留数量和限制说明，没有完整数据不能报告显著的渠道差异 |

### 1.7 排除项

| 项目 | 处理 |
|---|---|
| 医生代码 | 仅为流程角色示例，不纳入个人绩效评估，不追加医生排行榜，不利用服务时间做个体能力评价 |
| 科室类型 | 本题材料只有一个门诊，不推断跨科室、跨医院或全市运营表现 |
| 临床判断 | 不提供任何临床判断或医疗建议 |
| 收费/处罚建议 | 不作为默认整改建议 |


## 二、流程图说明（文字版）

### 2.1 预约事件状态流转（基于现有资料可核查部分）

```
预约创建（渠道：电话/网页/窗口）
        │
        ▼
   [预约事件编号生成]
        │
        ├──► 用户主动取消 ──► CANCELLED（单独统计，不附加临床解释）
        │
        ├──► 到诊登记 ──► ARRIVED（计入到诊事件）
        │
        └──► 状态未明 ──► UNKNOWN
                              │
                              ▼
                    [待核验事件池]
                    （观察窗口未定，不归入爽约）
```

### 2.2 渠道操作事件与预约事件的关系

```
电话操作事件 ─┐
              ├─► 可能对应同一次预约 ──► 预约事件（主统计单位）
网页操作事件 ─┘
窗口操作事件 ───► 预约事件

注意：操作次数 ≠ 预约量。
渠道比较前须定义“首次渠道”和“变更渠道”。
```

### 2.3 爽约认定流程（当前状态：不可执行至最终结论）

```
预约事件到诊状态 = UNKNOWN
        │
        ▼
观察窗口是否已确定？ ──否──► 仅展示为“待核验事件”
        │是
        ▼
取消免责边界是否已确定？ ──否──► 仅展示为“待核验事件”
        │是
        ▼
来源核查（设备同步/漏登记/记录缺项）──► 核验后非患者责任 ──► 不计爽约
        │
        ▼
核验后确属未到诊且未取消 ──► 方可讨论爽约
```

**当前结论**：因观察窗口和取消免责边界均未确定，本季度分析仅能产出“待核验事件”清单及描述性统计，不产出最终爽约率。

| 字段名 | 建议类型 | 用途 | 是否含敏感信息 |
