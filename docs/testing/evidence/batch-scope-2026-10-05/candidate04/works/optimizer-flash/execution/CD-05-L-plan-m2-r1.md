# 提示词整理工具对照研究方案

## 一、研究问题

本研究比较三种提示词准备条件对下游任务输出质量的影响：原始需求条件、直接增强条件、交互式计划确认增强条件。核心问题为：在相同初始信息下，直接增强与交互式计划确认增强是否比原始需求产生更高质量的下游输出；交互式计划确认在获得额外确认答案后，其效果是否可归因于交互组织方式本身，而非仅因新增信息量。研究不评价任何产品绝对优劣。

## 二、实验设计

**任务与条件。** 固定二十个任务，覆盖开发与写作两类。开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本。跨任务不使用代码测试通过率作为统一质量指标。每个条件对每个任务独立重复三次，共 240 份下游输出。

**四种条件。** 原始组接收原始需求与初始材料。直接增强组接收由同一初始信息生成的优化提示词。计划确认组由系统先提问，实验操作者按预先制定的答案卡作答，再生成最终提示词；该组记录每个问题、选项、推荐依据和答案，错误推荐被答案纠正后仍计入交互阶段风险。信息量匹配对照组获得与计划确认组相同的已确认事实，但不经历本平台问答过程，用于区分新增信息与交互组织方式的效应。原始组和直接增强组均不得接触计划确认组后来回答的业务选择。

**材料与来源标签。** 任务材料保留真实实现、用户说明、测试示例与待办四种来源标签。人工评分前不得删除不利的测试污染反例。

**重复与隔离。** 每个条件的三次重复开启隔离会话，随机化任务顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本；工具失败与首轮失败均须保留在失败记录中。

**盲评。** 两名盲评者独立评分。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源。评审可查看任务事实，但不能查看另一名评审的先前评分。

## 三、主要指标

结果指标为质量分，由两名盲评者在五个维度上评分：需求保真、业务规则、输出可用性、阅读负担、执行边界。评分表记录主错误和关联维度，同一问题不重复计为多个独立失败。过程指标包括工具生成速度、交互轮次记录和失败记录；过程指标不进入质量分。没有计费日志时不估算真实 Token 成本，不把字符数换算成实际费用。

## 四、统计方法选择流程

统计方法在数据收集后按以下流程选择：先判断质量分是否有序、是否连续、是否重复测量，再据此选择描述统计与推断方法。方案不预先锁定具体显著性检验。

## 五、人工评阅与可复核标准

每个任务附可复核的任务事实与评分锚点，评审据此评分。专业领域判断尚需专家参与，专家意见作为后续效度检验的输入，不替代盲评分数。

## 六、限制

本研究为尚未执行的方案，无实验结果。计划确认组的交互轮次上限与终止规则未定，两名评审的分歧处理与一致性评价方式未定，均列入预注册待确认清单。研究结论将受任务类型、模型版本和评分主观性限制。
