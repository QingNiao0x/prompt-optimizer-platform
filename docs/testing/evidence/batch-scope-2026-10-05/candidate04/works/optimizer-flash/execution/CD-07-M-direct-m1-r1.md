## 2. 流程图说明

### 2.1 预约事件从产生到最终状态判定的流程

1. **事件产生**：患者通过电话、网页或窗口发起预约，系统生成预约事件编号。
2. **渠道操作记录**：同一预约事件可能产生多次渠道操作记录（例如电话与网页分别记录）。
3. **首次渠道判定**：取该预约事件中最早记录的渠道操作作为首次渠道。
4. **变更渠道判定**：首次渠道之后发生的渠道操作记为变更渠道，仅作辅助观察，不单独计为新增预约量。
5. **状态记录**：系统记录到诊状态，包括 ARRIVED、CANCELLED、UNKNOWN。
6. **观察窗口判定**：
   - 观察窗口未确定前，事件仅作为待核验事件展示；
   - 观察窗口确定且事件到期后，方可归为最终状态；
   - 尚未到期的预约不计入爽约率。
7. **爽约判定**：仅在观察窗口确定、事件到期、且状态可归为未到诊时统计；UNKNOWN 不直接计为爽约。
8. **取消免责判定**：依据取消免责边界判断取消是否计入爽约；该边界当前尚未决定，须单独呈现争议，不擅自采用其中一项。

### 2.2 渠道比较时首次渠道与变更渠道判定规则

- **首次渠道**：以预约事件编号为单位，取该事件中最早记录的渠道操作。
- **变更渠道**：首次渠道之后发生的渠道操作，记为变更渠道。
- **计数规则**：渠道比较以预约事件为计数单位，不以操作次数为预约量。
- **去重要求**：电话预约与网页预约可能记录同一预约的不同操作事件，须先按预约事件编号去重。
- **主统计单位待确认**：比较渠道时使用预约事件还是去重患者作为主统计单位，当前尚未决定，不得默认补全。
- **样本限制**：小渠道样本较少时应保留数量和限制说明；没有完整数据不能报告显著的渠道差异。

## 5. 人工复核及隐私边界清单

### 5.1 人工复核项

- UNKNOWN 状态来源核查：区分设备同步延迟、现场漏登记或记录缺项；缺少来源核查时不得解释为患者责任。
- 渠道操作事件去重：按预约事件编号去重，避免把操作次数当成预约量。
- 首次渠道与变更渠道判定复核：确认判定规则一致，不把操作次数当预约量。
- 观察窗口到期判定复核：确认事件是否已到期、是否可归为最终状态。
- 取消免责边界复核：旧流程说明与新会议草稿差异单独呈现，不擅自采用其中一项。
- 爽约率计算复核：确认 UNKNOWN 未直接计为爽约，尚未到期预约未计入爽约率。
- 小渠道样本量复核：保留数量和限制说明，不报告显著渠道差异。
- 时区口径复核：预约取消时间与就诊时间均用医院本地时区，当前汇总表没有时区转换证据。
- 主统计单位复核：预约事件或去重患者，当前尚未决定，不得默认补全。
