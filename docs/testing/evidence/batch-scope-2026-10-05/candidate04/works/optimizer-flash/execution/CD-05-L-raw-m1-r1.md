# 提示词整理工具对照研究方案

## 一、研究问题与目标

本研究比较三种提示词整理条件对下游任务输出的影响：原始需求（A组）、直接增强（B组）、交互式计划确认增强（C组），并增设信息量匹配对照（D组）。目标不是评价某家产品绝对优劣，而是区分“新增已确认信息”与“交互组织方式”各自对输出的作用。所有工具获取相同初始材料；A、B两组不得接触C组后续回答的业务选择。

交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答，再生成最终提示词，不是静态任务分解列表。D组获得与C组相同的已确认事实，但不经历本平台问答过程，用于减少新增信息与交互组织方式的混淆。

## 二、实验设计

固定二十个任务，每条件独立重复三次，开启隔离会话，随机化顺序并记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本。两名盲评者独立评分，评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源，也不看另一名评审先前评分。

任务材料保留真实实现、用户说明、测试示例与待办等来源标签，不在人工评分前删除不利的测试污染反例。开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本，因此跨任务不能用代码测试通过率作为统一质量指标。

## 三、主要指标

评价同时覆盖需求保真、业务规则、输出可用性、阅读负担和执行边界。工具生成速度是过程指标，质量分是结果指标；没有计费日志时不估算真实Token成本，不把字符数换算成实际费用。一个错误可能同时影响完整性与可执行性，评分表记录主错误和关联维度，避免同一问题多次计成独立失败。

## 四、统计与限制

候选评价统计方法依赖分数是否有序、是否连续和是否重复测量；本方案说明选择流程，不在变量尚未确定时锁定某个显著性检验。即使三个模型给出相似结论也不是研究完成证据，需安排人工评阅与可复核任务标准，专业领域判断尚需专家参与。实验尚未运行，本方案不报告准确率、显著性、成功案例数量或用户结论。

## 五、预注册待确认事项

1. 交互式计划确认的最大轮次和终止规则尚未决定，不得默认补全；该决定影响C组交互阶段风险记录与D组信息量匹配的边界。
2. 两名评审的分歧处理与一致性评价方式尚未决定，不得默认补全；该决定影响评分表汇总规则与统计选择流程。
