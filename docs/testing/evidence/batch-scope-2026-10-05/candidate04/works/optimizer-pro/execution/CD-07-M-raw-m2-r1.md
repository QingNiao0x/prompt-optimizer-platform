# 合成门诊预约到诊与爽约情况内部运营分析方案（二〇二六年第一季度）

> 适用对象：运营分析讨论稿  
> 数据性质：合成汇总数据，无真实患者信息，无完整逐条数据  
> 分析边界：仅讨论预约事件层面的运营流程与数据质量，不涉及诊断、处方、分诊优先级、医嘱或个体治疗；不计算真实医院指标；不建议减少任何患者服务权益。


## 一、口径梳理

### 1.1 主统计单位

| 口径项 | 当前状态 | 说明 |
|---|---|---|
| 预约事件数 | 可用 | 预约事件编号可区分一次预约，作为事件层面统计的基础单位 |
| 去重患者数 | 不可直接使用 | 一个患者可多次预约，事件数不等于人数；当前资料未提供可去重的患者标识，也未决定渠道比较时采用事件数还是去重患者数 |
| 渠道比较主单位 | **待确认** | 比较渠道时使用预约事件还是去重患者作为主统计单位，当前尚未决定，不得默认补全 |

### 1.2 到诊状态口径

| 状态 | 运营口径 | 是否可计为爽约 |
|---|---|---|
| ARRIVED | 系统记录已到诊 | 否 |
| CANCELLED | 系统记录用户主动取消 | 否。取消不意味着治疗结束、病情缓解或不再需要服务，不得附加临床解释 |
| UNKNOWN | 到诊状态未知 | **否**。不得直接计为爽约。可能来自设备同步延迟、现场漏登记或记录缺项；在缺少来源核查时，不能解释为患者责任 |

### 1.3 爽约的认定前提

- 爽约的认定依赖"预约未到诊的观察窗口"和"取消免责边界"两个业务定义。
- 当前观察窗口尚未确定。窗口未确定前，只应展示待核验事件，不应将尚未到期的预约算入爽约率。
- 当前取消免责边界存在两份材料差异，见 1.4。

### 1.4 取消免责边界的材料差异（须单独呈现，不得擅自采用）

| 来源 | 内容 | 状态 |
|---|---|---|
| 旧流程说明（legacy-note） | 提前24小时取消不计爽约 | 旧版说明，权威性未建立 |
| 新会议草稿 | 建议提前12小时取消不计爽约 | 草稿，**尚未批准** |

- 在未批准前，报告不得默认采用12小时或24小时作为免责边界；涉及爽约认定的部分应标注"取消免责边界待定"。

| 口径项 | 说明 |

## 二、流程图说明（基于现行资料）

### 2.1 预约事件状态流转（合成门诊，二〇二六年第一季度）

```
[预约创建]──渠道：电话/网页/窗口
     │
     ▼
[预约存续]──可能发生：渠道操作事件（电话/网页重复记录）
     │
     ├──[用户主动取消]──取消时间记录──► 状态：CANCELLED
     │
     ├──[到诊登记]──► 状态：ARRIVED
     │
     └──[观察窗口内未明确]──► 状态：UNKNOWN
                                   │
                                   ▼
                        待核验：设备同步延迟/现场漏登记/记录缺项
```

### 2.2 流程说明

1. **预约创建**：一次预约事件获得唯一预约事件编号。渠道为电话、网页或窗口之一。
2. **渠道操作事件**：电话预约与网页预约可能对同一次预约产生多个操作事件。在未定义首次渠道与变更渠道前，操作事件数不得作为预约量。
3. **取消**：系统记录到用户主动取消，状态为 CANCELLED。取消行为不附加临床解释。
4. **到诊**：系统记录到诊，状态为 ARRIVED。
5. **未知**：观察窗口内未明确到诊或取消，状态为 UNKNOWN。该状态不得直接计为爽约，须进入待核验流程。
6. **爽约认定**：仅在观察窗口和取消免责边界均确定后，方可对符合条件的未到诊事件进行爽约认定。当前两个条件均未确定，本季度报告不产出爽约率。


## 三、拟议数据采集字段建议

> 以下为拟议采集表字段，用于支持后续运营分析。实施前仍需合规评估；不得写成已经建表或已获得数据授权。

### 3.1 事件基础字段

| 字段名 | 建议内容 | 用途 | 是否含敏感信息 |

| 预约创建时间 | 医院本地时区 | 计算提前量 | 否 |
| 就诊时间 | 医院本地时区 | 判断观察窗口 | 否 |
| 预约渠道 | 电话/网页/窗口 | 渠道分析 | 否 |
| 首次渠道标记 | 待定义后采集 | 区分首次渠道与变更渠道 | 否 |
| 变更渠道标记 | 待定义后采集 | 避免操作次数误计为预约量 | 否 |

### 3.2 状态字段

| 字段名 | 建议内容 | 用途 | 是否含敏感信息 |
|---|---|---|---|
| 到诊状态 | ARRIVED/CANCELLED/UNKNOWN | 状态统计 | 否 |
| 状态更新时间 | 医院本地时区 | 判断状态确认时点 | 否 |
| 取消时间 | 医院本地时区，可空 | 计算取消提前量 | 否 |

### 3.3 待核验字段（针对 UNKNOWN）

| 字段名 | 建议内容 | 用途 | 是否含敏感信息 |
|---|---|---|---|
| 待核验原因分类 | 设备同步延迟/现场漏登记/记录缺项/其他 | 区分 UNKNOWN 来源 | 否 |
| 最后同步时间 | 医院本地时区 | 判断是否同步延迟 | 否 |

- 患者姓名、身份证号、联系方式等可识别信息。
- 医生个人绩效相关字段。资料中的医生代码只是流程角色示例，不是个人绩效评估范围；不得追加医生排行榜或利用服务时间做个体能力评价。
- 诊断、处方、分诊优先级、医嘱或个体治疗相关字段。

## 五、人工复核及隐私边界清单

### 5.1 人工复核清单

| 复核项 | 复核内容 | 复核目的 |
|---|---|---|
| UNKNOWN 状态核查 | 对 UNKNOWN 事件逐条核对设备同步时间、现场登记记录、来源系统日志 | 区分设备同步延迟、现场漏登记、记录缺项，不归因于患者责任 |
| 取消记录核查 | 核对取消时间与就诊时间的本地时区一致性 | 确认取消提前量计算基础 |
| 渠道操作事件核查 | 核对同一预约事件编号下的电话/网页操作记录 | 区分首次渠道与变更渠道，避免操作次数误计为预约量 |
| 状态更新时间核查 | 核对状态更新时间是否晚于就诊时间 | 判断是否存在事后补录 |
| 时区证据核查 | 核对取消时间与就诊时间是否均无时区转换证据 | 确认分析中不假设已做转换 |

### 5.2 隐私边界清单

| 边界项 | 要求 |
|---|---|
| 患者可识别信息 | 不采集、不展示姓名、身份证号、联系方式等 |
| 医生个人绩效 | 不追加医生排行榜，不利用服务时间做个体能力评价 |
| 敏感诊疗明细 | 不包含诊断、处方、分诊优先级、医嘱或个体治疗 |
| 取消行为的临床解释 | 不对取消行为附加"病情缓解""不再需要服务"等临床解释 |
| 患者责任归因 | UNKNOWN 状态在缺少来源核查时，不解释为患者责任 |
| 处罚性建议 | 不默认采取罚款、降低预约资格或公开患者记录 |
| 短信提醒 | 如后续要求短信提醒方案，需另行确认通知授权和退订流程；本次不将提醒需求扩成发送短信的实施任务 |
