### 1.2 渠道口径的特殊说明

电话预约与网页预约可能记录相同一次预约的不同操作事件。因此，渠道比较必须先定义**首次渠道**和**变更渠道**，不能把操作次数当成预约量。

- **首次渠道**：一次预约事件最早被记录时对应的渠道。
- **变更渠道**：同一预约事件后续发生操作时对应的渠道（如先电话预约、后网页改约）。
- **当前未决**：比较渠道时使用预约事件还是去重患者作为主统计单位，尚未决定，不得默认补全。

### 1.5 流程图说明（文字版）

以下为预约事件状态流转的**文字流程说明**，用于内部讨论，不依赖图形渲染：

1. **预约创建**：患者通过电话、网页或窗口渠道创建预约事件，系统生成预约事件编号。
2. **渠道操作记录**：同一预约事件可能在多个渠道产生操作记录（如电话创建后网页改约）。分析时需区分首次渠道与变更渠道，不能将操作次数计为预约量。
3. **状态记录**：系统记录到诊状态为 ARRIVED、CANCELLED 或 UNKNOWN。
   - ARRIVED：已到诊。
   - CANCELLED：系统记录到用户主动取消；取消时间与就诊时间均为医院本地时区。
   - UNKNOWN：原因未细分，可能来自设备同步延迟、现场漏登记或记录缺项。
4. **观察窗口判定**：在观察窗口未确定前，尚未到期的预约事件应标记为“待核验”，不纳入爽约率计算。
5. **爽约判定**：仅在观察窗口已确定、取消免责边界已明确、且 UNKNOWN 状态经来源核查后，方可讨论爽约判定。当前阶段不进行爽约率计算。


## 二、流程问题清单

以下问题用于内部讨论，覆盖预约到诊与爽约流程中的关键关注点。

| 编号 | 问题类别 | 具体问题 | 当前状态/影响 |
|---|---|---|---|
| P-1 | 渠道重复记录 | 电话预约与网页预约可能记录相同一次预约的不同操作事件，操作次数可能被误当作预约量 | 需先定义首次渠道和变更渠道；主统计单位未定（U-3） |
| P-2 | UNKNOWN 状态原因 | UNKNOWN 的原因没有细分，可能来自设备同步延迟、现场漏登记或记录缺项 | 缺少来源核查时不能解释为患者责任；需人工复核 |
| P-3 | 取消规则差异 | 旧流程说明提前24小时取消不计爽约；新会议草稿建议提前12小时，尚未批准 | 差异须单独呈现，不擅自采用其一（U-2） |
| P-4 | 观察窗口未定 | 观察窗口决定预约事件何时可归为最终状态 | 窗口未定前只展示待核验事件，不计算爽约率（U-1） |
| P-5 | 取消状态含义边界 | 取消状态仅表示系统记录到用户主动取消，不意味着治疗结束、病情缓解或不再需要服务 | 分析报告不能给取消行为附加临床解释 |
| P-6 | 时区一致性 | 预约取消时间与就诊时间均用医院本地时区，当前汇总表没有时区转换证据 | 后续如涉及跨系统数据合并，需先核验时区一致性 |
| P-7 | 小样本渠道波动 | 预约事件量不同会影响百分比波动，小渠道样本较少时应保留数量和限制说明 | 没有完整数据不能报告显著的渠道差异 |
| P-8 | 登记质量 | 现场漏登记或记录缺项可能导致 UNKNOWN 状态 | 改进建议应优先考虑核对登记质量，而非归责患者 |
| P-9 | 改约便捷性 | 便捷改约可能影响取消行为与到诊行为 | 改进建议可讨论便捷改约，不默认采取罚款或降低预约资格 |

### 3.2 拟议采集表的使用边界

- 本表仅用于**合成数据**的汇总分析，不包含患者姓名、联系方式、身份证号、病历号等可识别信息。
- 医生代码仅作为流程角色示例，**不纳入采集表用于个体能力评价**。
- 拟议字段中的“状态更新时间”“取消时间”“来源系统”为**建议增加项**，实施前仍需合规评估，不能写成已经建表或已获得数据授权。
- 当前阶段**不计算真实医院指标**，不基于本表输出爽约率或渠道差异结论。
