# 提示词整理工具对照研究方案

## 一、研究问题

本研究比较三种提示词准备条件对下游任务输出质量的影响：原始需求直接输入、经提示词整理工具直接增强、经交互式计划确认后增强。核心问题不是“哪家产品更好”，而是：在相同初始信息下，直接增强是否优于原始输入；在信息量匹配的前提下，交互式计划确认的组织方式是否带来额外收益。

## 二、实验设计

**任务集。** 固定二十个任务，覆盖开发方案类（下游模型只输出方案、不修改仓库）与写作交付类（交付文本），两类任务不共用代码测试通过率等统一指标。每个任务附带初始材料，保留真实实现、用户说明、测试示例、待办四类来源标签；测试污染反例在评分前不得人为删除。

**条件与分组。** 设四个条件：

- **A 原始组**：下游模型直接接收原始需求与初始材料。
- **B 直接增强组**：提示词整理工具接收同一初始信息，生成优化提示词后交下游模型。
- **C 计划确认组**：工具先提问，实验操作者按预先制定的答案卡作答，再生成最终提示词。记录每个问题、选项、推荐依据和答案；错误推荐被答案纠正后仍计入交互阶段风险。
- **D 信息量匹配对照组**：获得与 C 组相同的已确认事实，但不经历问答过程，直接形成提示词交下游模型。

A、B 两组不得接触 C 组后续回答的业务选择。D 组用于分离“新增信息”与“交互组织方式”的效应：B 与 A 比较直接增强的净效应；C 与 D 比较交互过程本身的净效应；D 与 B 比较新增信息量的效应。

**重复与随机化。** 每个条件对每个任务独立重复三次，共 240 次下游生成。每次重复开启隔离会话，随机化执行顺序，记录模型版本、日期和参数。失败后的重试不得替代第一份失败样本；工具失败和首轮失败均保留。

**盲评。** 两名盲评者独立评分，看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源。评审可查看任务事实，但不得查看另一名评审的先前评分。

## 三、评价指标

评分覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。每个维度采用有序等级评分。一个错误可能同时影响多个维度，评分表记录主错误和关联维度，避免同一问题重复计为独立失败。工具生成速度作为过程指标单独记录，不纳入质量分；无计费日志时不估算 Token 成本，不以字符数换算费用。

## 四、统计分析原则

统计方法的选择依赖分数是否有序、是否连续及是否重复测量，在变量性质确定前不锁定具体显著性检验。方案预注册时按以下流程确定：先判定各维度分数的测量层级，再确认重复测量结构，据此选择相应的描述统计与推断方法。人工评阅与可复核任务标准为必需环节，专业领域判断尚需专家参与。

## 五、限制

本研究为合成资料下的方法学对照设计，不评价任何产品的绝对优劣。实验尚未运行，无准确率、显著性结果或成功案例可报告。交互式计划确认的最大轮次与终止规则、两名评审的分歧处理与一致性评价方式尚未确定，须在预注册阶段明确后方可执行。
