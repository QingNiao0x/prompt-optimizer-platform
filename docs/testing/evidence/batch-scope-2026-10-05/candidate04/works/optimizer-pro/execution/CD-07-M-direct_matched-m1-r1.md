### 1.2 流程图说明（文字版）

以下为预约事件从产生到归入最终状态的流程说明，用于讨论口径衔接，不代表已实现系统流程。

```
[预约事件产生]
      │
      ▼
[渠道记录] ── 电话 / 网页 / 窗口
      │
      │  ← 注意：电话与网页可能记录同一预约的不同操作事件
      │     需先定义「首次渠道」与「变更渠道」，不能把操作次数当预约量
      ▼
[渠道去重与合并]  ← 规则未定（待确认）
      │
      ▼
[预约事件进入待观察状态]
      │
      ├── 到达就诊时间 ──→ [状态记录]
      │                        │
      │                        ├── ARRIVED
      │                        ├── CANCELLED（系统记录用户主动取消）
      │                        └── UNKNOWN（原因未细分）
      │
      ▼
[观察窗口]  ← 窗口未定（待确认）
      │
      │  窗口未确定前：只展示待核验事件
      │  不得将尚未到期的预约算入爽约率
      ▼
[归入最终状态]  ← 需在窗口与取消免责边界确定后
      │
      ▼
[运营讨论报告]
```

**流程说明要点**：

1. **渠道环节**：电话与网页可能记录同一预约的不同操作事件，渠道比较必须先定义首次渠道和变更渠道，不能把操作次数当成预约量（来源：current-brief.md）。
2. **状态环节**：UNKNOWN 可能来自设备同步延迟、现场漏登记或记录缺项；在缺少来源核查时，不能把这一状态解释为患者责任（来源：current-brief.md）。
3. **取消环节**：取消状态表示系统记录到用户主动取消，不意味着治疗结束、病情缓解或不再需要服务；分析报告不能给取消行为附加临床解释（来源：current-brief.md）。
4. **观察窗口环节**：窗口未确定前只应展示待核验事件，不应将尚未到期的预约算入爽约率（来源：current-brief.md）。
5. **时区环节**：取消时间与就诊时间均用医院本地时区，当前汇总表没有时区转换证据；是否需要转换未定。

## 2. 流程问题清单

以下为预约到诊与爽约流程中需要关注的问题，供内部讨论逐项核对。

### 2.1 渠道重复记录

- 电话预约与网页预约可能记录相同一次预约的不同操作事件。
- 渠道比较必须先定义**首次渠道**和**变更渠道**，不能把操作次数当成预约量。
- 需讨论：同一预约在电话与网页均有操作记录时，如何判定首次渠道？变更渠道如何标注？
- 需讨论：渠道去重规则未定前，渠道比较结果是否只作待核验展示？
- 来源：current-brief.md。

### 2.2 UNKNOWN 状态原因

- 到诊状态包括 ARRIVED、CANCELLED、UNKNOWN，UNKNOWN 的原因没有细分。
- UNKNOWN 可能来自设备同步延迟、现场漏登记或记录缺项。
- 在缺少来源核查时，**不能把这一状态解释为患者责任**，也不能直接计为爽约。
- 需讨论：如何设计来源核查字段（如状态更新时间、来源系统）以区分 UNKNOWN 成因？
- 来源：current-brief.md。

### 2.3 取消规则差异

- 旧流程说明：提前 24 小时取消不计爽约。
- 新会议草稿：建议提前 12 小时，尚未批准。
- 两份材料的适用口径和审批状态应按本题说明核对，不能只凭日期决定。
- 报告需将争议单独呈现，不能按文件修改时间直接断定新规则生效。
- 需讨论：在采用口径确定前，取消免责边界相关指标是否只作差异并列展示？
- 来源：`legacy-note.md`、current-brief.md。

### 2.4 观察窗口未定

- 观察窗口决定一个预约事件何时可以归为最终状态。
- 窗口未确定前只应展示待核验事件，不应将尚未到期的预约算入爽约率。
- 需讨论：窗口定义与分母规则未定前，是否暂不计算爽约率？
- 来源：current-brief.md。

### 2.5 取消状态的解释边界

- 取消状态表示系统记录到用户主动取消，不意味着治疗结束、病情缓解或不再需要服务。
- 分析报告不能给取消行为附加临床解释。
- 来源：current-brief.md。

### 2.6 时区与时间口径

- 预约取消时间与就诊时间均用医院本地时区。
- 当前汇总表没有时区转换证据。
- 需讨论：是否需要时区转换？在证据不足时是否只按本地时区展示并标注？
- 来源：current-brief.md。

### 2.7 样本量与百分比波动

- 预约事件量不同会影响百分比波动，小渠道样本较少时应保留数量和限制说明。
- 没有完整数据不能报告显著的渠道差异。
- 来源：current-brief.md。

### 2.8 角色与范围边界

- 医生代码只是流程角色示例，不是个人绩效评估范围；不能追加医生排行榜或利用服务时间做个体能力评价。
- 科室类型可能影响预约提前量和到诊行为，但本题材料只有一个门诊；不推断跨科室、跨医院或全市的运营表现。
- 来源：current-brief.md。

### 2.9 改进方向边界

- 改进建议应优先考虑清楚提示取消规则、核对登记质量与便捷改约。
- 不默认采取罚款、降低预约资格或公开患者记录。
- 若机构后来要求短信提醒方案，需要另行确认通知授权和退订流程；本次不把提醒需求悄悄扩成发送短信的实施任务。
- 来源：current-brief.md。
