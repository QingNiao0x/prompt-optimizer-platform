# 提示词整理工具对照研究方案

## 1. 研究问题

本研究比较三种提示词准备方式对下游任务输出的影响：原始需求直接输入、基于同一初始信息直接增强、以及交互式计划确认增强。交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答，再生成最终提示词，不是静态任务分解列表。研究不评价任何产品绝对优劣，只考察不同准备方式在需求保真、业务规则、输出可用性、阅读负担和执行边界五个维度上的差异。

公平比较需区分两个问题。其一，相同初始信息比较：原始组接收原始需求与初始材料，直接增强组接收同一初始信息得到的优化提示词；两组均不能接触计划确认组后来回答的业务选择。其二，信息量匹配比较：计划确认组因问答获得额外已确认事实，若仅与原始组比较，无法区分收益来自新增信息还是交互组织方式。因此增设信息量匹配对照组，该组获得与计划确认组相同的已确认事实，但不经历本平台问答过程，用于减少新增信息与交互组织方式之间的混淆。

## 2. 实验设计

固定二十个任务，覆盖开发任务与写作任务两类。开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本。跨任务不能用代码测试通过率作为统一质量指标。

四个条件：原始组、直接增强组、计划确认组、信息量匹配对照组。每个条件独立重复三次，共二百四十次下游生成。每次重复开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本；工具失败和首轮失败均须保留。

计划确认组记录每个问题、选项、推荐依据和答案，不只保存最终提示词；错误推荐被答案纠正后仍计入交互阶段风险。任务材料必须保留真实实现、用户说明、测试示例与待办来源标签；不能在人工评分前人为删除不利的测试污染反例。

两名盲评者独立评分。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；评分时可查看任务事实，但不能查看另一名评审先前评分。分歧处理和一致性评价方式尚未确定，不默认平均分、共识分、第三人仲裁或具体一致性统计量，列入预注册待确认清单。

## 3. 主要指标

五个评价维度各设独立评分项：需求保真、业务规则、输出可用性、阅读负担、执行边界。一个错误可能同时影响多个维度，评分表记录主错误和关联维度，避免将同一问题多次计成不同独立失败。工具生成速度是过程指标，质量分是结果指标；没有计费日志时不能估算真实 Token 成本，不能把字符数直接换算成实际费用。

候选统计方法依赖分数是否有序、是否连续和是否重复测量。方案说明选择流程，不在变量尚未确定时锁定某个显著性检验。

## 4. 限制

实验尚未运行，没有准确率、显著性、成功案例数量和用户结论。即使三个模型给出相似结论也不是研究完成证据；方案安排人工评阅与可复核任务标准，专业领域判断尚需专家参与。最大交互轮次和终止规则尚未确定，只进入预注册待确认清单，不默认任何轮次。
