# 合成门诊预约到诊与爽约情况内部运营分析方案（讨论版）

## 0. 方案定位与使用边界

本方案仅用于内部运营讨论，分析对象为某合成门诊二〇二六年第一季度的预约事件。资料为合成汇总字典与流程材料，不含真实患者信息，也不含完整逐条数据。

本方案不涉及诊断、处方、分诊优先级、医嘱或个体治疗；不计算真实医院指标；不建议减少任何患者服务权益；不把未知到诊状态直接计为爽约；不以收费或处罚作为默认整改建议。

本方案输出四类交付物：

1. 口径表和流程图说明；
2. 合成数据采集字段建议；
3. 运营讨论报告目录；
4. 人工复核及隐私边界清单。

资料引用分为三类，后文分别标注：

- **正式说明**：`materials/hospital_operations/current-brief.md`；
- **旧版草稿**：`materials/hospital_operations/legacy-note.md` 中的旧流程说明；
- **测试示例**：`materials/hospital_operations/tests/layout-example.txt`，仅用于排版和来源识别，不是本题事实，不代表工具偏好或已实现成果。

## 2. 流程图说明

### 2.1 预约事件进入分析池

预约事件编号进入分析池。一个患者可以多次预约，因此事件数不等于人数。分析池只包含某合成门诊二〇二六年第一季度的预约事件。

### 2.2 渠道归集

预约渠道有电话、网页和窗口三类。电话预约与网页预约可能记录相同一次预约的不同操作事件，因此渠道比较必须先定义首次渠道和变更渠道，不能把操作次数当成预约量。

在首次渠道和变更渠道定义未确定前，流程图只展示“渠道归集待定义”，不输出渠道比较结论。

### 2.3 状态分流

到诊状态包括 ARRIVED、CANCELLED、UNKNOWN。

- ARRIVED：进入已到诊分支；
- CANCELLED：进入已取消分支，表示系统记录到用户主动取消，不意味着治疗结束、病情缓解或不再需要服务；
- UNKNOWN：进入待核验分支，原因没有细分，可能来自设备同步延迟、现场漏登记或记录缺项；在缺少来源核查时，不能把这一状态解释为患者责任。

### 2.4 观察窗口与最终状态

观察窗口决定一个预约事件何时可以归为最终状态。窗口未确定前只应展示待核验事件，不应将尚未到期的预约算入爽约率。

当前观察窗口尚未确定，因此流程图在“待核验”与“最终状态”之间保留“窗口待定义”节点，不默认补全。

### 2.5 取消免责边界

取消免责边界存在两份材料差异：

- 旧流程说明：提前24小时取消不计爽约；
- 新会议草稿：建议提前12小时，尚未批准。

材料权威性并未建立，报告需将争议单独呈现，不能按文件修改时间直接断定新规则生效。流程图中该节点标注为“免责边界争议待决”，不自动采用其中一项。

### 2.6 指标计算前置条件

缺少核验及分母规则时不计算比例。小渠道样本较少时应保留数量和限制说明；没有完整数据不能报告显著的渠道差异。

### 2.7 报告输出

运营会议报告应标注合成材料与方法草案，明确专业评审后才能应用；文字可讨论工作流程，但不宣称任何方案已提高疗效。

以下字段为拟议采集表，实施前仍需合规评估；不能写成已经建表或已获得数据授权。表格只展示合成汇总信息，不包含患者、医生的可识别信息或敏感诊疗明细。

| 渠道 | 首次渠道 | 渠道归集 | 电话、网页、窗口 |
| 渠道 | 变更渠道 | 渠道归集 | 需先定义首次与变更 |
| 状态 | 到诊状态 | 分流 | ARRIVED、CANCELLED、UNKNOWN |
| 状态 | 取消来源系统 | 核验取消记录 | 拟议新增；实施前需合规评估 |
| 状态 | UNKNOWN 来源核查标记 | 核验未知状态 | 原因未细分，需来源核查 |
| 流程角色 | 医生代码 | 流程角色示例 | 不是个人绩效评估范围 |

| 样本 | 渠道事件量 | 波动说明 | 小渠道样本较少时保留数量和限制说明 |
