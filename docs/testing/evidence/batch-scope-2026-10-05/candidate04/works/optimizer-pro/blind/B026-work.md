### 1.2 预约事件从创建到最终状态的可能路径（流程图说明）

以下为文字化流程路径，用于讨论，不代表已实现系统逻辑：

```
[预约创建]
   │
   ├─ 渠道记录：电话 / 网页 / 窗口
   │     └─ 同一预约可能产生多次操作事件（电话+网页）
   │           └─ 需先定义：首次渠道？变更渠道？  ← 待确认
   │
   ▼
[预约存续期]
   │
   ├─ 用户主动取消 ──► 状态 CANCELLED
   │        └─ 取消时间 vs 就诊时间关系 → 是否免责  ← 待确认（24h / 12h 两版并存）
   │
   ├─ 到诊 ──────────► 状态 ARRIVED
   │
   └─ 状态未明 ──────► 状态 UNKNOWN
            └─ 可能来源：设备同步延迟 / 现场漏登记 / 记录缺项
                 └─ 需人工复核，不得解释为患者责任
   │
   ▼
[观察窗口判定]  ← 待确认
   │
   ├─ 窗口内且状态已最终 → 可归入统计（口径待定）
   └─ 窗口未到 / 状态未最终 → 仅列为“待核验事件”，不计入爽约率
```

**流程说明要点**：
1. 同一预约在电话与网页可能产生多个操作事件，渠道比较前必须先定义首次渠道与变更渠道，不能把操作次数当预约量。【现行】
2. UNKNOWN 在缺少来源核查时不得解释为患者责任。【现行】
3. 观察窗口未确定前，只展示待核验事件，不计算爽约率。【现行】
4. 取消免责边界两版并存，须同时呈现，不擅自采用。【旧版】【草稿】

## 二、合成数据采集字段建议

**总合规前提**：以下为拟议采集字段，**尚未建表、尚未获得数据授权**；实施前须经合规评估。字段仅采集合成汇总信息，不含患者、医生可识别信息或敏感诊疗明细。【现行】

| 字段名 | 说明 | 采集目的 | 合规前提 |
|---|---|---|---|
| 预约事件编号 | 区分一次预约的唯一编号 | 作为事件级统计基础，避免与人数混淆 | 编号不可反向关联到个人身份 |
| 渠道 | 电话 / 网页 / 窗口 | 支持渠道维度分析 | 仅记录渠道类别，不记录联系方式 |
| 首次渠道 | 该预约首次出现的渠道 | 定义首次渠道，避免操作次数当预约量 | 规则须先确认后采集 |
| 变更渠道 | 后续发生变更的渠道 | 识别渠道变更事件 | 同上 |
| 到诊状态 | ARRIVED / CANCELLED / UNKNOWN | 支持到诊与爽约分析 | 不附加临床解释 |
| 取消时间 | 用户主动取消的时间（医院本地时区） | 判断取消与就诊时间关系 | 不做时区换算推断 |
| 就诊时间 | 预约就诊时间（医院本地时区） | 计算提前量、判断免责边界 | 同上 |
| 状态更新时间 | 状态最近一次更新时间 | 支持观察窗口与最终状态判定 | 用于核验，不用于个体评价 |
| 来源系统 | 记录该事件的系统来源 | 识别重复记录、同步延迟 | 不泄露系统内部敏感配置 |
| 观察窗口标记 | 该事件是否已过观察窗口 | 区分待核验与可统计事件 | 窗口定义待确认后启用 |
| 核验状态 | 是否已人工复核 | 标记 UNKNOWN 等需复核事件 | 复核记录不含个人身份 |

**说明**：
- 状态更新时间、取消时间、来源系统为拟议新增字段，实施前仍需合规评估，不能写成已经建表或已获得数据授权。【现行】
- 若机构后续要求短信提醒方案，须另行确认通知授权与退订流程；本次不把提醒需求扩成发送短信的实施任务。【现行】

## 四、人工复核及隐私边界清单

### 4.1 人工复核事项

| 复核事项 | 复核内容 | 复核原因 | 依据 |
|---|---|---|---|
| UNKNOWN 状态原因 | 设备同步延迟 / 现场漏登记 / 记录缺项 | 原因未细分，不得解释为患者责任 | 【现行】 |
| 取消时间与就诊时间关系 | 是否落在免责边界内 | 24h / 12h 两版并存，待确认 | 【旧版】【草稿】 |
| 渠道重复记录 | 电话与网页是否记录同一预约的不同操作事件 | 避免操作次数当预约量 | 【现行】 |
| 首次渠道 / 变更渠道定义 | 规则是否已固定 | 渠道比较前提 | 【现行】 |
| 观察窗口判定 | 事件是否已过窗口、是否可归最终状态 | 窗口未定前只展示待核验事件 | 【现行】 |
| 主统计单位 | 事件口径 或 患者口径 | 事件数≠人数 | 【现行】 |
| 时区一致性 | 是否均为医院本地时区 | 汇总表无时区转换证据 | 【现行】 |
| 小样本渠道 | 数量与限制说明 | 避免报告显著渠道差异 | 【现行】 |

### 4.2 隐私保护边界

1. 不展示患者可识别信息（姓名、联系方式、证件号等）。
2. 不展示医生可识别信息；医生代码仅为流程角色示例，不做排行榜或个体能力评价。【现行】
3. 不展示敏感诊疗明细。
4. 表格仅展示合成汇总信息。
5. 不公开患者记录，不默认采取罚款、降低预约资格等整改建议。【现行】
6. 拟议采集表实施前须经合规评估，不得写成已建表或已获授权。【现行】
7. 如后续涉及短信提醒，须另行确认通知授权与退订流程。【现行】
