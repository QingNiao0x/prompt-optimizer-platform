# 提示词整理工具对照研究方案

## 1. 研究问题

本研究比较三种提示词准备条件对下游任务输出的影响：原始需求直接输入、对同一初始信息进行直接增强、以及交互式计划确认增强。核心问题不是“哪家产品更好”，而是：在相同初始信息下，交互式计划确认是否带来可归因于交互组织方式本身的输出质量差异；新增确认信息与交互过程各自贡献多少。

## 2. 实验设计

固定二十个任务，覆盖开发方案类与写作交付类。每个任务在四个条件下各独立重复三次，共二百四十次生成。条件如下：

- **A 原始组**：下游模型直接接收原始需求与初始材料。
- **B 直接增强组**：接收由同一初始信息生成的优化提示词，不接触计划确认组后来回答的业务选择。
- **C 计划确认组**：系统先提问，实验操作者按预先制定答案卡作答，再生成最终提示词。记录每个问题、选项、推荐依据和答案；错误推荐被答案纠正后仍计入交互阶段风险。
- **D 信息量匹配对照组**：获得与 C 组相同的已确认事实，但不经历本平台问答过程，用于分离新增信息与交互组织方式的效应。

每次重复开启隔离会话，随机化任务与条件顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本；工具失败和首轮失败均保留。

## 3. 主要指标

质量评分由两名盲评者独立给出，覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可查看任务事实，但不能看另一名评审先前评分。一个错误同时影响多个维度时，记录主错误和关联维度，避免同一问题多次计成独立失败。

跨任务不使用代码测试通过率作为统一质量指标。工具生成速度作为过程指标单独记录；无计费日志时不估算真实 Token 成本，不将字符数换算为实际费用。

## 4. 统计与限制

候选统计方法依赖分数是否有序、是否连续及是否重复测量，方案仅说明选择流程，不在变量性质未确定时锁定具体显著性检验。两名盲评者独立评分已定，分歧处理和一致性评价方式尚未确定，不默认平均分、共识分、第三人仲裁或具体一致性统计量。交互式计划确认的最大轮次和终止规则尚未确定，不默认任何轮次。即使三个模型给出相似结论也不构成研究完成证据；人工评阅与可复核任务标准为必需，专业领域判断尚需专家参与。
