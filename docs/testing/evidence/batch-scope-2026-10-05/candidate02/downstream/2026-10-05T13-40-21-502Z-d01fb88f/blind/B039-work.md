## 二、流程图说明

### 2.1 预约到诊与爽约流程节点

```
[预约创建] → [渠道记录] → [等待就诊] → [就诊时间到达] → [到诊状态判定]
                  │                              │
                  │                              ├─ ARRIVED：到诊
                  │                              ├─ CANCELLED：用户主动取消
                  │                              └─ UNKNOWN：待核验（同步延迟/漏登记/缺项）
                  │
                  └─ 电话/网页可能产生同一预约的多个操作事件
                     → 需区分首次渠道与变更渠道，不能以操作次数计预约量
```

### 2.2 状态流转与关键分支

| 节点 | 状态/分支 | 说明 |
|---|---|---|
| 预约创建 | 生成预约事件编号 | 一个患者可多次预约，事件数≠人数 |
| 渠道记录 | 电话/网页/窗口 | 电话与网页可能重复记录同一预约的不同操作事件；渠道比较前须定义首次渠道与变更渠道 |
| 等待就诊 | 未到就诊时间 | 观察窗口未定前，尚未到期事件只展示为待核验，不计入爽约率 |
| 到诊状态判定 | ARRIVED | 到诊 |
| 到诊状态判定 | CANCELLED | 系统记录的用户主动取消；不附加临床解释 |
| 到诊状态判定 | UNKNOWN | 可能来自设备同步延迟、现场漏登记或记录缺项；不解释为患者责任，不直接计为爽约 |

### 2.3 旧流程与新会议草稿差异（须分开标注）

| 材料 | 取消免责边界 | 审批状态 | 引用来源 |
|---|---|---|---|
| 旧流程说明 | 提前24小时取消不计爽约 | 旧版流程，适用性待核对 | legacy-note.md |
| 新会议草稿 | 建议提前12小时取消不计爽约 | 尚未批准 | legacy-note.md / current-brief.md |
