# 提示词整理工具对照研究方案

## 一、研究问题

本研究比较三种提示词整理方式对下游任务输出的影响：原始需求组、直接增强组、交互式计划确认增强组。研究不评价任何产品的绝对优劣，只考察整理方式与输出质量的关系。

核心问题：在初始材料相同的前提下，交互式计划确认是否比直接增强更能改善下游输出？该改善中有多少来自新增的已确认事实，多少来自问答交互的组织方式？

## 二、实验设计

**任务与重复**：固定二十个任务，每个条件独立重复三次，共一百八十次运行。每次运行开启隔离会话，随机化运行顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本。

**四个条件**：

1. **原始组**：接收原始需求与初始材料。
2. **直接增强组**：接收由同一初始信息生成的优化提示词。
3. **计划确认组**：系统先提问，实验操作者按预先制定的答案卡作答，再生成最终提示词。需记录每个问题、选项、推荐依据和答案，不只保存最终提示词。错误推荐被答案纠正后仍计入交互阶段风险。
4. **信息量匹配对照组**：获得与计划确认组相同的已确认事实，但不经历本平台问答过程。用于减少新增信息与交互组织方式之间的混淆。

原始组和直接增强组均不能偷看计划确认组后来回答的业务选择。

**材料要求**：任务材料必须保留真实实现、用户说明、测试示例与待办这几种来源标签。不能在人工评分前人为删除不利的测试污染反例。

**盲评**：两名盲评者独立评分。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源。评审可以看任务事实，但不能看另一名评审先前的评分。

## 三、主要指标

评价同时覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。

- **质量分**为结果指标，基于上述五维度评分。
- **工具生成速度**为过程指标，单独记录，不与质量分混用。
- 没有计费日志时不能估算真实 Token 成本，不能把字符数直接换算成实际费用。
- 跨任务不能用代码测试通过率作为统一质量指标：开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本。

一个错误可能同时影响完整性与可执行性，评分表需记录主错误和关联维度，避免将同一问题多次计成不同独立失败。

## 四、限制

1. 实验尚未运行，无准确率、显著性、成功案例数量或用户结论。
2. 评分尺度已确定为顺序尺度，但具体等级与评分锚点仍未确定。
3. 交互式计划确认的最大轮次和终止规则尚未确定。
4. 两名评审的分歧处理流程与一致性评价指标尚未确定。
5. 候选统计方法依赖分数是否有序、是否连续和是否重复测量；方案只说明选择流程，不在变量尚未确定时锁定某个显著性检验。
6. 即使三个模型给出相似结论也不是研究完成证据；需安排人工评阅与可复核任务标准，专业领域判断尚需专家参与。
7. 本方案不涉及伦理审批，也未获得任何审批。

## 附表一：变量与分组

| 变量类型 | 变量名 | 定义 | 取值/说明 |
|---|---|---|---|
| 自变量 | 整理方式 | 提示词整理条件 | 原始组 / 直接增强组 / 计划确认组 / 信息量匹配对照组 |
| 因变量 | 需求保真 | 输出是否忠实于原始需求 | 顺序尺度，等级待定 |

| 因变量 | 输出可用性 | 输出是否可直接使用 | 顺序尺度，等级待定 |
| 因变量 | 阅读负担 | 阅读输出所需认知成本 | 顺序尺度，等级待定 |
| 因变量 | 执行边界 | 输出是否越界或遗漏边界 | 顺序尺度，等级待定 |
| 过程指标 | 生成速度 | 工具生成耗时 | 单独记录，不与质量分混用 |
| 控制变量 | 任务 | 二十个固定任务 | 任务编号 1–20 |
| 控制变量 | 重复 | 每条件三次独立重复 | 隔离会话，随机化顺序 |

| 控制变量 | 评审 | 两名盲评者 | 独立评分，互不可见 |

| 原始组 | 有 | 无 | 无 | 无 |
