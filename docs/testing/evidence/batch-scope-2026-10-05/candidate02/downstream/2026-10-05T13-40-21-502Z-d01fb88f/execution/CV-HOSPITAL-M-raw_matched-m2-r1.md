# 合成医院门诊预约运营分析方案（二〇二六年第一季度）

> 用途：内部运营讨论稿，仅分析预约到诊与爽约的流程口径与数据采集方案。  
> 数据性质：合成汇总信息，无真实患者信息，无完整逐条数据。  
> 范围限制：不涉及诊断、处方、分诊优先级、医嘱或个体治疗；不计算真实医院指标；不建议减少任何患者服务权益。


## 一、输出口径梳理

### 1.1 统计单位口径

| 口径项 | 当前状态 | 说明 |
|---|---|---|
| 预约事件编号 | 可区分一次预约 | 一个患者可多次预约，事件数 ≠ 人数 |
| 主统计单位 | **尚未确定** | 比较渠道时，采用预约事件还是去重患者，需业务决策后确定；两者不可混用 |
| 渠道分类 | 电话、网页、窗口三类 | 已明确，不再增删 |
| 到诊状态 | ARRIVED / CANCELLED / UNKNOWN | UNKNOWN 原因未细分，**不得直接计为爽约** |
| 时区口径 | 预约取消时间与就诊时间均为医院本地时区 | 当前汇总表无时区转换证据，分析时不做跨时区推断 |

### 1.2 状态判定口径

| 状态 | 判定方式 | 备注 |
|---|---|---|
| ARRIVED | 系统记录到诊 | 可直接用于到诊统计 |
| CANCELLED | 系统记录用户主动取消 | 不附加临床解释；不意味着治疗结束或不再需要服务 |
| UNKNOWN | 状态未知 | 可能来自设备同步延迟、现场漏登记或记录缺项；**不得解释为患者责任**；是否进入分母尚未确定 |

### 1.3 爽约判定口径

| 口径项 | 当前状态 |
|---|---|
| 爽约定义 | 尚未确定。UNKNOWN 不直接计为爽约 |
| 观察窗口 | **尚未确定**。窗口决定一个预约事件何时可归为最终状态；窗口未确定前，只展示待核验事件，不将尚未到期的预约算入爽约率 |
| 取消免责边界 | **存在两份材料差异，尚未确定**（见下表） |

### 1.4 取消免责边界——材料差异对照

| 材料 | 规定 | 状态 |
|---|---|---|
| 旧流程说明（legacy-note.md） | 提前 24 小时取消不计爽约 | 旧版，适用性未定 |
| 新会议草稿（legacy-note.md 所载） | 建议提前 12 小时，尚未批准 | 草稿，未批准 |

**处理方式**：两份材料的适用口径和审批状态按本题说明核对，不按文件修改时间断定新规则生效；报告中将差异单独呈现，不擅自采用其中一项。


## 二、流程图说明（文字版）

### 2.1 预约事件状态流转（基于现有资料）

```
预约创建（电话 / 网页 / 窗口）
        │
        ▼
   ┌─────────────────────────┐
   │ 预约事件进入汇总表        │
   │ 记录：事件编号、渠道、    │
   │ 预约时间、就诊时间、状态  │
   └─────────────────────────┘
        │
        ├──► 状态 = ARRIVED ──────► 计入到诊
        │
        ├──► 状态 = CANCELLED ────► 计入取消
        │        │
        │        └── 是否触发爽约判定？
        │              ├─ 取消时间距就诊时间 ≥ 免责边界（未定：24h 或 12h）→ 不计爽约
        │              └─ 取消时间距就诊时间 < 免责边界（未定）→ 是否计爽约，待定
        │
        └──► 状态 = UNKNOWN ──────► 进入待核验池
                 │
                 ├─ 观察窗口（未定）内 → 不归入最终状态
                 └─ 观察窗口（未定）届满后 → 需人工核验来源，不直接计为爽约
```

### 2.2 渠道比较的流程前提

```
同一预约事件可能由电话与网页分别记录操作
        │
        ▼
渠道比较前必须定义：
  ① 首次渠道（预约创建时使用的渠道）
  ② 变更渠道（后续操作使用的渠道）
        │
        ▼
不能把操作次数当成预约量
```

**说明**：渠道比较的主统计单位（预约事件或去重患者）尚未确定，且首次渠道与变更渠道的划分规则需在分析前明确；当前汇总表若无此区分字段，渠道比较仅能做描述性展示，不做显著性结论。


## 三、拟议数据采集字段建议

> 以下字段为**拟议**采集内容，用于支持后续运营分析；实施前需合规评估，不视为已建表或已获数据授权。

### 3.1 基础字段（已有或应保留）

| 字段名 | 说明 | 用途 |
|---|---|---|
| 预约事件编号 | 唯一标识一次预约 | 主键，区分事件 |
| 患者去重标识（脱敏） | 用于识别同一患者多次预约，不含可识别信息 | 支持去重患者口径分析 |
| 预约渠道 | 电话 / 网页 / 窗口 | 渠道比较 |
| 首次渠道 | 预约创建时使用的渠道 | 区分首次与变更渠道 |
| 变更渠道 | 后续操作使用的渠道（如有） | 避免操作次数混入预约量 |
| 预约创建时间 | 医院本地时区 | 时间序列分析 |
| 就诊时间 | 医院本地时区 | 判定爽约与观察窗口 |
| 到诊状态 | ARRIVED / CANCELLED / UNKNOWN | 核心状态字段 |

### 3.2 建议补充字段（拟议，需合规评估）

| 字段名 | 说明 | 用途 |
|---|---|---|
| 状态更新时间 | 状态最后一次变更的时间 | 判断 UNKNOWN 是否仍在观察窗口内 |
| 取消时间 | 用户主动取消的时间（医院本地时区） | 计算取消提前量，判定免责边界 |
| 来源系统 | 记录该状态或操作的系统名称 | 核查 UNKNOWN 来源（同步延迟 / 漏登记 / 缺项） |
| 现场登记标记 | 是否完成现场到诊登记 | 辅助核验 ARRIVED 与 UNKNOWN |
| 改约标记 | 是否存在改约操作 | 区分取消后重新预约与单纯取消 |

### 3.3 明确不采集的字段

| 不采集内容 | 原因 |
|---|---|
| 患者姓名、身份证号、联系方式等可识别信息 | 隐私边界，分析仅需脱敏标识 |
| 医生个人绩效相关字段 | 医生代码仅为流程角色示例，不做个体能力评价 |
| 诊断、处方、分诊优先级、医嘱、治疗明细 | 超出本题范围 |
| 短信提醒授权与退订信息 | 本次不涉及短信提醒实施 |

## 五、人工复核及隐私边界清单

### 5.1 人工复核清单

| 复核项 | 复核内容 | 触发条件 |
|---|---|---|
| UNKNOWN 状态核验 | 核查来源系统记录，判断是同步延迟、漏登记还是记录缺项 | 所有 UNKNOWN 状态事件，观察窗口届满后 |
| 取消时间核验 | 核对取消时间与就诊时间是否同属医院本地时区，无时区转换证据时不做跨时区推断 | 涉及取消免责边界判定的事件 |
| 渠道归属核验 | 确认首次渠道与变更渠道的划分，避免操作次数混入预约量 | 渠道比较分析前 |
| 状态最终性核验 | 确认预约事件是否已过观察窗口（窗口未定时，仅标注待核验） | 计算任何爽约相关比例前 |
| 材料口径核验 | 确认取消免责边界采用哪份材料（24h 旧流程 / 12h 草稿），以审批状态为准 | 报告定稿前 |

### 5.2 隐私边界清单

| 边界项 | 要求 |
|---|---|
| 患者标识 | 仅使用脱敏去重标识，不含姓名、证件号、联系方式等可识别信息 |
| 医生信息 | 医生代码仅作流程角色示例，不用于个人绩效评估、排行榜或个体能力评价 |
| 诊疗明细 | 不采集、不展示诊断、处方、分诊优先级、医嘱、治疗内容 |
| 数据展示 | 表格只展示合成汇总信息，不包含可识别个体记录 |
| 数据授权 | 拟议采集表实施前需合规评估，不视为已获数据授权 |
| 通知授权 | 如后续涉及短信提醒，需另行确认通知授权和退订流程；本次不扩展为实施任务 |
