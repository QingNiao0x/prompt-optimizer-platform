# 提示词整理工具对照研究方案（未执行）

## 一、研究方案主文

**研究问题。** 本研究比较三种提示词准备条件对下游任务输出的影响：原始需求（原始组）、直接增强（直接增强组）、交互式计划确认增强（计划确认组）。研究不评价任何产品的绝对优劣，只比较条件差异。交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答，再生成最终提示词，不是静态任务分解列表。

**公平比较条件。** 原始组接收原始需求与初始材料；直接增强组接收由同一初始信息得到的优化提示词；两组均不得接触计划确认组后来回答的业务选择。计划确认组会额外获得已确认答案，因此另设信息量匹配对照组：该组获得相同已确认事实，但不经历本平台问答过程，用于减少“新增信息”与“交互组织方式”之间的混淆。所有工具获取相同初始材料。

**实验设计。** 固定二十个任务，每条件独立重复三次，共四组。每次重复开启隔离会话，随机化运行顺序，记录模型版本、日期与参数。失败后的重试不能替代第一份失败样本，首轮失败必须保留。计划确认组须记录每个问题、选项、推荐依据和答案，不只保存最终提示词；错误推荐被答案纠正后仍计入交互阶段风险。最大交互轮次与终止规则尚未确定，不默认任何轮次或提前终止条件。

**主要指标。** 评价同时覆盖需求保真、业务规则、输出可用性、阅读负担和执行边界。评分尺度采用顺序尺度；具体等级数量与评分锚点仍未确定，不得自行指定。工具生成速度是过程指标，质量分是结果指标。没有计费日志时不能估算真实 Token 成本，不能把字符数直接换算成实际费用。跨任务不能用代码测试通过率作为统一质量指标：开发任务要求下游模型只输出方案、不实际修改仓库；写作任务要求交付文本。

**评审与统计。** 两名盲评者独立评分。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；为评分可看任务事实，但不能看另一名评审先前评分。一个错误可能同时影响完整性与可执行性，评分表须记录主错误和关联维度，避免同一问题被多次计成独立失败。分歧处理流程暂不确定；一致性评价指标尚未确定，不锁定某个指标。候选统计方法依赖分数是否有序、是否连续和是否重复测量；方案可说明选择流程，不应在变量尚未确定时锁定某个显著性检验。

**材料与限制。** 任务材料必须保留真实实现、用户说明、测试示例与待办这几种来源标签；不能在人工评分前人为删除不利的测试污染反例。实验尚未运行，没有准确率、显著性、成功案例数量或用户结论。即使三个模型给出相似结论也不是研究完成证据；方案安排人工评阅与可复核任务标准，专业领域判断尚需专家参与。详细答案卡、记录字段和材料目录见附表。

## 二、变量与分组附表

| 组别 | 接收信息 | 是否经历问答 | 是否获得已确认事实 | 禁止接触 |
|---|---|---|---|---|
| 原始组 | 原始需求＋初始材料 | 否 | 否 | 计划确认组答案 |
| 直接增强组 | 同一初始信息得到的优化提示词 | 否 | 否 | 计划确认组答案 |
| 计划确认组 | 初始材料＋问答后最终提示词 | 是 | 是 | — |
| 信息量匹配对照 | 初始材料＋相同已确认事实 | 否 | 是 | — |

**变量。** 自变量：提示词准备条件（四水平）。因变量：需求保真、业务规则、输出可用性、阅读负担、执行边界（顺序尺度，等级待定）。控制变量：任务集（20）、重复次数（3）、模型版本、日期、参数、初始材料。过程指标：生成速度。结果指标：质量分。

**材料来源标签。** 真实实现、用户说明、测试示例、待办，四类均须保留。

## 三、评分表及失败记录模板

**评分表字段。** 评审编号｜任务编号｜条件代码（匿名）｜重复序号｜需求保真｜业务规则｜输出可用性｜阅读负担｜执行边界｜主错误｜关联维度｜备注。主错误与关联维度须同时记录，防止同一问题重复计为独立失败。

**失败记录模板。** 任务编号｜条件代码｜重复序号｜会话是否隔离｜首轮是否失败｜失败类型｜是否重试｜重试是否替代首轮样本（应为否）｜计划确认组：问题、选项、推荐依据、答案｜错误推荐是否被纠正｜是否计入交互阶段风险｜记录人｜日期。
