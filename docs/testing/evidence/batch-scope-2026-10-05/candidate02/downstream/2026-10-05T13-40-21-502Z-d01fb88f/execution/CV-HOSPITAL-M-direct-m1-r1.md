# 合成门诊预约到诊与爽约情况——内部运营分析方案（方法草案）

## 0. 文档性质与边界

- 本方案仅针对**某合成门诊二〇二六年第一季度的预约事件**，用于内部运营讨论，属于**方法草案**，须经专业评审后方可应用。
- 资料为**合成材料**，不含真实患者信息，也**没有完整逐条数据**；本方案不计算任何真实医院指标。
- 本方案只提供运营资料分析与写作方案，**不给出任何临床判断或医疗建议**；不对取消行为附加临床解释，不将未知到诊状态解释为患者责任。
- 本方案不涉及诊断、处方、分诊优先级、医嘱或个体治疗；不追加医生排行榜，不利用服务时间做个体能力评价。
- 不推断跨科室、跨医院或全市运营表现（本题材料只有一个门诊）。
- 不宣称任何方案已提高疗效；不写成已建表或已获得数据授权。
- 资料引用区分：**正式说明**（current-brief.md）、**旧版草稿**（legacy-note.md）、**测试示例**（tests/layout-example.txt，仅用于排版与来源识别，不是本题事实）。

## 1. 口径梳理

### 1.1 口径表

| 口径项 | 定义 | 统计口径要点 | 状态 |
|---|---|---|---|
| 预约事件 | 以预约事件编号区分的一次预约 | 事件数 ≠ 人数；一个患者可多次预约 | 已知事实 |
| 患者 | 预约主体 | 去重患者数需另行定义主统计单位后方可计算 | 待确认（主统计单位未定） |
| 渠道 | 电话、网页、窗口三类 | 渠道已明确，不再询问分析哪些渠道；电话与网页可能记录同一预约的不同操作事件 | 已知事实 |
| 首次渠道 / 变更渠道 | 渠道比较前必须先定义 | 不能把操作次数当成预约量 | 已知事实（定义待落地） |
| 到诊状态 | ARRIVED、CANCELLED、UNKNOWN | UNKNOWN 原因未细分；不得直接计为爽约 | 已知事实 |
| 取消时间 | 系统记录的用户主动取消时间 | 医院本地时区；当前汇总表无时区转换证据 | 已知事实 |
| 就诊时间 | 预约就诊时间 | 医院本地时区；无时区转换证据 | 已知事实 |
| 观察窗口 | 决定预约事件何时可归为最终状态 | 窗口未确定前只展示待核验事件，不将未到期预约计入爽约率 | 待确认（窗口未定） |
| 取消免责边界 | 提前多久取消不计爽约 | 旧流程说明：提前24小时；新会议草稿建议：提前12小时，尚未批准 | 待确认（两份材料差异，未擅自采用） |
| 爽约 | 未到诊且非取消、非未知 | 分母、分子须与观察窗口一致；UNKNOWN 不计入爽约 | 待确认（依赖窗口与免责边界） |

### 1.2 已知事实、待确认项与必要假设

**已知事实（来自 current-brief.md）**
- 预约事件编号可区分一次预约，但一个患者可以多次预约，事件数不等于人数。
- 预约渠道有电话、网页和窗口三类，已明确；不得再询问本次需要分析哪些渠道。
- 到诊状态包括 ARRIVED、CANCELLED、UNKNOWN，UNKNOWN 的原因没有细分。
- 预约取消时间与就诊时间均用医院本地时区，当前汇总表没有时区转换证据。
- 电话预约与网页预约可能记录相同一次预约的不同操作事件，渠道比较必须先定义首次渠道和变更渠道，不能把操作次数当成预约量。
- 取消状态表示系统记录到用户主动取消，不意味着治疗结束、病情缓解或不再需要服务；分析报告不能给取消行为附加临床解释。
- 到诊状态未知可能来自设备同步延迟、现场漏登记或记录缺项；在缺少来源核查时，不能把这一状态解释为患者责任。
- 观察窗口决定一个预约事件何时可以归为最终状态，窗口未确定前只应展示待核验事件，不应将尚未到期的预约算入爽约率。
- 旧流程与新会议草稿有不同取消提前量，材料权威性并未建立；报告需将争议单独呈现，不能按文件修改时间直接断定新规则生效。
- 预约事件量不同会影响百分比波动，小渠道样本较少时应保留数量和限制说明；没有完整数据不能报告显著的渠道差异。
- 资料中的医生代码只是流程角色示例，不是个人绩效评估范围。
- 科室类型可能影响预约提前量和到诊行为，但本题材料只有一个门诊。
- 拟议采集表可以增加状态更新时间、取消时间和来源系统字段，实施前仍需合规评估。
- 改进建议应优先考虑清楚提示取消规则、核对登记质量与便捷改约，不默认采取罚款、降低预约资格或公开患者记录。
- 如果机构后来要求短信提醒方案，需要另行确认通知授权和退订流程；本次不把提醒需求悄悄扩成发送短信的实施任务。
- 运营会议报告应标注合成材料与方法草案，明确专业评审后才能应用。

**用户确认信息**
- 分析对象仅为某合成门诊二〇二六年第一季度的预约事件。
- 资料没有真实患者信息，也没有完整逐条数据。
- 只提供运营资料分析与写作方案，不给任何临床判断或医疗建议。
- 表格只展示合成汇总信息，不含患者、医生的可识别信息或敏感诊疗明细。
- 对于仍未明确的条件，不得默认补全。

**待确认项（影响任务目标，不得默认补全）**
1. 预约未到诊的**观察窗口**和**取消免责边界**如何定义。
2. 比较渠道时使用**预约事件**还是**去重患者**作为主统计单位。
3. 旧流程说明（提前24小时）与新会议草稿（提前12小时，尚未批准）的**适用口径与审批状态**——本方案只指出差异，不擅自采用其中一项。

**必要假设（仅用于方案写作，不冒充已选方法）**
- 假设一：在观察窗口确定前，所有尚未到期的预约事件均标记为“待核验”，不进入爽约率分子或分母。
- 假设二：在首次渠道/变更渠道规则确定前，渠道比较仅展示操作事件数量，不展示渠道爽约率差异。
- 假设三：UNKNOWN 状态在来源核查完成前单独列示，不并入 ARRIVED 或 CANCELLED。
- 以上假设均为**方法草案中的临时处理**，须经评审确认后方可替换为正式口径。

### 1.3 统计口径一致性要求

- 指标、分母、缺失值和时间边界必须一致。
- 建议或待定参数不冒充已选方法。

## 2. 流程图说明

### 2.1 流程节点与状态流转

基于流程材料，预约到诊与爽约的流程节点如下：

```
[预约创建] → [渠道记录] → [预约确认] → [就诊前取消判断] → [就诊日到诊登记] → [状态归集] → [观察窗口判定] → [最终状态]
```

**状态流转说明**

| 节点 | 输入 | 输出状态 | 关键分支 |
|---|---|---|---|
| 预约创建 | 患者发起预约 | 预约事件编号生成 | 渠道记录：电话/网页/窗口 |
| 渠道记录 | 操作事件 | 首次渠道、变更渠道 | 电话与网页可能记录同一预约的不同操作事件 |
| 预约确认 | 预约信息 | 待就诊 | — |
| 就诊前取消判断 | 取消时间 vs 就诊时间 | CANCELLED 或继续 | 提前量是否达到免责边界（旧24h / 新草稿12h，未批准） |
| 就诊日到诊登记 | 现场登记 | ARRIVED 或 UNKNOWN | 设备同步延迟、现场漏登记、记录缺项 |
| 状态归集 | 各节点状态 | ARRIVED / CANCELLED / UNKNOWN | UNKNOWN 原因未细分 |
| 观察窗口判定 | 就诊时间 + 窗口 | 最终状态或待核验 | 窗口未确定前只展示待核验事件 |
| 最终状态 | 归集结果 | 可计入指标 | 未到期预约不计入爽约率 |

### 2.2 关键分支

1. **渠道分支**：电话、网页、窗口三类。电话与网页可能记录同一预约的不同操作事件，渠道比较必须先定义首次渠道和变更渠道。
2. **取消分支**：取消状态表示系统记录到用户主动取消，不意味着治疗结束、病情缓解或不再需要服务；分析报告不能给取消行为附加临床解释。
3. **未知分支**：UNKNOWN 可能来自设备同步延迟、现场漏登记或记录缺项；在缺少来源核查时，不能把这一状态解释为患者责任。
4. **观察窗口分支**：窗口未确定前只应展示待核验事件，不应将尚未到期的预约算入爽约率。

### 2.3 旧流程与新会议草稿的差异

| 项目 | 旧流程说明 | 新会议草稿 | 本方案处理 |
|---|---|---|---|
| 取消免责提前量 | 提前24小时取消不计爽约 | 建议提前12小时 | 指出差异，不擅自采用其中一项 |
| 审批状态 | 旧流程说明（正式说明） | 尚未批准（草稿） | 材料权威性并未建立，不能按文件修改时间直接断定新规则生效 |
| 适用口径 | 按本题说明核对 | 按本题说明核对 | 报告需将争议单独呈现 |

> 来源区分：旧流程说明见 `materials/hospital_operations/legacy-note.md`；新会议草稿建议见同一文件中的草稿段落，尚未批准。正式说明见 `materials/hospital_operations/current-brief.md`。测试示例见 `materials/hospital_operations/tests/layout-example.txt`，仅用于排版与来源识别，不是本题事实。
