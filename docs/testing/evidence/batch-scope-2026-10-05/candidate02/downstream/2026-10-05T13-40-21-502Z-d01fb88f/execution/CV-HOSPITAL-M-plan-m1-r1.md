## 一、口径表和流程图说明

### 1.1 口径表

| 分析对象 | 定义 | 取值 | 来源 | 备注 |
|---|---|---|---|---|
| 预约事件 | 系统记录的一次预约操作，由预约事件编号唯一标识 | 预约事件编号（合成编号） | 【现行】 | 事件数不等于人数；一个患者可多次预约 |
| 患者 | 预约事件对应的服务对象 | 去重患者标识（合成标识） | 【现行】 | 与预约事件为多对一关系；主统计单位尚未确定，保留事件与去重患者的区别 |
| 渠道 | 预约发起的操作入口 | 电话、网页、窗口 | 【现行】 | 三类已明确，不再询问；电话与网页可能记录同一次预约的不同操作事件 |
| 首次渠道 | 一次预约中最早记录的操作渠道 | 电话/网页/窗口 | 【现行】 | 渠道比较前必须先定义，不能把操作次数当预约量 |
| 变更渠道 | 同一次预约中后续记录的操作渠道 | 电话/网页/窗口 | 【现行】 | 需与首次渠道区分；变更规则待业务确认 |
| 到诊状态 | 系统记录的预约到诊结果 | ARRIVED、CANCELLED、UNKNOWN | 【现行】 | UNKNOWN 原因未细分；不直接计为爽约，是否进入分母尚未确定 |
| 取消状态 | 系统记录到用户主动取消 | 已取消/未取消（由 CANCELLED 派生） | 【现行】 | 不意味着治疗结束、病情缓解或不再需要服务；不得附加临床解释 |
| 观察窗口 | 决定预约事件何时可归为最终状态的时间边界 | 尚未确定，不默认任何时长 | 【现行】 | 窗口未确定前只展示待核验事件，不将未到期预约计入爽约率 |
| 统计单位 | 指标计算的基本单位 | 预约事件 或 去重患者（尚未确定） | 【现行】 | 两者区别须保留，不默认其中一种 |
| 取消免责边界 | 提前多久取消不计爽约 | 24小时（旧版）/ 12小时（草稿，未批准） | 【旧版】【草稿】 | 适用性和批准情况尚未确定，分别保留差异与出处，不擅自采用 |
| 时区 | 取消时间与就诊时间所用时区 | 医院本地时区 | 【现行】 | 当前汇总表没有时区转换证据 |
| 科室范围 | 本题材料覆盖的门诊范围 | 单一门诊 | 【现行】 | 不推断跨科室、跨医院或全市运营表现 |
| 医生代码 | 流程角色示例 | 合成代码 | 【现行】 | 不是个人绩效评估范围；不做排行榜或个体能力评价 |


### 1.2 流程图说明

**预约事件从创建到最终状态的可能路径：**

```
[预约创建]
    │
    ├─ 记录首次渠道（电话/网页/窗口）
    │
    ▼
[可能发生渠道变更操作]
    │  电话与网页可能记录同一次预约的不同操作事件
    │  → 待核验点：首次渠道与变更渠道的判定规则
    │
    ▼
[预约进行中]
    │
    ├──→ [用户主动取消] ──→ 状态 CANCELLED
    │         │
    │         └─ 待核验点：取消时间与就诊时间间隔
    │              是否满足免责边界（24h旧版 / 12h草稿，均未确定）
    │
    ├──→ [到诊] ──→ 状态 ARRIVED
    │
    └──→ [状态未知] ──→ 状态 UNKNOWN
              │
              └─ 可能来源：设备同步延迟、现场漏登记、记录缺项
                 → 待核验点：来源核查后才能归类
                 → 不直接计为爽约，是否进入分母尚未确定

[观察窗口判定]
    │  窗口尚未确定，不默认任何时长
    │  窗口未确定前：只展示待核验事件
    │  不将尚未到期的预约算入爽约率
    ▼
[最终状态归类]
```

**关键分支与待核验点汇总：**

| 序号 | 待核验点 | 说明 | 来源 |
|---|---|---|---|
| 1 | 首次渠道与变更渠道判定规则 | 渠道比较前必须定义，不能把操作次数当预约量 | 【现行】 |
| 2 | UNKNOWN 来源核查 | 设备同步延迟/现场漏登记/记录缺项，缺少来源核查时不解释为患者责任 | 【现行】 |
| 3 | 观察窗口时长 | 尚未确定，不默认任何时长 | 【现行】 |
| 4 | UNKNOWN 是否进入爽约分母 | 尚未确定 | 【现行】 |
| 5 | 取消免责边界适用材料 | 24h旧版与12h草稿的适用性和批准情况尚未确定 | 【旧版】【草稿】 |
| 6 | 主统计单位 | 预约事件或去重患者，尚未确定 | 【现行】 |
| 7 | 时区转换证据 | 当前汇总表没有时区转换证据 | 【现行】 |


## 二、合成数据采集字段建议

> **状态声明**：以下字段为**拟议**采集项，**当前未建表、未获得数据授权**。实施前仍需合规评估。不得写成已经建表或已获得数据授权。【现行】

| 字段名称 | 类型 | 含义 | 采集目的 | 合规前提 |
|---|---|---|---|---|
| 预约事件编号 | 文本/编号 | 唯一标识一次预约 | 区分预约事件，避免与操作次数混淆 | 合成编号，不含真实身份信息 |
| 患者去重标识 | 文本/编号 | 合成去重标识 | 支持去重患者统计，保留与事件数的区别 | 不可逆匿名化，不含可识别信息 |
| 首次渠道 | 枚举 | 电话/网页/窗口 | 渠道比较的基础 | 需先定义判定规则 |
| 变更渠道 | 枚举 | 电话/网页/窗口 | 记录后续操作渠道 | 需与首次渠道区分 |
| 渠道操作时间 | 日期时间 | 各次渠道操作的时间 | 判定首次与变更顺序 | 医院本地时区，需注明 |
| 到诊状态 | 枚举 | ARRIVED/CANCELLED/UNKNOWN | 核心结果变量 | UNKNOWN 不直接计为爽约 |
| 状态更新时间 | 日期时间 | 状态最后一次更新时间 | 支持观察窗口判定和同步延迟识别 | 拟议新增字段，需合规评估 |
| 取消时间 | 日期时间 | 用户主动取消的时间 | 判定取消免责边界 | 医院本地时区，需注明；拟议新增字段 |
| 就诊时间 | 日期时间 | 预约就诊时间 | 计算提前量 | 医院本地时区，需注明 |
| 来源系统 | 文本 | 记录来源系统标识 | 识别设备同步延迟或记录缺项 | 拟议新增字段，需合规评估 |
| 科室类型 | 枚举 | 门诊类型 | 控制科室影响 | 本题仅一个门诊，不推断跨科室 |
| 医生代码 | 文本/编号 | 流程角色示例 | 仅作流程角色标识 | 不是个人绩效评估范围，不做排行榜 |

**采集前提说明：**
- 所有字段均为拟议，实施前需合规评估。【现行】
- 状态更新时间、取消时间和来源系统为拟议新增字段。【现行】
- 时区统一为医院本地时区，当前汇总表没有时区转换证据。【现行】
- 不采集患者、医生的可识别信息或敏感诊疗明细。
