## 一、口径表和流程图说明

### 1.1 分析口径表

|---|---|---|---|---|

| **就诊时间** | 预约计划就诊的时间点 | 日期时间（医院本地时区） | 预约系统记录 | 同上 |
| **观察窗口** | 决定一个预约事件何时可归为最终状态的时间边界 | **尚未确定，不默认任何时长** | 待业务决定 | 窗口未确定前只展示待核验事件，不应将尚未到期的预约算入爽约率（来源：current-brief.md；用户确认） |

### 1.2 流程图说明：预约事件从创建到最终状态的可能路径

```
[预约创建]
    │
    ├── 渠道记录：电话 / 网页 / 窗口
    │        │
    │        └── 同一事件可能存在多个渠道操作记录
    │             → 待核验点①：需区分首次渠道与变更渠道，
    │                不能将操作次数计为预约量
    │
    ▼
[等待就诊]
    │
    ├── 用户主动取消 ──→ [CANCELLED]
    │        │
    │        └── 待核验点②：取消时间与就诊时间的间隔
    │             → 适用哪份取消免责规则（24h旧流程 vs 12h草稿）尚未确定
    │
    ├── 到诊 ──→ [ARRIVED]
    │
    ├── 未到诊且未取消 ──→ [UNKNOWN 或 未记录]
    │        │
    │        └── 待核验点③：UNKNOWN 来源未细分
    │             （设备同步延迟 / 现场漏登记 / 记录缺项）
    │             → 不得直接计为爽约，不得归因于患者
    │
    └── 尚未到就诊时间 ──→ [待核验事件]
             │
             └── 待核验点④：观察窗口未确定
                  → 不默认任何时长，不将尚未到期事件计入爽约率
```

**关键分支说明**：

1. **渠道分支**：同一预约事件在电话和网页渠道均可能出现操作记录。分析前必须先定义"首次渠道"（事件最早记录的渠道）和"变更渠道"（后续操作中出现的不同渠道），否则渠道比较会把操作次数误当预约量（来源：current-brief.md）。
2. **取消分支**：CANCELLED 仅表示系统记录到用户主动取消，不附加任何临床含义（来源：current-brief.md）。取消是否免责取决于取消时间与就诊时间的间隔，但适用规则（24小时旧流程 vs 12小时会议草稿）尚未确定（来源：legacy-note.md；用户确认）。
3. **UNKNOWN 分支**：到诊状态未知的来源未细分，须在来源核查后才能判断原因，不得在分析中将其解释为患者责任（来源：current-brief.md）。
4. **观察窗口分支**：窗口未确定前，所有尚未到就诊时间或状态未最终确认的事件均列为"待核验事件"，不进入爽约率计算（来源：current-brief.md；用户确认）。


## 二、合成数据采集字段建议（拟议，未建表、未授权）

> **状态声明**：以下字段为拟议采集方案，**尚未建表，尚未获得数据授权**。实施前需完成合规评估（来源：current-brief.md）。

| 字段名称 | 类型 | 含义 | 采集目的 | 合规前提 |
|---|---|---|---|---|
| 预约事件编号 | 字符串（脱敏） | 唯一标识一次预约事件 | 区分事件，避免重复计数 | 需确认编号不直接关联患者身份 |

| 就诊时间 | 日期时间（医院本地时区） | 计划就诊时间 | 判断事件是否到期、计算提前量 | 需确认时区口径一致 |
| 到诊状态 | 枚举：ARRIVED/CANCELLED/UNKNOWN | 系统记录的到诊状态 | 核心分析变量 | 需确认状态取值完整 |

| 取消时间 | 日期时间（医院本地时区，可空） | 用户取消预约的时间 | 判断取消是否在免责边界内（边界确定后） | 需确认取消时间的记录完整性 |
| 来源系统 | 字符串 | 记录该事件的系统标识 | 核查 UNKNOWN 状态来源（同步延迟/漏登记/缺项） | 需确认系统间数据链路可追溯 |
| 科室类型 | 枚举（本题仅一个门诊） | 预约所属科室 | 本题仅一个门诊，不跨科室推断 | 如后续扩展需另行评估 |

- 所有字段采集前须完成合规评估，确认不涉及患者、医生的可识别信息或敏感诊疗明细（来源：current-brief.md）。
