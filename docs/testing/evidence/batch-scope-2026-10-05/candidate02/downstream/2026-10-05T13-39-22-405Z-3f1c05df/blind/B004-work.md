# 提示词整理工具对照研究方案（未执行）

## 一、研究问题

本研究比较三种提示词整理条件对下游任务输出的影响：原始需求（A组）、直接增强（B组）、交互式计划确认增强（C组）。交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答，再生成最终提示词，不是静态任务分解列表。研究不评价某家产品绝对优劣。

C组会额外获得已确认答案，因此另设信息量匹配对照（D组）：获得相同已确认事实，但不经历本平台问答过程，用于减少新增信息与交互组织方式之间的混淆。

## 二、实验设计

固定二十个任务、每条件独立重复三次、两名盲评者独立评分；所有工具获取相同初始材料。每条件三次重复开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本。

A组接收原始需求与初始材料；B组接收同一初始信息得到的优化提示词；A、B两组都不能偷看C组后来回答的业务选择。C组记录每个问题、选项、推荐依据和答案，不只保存最终提示词；错误推荐被答案纠正后仍应计入交互阶段风险。D组获得相同已确认事实，但不经历本平台问答过程。

任务材料保留真实实现、用户说明、测试示例与待办这几种来源标签；不能在人工评分前人为删除不利的测试污染反例。开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本，因此跨任务不能用代码测试通过率作为统一质量指标。

## 三、主要指标

评价同时覆盖需求保真、业务规则、输出可用性、阅读负担和执行边界。工具生成速度是过程指标，质量分是结果指标；没有计费日志时不能估算真实 Token 成本，不能把字符数直接换算成实际费用。

一个错误可能同时影响完整性与可执行性，评分表记录主错误和关联维度，避免将同一问题多次计成不同独立失败。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；为了评分可以看任务事实，但不能看另一名评审先前评分。

## 四、限制

实验尚未运行，没有准确率、显著性、成功案例数量和用户结论。候选评价统计方法依赖分数是否有序、是否连续和是否重复测量；方案只说明选择流程，不在变量尚未确定时锁定某个显著性检验。即使三个模型给出相似结论也不是研究完成证据；方案安排人工评阅与可复核任务标准，专业领域判断尚需专家参与。

## 五、公平比较条件

| 条件 | 初始信息 | 确认答案 | 问答过程 | 用途 |
|---|---|---|---|---|
| A 原始 | 相同 | 无 | 无 | 基线 |
| B 直接增强 | 相同 | 无 | 无 | 增强效果 |
| C 计划确认 | 相同 | 有 | 有 | 交互增强 |
| D 信息量匹配 | 相同 | 有 | 无 | 控制信息量 |

A、B两组不得偷看C组后来回答的业务选择。C组错误推荐被答案纠正后仍计入交互阶段风险。
