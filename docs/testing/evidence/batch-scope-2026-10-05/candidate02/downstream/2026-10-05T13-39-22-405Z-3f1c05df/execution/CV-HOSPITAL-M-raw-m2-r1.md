# 合成门诊预约到诊与爽约情况内部运营分析方案

**适用范围**：合成门诊二〇二六年第一季度预约事件。仅用于运营流程讨论，不涉及诊断、处方、分诊优先级、医嘱或个体治疗。全部数据为合成汇总信息，不含真实患者或医生可识别信息。


## 一、口径梳理

### 1.1 基础统计单位

| 口径项 | 当前状态 | 说明 |
|---|---|---|
| 预约事件编号 | 可用 | 可区分一次预约；一个患者可多次预约，事件数 ≠ 人数 |
| 患者去重口径 | 待确认 | 比较渠道时以预约事件还是去重患者为主统计单位，尚未决定 |
| 渠道分类 | 已确定 | 电话、网页、窗口三类，不再询问 |
| 首次渠道 vs 变更渠道 | 待确认 | 电话与网页可能记录同一预约的不同操作事件；渠道比较前须定义首次渠道和变更渠道，不能把操作次数当预约量 |

### 1.2 到诊状态口径

| 状态 | 含义 | 分析处理 |
|---|---|---|
| ARRIVED | 系统记录已到诊 | 计入到诊 |
| CANCELLED | 系统记录用户主动取消 | 单独统计，不附加临床解释（不意味治疗结束、病情缓解或不再需要服务） |
| UNKNOWN | 原因未细分 | **不得直接计为爽约**；可能来自设备同步延迟、现场漏登记或记录缺项，须列为待核验 |

### 1.3 爽约认定口径

| 口径项 | 当前状态 |
|---|---|
| 爽约定义 | 尚未确定。UNKNOWN 不得直接计入爽约 |
| 观察窗口 | 尚未确定。一个预约事件何时可归为最终状态，须先定义观察窗口；窗口未确定前只展示待核验事件，不将尚未到期预约算入爽约率 |
| 取消免责边界 | 存在争议，见 1.4 |

### 1.4 取消免责边界——材料差异（须单独呈现，不得擅自采用）

| 来源 | 内容 | 状态 |
|---|---|---|
| 旧流程说明（legacy-note.md） | 提前 24 小时取消不计爽约 | 旧版，权威性未建立 |
| 新会议草稿 | 建议提前 12 小时取消不计爽约 | 草稿，**尚未批准** |

**处理要求**：报告须将上述差异单独呈现，不能按文件修改时间断定新规则生效，也不能默认采用其中任何一项。在运营讨论中列为待决策项。

### 1.5 时区口径

| 口径项 | 当前状态 |
|---|---|
| 取消时间与就诊时间时区 | 均为医院本地时区 |
| 时区转换证据 | 当前汇总表没有时区转换证据；分析时不得假设已做转换 |

### 1.6 样本量限制口径

| 口径项 | 说明 |
|---|---|
| 小渠道样本 | 预约事件量不同会影响百分比波动；小渠道样本较少时须保留数量和限制说明 |
| 显著性判断 | 没有完整数据不能报告显著的渠道差异 |


## 二、流程图说明（文字版）

### 2.1 预约事件主流程

```
[患者发起预约] → [渠道记录：电话/网页/窗口] → [生成预约事件编号]
    → [预约状态进入待就诊] → [到达就诊时间前后]
        ├─ [系统记录 ARRIVED] → 到诊
        ├─ [系统记录 CANCELLED] → 取消（记录取消时间）
        └─ [状态仍为 UNKNOWN] → 待核验（不直接计为爽约）
```

### 2.2 渠道操作事件与预约事件的关系

```
电话渠道操作 ─┐
              ├→ 可能指向同一预约事件 → 渠道归属须区分"首次渠道"与"变更渠道"
网页渠道操作 ─┘
窗口渠道操作 ─── 独立记录
```

**说明**：渠道比较前必须先定义首次渠道和变更渠道。操作次数不等于预约量。

### 2.3 状态核验流程（UNKNOWN 处理）

```
[UNKNOWN 事件] → [检查是否已过观察窗口]
    ├─ 未过窗口 → 保留为待核验，不纳入爽约率
    └─ 已过窗口 → [来源系统核查]
          ├─ 设备同步延迟 → 修正为实际状态
          ├─ 现场漏登记 → 补登记
          └─ 记录缺项且无法核查 → 保留为 UNKNOWN，单独列示
```

### 2.4 取消规则适用流程（含争议标注）

```
[取消事件] → [计算取消时间距就诊时间的提前量]
    → 适用哪条免责边界？
          ├─ 旧流程：提前 ≥ 24 小时 → 不计爽约
          └─ 新草稿：提前 ≥ 12 小时 → 不计爽约（未批准）
    → 当前状态：两条规则并存，报告须并列呈现，待运营会议决策
```


## 三、拟议数据采集字段建议

以下为**拟议**采集字段，实施前仍需合规评估；不表示已经建表或已获得数据授权。

### 3.1 预约事件基础字段

| 字段名 | 说明 | 是否已有 |
|---|---|---|
| 预约事件编号 | 唯一标识一次预约 | 已有 |
| 预约创建时间 | 医院本地时区 | 已有 |
| 就诊时间 | 医院本地时区 | 已有 |
| 预约渠道（首次） | 电话/网页/窗口 | 已有，但需确认是否为首值 |
| 预约渠道（变更后） | 如有渠道变更 | 待确认是否可采集 |
| 到诊状态 | ARRIVED / CANCELLED / UNKNOWN | 已有 |
| 状态更新时间 | 状态最后一次变更的时间戳 | 拟增加 |
| 取消时间 | 仅 CANCELLED 事件 | 拟增加 |
| 来源系统 | 记录该事件状态的系统名称 | 拟增加 |

### 3.2 核验辅助字段

| 字段名 | 说明 | 目的 |
|---|---|---|
| 现场登记标记 | 是否有现场签到记录 | 区分 UNKNOWN 中的漏登记 |
| 设备同步时间 | 终端设备最后同步时间 | 判断同步延迟 |
| 改约记录 | 是否发生过改约及改约时间 | 判断取消与改约的边界 |

### 3.3 明确不采集的字段

| 不采集项 | 原因 |
|---|---|
| 患者姓名、证件号 | 隐私边界，分析不需要 |
| 医生个人绩效标识 | 医生代码仅为流程角色示例，不做个体评价 |
| 诊断、处方、医嘱信息 | 超出运营分析范围 |
| 敏感诊疗明细 | 超出范围且涉及隐私 |

## 五、人工复核及隐私边界清单

### 5.1 人工复核清单

| 复核项 | 复核内容 | 触发条件 |
|---|---|---|
| UNKNOWN 状态核查 | 逐条核对来源系统记录、现场签到、设备同步时间 | 所有 UNKNOWN 事件 |
| 取消时间准确性 | 核对取消时间戳与就诊时间戳的时区一致性 | 所有 CANCELLED 事件 |
| 渠道归属复核 | 同一预约事件存在多个渠道操作记录时，人工确认首次渠道 | 渠道比较分析前 |
| 观察窗口到期复核 | 确认事件是否已过观察窗口、可否归为最终状态 | 爽约率计算前 |
| 小样本渠道复核 | 对样本量较小的渠道，人工复核数据完整性 | 渠道差异讨论前 |

### 5.2 隐私边界清单

| 边界项 | 要求 |
|---|---|
| 患者身份 | 不采集、不展示患者姓名、证件号、联系方式 |
| 医生身份 | 医生代码仅作流程角色示例，不用于个人绩效评估或排行榜 |
| 诊疗信息 | 不涉及诊断、处方、分诊优先级、医嘱或个体治疗 |
| 取消行为解释 | 不对取消行为附加临床解释（不推断病情变化或不再需要服务） |
| 数据展示 | 表格只展示合成汇总信息，不含可识别信息或敏感诊疗明细 |
| 短信提醒 | 如后续要求短信提醒方案，须另行确认通知授权和退订流程；本次不扩展为实施任务 |
