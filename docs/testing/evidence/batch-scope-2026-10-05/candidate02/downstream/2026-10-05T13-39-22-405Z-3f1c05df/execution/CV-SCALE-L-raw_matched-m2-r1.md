# 提示词整理工具对照研究方案

## 1. 研究问题

本研究考察提示词整理工具在相同初始材料下，不同增强方式对下游任务输出质量的影响。具体比较三个条件：原始需求直接输入、经工具直接增强的提示词、经交互式计划确认后生成的提示词。为分离“新增确认信息”与“交互组织方式”的贡献，另设信息量匹配对照，该组获得与计划确认组相同的已确认事实，但不经历问答过程。

研究不评价任何产品绝对优劣，不报告准确率或显著性结果。实验尚未运行，本文仅规定设计与执行规则。

## 2. 实验设计

固定二十个任务，覆盖开发方案与写作交付两类。开发任务要求下游模型只输出方案、不修改仓库；写作任务要求交付文本。跨任务不采用代码测试通过率作为统一质量指标。

四个条件：

- **A 原始组**：接收原始需求与初始材料。
- **B 直接增强组**：接收由同一初始信息经工具直接优化得到的提示词。
- **C 计划确认组**：系统先提问，实验操作者按预先制定答案卡作答，再生成最终提示词。记录每个问题、选项、推荐依据和答案；错误推荐被答案纠正后仍计入交互阶段风险。
- **D 信息量匹配对照**：获得与 C 组相同的已确认事实，但不经历问答过程，用于减少新增信息与交互组织方式之间的混淆。

A、B 两组不得接触 C 组后来回答的业务选择。每个条件对每个任务独立重复三次，开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本；工具失败和首轮失败均保留。

任务材料保留真实实现、用户说明、测试示例与待办等来源标签，不得在人工评分前人为删除不利的测试污染反例。

## 3. 评价指标

两名盲评者独立评分，评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可查看任务事实，但不得查看另一名评审先前评分。

评分覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。评分尺度采用顺序尺度，具体等级与评分锚点尚未确定，不自行指定。一个错误可能同时影响多个维度，评分表记录主错误和关联维度，避免同一问题多次计成不同独立失败。

工具生成速度作为过程指标单独记录；质量分为结果指标。没有计费日志时不估算真实 Token 成本，不将字符数换算为实际费用。

## 4. 统计与一致性

候选统计方法依赖分数是否有序、是否连续和是否重复测量。本方案仅规定选择流程：待评分尺度和锚点确定后，根据测量属性选择相应方法，不预先锁定某个显著性检验。两名评审的分歧处理流程与一致性评价指标尚未确定，不默认任何方案。

## 5. 限制

即使多个模型给出相似结论也不构成研究完成证据。方案安排人工评阅与可复核任务标准；专业领域判断尚需专家参与，不声称模型可独立替代专家。本研究使用合成资料，不代表真实单位、患者、当事人或平台运行数据。
