# 合成门诊预约到诊与爽约内部运营分析方案

> 本方案仅面向某合成门诊二〇二六年第一季度预约事件的内部运营讨论，不涉及诊断、处方、分诊优先级、医嘱或个体治疗。全部材料为合成数据，无真实患者信息，也无完整逐条数据。报告须标注"合成材料与方法草案"，经专业评审后方可应用。


## 一、预约到诊与爽约口径表

### 1.1 基础口径

| 口径项 | 定义/取值 | 依据 | 备注 |
|---|---|---|---|
| 分析对象 | 某合成门诊二〇二六年第一季度预约事件 | current-brief.md | 单一门诊，不跨科室/医院推断 |
| 预约事件编号 | 可区分一次预约 | current-brief.md | 一个患者可多次预约，事件数≠人数 |
| 预约渠道 | 电话、网页、窗口三类 | current-brief.md | 已明确，不再询问 |
| 到诊状态 | ARRIVED / CANCELLED / UNKNOWN | current-brief.md | UNKNOWN 原因未细分 |
| 时间基准 | 医院本地时区 | current-brief.md | 当前汇总表无时区转换证据 |
| 取消状态含义 | 系统记录到用户主动取消 | current-brief.md | 不附加临床解释，不推断治疗结束或不再需要服务 |
| UNKNOWN 含义 | 设备同步延迟、现场漏登记或记录缺项 | current-brief.md | 不得解释为患者责任 |
| 医生代码 | 流程角色示例 | current-brief.md | 不用于个人绩效评估，不出医生排行榜 |

### 1.2 到诊与爽约判定口径

| 状态 | 判定 | 条件 | 备注 |
|---|---|---|---|
| ARRIVED | 到诊 | 系统记录为 ARRIVED | 直接计入到诊 |
| CANCELLED | 取消 | 系统记录为 CANCELLED | 是否计爽约取决于取消免责边界（见待确认项） |
| UNKNOWN | 待核验 | 系统记录为 UNKNOWN | **不得直接计为爽约**；观察窗口未确定前仅展示为待核验事件 |
| 未到期预约 | 待核验 | 就诊时间尚未到达观察窗口截止点 | 不计入爽约率 |

### 1.3 渠道比较口径

| 口径项 | 定义 | 依据 | 备注 |
|---|---|---|---|
| 首次渠道 | 同一预约事件最早记录到的渠道 | current-brief.md | 电话与网页可能记录同一预约的不同操作事件 |
| 变更渠道 | 同一预约事件后续操作中出现的其他渠道 | current-brief.md | 渠道比较前必须先定义首次渠道和变更渠道 |
| 统计单位 | 预约事件 or 去重患者 | 待确认 | 当前尚未决定，不得默认补全 |
| 操作次数 | 不作为预约量 | current-brief.md | 不得把操作次数当成预约量 |

### 1.4 爽约率计算口径（观察窗口未确定前的临时方案）

| 指标 | 公式 | 适用条件 |
|---|---|---|
| 到诊率 | ARRIVED 事件数 ÷ 已到期且状态可判定的事件数 | 仅限观察窗口已覆盖的事件 |
| 取消率 | CANCELLED 事件数 ÷ 已到期且状态可判定的事件数 | 同上 |
| 待核验率 | UNKNOWN 事件数 ÷ 已到期事件数 | 单独展示，不并入爽约 |
| 爽约率 | 暂不计算 | 观察窗口未确定前不计算爽约率 |

> **说明**：观察窗口决定一个预约事件何时可以归为最终状态。窗口未确定前，只展示待核验事件，不将尚未到期的预约算入爽约率（current-brief.md）。


## 二、流程图说明

### 2.1 预约事件状态流转图（文字版）

```
预约事件产生
    │
    ├── 渠道记录：电话 / 网页 / 窗口
    │       │
    │       └── 同一预约可能有多渠道操作事件
    │             → 需定义首次渠道与变更渠道（不把操作次数当预约量）
    │
    ├── 就诊时间到达前
    │       │
    │       ├── 用户主动取消 → CANCELLED
    │       │       │
    │       │       └── 是否计爽约？
    │       │             ├── 旧流程：提前24小时取消不计爽约（legacy-note.md）
    │       │             └── 新会议草稿：提前12小时，尚未批准（legacy-note.md）
    │       │                   → 争议单独呈现，不擅自采用
    │       │
    │       └── 未取消 → 等待就诊时间
    │
    ├── 就诊时间到达
    │       │
    │       ├── 系统记录 ARRIVED → 到诊
    │       │
    │       ├── 系统记录 CANCELLED → 取消（按上述免责边界判定）
    │       │
    │       └── 系统记录 UNKNOWN → 待核验
    │               │
    │               └── 可能原因：设备同步延迟 / 现场漏登记 / 记录缺项
    │                     → 不解释为患者责任
    │
    └── 观察窗口（未确定）
            │
            ├── 窗口内 → 可归为最终状态
            └── 窗口外 → 仍为待核验，不计入爽约率
```

### 2.2 渠道比较流程图（文字版）

```
同一预约事件的操作记录
    │
    ├── 电话渠道操作
    ├── 网页渠道操作
    └── 窗口渠道操作
            │
            ▼
    按预约事件编号归并
            │
            ▼
    定义首次渠道（最早记录到的渠道）
    定义变更渠道（后续出现的其他渠道）
            │
            ▼
    选择统计单位（预约事件 or 去重患者）→ 待确认
            │
            ▼
    渠道间比较
            │
            └── 小渠道样本较少时保留数量和限制说明
                 没有完整数据不报告显著渠道差异
```
