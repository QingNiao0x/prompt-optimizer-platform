# 提示词整理工具对照研究方案（尚未执行）

## 一、研究问题

本研究比较三种提示词条件对下游任务输出的影响：**原始需求**（原始组）、**直接增强**（直接增强组）、**交互式计划确认增强**（计划确认组）。交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答，再生成最终提示词，不是静态任务分解列表。研究不评价任何产品的绝对优劣。

计划确认组会额外获得答案，因此另设**信息量匹配对照**：该组获得相同已确认事实，但不经历本平台问答过程，用于减少新增信息与交互组织方式之间的混淆。公平比较因此区分两类问题：相同初始信息下的比较（原始组、直接增强组、计划确认组在提问前共享同一初始信息），以及收到确认答案后的信息量匹配比较（计划确认组与信息量匹配对照）。

## 二、实验设计

固定设计：二十个任务、每个条件独立重复三次、两名盲评者独立评分；所有工具获取相同初始材料。样本数量已确定，不重新选择。

原始组接收原始需求与初始材料；直接增强组接收同一初始信息得到的优化提示词；两组都不能偷看计划确认组后来回答的业务选择。计划确认组记录每个问题、选项、推荐依据和答案，不只保存最终提示词；错误推荐被答案纠正后仍计入交互阶段风险。

每个条件的三次重复开启隔离会话，随机化顺序并记录模型版本、日期和参数；失败后的重试不能替代第一份失败样本。任务材料保留真实实现、用户说明、测试示例与待办四种来源标签；人工评分前不得删除不利的测试污染反例。

开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本。因此跨任务不使用代码测试通过率作为统一质量指标。

## 三、主要指标

评价覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。评分表记录主错误与关联维度，避免将同一问题多次计成不同独立失败。工具生成速度作为过程指标，质量分作为结果指标；没有计费日志时不估算真实 Token 成本，不把字符数直接换算成实际费用。

盲评：评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可看任务事实，但不能看另一名评审先前评分。

统计方法说明选择流程：依据分数是否有序、是否连续、是否重复测量决定；在变量尚未确定时不锁定某个显著性检验。

## 四、限制

实验尚未运行，没有准确率、显著性、成功案例数量和用户结论。三个模型给出相似结论不构成研究完成证据；方案安排人工评阅与可复核任务标准，专业领域判断尚需专家参与。详细答案卡、记录字段和材料目录见附表。

## 附表A：变量与分组

| 条件 | 初始信息 | 是否经历问答 | 是否获得确认答案 | 比较用途 |
|---|---|---|---|---|
| 原始组 | 原始需求+初始材料 | 否 | 否 | 相同初始信息比较 |
| 直接增强组 | 同一初始信息得到的优化提示词 | 否 | 否 | 相同初始信息比较 |
| 计划确认组 | 同一初始信息 | 是 | 是 | 交互效果 |
| 信息量匹配对照 | 同一初始信息 | 否 | 是（相同已确认事实） | 分离信息量与交互组织方式 |

| 变量 | 类型 | 说明 |
|---|---|---|
| 条件 | 自变量 | 四组如上 |
| 任务 | 分层变量 | 二十个任务，开发/写作分支 |
| 重复 | 区组 | 每条件三次，隔离会话 |
| 模型版本、日期、参数 | 记录变量 | 每次运行记录 |
| 五维评分 | 因变量 | 需求保真、业务规则、输出可用性、阅读负担、执行边界 |
| 生成速度 | 过程指标 | 不换算费用 |

## 附表B：评分表与失败记录模板

**评分表字段**：任务编号、条件（匿名）、重复序号、维度、主错误、关联维度、评分、备注。主错误只记一次，关联维度标注但不重复计为独立失败。

**失败记录模板**：任务编号、条件、重复序号、失败阶段（生成/交互/评分）、失败描述、是否首份失败样本（是/否）、重试记录（重试不替代首份）、模型版本、日期、参数。
