# 提示词整理工具对照研究方案（合成演练稿）

## 一、研究问题与定位

本研究比较三种提示词整理条件对下游任务输出的影响：原始需求（A组）、直接增强（B组）、交互式计划确认增强（C组），并增设信息量匹配对照（D组）。研究不评价任何产品的绝对优劣，只比较条件差异。实验尚未运行，本方案不含准确率、显著性、成功案例或用户结论。

交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答，再生成最终提示词，不是静态任务分解列表。因此C组与D组的关键区别在于：D组获得相同已确认事实，但不经历本平台问答过程，用于减少“新增信息”与“交互组织方式”之间的混淆。

## 二、设计

固定二十个任务，每条件独立重复三次，两名盲评者独立评分。所有工具获取相同初始材料。A组接收原始需求与初始材料；B组接收同一初始信息得到的优化提示词；A、B两组不得接触C组后来回答的业务选择。C组记录每个问题、选项、推荐依据和答案，不只保存最终提示词；错误推荐被答案纠正后仍计入交互阶段风险。D组获得与C组相同的已确认事实，但不经过问答。

每个条件的三次重复开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本，首轮失败与工具失败均须保留。

任务材料保留真实实现、用户说明、测试示例与待办等来源标签，人工评分前不得删除不利的测试污染反例。开发任务只要求下游模型输出方案，不实际修改仓库；写作任务要求交付文本。因此跨任务不能用代码测试通过率作为统一质量指标。

## 三、主要指标

评价同时覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。质量分为结果指标，工具生成速度为过程指标。没有计费日志时，不估算真实Token成本，不把字符数换算为费用。

一个错误可能同时影响完整性与可执行性，评分表记录主错误与关联维度，避免同一问题被计为多个独立失败。

## 四、盲评与统计

评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可看任务事实，但不得查看另一名评审先前评分。

统计方法依赖分数是否有序、是否连续和是否重复测量。本方案只说明选择流程：先确认分数性质与设计结构，再选择相应方法；变量未确定前不锁定具体显著性检验。即使三个模型给出相似结论，也不构成研究完成证据，仍须人工评阅与可复核任务标准；专业领域判断尚需专家参与。

## 五、限制与待确认

本方案为合成演练稿，不代表真实单位、患者、当事人、市场或平台运行数据，也不声称已完成伦理审批或研究验收。两项关键决定尚未确定，影响执行与预注册，须在启动前明确：

1. 交互式计划确认的最大轮次与终止规则。该决定影响C组交互深度、D组信息量匹配方式及任务间可比性。
2. 两名评审的分歧处理与一致性评价方式。该决定影响评分汇总规则与结果解释边界。

上述两项不得默认补全。其余常规组织细节由执行者按本方案与附表完成。
