# 地区基线自动匹配与表单补值实现方案

> 说明：本方案为只读分析与方案交付，不含代码改动、数据库迁移或部署步骤。文中“已知事实”均来自 `materials/software/current-brief.md`；“测试示例”来自 `materials/software/tests/layout-example.txt`，仅用于排版与来源识别，不作为生产接口或业务事实。未决项单独标注。

---

## 1. 背景与现有调用关系说明

### 1.1 已知事实（来源：materials/software/current-brief.md）

- 系统为公共卫生调查录入系统，后端 Java 21 / Spring Boot 3 / MyBatis-Plus / PostgreSQL，前端 Vue 3 + TypeScript（技术栈已定，无需选型）。
- 现有两个调查模块：**基础调查**与**追踪调查**，二者**复用同一份补值服务**。
- 现有能力：
  - 已有**查询接口**返回候选摘要；
  - 已有**读取单条详情的接口**返回补值字段；
  - 现有查询接口、路由与鉴权行为需保持兼容。
- 匹配规则：使用**姓名 + 证件号**两个键，且记录必须符合**当前用户所属地区**条件；两个条件都满足才属于可补值候选。
- 字段白名单：**联系电话、职业类别、常住地址**；禁止写入其他表单字段；目录中的演示字段不属于本次范围。
- 写入前必须获取该候选的**最新详情**（在用户同意之后、写入表单之前）。
- 候选排序：**更新时间降序**，时间相同按**记录编号升序**；分页加载或重试后顺序不能随机变化。
- 空值判断：仅目标值为 **null 或空字符串**时允许补入来源值；**0、false、非空字符串**都是有效原值，必须保留。
- 取消语义：用户点击取消必须保持全部字段原值不变；取消、关闭弹窗或离开编辑页面时都不得补写字段；页面已保存的原值和当前未保存的编辑值都不能因取消动作被清空。
- 时序保护：用户在候选请求尚未结束时再次修改姓名，迟到的旧请求必须失效。
- 详情一致性：用户已同意一条候选后，若详情接口返回另一条编号，应停止写入并提示信息不一致；不能只因为部分字段相似就接受响应。
- 摘要与日志：候选摘要包含编号、地区、更新时间以及姓名掩码；确认框不得展示完整证件号；日志只记录稳定错误类型和请求标识，不记录姓名或证件号原文。
- 失败提示：网络失败提示应面向录入人员，说明本次未执行补值且原数据保留；不要附带内部堆栈、数据库错误文本或上游服务地址。
- 地区处理：地区缺失不是地区匹配成功；查询接口的返回顺序也不是授权证据；方案应把**无法核验的记录**与**确无候选**、**明确地区不符**分别说明。

### 1.2 两个模块如何复用同一补值服务

- **基础调查模块**：页面进入编辑状态时，可根据当前已有的姓名与证件号发起候选查询；用户修改这两个键后，之前的候选必须失效，不能沿用旧身份对应的详情。
- **追踪调查模块**：路由参数只负责定位当前调查记录，**不能被直接当作基线记录编号**；复用服务必须接收**明确的身份键与当前地区**，而不是暗中读取另一个页面状态。
- **共用补值服务**：接收调用方显式传入的 `{姓名, 证件号, 当前地区, 目标表单字段快照, 请求标识}`，对外暴露“查询候选”“读取详情”“执行补值”三类能力；两个模块只负责提供身份键、地区与目标表单上下文，不各自实现匹配与写入逻辑。

### 1.3 现有接口、路由与鉴权在方案中的位置与兼容要求

| 现有资产 | 在方案中的位置 | 兼容要求 |
|---|---|---|
| 查询接口（返回候选摘要） | 候选查询入口，返回编号、地区、更新时间、姓名掩码 | 保持现有路径、入参、鉴权行为不变；不因本方案新增必填参数或改变返回结构语义 |
| 详情接口（返回补值字段） | 用户同意后、写入前调用，用于获取最新详情 | 保持现有路径与鉴权；调用方需校验返回编号与已同意候选编号一致 |
| 路由 | 追踪调查路由参数仅用于定位当前调查记录 | 不将路由参数当作基线记录编号；不改变现有路由语义 |
| 鉴权 | 现有鉴权行为继续生效 | 不绕过、不弱化；补值服务不自行读取其他页面状态来替代鉴权上下文 |

### 1.4 已知事实 / 用户确认信息 / 必要假设

- **已知事实**：1.1 中列出的规则均来自 `materials/software/current-brief.md`。
- **用户确认信息**：地区信息缺失或无法核验时不得进入补值流程；可以先比较“排除候选”和“展示但禁止选择”两种安全处理，具体呈现策略仍未决；不允许直接或经用户确认后绕过地区条件补值。
- **必要假设**（仅用于方案可执行，不改变业务规则）：
  - 假设查询接口与详情接口已存在且可被两个模块调用；本方案不新增接口，仅描述调用与校验方式。
  - 假设“当前用户所属地区”可由现有鉴权上下文或调用方显式传入，补值服务不暗中读取其他页面状态。
  - 假设候选摘要中的“姓名掩码”已由现有查询接口提供；本方案不改变其生成方式。

## 2. 两个模块共用的处理步骤

以下步骤对基础调查与追踪调查**完全共用**，差异仅在调用方如何提供身份键与地区。

1. **进入编辑状态**
   - 基础调查：页面进入编辑状态时，读取当前已有的姓名与证件号。
   - 追踪调查：由路由参数定位当前调查记录，但**不将路由参数当作基线记录编号**；身份键与当前地区由调用方显式传入补值服务。
   - 若姓名或证件号为空，不发起候选查询（无候选时不弹确认框）。

2. **以姓名与证件号发起候选查询**
   - 调用现有查询接口，显式传入 `{姓名, 证件号, 当前地区, 请求标识}`。
   - 记录本次请求的请求标识，用于迟到响应失效判断。

3. **地区条件核验**
   - 对每条返回记录，核验其地区是否与当前用户所属地区一致。
   - 地区信息缺失或无法核验的记录：**不得进入补值流程**，也不得直接或经用户确认后绕过地区条件补值。
   - 明确地区不符的记录：不属于可补值候选。
   - 无法核验的记录与“确无候选”“明确地区不符”分别说明（见第 5 节）。

4. **候选排序与展示**
   - 排序：更新时间降序；时间相同按记录编号升序；分页加载或重试后顺序不能随机变化。
   - 展示：候选摘要包含编号、地区、更新时间以及姓名掩码；确认框不得展示完整证件号。
   - 无候选时不弹确认框；有匹配候选时必须询问用户，不得改为无确认自动写入。

5. **用户确认**
   - 用户选择一条候选并确认后，记录已同意候选的编号。
   - 用户取消、关闭弹窗或离开编辑页面时，不得补写字段；页面已保存的原值和当前未保存的编辑值都不能因取消动作被清空。

6. **写入前获取最新详情**
   - 在用户同意之后、写入表单之前，调用现有详情接口获取该候选的最新详情。
   - 校验详情返回的编号与已同意候选编号一致；若不一致，停止写入并提示信息不一致。

7. **字段补值**
   - 仅对白名单字段（联系电话、职业类别、常住地址）执行补值。
   - 仅当目标值为 null 或空字符串时允许补入来源值；0、false、非空字符串都是有效原值，必须保留。
   - 目标联系电话为空、来源电话有值时补入；目标电话已有值时即使来源更新也不得覆盖；目标电话为空且来源也为空时保持空值，不制造占位号码。
   - 职业类别为数值零时代表有效类别，必须使用空值比较，不能用逻辑或表达式触发替换。
   - 常住地址是单个字符串字段，不包含户籍地址、单位地址或紧急联系人地址；不扩张字段白名单。

8. **取消 / 失败回退**
   - 取消、关闭弹窗、离开编辑页面：不补写字段，保留原值与当前未保存的编辑值。
   - 查询或详情失败：保留原值，显示可理解的失败提示，不得伪装为没有匹配记录。
   - 网络失败提示面向录入人员，说明本次未执行补值且原数据保留；不附带内部堆栈、数据库错误文本或上游服务地址。
   - 日志只记录稳定错误类型和请求标识，不记录姓名或证件号原文。

## 3. 字段写入与异常分支伪代码

> 以下为方案级伪代码，用于表达业务分支，不代表实际实现语言或框架。

```text
// 常量
WHITELIST = {联系电话, 职业类别, 常住地址}
EMPTY = (v) => v == null || v === ""

// 入口：两个模块共用
function onEnterEdit(context):
    identity = context.identityKey        // 姓名 + 证件号，显式传入
    region   = context.currentRegion      // 当前用户所属地区，显式传入
    form     = context.formSnapshot       // 目标表单字段快照
    if EMPTY(identity.name) or EMPTY(identity.idNo):
        return NO_QUERY                    // 无候选时不弹确认框

    requestId = newRequestId()
    context.latestRequestId = requestId
    result = queryCandidates(identity, region, requestId)

    // 迟到响应失效
    if requestId != context.latestRequestId:
        return STALE_RESPONSE_DISCARDED

    if result.failed:
        showUserMessage("本次未执行补值，原数据保留")
        logStableError(result.errorType, requestId)   // 不记录姓名/证件号原文
        return QUERY_FAILED

    candidates = result.items
    // 地区核验
    verifiable = []
    unverifiable = []
    for c in candidates:
        if c.region == null or c.region == "":
            unverifiable.push(c)          // 不得进入补值流程
        else if c.region != region:
            // 明确地区不符，不属于可补值候选
            continue
        else:
            verifiable.push(c)

    if verifiable.isEmpty():
        if unverifiable.isEmpty():
            return NO_CANDIDATE           // 确无候选，不弹确认框
        else:
            // 存在无法核验记录：呈现策略未决，不得绕过地区条件补值
            return UNVERIFIABLE_PRESENTATION_PENDING

    // 排序：更新时间降序，时间相同按编号升序
    sort verifiable by (updatedAt DESC, recordId ASC)

    // 展示摘要：编号、地区、更新时间、姓名掩码；不展示完整证件号
    selected = showConfirmDialog(verifiable)
    if selected == null:
        return USER_CANCELLED             // 不补写，保留原值与编辑值

    // 写入前获取最新详情
    detail = getDetail(selected.recordId, requestId)
    if requestId != context.latestRequestId:
        return STALE_RESPONSE_DISCARDED
    if detail.failed:
        showUserMessage("本次未执行补值，原数据保留")
        logStableError(detail.errorType, requestId)
        return DETAIL_FAILED

    // 详情编号一致性
    if detail.recordId != selected.recordId:
        showUserMessage("信息不一致，已停止写入")
        logStableError("DETAIL_ID_MISMATCH", requestId)
        return DETAIL_MISMATCH

    // 字段补值：仅白名单，仅 null 或空字符串可补入
    for field in WHITELIST:
        target = form[field]
        source = detail[field]
        if EMPTY(target):
            if not EMPTY(source):
                form[field] = source
            else:
                // 目标为空且来源也为空：保持空值，不制造占位
                form[field] = target
        else:
            // 0、false、非空字符串均为有效原值，保留
            form[field] = target

    return APPLIED

// 用户修改姓名或证件号
function onIdentityKeyChanged(context):
    context.latestRequestId = newRequestId()   // 使旧请求失效
    context.candidates = null                  // 旧候选失效
    // 不沿用旧身份对应的详情

// 取消 / 关闭弹窗 / 离开编辑页面
function onCancelOrLeave(context):
    // 不补写字段
    // 保留页面已保存的原值与当前未保存的编辑值
    return NO_WRITE
```
