# 地区基线自动匹配与表单补值——实现方案（只读分析交付）

> 说明：本方案仅做只读分析与方案交付，不运行命令、不修改项目、不部署、不产生代码修改和数据库迁移。文中“已知事实”均来自 `materials/software/current-brief.md`；“测试示例”来自 `materials/software/tests/layout-example.txt`，仅用于验证分支，不作为生产接口与业务事实。未决条件单列，不默认补全。

---

## 1. 背景与现有调用关系

### 1.1 两个模块与共用补值服务

- 现有两个调查模块：**基础调查**、**追踪调查**。
- 二者**复用同一份补值服务**（同一套候选查询、详情读取、字段写入判定逻辑），本次方案必须同时覆盖两个模块。
- 复用服务**必须接收明确的身份键（姓名、证件号）与当前地区**作为入参，**不得暗中读取另一个页面状态**。
- **追踪调查的路由参数只负责定位当前调查记录，不能被直接当作基线记录编号**；基线记录编号必须由服务入参显式给出。

### 1.2 现有接口与兼容边界

| 现有能力 | 行为 | 兼容边界（不得破坏） |
|---|---|---|
| 查询接口 | 返回候选摘要（编号、地区、更新时间、姓名掩码） | 保持现有查询接口签名与返回结构；不新增破坏性字段变更 |
| 详情接口 | 读取单条候选详情，返回补值字段 | 保持现有详情接口；在用户同意后、写入表单前调用获取最新详情 |
| 路由 | 基础调查进入编辑状态；追踪调查路由参数定位当前调查记录 | 路由行为不变；追踪调查路由参数不得当作基线记录编号 |
| 鉴权 | 现有鉴权行为 | 不得削弱或删除；地区条件校验基于当前用户所属地区 |

### 1.3 匹配与候选定义（已知事实）

- 匹配使用**姓名与证件号两个键**，且记录必须**符合当前用户所属地区条件**；**两个条件都满足**才属于可补值候选。
- 候选排序：**更新时间降序**，时间相同按**记录编号升序**；分页加载或重试后顺序必须稳定。
- 确认框只展示候选摘要（编号、地区、更新时间、姓名掩码），**不得展示完整证件号**。
- 日志只记录**稳定错误类型和请求标识**，不记录姓名或证件号原文。

### 1.4 字段白名单（已知事实）

- 白名单只有：**联系电话、职业类别、常住地址**。
- 禁止写入其他表单字段；目录中的演示字段不属于本次范围。
- 常住地址是**单个字符串字段**，不包含户籍地址、单位地址或紧急联系人地址；附件展示的其他地址种类只能作为背景，不能扩张字段白名单。
- 只有目标值为 **null 或空字符串**时允许补入来源值；**0、false 和非空字符串都是有效原值，必须保留**。
- 职业类别为数值零时是有效类别，必须使用**空值比较**，不能用 JavaScript 假值判断或简单逻辑或表达式。

## 2. 两个模块共用的处理步骤（有序流程）

以下步骤对基础调查与追踪调查**完全共用**，差异仅在于“当前调查记录”的来源（基础调查来自编辑状态上下文，追踪调查来自路由参数定位的记录），但**身份键与当前地区均由调用方显式传入服务**。

1. **进入编辑状态**
   - 基础调查：页面进入编辑状态时，可根据当前已有的姓名与证件号发起候选查询。
   - 追踪调查：路由参数仅定位当前调查记录；不得把路由参数当作基线记录编号。
   - 服务入参：`{ name, idNumber, currentRegion, currentRecordId }`，其中 `currentRecordId` 为当前调查记录标识，非基线记录编号。

2. **发起候选查询**
   - 以姓名与证件号两个键发起查询，并携带当前用户所属地区条件。
   - 记录本次请求标识（requestId），用于迟到请求失效与日志。

3. **地区条件校验**
   - 候选必须同时满足：姓名匹配、证件号匹配、记录符合当前用户所属地区条件。
   - 地区缺失**不等于**地区匹配成功；查询接口返回顺序**不是**授权证据。
   - 三种情况分别说明：
     - **无法核验**：候选地区信息缺失或无法核验当前地区条件 → 按未决条件处理（见第 6 节），不得默认视为匹配成功。
     - **确无候选**：无任何满足姓名+证件号的记录 → 不弹确认框。
     - **明确地区不符**：存在姓名+证件号匹配但地区明确不符 → 不纳入候选，不弹确认框。

4. **候选排序**
   - 按更新时间降序；时间相同按记录编号升序。
   - 分页加载或重试后顺序必须稳定，不得随机变化。

5. **用户确认**
   - 无候选时不弹确认框。
   - 有匹配候选时**必须询问用户**，不得改为无确认自动写入。
   - 确认框只展示候选摘要：编号、地区、更新时间、姓名掩码；不得展示完整证件号。

6. **写入前获取最新详情**
   - 用户同意一条候选后，在写入表单前调用详情接口获取该候选的最新详情。
   - 校验详情返回的编号与用户同意的候选编号是否一致。

7. **最终写入或取消**
   - 编号一致：按字段白名单与空值判定写入。
   - 编号不一致：停止写入并提示信息不一致。
   - 用户取消、关闭弹窗或离开编辑页面：不得补写字段；已保存原值与当前未保存的编辑值都不能因取消动作被清空。

8. **时序保护**
   - 用户修改姓名或证件号后，之前的候选必须失效。
   - 候选请求尚未结束时再次修改姓名，迟到的旧请求必须失效（按 requestId 丢弃）。

## 3. 字段写入与异常分支伪代码

> 伪代码为方案级描述，不指定具体语言实现；关键判定使用显式空值比较。

### 3.1 空值判定与字段写入

```text
// 空值判定：仅 null 或空字符串视为“可补入”
function isBlank(v):
    return v == null OR v == ""

// 字段白名单
ALLOWED_FIELDS = ["contactPhone", "occupationCategory", "permanentAddress"]

// 单字段写入判定
function shouldFill(targetValue, sourceValue):
    if not isBlank(targetValue):
        return false          // 0、false、非空字符串均保留
    if isBlank(sourceValue):
        return false          // 来源也为空则保持空值，不制造占位
    return true

// 应用补值
function applyFill(form, detail):
    for field in ALLOWED_FIELDS:
        if shouldFill(form[field], detail[field]):
            form[field] = detail[field]
    // 白名单外字段一律不写
```

### 3.2 主流程伪代码

```text
function onEnterEdit(context):
    identity = { name: context.name, idNumber: context.idNumber }
    region   = context.currentRegion
    recordId = context.currentRecordId   // 追踪调查：来自路由定位的记录，非基线编号
    requestId = newRequestId()
    activeRequestId = requestId

    result = queryCandidates(identity, region, requestId)

    // 迟到请求失效
    if requestId != activeRequestId:
        return   // 丢弃旧响应

    if result.failed:
        showUserMessage("本次未执行补值，原数据已保留")
        logStableError(result.errorType, requestId)
        return

    candidates = result.candidates

    // 地区无法核验的候选：按未决条件处理，不默认视为匹配成功
    verifiable = filterVerifiable(candidates)
    unverifiable = candidates - verifiable

    if verifiable.isEmpty():
        if unverifiable.notEmpty():
            // 未决条件：见第 6 节，暂不参与补值
            handleUnverifiable(unverifiable)
        else:
            // 确无候选 或 明确地区不符：不弹确认框
            return

    sorted = sortCandidates(verifiable)   // 更新时间降序，时间相同按编号升序

    // 有匹配候选：必须询问用户
    chosen = showConfirmDialog(sorted)    // 仅展示编号、地区、更新时间、姓名掩码
    if chosen == null:
        return   // 用户取消：不写入，原值与未保存编辑值均保留

    // 写入前获取最新详情
    detail = fetchDetail(chosen.id, requestId)
    if detail.failed:
        showUserMessage("本次未执行补值，原数据已保留")
        logStableError(detail.errorType, requestId)
        return

    // 详情编号一致性校验
    if detail.id != chosen.id:
        showUserMessage("信息不一致，已停止写入")
        logStableError("DETAIL_ID_MISMATCH", requestId)
        return

    applyFill(form, detail)
```

### 3.3 异常与边界分支

```text
// 用户修改姓名或证件号
function onIdentityChanged(newName, newIdNumber):
    activeRequestId = null      // 旧候选失效
    // 重新进入编辑状态时再发起新查询

// 候选请求未结束时再次修改姓名
function onNameChangedDuringRequest(newName):
    activeRequestId = null      // 迟到旧请求必须失效

// 用户取消 / 关闭弹窗 / 离开编辑页面
function onCancelOrCloseOrLeave():
    // 不补写任何字段
    // 已保存原值保持不变
    // 当前未保存的编辑值不被清空
    return

// 查询或详情失败
function onQueryOrDetailFailure(errorType, requestId):
    showUserMessage("本次未执行补值，原数据已保留")
    logStableError(errorType, requestId)
    // 不得伪装为“没有匹配记录”
    // 不附带内部堆栈、数据库错误文本或上游服务地址

// 日志
function logStableError(errorType, requestId):
    // 只记录稳定错误类型和请求标识
    // 不记录姓名或证件号原文
```

| 情况 | 判定 | 处理 |
|---|---|---|
| 无法核验 | 候选地区信息缺失或无法核验当前地区条件 | 按未决条件处理，不默认视为匹配成功（见第 6 节） |

## 6. 未决条件（需人工确认，不得默认补全）

**候选地区信息缺失、无法核验当前地区条件时，应如何处理这条候选？**

当前尚未决定，不得默认补全。需明确：

1. 该候选是**直接排除**、**标记为待人工核验后暂不参与补值**，还是**其他处理方式**；
2. 该处理是否需要在**界面或日志**中体现。

此决定会影响候选筛选逻辑与异常分支伪代码（第 3.2 节 `handleUnverifiable` 与第 3.4 节“无法核验”分支）。在确认前，方案不假定答案，不将地区缺失视为匹配成功。
