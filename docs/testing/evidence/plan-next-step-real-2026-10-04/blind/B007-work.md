# 地区基线自动匹配与表单补值——实现方案（只读分析交付）

## 0. 事实、确认与待确认项

**已知事实（来源：materials/software/current-brief.md）**
- 匹配键为姓名 + 证件号，且记录必须符合当前用户所属地区；两者同时满足才是可补值候选。
- 字段白名单：联系电话、职业类别、常住地址；其他表单字段禁止写入。
- 已有查询接口返回候选摘要；详情接口返回补值字段；用户同意后、写入前必须重新获取该候选最新详情。
- 候选排序：更新时间降序，时间相同按记录编号升序。
- 仅当目标值为 null 或空字符串时允许补入；0、false、非空字符串为有效原值。
- 取消必须保持全部字段原值不变。
- 基础调查：进入编辑状态可按当前姓名+证件号发起查询；修改这两个键后旧候选失效。
- 追踪调查：路由参数只定位当前调查记录，不得当作基线记录编号；复用服务必须接收明确身份键与当前地区。
- 确认框仅展示编号、地区、更新时间、姓名掩码；不得展示完整证件号。
- 日志只记录稳定错误类型与请求标识，不记录姓名或证件号原文。
- 详情返回编号与已同意候选编号不一致时停止写入并提示。
- 迟到请求（请求未结束前用户再次修改姓名）必须失效。
- 地区缺失不等于匹配成功；查询接口返回顺序不是授权证据。
- 取消、关闭弹窗、离开编辑页面均不得写入；已保存原值与未保存编辑值不得被清空。
- 网络失败提示面向录入人员，说明本次未执行补值且原数据保留；不暴露内部堆栈、数据库错误文本、上游服务地址。

**用户确认信息**
- 地区信息缺失或无法核验时，该候选不得进入补值流程；不得直接或经确认后绕过地区条件补值。
- 具体呈现策略（比较排除候选 vs 展示但禁止选择）尚未决定，属待确认项。

**待确认项（不得默认补全）**
- 地区无法核验候选的呈现策略：直接排除，还是展示但禁止选择；是否需要在界面或日志中体现。该决定影响候选筛选逻辑与异常分支伪代码，需人工确认后再落地。

**测试示例（仅用于验证分支，非生产事实）**
- materials/software/tests/layout-example.txt 中的 CSV、Python、收入 100 万元、准确率 99% 等，仅用于排版与来源识别，不代表已实现或业务事实。

**必要假设（明确标注，非事实）**
- 假设现有查询接口与详情接口的路径、请求/响应字段名保持不变；本方案只描述调用语义与兼容边界，不新增或修改接口契约。
- 假设鉴权沿用现有机制（当前用户身份与所属地区由既有鉴权上下文提供），本方案不改变鉴权行为。

## 1. 背景与现有调用关系

### 1.1 两个模块与共用补值服务

- **基础调查模块**：进入编辑状态时，以当前已有的姓名与证件号发起候选查询；用户修改姓名或证件号后，旧候选失效。
- **追踪调查模块**：路由参数只负责定位当前调查记录，不得直接当作基线记录编号；调用补值服务时必须显式传入身份键（姓名、证件号）与当前地区。
- **共用补值服务**：两个模块复用同一份服务。服务接口接收明确的身份键与当前地区，不暗中读取另一个页面状态；服务内部完成候选查询、地区条件校验、排序、详情获取与写入判定。

### 1.2 现有接口与兼容边界

| 现有能力 | 兼容边界 |
|---|---|
| 候选查询接口（返回候选摘要） | 保持路径、入参语义、返回结构不变；摘要含编号、地区、更新时间、姓名掩码；不返回完整证件号。 |
| 详情接口（返回补值字段） | 保持路径与返回结构不变；用户同意后、写入前调用；返回编号必须与已同意候选编号一致。 |
| 路由 | 基础调查与追踪调查现有路由不变；追踪调查路由参数不得被解释为基线记录编号。 |
| 鉴权 | 沿用现有鉴权行为；当前用户所属地区由既有鉴权上下文提供，不新增或削弱鉴权。 |

**兼容原则**：不新增破坏性变更，不删除或削弱现有功能；补值服务只作为既有接口之上的编排层。

## 2. 两个模块共用的处理步骤

1. **进入编辑状态**：基础调查以当前姓名+证件号发起候选查询；追踪调查以显式传入的身份键+当前地区发起查询。路由参数仅用于定位当前调查记录。
2. **发起候选查询**：调用现有查询接口，携带姓名、证件号、当前地区；记录本次请求标识（用于迟到请求判定）。
3. **地区条件校验**：对每条候选校验地区是否符合当前用户所属地区。地区缺失或无法核验的候选，按待确认项处理（不得进入补值流程）。
4. **候选排序**：按更新时间降序，时间相同按记录编号升序；分页加载或重试后顺序稳定。
5. **无候选处理**：无匹配候选时不弹确认框，仅提示无匹配记录。
6. **有候选处理**：必须询问用户；确认框仅展示编号、地区、更新时间、姓名掩码，不展示完整证件号。
7. **用户确认**：用户选择一条候选并同意。
8. **写入前获取最新详情**：调用详情接口获取该候选最新详情；若返回编号与已同意候选编号不一致，停止写入并提示信息不一致。
9. **字段写入判定**：仅对白名单字段（联系电话、职业类别、常住地址），仅当目标值为 null 或空字符串时补入来源值；0、false、非空字符串保留。
10. **写入或取消**：写入成功后保留原值与编辑值语义；取消、关闭弹窗、离开编辑页面均不写入，且不清空已保存原值与未保存编辑值。

**时序保护**：候选请求未结束时用户再次修改姓名或证件号，迟到的旧请求必须失效（通过请求标识比对，不指定具体浏览器库或状态管理实现）。

## 3. 字段写入与异常分支伪代码

> 说明：以下为方案级伪代码，不指定具体语言实现；空值判定统一使用显式 null/空字符串比较，不使用 JavaScript 假值判断或简单逻辑或表达式。

```
// 常量
WHITELIST = ["联系电话", "职业类别", "常住地址"]

// 空值判定：仅 null 或空字符串视为可补入
function isBlank(v):
    return v == null OR v == ""

// 字段写入判定
function shouldFill(targetValue, sourceValue):
    if not isBlank(targetValue):
        return false          // 0、false、非空字符串均保留
    if isBlank(sourceValue):
        return false          // 来源也为空，保持空值，不制造占位
    return true

// 主流程
function runFill(module, identityKeys, currentRegion, requestId):
    // 1. 发起候选查询
    candidates = queryCandidates(identityKeys, currentRegion, requestId)

    // 2. 迟到请求失效
    if requestId != latestRequestId:
        return ABORT_LATE_REQUEST

    // 3. 地区条件校验
    verified = []
    unverifiable = []
    for c in candidates:
        if c.region == null OR cannotVerify(c.region, currentRegion):
            unverifiable.append(c)      // 待确认项：排除或展示但禁止选择
        else if c.region == currentRegion:
            verified.append(c)
        else:
            // 明确地区不符，排除
            continue

    // 4. 排序：更新时间降序，时间相同按编号升序
    sort(verified, by updateTime desc, then recordId asc)

    // 5. 无候选
    if verified.isEmpty():
        if unverifiable.isEmpty():
            showNoMatch()               // 确无候选
        else:
            showUnverifiablePending()   // 地区无法核验，按待确认项处理
        return NO_WRITE

    // 6. 有候选：必须询问用户
    chosen = showConfirmDialog(verified)   // 仅展示编号、地区、更新时间、姓名掩码
    if chosen == null:
        return NO_WRITE                    // 取消/关闭弹窗

    // 7. 写入前获取最新详情
    detail = fetchDetail(chosen.recordId, requestId)
    if detail == null:
        showUserFriendlyFailure("本次未执行补值，原数据保留")
        return NO_WRITE

    // 8. 详情编号一致性校验
    if detail.recordId != chosen.recordId:
        showInconsistent()
        return NO_WRITE

    // 9. 字段写入
    for field in WHITELIST:
        if shouldFill(form[field], detail[field]):
            form[field] = detail[field]

    return WRITE_DONE

// 取消/关闭/离开
function onCancelOrCloseOrLeave():
    // 不写入任何字段；不清空已保存原值与未保存编辑值
    return NO_WRITE

// 查询或详情失败
function onQueryOrDetailFailure():
    showUserFriendlyFailure("本次未执行补值，原数据保留")
    // 不伪装为无匹配记录；不暴露内部堆栈、数据库错误文本、上游服务地址
    return NO_WRITE
```

**日志规范**：仅记录稳定错误类型与请求标识，不记录姓名或证件号原文。
