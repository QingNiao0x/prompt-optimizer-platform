# 提示词整理工具对照研究方案（尚未执行）

## 一、研究问题

本研究比较三种提示词整理条件对下游任务输出的影响：**原始需求**（直接给出原始需求与初始材料）、**直接增强**（对同一初始信息生成优化提示词后交付）、**交互式计划确认增强**（系统先提问，实验操作者按预先制定答案卡作答，再生成最终提示词）。研究不评价任何产品的绝对优劣，只比较条件差异。

由于计划确认组会额外获得操作者回答的业务选择，其信息量高于前两组。为区分“新增信息”与“交互组织方式”的作用，另设**信息量匹配对照**：获得与计划确认组相同的已确认事实，但不经历问答过程。原始组与直接增强组不得接触计划确认组后来回答的业务选择。

## 二、实验设计

固定二十个任务，每条件独立重复三次，共 4 条件 × 20 任务 × 3 次 = 240 个下游输出单元。所有条件获取相同初始材料。三次重复开启隔离会话，随机化执行顺序，记录模型版本、日期与参数。失败后的重试不能替代第一份失败样本，首轮失败样本必须保留。

任务材料保留四类来源标签：真实实现、用户说明、测试示例、待办。人工评分前不得删除不利的测试污染反例。开发任务要求下游模型只输出方案、不修改仓库；写作任务交付文本。因此跨任务不得用代码测试通过率作为统一质量指标。

## 三、主要指标

评价覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。质量分为结果指标；工具生成速度为过程指标，单独记录，不并入质量分。无计费日志时不估算真实 Token 成本，不把字符数换算为实际费用。

## 四、盲评与评分

两名盲评者独立评分。评审看到匿名化下游输出与等量任务信息，不展示产品名称、标志和生成来源；可看任务事实，不得查看另一名评审先前评分。评分表记录主错误与关联维度，避免同一问题被多次计为不同独立失败。

## 五、统计方法选择流程

统计方法依分数是否有序、是否连续、是否重复测量决定，不在变量尚未确定时锁定具体显著性检验。选择流程与候选方法写入附表，待预注册确认后执行。

## 六、限制

实验尚未运行，无准确率、显著性、成功案例数量或用户结论。三个模型给出相似结论不构成研究完成证据。专业领域判断尚需专家参与。交互式计划确认的最大轮次与终止规则、两名评审的分歧处理与一致性评价方式均未决定，须在执行前预注册，详见附表四。

# 附表一：变量与分组

| 条件 | 初始信息 | 额外信息 | 是否经历问答 | 是否可见计划确认组答案 | 重复次数 |
|---|---|---|---|---|---|
| 原始组 | 原始需求 + 初始材料 | 无 | 否 | 否 | 3 |
| 直接增强组 | 同一初始信息 | 优化提示词 | 否 | 否 | 3 |
| 计划确认组 | 同一初始信息 | 操作者答案卡回答 | 是 | — | 3 |
| 信息量匹配对照 | 同一初始信息 | 相同已确认事实 | 否 | 否 | 3 |

| 变量 | 定义 | 类型 | 值域/单位 | 状态 |
|---|---|---|---|---|
| 条件 | 四种提示词整理方式 | 分类 | 原始/直接增强/计划确认/信息量匹配 | 已确定 |
| 任务 | 二十个下游任务 | 分类 | T01–T20 | 已确定 |
| 重复 | 每条件独立重复次数 | 计数 | 3 | 已确定 |
| 模型版本 | 下游模型标识 | 文本 | 待记录 | 执行时填写 |
| 日期 | 执行日期 | 日期 | — | 执行时填写 |
| 参数 | 模型调用参数 | 文本 | 待记录 | 执行时填写 |
| 质量分 | 五维度评分汇总 | 待定 | 待定 | 待预注册 |
| 生成速度 | 过程指标 | 连续 | 秒/任务 | 已确定 |
| Token 成本 | 真实费用 | — | — | 无计费日志，不估算 |

**信息量匹配对照设置说明**：该组获得与计划确认组相同的已确认事实，但不经历本平台问答过程。用于减少“新增信息”与“交互组织方式”之间的混淆。若两组信息量不等，则不能将差异归因于交互方式。

| 业务规则 | 是否遵守业务约束 | 待定 | 待预注册 |
