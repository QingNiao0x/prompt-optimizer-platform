# 地区基线自动匹配与表单补值实现方案

## 一、背景与现有调用关系

### 1.1 业务背景
基础调查与追踪调查两个模块在编辑状态下，均需要根据当前表单中的**姓名 + 证件号**两个身份键，结合**当前用户所属地区**条件，从基线库中匹配候选记录，并在用户确认后，将白名单字段补入当前表单。

### 1.2 现有调用关系（保持兼容，不新增/不修改路由与鉴权）
- **候选查询接口**（已有）：入参为身份键（姓名、证件号）与当前地区；返回候选摘要列表，摘要字段包括：记录编号、地区、更新时间、姓名掩码。**不返回完整证件号**。
- **单条详情接口**（已有）：入参为候选记录编号；返回可补值字段（联系电话、职业类别、常住地址）。**在用户同意后、写入表单前调用**，以获取最新详情。
- **补值服务**（共用）：基础调查与追踪调查复用同一服务。服务接收**显式的身份键与当前地区**，不读取任何页面状态或路由参数。
- **鉴权**：沿用现有鉴权行为，不新增权限点，不改变接口可见性。

### 1.3 关键前提（必须体现在实现中，不能只留在页面提示）
1. 候选必须同时满足：**姓名匹配 + 证件号匹配 + 地区符合当前用户所属地区**。三者缺一不可。
2. 字段白名单仅：**联系电话、职业类别、常住地址**。其他字段（含目录演示字段、户籍地址、单位地址、紧急联系人地址等）一律禁止写入。
3. 只有目标值为 `null` 或空字符串时允许补入；`0`、`false`、非空字符串均为有效原值，必须保留。
4. 候选排序：**更新时间降序，时间相同按记录编号升序**，分页/重试后顺序稳定。
5. 用户取消、关闭弹窗、离开编辑页面：**不得补写任何字段**，且不得清空已保存原值与当前未保存编辑值。
6. 查询或详情失败：保留原值，显示面向录入人员的可理解提示；**不得伪装为“没有匹配记录”**。
7. 无候选：不弹确认框。有候选：必须询问用户，不得自动写入。
8. 地区信息缺失或无法核验：**不得进入补值流程**，不得直接或经确认后绕过地区条件补值（详见第五节待确认项）。

## 二、两个模块共用的处理步骤

以下步骤对基础调查与追踪调查完全一致，仅“触发入口”不同（基础调查在编辑状态根据当前姓名/证件号触发；追踪调查由页面显式传入身份键与当前地区，路由参数仅用于定位当前调查记录，**不得**当作基线记录编号）。

1. **采集身份键与地区**
   - 从当前表单读取姓名、证件号；从当前用户会话读取所属地区。
   - 追踪调查：身份键与地区由调用方显式传入，服务不读取路由参数作为基线编号。

2. **发起候选查询**
   - 调用候选查询接口，携带身份键与当前地区。
   - 记录本次请求标识（用于日志与迟到响应判定）。

3. **时序保护（迟到请求失效）**
   - 每次发起查询时生成新的请求序号/令牌。
   - 用户修改姓名或证件号后，旧请求的响应到达时直接丢弃，不更新候选列表、不弹确认框。

4. **候选结果分类处理**
   - **查询失败**：保留原值，提示“本次未执行补值，原数据已保留”，不显示为“无匹配”。
   - **无候选**：不弹确认框，静默结束（可给轻提示，但不进入确认流程）。
   - **有候选**：按“更新时间降序、编号升序”稳定排序后展示确认框。
   - **地区缺失/无法核验的候选**：不进入补值流程（见第五节）。

5. **确认框展示**
   - 展示候选摘要：编号、地区、更新时间、姓名掩码。
   - **不得展示完整证件号**。
   - 用户可选择某条候选或取消。

6. **用户同意后获取最新详情**
   - 调用单条详情接口，入参为所选候选编号。
   - 校验返回的编号与所选编号一致；不一致则停止写入并提示“信息不一致”。
   - 详情失败：保留原值，提示“本次未执行补值，原数据已保留”。

7. **字段写入（白名单 + 空值判断）**
   - 仅处理联系电话、职业类别、常住地址。
   - 对每个字段：仅当目标值为 `null` 或空字符串时，才写入来源值。
   - `0`、`false`、非空字符串一律保留原值。
   - 来源值为空时保持目标为空，不制造占位值。

8. **取消/关闭/离开**
   - 任何取消动作：不写入任何字段，不清空已保存原值与当前未保存编辑值。

9. **日志**
   - 仅记录稳定错误类型与请求标识。
   - **不记录姓名、证件号原文**。

## 三、字段写入与异常分支伪代码

> 说明：以下为方案级伪代码，用于表达分支与判定逻辑，不指定具体框架、状态管理库或浏览器 API。

### 3.1 候选查询与确认主流程

```
function startCandidateMatch(identityKeys, currentRegion, requestToken):
    // identityKeys = { name, idNumber }
    // currentRegion 来自当前用户会话，不由路由参数推导
    requestToken = newToken()
    activeToken = requestToken

    result = callCandidateQuery(identityKeys, currentRegion)

    if result is FAILED:
        showUserMessage("本次未执行补值，原数据已保留")
        log(stableErrorType = QUERY_FAILED, requestId = requestToken)
        return

    if activeToken != requestToken:
        // 迟到响应，用户已修改身份键
        return

    candidates = result.candidates

    // 地区缺失/无法核验的候选：不进入补值流程
    usableCandidates = filter(candidates, c => c.region is present and c.region matches currentRegion)
    unverifiableCandidates = filter(candidates, c => c.region is missing or cannot be verified)

    if usableCandidates is empty:
        if unverifiableCandidates is not empty:
            // 与“确无候选”“明确地区不符”区分说明
            showUserMessage("存在无法核验地区的记录，未执行补值")
        // 无候选：不弹确认框
        return

    sortedCandidates = sort(usableCandidates, by updateTime desc, then recordId asc)
    showConfirmDialog(sortedCandidates)   // 仅展示编号、地区、更新时间、姓名掩码
```

### 3.2 用户确认后获取详情并写入

```
function onUserConfirm(selectedCandidateId, requestToken):
    if activeToken != requestToken:
        return

    detail = callCandidateDetail(selectedCandidateId)

    if detail is FAILED:
        showUserMessage("本次未执行补值，原数据已保留")
        log(stableErrorType = DETAIL_FAILED, requestId = requestToken)
        return

    if detail.recordId != selectedCandidateId:
        showUserMessage("信息不一致，已停止补值")
        log(stableErrorType = ID_MISMATCH, requestId = requestToken)
        return

    applyWhitelistFields(detail)
```

### 3.3 白名单字段写入（空值判断，禁止逻辑或）

```
function applyWhitelistFields(detail):
    // 仅三个字段，禁止扩展
    applyField("联系电话", detail.phone)
    applyField("职业类别", detail.occupationCategory)
    applyField("常住地址", detail.residentAddress)

function applyField(fieldName, sourceValue):
    targetValue = form.get(fieldName)

    // 仅 null 或空字符串允许补入
    if targetValue is null or targetValue == "":
        if sourceValue is null or sourceValue == "":
            // 来源也为空：保持空值，不制造占位
            return
        form.set(fieldName, sourceValue)
    else:
        // 0、false、非空字符串均为有效原值，保留
        return
```

### 3.4 取消/关闭/离开

```
function onCancelOrCloseOrLeave():
    // 不写入任何字段
    // 不清空已保存原值
    // 不清空当前未保存编辑值
    return
```

### 3.5 身份键变更时的时序保护

```
function onIdentityKeyChanged(newName, newIdNumber):
    // 使旧请求失效
    activeToken = null
    // 不沿用旧身份对应的候选与详情
    clearCandidateState()
```

## 五、待确认项（仅保留真正影响任务目标且目前缺失的业务决定）

**待确认项 1：地区信息缺失或无法核验的候选，在界面上的呈现策略**
- 已确定：不得进入补值流程；不得直接或经确认后绕过地区条件补值。
- 未确定：是“比较后排除候选（不展示）”还是“展示但禁止选择”。两种均为安全处理，具体呈现策略尚未决定。
- 影响：确认框的展示内容与用户提示文案；不影响写入逻辑与安全边界。

> 除上述一项外，其余常规细节（双键匹配、地区条件、白名单、空值判断、排序、取消行为、失败提示、时序保护、日志脱敏）均可由给定资料核查并已在本方案中明确，不再列为待确认项。
