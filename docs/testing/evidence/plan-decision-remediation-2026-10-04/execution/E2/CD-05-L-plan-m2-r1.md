# 提示词整理工具对照研究方案

## 1. 研究方案主文

**研究问题**：比较原始需求、直接增强、交互式计划确认增强三种条件对下游任务输出的影响差异。核心关注：计划确认组额外获得确认答案后，其输出变化究竟来自新增信息本身，还是来自交互组织方式。

**实验设计**：采用四组对照。原始组接收原始需求与初始材料；直接增强组接收由同一初始信息生成的优化提示词；计划确认组在生成最终提示词前，由系统按预设问题提问，实验操作者依据预先制定的答案卡作答，系统据此生成最终提示词；信息量匹配对照组不经历问答过程，但获得与计划确认组相同的已确认事实，用于分离“新增信息量”与“交互组织方式”的效应。原始组与直接增强组均不得接触计划确认组后来回答的业务选择。

二十个任务覆盖开发与写作两类。开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本。每个条件独立重复三次，共 240 次下游生成。每次重复开启隔离会话，随机化任务顺序，记录模型版本、日期和参数。失败后的重试不替代第一份失败样本；工具失败与首轮失败均保留。

**主要指标**：结果指标为盲评质量分，覆盖需求保真、业务规则、输出可用性、阅读负担、执行边界五个维度。过程指标为工具生成速度，仅作辅助记录。无计费日志时不估算 Token 成本，不以字符数换算费用。跨任务不采用代码测试通过率作为统一质量指标。

**盲评与评分**：两名盲评者独立评分。评审仅见匿名化下游输出与等量任务信息，不展示产品名称、标志和生成来源；可查看任务事实，但不得查看另一名评审先前评分。评分表记录主错误与关联维度，同一错误不重复计为独立失败。

**统计方法**：候选评价统计方法依赖分数是否有序、是否连续、是否重复测量。预注册前仅说明选择流程：先检验分数分布性质，再据此选择描述统计与推断方法；在变量尚未确定时不锁定具体显著性检验。

**限制**：实验尚未运行，无准确率、显著性、成功案例数量或用户结论。任务材料为合成资料，不代表真实单位、患者、当事人、市场或平台运行数据。专业领域判断尚需专家参与。计划确认组的最大轮次与终止规则、两名盲评者分歧处理与一致性评价方式尚未确定，列入预注册待确认清单。

## 2. 变量与分组附表

| 条件 | 接收信息 | 是否经历问答过程 | 重复次数 | 记录字段 |
|---|---|---|---|---|
| 原始组 | 原始需求与初始材料 | 否 | 每任务 3 次 | 会话编号、任务编号、模型版本、日期、参数、下游输出、失败类型（工具失败/首轮失败/无）、重试标记 |
| 直接增强组 | 由同一初始信息生成的优化提示词 | 否 | 每任务 3 次 | 同上，另记录优化提示词生成依据 |
| 计划确认组 | 初始材料＋问答确认后生成的最终提示词 | 是 | 每任务 3 次 | 上述字段，另记录每个问题、选项、推荐依据、答案、错误推荐被纠正情况、问答轮次 |
| 信息量匹配对照组 | 初始材料＋与计划确认组相同的已确认事实（不经问答） | 否 | 每任务 3 次 | 上述字段，另记录已确认事实清单及与计划确认组的对应关系 |

任务材料须保留真实实现、用户说明、测试示例、待办四种来源标签；不得在人工评分前删除不利的测试污染反例。资料引用应能让接收任务者找到对应依据；测试示例、旧版草稿与正式说明分开标注。

## 3. 评分表及失败记录模板

| 维度 | 定义 | 评分范围 | 得分 |
|---|---|---|---|
| 需求保真 | 输出是否完整保留原始需求中的硬约束、否定规则、边界条件 | 1–5，未定序时按类别记录 | |
| 业务规则 | 是否遵守适用对象与条件相符的业务规则，未跨模块/年份/人群迁移 | 1–5 | |
| 输出可用性 | 输出是否可直接用于后续任务，格式与内容完整 | 1–5 | |
