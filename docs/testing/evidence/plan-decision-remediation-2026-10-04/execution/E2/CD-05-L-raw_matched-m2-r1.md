# 提示词整理工具对照研究方案

## 1. 研究问题

本研究考察提示词整理工具在“原始需求—最终提示词”转换环节对下游任务输出的影响。核心问题为：在相同初始材料下，三种提示词整理条件（原始需求、直接增强、交互式计划确认增强）是否导致下游输出质量出现可观察差异；若存在差异，该差异在多大程度上可归因于新增业务信息本身，而非交互式问答这一组织形式。

研究不评价任何具体产品的绝对优劣，不推断市场排名，不将结果外推至未纳入的任务类型。

## 2. 实验设计

### 2.1 任务与材料

固定使用二十个任务，覆盖开发类（下游仅输出方案、不实际修改仓库）与写作类（下游交付文本）两种性质。跨任务不采用代码测试通过率作为统一质量指标。每个任务的材料保留来源标签，至少包括：真实实现、用户说明、测试示例、待办事项。材料中存在的测试污染反例在人工评分前不得人为删除。

### 2.2 条件与分组

设四个条件：

- **A 原始需求组**：下游模型直接接收原始需求与初始材料。
- **B 直接增强组**：下游模型接收由同一初始信息生成的优化提示词，不经历交互问答，不获得计划确认组后来回答的业务选择。
- **C 计划确认组**：系统先提问，实验操作者按预先制定的答案卡作答，再生成最终提示词。记录每个问题、选项、推荐依据和答案；错误推荐被答案纠正后仍计入交互阶段风险。
- **D 信息量匹配对照组**：获得与 C 组相同的已确认事实，但不经历本平台问答过程。用于区分“新增信息”与“交互组织方式”的贡献。

A、B 两组不得接触 C 组在交互阶段才确认的业务选择；D 组的信息内容与 C 组最终确认事实一致，但获取形式不同。

### 2.3 重复与随机化

每个条件对每个任务独立重复三次，共 240 个下游输出（4 条件 × 20 任务 × 3 重复）。每次重复开启隔离会话，随机化任务顺序，记录模型版本、日期和参数。失败后的重试不得替代第一份失败样本；工具失败与首轮失败均保留在数据中。

### 2.4 盲评

两名盲评者独立评分。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源。评审可查看任务事实，但不得查看另一名评审的先前评分。

## 3. 主要指标

评分同时覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。每个维度单独计分。一个错误可能同时影响多个维度，评分表记录主错误和关联维度，避免将同一问题重复计为多个独立失败。

工具生成速度作为过程指标单独记录，不进入质量分。无计费日志时，不估算真实 Token 成本，不将字符数换算为实际费用。

## 4. 统计方法选择流程

统计方法不预先锁定。选择流程为：先确认各维度分数是否有序、是否连续、是否重复测量，再据此确定适用的检验方法。在变量性质未确定前，不指定具体显著性检验。

## 5. 限制

本研究为尚未执行的方案，不含实验结果。三个模型给出相似结论不构成研究完成证据；人工评阅与可复核任务标准为必需环节，专业领域判断尚需专家参与。交互式计划确认的最大轮次与终止规则、两名评审的分歧处理与一致性评价方式尚未确定，须在预注册前明确，当前不默认补全。
