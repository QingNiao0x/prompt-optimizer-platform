# 提示词整理工具对照研究方案（未执行）

## 一、研究问题与目标

本研究比较三种提示词整理条件对下游任务输出的影响：原始需求、直接增强、交互式计划确认增强。目标不是评价某家产品绝对优劣，而是在相同初始材料下，观察不同整理方式对需求保真、业务规则、输出可用性、阅读负担和执行边界的影响。实验尚未运行，本方案不报告准确率、显著性、成功案例数量或用户结论。

交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答，再生成最终提示词，不是静态任务分解列表。由于该组额外获得答案，必须另设信息量匹配对照，避免把新增信息收益误判为模型能力。

## 二、实验设计

固定二十个任务，每条件独立重复三次，两名盲评者独立评分。所有工具获取相同初始材料。四个条件为：

1. 原始组：原始需求与初始材料；
2. 直接增强组：同一初始信息得到的优化提示词；
3. 计划确认组：经问答与答案卡确认后生成最终提示词；
4. 信息量匹配组：获得相同已确认事实，但不经历本平台问答过程。

原始组与直接增强组不得偷看计划确认组后来回答的业务选择。计划确认组记录每个问题、选项、推荐依据和答案，不只保存最终提示词；错误推荐被答案纠正后仍计入交互阶段风险。信息量匹配组用于减少新增信息与交互组织方式之间的混淆。

每个条件三次重复开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本。任务材料保留真实实现、用户说明、测试示例与待办来源标签，评分前不得删除不利的测试污染反例。

## 三、主要指标与评价

评价覆盖需求保真、业务规则、输出可用性、阅读负担和执行边界。开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本，因此跨任务不能用代码测试通过率作为统一质量指标。工具生成速度是过程指标，质量分是结果指标；没有计费日志时不估算真实 Token 成本，不把字符数直接换算成实际费用。

评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可看任务事实，但不能看另一名评审先前评分。一个错误可能同时影响完整性与可执行性，评分表记录主错误和关联维度，避免同一问题多次计成独立失败。候选统计方法依赖分数是否有序、是否连续和是否重复测量；方案说明选择流程，不在变量未确定时锁定显著性检验。即使三个模型给出相似结论也不是研究完成证据，专业领域判断尚需专家参与。

## 四、限制与待确认

本方案不声称已完成实际论文或研究设计业务验收。当前两项方法条件尚未决定，保留为预注册前待确认事项：交互式计划确认的最大轮次与终止规则；两名评审的分歧处理与一致性评价方式。不得默认选择具体轮数、停止阈值、第三名评审或一致性指标。
