# 提示词整理工具对照研究方案（尚未执行）

## 一、研究方案主文

### 1. 研究问题

本研究比较三类提示词整理条件对下游任务输出的影响：**原始需求**（直接使用原始需求与初始材料）、**直接增强**（使用由同一初始信息生成的优化提示词）、**交互式计划确认增强**（系统先提问、实验操作者按预先制定答案卡作答，再生成最终提示词）。研究不评价任何产品的绝对优劣，只比较条件差异。

交互式计划确认在本题中指：系统先提问，实验操作者按预先制定答案卡作答，再生成最终提示词；它不是静态任务分解列表。

### 2. 实验设计

固定设计：二十个任务，每个条件独立重复三次，两名盲评者独立评分。所有工具获取相同初始材料。

**公平比较分两层：**

- **相同初始信息比较**：原始组与直接增强组接收同一初始信息；两组均不得偷看计划确认组后来回答的业务选择。
- **信息量匹配比较**：计划确认组额外获得答案，因此另设**信息量匹配对照组**——获得相同已确认事实，但不经历问答过程。该组用于减少“新增信息”与“交互组织方式”之间的混淆，避免把多得到答案带来的收益误判为单纯模型能力。

三次重复须开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本；工具失败与首轮失败样本均须保留。

### 3. 主要指标

评价同时覆盖五个维度：**需求保真**（输出是否忠实于原始需求）、**业务规则**（是否遵守任务给定规则）、**输出可用性**（能否直接使用或推进）、**阅读负担**（理解与核对成本）、**执行边界**（是否越界，如开发任务只输出方案、不实际修改仓库）。

开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本。因此跨任务不能用代码测试通过率作为统一质量指标。

评分表记录**主错误**与**关联维度**：一个错误可能同时影响完整性与可执行性，须避免将同一问题多次计成不同独立失败。

盲评仅见匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可看任务事实，但不得看另一名评审先前评分。

### 4. 限制与风险

- 专业领域判断尚需专家参与；三个模型给出相似结论也不构成研究完成证据。
- 统计方法选择流程：候选方法依赖分数是否有序、是否连续和是否重复测量；变量尚未确定时不锁定具体显著性检验，只说明选择流程。
- 过程指标与结果指标须区分：工具生成速度是过程指标，质量分是结果指标。没有计费日志时不能估算真实 Token 成本，不能把字符数直接换算成实际费用。
- 任务材料须保留真实实现、用户说明、测试示例与待办来源标签；人工评分前不得删除不利的测试污染反例。
- 本方案尚未执行，无准确率、显著性、成功案例数量或用户结论。

## 二、变量与分组附表

| 条件 | 输入 | 隔离要求 | 记录字段 |
|---|---|---|---|
| 原始需求 | 原始需求 + 初始材料 | 不得偷看计划确认组答案；隔离会话 | 会话ID、模型版本、日期、参数、首轮输出、失败标记 |
| 直接增强 | 同一初始信息生成的优化提示词 | 不得偷看计划确认组答案；隔离会话 | 同上 + 优化提示词版本 |
| 交互式计划确认增强 | 系统提问 + 答案卡作答后生成的最终提示词 | 隔离会话；记录每轮问答 | 同上 + 每个问题、选项、推荐依据、答案；错误推荐被纠正后仍计入交互阶段风险 |
| 信息量匹配对照 | 相同已确认事实，不经历问答过程 | 隔离会话 | 同上；标注“信息量匹配” |

**材料来源标签**（须保留）：真实实现、用户说明、测试示例、待办。

**随机化与记录**：每条件三次重复，随机化顺序；记录模型版本、日期、参数；失败重试不替代首轮失败样本。
