# 地区基线自动匹配与表单补值实现方案

## 一、背景与现有调用关系

### 1.1 业务背景

基础调查与追踪调查两个模块在编辑状态下，需要根据当前表单中已有的**姓名**与**证件号**，在符合**当前用户所属地区**的基线记录中查找可补值候选，经用户确认后，将候选记录中的白名单字段补入当前表单。

### 1.2 现有调用关系（保持不变）

| 环节 | 现有接口/行为 | 本次要求 |
| --- | --- | --- |
| 候选查询 | 已有查询接口，返回候选摘要 | 保持接口、路由、鉴权不变 |
| 单条详情 | 已有读取单条详情接口，返回补值字段 | 保持接口、路由、鉴权不变 |
| 补值服务 | 两个模块复用同一份补值服务 | 本次同时覆盖两个模块 |
| 前端路由 | 追踪调查路由参数仅定位当前调查记录 | 不得当作基线记录编号使用 |

### 1.3 关键前提（来自现行资料，非页面提示）

- 匹配键为**姓名 + 证件号**，且记录必须符合**当前用户所属地区**条件，两者同时满足才是可补值候选。
- 字段白名单仅：**联系电话、职业类别、常住地址**。目录中的演示字段不属于本次范围。
- 候选排序：**更新时间降序，时间相同按记录编号升序**。
- 写入规则：仅当目标值为 `null` 或空字符串时允许补入；`0`、`false`、非空字符串均为有效原值，必须保留。
- 用户取消、关闭弹窗、离开编辑页面均不得补写；已保存原值与未保存编辑值都不能被取消动作清空。
- 查询或详情失败时保留原值并给出面向录入人员的失败提示，不得伪装为"没有匹配记录"。
- 日志只记录稳定错误类型与请求标识，不记录姓名或证件号原文；确认框不得展示完整证件号。

## 二、两个模块共用的处理步骤

两个模块共用同一份补值服务，差异仅在于**身份键来源**与**当前地区来源**由调用方显式传入，服务内部不读取任何页面状态。

### 2.1 统一处理流程

```
[编辑态进入 / 姓名或证件号变更]
        │
        ▼
(1) 采集身份键：姓名 + 证件号（来自当前表单）
    采集当前地区：由调用方显式传入（基础调查 / 追踪调查各自提供）
        │
        ▼
(2) 生成请求标识 requestId，记录"当前有效请求"
        │
        ▼
(3) 调用候选查询接口（保持现有接口）
        │
        ├─ 失败 → 保留原值 + 面向录入人员的失败提示（不伪装为无候选）
        │
        ▼
(4) 对返回候选做地区可核验性判定
        ├─ 地区信息缺失 / 无法核验 → 单独标记"无法核验"，不进入可补值候选
        ├─ 明确地区不符 → 排除
        └─ 地区符合 → 进入候选列表
        │
        ▼
(5) 候选排序：更新时间降序，时间相同按记录编号升序
        │
        ├─ 无候选 → 不弹确认框，流程结束
        │
        ▼
(6) 有候选 → 弹出确认框（展示编号、地区、更新时间、姓名掩码；不展示完整证件号）
        │
        ├─ 用户取消 / 关闭弹窗 / 离开页面 → 全部字段原值不变，流程结束
        │
        ▼
(7) 用户同意 → 在写入前调用单条详情接口获取该候选最新详情
        │
        ├─ 详情失败 → 保留原值 + 失败提示
        ├─ 详情返回编号 ≠ 用户同意的编号 → 停止写入 + 提示信息不一致
        │
        ▼
(8) 按字段白名单与空值规则写入
        │
        ▼
(9) 写入完成
```

### 2.2 时序保护（两个模块共用）

- 每次发起候选查询时生成新的 `requestId`，并记录为"当前有效请求"。
- 当姓名或证件号再次变更时，旧 `requestId` 立即失效。
- 迟到的旧请求响应到达时，若其 `requestId` 不等于当前有效请求，直接丢弃，不更新候选列表、不弹确认框、不写入。
- 本方案只描述时序保护要求，不指定具体浏览器库或状态管理实现。

### 2.3 地区可核验性判定（对应待明确项的处理）

按用户补充决定执行：

- **地区信息缺失或无法核验当前用户所属地区条件的候选**：本次**排除**，不进入可补值候选。
- 该情况需**单独说明"无法核验"**，不得伪装成查询失败，也不得伪装成"没有匹配记录"。
- 三种结果必须分别呈现：
  1. **无法核验**：候选存在但地区信息缺失/无法核验；
  2. **确无候选**：查询成功且无任何符合条件记录；
  3. **明确地区不符**：候选存在但地区明确不符合当前用户地区条件。

## 三、字段写入与异常分支伪代码

### 3.1 服务层伪代码（两个模块共用）

```java
// 伪代码：补值服务，两个模块共用
// 输入：identityKeys(姓名, 证件号)、currentRegion(由调用方显式传入)、requestId
// 输出：候选列表 / 无候选 / 无法核验 / 失败

class BaselineFillService {

    FillResult queryCandidates(IdentityKeys keys, Region currentRegion, String requestId) {
        // 1. 调用现有候选查询接口（接口、路由、鉴权不变）
        QueryResponse resp;
        try {
            resp = candidateQueryApi.query(keys, currentRegion);
        } catch (Exception e) {
            // 查询失败：保留原值，面向录入人员的失败提示
            log.warn("fill.query.failed", requestId, e.stableType());
            return FillResult.failed("本次未执行补值，原数据已保留");
        }

        // 2. 地区可核验性判定
        List<Candidate> verifiable = new ArrayList<>();
        List<Candidate> unverifiable = new ArrayList<>();
        for (Candidate c : resp.getCandidates()) {
            RegionStatus rs = verifyRegion(c, currentRegion);
            if (rs == RegionStatus.MATCH) {
                verifiable.add(c);
            } else if (rs == RegionStatus.UNVERIFIABLE) {
                unverifiable.add(c);   // 地区缺失/无法核验 → 排除，单独说明
            }
            // rs == MISMATCH → 明确地区不符，排除
        }

        // 3. 排序：更新时间降序，时间相同按记录编号升序
        verifiable.sort(
            Comparator.comparing(Candidate::getUpdatedAt).reversed()
                      .thenComparing(Candidate::getRecordNo)
        );

        // 4. 结果分类返回
        if (!verifiable.isEmpty()) {
            return FillResult.hasCandidates(verifiable);
        }
        if (!unverifiable.isEmpty()) {
            return FillResult.unverifiable("存在候选但地区信息无法核验，本次不补值");
        }
        return FillResult.noCandidate();   // 确无候选，不弹确认框
    }

    // 用户同意后、写入前获取最新详情
    FillResult fetchDetail(String agreedRecordNo, String requestId) {
        DetailResponse detail;
        try {
            detail = candidateDetailApi.get(agreedRecordNo);
        } catch (Exception e) {
            log.warn("fill.detail.failed", requestId, e.stableType());
            return FillResult.failed("本次未执行补值，原数据已保留");
        }
        // 详情返回编号必须与用户同意的编号一致
        if (!agreedRecordNo.equals(detail.getRecordNo())) {
            log.warn("fill.detail.mismatch", requestId);
            return FillResult.failed("候选信息不一致，已停止写入");
        }
        return FillResult.detail(detail);
    }
}
```

### 3.2 字段写入伪代码（空值规则）

```java
// 伪代码：按白名单与空值规则写入
// 白名单：联系电话、职业类别、常住地址
// 规则：仅当目标值为 null 或空字符串时允许补入
//       0、false、非空字符串均为有效原值，必须保留

void applyFill(Form form, Detail detail) {
    // 联系电话
    if (isBlank(form.getPhone()) && isNotBlank(detail.getPhone())) {
        form.setPhone(detail.getPhone());
    }
    // 目标为空且来源也为空 → 保持空值，不制造占位号码（无需操作）

    // 职业类别：数值 0 是有效类别，必须用空值比较，不能用逻辑或
    if (isNullOrEmpty(form.getOccupationCategory())   // 明确空值比较
            && detail.getOccupationCategory() != null) {
        form.setOccupationCategory(detail.getOccupationCategory());
    }

    // 常住地址：单个字符串字段，不包含户籍地址、单位地址、紧急联系人地址
    if (isBlank(form.getResidentAddress()) && isNotBlank(detail.getResidentAddress())) {
        form.setResidentAddress(detail.getResidentAddress());
    }

    // 其他字段一律不写入（白名单外禁止）
}

// 空值判定：null 或空字符串
boolean isBlank(String s) { return s == null || s.isEmpty(); }
boolean isNullOrEmpty(Object o) { return o == null || "".equals(o); }
```

### 3.3 异常分支汇总

| 分支 | 处理 | 用户可见提示 |
| --- | --- | --- |
| 候选查询失败 | 保留原值 | "本次未执行补值，原数据已保留" |
| 详情查询失败 | 保留原值 | "本次未执行补值，原数据已保留" |
| 详情编号与同意编号不一致 | 停止写入 | "候选信息不一致，已停止写入" |
| 地区缺失/无法核验 | 排除该候选 | "存在候选但地区信息无法核验，本次不补值" |
| 确无候选 | 不弹确认框 | 无（或"无匹配记录"） |
| 明确地区不符 | 排除 | 归入无候选或单独说明 |
| 用户取消/关闭/离开 | 不写入 | 无，原值与编辑值均保留 |
| 迟到旧请求响应 | 丢弃 | 无 |

### 3.4 前端交互要点（Vue 3 + TypeScript）

- 确认框展示：编号、地区、更新时间、姓名掩码；**不展示完整证件号**。
- 无候选时不弹确认框。
- 有候选时必须询问用户，不得改为无确认自动写入。
- 姓名/证件号变更时使旧 `requestId` 失效。
- 取消、关闭弹窗、离开编辑页面均不补写，且不清空已保存原值与未保存编辑值。
- 失败提示面向录入人员，不附带内部堆栈、数据库错误文本或上游服务地址。
