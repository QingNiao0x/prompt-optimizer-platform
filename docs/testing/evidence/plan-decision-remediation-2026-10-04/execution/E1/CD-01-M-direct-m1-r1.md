# 地区基线自动匹配与表单补值实现方案

> 说明：本方案为只读分析与方案交付，不产生代码修改、不执行命令、不做数据库迁移、不部署。文中“已知事实”均来自 `materials/software/current-brief.md`（正式说明）；`materials/software/tests/layout-example.txt` 仅作排版与来源识别示例，不作为业务事实。凡属推断或需人工确认的内容，均单独标注。

## 1. 背景与现有调用关系

### 1.1 已知事实（来源：`materials/software/current-brief.md`）
- 系统包含两个调查模块：**基础调查**与**追踪调查**，二者**复用同一份补值服务**。
- 已有**查询接口**返回候选摘要；已有**读取单条详情的接口**返回补值字段。
- 匹配使用**姓名与证件号两个键**，且记录必须符合**当前用户所属地区**条件；两个条件都满足才属于可补值候选。
- 字段白名单只有**联系电话、职业类别、常住地址**。
- 候选按**更新时间降序**排列，时间相同按**记录编号升序**排列。
- 只有目标值为 **null 或空字符串**时允许补入来源值；0、false 和非空字符串都是有效原值。
- 追踪调查页面的**路由参数只用于定位当前调查记录**，不得直接当作基线记录编号。
- 复用服务必须接收**明确的身份键（姓名、证件号）与当前地区**，不得暗中读取另一页面状态。

### 1.2 调用关系（基于上述事实整理）

```
[基础调查页面]                         [追踪调查页面]
   │  进入编辑状态                          │  进入编辑状态
   │  读取当前姓名/证件号/地区              │  读取当前姓名/证件号/地区
   │  （路由参数仅定位当前调查记录）        │  （路由参数仅定位当前调查记录）
   └──────────────┬─────────────────────────┘
                  ▼
        [共用补值服务]（入参：姓名、证件号、当前地区）
                  │
                  ├─► [查询接口] 返回候选摘要
                  │     摘要字段：编号、地区、更新时间、姓名掩码
                  │     排序：更新时间降序，时间相同按编号升序
                  │
                  └─► 用户同意后、写入表单前
                         ▼
                  [详情接口] 按候选编号读取最新详情
                         │
                         ▼
                  字段白名单写入：联系电话、职业类别、常住地址
```

### 1.3 兼容性约束
- 保持现有**查询接口、路由与鉴权行为兼容**，不新增破坏性变更。
- 两个模块共用同一补值服务，服务入参显式传入身份键与当前地区，不依赖页面隐式状态。

## 2. 两个模块共用的处理步骤

### 2.1 统一流程

1. **进入编辑状态**
   - 基础调查：进入编辑状态时，可根据当前已有的姓名与证件号发起候选查询。
   - 追踪调查：路由参数仅用于定位当前调查记录，**不得**直接当作基线记录编号；身份键与地区从当前调查记录上下文中显式取得。

2. **构造服务入参**
   - 入参：`姓名`、`证件号`、`当前地区`。
   - 不得暗中读取另一页面状态；不得用路由参数替代身份键或地区。

3. **调用查询接口获取候选摘要**
   - 摘要包含：编号、地区、更新时间、姓名掩码。
   - 排序：更新时间降序；时间相同按编号升序。
   - 分页加载或重试后顺序必须稳定，不得随机变化。

4. **候选判定**
   - 姓名与证件号两个键匹配，**且**记录符合当前用户所属地区条件，两个条件都满足才属于可补值候选。
   - 地区缺失不等于地区匹配成功；查询接口返回顺序不是授权证据。

5. **用户确认**
   - 无候选：**不弹确认框**。
   - 有匹配候选：**必须询问用户**，不得改为无确认自动写入。
   - 确认框展示：编号、地区、更新时间、姓名掩码；**不得展示完整证件号**。

6. **获取最新详情**
   - 在用户同意后、写入表单前，调用详情接口获取该候选的最新详情。

7. **一致性校验**
   - 若详情接口返回的编号与用户已同意的候选编号不一致，**停止写入并提示信息不一致**；不得因部分字段相似而接受响应。

8. **字段写入（白名单）**
   - 仅允许写入：联系电话、职业类别、常住地址。
   - 空值判定：仅当目标值为 `null` 或空字符串时允许补入来源值；0、false 和非空字符串都是有效原值，必须保留。
   - 职业类别为数值 0 时代表有效类别，必须使用**空值比较**，不得使用逻辑或表达式，避免 JavaScript 假值判断触发替换。
   - 常住地址为单个字符串字段，不包含户籍地址、单位地址或紧急联系人地址。

9. **取消语义**
   - 用户点击取消、关闭弹窗或离开编辑页面时，均不得补写字段。
   - 页面已保存的原值与当前未保存的编辑值都不能因取消动作被清空。

10. **时序保护**
    - 用户修改姓名或证件号后，之前的候选必须失效，不能沿用旧身份对应的详情。
    - 候选请求未结束时再次修改姓名，迟到的旧请求必须失效。
    - 本方案只描述时序保护要求，不指定具体浏览器库或状态管理实现。

11. **异常与失败分支**
    - 查询或详情失败时保留原值，并显示可理解的失败提示；不得伪装为没有匹配记录。
    - 网络失败提示面向录入人员，说明本次未执行补值且原数据保留；不附带内部堆栈、数据库错误文本或上游服务地址。

12. **地区缺失处理**
    - **无法核验的记录**：地区信息缺失或无法核验当前地区条件时，该候选不得视为可补值候选。**当前尚未决定具体处理方式，不得默认补全**（见第 6 节待确认项）。
    - **确无候选**：查询接口正常返回但无匹配记录，不弹确认框。
    - **明确地区不符**：记录地区与当前用户所属地区明确不一致，排除该候选。

13. **隐私与日志**
    - 候选摘要包含编号、地区、更新时间、姓名掩码；确认框不得展示完整证件号。
    - 日志只记录稳定错误类型和请求标识，不记录姓名或证件号原文。

### 2.2 两个模块的差异点

| 维度 | 基础调查 | 追踪调查 |
|---|---|---|
| 进入编辑状态触发查询 | 可根据当前姓名与证件号发起 | 同样可发起，但身份键与地区从当前调查记录上下文显式取得 |
| 路由参数用途 | 定位当前调查记录 | 仅定位当前调查记录，**不得**当作基线记录编号 |
| 共用服务 | 是 | 是 |
| 字段白名单 | 联系电话、职业类别、常住地址 | 同左 |
| 排序、空值、取消、时序、一致性、异常、隐私 | 同左 | 同左 |

## 3. 字段写入与异常分支伪代码

> 说明：以下伪代码为方案级描述，不指定具体语言实现细节；空值判定与取消语义严格遵循正式说明。

```
// 常量
WHITELIST = ["联系电话", "职业类别", "常住地址"]

// 空值判定：仅 null 或空字符串视为空
function isEmptyValue(v):
    return v == null OR v == ""

// 主流程
function fillFromCandidate(form, identity, region, userConsent):
    // identity = { name, idNumber }
    // region = 当前用户所属地区
    // 入参显式传入，不读取其他页面状态

    // 1. 查询候选
    try:
        candidates = queryCandidates(identity.name, identity.idNumber, region)
    catch (e):
        logStableError("QUERY_FAILED", requestId)
        showUserMessage("本次未执行补值，原数据保留")
        return UNCHANGED

    // 2. 候选判定：姓名+证件号匹配 且 地区符合
    validCandidates = []
    for c in candidates:
        if c.region == null OR cannotVerify(c.region, region):
            // 无法核验：不得视为可补值候选；当前尚未决定具体处理方式
            markAsUnverifiable(c)
            continue
        if c.region != region:
            // 明确地区不符
            continue
        validCandidates.append(c)

    // 3. 排序：更新时间降序，时间相同按编号升序
    sort(validCandidates, by: (updateTime DESC, recordId ASC))

    // 4. 无候选：不弹确认框
    if validCandidates.isEmpty():
        return UNCHANGED

    // 5. 有候选：必须询问用户
    selected = askUser(validCandidates)   // 展示编号、地区、更新时间、姓名掩码
    if selected == null:                  // 用户取消
        return UNCHANGED

    // 6. 用户同意后、写入前获取最新详情
    try:
        detail = getDetail(selected.recordId)
    catch (e):
        logStableError("DETAIL_FAILED", requestId)
        showUserMessage("本次未执行补值，原数据保留")
        return UNCHANGED

    // 7. 一致性校验
    if detail.recordId != selected.recordId:
        showUserMessage("信息不一致，已停止写入")
        return UNCHANGED

    // 8. 字段写入（白名单 + 空值判定）
    for field in WHITELIST:
        target = form[field]
        source = detail[field]
        if isEmptyValue(target):          // 仅 null 或空字符串
            form[field] = source
        // 否则保留原值（0、false、非空字符串均保留）

    return WRITTEN

// 取消语义
function onCancel(form, snapshot):
    // 不补写任何字段
    // 已保存原值与未保存编辑值均不清空
    restore(form, snapshot)
    return UNCHANGED

// 时序保护
function onIdentityChanged(newName, newIdNumber):
    invalidatePreviousCandidates()
    // 迟到的旧请求必须失效
    cancelPendingRequests()
    // 重新发起查询（如进入编辑状态）
```
