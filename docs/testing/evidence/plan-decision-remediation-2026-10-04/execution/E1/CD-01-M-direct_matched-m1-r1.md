# 地区基线自动匹配与表单补值实现方案

> 说明：本方案为只读分析与方案交付，不产生代码修改、不执行命令、不做数据库迁移、不部署。方案同时覆盖基础调查与追踪调查两个模块，二者复用同一份补值服务，并保持现有查询接口、路由与鉴权行为兼容。

---

## 1. 背景与现有调用关系说明

### 1.1 系统背景

目标系统是一套合成的公共卫生调查录入系统，包含两个调查模块：

- **基础调查模块**：录入基线信息。
- **追踪调查模块**：在基线基础上进行随访/追踪录入。

两个模块复用同一份**补值服务**，用于在用户编辑表单时，根据身份键与地区条件匹配候选记录，并在用户同意后把候选详情中的部分字段补入当前表单。

技术栈（已明确，无需重新选型）：后端 Java 21、Spring Boot 3、MyBatis-Plus、PostgreSQL；前端 Vue 3 与 TypeScript。

### 1.2 现有能力

- **查询接口**：返回候选摘要（编号、地区、更新时间、姓名掩码等）。
- **详情接口**：读取单条详情，返回补值字段。
- **补值服务**：两个模块共用，负责匹配、排序、白名单写入与异常处理。

### 1.3 调用关系（文字版）

```
[基础调查页面] ─┐
                ├─→ [补值服务] ─→ [查询接口] ─→ 候选摘要列表
[追踪调查页面] ─┘        │
                         └─→ [详情接口] ─→ 单条详情（补值字段）

路由参数（追踪调查）──→ 仅用于定位当前调查记录，不进入补值服务作为基线编号
鉴权/地区上下文 ──→ 由现有鉴权行为提供当前用户所属地区，补值服务显式接收
```

要点：

- 两个模块页面**不直接互相读取状态**；补值服务入参为**明确的身份键（姓名、证件号）与当前地区**。
- 追踪调查页面的**路由参数只用于定位当前调查记录**，不得直接当作基线记录编号传给补值服务。
- 现有查询接口、路由与鉴权行为保持不变；补值服务在其之上做编排，不替换、不削弱现有能力。

### 1.4 已知事实与必要假设

**已知事实（来源：materials/software/current-brief.md）**：

- 匹配使用姓名与证件号两个键，并且记录必须符合当前用户所属地区条件。
- 字段白名单只有联系电话、职业类别、常住地址。
- 已有查询接口返回候选摘要，读取单条详情的接口返回补值字段；在用户同意后、写入表单前获取该候选的最新详情。
- 候选按更新时间降序排列，时间相同按记录编号升序排列。
- 只有目标值为 null 或空字符串时允许补入来源值；0、false 和非空字符串都是有效原值。
- 用户点击取消必须保持全部字段原值不变。
- 用户修改姓名与证件号后，之前的候选必须失效。
- 候选摘要包含编号、地区、更新时间以及姓名掩码；确认框不得展示完整证件号。
- 日志只记录稳定错误类型和请求标识，不记录姓名或证件号原文。
- 地区缺失不是地区匹配成功；查询接口返回顺序不是授权证据。

**用户确认信息（本次补充描述）**：

- 当候选记录的地区信息缺失、无法核验是否符合当前用户所属地区条件时：**本次排除该候选，单独说明“无法核验”，不伪装成查询失败或没有匹配。**

**必要假设（仅用于方案完整性，需在实现前确认）**：

- 当前用户所属地区由现有鉴权上下文提供，补值服务以显式入参接收，不暗中读取页面状态。
- 查询接口与详情接口的现有契约（路径、鉴权、返回结构）保持不变，本方案只在其上编排。

## 2. 两个模块共用的处理步骤说明

### 2.1 统一流程（基础调查与追踪调查共用）

1. **进入编辑状态**
   - 基础调查页面进入编辑状态时，可根据当前已有的姓名与证件号发起候选查询。
   - 追踪调查页面进入编辑状态时同理；其路由参数仅用于定位当前调查记录，**不得**作为基线记录编号传入补值服务。

2. **构造服务入参**
   - 入参：`{ name, idNumber, currentRegion }`。
   - `currentRegion` 来自现有鉴权上下文，显式传入；**不得**暗中读取另一页面状态。
   - 追踪调查页面的路由参数不进入该入参。

3. **调用查询接口获取候选摘要**
   - 返回候选摘要列表，包含编号、地区、更新时间、姓名掩码。
   - 排序：更新时间降序；时间相同按记录编号升序。
   - 分页加载或重试后顺序必须稳定，不得随机变化。

4. **地区条件核验**
   - 对每条候选核验其地区是否与 `currentRegion` 一致。
   - 三种情况分别处理：
     - **明确地区不符**：排除该候选。
     - **地区信息缺失、无法核验**：排除该候选，并单独说明“无法核验”，不伪装成查询失败或没有匹配。
     - **确无候选**：不弹确认框，按无候选处理。

5. **候选展示与用户确认**
   - 有匹配候选时**必须询问用户**，不得改为无确认自动写入。
   - 确认框展示候选摘要（编号、地区、更新时间、姓名掩码），**不得展示完整证件号**。
   - 无候选时不弹确认框。

6. **用户同意后获取最新详情**
   - 在用户同意后、写入表单前，调用详情接口获取该候选的最新详情。
   - 一致性校验：若详情接口返回的编号与用户同意的候选编号不一致，**停止写入并提示信息不一致**，不得因部分字段相似而接受响应。

7. **字段白名单写入**
   - 仅允许写入：**联系电话、职业类别、常住地址**。
   - 禁止写入其他表单字段；目录中的演示字段不在本次范围。
   - 常住地址为单个字符串字段，不包含户籍地址、单位地址或紧急联系人地址。

8. **空值判定**
   - 只有目标值为 `null` 或空字符串时允许补入来源值。
   - `0`、`false` 和非空字符串都是有效原值，必须保留。
   - 职业类别为数值 `0` 时代表有效类别，必须使用**空值比较**，而非逻辑或表达式，避免 JavaScript 假值判断触发替换。

9. **取消语义**
   - 用户点击取消、关闭弹窗或离开编辑页面时，均不得补写字段。
   - 页面已保存的原值与当前未保存的编辑值都不能因取消动作被清空。

10. **时序保护**
    - 用户修改姓名或证件号后，之前的候选必须失效，不能沿用旧身份对应的详情。
    - 候选请求未结束时再次修改姓名，迟到的旧请求必须失效。
    - 本方案只描述时序保护要求，不指定具体浏览器库或状态管理实现。

11. **异常与失败分支**
    - 查询或详情失败时保留原值，并显示可理解的失败提示，不得伪装为没有匹配记录。
    - 网络失败提示面向录入人员，说明本次未执行补值且原数据保留；不附带内部堆栈、数据库错误文本或上游服务地址。

12. **隐私与日志**
    - 候选摘要包含编号、地区、更新时间以及姓名掩码；确认框不得展示完整证件号。
    - 日志只记录稳定错误类型和请求标识，不记录姓名或证件号原文。

### 2.2 地区缺失处理（三种情况分别说明）

| 情况 | 判定 | 处理 |
|---|---|---|
| 无法核验的记录 | 候选地区信息缺失，无法核验是否符合当前用户所属地区条件 | 排除该候选，单独说明“无法核验”，不伪装成查询失败或没有匹配 |
| 确无候选 | 查询接口返回空列表 | 不弹确认框，按无候选处理 |
| 明确地区不符 | 候选地区存在且与当前用户所属地区不一致 | 排除该候选 |

补充：查询接口的返回顺序**不是**授权证据；地区缺失**不等于**地区匹配成功。

### 2.3 兼容性说明

- 现有查询接口、路由与鉴权行为保持不变。
- 补值服务在两个模块间共用，不新增模块专属分支破坏复用。
- 追踪调查页面路由参数仅用于定位当前调查记录，不改变现有路由语义。

## 3. 字段写入与异常分支伪代码

```pseudo
// 补值服务入口（基础调查与追踪调查共用）
function enrichForm(input):
    // input = { name, idNumber, currentRegion, formState, requestId }
    // 注意：currentRegion 由鉴权上下文显式传入，不暗中读取页面状态
    // 追踪调查路由参数不进入本函数

    if input.name is empty or input.idNumber is empty or input.currentRegion is empty:
        return { status: "SKIPPED", reason: "IDENTITY_OR_REGION_MISSING" }

    // 时序保护：记录本次请求的身份键快照
    snapshot = { name: input.name, idNumber: input.idNumber, requestId: input.requestId }

    candidates = queryCandidates(snapshot.name, snapshot.idNumber, input.currentRegion)
    if candidates is FAILED:
        // 查询失败：保留原值，提示失败，不伪装成无匹配
        return { status: "FAILED", reason: "QUERY_FAILED", message: "本次未执行补值，原数据保留" }

    // 地区核验与分类
    usable = []
    unverifiable = []
    for c in candidates:
        if c.region is null or c.region is empty:
            unverifiable.append(c)          // 无法核验，单独说明
        else if c.region != input.currentRegion:
            continue                        // 明确地区不符，排除
        else:
            usable.append(c)

    // 排序：更新时间降序；时间相同按记录编号升序
    usable.sortBy(updateTime DESC, recordId ASC)

    if usable is empty:
        if unverifiable is not empty:
            return { status: "NO_USABLE_CANDIDATE", reason: "UNVERIFIABLE_REGION",
                     message: "存在无法核验地区的候选，本次未执行补值" }
        return { status: "NO_CANDIDATE" }   // 确无候选，不弹确认框

    // 有匹配候选：必须询问用户
    userChoice = askUser(usable)            // 确认框展示编号、地区、更新时间、姓名掩码
    if userChoice is CANCEL or userChoice is CLOSE or userChoice is LEAVE:
        // 取消语义：不补写字段，原值与未保存编辑值都不清空
        return { status: "CANCELLED" }

    // 时序保护：用户同意前再次校验身份键是否被修改
    if currentIdentity() != snapshot:
        return { status: "STALE", reason: "IDENTITY_CHANGED" }

    // 用户同意后、写入前获取最新详情
    detail = getDetail(userChoice.recordId)
    if detail is FAILED:
        return { status: "FAILED", reason: "DETAIL_FAILED",
                 message: "本次未执行补值，原数据保留" }

    // 一致性校验：详情编号必须与用户同意的候选编号一致
    if detail.recordId != userChoice.recordId:
        return { status: "INCONSISTENT", reason: "DETAIL_ID_MISMATCH",
                 message: "信息不一致，已停止写入" }

    // 字段白名单写入
    writeWhitelist(input.formState, detail)
    return { status: "SUCCESS" }


// 字段白名单写入：仅联系电话、职业类别、常住地址
function writeWhitelist(formState, detail):
    // 联系电话
    if isEmpty(formState.phone) and not isEmpty(detail.phone):
        formState.phone = detail.phone
    // 目标电话为空且来源也为空：保持空值，不制造占位号码

    // 职业类别：数值 0 是有效类别，必须用空值比较
    if isEmpty(formState.occupationCategory) and not isEmpty(detail.occupationCategory):
        formState.occupationCategory = detail.occupationCategory

    // 常住地址：单个字符串字段
    if isEmpty(formState.residentAddress) and not isEmpty(detail.residentAddress):
        formState.residentAddress = detail.residentAddress

    // 禁止写入其他字段


// 空值判定：只有 null 或空字符串算空
function isEmpty(v):
    return v is null or v == ""


// 时序保护：迟到的旧请求失效
function onIdentityChanged(newName, newIdNumber):
    // 使所有未完成的旧请求失效
    invalidatePendingRequests()
    // 旧候选不得沿用
    clearCandidates()
```
