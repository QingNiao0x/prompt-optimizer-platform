# 地区基线自动匹配与表单补值实现方案

## 1. 背景与现有调用关系

### 1.1 业务背景
公共卫生调查录入系统包含两个调查模块：**基础调查**和**追踪调查**。两模块均需在录入过程中，根据当前表单已有的姓名与证件号，自动匹配本地区基线记录，并在用户确认后将白名单字段补入当前表单。

### 1.2 现有接口与调用关系
- **候选查询接口**：接收姓名、证件号、当前用户所属地区，返回候选摘要列表（编号、地区、更新时间、姓名掩码）。
- **候选详情接口**：接收候选编号，返回可补值字段（联系电话、职业类别、常住地址）。
- **补值服务**：两个模块共用的服务层组件，负责候选匹配、详情获取、字段写入决策。
- **前端页面**：
  - 基础调查编辑页：进入编辑状态时可根据当前姓名与证件号发起候选查询；用户修改姓名或证件号后，旧候选失效。
  - 追踪调查页：路由参数仅用于定位当前调查记录，不得作为基线记录编号使用。

### 1.3 兼容性要求
- 保持现有查询接口、路由和鉴权行为不变。
- 不修改数据库结构，不新增迁移。
- 两个模块复用同一补值服务，服务接收明确的身份键与当前地区，不读取页面状态。

## 2. 两个模块共用的处理步骤

### 2.1 候选匹配条件
候选必须同时满足：
1. 姓名与证件号匹配；
2. 记录地区符合当前用户所属地区条件。

两个条件都满足才属于可补值候选。

### 2.2 候选排序规则
- 按更新时间降序；
- 更新时间相同时按记录编号升序；
- 分页加载或重试后顺序必须稳定，不得随机变化。

### 2.3 处理流程（两模块共用）
1. **触发查询**：基础调查进入编辑状态时，或追踪调查在明确身份键与当前地区后，调用候选查询接口。
2. **候选展示**：
   - 无候选：不弹确认框，直接结束。
   - 有候选：展示确认框，内容包含编号、地区、更新时间、姓名掩码；不得展示完整证件号。
3. **用户确认**：用户同意某条候选后，在写入表单前调用详情接口获取该候选最新详情。
4. **详情校验**：详情返回的编号必须与用户同意的候选编号一致；不一致则停止写入并提示信息不一致。
5. **字段写入**：仅对白名单字段（联系电话、职业类别、常住地址）执行补值；仅当目标值为 `null` 或空字符串时允许写入来源值。
6. **取消/关闭/离开**：用户取消、关闭弹窗或离开编辑页面时，不得补写任何字段；已保存原值和未保存编辑值均保持不变。
7. **异常处理**：
   - 查询或详情失败：保留原值，显示面向录入人员的失败提示，说明本次未执行补值且原数据保留；不得伪装为无匹配记录。
   - 网络失败提示不得包含内部堆栈、数据库错误文本或上游服务地址。
8. **时序保护**：候选请求未结束时用户再次修改姓名或证件号，迟到的旧请求必须失效，不得沿用旧身份对应的详情。

### 2.4 地区缺失处理（待确认项）
候选地区信息缺失、无法核验当前地区条件时，**不得默认补全**。当前尚未决定处理方式，需保留为待确认项。方案中应将该情况与“确无候选”“明确地区不符”分别说明，不得混为一谈。

## 3. 字段写入与异常分支伪代码

### 3.1 补值服务核心逻辑（伪代码）

```java
// 补值服务：接收明确的身份键与当前地区
public class BaselineFillService {

    // 候选查询
    public List<CandidateSummary> queryCandidates(String name, String idNo, String currentRegion) {
        // 1. 校验身份键与地区非空
        // 2. 调用查询接口，返回候选摘要列表
        // 3. 按更新时间降序、编号升序排序
        // 4. 地区缺失的候选单独标记，不默认补全
        // 5. 返回结果
    }

    // 详情获取与写入
    public FillResult fillForm(String candidateId, FormData targetForm, String currentRegion) {
        // 1. 调用详情接口获取候选最新详情
        CandidateDetail detail = detailApi.getDetail(candidateId);

        // 2. 校验详情编号与用户同意的候选编号一致
        if (!detail.getId().equals(candidateId)) {
            return FillResult.fail("信息不一致，已停止写入");
        }

        // 3. 校验地区条件
        if (detail.getRegion() == null || !detail.getRegion().equals(currentRegion)) {
            // 地区缺失或无法核验：待确认项，不得默认补全
            return FillResult.pending("地区信息缺失，无法核验");
        }

        // 4. 字段白名单写入
        // 联系电话
        if (isBlank(targetForm.getPhone()) && isNotBlank(detail.getPhone())) {
            targetForm.setPhone(detail.getPhone());
        }
        // 职业类别：使用空值比较，避免 JavaScript 假值判断
        if (isBlank(targetForm.getOccupation()) && isNotBlank(detail.getOccupation())) {
            targetForm.setOccupation(detail.getOccupation());
        }
        // 常住地址：仅单个字符串字段
        if (isBlank(targetForm.getAddress()) && isNotBlank(detail.getAddress())) {
            targetForm.setAddress(detail.getAddress());
        }

        // 5. 返回成功
        return FillResult.success();
    }

    // 空值判断：仅 null 或空字符串
    private boolean isBlank(Object value) {
        return value == null || (value instanceof String && ((String) value).isEmpty());
    }

    private boolean isNotBlank(Object value) {
        return !isBlank(value);
    }
}
```

### 3.2 前端处理伪代码（Vue 3 + TypeScript）

```typescript
// 基础调查编辑页
const handleEditEnter = async () => {
  const requestId = generateRequestId();
  currentRequestId.value = requestId;

  try {
    const candidates = await queryCandidates(name.value, idNo.value, currentRegion.value);

    // 迟到的旧请求失效
    if (currentRequestId.value !== requestId) return;

    if (candidates.length === 0) {
      // 无候选：不弹确认框
      return;
    }

    // 展示确认框，仅显示掩码姓名
    const confirmed = await showConfirmDialog(candidates);
    if (!confirmed) {
      // 用户取消：保持原值不变
      return;
    }

    // 用户同意后，写入前获取最新详情
    const detail = await getDetail(confirmed.id);

    // 校验编号一致
    if (detail.id !== confirmed.id) {
      showMessage("信息不一致，已停止写入");
      return;
    }

    // 执行补值
    applyFill(detail);
  } catch (error) {
    // 查询或详情失败：保留原值，显示可理解提示
    showMessage("本次未执行补值，原数据已保留");
  }
};

// 用户修改姓名或证件号时
const onIdentityChange = () => {
  // 旧候选失效
  currentRequestId.value = null;
  candidates.value = [];
};
```

### 3.3 异常分支说明

| 分支 | 处理方式 |
|------|----------|
| 无候选 | 不弹确认框，直接结束 |
| 有候选 | 必须询问用户，不得自动写入 |
| 用户取消/关闭/离开 | 不补写字段，原值与编辑值均保留 |
| 查询失败 | 保留原值，提示“本次未执行补值，原数据保留” |
| 详情失败 | 同上，不得伪装为无匹配 |
| 详情编号不一致 | 停止写入，提示信息不一致 |
| 地区缺失/无法核验 | 待确认项，不得默认补全 |
| 目标值非空（0、false、非空字符串） | 保留原值，不覆盖 |
| 目标值为 null 或空字符串 | 允许补入来源值 |
| 来源值为空 | 保持空值，不制造占位号码 |
| 迟到请求 | 旧请求失效，不沿用旧身份详情 |
