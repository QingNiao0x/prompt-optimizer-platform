# 地区基线自动匹配与表单补值实现方案

> 说明：本方案为只读分析与交付，不产生代码修改、数据库迁移、部署或命令执行。资料引用中，`materials/software/current-brief.md` 为正式现行说明；`materials/software/tests/layout-example.txt` 仅为排版与来源识别测试示例，其中 CSV、Python、100 万元、准确率 99% 等均非本题事实，仅用于验证分支。

---

## 1. 背景与现有调用关系

### 1.1 系统与技术栈（已知事实）

- 后端：Java 21、Spring Boot 3、MyBatis-Plus、PostgreSQL。
- 前端：Vue 3 + TypeScript。
- 现有两个调查模块：**基础调查**、**追踪调查**。
- 两个模块**复用同一份补值服务**，本次方案必须同时覆盖两个模块。

### 1.2 现有接口与调用时序（已知事实）

- **查询接口**：返回候选摘要，摘要字段包含编号、地区、更新时间、姓名掩码。
- **详情接口**：返回补值字段（联系电话、职业类别、常住地址）。
- **调用时序**：用户同意某条候选后、写入表单前，必须调用详情接口获取该候选的**最新详情**，再执行写入判定。
- 候选排序：按更新时间降序；更新时间相同按记录编号升序，分页或重试后顺序稳定。
- 匹配条件：姓名 + 证件号两个键，且记录必须符合当前用户所属地区条件；两个条件都满足才属于可补值候选。

### 1.3 两个模块的复用链路

```
基础调查页面（编辑态）
        │
        │ 传入：姓名、证件号、当前地区
        ▼
   共用补值服务  ◄──── 追踪调查页面（编辑态）
        │                传入：姓名、证件号、当前地区
        │                （路由参数仅用于定位当前调查记录，
        │                  不得当作基线记录编号）
        ▼
   查询接口（候选摘要）
        │
        ▼
   用户确认 → 详情接口（最新详情）→ 写入判定 → 表单字段
```

要点：

- 复用服务**接收明确的身份键（姓名、证件号）与当前地区**，不暗中读取另一页面状态。
- 追踪调查页面的路由参数只负责定位当前调查记录，**不能被直接当作基线记录编号**。
- 基础调查页面进入编辑状态时，可根据当前已有的姓名与证件号发起候选查询；用户修改这两个键后，之前的候选必须失效。

### 1.4 路由与鉴权兼容方式

- 保持现有查询接口、路由与鉴权行为兼容，不新增、不删除、不改写现有路由与鉴权规则。
- 补值服务作为两个模块共用的内部服务，不改变现有鉴权入口；调用方仍按现有鉴权上下文获取“当前用户所属地区”。
- 查询接口的返回顺序**不是授权证据**；地区匹配必须由服务端按当前用户所属地区条件判定，不能以返回顺序推断授权。

## 2. 两个模块共用的处理步骤

以下步骤对基础调查与追踪调查**完全一致**，仅调用方传入的身份键与当前地区来源不同（基础调查来自页面当前编辑值，追踪调查来自当前调查记录对应的身份键与当前地区，路由参数不参与身份键构造）。

1. **进入编辑状态**
   - 基础调查：读取当前已有的姓名与证件号。
   - 追踪调查：读取当前调查记录对应的姓名与证件号；路由参数仅用于定位当前调查记录。
   - 由调用方显式传入：`name`、`idNumber`、`currentRegion`。

2. **发起候选查询**
   - 调用查询接口，传入姓名、证件号、当前地区。
   - 记录本次请求的请求标识（requestId）与身份键快照（name、idNumber）。
   - 若姓名或证件号为空/非法，不发起查询，按“无候选”处理并提示。

3. **展示候选摘要**
   - 摘要仅展示：编号、地区、更新时间、姓名掩码。
   - **确认框不得展示完整证件号**。
   - 排序：更新时间降序；时间相同按编号升序；分页或重试后顺序稳定。

4. **地区核验与候选分类**
   - 对每条候选核验地区是否符合当前用户所属地区条件。
   - 地区信息缺失或无法核验的候选：**排除**，并单独说明“无法核验”，不得伪装成查询失败或没有匹配记录。
   - 明确地区不符的候选：单独说明“地区不符”。
   - 确无候选：单独说明“无匹配候选”。

5. **用户确认**
   - 无候选时不弹确认框。
   - 有匹配候选时必须询问用户，不得改为无确认自动写入。
   - 用户取消：保持全部字段原值不变，不补写。

6. **拉取最新详情**
   - 用户同意后、写入表单前，调用详情接口获取该候选的最新详情。
   - 校验详情返回的编号是否与用户同意的候选编号一致；不一致则停止写入并提示信息不一致。

7. **写入表单**
   - 仅对白名单字段（联系电话、职业类别、常住地址）执行写入判定。
   - 仅当目标值为 `null` 或空字符串时补入来源值；`0`、`false` 和非空字符串都是有效原值，必须保留。
   - 职业类别为数值 `0` 时代表有效类别，必须使用空值比较，不得使用逻辑或表达式。

8. **时序保护与身份键失效**
   - 用户修改姓名或证件号后，之前的候选必须失效，不能沿用旧身份对应的详情。
   - 候选请求尚未结束时再次修改姓名，迟到的旧请求必须失效（按请求标识与身份键快照比对，不匹配则丢弃）。
   - 本方案描述时序保护要求，不指定具体浏览器库或状态管理实现。

9. **取消、关闭、离开编辑页面**
   - 用户取消、关闭弹窗或离开编辑页面时，均不得补写字段。
   - 页面已保存的原值和当前未保存的编辑值都不能因取消动作被清空。

10. **失败处理**
    - 查询或详情失败时保留原值，并显示面向录入人员的可理解提示，说明本次未执行补值且原数据保留。
    - 不得伪装为没有匹配记录；不得附带内部堆栈、数据库错误文本或上游服务地址。
    - 日志只记录稳定错误类型和请求标识，不记录姓名或证件号原文。

## 3. 字段写入与异常分支伪代码

```text
// 常量
WHITELIST = ["contactPhone", "occupationCategory", "permanentAddress"]
// 注意：常住地址是单个字符串字段，不包含户籍地址、单位地址或紧急联系人地址；
// 附件展示的其他地址种类只能作为背景，不能扩张字段白名单。

// 空值判定：仅 null 或空字符串视为可补入
function isBlank(v):
    return v == null || v === ""

// 主流程
function runSupplement(pageContext):
    // pageContext 显式提供：name, idNumber, currentRegion, formFields
    // 不读取另一页面状态；追踪调查的路由参数不参与身份键构造

    if isBlank(pageContext.name) || isBlank(pageContext.idNumber):
        return { status: "NO_CANDIDATE", message: "无匹配候选" }

    snapshot = { name: pageContext.name, idNumber: pageContext.idNumber }
    requestId = newRequestId()

    // 发起候选查询
    try:
        candidates = queryCandidates(snapshot.name, snapshot.idNumber, pageContext.currentRegion, requestId)
    catch err:
        logStableError("QUERY_FAILED", requestId)   // 不记录姓名/证件号原文
        return { status: "QUERY_FAILED", message: "本次未执行补值，原数据已保留" }

    // 迟到请求失效：若期间身份键已变化，丢弃本次结果
    if snapshot != currentIdentity(pageContext):
        return { status: "STALE_DROPPED" }

    // 地区核验与候选分类
    verified = []
    unverifiable = []
    regionMismatch = []
    for c in candidates:
        if c.region == null || c.region == "":
            unverifiable.push(c)          // 单独说明“无法核验”
        else if !regionMatches(c.region, pageContext.currentRegion):
            regionMismatch.push(c)        // 单独说明“地区不符”
        else:
            verified.push(c)

    // 稳定排序：更新时间降序，时间相同按编号升序
    verified.sort(by updateTime desc, then by recordId asc)

    if verified.isEmpty():
        // 无候选时不弹确认框
        return {
            status: "NO_CANDIDATE",
            message: "无匹配候选",
            unverifiableCount: unverifiable.length,   // 单独说明无法核验
            regionMismatchCount: regionMismatch.length
        }

    // 展示候选摘要：编号、地区、更新时间、姓名掩码；确认框不展示完整证件号
    chosen = askUserToConfirm(verified)   // 必须询问用户，不得自动写入
    if chosen == null:
        // 用户取消：保持全部字段原值不变
        return { status: "USER_CANCELLED" }

    // 拉取最新详情
    try:
        detail = getCandidateDetail(chosen.recordId, requestId)
    catch err:
        logStableError("DETAIL_FAILED", requestId)
        return { status: "DETAIL_FAILED", message: "本次未执行补值，原数据已保留" }

    // 详情编号一致性校验
    if detail.recordId != chosen.recordId:
        return { status: "IDENTITY_MISMATCH", message: "信息不一致，已停止写入" }

    // 写入判定：仅白名单字段，仅目标为 null 或空字符串时补入
    for field in WHITELIST:
        target = pageContext.formFields[field]
        source = detail[field]
        if isBlank(target) && !isBlank(source):
            pageContext.formFields[field] = source
        // 目标已有值（含 0、false、非空字符串）一律保留
        // 目标为空且来源也为空：保持空值，不制造占位号码

    // 职业类别为数值 0 时必须保留：使用 isBlank 空值比较，不得使用逻辑或表达式
    // 反例（禁止）：target = target || source   // 会把 0 误判为假值而替换

    return { status: "SUCCESS" }

// 取消 / 关闭 / 离开编辑页面
function onCancelOrCloseOrLeave(pageContext):
    // 不补写任何字段
    // 已保存原值与未保存编辑值均不清空
    return
```

关键判定说明：

- **空值比较**：统一使用 `isBlank(v)`（`null` 或空字符串），不得使用 `||`、`??` 之外的隐式假值判断；`0`、`false`、非空字符串均视为有效原值。
- **职业类别**：数值 `0` 是有效类别，必须走 `isBlank` 判定，禁止 `target || source` 这类逻辑或表达式。
- **联系电话**：目标为空、来源有值可补入；目标已有值即使来源更新也不覆盖；目标为空且来源也为空保持空值，不制造占位号码。
- **常住地址**：单个字符串字段，不包含户籍地址、单位地址或紧急联系人地址；不得扩张白名单。
- **地区核验**：地区缺失或无法核验 → 排除并单独说明“无法核验”；明确不符 → 单独说明“地区不符”；确无候选 → 单独说明“无匹配候选”。三者不得互相伪装。
- **详情编号不一致**：停止写入并提示信息不一致；不能只因为部分字段相似就接受响应。
- **迟到请求**：按请求标识与身份键快照比对，不匹配则丢弃。
- **日志**：只记录稳定错误类型与请求标识，不记录姓名或证件号原文。
