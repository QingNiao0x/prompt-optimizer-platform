# 地区基线自动匹配与表单补值实现方案

**文档状态**：只读分析与方案交付，不产生代码修改、不执行命令、不做数据库迁移、不部署。

**范围**：同时覆盖基础调查与追踪调查两个模块，二者复用同一份补值服务；保持现有查询接口、路由与鉴权行为兼容。


## 1. 背景与现有调用关系

### 1.1 现有能力（依据：`materials/software/current-brief.md`）

- 已有查询接口返回候选摘要（编号、地区、更新时间、姓名掩码）。
- 已有读取单条详情的接口返回补值字段。
- 匹配使用姓名与证件号两个键，且记录必须符合当前用户所属地区条件。
- 字段白名单仅限：联系电话、职业类别、常住地址。

### 1.3 关键约束

- 追踪调查页面的路由参数只用于定位当前调查记录，**不得直接当作基线记录编号**。补值服务必须接收明确的身份键（姓名、证件号）与当前地区，不得暗中读取另一页面状态。
- 两个模块均通过同一补值服务入口，传入各自页面当前表单中的姓名、证件号与当前用户所属地区。


## 2. 两个模块共用的处理步骤

### 2.1 统一流程

```
步骤 0：前置条件
  - 当前页面处于编辑状态。
  - 当前表单中姓名与证件号均非空（两个键缺一不可）。
  - 当前用户所属地区已获取（缺失时按"地区缺失"分支处理，见步骤 6）。

步骤 1：发起候选查询
  - 以（姓名, 证件号, 当前地区）为入参调用现有候选摘要查询接口。
  - 记录本次请求标识（requestId），用于时序保护。

步骤 2：处理查询响应
  - 若请求已因身份键变更而失效（requestId 不匹配），丢弃响应，不做任何处理。
  - 若查询失败：保留原值，显示可理解失败提示（见异常分支），流程终止。
  - 若查询成功但候选列表为空：不弹确认框，流程终止（确无候选）。
  - 若存在候选但均无法核验地区：按"无法核验"分支处理（见步骤 6），流程终止。
  - 若存在候选但均明确地区不符：按"明确地区不符"分支处理（见步骤 6），流程终止。
  - 若存在符合地区条件的候选：进入步骤 3。

步骤 3：排序
  - 按更新时间降序排列；更新时间相同时按记录编号升序排列。
  - 排序结果在分页加载或重试后必须稳定一致。

步骤 4：展示确认框
  - 展示排序后的候选摘要（编号、地区、更新时间、姓名掩码）。
  - 不得展示完整证件号。
  - 等待用户选择/同意或取消。

步骤 5：用户同意后获取详情
  - 用户同意某条候选后，以该候选编号调用单条详情接口。
  - 获取最新补值字段（联系电话、职业类别、常住地址）。

步骤 6：一致性校验
  - 校验详情接口返回的记录编号与用户同意的候选编号一致。
  - 不一致：停止写入，提示信息不一致，流程终止。

步骤 7：字段写入（空值判定）
  - 对白名单内每个字段独立执行空值判定：
    - 目标值为 null 或空字符串 → 允许补入来源值。
    - 目标值为 0、false 或非空字符串 → 保留原值，不覆盖。
  - 职业类别为数值 0 时视为有效原值，必须保留。

步骤 8：完成
  - 写入仅发生在用户同意且所有校验通过之后。
```

### 2.2 地区缺失处理（三种情况分别说明）

| 情况 | 判定依据 | 处理方式 |
|------|---------|---------|
| **无法核验的记录** | 候选记录中地区字段缺失或为空，无法判断是否与当前用户所属地区一致 | **当前尚未决定，不得默认补全**。方案预留处理分支：在未获人工确认前，不将该候选视为可补值候选，不弹确认框，不写入。 |
| **确无候选** | 查询接口返回空列表，或所有候选均不满足姓名+证件号双键匹配 | 不弹确认框，流程静默终止。 |
| **明确地区不符** | 候选记录中地区字段有值，且与当前用户所属地区不一致 | 该候选不进入确认框，不作为可补值候选。 |

> **待确认项**：候选地区信息缺失、无法核验当前地区条件时，应如何处理该候选？当前尚未决定，不得默认补全。此分支在获得人工确认前，按"不视为可补值候选"处理。


## 3. 字段写入与异常分支伪代码

### 3.1 字段写入伪代码

```
function applyPatch(targetForm, sourceDetail, whitelist):
    # whitelist = ["联系电话", "职业类别", "常住地址"]
    # 前置：一致性校验已通过，用户已同意

    for field in whitelist:
        targetValue = targetForm[field]
        sourceValue = sourceDetail[field]

        if isEmpty(targetValue):
            # 仅当目标值为 null 或空字符串时写入
            targetForm[field] = sourceValue
        else:
            # 0、false、非空字符串均为有效原值，保留
            continue

    return targetForm


function isEmpty(value):
    # 空值判定：仅 null 或空字符串视为空
    # 注意：不得使用逻辑或表达式（如 value || default），
    # 否则数值 0 和布尔 false 会被误判为空
    if value == null:
        return true
    if typeof value == "string" and value == "":
        return true
    return false
```

### 3.2 异常分支伪代码

```
function handleCandidateQueryFailure(error, requestId):
    # 查询失败：保留原值，显示可理解提示
    # 不得伪装为"没有匹配记录"
    logStableError("CANDIDATE_QUERY_FAILED", requestId)   # 只记录稳定错误类型和请求标识
    showUserMessage("本次未执行补值，原数据已保留。请稍后重试。")
    # 不附带内部堆栈、数据库错误文本或上游服务地址
    return


function handleDetailFetchFailure(error, requestId):
    # 详情获取失败：保留原值，显示可理解提示
    logStableError("DETAIL_FETCH_FAILED", requestId)
    showUserMessage("本次未执行补值，原数据已保留。请稍后重试。")
    return


function handleConsistencyMismatch(agreedCandidateId, returnedDetailId):
    # 一致性校验失败：停止写入
    logStableError("CONSISTENCY_MISMATCH", requestId)
    showUserMessage("候选信息不一致，本次未执行补值，原数据已保留。")
    return


function handleStaleResponse(responseRequestId, currentRequestId):
    # 时序保护：迟到的旧请求必须失效
    if responseRequestId != currentRequestId:
        # 丢弃响应，不做任何处理
        return DISCARD
    return PROCESS


function handleCancel():
    # 取消语义：用户点击取消、关闭弹窗或离开编辑页面
    # 不得补写字段；已保存原值与未保存编辑值均不得被清空
    # 实现要点：取消操作不调用 applyPatch，不修改 targetForm 任何字段
    return
```

### 3.3 主流程伪代码

```
function runAutoFill(pageContext):
    # pageContext 由调用方显式传入：
    #   - name: 当前表单姓名
    #   - idNumber: 当前表单证件号
    #   - region: 当前用户所属地区
    #   - targetForm: 当前表单对象（基础调查或追踪调查）
    # 追踪调查页面：路由参数仅用于定位当前调查记录，
    # 从记录中提取 name 和 idNumber 后传入，不得将路由参数当作基线记录编号。

    if isEmpty(name) or isEmpty(idNumber):
        return   # 双键不完整，不发起查询

    requestId = generateRequestId()
    currentRequestId = requestId

    candidates = queryCandidates(name, idNumber, region, requestId)

    # 时序保护：响应返回时校验 requestId 是否仍为当前
    if handleStaleResponse(requestId, currentRequestId) == DISCARD:
        return

    if candidates == null:
        handleCandidateQueryFailure(...)
        return

    if candidates is empty:
        return   # 确无候选，不弹确认框

    # 过滤：仅保留地区与当前用户所属地区一致的候选
    regionMatched = filterByRegion(candidates, region)
    if regionMatched is empty:
        # 区分"无法核验"与"明确地区不符"
        # 无法核验：按待确认项处理，当前不弹框、不写入
        # 明确地区不符：不弹框、不写入
        return

    # 排序：更新时间降序，时间相同按记录编号升序
    sortedCandidates = sort(regionMatched, by=[updateTime desc, recordId asc])

    # 展示确认框（摘要：编号、地区、更新时间、姓名掩码；不展示完整证件号）
    userChoice = showConfirmDialog(sortedCandidates)

    if userChoice == CANCEL:
        handleCancel()
        return

    agreedCandidateId = userChoice.candidateId

    # 用户同意后获取最新详情
    detail = fetchDetail(agreedCandidateId, requestId)

    if detail == null:
        handleDetailFetchFailure(...)
        return

    # 一致性校验
    if detail.recordId != agreedCandidateId:
        handleConsistencyMismatch(agreedCandidateId, detail.recordId)
        return

    # 字段写入（空值判定）
    applyPatch(targetForm, detail, whitelist=["联系电话", "职业类别", "常住地址"])
```
