# 地区基线自动匹配与表单补值实现方案

## 0. 事实、确认信息与假设的区分

**已知事实（来自 materials/software/current-brief.md）**
- 匹配键为姓名 + 证件号，且记录必须符合当前用户所属地区条件，两个条件都满足才属于可补值候选。
- 字段白名单只有联系电话、职业类别、常住地址。
- 已有查询接口返回候选摘要；详情接口返回补值字段；用户同意后、写入前获取最新详情。
- 候选排序：更新时间降序，时间相同按记录编号升序。
- 只有目标值为 null 或空字符串才允许补入来源值；0、false、非空字符串都是有效原值。
- 基础调查进入编辑状态可按当前姓名与证件号发起查询；修改这两个键后旧候选失效。
- 追踪调查路由参数只定位当前调查记录，不能当作基线记录编号；复用服务必须接收明确的身份键与当前地区。
- 候选摘要含编号、地区、更新时间、姓名掩码；确认框不得展示完整证件号；日志只记录稳定错误类型和请求标识。
- 取消、关闭弹窗、离开编辑页面都不得补写字段；已保存原值和未保存编辑值都不能因取消被清空。
- 网络失败提示面向录入人员，不暴露内部堆栈、数据库错误文本或上游服务地址。
- 地区缺失不是地区匹配成功；查询接口返回顺序不是授权证据。

**用户确认信息（本次执行选择）**
- 候选地区信息缺失或无法核验当前地区条件的记录，排除出可补值候选，并单独说明“无法核验”，不得伪装为无匹配或查询失败。

**必要假设（仅用于方案落地，不改变上述事实）**
- 查询接口与详情接口的现有 URL、请求/响应字段名、鉴权方式保持不变，本方案只在其上增加调用约束与前端处理逻辑。
- 当前用户所属地区由现有鉴权上下文提供，服务端在查询时已按地区过滤；前端不自行推断地区。
- 记录编号在系统内唯一且稳定，可作为排序与一致性校验的键。
- 详情接口返回体中包含记录编号，可用于与用户已同意的候选编号比对。

**明确不作为事实的内容**
- materials/software/tests/layout-example.txt 中的 CSV 输出格式、Python 分析工具、收入 100 万元、准确率 99% 均不是本题事实，仅用于验证分支，不得写入生产接口、业务规则或验收结论。

## 1. 背景与现有调用关系

### 1.1 两个模块如何复用补值服务

基础调查与追踪调查共用同一份补值服务。复用方式是：两个页面都调用同一组查询接口与详情接口，并把“身份键 + 当前地区”作为显式输入传入服务层，而不是让服务层去读取另一个页面的状态。

- **基础调查**：进入编辑状态时，以当前表单中已有的姓名与证件号作为身份键，以当前用户所属地区作为地区条件，发起候选查询。用户修改姓名或证件号后，旧候选立即失效。
- **追踪调查**：路由参数只用于定位当前调查记录，不能直接当作基线记录编号。页面需要从当前调查记录中解析出明确的身份键与当前地区，再调用同一补值服务。服务层不读取基础调查页面的状态，也不依赖路由参数推断基线。

### 1.2 现有接口与兼容边界

| 接口/行为 | 现有职责 | 兼容边界 |
|---|---|---|
| 候选查询接口 | 返回候选摘要：编号、地区、更新时间、姓名掩码 | 不改变请求/响应结构；不新增必填字段；排序规则在服务端已按更新时间降序、编号升序实现，前端不得重排 |
| 详情接口 | 按候选编号返回补值字段 | 调用时机为“用户同意后、写入前”；返回体必须含记录编号用于一致性校验 |
| 路由参数 | 定位当前调查记录 | 不得作为基线记录编号；不得作为地区来源 |
| 鉴权行为 | 提供当前用户与所属地区 | 地区条件由服务端鉴权上下文提供；前端不自行拼接或覆盖地区 |

### 1.3 地区条件的处理边界

- 地区匹配成功：候选记录地区存在且与当前用户所属地区一致。
- 明确地区不符：候选记录地区存在但与当前用户所属地区不一致，排除。
- 无法核验：候选记录地区缺失或无法判断是否符合当前用户所属地区条件，按用户确认信息排除出可补值候选，并单独说明“无法核验”。
- 确无候选：在地区可核验且身份键匹配的前提下，没有任何候选记录。
- 查询失败：接口调用失败或返回错误，保留原值并提示失败，不得伪装为无匹配。

这四类结果必须在 UI 与日志中可区分，不能合并为同一种提示。

## 2. 两个模块共用的处理步骤

以下步骤对基础调查与追踪调查完全一致，差异仅在于身份键与当前地区的来源。

### 步骤 1：收集输入
- **输入**：身份键（姓名、证件号）、当前地区（来自鉴权上下文）、当前表单目标字段值（联系电话、职业类别、常住地址）。
- **输出**：一次查询请求所需的参数集合。
- **失败处理**：姓名或证件号为空时，不发起查询，提示“请先填写姓名与证件号”。

### 步骤 2：发起候选查询
- **输入**：身份键 + 当前地区。
- **输出**：候选摘要列表（编号、地区、更新时间、姓名掩码），以及本次请求标识。
- **失败处理**：网络失败或接口错误时，保留原值，提示“本次未执行补值，原数据已保留”，不展示内部错误文本。

### 步骤 3：候选分类与排序
- **输入**：候选摘要列表。
- **输出**：可补值候选列表、无法核验列表、明确地区不符列表。
- **规则**：
  - 地区存在且与当前地区一致 → 可补值候选。
  - 地区缺失或无法核验 → 无法核验列表，单独说明。
  - 地区存在但不一致 → 明确地区不符，排除。
  - 排序：更新时间降序；时间相同按记录编号升序。前端不得重排，分页或重试后顺序必须稳定。
- **失败处理**：无可补值候选时不弹确认框；若存在无法核验记录，单独提示“存在无法核验地区的记录，已排除”。

### 步骤 4：用户确认
- **输入**：可补值候选列表。
- **输出**：用户选中的候选编号，或取消动作。
- **规则**：
  - 有可补值候选时必须询问用户，不得自动写入。
  - 确认框展示编号、地区、更新时间、姓名掩码；不得展示完整证件号。
  - 用户取消、关闭弹窗或离开编辑页面 → 不写入任何字段，已保存原值与未保存编辑值均保持不变。
- **失败处理**：取消即终止流程，不产生副作用。

### 步骤 5：获取最新详情
- **输入**：用户选中的候选编号、身份键、当前地区。
- **输出**：详情接口返回的补值字段与记录编号。
- **规则**：
  - 必须在用户同意后、写入前调用。
  - 返回的记录编号必须与用户选中的候选编号一致；不一致时停止写入并提示“信息不一致”。
  - 不得因为部分字段相似就接受响应。
- **失败处理**：详情接口失败时保留原值，提示“本次未执行补值，原数据已保留”。

### 步骤 6：字段写入
- **输入**：详情返回的补值字段、当前表单目标字段值。
- **输出**：更新后的表单字段值。
- **规则**：
  - 仅写入白名单字段：联系电话、职业类别、常住地址。
  - 仅当目标值为 null 或空字符串时允许补入来源值。
  - 0、false、非空字符串都是有效原值，必须保留。
  - 职业类别为数值 0 时是有效类别，必须用空值比较，不能用逻辑或表达式。
  - 目标电话为空且来源也为空时保持空值，不制造占位号码。
  - 常住地址是单个字符串字段，不包含户籍地址、单位地址或紧急联系人地址。
- **失败处理**：写入过程中若发现身份键已变更或请求已过期，放弃写入。

### 步骤 7：时序保护与失效
- **输入**：请求标识、当前身份键快照。
- **输出**：是否允许继续处理。
- **规则**：
  - 用户修改姓名或证件号后，之前发起的候选查询与详情请求全部失效。
  - 候选请求尚未结束时再次修改姓名，迟到的旧请求必须被丢弃，不得更新候选列表或触发写入。
  - 不指定具体浏览器库或状态管理实现，只要求有稳定的请求标识与身份键快照比对。
- **失败处理**：判定为过期请求时静默丢弃，不提示用户，不写入字段。

## 3. 字段写入与异常分支伪代码

以下伪代码为方案级描述，不绑定具体框架实现。

```text
// 常量
WHITELIST = ["contactPhone", "occupationCategory", "permanentAddress"]

// 空值判断：仅 null 或空字符串视为空
function isEmptyValue(v):
    return v == null || v == ""

// 字段写入：仅白名单且目标为空时补入
function applyField(target, source):
    if target not in WHITELIST:
        return target  // 禁止写入非白名单字段
    if not isEmptyValue(target):
        return target  // 0、false、非空字符串均保留
    if isEmptyValue(source):
        return target  // 来源为空时保持空值，不制造占位
    return source

// 主流程
function runSupplement(context):
    // context: { name, idNumber, region, formValues, requestId, identitySnapshot }

    // 1. 输入校验
    if isEmptyValue(context.name) || isEmptyValue(context.idNumber):
        return { status: "INPUT_MISSING", message: "请先填写姓名与证件号" }

    // 2. 发起候选查询
    queryResult = queryCandidates(context.name, context.idNumber, context.region, context.requestId)

    // 3. 迟到响应保护
    if context.requestId != currentRequestId || context.identitySnapshot != currentIdentity():
        return { status: "STALE_DROPPED" }  // 静默丢弃

    // 4. 查询失败
    if queryResult.failed:
        return { status: "QUERY_FAILED", message: "本次未执行补值，原数据已保留" }

    // 5. 候选分类
    eligible = []
    unverifiable = []
    regionMismatch = []
    for c in queryResult.candidates:
        if isEmptyValue(c.region):
            unverifiable.append(c)
        else if c.region != context.region:
            regionMismatch.append(c)
        else:
            eligible.append(c)

    // 6. 排序：更新时间降序，时间相同按编号升序
    eligible.sortBy(updateTime desc, recordId asc)

    // 7. 无候选处理
    if eligible.isEmpty():
        if unverifiable.notEmpty():
            return { status: "NO_ELIGIBLE_BUT_UNVERIFIABLE",
                     message: "存在无法核验地区的记录，已排除；本次无可用候选" }
        return { status: "NO_CANDIDATE", message: "未找到可补值候选" }

    // 8. 用户确认
    selected = showConfirmDialog(eligible)  // 展示编号、地区、更新时间、姓名掩码
    if selected == null:
        return { status: "USER_CANCELLED" }  // 不写入任何字段

    // 9. 获取最新详情
    detail = fetchDetail(selected.recordId, context.requestId)

    // 10. 迟到响应保护（详情阶段）
    if context.requestId != currentRequestId || context.identitySnapshot != currentIdentity():
        return { status: "STALE_DROPPED" }

    // 11. 详情失败
    if detail.failed:
        return { status: "DETAIL_FAILED", message: "本次未执行补值，原数据已保留" }

    // 12. 详情编号一致性校验
    if detail.recordId != selected.recordId:
        return { status: "DETAIL_MISMATCH", message: "信息不一致，已停止写入" }

    // 13. 字段写入
    newValues = copy(context.formValues)
    for field in WHITELIST:
        newValues[field] = applyField(context.formValues[field], detail.fields[field])

    return { status: "SUCCESS", values: newValues }
```

**异常分支汇总**

| 分支 | 触发条件 | 处理 |
|---|---|---|
| 输入缺失 | 姓名或证件号为空 | 不查询，提示补全 |
| 查询失败 | 网络或接口错误 | 保留原值，提示未执行补值 |
| 无法核验 | 候选地区缺失 | 排除并单独说明 |
| 明确地区不符 | 候选地区存在但不一致 | 排除 |
| 确无候选 | 地区可核验且无匹配 | 提示无候选，不弹确认框 |
| 用户取消 | 取消/关闭/离开 | 不写入，原值与编辑值保留 |
| 身份键变更 | 姓名或证件号被修改 | 旧候选与旧详情失效 |
| 迟到响应 | 请求标识或身份快照不匹配 | 静默丢弃 |
| 详情编号不一致 | 详情编号 ≠ 已同意编号 | 停止写入，提示信息不一致 |
| 详情失败 | 详情接口错误 | 保留原值，提示未执行补值 |
| 职业类别为 0 | 目标值为 0 | 视为有效原值，不替换 |
| 电话来源为空 | 目标与来源均为空 | 保持空值，不造占位 |

## 5. 待确认项

以下为真正影响任务目标且目前缺失的业务决定，保留为待确认项：

1. 详情接口返回体中记录编号的具体字段名，以及现有响应是否已包含该字段；若未包含，需要在不破坏兼容的前提下补充。
2. 当前用户所属地区在鉴权上下文中的具体字段名与取值格式，用于前端与服务端比对。
3. “无法核验”在 UI 上的具体文案与展示位置，是否需要与“确无候选”“明确地区不符”并列展示。
4. 请求标识的生成方式与生命周期，由前端现有机制决定，本方案不指定具体实现。

以上待确认项不影响本方案已明确的规则与分支处理。
