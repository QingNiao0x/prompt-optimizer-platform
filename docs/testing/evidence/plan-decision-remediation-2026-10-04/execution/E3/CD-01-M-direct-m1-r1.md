# 地区基线自动匹配与表单补值——实现方案（只读分析交付）

## 0. 事实、确认信息与待确认项

**已知事实（来源：`materials/software/current-brief.md`）**
- 匹配使用姓名与证件号两个键，且记录必须符合当前用户所属地区条件；两个条件都满足才属于可补值候选。
- 字段白名单只有联系电话、职业类别、常住地址。
- 已有查询接口返回候选摘要；已有读取单条详情的接口返回补值字段；在用户同意后、写入表单前获取该候选的最新详情。
- 候选按更新时间降序排列，时间相同按记录编号升序排列。
- 只有目标值为 null 或空字符串时才允许补入来源值；0、false 和非空字符串都是有效原值。
- 基础调查：进入编辑状态可按当前姓名与证件号发起候选查询；修改这两个键后旧候选失效。
- 追踪调查：路由参数只定位当前调查记录，不得直接当作基线记录编号；复用服务必须接收明确的身份键与当前地区。
- 候选摘要包含编号、地区、更新时间、姓名掩码；确认框不得展示完整证件号；日志只记录稳定错误类型和请求标识。
- 取消、关闭弹窗、离开编辑页面均不得补写字段；已保存原值与未保存编辑值都不能因取消被清空。
- 地区缺失不等于地区匹配成功；查询接口返回顺序不是授权证据。
- 网络失败提示面向录入人员，说明本次未执行补值且原数据保留，不含内部堆栈、数据库错误文本或上游服务地址。

**用户确认信息**
- 本次为只读分析与方案交付，不产生代码修改、不执行命令、不做数据库迁移、不部署。
- 两个模块（基础调查、追踪调查）必须同时覆盖，复用同一份补值服务。
- 保持现有查询接口、路由和鉴权行为兼容。
- 无候选时不弹确认框；有匹配候选时必须询问用户，不得无确认自动写入。
- 查询或详情失败时保留原值并显示可理解的失败提示，不得伪装为没有匹配记录。

**必要假设（用于方案可落地，非事实）**
- 查询接口与详情接口已存在，本方案只描述调用方式与约束，不新增接口契约。
- 补值服务为后端可复用组件，接收“身份键 + 当前地区 + 候选编号”等显式入参。
- 前端存在可承载“候选列表 / 确认框 / 失败提示”的交互层，本方案不指定具体库。

## 1. 背景与现有调用关系

### 1.1 组件与职责
- **基础调查模块（前端页面）**：编辑状态下持有姓名、证件号、联系电话、职业类别、常住地址等表单字段；可发起候选查询；展示确认框；在用户同意后触发补值写入。
- **追踪调查模块（前端页面）**：路由参数仅用于定位当前调查记录；不得把路由参数当作基线记录编号；通过复用服务显式传入身份键与当前地区。
- **查询接口（已有）**：入参为姓名、证件号、当前地区等；返回候选摘要列表（编号、地区、更新时间、姓名掩码）。
- **详情接口（已有）**：入参为候选编号；返回补值字段（联系电话、职业类别、常住地址等）。
- **补值服务（后端复用组件）**：被两个模块共同调用；接收显式身份键与当前地区；负责候选筛选、排序、详情获取与白名单写入判定；不暗中读取另一页面状态。

### 1.2 调用关系（文字时序）
1. 用户在基础调查或追踪调查页面进入编辑状态。
2. 页面收集当前姓名、证件号、当前用户所属地区，调用**查询接口**。
3. 查询接口返回候选摘要列表；补值服务按“更新时间降序、编号升序”稳定排序。
4. 若无候选：不弹确认框，流程结束。
5. 若有候选：展示确认框（仅展示编号、地区、更新时间、姓名掩码；不展示完整证件号）。
6. 用户同意某条候选后，页面调用**详情接口**获取该候选最新详情。
7. 补值服务校验详情返回的编号与用户同意的编号一致；不一致则停止写入并提示。
8. 一致时，按白名单与空值规则写入联系电话、职业类别、常住地址。
9. 用户取消、关闭弹窗或离开编辑页面：不写入任何字段，已保存原值与未保存编辑值均保留。

### 1.3 兼容性约束
- 不修改现有查询接口、详情接口的路径、入参与返回结构。
- 不修改现有路由定义与鉴权行为。
- 补值服务作为新增复用层，不替换现有接口。

## 2. 两个模块共用的处理步骤

以下步骤为基础调查与追踪调查共用流程；两模块差异仅在“身份键与地区来源”的收集方式。

**步骤 1：收集输入**
- 基础调查：从当前编辑表单读取姓名、证件号；地区取当前用户所属地区。
- 追踪调查：从当前调查记录读取姓名、证件号；地区取当前用户所属地区；路由参数仅用于定位当前调查记录，不参与身份键构造。
- 校验：姓名、证件号、地区任一为空或非法时，不发起候选查询，提示录入人员补全。

**步骤 2：发起候选查询**
- 调用查询接口，显式传入姓名、证件号、当前地区。
- 记录本次请求标识（用于日志与迟到响应判定）。

**步骤 3：处理查询结果**
- 查询失败：保留原值，显示面向录入人员的失败提示（本次未执行补值，原数据保留），不伪装为“无匹配”。
- 查询成功且无候选：不弹确认框，流程结束。
- 查询成功且有候选：按“更新时间降序、编号升序”稳定排序；分页或重试后顺序必须一致。

**步骤 4：地区条件判定**
- 候选地区与当前用户所属地区一致：属于可补值候选。
- 候选地区明确不符：排除，不计入可补值候选。
- 候选地区缺失、无法核验：按待确认项处理（见第 0 节），不得默认视为匹配成功。
- 查询接口返回顺序不作为授权证据。

**步骤 5：展示确认框**
- 仅展示编号、地区、更新时间、姓名掩码。
- 不展示完整证件号。
- 无候选时不弹确认框。

**步骤 6：用户同意后获取最新详情**
- 用户同意某条候选编号后，调用详情接口获取该候选最新详情。
- 详情失败：保留原值，显示面向录入人员的失败提示，不伪装为“无匹配”。

**步骤 7：编号一致性校验**
- 详情返回编号与用户同意编号不一致：停止写入，提示信息不一致；不得因部分字段相似而接受。

**步骤 8：白名单与空值写入**
- 仅允许写入联系电话、职业类别、常住地址。
- 仅当目标值为 null 或空字符串时补入来源值。
- 0、false、非空字符串均为有效原值，必须保留。
- 目标为空且来源也为空：保持空值，不制造占位值。

**步骤 9：取消与离开**
- 用户取消、关闭弹窗、离开编辑页面：不写入任何字段。
- 已保存原值与当前未保存编辑值均不得因取消动作被清空。

**步骤 10：时序保护**
- 用户在候选请求未结束时再次修改姓名（或证件号）：旧请求的迟到响应必须失效，不得用于展示候选或写入。
- 本方案只描述该要求，不指定具体浏览器库或状态管理实现。

**步骤 11：日志与隐私**
- 日志只记录稳定错误类型与请求标识。
- 不记录姓名、证件号原文。
- 不记录密码、Token、API Key、私钥。
- 不读取或输出受保护路径：`.env`、`**/*.pem`、`**/*.key`、生产环境配置。

## 3. 字段写入与异常分支伪代码

> 说明：以下为方案级伪代码，用于表达逻辑与分支，不代表可直接运行的实现；不涉及具体框架 API。

### 3.1 主流程

```
function fillFromBaseline(module, form, identity, region, requestId):
    # 输入校验
    if isBlank(identity.name) or isBlank(identity.idNo) or isBlank(region):
        return Fail("请补全姓名、证件号与地区后再发起补值")

    # 发起候选查询
    queryResult = queryCandidates(identity.name, identity.idNo, region, requestId)

    if queryResult.isError:
        # 查询失败：保留原值，提示未执行补值
        return Fail("本次未执行补值，原数据已保留，请稍后重试")

    candidates = queryResult.list

    # 地区条件判定
    eligible = []
    for c in candidates:
        if c.region is missing:
            # 待确认项：不得默认视为匹配成功
            handleUnverifiable(c)   # 见 3.4
        else if c.region == region:
            eligible.append(c)
        else:
            # 明确地区不符：排除
            continue

    if eligible.isEmpty:
        # 无候选：不弹确认框
        return NoCandidate

    # 稳定排序：更新时间降序，编号升序
    eligible.sortBy(updateTime desc, recordId asc)

    # 展示确认框（仅编号、地区、更新时间、姓名掩码）
    chosen = showConfirmDialog(eligible)
    if chosen is null:
        # 用户取消：不写入，保留原值与编辑值
        return Cancelled

    # 用户同意后获取最新详情
    detail = getCandidateDetail(chosen.recordId, requestId)
    if detail.isError:
        return Fail("本次未执行补值，原数据已保留，请稍后重试")

    # 编号一致性校验
    if detail.recordId != chosen.recordId:
        return Fail("候选信息不一致，已停止写入，请重新选择")

    # 白名单与空值写入
    writeWhitelistFields(form, detail)
    return Success
```

### 3.2 白名单与空值写入

```
function writeWhitelistFields(form, detail):
    # 仅三个白名单字段
    applyIfTargetEmpty(form.phone,        detail.phone)
    applyIfTargetEmpty(form.occupation,   detail.occupation)
    applyIfTargetEmpty(form.residenceAddr, detail.residenceAddr)

function applyIfTargetEmpty(target, source):
    # 仅当目标为 null 或空字符串时补入
    if target is null or target == "":
        if source is null or source == "":
            # 来源也为空：保持空值，不制造占位值
            return
        target = source
    else:
        # 0、false、非空字符串均为有效原值，保留
        return
```
