## 1. 研究问题与假设

### 1.1 研究问题

**主研究问题**：在提示词增强任务中，“先让用户回答关键问题再增强提示词”（以下简称“提问增强”）与“不提问直接增强提示词”（以下简称“直接增强”）两种流程，在提示词质量、任务完成度和用户满意度上是否存在差异？

**次级研究问题**：
- 提问增强是否在“用户原始需求表达不充分”的场景下优势更明显？
- 提问增强所增加的时间成本是否被其带来的质量提升所抵消（即效率-效果权衡）？
- 用户对两种流程的主观体验（认知负担、控制感、信任度）有何差异？

### 1.2 研究假设

**[假设]** 基于方法学推理（非既有数据），提出以下待检验假设：

- **H1（质量假设）** ：提问增强产出的最终提示词在盲评质量得分上高于直接增强。
- **H2（完成度假设）** ：使用提问增强产出的提示词执行原始任务时，任务完成度更高。
- **H3（满意度假设）** ：用户对提问增强流程的满意度不低于直接增强（非劣效），且在“需求被理解”维度上显著更高。
- **H4（调节假设）** ：原始任务表述的模糊程度调节两种流程的效果差异——模糊度越高，提问增强的优势越大。
- **H5（成本假设）** ：提问增强的总耗时显著高于直接增强，但单位时间产出质量（质量/分钟）不一定更低。

### 1.3 假设的检验逻辑

所有假设均为**双侧检验**，不预设方向（H3中“非劣效”部分除外）。若H1-H3均未获支持，则说明提问增强的增量价值有限，需进一步分析适用条件。


## 2. 参与者招募与样本量

### 2.1 参与者角色

本研究涉及两类参与者角色：

| 角色 | 任务 | 人数 |
|------|------|------|
| **提示词使用者（主参与者）** | 提供原始任务需求，接受增强流程，评估结果 | 核心样本 |
| **盲评评分者** | 对最终提示词质量进行独立评分（不知晓来源条件） | 3-5人 |

### 2.2 招募来源

**[假设]** 建议以下招募渠道（按优先级排序）：

1. **内部用户池/产品用户群**：若研究背景涉及某AI产品或平台，优先从其活跃用户中招募，确保参与者有真实的提示词使用需求。
2. **专业社区**：通过AI工具使用者社区、提示词工程学习群组、技术论坛发布招募信息。
3. **众包平台**：如Prolific、Amazon Mechanical Turk（需筛选有AI工具使用经验者），或国内等效平台。
4. **高校/研究机构合作**：若涉及学术场景，可通过课程或实验室招募。

### 2.3 纳入标准

**[假设]** 建议纳入标准：

- 年龄≥18岁
- 过去3个月内至少使用过一种大语言模型工具（如ChatGPT、Claude、文心一言等）≥5次
- 能提供至少一个真实的、自己需要完成的文本类任务（非虚构）
- 具备基本的文字表达能力（以完成招募问卷中的开放式问题为筛查）

**排除标准**：

- 提示词工程专业从业者（如以提示词优化为职业者），因其专业水平可能产生天花板效应
- 无法用研究指定语言完成任务的个体

### 2.4 样本量估算

**[假设]** 由于无既有效应量数据，采用以下方法估算：

**方法：基于最小可检测效应量（MDE）的估算**

- 设显著性水平 α = 0.05（双侧）
- 设统计功效 1-β = 0.80
- 若采用**组间设计**：假设中等效应量 Cohen's d = 0.50，每组需约 **64人**，两组共 **128人**。考虑20%流失率，建议招募 **160人**。
- 若采用**组内设计**（推荐，见第4节）：假设中等效应量 Cohen's d = 0.50，需约 **34人**。考虑20%流失率，建议招募 **42-50人**。

**可调整说明**：若预试验（n=8-10）显示效应量偏小（d < 0.30），需将样本量上调至组内设计约 **90-100人**；若效应量偏大（d > 0.80），可适当减少。**预试验数据仅用于校准样本量，不纳入正式分析。**


## 3. 测试任务与材料

### 3.1 任务来源

**[用户确认]** 研究比较的是两种提示词增强流程，测试任务应为用户真实需要完成的原始任务。

**推荐方案：混合任务集**

| 任务类型 | 占比 | 获取方式 | 目的 |
|----------|------|----------|------|
| **用户自带真实任务** | 60% | 参与者在招募阶段提交1-2个自己近期需要完成的真实文本任务（如写邮件、写报告、做总结、写文案等） | 保证生态效度 |
| **标准化任务** | 40% | 研究者预设的任务场景描述（如“帮我写一封向房东申请维修的邮件”“总结以下三段文字的要点”），所有参与者使用相同任务 | 保证可比性 |

### 3.2 标准化任务的获取

**[假设]** 标准化任务由研究团队在预试验阶段编制，来源为：

- 研究者根据常见提示词使用场景编写任务描述
- 任务描述**故意保留一定模糊性**（如缺少关键细节），以模拟真实用户初次表达需求时的状态
- 每个标准化任务附带一份**“补充信息卡”**（见3.3），包含完成任务所需但任务描述中未提及的关键信息

### 3.3 关键材料：补充信息卡

**[用户确认]** 公平性约束要求：两组接收并可使用同一原始任务与同一份实际确认信息；不追问不等于不能使用已提供答案。

**材料设计**：

- 每个测试任务（无论用户自带还是标准化）均配有一份**“补充信息卡”**，内容为完成该任务所需的关键背景信息（如目标受众、语气偏好、长度要求、关键事实等）。
- **信息卡的信息量在两组间完全相同**。
- 信息卡在实验中的呈现方式因条件而异（见第4.3节），但**内容不因条件而改变**。

**示例（标准化任务）** ：

> **原始任务描述**：“帮我写一封邮件，向我的房东说明需要维修热水器。”
>
> **补充信息卡**：
> - 收件人：房东（姓王，关系一般，平时沟通较正式）
> - 热水器已坏3天，期间无热水可用
> - 你已尝试电话联系但未接通
> - 希望本周内安排维修
> - 你的可用时间：工作日晚6点后、周末全天
> - 期望语气：礼貌但坚定

### 3.4 任务模糊度分级

**[假设]** 为检验H4（调节假设），每个任务在预试验阶段由2-3名研究者独立评定“初始表述模糊度”（1-5分，1=信息充分，5=信息严重缺失）。取均值作为该任务的模糊度标签。分析时可将模糊度作为连续调节变量或按中位数分为高/低模糊组。


## 4. 实验设计与比较条件

### 4.1 设计类型：组内设计（推荐）

**推荐理由**：

- 参与者个体差异（提示词使用经验、表达能力、任务类型偏好）对结果影响较大，组内设计可控制个体差异
- 样本量需求更小，可行性更高
- 每位参与者可对两种流程提供直接对比体验

**设计结构**：

- 每位参与者完成 **2个任务**（或2组任务），分别经历两种增强流程
- **条件顺序随机平衡**：一半参与者先经历“提问增强”再经历“直接增强”，另一半顺序相反
- **任务-条件配对随机**：每个任务被分配到哪种条件下也是随机的（在参与者间平衡）

### 4.2 两种比较条件

#### 条件A：先提问再增强（“提问增强”）

**流程**：

1. 参与者提交原始任务描述
2. 系统/研究者基于任务类型和内容，向参与者提出 **3-5个关键问题**（问题来源见第5节）
3. 参与者回答这些问题（可跳过，但需标注“跳过”）
4. 增强器基于“原始任务描述 + 参与者回答”生成增强后的提示词
5. 参与者查看增强结果，可进行**一轮**微调（两种条件下微调机会相同）
6. 参与者使用最终提示词执行任务（或由研究者代为执行）

#### 条件B：直接增强（“直接增强”）

**流程**：

1. 参与者提交原始任务描述
2. 增强器基于“原始任务描述 + 补充信息卡内容”直接生成增强后的提示词
3. 参与者查看增强结果，可进行**一轮**微调（与条件A相同）
4. 参与者使用最终提示词执行任务（或由研究者代为执行）

### 4.3 公平性保障措施

**[用户确认]** 公平性须落实到信息流。具体措施如下：

| 公平性维度 | 保障措施 |
|------------|----------|
| **信息量对等** | 条件A中，参与者通过回答问题提供的信息，在内容上等同于条件B中补充信息卡所包含的信息。即：**条件A的关键问题旨在引导参与者主动提供补充信息卡中的同类信息**。 |
| **信息可用性对等** | 条件B中，补充信息卡的内容**明确提供给增强器使用**，增强器在生成增强提示词时必须纳入信息卡中的关键信息。条件A中，参与者的回答**同样提供给增强器使用**。两组增强器获得的信息内容实质相同，区别仅在于获取方式（主动提问 vs. 直接提供）。 |
| **任务相同** | 两组使用同一批原始任务（同一参与者的同一任务在不同条件下不重复使用；标准化任务在参与者间平衡分配）。 |
| **修订轮次相同** | 两种条件下参与者均只有**一轮**微调机会，不额外增加某组的修订轮次。 |
| **增强器相同** | 两种条件使用**同一个增强器**（同一模型、同一系统提示词框架），仅输入信息的组织方式不同。 |
| **时间控制** | 记录但不限制各环节耗时。分析时将耗时作为协变量或次要结果，而非通过限制时间来人为制造公平。 |

### 4.4 信息流的操作化定义

**条件A（提问增强）的信息流**：

```
原始任务描述 → [增强器生成关键问题] → 参与者回答 → [增强器整合：原始描述 + 回答] → 增强提示词 → 参与者一轮微调 → 最终提示词
```

**条件B（直接增强）的信息流**：

```
原始任务描述 + 补充信息卡 → [增强器整合：原始描述 + 信息卡] → 增强提示词 → 参与者一轮微调 → 最终提示词
```

**关键对等点**：条件A中参与者回答所覆盖的信息域 ≈ 条件B中补充信息卡所覆盖的信息域。两者在信息内容上设计为等价，区别仅在于信息获取的交互方式。


## 5. 关键问题生成流程

### 5.1 问题由谁生成

**[假设]** 推荐采用**“增强器自动生成 + 研究者预校准”**的混合方式：

| 步骤 | 执行者 | 说明 |
|------|--------|------|
| 问题框架设计 | 研究者 | 在预试验阶段确定问题生成的规则和约束（如问题数量、类型、禁止询问的信息类别） |
| 问题实时生成 | 增强器（LLM） | 在实验过程中，由增强器根据原始任务描述自动生成3-5个关键问题 |
| 问题质量预校准 | 研究者 | 在预试验阶段（n=8-10）检查增强器生成问题的质量，调整生成提示词中的约束条件 |

**不推荐**由研究者为每个任务手工预设问题，因为：
- 无法覆盖用户自带任务的多样性
- 手工预设可能引入研究者偏倚
- 实际产品场景中问题通常由系统自动生成

**不推荐**由用户自选问题，因为：
- 用户可能不知道什么信息对增强提示词最重要
- 自选问题会引入额外的个体差异，降低可比性

### 5.2 问题数量与内容约束

**[假设]** 建议：

- **问题数量**：固定为 **4个**（预试验后可在3-5之间调整，但正式实验中须固定）
- **问题类型约束**：
  - 必须与补充信息卡中的信息域对应（即问题旨在引导用户提供信息卡中同类信息）
  - 问题应为开放式问题（非是/否），以获取丰富信息
  - 问题应聚焦于任务完成所必需的关键信息，不询问无关细节
  - 禁止询问敏感个人信息（见第8节伦理考虑）
- **问题生成提示词框架**（供增强器使用）：

> “基于用户的原始任务描述，生成4个关键问题，用于获取完成任务所必需但当前描述中缺失的信息。问题应覆盖：目标受众、格式/长度要求、语气风格、关键事实/背景。问题应为开放式，简洁明了，每个问题不超过25字。”

### 5.3 问题质量检查清单

预试验阶段，研究者对增强器生成的问题进行质量评估：

- [ ] 每个问题是否对应补充信息卡中的一个信息域？
- [ ] 问题是否清晰无歧义？
- [ ] 问题是否避免了引导性表述（如“你是不是想要正式一点的语气？”）？
- [ ] 4个问题之间是否无重复？
- [ ] 问题是否不涉及敏感信息？


## 6. 结果指标与测量方法

### 6.1 主要结果指标

#### 指标1：提示词质量盲评得分（主要指标）

**测量方式**：将两种条件下产出的最终提示词（去除任何条件标识）交由3-5名盲评评分者独立评分。

**评分维度**（1-7分李克特量表，每个维度单独评分）：

| 维度 | 定义 | 评分锚点 |
|------|------|----------|
| **清晰度** | 提示词表达是否明确、无歧义 | 1=非常模糊，7=非常清晰 |
| **完整性** | 是否包含完成任务所需的关键信息 | 1=严重缺失，7=信息完整 |
| **可执行性** | 是否可直接用于执行任务而无需额外补充 | 1=不可执行，7=可直接执行 |
| **结构合理性** | 信息组织是否有逻辑、有条理 | 1=混乱，7=结构清晰 |

**总分**：4个维度得分之和（范围4-28分），或取均值（范围1-7分）。

**盲评保障**：
- 评分者不知晓每条提示词来自哪种条件
- 提示词呈现顺序随机化
- 评分者之间的一致性用组内相关系数（ICC）评估，ICC < 0.60时需讨论评分标准或增加评分者

#### 指标2：任务完成度（主要指标）

**测量方式**：使用最终提示词在**同一LLM**上执行原始任务，由盲评评分者对任务输出结果进行评分。

**评分维度**（1-7分）：

| 维度 | 定义 |
|------|------|
| **需求满足度** | 输出结果多大程度上满足了原始任务的核心需求 |
| **信息准确度** | 输出中使用的关键事实是否准确（对照补充信息卡） |
| **可用性** | 输出结果是否可直接使用或仅需少量修改 |

**总分**：3个维度得分之和（范围3-21分），或取均值。

#### 指标3：用户满意度（主要指标）

**测量方式**：参与者在完成每种条件后立即填写满意度问卷。

**问卷维度**（1-7分）：

| 维度 | 示例条目 |
|------|----------|
| **总体满意度** | “总体而言，我对这次提示词增强的结果感到满意” |
| **需求被理解感** | “我觉得增强流程理解了我的真实需求” |
| **控制感** | “我觉得自己对增强过程有足够的控制” |
| **信任度** | “我愿意信任这个增强流程产出的提示词” |
| **认知负担** | “这个增强流程让我感到费劲”（反向计分） |

### 6.2 次要结果指标

| 指标 | 测量方式 | 目的 |
|------|----------|------|
| **总耗时** | 从提交原始任务到获得最终提示词的时间（分钟），分环节记录 | 检验H5（效率-效果权衡） |
| **微调幅度** | 参与者在微调轮次中对增强提示词的修改程度（由研究者按1-3分评定：1=几乎未改，3=大幅修改） | 间接反映增强结果的初始质量 |
| **跳过率** | 条件A中参与者跳过问题的比例 | 反映提问环节的实际参与度 |
| **单位时间质量** | 提示词质量盲评得分 ÷ 总耗时 | 效率指标 |

### 6.3 测量时间点

| 时间点 | 测量内容 |
|--------|----------|
| 招募阶段 | 人口学信息、LLM使用经验、自带任务提交 |
| 条件A完成后 | 满意度问卷（条件A版）、耗时记录 |
| 条件B完成后 | 满意度问卷（条件B版）、耗时记录 |
| 全部完成后 | 两种流程的对比偏好（开放式问题+强制选择） |
| 实验结束后 | 盲评评分（提示词质量、任务完成度） |


## 7. 数据分析计划

### 7.1 数据预处理

- 检查缺失数据：若某参与者的某个主要指标缺失，该参与者的该指标数据不纳入对应分析（成对删除），并在报告中说明缺失率
- 检查盲评评分者一致性：计算ICC，若ICC < 0.50，需重新培训评分者或修订评分标准后重新评分
- 离群值检查：使用箱线图识别极端值，若某数据点超过1.5×IQR，进行敏感性分析（含/不含该数据点）

### 7.2 主要分析

**分析单元**：任务-条件组合（每位参与者贡献2个数据点，分别对应两种条件）。

**主效应分析**（检验H1-H3）：

| 假设 | 统计方法 | 说明 |
|------|----------|------|
| H1（提示词质量） | 线性混合模型（LMM）或配对t检验 | 因变量=盲评质量总分；固定效应=条件（A vs. B）；随机效应=参与者、任务、评分者 |
| H2（任务完成度） | 线性混合模型（LMM）或配对t检验 | 因变量=完成度总分；固定效应=条件；随机效应=参与者、任务、评分者 |
| H3（满意度） | 配对t检验或Wilcoxon符号秩检验 | 因变量=各满意度维度得分；若数据非正态则用非参数方法 |

**推荐使用线性混合模型**，理由：
- 可同时纳入参与者和任务的随机效应
- 可处理组内设计中的非独立性
- 可纳入协变量（如任务模糊度、参与者经验）

**模型示例**（以H1为例）：

```
质量得分 ~ 条件 + 任务模糊度 + 条件×任务模糊度 + LLM使用经验 + (1|参与者) + (1|任务) + (1|评分者)
```

### 7.3 调节效应分析（检验H4）

- 在LMM中加入“条件 × 任务模糊度”交互项
- 若交互项显著，进一步做简单斜率分析（高模糊度 vs. 低模糊度条件下两种流程的差异）
- 可视化：绘制交互效应图

### 7.4 效率分析（检验H5）

- 配对t检验比较两种条件的总耗时
- 计算单位时间质量（质量得分/耗时），配对比较
- 若提问增强质量更高但耗时也更长，计算“质量提升幅度/时间增加幅度”的比值，讨论实际意义

### 7.5 补充分析

- **顺序效应检验**：在LMM中加入“条件顺序”作为协变量，检验是否存在遗留效应
- **敏感性分析**：排除跳过≥2个问题的参与者后重新分析（检验提问环节参与度对结果的影响）
- **亚组分析**：按参与者LLM使用经验（高/低）分层分析

### 7.6 统计软件与报告规范

- 推荐使用R（lme4包用于LMM）或Python（statsmodels）
- 报告效应量（Cohen's d或标准化β）及其95%置信区间
- 报告所有预注册的分析，区分“预注册分析”和“探索性分析”
- 显著性水平α=0.05，多重比较时使用Holm-Bonferroni校正

## 10. 适用条件与局限性

### 10.1 适用条件

本方案在以下条件下适用性最佳：

| 条件 | 说明 |
|------|------|
| **任务类型** | 文本生成类任务（写作、总结、翻译、邮件等），不适用于代码生成、图像生成等非文本任务 |
| **增强器类型** | 基于LLM的提示词增强器，具备生成问题和整合信息的能力 |
| **用户特征** | 用户有真实任务需求，且愿意花时间参与交互式增强流程 |
| **语言环境** | 方案默认使用单一语言；跨语言场景需额外设计 |
| **信息对等可行性** | 补充信息卡能够预先定义，且关键问题能够引导用户提供同类信息 |

### 10.2 局限性

**[假设]** 以下局限性为方法学层面的预期限制，需在报告中如实讨论：

1. **生态效度限制**：实验环境中参与者可能比真实使用场景更耐心（回答问题的意愿更高），提问增强的效果可能被高估。
2. **信息对等的理想化**：实际操作中，参与者回答问题的信息量可能与补充信息卡不完全对等（可能更多或更少），尽管设计上力求对等，但无法完全控制。
3. **单轮微调的人为限制**：真实场景中用户可能进行多轮迭代，本方案限制为一轮以保证公平，但可能低估两种流程在多轮迭代下的差异。
4. **增强器固定效应**：结果可能依赖于所使用的特定增强器（LLM模型和提示词框架），推广到其他增强器时需谨慎。
5. **任务类型覆盖有限**：标准化任务集不可能覆盖所有提示词使用场景，结论的推广范围受限于所纳入的任务类型。
6. **盲评评分的主观性**：尽管采用多评分者和标准化评分标准，提示词质量评分仍存在主观性。
7. **样本代表性**：招募来源可能偏向于对AI工具较熟悉的用户，结论对新手用户的适用性需进一步验证。
8. **无长期效果测量**：本方案仅测量单次使用的即时效果，无法评估两种流程对用户长期提示词能力的影响。

### 10.3 可调整处

| 参数 | 默认值 | 可调整范围 | 调整依据 |
|------|--------|------------|----------|
| 关键问题数量 | 4个 | 3-5个 | 预试验中问题质量评估结果 |
| 样本量 | 42-50人（组内） | 34-100人 | 预试验效应量估算 |
| 微调轮次 | 1轮 | 0-2轮 | 研究目的（若关注初始增强质量，可设为0轮） |
| 标准化任务占比 | 40% | 0-100% | 研究重心（生态效度 vs. 内部效度） |
| 盲评评分者数量 | 3-5人 | 2-6人 | 资源可用性和ICC评估结果 |
| 评分量表 | 1-7分 | 1-5分或1-9分 | 评分者区分能力 |
