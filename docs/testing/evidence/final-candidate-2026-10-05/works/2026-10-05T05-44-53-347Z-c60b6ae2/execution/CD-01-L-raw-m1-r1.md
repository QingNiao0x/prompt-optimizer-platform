# 地区基线自动匹配与表单补值实现方案

## 一、背景与现有调用关系

### 1.1 业务背景

本方案面向一套合成的公共卫生调查录入系统，覆盖两个调查模块：

- **基础调查**：页面进入编辑状态时，可依据当前已有的姓名与证件号发起候选查询。
- **追踪调查**：页面路由参数仅用于定位当前调查记录，不得直接当作基线记录编号。

两个模块复用同一份补值服务。补值服务接收明确的身份键（姓名、证件号）与当前用户所属地区，不读取任何页面状态或路由参数作为隐式输入。

### 1.2 现有接口与调用关系

| 接口 | 职责 | 返回内容 |
| --- | --- | --- |
| 候选查询接口 | 按姓名 + 证件号 + 当前地区条件检索候选 | 候选摘要列表：编号、地区、更新时间、姓名掩码 |
| 单条详情接口 | 按候选编号读取补值字段 | 补值字段：联系电话、职业类别、常住地址 |

调用时序：

1. 页面进入编辑状态 → 以当前姓名、证件号、当前地区发起候选查询。
2. 用户修改姓名或证件号 → 旧候选失效，重新查询。
3. 有候选 → 弹确认框（展示摘要，不展示完整证件号）。
4. 用户同意 → 在写入前调用详情接口获取该候选最新详情。
5. 详情编号与已同意候选编号一致 → 按字段白名单与空值规则写入。
6. 详情编号不一致 → 停止写入并提示信息不一致。

### 1.3 兼容性边界

- 保持现有查询接口、路由和鉴权行为不变。
- 不新增数据库迁移，不修改现有表结构。
- 补值服务为两个模块共用，不针对单一模块做特化分支。

## 二、两个模块共用的处理步骤

### 2.1 候选查询阶段

1. 接收显式输入：姓名、证件号、当前用户所属地区。
2. 按姓名 + 证件号 + 地区条件检索候选。
3. 排序规则：更新时间降序；更新时间相同时按记录编号升序。
4. 返回候选摘要列表（编号、地区、更新时间、姓名掩码）。
5. 地区信息缺失或无法核验的候选，单独标记为“无法核验”，不并入“确无候选”，也不并入“明确地区不符”。

### 2.2 用户确认阶段

1. 无候选 → 不弹确认框。
2. 有候选 → 必须弹确认框，展示摘要信息，不展示完整证件号。
3. 用户取消、关闭弹窗或离开编辑页面 → 不写入任何字段，已保存原值与未保存编辑值均保持不变。

### 2.3 详情获取与写入阶段

1. 用户同意后，写入前调用详情接口获取该候选最新详情。
2. 校验详情返回的候选编号与已同意候选编号一致。
3. 一致 → 按字段白名单与空值规则写入。
4. 不一致 → 停止写入，提示信息不一致。
5. 查询或详情失败 → 保留原值，显示面向录入人员的失败提示，不伪装为“没有匹配记录”。

### 2.4 时序保护

- 用户在候选请求未结束时再次修改姓名 → 迟到的旧请求必须失效。
- 实现方式不限定具体浏览器库或状态管理方案，但需保证请求与当前身份键绑定，旧响应到达时若身份键已变更则丢弃。

## 三、字段写入与异常分支伪代码

### 3.1 字段白名单

| 字段 | 类型 | 写入条件 |
| --- | --- | --- |
| 联系电话 | 字符串 | 目标为 null 或空字符串，且来源有值 |
| 职业类别 | 数值 | 目标为 null 或空字符串，且来源有值；0 为有效原值 |
| 常住地址 | 字符串 | 目标为 null 或空字符串，且来源有值 |

禁止写入其他表单字段。目录中的演示字段、附件中的其他地址种类（户籍地址、单位地址、紧急联系人地址）均不在本次范围。

### 3.2 空值判断规则

- 允许补入的条件：目标值为 `null` 或空字符串 `""`。
- 以下均为有效原值，必须保留：`0`、`false`、非空字符串。
- 职业类别为数值 `0` 时，不得因 JavaScript 假值判断触发替换；必须使用显式空值比较，而非逻辑或表达式。

### 3.3 伪代码

```text
// 候选查询
function queryCandidates(name, idNumber, region, requestToken):
    if name is empty or idNumber is empty:
        return NO_CANDIDATES

    response = callCandidateQuery(name, idNumber, region)

    if response failed:
        return QUERY_FAILED

    if requestToken is stale:
        return STALE_REQUEST_DISCARDED

    candidates = response.candidates
    sort candidates by updatedAt desc, recordId asc

    verified = []
    unverifiable = []
    for each candidate in candidates:
        if candidate.region is missing or cannot be verified:
            unverifiable.append(candidate)
        else if candidate.region matches current region:
            verified.append(candidate)
        else:
            // 明确地区不符，不进入候选
            continue

    return { verified, unverifiable }
```

```text
// 用户确认与写入
function applyBaseline(selectedCandidate, currentForm, requestToken):
    if selectedCandidate is null:
        return NO_CONFIRMATION_NEEDED

    if user cancelled or closed dialog or left page:
        return CANCELLED_NO_WRITE

    detail = callCandidateDetail(selectedCandidate.id)

    if detail failed:
        showUserMessage("本次未执行补值，原数据已保留")
        return DETAIL_FAILED

    if requestToken is stale:
        return STALE_REQUEST_DISCARDED

    if detail.recordId != selectedCandidate.id:
        showUserMessage("候选信息不一致，已停止补值")
        return ID_MISMATCH

    newForm = copy(currentForm)

    // 联系电话
    if isNullOrEmpty(newForm.phone) and not isNullOrEmpty(detail.phone):
        newForm.phone = detail.phone

    // 职业类别：显式空值比较，0 为有效原值
    if isNullOrEmpty(newForm.occupation) and not isNullOrEmpty(detail.occupation):
        newForm.occupation = detail.occupation

    // 常住地址
    if isNullOrEmpty(newForm.address) and not isNullOrEmpty(detail.address):
        newForm.address = detail.address

    return newForm
```

```text
// 空值判断
function isNullOrEmpty(value):
    return value is null or value is empty string

// 注意：0、false、非空字符串均返回 false，视为有效原值
```

### 3.4 异常分支汇总

| 分支 | 处理 |
| --- | --- |
| 无候选 | 不弹确认框，不写入 |
| 有候选 | 必须弹确认框 |
| 用户取消 / 关闭弹窗 / 离开页面 | 不写入，原值与编辑值均保留 |
| 查询失败 | 保留原值，提示“本次未执行补值，原数据已保留” |
| 详情失败 | 保留原值，提示“本次未执行补值，原数据已保留” |
| 详情编号不一致 | 停止写入，提示信息不一致 |
| 迟到旧请求 | 丢弃，不写入 |
| 地区缺失 / 无法核验 | 单独标记，不并入“确无候选”或“明确地区不符” |
| 目标已有值 | 不覆盖，即使来源更新 |
| 目标为空且来源为空 | 保持空值，不制造占位号码 |

### 3.5 日志与提示

- 日志只记录稳定错误类型和请求标识，不记录姓名或证件号原文。
- 网络失败提示面向录入人员，说明本次未执行补值且原数据保留；不附带内部堆栈、数据库错误文本或上游服务地址。
