# 地区基线自动匹配与表单补值实现方案

> 合成资料、只读分析。本文只交付方案、关键伪代码与测试清单，不运行命令、不修改项目、不部署，也不构成实际软件开发业务验收或专业有效性认证。

## 1. 背景与现有调用关系

### 1.1 术语

- **补值服务**：两个调查模块共用的同一份服务，负责候选查询、候选摘要、详情读取、字段写入判定。
- **身份键**：姓名 + 证件号，两个键同时参与匹配。
- **地区条件**：记录必须符合当前用户所属地区，才属于可补值候选。
- **字段白名单**：联系电话、职业类别、常住地址。仅这三个字段允许写入。
- **空值**：目标值为 `null` 或空字符串 `""`。`0`、`false`、非空字符串都是有效原值。

### 1.2 两个模块如何复用同一补值服务

| 模块 | 入口 | 传给补值服务的输入 | 路由参数的作用 |
|---|---|---|---|
| 基础调查 | 进入编辑状态 | 当前已有的姓名、证件号、当前地区 | 无（不依赖路由参数定位基线） |
| 追踪调查 | 进入编辑状态 | 当前已有的姓名、证件号、当前地区 | 仅定位当前调查记录，**不得**当作基线记录编号 |

复用方式：两个模块都调用同一补值服务，服务只接收**显式传入**的身份键与当前地区，不暗中读取另一个页面的状态。追踪调查的路由参数只用于定位当前调查记录，不能直接作为基线记录编号传给服务。

### 1.3 现有接口与行为（保持兼容）

- **查询接口**：返回候选摘要（编号、地区、更新时间、姓名掩码）。现有查询接口、路由、鉴权行为保持不变。
- **详情接口**：读取单条详情，返回补值字段。在用户同意后、写入表单前调用，获取该候选的最新详情。
- **鉴权**：沿用现有鉴权行为，本次不改动。

## 2. 两个模块共用的处理步骤

按以下顺序组织，基础调查与追踪调查共用：

1. **候选查询**
   - 进入编辑状态时，用当前已有的姓名、证件号、当前地区发起查询。
   - 追踪调查中，路由参数只定位当前调查记录，不当作基线记录编号。
   - 用户修改姓名或证件号后，之前的候选立即失效，不能沿用旧身份对应的详情。
   - 候选请求未结束时再次修改姓名，迟到的旧请求必须失效（时序保护，见第 3 节）。

2. **候选摘要展示**
   - 摘要包含：编号、地区、更新时间、姓名掩码。
   - 确认框不得展示完整证件号。
   - 排序：更新时间降序；时间相同按记录编号升序；分页或重试后顺序稳定。
   - 无候选时不弹确认框；有匹配候选时必须询问用户，不得无确认自动写入。

3. **用户确认**
   - 用户选定一条候选并同意后，记录该候选编号，进入写入前校验。
   - 用户取消、关闭弹窗或离开编辑页面：不补写任何字段，已保存原值与未保存编辑值都不被清空。

4. **写入前获取最新详情**
   - 在用户同意后、写入表单前，调用详情接口获取该候选的最新详情。
   - 校验详情返回的编号与已同意候选编号一致；不一致则停止写入并提示信息不一致。

5. **字段补值**
   - 仅对白名单字段（联系电话、职业类别、常住地址）判定。
   - 仅当目标值为 `null` 或空字符串时，才允许补入来源值。
   - `0`、`false`、非空字符串保留，不覆盖。

6. **取消与异常分支**
   - 取消/关闭/离开：不写入，原值与编辑值保留。
   - 查询或详情失败：保留原值，显示面向录入人员的失败提示，不伪装为没有匹配记录。
   - 网络失败提示：说明本次未执行补值且原数据保留，不带内部堆栈、数据库错误文本或上游服务地址。
   - 地区缺失、确无候选、明确地区不符：三种情况分别说明（见第 3 节与第 5 节）。

## 3. 字段写入与异常分支伪代码

> 说明：伪代码为方案表达，不指定具体浏览器库或状态管理实现。日志只记录稳定错误类型和请求标识，不记录姓名或证件号原文。

```text
// 常量
WHITELIST = ["联系电话", "职业类别", "常住地址"]

// 空值判断：仅 null 或空字符串视为空
function isEmpty(v):
    return v == null OR v == ""

// 候选查询（含时序保护）
function queryCandidates(identityKeys, currentRegion, requestToken):
    // identityKeys = { name, idNumber }
    // currentRegion 由调用方显式传入，不读取其他页面状态
    if identityKeys.name is empty OR identityKeys.idNumber is empty:
        return NO_CANDIDATE   // 无候选，不弹确认框
    if currentRegion is missing:
        return REGION_UNVERIFIABLE   // 地区缺失，不等于匹配成功

    resp = callQueryApi(identityKeys, currentRegion, requestToken)
    if resp.failed:
        return QUERY_FAILED   // 保留原值，提示失败，不伪装为无匹配

    // 迟到的旧请求失效：仅当 requestToken 仍为当前有效令牌时才接受
    if requestToken != currentRequestToken:
        return STALE_DISCARDED

    candidates = resp.candidates
    // 排序：更新时间降序，时间相同按记录编号升序
    sort candidates by (updateTime DESC, recordId ASC)
    if candidates is empty:
        return NO_CANDIDATE
    return candidates

// 用户确认后写入
function applyCandidate(agreedCandidate, targetForm, requestToken):
    // 1. 写入前获取最新详情
    detail = callDetailApi(agreedCandidate.recordId, requestToken)
    if detail.failed:
        return DETAIL_FAILED   // 保留原值，提示失败

    // 2. 详情编号一致性校验
    if detail.recordId != agreedCandidate.recordId:
        return ID_MISMATCH     // 停止写入，提示信息不一致

    // 3. 地区条件复核（详情返回的地区必须可核验且符合当前地区）
    if detail.region is missing:
        return REGION_UNVERIFIABLE
    if detail.region != currentRegion:
        return REGION_MISMATCH

    // 4. 仅白名单字段补值
    for field in WHITELIST:
        targetValue = targetForm[field]
        sourceValue = detail[field]
        if isEmpty(targetValue) AND NOT isEmpty(sourceValue):
            targetForm[field] = sourceValue
        // 否则保留原值：0、false、非空字符串均不覆盖

    return APPLIED

// 取消 / 关闭 / 离开
function onCancelOrLeave(targetForm):
    // 不写入任何字段
    // 已保存原值与未保存编辑值均保留
    return NO_WRITE
```

**关键点对照**

| 要求 | 伪代码落点 |
|---|---|
| 空值判断 | `isEmpty` 仅判 `null` 或 `""` |
| 白名单 | `WHITELIST` 仅三项 |
| 地区条件 | `REGION_UNVERIFIABLE` / `REGION_MISMATCH` 分支 |
| 身份键传递 | `identityKeys` 显式入参，不读其他页面状态 |
| 时序保护 | `requestToken` 校验，迟到旧请求 `STALE_DISCARDED` |
| 详情编号一致性 | `detail.recordId != agreedCandidate.recordId` → `ID_MISMATCH` |
| 取消不写入 | `onCancelOrLeave` 返回 `NO_WRITE` |
