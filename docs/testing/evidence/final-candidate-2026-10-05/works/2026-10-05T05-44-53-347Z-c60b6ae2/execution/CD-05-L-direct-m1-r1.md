# 提示词整理工具对照研究方案（未执行）

## 一、研究方案主文

### 1. 研究问题

本研究比较三种提示词整理方式对下游任务输出的影响：原始需求（原始组）、直接增强（直接增强组）、交互式计划确认增强（计划确认组），并设置信息量匹配对照组。研究不评价任何产品的绝对优劣，只考察条件差异对输出的作用。

核心问题：（1）直接增强相对原始需求是否改变输出质量；（2）计划确认相对直接增强是否改变输出质量；（3）计划确认组多获得的确认答案本身带来多少收益——这由信息量匹配对照组分离；（4）交互阶段的风险（如错误推荐被纠正）是否影响最终输出。

### 2. 实验设计

**任务与重复**：固定二十个任务，覆盖开发类与写作类。每个条件对每个任务独立重复三次，共 4 条件 × 20 任务 × 3 次 = 240 个下游输出单元。三次重复开启隔离会话，随机化条件与任务顺序，记录模型版本、日期与参数。

**四组条件差异**：

| 组别 | 初始信息 | 是否经历问答 | 是否获得确认答案 |
|---|---|---|---|
| 原始组 | 原始需求＋初始材料 | 否 | 否 |
| 直接增强组 | 同一初始信息得到的优化提示词 | 否 | 否 |
| 计划确认组 | 同一初始信息 | 是（系统提问，操作者按答案卡作答） | 是 |
| 信息量匹配对照组 | 同一初始信息＋相同已确认事实 | 否 | 是 |

原始组与直接增强组不得接触计划确认组后来回答的业务选择。计划确认组须记录每个问题、选项、推荐依据与答案，不只保存最终提示词；错误推荐被答案纠正后仍计入交互阶段风险。信息量匹配对照组获得与计划确认组相同的已确认事实，但不经历问答过程，用于减少“新增信息”与“交互组织方式”之间的混淆。

**公平比较逻辑**：直接增强组与原始组共享同一初始信息，差异只在提示词是否被优化；计划确认组与信息量匹配对照组共享同一已确认事实，差异只在是否经历问答。因此“多得到答案带来的收益”不能被误判为单纯模型能力。

**材料来源标签**：任务材料保留真实实现、用户说明、测试示例与待办四类来源标签；人工评分前不得删除不利的测试污染反例。

**盲评**：两名盲评者独立评分，看到匿名化下游输出与等量任务信息，不展示产品名称、标志与生成来源；可看任务事实，但不得看另一名评审先前评分。

**分支边界**：开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本。跨任务不得用代码测试通过率作为统一质量指标。

### 3. 主要指标

评价覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。质量分为结果指标；工具生成速度为过程指标。无计费日志时不估算真实 Token 成本，不以字符数换算实际费用。一个错误可能同时影响多个维度，评分表记录主错误与关联维度，避免同一问题被多次计为独立失败。

统计方法选择流程：依据分数是否有序、是否连续、是否重复测量决定，不在变量未确定时锁定某一显著性检验。

### 4. 限制

实验尚未运行，无准确率、显著性、成功案例数量或用户结论。即使多个模型给出相似结论也不构成研究完成证据；方案安排人工评阅与可复核任务标准，专业领域判断尚需专家参与。详细答案卡、记录字段与材料目录见附表，不占用主文字数。
