# 地区基线自动匹配与表单补值实现方案

> 范围声明：本方案为只读分析与方案交付，不含代码修改、数据库迁移或部署内容。文中所有业务条件均来自 `materials/software/current-brief.md`（现行合成资料）；`materials/software/tests/layout-example.txt` 仅用于排版与来源识别，不作为业务事实。

## 1. 背景与现有调用关系

### 1.1 系统与模块

- 目标系统：合成公共卫生调查录入系统。
- 后端：Java 21、Spring Boot 3、MyBatis-Plus、PostgreSQL。
- 前端：Vue 3、TypeScript。
- 调查模块：**基础调查**、**追踪调查**，两者复用同一份补值服务。

### 1.2 现有接口职责

| 接口 | 职责 | 返回内容 |
| --- | --- | --- |
| 候选查询接口 | 按姓名 + 证件号 + 当前用户所属地区筛选候选 | 候选摘要列表：编号、地区、更新时间、姓名掩码 |
| 单条详情接口 | 读取某条候选的最新详情 | 补值字段（联系电话、职业类别、常住地址） |

- 候选摘要**不含完整证件号**，确认框只展示掩码。
- 候选排序：**更新时间降序；时间相同按记录编号升序**，分页/重试后顺序必须稳定。
- 详情接口在**用户同意之后、写入表单之前**调用，用于获取该候选的最新值。

### 1.3 两个模块的调用链路

**基础调查**

1. 页面进入编辑状态。
2. 以当前已有的姓名与证件号发起候选查询。
3. 用户修改姓名或证件号 → 之前的候选失效。
4. 用户确认某条候选 → 调用详情接口 → 写入白名单字段。

**追踪调查**

1. 路由参数**只用于定位当前调查记录**，不得直接当作基线记录编号。
2. 复用服务必须接收**明确的身份键（姓名 + 证件号）与当前地区**，不得暗中读取另一页面状态。
3. 后续步骤与基础调查一致：候选查询 → 失效 → 确认 → 详情 → 写入。

### 1.4 数据流向

```
用户编辑（姓名/证件号）
        │
        ▼
候选查询接口（姓名 + 证件号 + 当前地区）
        │  返回：编号、地区、更新时间、姓名掩码
        ▼
用户确认某条候选
        │
        ▼
详情接口（候选编号）
        │  返回：联系电话、职业类别、常住地址
        ▼
字段写入（仅白名单、仅空值可补）
```

### 1.5 兼容性约束

- 保持现有**查询接口、路由、鉴权行为**不变。
- 不新增字段、不扩张白名单；目录中的演示字段不属于本次范围。

## 2. 两个模块共用的处理步骤

### 2.1 主流程

1. **进入编辑状态**（基础调查）或**定位当前记录**（追踪调查）。
2. **构造身份键**：姓名 + 证件号 + 当前用户所属地区。
3. **发起候选查询**，记录本次请求标识（用于迟到请求失效）。
4. **候选返回后**：
   - 无候选 → 不弹确认框，流程结束。
   - 有候选 → 展示摘要（编号、地区、更新时间、姓名掩码），等待用户确认。
5. **用户确认**某条候选 → 调用详情接口。
6. **详情返回后校验编号一致性**：
   - 编号一致 → 进入字段写入。
   - 编号不一致 → 停止写入，提示信息不一致。
7. **字段写入**：仅对白名单字段、仅当目标值为 `null` 或空字符串时补入。
8. **异常分支**：查询失败、详情失败、迟到请求、取消/关闭/离开页面，均按第 3 节处理。

### 2.2 候选失效规则

- 用户修改**姓名或证件号**后，之前的候选立即失效，不得沿用旧身份对应的详情。
- 候选请求尚未结束时用户再次修改姓名 → **迟到的旧请求必须失效**（按请求标识丢弃）。
- 本方案只描述时序保护，不指定具体浏览器库或状态管理实现。

### 2.3 用户确认规则

- **无候选时不弹确认框**。
- **有匹配候选时必须询问用户**，不得改为无确认自动写入。
- 确认框只展示掩码，不展示完整证件号。

### 2.4 取消/关闭/离开页面

- 用户取消、关闭弹窗或离开编辑页面时，**都不得补写字段**。
- 页面**已保存的原值**和**当前未保存的编辑值**都不能因取消动作被清空。

## 3. 字段写入与异常分支伪代码

> 说明：以下为方案级伪代码，用于表达业务规则，不代表已实现代码。

### 3.1 主入口

```
function applyBaseline(currentForm, identity, region, requestId):
    candidates = queryCandidates(identity.name, identity.idNo, region, requestId)

    if candidates is FAILED:
        showUserMessage("本次未执行补值，原数据保留")
        return UNCHANGED

    if candidates is EMPTY:
        return UNCHANGED            # 无候选，不弹确认框

    selected = showConfirmDialog(candidates)   # 仅展示掩码
    if selected is CANCELLED:
        return UNCHANGED

    detail = fetchDetail(selected.id, requestId)
    if detail is FAILED:
        showUserMessage("本次未执行补值，原数据保留")
        return UNCHANGED

    if detail.id != selected.id:
        showUserMessage("信息不一致，已停止写入")
        return UNCHANGED

    return writeWhitelistFields(currentForm, detail)
```

### 3.2 白名单字段写入

```
function writeWhitelistFields(form, detail):
    # 联系电话
    if isNullOrEmpty(form.phone):
        if not isNullOrEmpty(detail.phone):
            form.phone = detail.phone
        # 目标为空且来源也为空 → 保持空值，不制造占位号码

    # 职业类别（数值 0 是有效类别）
    if isNullOrEmpty(form.occupation):
        if not isNullOrEmpty(detail.occupation):
            form.occupation = detail.occupation

    # 常住地址（单个字符串字段）
    if isNullOrEmpty(form.residenceAddress):
        if not isNullOrEmpty(detail.residenceAddress):
            form.residenceAddress = detail.residenceAddress

    return APPLIED
```

**关键点**

- `isNullOrEmpty` 只判断 `null` 或空字符串；`0`、`false`、非空字符串都视为有效原值，必须保留。
- 职业类别必须使用**空值比较**，不能写成 `form.occupation || detail.occupation` 这类假值判断，否则数值 `0` 会被误替换。
- 常住地址只对应**一个字符串字段**，不涉及户籍地址、单位地址、紧急联系人地址；附件中的其他地址种类只能作为背景。

### 3.3 异常分支

```
# 迟到请求失效
onIdentityChanged(newName, newIdNo):
    invalidateRequestId(currentRequestId)
    currentRequestId = newRequestId()

onResponseArrived(response, requestId):
    if requestId != currentRequestId:
        discard(response)          # 迟到的旧请求直接丢弃
        return

# 取消 / 关闭 / 离开页面
onCancelOrCloseOrLeave():
    discardPendingRequest()
    # 不写入任何字段
    # 不清空已保存原值，也不清空当前未保存的编辑值

# 查询或详情失败
onQueryOrDetailFailure(errorType, requestId):
    log(stableErrorType=errorType, requestId=requestId)   # 不记录姓名/证件号原文
    showUserMessage("本次未执行补值，原数据保留")
    # 不得伪装为“没有匹配记录”
    # 不附带内部堆栈、数据库错误文本或上游服务地址
```

### 3.4 三种“无结果”情况的区分

| 情况 | 含义 | 处理 |
| --- | --- | --- |
| 确无候选 | 查询成功，但无满足姓名 + 证件号 + 地区的记录 | 不弹确认框，流程结束 |
| 明确地区不符 | 有记录但地区与当前用户所属地区不一致 | 视为不可补值候选，不进入确认 |
| 无法核验的记录 | 候选记录地区信息缺失，无法判断是否符合当前地区条件 | **未决前提**，见第 6 节 |

- **地区缺失不是地区匹配成功**。
- **查询接口的返回顺序不是授权证据**。

## 6. 未决前提与缺口

### 6.1 未决前提（实施前必须确认）

**候选记录地区信息缺失、无法核验是否符合当前用户所属地区条件时，这条候选应如何处理？**

- 用户说明：暂不确定，保留为未决前提，实施前先确认；不得绕过地区匹配条件。
- 影响范围：候选筛选逻辑、异常分支、测试用例设计（对应 T-10）。
- 在确认前，该分支不得默认补全或绕过地区匹配条件。

### 6.2 缺口

- 本方案未覆盖具体前端状态管理实现、具体接口字段名与后端实现细节，需在实施阶段结合现有代码确认。
