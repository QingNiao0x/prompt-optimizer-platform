# 提示词整理工具对照研究方案（未执行）

## 一、研究方案主文

**研究问题。** 本研究比较三种提示词整理条件对下游任务输出的影响：原始需求（原始组）、直接增强（直接增强组）、交互式计划确认增强（计划确认组）。研究不评价任何产品的绝对优劣，只比较条件差异。交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答、再生成最终提示词，不是静态任务分解列表。

**实验设计。** 二十个任务、每条件三次独立重复、两名盲评者已确定，不再重新选择样本量。原始组接收原始需求与初始材料；直接增强组接收由同一初始信息得到的优化提示词；两组均不得接触计划确认组后续回答的业务选择。计划确认组记录每个问题、选项、推荐依据和答案，不只保存最终提示词；错误推荐被答案纠正后仍计入交互阶段风险。因计划确认组额外获得答案，另设信息量匹配对照组：获得相同已确认事实，但不经历本平台问答过程，用于减少新增信息与交互组织方式之间的混淆。公平比较须区分“相同初始信息”与“收到确认答案后的信息量匹配”两类问题。

**过程控制。** 每个条件的三次重复开启隔离会话，随机化顺序，记录模型版本、日期和参数；失败后的重试不能替代第一份失败样本。任务材料保留真实实现、用户说明、测试示例与待办等来源标签，不在人工评分前删除不利的测试污染反例。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；可看任务事实，但不得查看另一名评审先前评分。

**主要指标。** 评价同时覆盖需求保真、业务规则、输出可用性、阅读负担和执行边界。开发任务只输出方案、不修改仓库；写作任务交付文本，因此跨任务不能用代码测试通过率作为统一质量指标。工具生成速度属过程指标，质量分属结果指标；没有计费日志时不估算真实 Token 成本，不把字符数直接换算成实际费用。评分表记录主错误和关联维度，避免同一问题被多次计为独立失败。

**统计方法选择流程。** 候选评价统计方法取决于分数是否有序、是否连续、是否重复测量。方案只说明选择流程，不在变量尚未确定时锁定某个显著性检验。两名盲评者独立评分后的分歧处理与一致性评价方式尚未确定，按评分变量类型提出候选并说明选择条件，预注册前确认。

**限制。** 实验尚未运行，无准确率、显著性、成功案例数量或用户结论。即使三个模型给出相似结论也不是研究完成证据。人工评阅与可复核任务标准需安排，专业领域判断尚需专家参与。计划确认组最大提问轮次和终止规则尚未确定，保留为预注册前待确认条件，不默认补全为一轮或无限追问。

## 三、评分表及失败记录模板

**评分表字段：** 任务编号、条件（匿名）、重复序号、需求保真、业务规则、输出可用性、阅读负担、执行边界、主错误、关联维度、评分者、备注。

**失败记录模板：**
- 工具失败：条件、任务、重复序号、失败阶段、错误信息、是否重试、重试是否替代首轮（否）。
- 首轮失败：条件、任务、重复序号、首轮输出标识、失败类型、是否保留、备注。
