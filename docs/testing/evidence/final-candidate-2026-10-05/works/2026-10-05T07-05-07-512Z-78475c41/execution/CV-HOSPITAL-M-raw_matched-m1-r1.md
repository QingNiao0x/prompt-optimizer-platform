# 合成门诊预约到诊与爽约情况内部运营分析方案（讨论版）

## 0. 资料边界与使用说明

本方案仅针对某合成门诊 2026 年第一季度预约事件，用于内部运营讨论。资料为合成材料，不含真实患者信息，也不含完整逐条数据。本方案不涉及诊断、处方、分诊优先级、医嘱或个体治疗，不计算真实医院指标，不建议减少任何患者服务权益。

资料引用分层如下，接收任务的人可按此定位依据：

| 资料类型 | 文件 | 用途 | 注意 |
|---|---|---|---|
| 现行资料 | `materials/hospital_operations/current-brief.md` | 口径、边界、流程问题的主要依据 | 正式说明，优先用于核查常规细节 |
| 旧流程说明 | `materials/hospital_operations/legacy-note.md` | 取消提前量差异来源之一 | 旧版口径，不因日期自动失效或生效 |
| 新会议草稿 | `materials/hospital_operations/legacy-note.md` 内引用 | 取消提前量差异来源之二 | 尚未批准，不得默认采用 |
| 测试示例 | `materials/hospital_operations/tests/layout-example.txt` | 仅用于排版和来源识别 | 其中 CSV、Python、收入、准确率等均非本题事实 |

## 1. 口径表

### 1.1 统计对象与单位

| 项目 | 讨论口径 | 依据/状态 |
|---|---|---|
| 分析对象 | 某合成门诊 2026 年第一季度预约事件 | 任务给定 |
| 事件标识 | 预约事件编号可区分一次预约 | 现行资料 |
| 人数关系 | 一个患者可多次预约，事件数不等于人数 | 现行资料 |
| 主统计单位 | 预约事件 | 用户已明确：本次以预约事件为主统计单位，不把事件数当作患者数 |
| 参考统计单位 | 去重患者 | 用户已明确：作为独立参考 |
| 渠道范围 | 电话、网页、窗口三类 | 现行资料已明确，不再询问 |
| 到诊状态 | ARRIVED、CANCELLED、UNKNOWN | 现行资料 |
| UNKNOWN 处理 | 不直接计为爽约；原因未细分 | 现行资料与任务约束 |

### 1.2 状态归类口径

| 状态 | 可讨论归类 | 不可做的事 |
|---|---|---|
| ARRIVED | 可计入到诊事件 | 不推断诊疗结果或疗效 |
| CANCELLED | 表示系统记录到用户主动取消 | 不解释为治疗结束、病情缓解或不再需要服务；不附加临床解释 |
| UNKNOWN | 待核验事件 | 不解释为患者责任；不直接计为爽约；不归因于设备、现场或记录中的任一项，除非有来源核查 |
| 未到期预约 | 待核验事件 | 观察窗口未确定前，不将尚未到期预约算入爽约率 |

### 1.3 渠道比较口径

| 问题 | 处理 |
|---|---|
| 电话与网页可能记录同一预约的不同操作事件 | 渠道比较必须先定义首次渠道和变更渠道 |
| 操作次数与预约量 | 不能把操作次数当成预约量 |
| 小渠道样本 | 样本较少时保留数量和限制说明 |
| 差异报告 | 没有完整数据不能报告显著的渠道差异 |
| 主单位 | 预约事件；去重患者作为独立参考 |

### 1.4 取消提前量差异（不擅自采用）

| 来源 | 内容 | 审批状态 | 本方案处理 |
|---|---|---|---|
| 旧流程说明 | 提前 24 小时取消不计爽约 | 旧版说明 | 列为争议口径之一 |
| 新会议草稿 | 建议提前 12 小时 | 尚未批准 | 列为争议口径之一，不默认采用 |
| 权威性 | 材料权威性并未建立 | — | 报告需将争议单独呈现，不能按文件修改时间直接断定新规则生效 |

### 1.5 观察窗口与免责边界

| 项目 | 当前状态 | 处理方式 |
|---|---|---|
| 预约未到诊的观察窗口 | 尚未决定 | 不默认补全；只列待核验事件，不计算爽约率 |
| 取消免责边界 | 尚未决定 | 不默认补全；与 24 小时/12 小时差异一并列为待确认 |
| 窗口未确定前的输出 | 待核验事件清单 | 不将尚未到期预约算入爽约率 |

### 1.6 时区口径

| 项目 | 现状 | 处理 |
|---|---|---|
| 取消时间与就诊时间 | 均用医院本地时区 | 按现行资料记录 |
| 时区转换证据 | 当前汇总表没有 | 不自行换算；如需跨时区比较，先补证据 |
| 报告标注 | 应注明“医院本地时区，未做时区转换” | 避免误读 |

## 2. 流程图说明

### 2.1 预约事件进入分析的主流程

```
预约事件产生
   │
   ├─ 渠道记录：电话 / 网页 / 窗口
   │     └─ 若同一预约出现多操作事件 → 先定义首次渠道与变更渠道
   │
   ├─ 状态记录：ARRIVED / CANCELLED / UNKNOWN
   │
   ├─ 时间记录：预约取消时间、就诊时间（医院本地时区）
   │
   └─ 进入待核验池
         │
         ├─ 观察窗口未确定 → 只展示待核验事件，不计算爽约率
         │
         ├─ 观察窗口确定后 → 按已批准口径归类
         │
         └─ UNKNOWN → 保持待核验，不直接计为爽约
```

### 2.2 渠道比较流程

```
渠道比较需求
   │
   ├─ 先确认主统计单位：预约事件（本次）
   │     └─ 去重患者作为独立参考
   │
   ├─ 处理同一预约的多操作事件
   │     ├─ 定义首次渠道
   │     └─ 定义变更渠道
   │
   ├─ 检查小渠道样本量
   │     └─ 样本少 → 保留数量与限制说明
   │
   └─ 输出
         ├─ 可报告：数量、占比、限制说明
         └─ 不可报告：无完整数据下的显著渠道差异
```

### 2.3 取消规则争议流程

```
取消提前量规则
   │
   ├─ 旧流程说明：24 小时
   ├─ 新会议草稿：12 小时，尚未批准
   │
   ├─ 权威性未建立
   │     └─ 不按文件修改时间断定新规则生效
   │
   └─ 报告处理
         ├─ 争议单独呈现
         ├─ 不擅自采用其中一项
         └─ 待机构明确审批状态后再统一口径
```

### 2.4 改进建议流程边界

```
改进建议
   │
   ├─ 优先方向
   │     ├─ 清楚提示取消规则
   │     ├─ 核对登记质量
   │     └─ 便捷改约
   │
   ├─ 不默认采用
   │     ├─ 罚款
   │     ├─ 降低预约资格
   │     └─ 公开患者记录
   │
   └─ 若涉及短信提醒
         └─ 另行确认通知授权与退订流程，不悄悄扩成实施任务
```

## 3. 合成数据采集字段建议

拟议采集表仅展示合成汇总信息，不包含患者、医生的可识别信息或敏感诊疗明细。实施前仍需合规评估，不能写成已经建表或已获得数据授权。

| 字段 | 说明 | 用途 | 备注 |
|---|---|---|---|
| 预约事件编号 | 区分一次预约 | 事件级统计 | 合成编号 |
| 患者去重标识 | 用于去重患者参考 | 独立参考单位 | 不可识别到个人 |
| 预约渠道 | 电话 / 网页 / 窗口 | 渠道比较 | 已明确三类 |
| 首次渠道 | 同一预约多操作事件时的首次渠道 | 渠道比较 | 需先定义 |
| 变更渠道 | 同一预约后续变更渠道 | 渠道比较 | 需先定义 |
| 到诊状态 | ARRIVED / CANCELLED / UNKNOWN | 状态归类 | UNKNOWN 不细分原因 |
| 状态更新时间 | 状态最近更新时间 | 观察窗口核验 | 拟增字段 |
| 取消时间 | 用户主动取消时间 | 取消规则核验 | 医院本地时区 |
| 就诊时间 | 预约就诊时间 | 观察窗口核验 | 医院本地时区 |
| 来源系统 | 记录来源系统 | 登记质量核查 | 拟增字段 |
| 时区标识 | 是否医院本地时区 | 时区口径 | 当前无转换证据 |
| 观察窗口标记 | 是否已到期、是否待核验 | 爽约率计算前置 | 窗口未定前只标待核验 |
| 取消免责标记 | 是否属于免责边界 | 取消规则核验 | 边界未定前不默认 |
| 科室类型 | 本题仅一个门诊 | 限制说明 | 不推断跨科室 |
| 医生代码 | 流程角色示例 | 流程角色 | 不是个人绩效评估范围 |

采集表使用原则：

1. 只展示合成汇总信息。
2. 不含患者、医生的可识别信息。
3. 不含敏感诊疗明细。
4. 实施前需合规评估。
5. 不写成已经建表或已获得数据授权。

## 6. 待确认项（仅保留真正影响任务目标的业务决定）
