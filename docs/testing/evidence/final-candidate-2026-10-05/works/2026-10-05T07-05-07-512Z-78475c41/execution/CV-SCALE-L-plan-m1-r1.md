# 提示词整理工具对照研究方案（未执行）

## 一、研究方案主文

**研究问题。** 本研究比较三种提示词条件对下游任务输出的影响：原始需求（原始组）、直接增强（直接增强组）、交互式计划确认增强（计划确认组）。研究不评价任何产品的绝对优劣，只考察条件差异。交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答，再生成最终提示词，不是静态任务分解列表。

**关键混淆与控制。** 计划确认组会额外获得已确认的业务选择，因此必须另设信息量匹配对照：该组获得与计划确认组相同的已确认事实，但不经历本平台问答过程。这样可减少“新增信息”与“交互组织方式”之间的混淆，避免把多得到答案带来的收益误判为单纯模型能力。公平比较须区分两类问题：相同初始信息下的比较（原始组、直接增强组），以及收到确认答案后的信息量匹配比较（计划确认组、信息量匹配对照组）。

**设计。** 固定二十个任务，每个条件独立重复三次，共四组。三次重复开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本，首轮失败与工具失败均须保留。原始组接收原始需求与初始材料；直接增强组接收同一初始信息得到的优化提示词；两组都不能偷看计划确认组后来回答的业务选择。计划确认组记录每个问题、选项、推荐依据和答案，不只保存最终提示词；错误推荐被答案纠正后仍应计入交互阶段风险。

**材料。** 所有工具获取相同初始材料。任务材料必须保留真实实现、用户说明、测试示例与待办这几种来源标签；不能在人工评分前人为删除不利的测试污染反例。材料均为合成演练材料，不代表任何真实单位、患者、当事人、市场或平台运行数据。

**评审。** 两名盲评者独立评分。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源；为了评分可以看任务事实，但不能看另一名评审先前评分。评价需同时覆盖需求保真、业务规则、输出可用性、阅读负担和执行边界。

**指标。** 工具生成速度是过程指标，质量分是结果指标。没有计费日志时不能估算真实 Token 成本，不能把字符数直接换算成实际费用。评分尺度采用顺序尺度；具体等级和评分锚点仍未确定，不得自行指定。

**统计。** 候选评价统计方法依赖分数是否有序、是否连续和是否重复测量；方案可说明选择流程，不应在变量尚未确定时锁定某个显著性检验。

**限制。** 实验尚未运行，没有准确率、显著性、成功案例数量或用户结论。即使三个模型给出相似结论也不是研究完成证据；方案应安排人工评阅与可复核任务标准，特别说明专业领域判断尚需专家参与。开发任务要求下游模型只输出方案，不实际修改仓库；写作任务要求交付文本，因此跨任务不能用代码测试通过率作为统一质量指标。本方案为合成演练材料，不代表任何真实单位、患者、当事人、市场或平台运行数据。

## 二、变量与分组附表

| 条件 | 接收信息 | 是否经历问答过程 | 重复次数 | 记录字段 |
|---|---|---|---|---|
| 原始组 | 原始需求与初始材料 | 否 | 3 | 模型版本、日期、参数、首轮输出、失败记录 |
| 直接增强组 | 同一初始信息得到的优化提示词 | 否 | 3 | 同上 |
| 计划确认组 | 初始材料＋问答后最终提示词 | 是 | 3 | 每个问题、选项、推荐依据、答案、错误推荐及纠正、最终提示词、模型版本、日期、参数、首轮输出、失败记录 |
| 信息量匹配对照组 | 初始材料＋相同已确认事实 | 否 | 3 | 模型版本、日期、参数、首轮输出、失败记录 |

注：原始组与直接增强组不得偷看计划确认组后来回答的业务选择。计划确认组错误推荐被答案纠正后仍应计入交互阶段风险。
