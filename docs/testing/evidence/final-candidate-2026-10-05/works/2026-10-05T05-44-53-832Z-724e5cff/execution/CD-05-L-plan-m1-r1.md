# 提示词整理工具对照研究方案

## 一、研究问题

本研究比较三种提示词准备方式对下游任务输出的影响：原始需求直接输入、直接增强提示词、交互式计划确认增强提示词。研究不评价任何产品绝对优劣，只考察在相同初始信息条件下，不同提示词整理路径是否带来可观察的输出差异。交互式计划确认指系统先提问、实验操作者按预先制定答案卡作答、再生成最终提示词，不是静态任务分解列表。

## 二、实验设计

**任务与材料。** 使用二十个任务，覆盖开发方案类（只输出方案、不修改仓库）与写作交付类（交付文本）等类型。任务材料保留真实实现、用户说明、测试示例与待办四种来源标签；不得在人工评分前人为删除不利的测试污染反例。

**条件与分组。** 设四个条件：

- **原始组**：接收原始需求与初始材料，不接收任何增强。
- **直接增强组**：接收由同一初始信息生成的优化提示词，不经历问答过程。
- **计划确认组**：系统先提问，实验操作者按预先制定答案卡作答，再生成最终提示词。记录每个问题、选项、推荐依据和答案，不只保存最终提示词；错误推荐被答案纠正后仍计入交互阶段风险。
- **信息量匹配对照组**：获得与计划确认组相同的已确认事实，但不经历本平台问答过程。该组用于区分“新增信息”与“交互组织方式”的效应，避免把多得到答案带来的收益误判为单纯模型能力。

原始组与直接增强组均不能接触计划确认组后来回答的业务选择。每个条件独立重复三次，共 240 次下游生成。每次重复开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试不能替代第一份失败样本。

**盲评安排。** 两名盲评者独立评分。评审看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源。评审可查看任务事实，但不能查看另一名评审先前评分。

## 三、主要指标

结果指标为质量分，由盲评者按评分表评定。评分维度同时覆盖：需求保真、业务规则、输出可用性、阅读负担、执行边界。跨任务不能用代码测试通过率作为统一质量指标，因为开发任务只输出方案、写作任务交付文本，任务类型不同。

过程指标与结果指标分开记录。工具生成速度是过程指标，质量分是结果指标。没有计费日志时不能估算真实 Token 成本，不能把字符数直接换算成实际费用。

评分表记录主错误和关联维度，避免将同一问题多次计成不同独立失败。失败记录模板保留工具失败和首轮失败两类记录。

## 四、统计方法选择流程

候选评价统计方法依赖三个条件：分数是否有序、是否连续、是否重复测量。方案不提前锁定某个显著性检验，而是按以下流程选择：若质量分为有序分类，考虑有序 Logistic 或秩方法；若为连续且近似正态，考虑线性混合模型；若为重复测量，纳入任务与重复的随机效应。最终选择在预注册前根据评分变量类型确定。

## 五、限制

本研究为尚未执行的方案，无准确率、显著性、成功案例数量或用户结论。专业领域判断尚需专家参与；即使三个模型给出相似结论也不是研究完成证据。计划确认组最大提问轮次和终止规则、两名盲评者分歧处理与一致性评价方式尚未确定，列入预注册待确认清单。所有材料为演练用合成资料，不代表真实单位、患者、当事人、市场或平台运行数据。


# 附表一：变量与分组

| 条件 | 接收信息 | 是否经历问答 | 重复次数 | 隔离会话 | 备注 |
|---|---|---|---|---|---|
| 原始组 | 原始需求与初始材料 | 否 | 3 | 是 | 不接触任何增强信息 |
| 直接增强组 | 同一初始信息生成的优化提示词 | 否 | 3 | 是 | 不接触计划确认组答案 |
| 计划确认组 | 初始信息＋问答确认后生成的最终提示词 | 是 | 3 | 是 | 记录每个问题、选项、推荐依据、答案；错误推荐被纠正仍计入交互风险 |
| 信息量匹配对照组 | 初始信息＋与计划确认组相同的已确认事实 | 否 | 3 | 是 | 不经历本平台问答过程，用于分离新增信息与交互组织方式 |

**固定变量**：二十个任务、每个条件三次独立重复、两名盲评者、匿名化下游输出、等量任务信息、模型版本/日期/参数记录。

**未定变量**：计划确认组最大提问轮次和终止规则；盲评分歧处理与一致性评价方式。


# 附表二：评分表及失败记录模板

## 评分表

| 维度 | 定义 | 评分范围 | 主错误记录 | 关联维度 |
|---|---|---|---|---|
| 需求保真 | 输出是否覆盖原始需求全部要点 | 待定（有序/连续待预注册确认） | 记录主要缺失或曲解 | 可关联业务规则、执行边界 |
| 业务规则 | 是否遵守任务给定的业务约束 | 待定 | 记录违反的具体规则 | 可关联需求保真、输出可用性 |
| 输出可用性 | 输出是否可直接用于后续工作 | 待定 | 记录不可用原因 | 可关联需求保真、阅读负担 |
| 阅读负担 | 信息组织是否清晰、冗余是否可控 | 待定 | 记录主要负担来源 | 可关联输出可用性 |
| 执行边界 | 是否超出任务允许的操作范围 | 待定 | 记录越界行为 | 可关联业务规则 |

**评分规则**：每个样本先记录主错误，再标注关联维度；同一主错误不在多个维度重复计为独立失败。盲评者独立评分，不查看另一名评审先前评分。

## 失败记录模板

| 字段 | 内容 |
|---|---|
| 样本编号 | 条件－任务－重复 |
| 失败类型 | 工具失败 / 首轮失败 / 评分失败 |
| 失败描述 | 具体现象 |
| 主错误 | 主要缺陷 |
| 关联维度 | 受影响的评分维度 |
| 是否重试 | 是/否 |
| 重试说明 | 重试不能替代第一份失败样本 |
