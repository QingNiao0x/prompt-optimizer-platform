# 提示词整理工具对照研究方案

## 1. 研究问题

本研究考察提示词整理工具在“原始需求—最终提示词”转化环节中的影响，比较三种条件对下游任务输出的作用：原始需求直接输入、直接增强提示词、交互式计划确认后生成提示词。研究不评价任何产品绝对优劣，只比较条件间差异。

## 2. 实验设计

**任务集**：二十个任务，覆盖开发方案类（下游模型只输出方案、不修改仓库）与写作交付类（交付文本）。跨任务不采用代码测试通过率作为统一质量指标。

**条件设置**：

- **A组（原始组）**：下游模型接收原始需求与初始材料。
- **B组（直接增强组）**：下游模型接收由同一初始信息生成的优化提示词，不经历交互问答。
- **C组（计划确认组）**：系统先提问，实验操作者按预先制定答案卡作答，再生成最终提示词。记录每个问题、选项、推荐依据和答案；错误推荐被答案纠正后仍计入交互阶段风险。
- **D组（信息量匹配对照）**：获得与C组相同的已确认事实，但不经历本平台问答过程。用于区分“新增信息”与“交互组织方式”的贡献。

A、B两组不得接触C组回答中产生的业务选择。每组每个任务独立重复三次，开启隔离会话，随机化顺序，记录模型版本、日期和参数。失败后的重试不替代第一份失败样本。

**盲评**：两名盲评者独立评分，看到匿名化下游输出和等量任务信息，不展示产品名称、标志和生成来源。评审可查看任务事实，但不得查看另一名评审的先前评分。

## 3. 主要指标

评分覆盖五个维度：需求保真、业务规则、输出可用性、阅读负担、执行边界。每个错误记录主错误与关联维度，避免同一问题在多个维度重复计分。工具生成速度作为过程指标单独记录；无计费日志时不估算真实Token成本，不以字符数换算费用。

## 4. 统计方法选择流程

统计方法取决于分数是否有序、是否连续、是否重复测量。方案预注册时先确定评分量尺类型与重复测量结构，再据此选择检验方法；不在变量尚未确定时锁定某个显著性检验。

## 5. 限制

- 人工评分存在主观性，需通过评分表锚定与分歧处理规则控制。
- 专业领域判断需专家参与，模型相似结论不构成研究完成证据。
- 任务材料保留真实实现、用户说明、测试示例与待办等来源标签，不人为删除不利反例。
- 交互式计划确认的最大轮次与终止规则尚未确定，需在预注册中明确。
- 两名评审的分歧处理与一致性评价方式尚未确定，需在预注册中明确。

| A 原始组 | 原始需求+初始材料 | 无 | 基准 | 3 | 是 |

**记录字段**：组别、任务编号、重复序号、会话ID、模型版本、日期、参数、首轮是否失败、失败后是否重试、重试次数。
