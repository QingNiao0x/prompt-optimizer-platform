# 合成门诊预约到诊与爽约情况内部运营分析方案

**适用期间**：二〇二六年第一季度  
**分析对象**：合成门诊预约事件（非患者个人）  
**材料性质**：合成汇总资料，无真实患者信息，无完整逐条数据  
**用途**：内部运营讨论，不涉及诊断、处方、分诊优先级、医嘱或个体治疗


## 一、口径梳理

### 1.1 基础统计单位

| 口径项 | 当前可确定内容 | 待确认项 |
|---|---|---|
| 预约事件编号 | 可区分一次预约；一个患者可多次预约，事件数 ≠ 人数 | 无 |
| 主统计单位 | 未定：按预约事件还是按去重患者比较渠道 | 渠道比较时采用预约事件还是去重患者作为主统计单位 |
| 渠道范围 | 电话、网页、窗口三类，已明确 | 无（不得再询问） |
| 到诊状态 | ARRIVED / CANCELLED / UNKNOWN 三类；UNKNOWN 无原因细分 | 无 |
| 时间字段 | 预约取消时间与就诊时间均为医院本地时区；当前汇总表无时区转换证据 | 无 |

### 1.2 状态口径

| 状态 | 运营分析中的处理方式 | 禁止事项 |
|---|---|---|
| ARRIVED | 计为到诊 | — |
| CANCELLED | 计为主动取消；不附加临床解释（不表示治疗结束、病情缓解或不再需要服务） | 不得将取消行为解释为患者责任或临床结果 |
| UNKNOWN | 列为待核验事件，单独展示 | **不得直接计为爽约**；不得在缺少来源核查时解释为患者责任 |

### 1.3 爽约口径

- 爽约的认定依赖“预约未到诊的观察窗口”和“取消免责边界”两个业务决定。
- 当前两个决定均**尚未确定**，本方案不默认补全。
- 在窗口和免责边界确定前，分析报告只展示待核验事件，不将尚未到期的预约算入爽约率。

### 1.4 取消免责边界的材料差异

| 来源 | 内容 | 状态 |
|---|---|---|
| `materials/hospital_operations/legacy-note.md` | 旧流程说明：提前24小时取消不计爽约 | 旧版说明 |
| 同文件所载草稿 | 新会议草稿建议：提前12小时取消不计爽约 | 尚未批准 |
| 材料权威性 | 两份材料的适用口径和审批状态应按本题说明核对，不能只凭日期决定 | 未建立 |

**处理方式**：在运营讨论报告中，将24小时与12小时两个口径**并列呈现为争议项**，标注各自来源与审批状态，不擅自采用其中一项，不按文件修改时间推断新规则生效。

### 1.5 渠道比较口径

- 电话预约与网页预约可能记录相同一次预约的不同操作事件。
- 渠道比较必须先定义**首次渠道**和**变更渠道**，不能把操作次数当成预约量。
- 在首次渠道/变更渠道定义未确定前，渠道维度仅做事件量级描述，不做显著性比较。

### 1.6 样本量限制

- 预约事件量不同会影响百分比波动。
- 小渠道样本较少时，保留数量并附加限制说明。
- 没有完整数据时，不报告显著的渠道差异。


## 二、流程图说明

### 2.1 预约事件状态流转（基于现有资料可确定部分）

```
[预约创建] ──→ [等待就诊] ──→ [ARRIVED 到诊]
                  │
                  ├──→ [CANCELLED 主动取消]（取消时间记录于本地时区）
                  │
                  └──→ [UNKNOWN 状态未知]
                           │
                           ├─ 可能原因（资料已列，不细分）：设备同步延迟 / 现场漏登记 / 记录缺项
                           │
                           └─ 处理：列为待核验，不归入爽约
```

### 2.2 爽约认定流程（标注未决节点）

```
预约事件到达预定就诊时间
        │
        ▼
是否已记录 ARRIVED？ ──是──→ 到诊，不涉及爽约
        │否
        ▼
是否已记录 CANCELLED？ ──是──→ 检查取消时间与就诊时间的间隔
        │                              │
        │否                            ├─ 间隔 ≥ 免责边界？ ──→ 不计爽约
        ▼                              └─ 间隔 < 免责边界？ ──→ 是否计爽约：待定
状态为 UNKNOWN
        │
        ▼
是否已超过观察窗口？ ──否──→ 列为待核验，不纳入爽约率
        │是
        ▼
进入人工复核，核查来源系统记录
        │
        ▼
复核后确认未到诊且无合规取消 ──→ 方可讨论是否归入爽约
```

**图中两个未决节点**：
1. 观察窗口时长——尚未决定。
2. 取消免责边界（24小时 vs 12小时）——旧流程与未批准草稿存在差异，尚未决定。


## 三、拟议数据采集表字段建议

以下字段为**拟议**采集内容，用于支持后续运营分析。实施前需经合规评估，不得视为已经建表或已获得数据授权。

### 3.1 预约事件基础字段

| 字段名 | 建议类型 | 说明 | 是否含敏感信息 |
|---|---|---|---|
| 预约事件编号 | 字符串（脱敏/合成） | 区分一次预约 | 否（需去标识化） |
| 患者匿名标识 | 字符串（合成/哈希） | 用于识别同一患者多次预约，不还原身份 | 是（需去标识化） |
| 预约渠道 | 枚举：电话/网页/窗口 | 记录首次记录到的渠道 | 否 |
| 渠道变更标记 | 枚举：无变更/有变更 | 用于区分首次渠道与后续操作渠道 | 否 |
| 预约创建时间 | 日期时间（本地时区） | 医院本地时区 | 否 |
| 预约就诊时间 | 日期时间（本地时区） | 医院本地时区 | 否 |
| 到诊状态 | 枚举：ARRIVED/CANCELLED/UNKNOWN | 系统当前记录状态 | 否 |
| 状态更新时间 | 日期时间（本地时区） | 用于判断状态是否为最终状态 | 否 |
| 取消时间 | 日期时间（本地时区，可空） | 仅 CANCELLED 状态填写 | 否 |
| 来源系统 | 枚举/字符串 | 记录状态写入的系统来源，用于核查 UNKNOWN | 否 |

### 3.2 建议补充的核验字段（针对 UNKNOWN 状态）

| 字段名 | 建议类型 | 用途 |
|---|---|---|
| 最后同步时间 | 日期时间 | 判断是否因设备同步延迟导致 UNKNOWN |
| 现场登记记录标记 | 枚举：有/无/不可查 | 核查是否现场漏登记 |
| 记录缺项标记 | 枚举：有/无 | 核查是否记录本身缺项 |

### 3.3 明确不纳入采集的字段

- 患者姓名、身份证号、联系方式等可识别信息。
- 医生个人绩效相关字段（医生代码仅为流程角色示例，不追加医生排行榜，不利用服务时间做个体能力评价）。
- 诊断、处方、医嘱、分诊优先级等临床信息。


## 四、运营讨论报告目录（草案）

> 以下目录用于内部运营讨论，报告全文须标注“合成材料与方法草案”，明确专业评审后才能应用；不宣称任何方案已提高疗效。

**《合成门诊二〇二六年第一季度预约到诊与爽约情况运营分析报告（讨论版）》**

1. **报告说明与材料性质**
   - 1.1 合成数据声明（无真实患者信息、无完整逐条数据）
   - 1.2 方法草案声明（需专业评审后应用）
   - 1.3 分析边界（不涉及诊断、处方、分诊优先级、医嘱、个体治疗）

2. **口径与定义**
   - 2.1 预约事件与患者人数的区别
   - 2.2 到诊状态定义（ARRIVED / CANCELLED / UNKNOWN）
   - 2.3 UNKNOWN 状态的处理原则（不直接计为爽约）
   - 2.4 爽约认定所需的两项未决业务决定（观察窗口、取消免责边界）
   - 2.5 渠道比较的统计单位问题（预约事件 vs 去重患者，未定）

3. **数据概况（合成汇总）**
   - 3.1 预约事件总量与状态分布

4. **流程问题清单**
   - 4.1 取消免责边界不一致（24小时旧流程 vs 12小时未批准草稿）

   - 4.3 UNKNOWN 状态缺少来源核查流程
   - 4.4 渠道操作事件与预约事件的混淆风险（首次渠道/变更渠道未定义）
   - 4.5 时区转换证据缺失对跨系统数据一致性的影响

5. **待核验事件分析框架**

   - 5.3 复核结果对爽约认定的影响

6. **改进方向讨论（不涉及处罚措施）**
   - 6.1 清楚提示取消规则（解决免责边界不清晰问题）
   - 6.2 核对登记质量（降低 UNKNOWN 比例）
   - 6.3 便捷改约流程（减少因改约困难导致的取消）
   - 6.4 明确不采取的措施：罚款、降低预约资格、公开患者记录

7. **争议项与待确认决定**

## 五、人工复核及隐私边界清单

### 5.1 人工复核清单

| 复核项 | 触发条件 | 复核内容 | 复核后处理 |
|---|---|---|---|
| UNKNOWN 状态事件 | 超过观察窗口后仍为 UNKNOWN（窗口确定后适用） | 核查来源系统记录、现场登记记录、设备同步时间 | 确认到诊则更正为 ARRIVED；确认取消则补录取消时间；确认未到诊且无合规取消则按既定口径讨论是否归入爽约 |
| 取消时间异常 | 取消时间晚于就诊时间或缺失 | 核查系统记录完整性 | 标记为数据质量问题，不直接归入爽约 |
| 渠道记录冲突 | 同一预约事件在电话和网页均有操作记录 | 核查首次渠道与变更渠道 | 按既定首次渠道定义归类，操作次数不计为预约量 |
| 时区一致性 | 跨系统时间字段存在偏差迹象 | 核查各来源系统的时区设置 | 统一为医院本地时区后再分析 |

### 5.2 隐私边界清单

| 边界项 | 要求 |
|---|---|
| 患者可识别信息 | 不采集、不展示姓名、证件号、联系方式等；患者标识须去标识化或合成 |
| 医生信息 | 医生代码仅作流程角色示例，不用于个人绩效评估，不追加医生排行榜 |
| 敏感诊疗明细 | 不采集、不展示诊断、处方、医嘱、分诊优先级等临床内容 |
| 取消行为的解释边界 | 取消状态不附加临床解释，不推断病情变化或服务需求变化 |
| UNKNOWN 状态的归因边界 | 在缺少来源核查时，不将 UNKNOWN 解释为患者责任 |
| 报告传播范围 | 标注合成材料与方法草案，专业评审前不得对外应用 |
| 短信提醒等衍生需求 | 如后续要求短信提醒方案，须另行确认通知授权和退订流程；本次不扩展为实施任务 |
