# 段落编辑候选的对照条件

本批先冻结六篇已见回归稿。试验以 `text-polish-v3` 为基线，以 `text-polish-paragraph-v1` 为候选。两臂使用同一个 `input` 对象，唯一实验变量是策略装配后的 system 指令。正文、读者、补充要求、锁定文字、文体、幅度、路由及发送参数均从 2026-11-18 的六条关闭思考执行记录提取并逐项核对。

- [冻结协议](pilot-protocol.json)记录完整输入、归档相对路径和 SHA-256。协议的 UTF-8 LF 摘要为 `7219b3f908215011221679f37319ce46d0e551dd4909da95f746b352cdf4ff50`。归档摘要也统一为 LF 后计算，便于 Windows 工作区复核。
- 基线路由为 `deepseek`，供应商模型为 `deepseek-flash`。发送温度 0.2，最多 8000 输出 Token，JSON object，非流式，思考关闭。运行前核对这些参数和完整 system 哈希，漂移时记录差异并重新冻结条件。
- 数字化文章沿用存档中实际发送的标题、三段正文和完整补充要求。用户提交的网页版指令和结果另有原件，用于核对偏好和新增主张。网页版的思考设置和指令来源与本批 A/B 条件不同。
- 只将各样本的 `input` 作为模型输入。`reviewOnly` 保存评阅问题与独立含义，包含服务说明的“保障权益”和“改善服务体验”两项，以及英语文本中计划、条件和例外的归属。
- 六篇均为回归样本。按方案在机制验证通过后冻结尚未用于指令调试的中英文新稿，采用决定由新稿作品支持。回归对照计划为 12 次正常生成。旧批账本已关闭，本目录记录的是试验准备。

## 候选入口

文章后端测试实例可显式设置 `app.text-polish.strategy-version=text-polish-paragraph-v1`。例如启动已构建的服务时向 Spring Boot 传入 `--app.text-polish.strategy-version=text-polish-paragraph-v1`。服务启动后，新生成由候选组装 system。默认值仍是 `text-polish-v3`。

候选按原文语言和所选文体组装一份示范，中英混合或语言证据不足使用通用段落指导。实际装配的完整 system 与各资源分别写入现有执行快照的哈希字段。评测需要逐对核对服务实际发送的消息与执行快照。
