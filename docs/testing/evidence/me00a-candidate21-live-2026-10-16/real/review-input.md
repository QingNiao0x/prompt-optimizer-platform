## 一、实现方案说明

### 1.1 整体思路

采用"薄封装 + 明确契约"的方式实现：核心函数 `fetch_page_title` 负责单次抓取与解析，命令行入口 `main` 负责参数解析与结果输出。请求层使用 `requests`，解析层默认使用标准库 `html.parser`（零额外依赖），并在文档中说明何时切换到 BeautifulSoup。

### 1.2 关键流程

1. 校验 URL（非空、scheme 为 http/https、host 非空）。
2. 使用 `requests.get` 发起请求，设置 `timeout=(connect, read)` 与 `User-Agent`。
3. 检查状态码，非 2xx 抛出明确异常。
4. 依据 `response.encoding` / `apparent_encoding` 解码，失败则回退 `utf-8` 并记录。

### 3.2 `parser.py`

```python
from html.parser import HTMLParser


class _TitleParser(HTMLParser):
    def __init__(self) -> None:
        super().__init__(convert_charrefs=True)
        self._in_title = False
        self._chunks: list[str] = []

    def handle_starttag(self, tag, attrs):
        if tag.lower() == "title":
            self._in_title = True

    def handle_endtag(self, tag):
        if tag.lower() == "title":
            self._in_title = False

    def handle_data(self, data):
        if self._in_title:
            self._chunks.append(data)

    @property
    def title(self) -> str | None:
        text = "".join(self._chunks).strip()
        return text or None


def extract_title(html: str) -> str | None:
    """从 HTML 文本中提取 <title> 内容；无标题返回 None。"""
    if not html:
        return None
    parser = _TitleParser()
    try:
        parser.feed(html)
        parser.close()
    except Exception:
        # html.parser 对畸形 HTML 通常不抛异常，此处仅作兜底
        return None
    return parser.title
```

> **何时改用 BeautifulSoup**：当页面存在嵌套 `<title>`、需要 CSS 选择器、或需要处理严重畸形 HTML 时。此时将 `extract_title` 替换为 `BeautifulSoup(html, "html.parser").title.string` 即可，接口不变。

### 3.3 `fetcher.py`

```python
from urllib.parse import urlparse

import requests

from .exceptions import (
    ConnectionFailedError,
    DecodingError,
    HTTPStatusError,
    InvalidURLError,
    RequestTimeoutError,
    TitleNotFoundError,
)
from .parser import extract_title

DEFAULT_TIMEOUT = (5.0, 10.0)  # (connect, read)
DEFAULT_HEADERS = {
    "User-Agent": "title-fetcher/1.0 (+https://example.invalid)",
    "Accept": "text/html,application/xhtml+xml",
}


def _validate_url(url: str) -> None:
    if not isinstance(url, str) or not url.strip():
        raise InvalidURLError("URL 不能为空")
    parsed = urlparse(url)
    if parsed.scheme not in ("http", "https"):
        raise InvalidURLError(f"不支持的 URL scheme: {parsed.scheme!r}")
    if not parsed.netloc:
        raise InvalidURLError(f"URL 缺少主机名: {url!r}")


def _decode(response: requests.Response) -> str:
    # 优先使用 requests 推断的编码；失败则回退 utf-8
    candidates = [response.encoding, response.apparent_encoding, "utf-8"]
    for enc in candidates:
        if not enc:
            continue
        try:
            return response.content.decode(enc, errors="strict")
        except (LookupError, UnicodeDecodeError):
            continue
    raise DecodingError("无法使用任何候选编码解码响应体")


def fetch_page_title(
    url: str,
    *,
    timeout: tuple[float, float] = DEFAULT_TIMEOUT,
    session: requests.Session | None = None,
    headers: dict[str, str] | None = None,
) -> str:
    """抓取 URL 并返回 <title> 文本。

    参数:
        url: 目标 URL，必须为 http/https。
        timeout: (connect, read) 秒数。
        session: 可选的 requests.Session，便于复用连接。
        headers: 覆盖默认请求头。

    返回:
        去除首尾空白后的标题字符串。

    异常:
        InvalidURLError, RequestTimeoutError, ConnectionFailedError,
        HTTPStatusError, DecodingError, TitleNotFoundError。
    """
    _validate_url(url)

    requester = session or requests
    merged_headers = {**DEFAULT_HEADERS, **(headers or {})}

    try:
        response = requester.get(url, timeout=timeout, headers=merged_headers)
    except requests.exceptions.Timeout as exc:
        raise RequestTimeoutError(f"请求超时: {url}") from exc
    except requests.exceptions.ConnectionError as exc:
        raise ConnectionFailedError(f"连接失败: {url}") from exc
    except requests.exceptions.RequestException as exc:
        # 其他 requests 异常统一映射，避免泄漏底层细节
        raise ConnectionFailedError(f"请求异常: {url}: {exc}") from exc

    if not (200 <= response.status_code < 300):
        raise HTTPStatusError(response.status_code, url)

    html = _decode(response)
    title = extract_title(html)
    if title is None:
        raise TitleNotFoundError(f"未找到 <title>: {url}")
    return title
```

import requests
from bs4 import BeautifulSoup

def get_page_title(url):
    """获取网页标题"""
    try:
        # 发送 GET 请求
        headers = {
            'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) '
                          'AppleWebKit/537.36 (KHTML, like Gecko) '
                          'Chrome/120.0.0.0 Safari/537.36'
        }
        response = requests.get(url, headers=headers, timeout=10)
        response.raise_for_status()  # 检查 HTTP 错误
        
        # 自动识别编码（避免中文乱码）
        response.encoding = response.apparent_encoding
        
        # 解析 HTML
        soup = BeautifulSoup(response.text, 'html.parser')
        title = soup.title.string.strip() if soup.title else '无标题'
        return title
    
    except requests.exceptions.RequestException as e:
        return f'请求失败: {e}'


if __name__ == '__main__':
    url = 'https://www.python.org'
    print(f'网页标题: {get_page_title(url)}')

## 二、时间序列分析（长期趋势 + 季节性）

### 1. 长期趋势
- **指标**：粗死亡率（CR）、年龄标化死亡率（ASMR，采用Segi's世界标准人口或2020中国标准人口）
- **方法**：
  - **Joinpoint回归**：识别趋势转折点，计算APC（年度变化百分比）和AAPC
  - **Joinpoint软件**（NCI）或 R包 `segmented`、`joinpointR`
  - 模型：$\ln(y) = \beta_0 + \beta_1 t$，APC = $(e^{\beta_1}-1)\times100\%$

### 2. 季节性趋势
- **方法**：
  - **时间序列分解**：STL（Seasonal-Trend decomposition using Loess）
  - **循环分布法**：计算月度/季度死亡构成比、季节指数
  - **ARIMA/SARIMA模型**：识别季节自相关
  - **Circular statistics**：Rayleigh检验、Watson-Williams检验（比较不同亚组季节分布差异）
- **可视化**：季节热图、极坐标图、STL分解图

### 3. 长期趋势与季节交互
- 分段STL：比较2015–2019与2020–2025（考虑COVID-19影响）
- 交互项模型：Poisson/NB回归中加入 `year × season`

## 四、减寿分析（YLL & YLL率）

### 1. 核心指标
- **YLL**（Years of Life Lost，减寿年数）：
$$YLL = \sum_{i} d_i \times (L - a_i)$$
其中 $d_i$ 为某年龄组死亡数，$L$ 为目标寿命（建议用**期望寿命**，如75岁或本地期望寿命），$a_i$ 为死亡年龄组中值。

- **YLL率**：$YLL率 = YLL / 人口数 \times 10万$
- **AYLL**（平均减寿年数）：$AYLL = YLL / 死亡数$
- **标化YLL率**：用标准人口年龄结构标化

### 2. 分析层次
- **年度YLL/YLL率**：2015–2025逐年
- **性别YLL/YLL率**：男女对比
- **年龄组YLL**：识别主要减寿年龄段
- **亚类YLL**：各亚类贡献
- **趋势分析**：Joinpoint回归YLL率

### 3. 软件实现
- R包：`YLL`、`epitools`、`DALY`
- Excel模板：WHO YLL计算表
- Stata：`daly` 命令

## 五、Arriaga分解方法

### 1. 方法原理
Arriaga分解用于**量化各年龄组/死因对期望寿命差异的贡献**，将两组人群（如2015 vs 2025、男 vs 女、城 vs 乡）期望寿命差分解为：
- **直接效应**（Direct effect）：某年龄组死亡率变化对期望寿命的贡献
- **间接效应**（Indirect effect）：存活人数变化带来的后续效应
- **交互效应**（Interaction effect）

### 2. 分解公式（简版）
对于年龄组 $i$：
$$nE_i = \frac{l_i}{l_0}\left(\frac{L_i^{2}}{l_i^{2}} - \frac{L_i^{1}}{l_i^{1}}\right) + \frac{T_{i+n}^{2}}{l_0}\left(\frac{l_i^{1}}{l_i^{2}} - 1\right)$$

其中上标1、2代表两组人群，$l$ 为存活人数，$L$ 为人年数，$T$ 为剩余总人年数。

### 3. 应用场景
- **时间维度**：2015 vs 2025 期望寿命差异分解
- **性别维度**：男女期望寿命差分解
- **地区维度**：城乡期望寿命差分解
- **死因维度**：心脑血管各亚类对期望寿命变化的贡献

### 4. 软件实现
- **R包**：`DemoDecomp`（HMD官方推荐）、`decompR`
- **Excel模板**：Arriaga方法计算表（可自制）
- **Stata**：`arriaga` 命令
- **Python**：`lifetable` + 自定义分解函数

### 5. 结果呈现
- 贡献值表（各年龄组/死因贡献年数）
- 瀑布图（Waterfall plot）
- 堆叠条形图（正负贡献）

## 二、时间序列分析

时间序列分析旨在回答两个问题：其一，2015—2025 年间某地区心脑血管疾病死亡率是否存在稳定的长期上升、下降或平台趋势；其二，死亡率是否存在年内季节性波动，例如冬季高发、夏季低发，或不同亚类具有不同季节形态。长期趋势与季节性趋势应分开建模和解释，因为二者对应不同的公共卫生机制：长期趋势可能反映医疗可及性、危险因素暴露、人口老龄化和诊断编码变化；季节性趋势则更可能反映气温变化、呼吸道感染、血压波动、行为模式改变以及医疗资源季节性紧张等因素。

在指标口径上，建议以年龄标化死亡率为主要长期趋势指标，以粗死亡率和死亡人数作为辅助描述。粗死亡率受年龄结构影响较大，若 2015—2025 年间某地区人口老龄化明显，粗死亡率上升不一定意味着各年龄组死亡风险上升。因此，长期趋势的解释应以年龄标化率为核心，并明确标准人口的选择。若标准人口尚未确认，则该标化口径待确认。季节性分析可采用月度或周度死亡率，计算季节指数、月度均值与全年均值之比，或采用时间序列分解方法分离趋势项、季节项和随机项。拟议方法包括：对月度率序列采用 STL 分解或季节性 ARIMA 模型；若数据为年度内多时点重复横截面，也可采用泊松回归或负二项回归，以月份虚拟变量控制季节性，以年份项或样条函数拟合长期趋势。适用条件包括：死亡率数据在时间上具有可比的分母和报告完整性；月份或周次划分一致；若存在报告延迟或编码变更，需在模型中设置断点或敏感性分析。上述方法为拟议设计，具体模型选择需在数据来源和年份边界确认后确定。

解释依据方面，长期趋势若呈下降，可能反映高血压管理、吸烟率下降、急救体系改善或二级预防覆盖提高；若呈上升或平台，可能反映人口老龄化、糖尿病和肥胖患病率上升、空气污染暴露或医疗资源不均。季节性峰值的解释需谨慎：冬季高峰可能与低温、流感和其他呼吸道感染、血压升高及体力活动减少有关，但不得将一般规律写成本研究已观察到的结果。若某地区数据覆盖不全或存在死亡登记延迟，季节性的幅度和相位可能被低估或偏移，需在不确定性说明中体现。

## 三、分组比较

分组比较的目标是识别心脑血管疾病死亡风险在不同性别、地区、人群和亚类之间的差异，并判断这些差异是否在 2015—2025 年间保持一致，还是随时间扩大或缩小。比较逻辑应遵循“先描述、后标化、再解释”的顺序：先给出各组的死亡人数、粗死亡率和年龄标化死亡率；再以率比、率差或集中指数等指标衡量相对差异和绝对差异；最后结合年龄结构、危险因素分布、医疗可及性和死因编码质量解释差异来源。

分性别比较方面，指标口径应包括男性、女性的年龄标化死亡率、性别率比和率差。解释依据通常涉及男性吸烟、饮酒、高血压控制率较低以及女性寿命更长但高龄段死亡率较高等因素。但具体到某地区，性别差异的方向和幅度需由实际数据确认，不能预设男性一定高于女性。分地区比较方面，需明确“地区”是省级、市级、区县还是城乡分类。若为城乡或区域分类，应使用同一标准人口进行年龄标化，并注意地区间死亡登记完整性和医疗资源差异。分地区比较的候选方案包括：按行政区划、按城乡二分、按社会经济水平分组或按地理气候带分组；具体采用哪一种待确认。分人群比较方面，候选维度包括年龄组、职业、教育程度、收入水平、医保类型或民族等。若采用年龄组比较，应注意高龄组死亡率的竞争风险和信息偏倚；若采用社会经济分组，应注意分母人口与死亡登记匹配问题。分亚类比较方面，心脑血管疾病可进一步分为缺血性心脏病、脑血管病、高血压性心脏病、心力衰竭、心律失常等。亚类定义应依据国际疾病分类编码，并明确编码版本和死因链选择规则。若亚类定义尚未确认，则亚类比较的候选方案为：按 ICD 章节或区块分组、按主要死因与根本死因区分、按出血性与缺血性脑血管病区分；具体口径待确认。

在解释依据上，分组差异可能来自真实风险差异、诊断和编码习惯差异、死亡登记完整性差异以及人口年龄结构差异。因此，任何分组比较都应同时报告标化前后的结果，并说明缺失数据如何处理。若某些年份或地区存在死亡数缺失，不得将缺失改为零值，也不得默认未知口径。对于小人群或稀有亚类，应报告置信区间或采用平滑方法，避免因随机波动产生过度解释。上述分组维度与亚类定义为候选方案，最终选择待确认。

## 四、减寿分析

减寿分析旨在衡量心脑血管疾病导致的早死负担，而不仅关注死亡数量。年度与性别的 YLL 和 YLL 率是本部分的核心指标。YLL 的基本计算口径为：对每一例死亡，计算其死亡年龄与参考寿命表中该年龄对应的预期剩余寿命之差，再按年份、性别和死因汇总。YLL 率通常为 YLL 除以对应人群的人口数或每十万人口，也可按年龄标化后比较。年度比较用于判断 2015—2025 年间早死负担是否下降；性别比较用于判断男性与女性在早死负担上的差异。比较逻辑应包括绝对 YLL、每十万人口 YLL 率、平均每例死亡 YLL 以及 YLL 率比或率差。若参考寿命表尚未确认，则 YLL 和 YLL 率的绝对数值无法最终确定，该口径待确认；本报告不写入具体寿命表数值，也不以惯例值替代。

在解释依据上，YLL 同时受死亡数量、死亡年龄分布和参考寿命表选择影响。若某地区心脑血管疾病死亡人数下降但 YLL 下降不明显，可能说明死亡向高龄集中，早死比例未同步改善；若男性 YLL 率高于女性，可能与男性早死风险更高有关，但需结合年龄别死亡率和参考寿命表确认。参考寿命表的选择会影响不同人群之间的比较：使用同一参考寿命表有利于比较，但若某地区实际预期寿命与参考寿命表差异较大，YLL 的绝对水平可能被高估或低估。因此，应明确参考寿命表来源、年份、性别和年龄分组，并进行敏感性分析。缺失数据、死亡年龄报告偏倚和人口分母不准确均会影响 YLL 率，需在不确定性说明中体现。

## 五、Arriaga 分解

Arriaga 分解用于将两组之间死亡率差异或预期寿命差异分解为年龄别死亡率和死因构成的贡献。本部分的分解对象拟为 2015—2025 年间某地区心脑血管疾病死亡率或预期寿命的变化，比较组可设为不同年份、不同性别、不同地区或不同人群。年龄分组拟采用五年一组或十年一组，具体分组待确认；死因分类拟依据心脑血管疾病亚类，如缺血性心脏病、脑血管病、高血压性心脏病等，具体编码口径待确认。拟议方案包括：以 Arriaga 方法分解年龄别死亡率差异的直接效应、间接效应和交互效应，并进一步按死因拆分贡献。适用条件包括：两组人群的年龄分组一致；死亡率和人口分母可比；死因分类在两组间一致；若存在编码变更或登记完整性差异，需在解释中说明。

解释依据方面，Arriaga 分解可回答“哪个年龄组的死亡率变化对总差异贡献最大”以及“哪个死因亚类的贡献最大”。例如，若老年组贡献较大，可能反映人口老龄化和高龄段心血管死亡风险；若中年组贡献较大，可能反映早死风险和二级预防不足。但具体贡献方向和大小需由实际数据计算，不能预设。若参考寿命表或年龄分组未确认，则分解结果无法最终确定，该部分为拟议设计。缺失数据、年龄报告偏倚和死因编码差异会影响分解结果的稳健性，需通过敏感性分析检验。

### 三、比较条件与同信息对照

同信息对照设两组，均获得逐字相同的确认信息。信息流拟议为：先针对同一案例取得实际确认信息，封存于只读文档并计算校验值；两组在同一时间获得同一份逐字文本。两组增强流程保持各自指定方式，不改写任一组回答、不另换任务、不单组增加修订轮次。直接组不追问不等于不能使用已提供答案。该对照用于比较“是否经历问答”与“是否获得同等信息”的差异。

### 四、随机化与盲法

任务与重复顺序按上述区组随机化执行。评审材料去除模式标签、组别、轮次与模型身份，仅保留任务、提示词及必要上下文；同一任务的所有模式结果拟由同一评审在盲态下评分，以减少任务难度造成的评审偏差。两名独立评审分别盲评，互不交流评分。实施步骤为：材料匿名化、随机编号、分发评分表、独立评分、回收后统一比对。若评审对同一任务的所有模式结果评分，需在评分表中固定任务内顺序随机，避免位置效应。

### 五、评价

四项评价均针对提示词质量：准确性指提示词是否忠实反映任务需求与确认信息；完整性指是否覆盖关键约束与必要步骤；清晰度指表述是否明确、无歧义；可执行性指据此提示词能否直接开展任务。评审所见材料为匿名化后的任务说明、确认信息与提示词，不展示模式来源。评分形式拟议采用7点李克特量表，并允许评审填写简短理由；适用条件为评审经统一培训、评分标准书面化。若后续需要更细粒度，可改为分项0—4分，但须在实施前固定。

### 六、分歧处理与统计

两名评审评分不一致时，先检查是否因材料理解或标准误用；若差异在预设范围内，取平均分；若超出范围，由第三名评审仲裁或双方复核后重新评分。统计检验依据未来数据分布与配对结构选择，不预先选定，也不预设显著性。候选方法包括：配对t检验或Wilcoxon符号秩检验，适用于同任务同重复的配对比较；混合效应模型，适用于任务与重复嵌套结构；若评分分布严重偏态，采用非参数方法。所有分析前检查缺失、异常与前提条件。

### 七、边界

已知事实为：4类任务、每类5个、共20个；每模式每任务重复3次；两名评审盲评；比较直接增强与Plan，并设同信息对照。用户确认信息为上述约束与公平对照要求。必要假设包括：任务具有可比性、评审能按标准评分、确认信息可封存并逐字提供。缺失数据、偏倚、不确定性与方法适用条件须在实施前记录；若确认信息不足或评审标准不稳定，结论仅限当前任务与流程，不推广至未验证情境。正文800至1200个汉字是否包含标题、摘要或关键词，拟议为仅计正文，不含标题、摘要、关键词、附表与代码；该口径须在实施前确认。

## 方法

**研究问题与设计一致性。** 本研究旨在比较直接增强与Plan两种问答模式对提示词质量的影响，并排除确认信息可得性差异的干扰。为此，设计采用2（增强模式）×2（信息条件）的配对结构：直接增强组与Plan组构成主比较；另设两个同信息对照组，分别按直接增强与Plan流程运行，但均获得与Plan组逐字相同的确认信息。四组共用同一批任务，使模式效应与信息效应可分离，与研究问题直接对应。

**任务与材料。** 拟定任务池包含4类提示词生成任务：文本生成、信息抽取、逻辑推理与格式转换，每类5个，共20个任务。任务均为可客观核验的指令型问题，不含需外部数据库或专有知识才能完成的内容。每模式每任务独立重复3次，共产生240条提示词（4组×20任务×3重复）。重复的目的在于估计组内变异，而非扩大样本推断总体。

**比较条件与同信息对照。** 直接增强组仅依据原始任务一次性生成提示词，不主动追问，但可使用任务中已提供的答案或示例。Plan组由增强器先提出关键澄清问题，研究者依据同一案例的真实信息作答，再生成提示词。同信息对照的信息流拟议如下：先运行Plan组，记录其全部问答及研究者确认信息，将确认信息按任务封存；随后同信息直接组与同信息Plan组均获得该逐字相同的确认信息后执行各自流程。两组均不追加修订轮次、不另换任务、不改写回答；Plan组问答拟设每任务最多3轮，达到3轮或增强器表示信息充分即终止。该流程确保同信息两组仅在是否经历追问上不同，而非信息内容不同。

**拟议设计。** 上述方案为拟议主方案，尚未实施。任务与重复的呈现顺序拟采用分层随机：20个任务随机排列，每任务内4组×3重复按随机顺序呈现，同一任务的所有条件在同一区组内完成，以减少任务间干扰。两名评审对同一任务的全部12条结果（4组×3重复）盲评。四项指标——准确性、完整性、清晰度与可执行性——均针对提示词本身评分，评审所见材料为去标识化提示词文本及对应任务，不含组别与重复标签。评分拟采用7点Likert量表，每项单独计分，不合成总分；若后续预试验显示区分度不足，可改为0–3分行为锚定评分，该调整需在正式评分前确定并记录。

**统计。** 正式统计方案待数据收集后依据分布特征确定。若各项评分近似正态且方差齐性，拟采用线性混合模型，以模式、信息条件及其交互为固定效应，任务与重复为随机效应；若评分呈明显偏态或离散，改用累积链接混合模型或对齐秩变换后的方差分析。配对结构下，同信息两组的比较采用配对检验。所有检验均为双侧，显著性水平待数据收集前在预注册中确定，不预设结论。

每个任务在四种模式下的12次生成（4模式×3重复）按随机顺序提交给模型，生成顺序由计算机生成的随机数表决定。两名评审对全部生成结果进行盲评，评审不知晓每条结果所属的模式、任务重复序号及研究假设。评审对同一任务的所有模式结果均评分，以支持配对比较。评分材料中不出现任何可识别模式来源的标记。

## 四、评价指标与分歧处理

准确性、完整性、清晰度与可执行性四项指标均采用5点Likert评分，1分为最低，5分为最高。评分前对两名评审进行校准培训，使用与正式任务相似但不相同的练习材料，统一评分标准。正式评分中，若两名评审在同一项目上评分相差超过1分，则启动分歧处理程序：先由两名评审独立复核，若仍不一致，由第三名资深评审裁定。最终分析采用两名评审的均分；若引入第三评审，则采用三人均分。

## 五、统计检验的候选方法

统计方法的选择将依据未来数据的分布特征与配对结构确定。若各指标评分近似正态且方差齐性满足，可采用重复测量方差分析，将提示模式作为四水平组内因素，任务作为随机因素；若需比较Plan与直接增强的差异，可预设线性对比。若数据呈偏态或评分视为有序分类变量，可采用Friedman检验作为整体检验，并以Wilcoxon符号秩检验进行配对事后比较，同时采用适当的校正方法控制多重比较。若需同时考察四项指标的联合差异，可考虑多元方差分析，但需满足协方差矩阵齐性等条件。所有检验均为双侧，显著性水平预设为0.05。本研究不预设任何模式必然显著，仅报告效应方向与置信区间。
