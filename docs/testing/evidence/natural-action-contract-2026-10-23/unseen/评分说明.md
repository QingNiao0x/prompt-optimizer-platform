# 自然增强动作与成果留出评分说明

本文件与 sealed-cases.json 一起在候选开启前冻结。它规定评测边界，不预设唯一范文，不授权任何真实模型调用。题目作者是同一开发系统内的独立子代理，未读取本轮候选指导和本轮开发题，但知晓用户报告的共同缺陷及历史分析，因此只能称为内部留出。

## 1. 题目及信息使用

共十题：八题 DIRECT、两题 PLAN。题目涵盖当前理解、明确短反馈、理解后明确作品、未来条件操作、背景创作动词、写作、分析、受托设计，以及重要未知与充分委托的两类 Plan。

input 是原始提示词，context 是所有臂可用的同一材料。answerCard、维度、评分示例不得发给增强或执行模型；它们只供评分。不要把标准答案、计算结果、未知状态分类或候选内部任务理解额外注入下游。

Plan 运行时只依据每道实际问题选择对应冻结回答，保留题号与问答原文。不要将同一答案捆绑复制成多个问题的覆盖证据。对于重要未知，预设回答在原始输入阶段不可见。无价值问题按冻结的 unexpectedQuestionReply 回应并单独记录提问缺陷，不能假装用户自行提供了额外设计偏好。

实际作品的公平轨道向三臂提供同一原始材料与逐字真实确认。若两版本问题不同，同一信息比较应使用冻结且对原始要求合法的确认集合；必须同时保留实际 Plan 题答与自然流程结果，说明该公平轨道不能证明未提问版本的自然问答能力。不得给一个臂提供独有信息后把差异称为正文质量收益。

## 2. 分开评价的四件事

1. 工程/协议：首次和最终有效率、协议修复、最终正文与历史一致；失败不能伪装为语义持平。
2. 动作与成果边界：哪些是本次动作、背景事实、未来有条件动作，以及用户要求或任务自然需要的结果。理解任务可以有短反馈；明确的摘要、说明、分析结论和设计不得被取消。
3. 实质补全：新增内容是否填补一个实际执行缺口，是否帮助交付完整、可执行且便于使用的结果。更长、标题更多、框架更齐全不计收益；充分需求允许不改。
4. 下游实际作品：在同信息条件下逐项说明错误与必要修改。下游首次出现错误不直接等于增强无责，也不直接等于平台缺陷；解盲后沿原始输入、任务理解、正文、组装、作品定位。

## 3. 最少必要修改的计数

计数单位是一个独立语义问题所需的最小修复操作，不是句数、字符数或审阅者偏好的文风。不把同一根因在正文重复三次记为三个收益。一个缺陷可有多个标签，但严重度与修改数只计一次。

| 分类 | 含义 |
| --- | --- |
| FACT / CALCULATION | 恢复事实、单位或数值计算 |
| STATE | 恢复确定程度、时间状态、未提供与不存在、拟议与完成 |
| AUTHORITY / PRIVACY | 恢复执行前提、主体权限及明确的信息范围 |
| SCOPE | 删除无依据的新任务、新作品或不相关义务，或恢复被替换任务 |
| OMISSION / CONSTRAINT | 补回明确要求、独立条件或例外 |
| EXECUTABILITY | 将缺少必要步骤/方式的交付补成可实际使用的内容 |
| FORMAT | 修复用户明确的行数、句数、表格、顺序等格式 |
| STYLE_ONLY | 不影响实际使用的文风选择；不计最低必要修改 |

SEVERE：原任务或交付被替换/取消、当前理解变成执行、事实/数字错误影响结论、用户明确权限或隐私越界、确认状态被升级等。
MAJOR：必须修改才适合直接使用的遗漏、无依据强制新作品、关键步骤不清或明确格式失守。
MINOR：确需修改但不改变事实和决策的局部表达。仅审美偏好不得记为 MINOR。

“文档”一词本身不是违约证据。需要判断是否新增了独立义务、长度/范围负担，或用另一种产物替换当前任务。简短理解反馈或用户明确要求的交接卡/报告均可以是正确结果。同样，不因出现“建议”“步骤”就判为越权；受托设计本来就需要由 AI 提出具体安排。

## 4. 匿名审阅

至少两份相互不交换初判的匿名审阅。审阅者先看原始输入、材料、实际确认和匿名作品，不看候选名、策略品牌或生成记录。逐项提供问题原句、违反的具体要求、最小修复与严重度，再给胜/平/负/双方失败。解盲以后才定位增强或下游责任。

AI 辅助评审必须标为内部 AI 评估，不称为人工或专家验收。分歧保留；必要时单独裁决，不能只采用有利分数。完整性和格式先用独立检查器检查；其输出只是证据，复杂语义不能靠正则替代。

## 5. 候选采用建议（由主代理在开启前确认冻结）

- 目标机制：十题候选增强均保留正确的当前动作、明确结果和条件，不出现新增严重任务/事实/授权错误。没有明确作品的题不能强制追加独立文档，明确作品的题不能被取消。
- 相比第四版，记录每种共同缺陷减少多少；若第四版未复现，不能编造“已修复”胜出，需结合独立回归证据说明收益。
- 正文实质收益：至少两道不同类型任务在两次同信息作品中均有可解释的实际改善；不把基线协议缺失当成语义胜利，充分需求持平不扣分。
- 正常变体：不得新增严重退步；最低必要修改总量应降低，但不能用多个小收益抵消一次严重越界。
- Plan：重要未知被有效询问，充分委托无需提问，实际回答后可生成且保留确认范围。问题数量少不自动等于提问有效。
- 分别报告目标修复、整体正文、Plan 与协议，不以一个维度通过覆盖另一个维度失败。有限内部留出通过不代表跨领域正式发布验收完成。

这些是本假设和本题集的事前建议，不复用历史统一胜率。若主代理选择不同采用判据，须在打开题文和获取候选结果前单独冻结理由；不得事后改阈值。

## 6. 调用分配建议

按十题全部三臂作品各两次计算：两版本增强二十次、两道 Plan 的两版本规划四次、三臂作品六十次，共八十四次基础调用。可预留八次协议修复、四次付费匿名整理/评审，总上限九十六次；若评审由当前开发代理完成，它不算外部模型 API 调用，但仍需披露参与程度。

失败、真实协议修复、付费评审都计入正式总账；不得为了完成题集超过冻结阶段上限。发现影响采用的严重失败可及时停止扩大采样并复核根因。若为修复而使用了这些留出题，后续采用需要新的未见题，不能反复运行本题集挑出满意作品。
