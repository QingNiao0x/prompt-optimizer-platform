# 单次生成内保真自检：第四版与第二十版有限对照

本批仅比较第四版与第二十版的单次正文生成，不继续独立检测、修订或模型评审路径。默认版本仍为第四版；第二十版只替换第四版已有自检段，原始来源、任务记录、覆盖与安全保护保持不变，Plan继续使用第四版指导。

本文件和工具将在调用前冻结，收口另写 `RESULTS.md`，不覆盖冻结原件。`offline-validation.json` 由父任务在最终测试后写入；该文件缺失时不能启动冻结运行副本。

## 固定范围与调用

- 总上限80次，阶段上限为GENERATION 40、PLAN 4、EXECUTION 36、REVIEW 0；失败及协议修复均计数，不进行质量重试。
- 旧十题原始请求、材料和实际答复保持不变。新四题覆盖状态核查与执行授权、实际未知与资料缺口、委托设计与已确认事实、独立条件与例外。
- 新四题的文本尚未用于模型调用，但其机制来自本轮已经看过的失败，标为 `FRESH_INPUT_SEEN_MECHANISM`，只能称新输入压力验证，不能称独立盲测。
- 十四个输入各增强两次，即4/20共28次正常生成。维护通知共用一次真实第四版Plan，实际题目和完整答复按同一服务端上下文绑定。
- 原六主任务、小组交接、Plan维护通知和新四题，共十二题生成RAW/4/20三臂实际作品，正常36次；两个严格格式控制仅验增强正文，不生成作品。
- 正常调用合计65次，最多80次。所有本批新增调用计候选预算，不转移历史已关闭余额；原始分配见 `protocol.json`。

## 验收边界

保真维度必须先确认第四版本身存在有证据的问题，再判断第二十版是否修复。两版均正常只记相持，不记提升；不把更长、更严或更多功能作为质量收益。用户已委托的设计继续由AI完成，拟议设计、明确假设和示例不能当成现实事实，也不能因未逐字复述委托而判遗漏。

实质补全维度单独保留旧六主题“至少3/6提示词明确收益、至少3/6实际作品明确收益”的两个门槛。四个新压力题及局部保真改善不加入该分母，不替代该门槛。不修改旧gold、旧分数或旧未通过结论来获得通过。

提示词、平台保护和实际作品分别评估。实际作品核对目标、条件、正确性、可直接使用程度及必要修改量；增强模型、下游执行和工具问题分开归因。只有有原件支撑的对照收益才可称提升；未改善或再现同类严重问题就保留第四版，停止本假设，不继续追加同义指导或critic采样。本批不证明专业全场景或整体发布门禁通过。

## 工具与执行

`start-evaluation.ps1` 仅在父任务显式运行后创建独立运行副本并启动9003回环进程，不接管已有进程、不迁移数据库、不创建账号。它冻结全部后端主源码、运行时classes、题目、协议、脚本、最终离线验证和实际编译后的4/20/Plan指导。每次上游传输前重新检查指纹、模型参数、题目、版本及调用预算。

`invoke-evaluation.ps1 -Command all` 使用固定合成账号的既有DPAPI凭据登录；账号、租户和工作区均复用 `tmp/local-acceptance/account.json`。密码与Cookie只在进程内存，不打印或写入公开证据。登录和读历史不计模型调用。

执行顺序为全部同信息4/20增强、一次共同Plan及两臂确认后增强、历史一致性检查、实际作品。Plan若无实际题目，则记录回答链路未验证并停止，不构造伪确认。历史正文、版本或约束不一致时停止实际作品。三臂作品均携带同一材料与实际答复。

结果及调用原件仅新增、不覆盖。中断后可重用完全一致且已记录的作业；已预留但没有结果的尝试不得自动重发。恢复共同Plan时沿用原context引用，不用新上下文套旧Plan；服务端TTL失效不能伪造或延长所有权。`-Command count` 只读取本批调用总账。所有数据均为合成开发数据；评估和收口由父任务执行，不引入模型评审调用。
