# 研究设计：用户先回答关键问题再增强提示词 vs. 直接增强提示词

## 一、研究问题与假设

**核心研究问题**：在提示词增强任务中，先让用户回答关键澄清问题再生成增强提示词，是否比直接增强产生更高质量的提示词和更好的任务结果？

**假设**：
- H1：交互式澄清条件下的增强提示词在“意图匹配度”上显著高于直接增强条件。
- H2：交互式澄清条件下的增强提示词在“下游任务表现”上显著高于直接增强条件。
- H3：交互式澄清条件下的用户满意度显著高于直接增强条件。
- H4：交互式澄清的增益在“模糊/复杂任务”上大于“清晰/简单任务”（调节效应）。


## 二、实验设计

### 2.1 总体设计

采用 **2×2 混合设计**：

| 因素 | 水平 | 类型 |
|------|------|------|
| 增强方式（A） | A1: 直接增强；A2: 先澄清后增强 | 被试间 |
| 任务复杂度（B） | B1: 简单/清晰；B2: 复杂/模糊 | 被试内 |

- **被试间变量**：增强方式（避免学习效应和顺序效应污染）
- **被试内变量**：任务复杂度（每个参与者都完成两类任务，提高统计效力）

### 2.2 参与者

**招募渠道**：
- 通过大学被试库、社交媒体（如Reddit r/PromptEngineering、AI相关Discord群）、专业众包平台（Prolific）招募。
- 筛选条件：具有基础LLM使用经验（至少使用过ChatGPT/Claude等产品≥3次），能读写中文或英文。

**样本量估算**：
- 预期效应量 d = 0.5（中等效应），α = 0.05，power = 0.80。
- 被试间比较（两组）：每组需约64人，共 **128人**。
- 考虑20%流失率，建议招募 **160人**。
- 若资源有限，可缩减为每组40人（共80人），此时可检测到 d ≈ 0.63 的效应。

### 2.3 任务材料

**任务池构建**：准备8个提示词增强任务（4个简单/清晰，4个复杂/模糊），每个任务包含：
- 一段原始用户提示词（如“帮我写一封邮件” vs. “帮我做一个关于公司战略的东西”）
- 任务背景简述
- 期望输出类型

**任务复杂度操作化**：
- **简单/清晰**：目标明确、约束少、输出格式清晰（如“写一封请假邮件给HR”）。
- **复杂/模糊**：目标含糊、涉及多步骤或多维度决策、需要领域知识（如“帮我规划一个新产品上市方案”）。

**材料示例**：

| 编号 | 复杂度 | 原始提示词示例 |
|------|--------|----------------|
| T1 | 简单 | “帮我写一封感谢面试官的邮件” |
| T2 | 简单 | “把这段文字翻译成英文” |
| T3 | 简单 | “写一个Python函数计算斐波那契数列” |
| T4 | 简单 | “总结以下会议纪要的要点” |
| T5 | 复杂 | “帮我做一个市场分析” |
| T6 | 复杂 | “写一份商业计划书” |
| T7 | 复杂 | “帮我设计一个用户调研方案” |
| T8 | 复杂 | “分析我们公司应该进入哪个新市场” |

### 2.4 实验流程

```
┌─────────────────────────────────────────────────┐
│ 1. 知情同意 + 前测问卷（LLM经验、人口学信息）      │
├─────────────────────────────────────────────────┤
│ 2. 随机分组                                      │
│    ├── A1组：直接增强条件                        │
│    └── A2组：澄清后增强条件                      │
├─────────────────────────────────────────────────┤
│ 3. 任务说明 + 练习试次（1个，不计入分析）          │
├─────────────────────────────────────────────────┤
│ 4. 正式任务（8个任务，顺序随机化/拉丁方平衡）      │
│    A1组：看到原始提示词 → 直接写增强版提示词       │
│    A2组：看到原始提示词 → 回答3-5个澄清问题       │
│           → 系统基于回答生成增强提示词             │
│           → 用户可修改 → 确认最终版               │
├─────────────────────────────────────────────────┤
│ 5. 每个任务后：主观评价（意图匹配度、满意度）       │
├─────────────────────────────────────────────────┤
│ 6. 全部任务后：后测问卷（整体体验、认知负荷、       │
│    开放反馈）                                    │
└─────────────────────────────────────────────────┘
```

### 2.5 关键操作细节

**A1组（直接增强）**：
- 参与者看到原始提示词后，直接在文本框中撰写增强版提示词。
- 无任何系统引导或澄清问题。

**A2组（澄清后增强）**：
- 参与者看到原始提示词后，系统依次呈现3-5个关键澄清问题（如“目标受众是谁？”“期望的输出格式是什么？”“有什么约束条件？”）。
- 参与者回答后，系统基于原始提示词+回答自动生成增强提示词草稿。
- 参与者可编辑修改，确认最终版。
- **关键**：澄清问题由研究者预先针对每个任务设计，确保两组在“可获得的信息量”上公平——A2组通过回答问题提供信息，A1组则被明确告知“请在增强提示词中包含你认为必要的所有信息”。

**公平性保障措施**：
1. **时间控制**：两组总时间限制相同（如每个任务5分钟），避免A2组因额外步骤获得更多思考时间。
2. **信息对等说明**：A1组明确告知“你可以自由添加任何你认为必要的细节”；A2组通过回答问题添加细节。两组最终增强提示词的信息丰富度理论上可达同等水平。
3. **LLM固定**：使用同一LLM（如GPT-4o或Claude 3.5 Sonnet），温度设为0.3，确保下游评估的一致性。
4. **A2组的系统生成环节**：为公平比较“澄清的价值”而非“用户写作能力”，A2组由系统基于回答生成草稿，但允许用户编辑。同时，A1组也提供“AI辅助润色”选项（可选），以平衡工具辅助效应。


## 三、结果测量

### 3.1 主要结果指标

| 指标 | 测量方式 | 评分者 |
|------|----------|--------|
| **意图匹配度**（主要） | 盲评：3位独立评分者用7点Likert量表评估增强提示词是否准确捕捉了原始意图 | 外部评分者（不知晓实验条件） |
| **下游任务表现**（主要） | 将增强提示词输入固定LLM，由评分者评估输出质量（7点量表，维度：相关性、完整性、准确性、可用性） | 外部评分者 |
| **用户满意度**（次要） | 每个任务后自评（7点量表：“你对最终增强提示词满意吗？”） | 参与者 |
| **认知负荷**（次要） | NASA-TLX简化版（3题：心理需求、努力程度、挫败感） | 参与者 |
| **效率**（探索性） | 完成任务所用时间（秒） | 系统记录 |

### 3.2 评分者间信度

- 3位评分者独立评分，计算ICC（组内相关系数）。
- 若ICC < 0.70，则增加评分者或进行校准讨论后重新评分。


## 四、数据分析计划

### 4.1 主要分析

**线性混合模型（LMM）**：

```
评分 ~ 增强方式 × 任务复杂度 + (1|参与者) + (1|任务)
```

- 固定效应：增强方式（A1 vs. A2）、任务复杂度（简单 vs. 复杂）、交互项
- 随机效应：参与者、任务（处理任务间差异）

### 4.2 次要分析

- 独立样本t检验或Mann-Whitney U检验（若数据非正态）比较两组在满意度、认知负荷上的差异。
- 调节分析：检验任务复杂度是否调节增强方式的效果（即交互项是否显著）。
- 探索性分析：时间效率与质量的关系（质量-效率权衡）。

### 4.3 效应量报告

- 报告Cohen's d（组间比较）和η²p（方差分析）。
- 报告95%置信区间。

## 六、预测试（Pilot Study）

正式实验前进行小规模预测试（N=10-15）：

1. 检验任务材料的复杂度操作是否有效（简单任务是否确实被评为简单）。
2. 检验澄清问题的质量和数量是否合适（是否过度引导或不足）。
3. 检验实验流程的时间是否合理。
4. 检验评分量表的信度。
5. 根据预测试结果调整材料和流程。


## 七、潜在偏差与控制

| 偏差来源 | 控制措施 |
|----------|----------|
| 参与者能力差异 | 随机分组 + 前测LLM经验作为协变量 |
| 任务顺序效应 | 拉丁方平衡/随机化 |
| 评分者偏差 | 盲评（评分者不知晓条件）+ 多评分者 |
| 时间差异 | 统一时间限制 |
| 工具辅助效应 | A1组也提供可选AI润色 |
| 需求特征 | 使用中性指导语，不透露具体假设 |
| LLM输出随机性 | 固定温度参数，必要时多次采样取均值 |


## 八、适用条件与局限性

### 适用条件
- 参与者需具备基础LLM使用能力。
- 需有稳定的LLM API访问权限。
- 任务类型为“提示词增强”场景（即用户已有初步提示词，需要优化）。

### 局限性
1. **生态效度**：实验室环境中的澄清问题是预设的，而真实场景中可能是动态生成的。后续可研究LLM自动生成澄清问题的效果。
2. **任务类型有限**：仅覆盖文本生成类任务，未涉及代码、多模态等。
3. **单次交互**：仅测试一轮澄清，真实场景可能多轮迭代。
4. **LLM依赖性**：结果可能随所用LLM版本变化，建议在多个LLM上重复验证。


## 九、预期贡献

若假设成立，本研究将提供实证证据支持“先澄清后增强”的交互设计，为提示词优化工具（如提示词工程助手、AI写作工具）的设计提供指导。若假设不成立（即直接增强同样有效），则说明澄清步骤可能是不必要的摩擦，工具设计应更注重快速迭代而非前置澄清。无论结果如何，研究都将为“人机协作中信息收集时机”这一更广泛的设计问题提供证据。
