这个方向可以做成一个很扎实的对照实验。下面给你一套可直接落地、且尽量公平的研究设计。核心思路是：**把“是否先问用户问题”作为唯一操纵变量，其他环节（底层增强模型、增强模板、输出格式、任务集、评价方式）全部保持一致。**

---

## 一、研究问题与假设

### 研究问题
1. 在提示词增强系统中，先让用户回答少量关键问题再增强（交互式增强），是否比直接增强（单轮增强）产生更好的最终输出？
2. 这种收益是否随任务类型变化？
3. 收益是否值得用户额外投入的交互成本？

### 假设
- **H1（主效应）**：交互式增强的最终输出质量显著高于直接增强。
- **H2（调节效应）**：在信息缺口大、约束多的任务上，交互式增强优势更大；在意图明确、上下文充足的任务上，两者差异不显著。
- **H3（成本）**：交互式增强会增加用户时间/认知成本，但若质量提升足够大，净收益仍为正。
- **H0（零假设）**：两者在最终输出质量上无显著差异。

---

## 二、实验条件设计

采用**被试内设计**为主，辅以被试间验证。推荐三条件：

| 条件 | 名称 | 流程 |
|---|---|---|
| C1 | 直接增强 | 用户输入原始提示 → 系统直接增强 → 生成输出 |
| C2 | 交互式增强 | 用户输入原始提示 → 系统问 3–5 个关键问题 → 用户回答 → 系统增强 → 生成输出 |
| C3 | 主动补充基线 | 用户输入原始提示 → 系统提示“可补充信息”但不提问 → 用户自由补充 → 增强 → 生成输出 |

C3 很关键：它区分了**“提问”本身的作用**和**“多一轮信息输入”的作用**。没有 C3，你无法判断收益来自“问题引导”还是仅仅来自“用户多说了话”。

### 关键控制
- 同一底层增强模型、同一版本、同一温度参数。
- 同一最终生成模型与解码参数。
- 增强模板除“是否插入问答”外完全一致。
- 问题由同一套问题生成策略产生，固定问题数量上限（如 4 个）。
- 所有条件最终增强后的提示词长度做统计控制（避免“更长=更好”的混淆）。

---

## 三、任务集设计

建议覆盖 4 类任务，每类 20–30 题，共 80–120 题：

| 任务类型 | 例子 | 信息缺口 |
|---|---|---|
| 创意写作 | 写品牌故事、短视频脚本 | 中 |
| 分析决策 | 市场进入分析、方案对比 | 高 |
| 信息提取/总结 | 从给定材料生成报告 | 低 |
| 代码/技术 | 生成函数、调试建议 | 中高 |

每题准备：
- 一个**初始用户提示**（故意保留自然的信息缺口，模拟真实用户）。
- 一个**参考答案或评分 rubric**。
- 一个**信息缺口清单**（专家标注：哪些信息若补充会显著改变输出质量）。

---

## 四、被试与分组

- 招募 60–120 名有 LLM 使用经验的被试。
- **被试内**：每人完成所有条件 × 部分任务，条件顺序拉丁方平衡。
- **被试间验证**：另招一组只做 C1 vs C2，避免练习效应质疑。
- 任务与条件交叉平衡，避免某题总出现在某条件。

---

## 五、测量指标

### 1. 主要结果变量：最终输出质量
采用**盲评**：
- 3 名评审（或 LLM-as-judge + 人工抽检）在不知道条件的情况下打分。
- 维度：相关性、完整性、具体性、可执行性、整体偏好。
- 用 1–7 Likert 或成对比较（Elo/Bradley-Terry）。
- 报告评分者间一致性（ICC / Krippendorff's α）。

### 2. 过程变量
- 用户回答问题的数量与字数。
- 增强后提示词长度、信息量。
- 用户补充信息中“被问题引导出来”的比例。

### 3. 成本变量
- 完成时间。
- 认知负荷（NASA-TLX）。
- 用户满意度与继续使用意愿。

### 4. 公平性变量
- 初始提示质量基线。
- 用户对任务的先验熟悉度。
- 任务难度评分。

## 六、实验流程（单被试单题）

1. 阅读任务背景。
2. 输入初始提示。
3. 系统按条件执行：
   - C1：直接增强 → 生成。
   - C2：生成 3–5 个问题 → 用户回答 → 增强 → 生成。
   - C3：提示可补充 → 用户自由补充 → 增强 → 生成。
4. 查看最终输出。
5. 填写满意度、TLX。
6. 进入下一题。

全程记录日志：时间戳、输入、问题、回答、增强后提示、最终输出。

---

## 七、分析与统计

### 主分析
- 线性混合模型（LMM）：
  `质量 ~ 条件 + 任务类型 + 条件×任务类型 + (1|被试) + (1|题目)`
- 若用成对比较，则用 Bradley-Terry 模型估计各条件胜率。
- 效应量报告 Cohen's d 或 η²，并给 95% CI。

### 调节分析
- 按任务类型分层。
- 按“初始提示信息缺口大小”分层（专家标注）。

### 成本-收益分析
- 计算每条件“质量提升 / 额外时间”。
- 做敏感性分析：质量提升到多少才值得额外交互。

### 稳健性
- 换一个增强模型复现。
- 换一批评审复评。
- 预注册分析计划，避免 p-hacking。

---

## 八、公平性保障清单

1. **同模型、同参数、同模板**，只改交互结构。
2. **C3 主动补充基线**，排除“多一轮输入”混淆。
3. **盲评**，评审不知道条件与假设。
4. **任务与条件交叉平衡**，避免题目难度偏置。
5. **控制提示词长度**，必要时把长度作为协变量。
6. **预注册**假设、样本量、分析方案。
7. **报告所有结果**，包括不显著与反例。
8. **用户成本纳入结论**，不只看质量。

## 九、可能的陷阱与应对

| 陷阱 | 应对 |
|---|---|
| 问题质量本身影响结果 | 固定问题生成策略，并单独评估问题质量 |
| 用户回答质量差异大 | 记录回答质量，作为协变量 |
| 练习效应 | 拉丁方平衡 + 被试间验证 |
| LLM-as-judge 偏差 | 人工抽检 + 多评审 + 位置随机 |
| 任务太简单导致天花板 | 预实验筛选难度适中题目 |
| 增强后提示变长 | 长度匹配或统计控制 |

## 十、最小可行版本（若资源有限）

- 40 名被试，60 题，3 条件。
- 只用 LLM-as-judge + 20% 人工复核。
- 主分析用成对比较 + 混合模型。
- 重点回答：**交互式增强是否在信息缺口大的任务上显著更好，且成本可接受。**
