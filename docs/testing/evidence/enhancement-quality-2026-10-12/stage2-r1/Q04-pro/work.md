# 研究设计文档：两种提示词增强方式的比较研究

> **文档状态说明**：本文档为研究设计，不包含任何实际数据、结果或已完成研究状态的陈述。所有参数分为三类标注：【已知事实】【用户确认】【必要假设】。未决参数一律标注为“待定”，不默认取值。


## 1. 研究问题与假设

### 1.1 研究问题

**核心问题**：在相同的任务场景下，“用户先回答若干关键问题、再基于回答增强提示词”（以下简称“先问后增强”）与“不询问用户、直接增强提示词”（以下简称“直接增强”）两种方式，在输出质量、用户满意度和交互效率上是否存在可检测的差异？

**子问题**：
- Q1：两种方式在任务输出质量上是否存在差异？
- Q2：两种方式在用户主观满意度上是否存在差异？
- Q3：两种方式在完成任务的交互成本（时间、操作步数）上是否存在差异？
- Q4：用户对“先问后增强”方式的额外询问环节的接受度如何？

### 1.2 研究假设

- **H1（质量假设）**：“先问后增强”条件下的任务输出质量均值高于“直接增强”条件下的任务输出质量均值。
- **H2（满意度假设）**：“先问后增强”条件下的用户主观满意度均值高于“直接增强”条件下的用户主观满意度均值。
- **H3（效率假设）**：“先问后增强”条件下的总交互时间均值高于“直接增强”条件下的总交互时间均值（即存在效率代价）。
- **H4（接受度假设）**：在“先问后增强”条件下，用户对询问环节有用性的主观评分均值高于量表理论中值（待定量表确定后明确）。

> 【必要假设】以上假设为双侧检验框架下的方向性假设，显著性水平 α 设为待定（建议值 0.05，但需在方案定稿时由研究负责人确认）。


## 2. 研究对象与样本

## 3. 实验设计与分组

### 3.1 总体设计

采用**随机对照实验（RCT）** 设计，将被试随机分配至两个实验条件之一：

- **条件 A（先问后增强）**：系统先向用户提出一组关键问题，用户回答后，系统基于“原始提示词 + 用户回答”生成增强提示词，再交由底层模型生成输出。
- **条件 B（直接增强）**：系统不向用户提问，直接基于“原始提示词”生成增强提示词，再交由底层模型生成输出。

### 3.2 随机化

- 随机化单位：个体被试。
- 随机化方法：分层区组随机化（stratified block randomization），分层变量为被试自报的 AI 使用频率（高/中/低，阈值待定）。
- 分配隐藏：使用中央随机化系统或预先生成的随机序列，确保分配前不可预测。

### 3.3 任务设计

【必要假设】每位被试完成 **N 个任务**（N 待定，建议 3–5 个，以控制疲劳效应）。任务类型需覆盖提示词增强的典型场景，例如：

- 写作类任务（如撰写邮件、报告摘要）；
- 信息整合类任务（如根据多段材料回答问题）；
- 创意生成类任务（如头脑风暴、方案构思）。

任务顺序在被试内随机化（拉丁方设计），以控制顺序效应。

### 3.4 实验流程

```
筛选问卷 → 知情同意 → 随机分配 → 任务说明与练习（如有）→
正式任务（条件 A 或 B）→ 任务后问卷 → 结束
```

- 条件 A 的额外环节：在正式任务开始前，系统展示关键问题（问题数量与内容见 §4.3），用户作答后进入增强与生成阶段。
- 条件 B 无额外询问环节，直接进入增强与生成阶段。


## 4. 变量定义与测量指标

### 4.1 自变量

| 变量 | 类型 | 取值 |
|------|------|------|
| 提示词增强方式 | 二分类自变量 | 0 = 直接增强；1 = 先问后增强 |

### 4.2 因变量（主要结局指标）

| 指标 | 定义 | 测量方式 | 统计口径 |
|------|------|----------|----------|
| **输出质量评分** | 对模型最终输出进行多维度质量评估的得分 | 由经过培训的评分员按评分细则（rubric）盲评打分 | 每位被试每个任务的输出由 ≥2 名评分员独立评分，取均值；评分维度与量表待定 |
| **用户满意度** | 用户对输出结果和整体体验的主观满意度 | 任务后自评问卷（Likert 量表，具体量表与锚点待定） | 每位被试每个任务后填写一次，取任务间均值作为个体水平指标 |

### 4.3 因变量（次要结局指标）

| 指标 | 定义 | 测量方式 | 统计口径 |
|------|------|----------|----------|
| **总交互时间** | 从任务开始到用户确认收到最终输出的总时长 | 系统日志自动记录 | 条件 A 包含回答问题的时间；条件 B 从任务开始计时 |
| **增强阶段时间** | 从原始提示词输入完成到增强提示词生成完毕的时长 | 系统日志 | 条件 A 包含用户回答关键问题的时间 |
| **用户操作步数** | 完成任务所需的用户操作次数（点击、输入、确认等） | 系统日志 | 条件 A 包含回答问题的操作 |
| **询问环节有用性评分** | 仅条件 A：用户对关键问题是否有用的主观评价 | 任务后问卷 | 仅条件 A 被试填写 |
| **询问环节负担评分** | 仅条件 A：用户对额外询问环节负担感的主观评价 | 任务后问卷 | 仅条件 A 被试填写 |

### 4.4 关键问题集（条件 A 的干预内容）

【必要假设】关键问题集需在预实验中确定。设计原则：

- 问题数量：待定（建议 3–7 个，需在预实验中测试负担与收益的平衡）；
- 问题类型：围绕任务目标澄清、受众、格式、风格、约束条件等维度；
- 问题形式：选择题为主、开放题为辅，以控制回答时间；
- 问题内容需针对每个任务类型定制，确保与任务相关。

> 【已知事实】关键问题的具体内容、数量、措辞在本方案中不预设，需通过预实验和专家评审确定后，在正式实验方案中冻结。

### 4.5 控制变量与协变量

| 变量 | 测量方式 | 用途 |
|------|----------|------|
| AI 使用频率 | 筛选问卷自报 | 分层随机化变量 |
| 任务类型 | 实验设计变量 | 作为固定效应或分层分析 |
| 任务顺序 | 实验设计变量 | 控制顺序效应 |
| 底层模型版本 | 系统配置记录 | 确保两组使用相同模型 |
| 增强提示词生成方法 | 系统配置记录 | 确保两组除干预差异外，增强算法一致 |
| 评分员 | 评分记录 | 用于评估评分者间信度 |


## 5. 数据收集与处理流程

### 5.1 数据来源

| 数据类型 | 来源 | 格式 |
|----------|------|------|
| 筛选与人口学数据 | 筛选问卷 | 结构化表格 |
| 任务输入（原始提示词） | 系统日志 | 文本 |
| 条件 A 用户回答 | 系统日志 | 结构化 + 文本 |
| 增强后提示词 | 系统日志 | 文本 |
| 模型最终输出 | 系统日志 | 文本 |
| 交互时间与操作日志 | 系统日志（前端埋点 + 后端记录） | 时间戳事件流 |
| 用户自评问卷 | 任务后问卷 | 结构化表格 |
| 评分员质量评分 | 评分表 | 结构化表格 |

### 5.2 数据收集流程

1. 被试完成筛选问卷，合格者进入知情同意环节；
2. 随机分配后，系统自动记录被试 ID、条件、任务序列；
3. 任务执行过程中，系统自动记录所有交互事件（时间戳、操作类型、输入/输出内容）；
4. 每个任务完成后，被试立即填写任务后问卷；
5. 全部任务完成后，输出结果进入评分池，由评分员按盲法评分。

### 5.3 数据清洗与预处理

- **去标识化**：评分员仅看到模型输出和任务要求，不看到被试身份和实验条件。
- **异常值检测**：对时间类指标进行分布检查，识别明显异常值（如超短时间可能表示未认真完成任务），处理规则待定（建议在预注册中明确阈值）。
- **日志完整性检查**：剔除缺失关键事件（如无输出记录）的试次。

### 5.4 缺失数据处理

- **完全随机缺失（MCAR）检验**：使用 Little’s MCAR 检验（或等效方法）判断缺失机制。
- **处理策略**（按优先级）：
  1. 若缺失比例 < 5%（待定阈值），采用完整案例分析（complete case analysis）；
  2. 若缺失比例在 5%–20% 之间（待定阈值），采用多重插补（multiple imputation），插补模型包含主要协变量；
  3. 若缺失比例 > 20%（待定阈值），该指标的分析结果需标注为探索性，并报告缺失模式。
- **敏感性分析**：对主要结局指标，比较完整案例分析与插补分析的结果一致性。

### 5.5 偏倚控制

| 偏倚类型 | 控制措施 |
|----------|----------|
| 选择偏倚 | 随机分配 + 分配隐藏 |
| 表现偏倚 | 统一实验脚本与界面；除干预差异外，系统行为一致 |
| 检测偏倚 | 评分员盲法（不知实验条件）；问卷匿名化 |
| 报告偏倚 | 预注册所有结局指标和分析计划 |
| 顺序效应 | 任务顺序随机化（拉丁方） |
| 疲劳效应 | 控制任务数量；任务间设置休息提示 |
| 评分者偏倚 | 多评分员独立评分 + 评分者间信度报告（如 ICC 或 Krippendorff’s α） |


## 6. 统计分析方法

### 6.1 分析原则

- 所有分析在预注册后执行，分析代码与数据（去标识化后）在可行范围内公开。
- 主要分析采用意向性分析（intention-to-treat, ITT）原则。
- 显著性水平 α 待定（建议 0.05），效应量及其置信区间必须报告。

### 6.2 主要分析

**输出质量评分**：
- 采用线性混合效应模型（LMM），固定效应为实验条件（A vs. B）和任务类型，随机效应为被试（截距）和评分员（如适用）。
- 模型形式（示意）：
  ```
  质量评分 ~ 条件 + 任务类型 + (1 | 被试ID) + (1 | 评分员ID)
  ```
- 若评分数据不满足正态性假设，考虑使用累积链接混合模型（ordinal mixed model）或对评分进行适当变换。

**用户满意度**：
- 采用类似的线性混合效应模型，固定效应为条件和任务类型，随机效应为被试。

### 6.3 次要分析

- **总交互时间**：对数变换后（如右偏）使用 LMM，或使用 Gamma 分布的广义线性混合模型（GLMM）。
- **操作步数**：使用泊松或负二项 GLMM。
- **询问环节有用性/负担评分**（仅条件 A）：描述性统计 + 单样本检验（与量表理论中值比较）。

### 6.4 亚组与探索性分析

- 按任务类型分层分析条件效应；
- 按 AI 使用频率分层分析条件效应；
- 探索关键问题回答内容与输出质量的关系（仅条件 A，描述性）。

### 6.5 多重比较校正

- 主要结局指标为输出质量评分和用户满意度（2 个），如需控制族错误率，采用 Bonferroni 或 Holm 校正（待定）。
- 次要结局指标的分析结果标注为探索性，不做严格的多重比较校正，但需报告所有检验的原始 p 值和效应量。


## 7. 公平性保障措施

### 7.1 两组条件的对等性

| 维度 | 保障措施 |
|------|----------|
| 底层模型 | 两组使用完全相同的底层大语言模型（版本号记录并冻结） |
| 增强算法 | 除“是否包含用户回答”外，增强提示词的生成逻辑、模板、模型参数完全一致 |
| 任务内容 | 两组使用完全相同的任务集 |
| 界面与交互 | 除条件 A 多出询问环节外，界面布局、视觉风格、操作方式一致 |
| 时间限制 | 两组均不设硬性时间限制（或设相同限制，待定） |
| 评分标准 | 评分员使用相同的评分细则，且对条件盲法 |

### 7.2 增强提示词生成的一致性

【必要假设】“直接增强”条件中，增强模块仅基于原始提示词生成增强提示词；“先问后增强”条件中，增强模块基于“原始提示词 + 用户回答”生成增强提示词。两者的增强算法核心逻辑相同，仅输入信息不同。该实现方式需在技术方案中明确记录。

### 7.3 时间计量的公平性

- 条件 A 的总交互时间包含回答问题的时间，条件 B 无此环节。这是干预本身的固有差异，不进行人为“补偿”。
- 同时报告“增强阶段时间”和“总交互时间”两个指标，以区分时间差异的来源。


## 8. 局限性与不确定性说明

### 8.1 方法学局限

- **外部效度**：实验任务为预设的标准化任务，与真实使用场景可能存在差异；结果推广到其他任务类型或用户群体时需谨慎。
- **干预强度**：关键问题的数量、质量和内容直接影响“先问后增强”的效果。本方案中关键问题集为待定参数，不同问题集可能产生不同结果。
- **底层模型依赖性**：结果可能依赖于所使用的底层大语言模型版本。模型更新后，结论的可迁移性需重新验证。
- **评分主观性**：输出质量评分依赖人工评分，尽管采用盲法和多评分员设计，仍存在主观判断差异。
- **短期效应**：本研究仅测量单次交互的效果，不涉及长期使用中的学习效应或用户习惯形成。

### 8.2 不确定性来源

- 效应量未知（需预实验估计），样本量计算存在不确定性；
- 关键问题集的设计质量直接影响干预效果，预实验中需迭代优化；
- 用户对额外询问环节的耐受度可能因任务类型和场景而异；
- 增强提示词生成模块的实现细节（如 prompt 模板）可能影响结果，需在技术文档中完整记录。

### 8.3 方法适用条件

本方案适用于以下条件：
- 任务为开放式生成任务（而非有唯一正确答案的任务）；
- 用户愿意在任务开始前投入少量时间回答问题；
- 增强提示词模块能够有效利用用户回答信息；
- 底层模型对提示词变化敏感（即增强确实能改变输出质量）。

不适用于：
- 用户追求极低交互成本、不愿回答任何额外问题的场景；
- 任务高度标准化、无需澄清即可明确意图的场景；
- 底层模型对提示词变化不敏感的场景。
