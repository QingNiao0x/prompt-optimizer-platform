# 研究设计方案：先回答关键问题再增强提示词 vs. 直接增强提示词

**文档版本**：v1.0（待确认参数版）  
**状态**：设计草案，含待确认项


## 0. 事实、确认与假设的区分说明

本方案严格区分以下三类信息：

| 类别 | 标记方式 | 本方案中的实例 |
|---|---|---|
| **已确定的事实** | 无标记，直接陈述 | 随机化可减少选择偏倚；组间比较需用交互效应检验而非分别检验显著性 |

## 1. 研究问题与假设

### 1.1 研究问题

在用户使用大语言模型完成特定任务时，“先让用户回答几个关键问题再增强提示词”（以下简称**问答增强组**）是否比“直接增强提示词”（以下简称**直接增强组**）产生更有用的结果？

### 1.2 必要假设

- `[假设 H1]` 用户具备完成目标任务的基本能力，能够理解并回答关键问题。
- `[假设 H2]` 存在可操作的“提示词增强”方法，且该方法在两组中可被标准化执行。
- `[假设 H3]` 用户有真实的任务需求，而非仅为参与研究而虚构任务。
- `[假设 H4]` 评价者能够对输出结果进行可靠评分（评分者间信度可接受）。


## 2. 研究对象

`[待确认]` 目标用户群体。候选方案（供用户选择，非默认值）：

- **候选A**：具有特定领域任务需求的知识工作者（如产品经理、研究员、内容创作者）
- **候选B**：高校学生（便于招募，任务类型可标准化）
- **候选C**：某企业内部的特定岗位员工（任务真实，但外部效度受限）

`[待确认]` 具体任务类型。候选方案（供用户选择，非默认值）：

- **候选A**：写作任务（如撰写报告、文章、方案）
- **候选B**：问答/信息整合任务（如研究一个问题并给出综合回答）
- **候选C**：编程任务（如实现一个功能模块）
- **候选D**：混合任务（需说明混合方式及理由）

### 2.3 样本来源与招募方式

`[待确认]` 样本来源。候选方案：

- **候选A**：线上众包平台（如Prolific、见数、Credamo），需说明筛选条件
- **候选B**：高校课程/实验室被试库
- **候选C**：企业内部招募

**招募时的筛选条件**（待用户群体确认后细化）：

- 具备目标任务领域的基础能力
- 有真实的任务需求（`[假设 H3]` 的检验方式：招募时要求参与者自带一个真实任务）
- 未参与过类似研究


## 3. 干预措施

### 3.1 共同基础：提示词增强方法

两组均使用**同一种提示词增强方法**作为底层技术。`[待确认]` 具体增强方法，候选方案：

- **候选A**：基于结构化框架的提示词扩展（如补充背景、目标、约束、输出格式）
- **候选B**：基于LLM的自动提示词优化（如使用另一个模型对原始提示词进行改写和丰富）
- **候选C**：人工专家增强（由研究者或专家手动完善提示词）

> 选择何种增强方法需在研究方案定稿前确认。无论选择哪种，两组使用的增强方法必须相同，仅“是否先让用户回答关键问题”这一环节不同。

### 3.2 问答增强组（干预组）流程

**步骤1：用户提交原始任务描述**

- 用户用自己的语言描述想要完成的任务（即“原始提示词”）。

**步骤2：生成关键问题**

- 基于用户的原始任务描述，生成3–5个关键问题。
- `[待确认]` 关键问题的生成方式：
  - **候选A**：由研究者/领域专家人工拟定（质量可控，但成本高、可扩展性差）
  - **候选B**：由LLM基于原始任务描述自动生成（可扩展，但需验证问题质量）
  - **候选C**：混合方式（LLM生成 + 人工审核）
- 关键问题的设计原则：旨在澄清任务中**影响输出质量的关键歧义或缺失信息**，如目标受众、使用场景、约束条件、期望深度、格式要求等。

**步骤3：用户回答关键问题**

- 用户对每个关键问题进行自由文本回答（不限制字数）。
- 用户可以选择“跳过”某个问题（记录跳过行为，用于后续分析）。

**步骤4：基于回答增强提示词**

- 将用户的原始任务描述 + 用户对关键问题的回答，合并输入到增强流程中，生成增强后的提示词。
- 增强后的提示词包含：原始任务描述中的信息 + 用户回答中提供的新信息 + 增强方法所添加的结构性元素。

**步骤5：用户使用增强提示词完成任务**

- 用户将增强后的提示词输入目标LLM，获得输出结果。

### 3.3 直接增强组（对照组）流程

**步骤1：用户提交原始任务描述**

- 与干预组相同。

**步骤2：直接增强提示词**

- 仅基于用户的原始任务描述，直接输入到增强流程中，生成增强后的提示词。
- 增强后的提示词包含：原始任务描述中的信息 + 增强方法所添加的结构性元素。
- **不包含**任何来自用户回答的额外信息。

**步骤3：用户使用增强提示词完成任务**

- 与干预组相同。

### 3.4 同等信息对照（关键公平性设计）

为控制“信息量差异”这一混淆因素，方案设计如下：

- **确认信息对照**：在直接增强组完成增强提示词后、使用提示词之前，向该组用户展示一份**确认信息**。该确认信息的内容与问答增强组中用户回答所提供的信息**在内容维度上相同**（即同样涵盖目标受众、使用场景、约束条件等维度），但以**陈述句形式**呈现，而非以问题形式引导用户回答。
- **确认信息的来源**：`[待确认]` 候选方案：
  - **候选A**：由研究者根据该任务类型的一般性常识拟定（适用于所有直接增强组用户，内容相同）
  - **候选B**：从问答增强组匹配用户的实际回答中提取（需配对设计，操作复杂）
  - **候选C**：由LLM基于原始任务描述生成“合理默认值”作为确认信息
- **关键原则**：确认信息向两组提供**内容相同的确认信息**，不以相同字数或限制其中一组可用信息替代。即：问答增强组通过回答问题获得了信息X，直接增强组也通过确认信息获得了信息X。两组的信息内容相同，区别仅在于**获取方式**（主动回答 vs. 被动接收）和**信息进入提示词的路径**（问答增强组的信息进入提示词，直接增强组的确认信息不进入提示词）。

> **设计说明**：此设计将“信息获取方式”与“信息是否进入提示词”绑定在一起，这是干预的本质特征。确认信息对照的目的是排除“问答组仅仅因为多看到了一些信息而表现更好”这一替代解释。如果直接增强组在收到相同信息后仍表现较差，则差异可归因于“主动回答 + 信息整合进提示词”这一干预机制。

### 3.5 干预流程图示

```
问答增强组：原始提示词 → 生成关键问题 → 用户回答 → 合并增强 → 使用增强提示词 → 获得输出
直接增强组：原始提示词 → 直接增强 → 展示确认信息（不进入提示词）→ 使用增强提示词 → 获得输出
```


## 4. 结果评价

### 4.1 “更有用”的操作化定义

`[待确认]` 主要评价指标。候选方案（供用户选择，非默认值）：

| 指标类别 | 具体指标 | 测量方式 | 适用条件 |
|---|---|---|---|
| **输出质量**（主要候选） | 专家评分：相关性、完整性、准确性、可操作性 | 盲法专家评分（1–7分Likert量表） | 适用于有明确质量标准的任务 |
| **用户满意度**（主要候选） | 用户自评：对输出结果的满意度、对过程的满意度 | 用户填写标准化问卷（1–7分） | 适用于主观体验重要的场景 |
| **任务完成度**（主要候选） | 输出是否满足用户原始任务需求的程度 | 用户自评 + 专家评分双重评价 | 适用于有明确任务目标的场景 |
| **效率指标**（次要候选） | 从提交原始提示词到获得满意输出所需的总时间 | 系统自动记录 | 需考虑时间成本是否纳入“有用”的定义 |
| **下游作品质量**（补充指标） | 用户基于LLM输出完成的最终作品质量 | 盲法专家评分 | 仅作为补充，不替代对提示词增强效果的直接评价 |

> **约束说明**：评价对象为“增强提示词所产生的输出结果的有用性”，而非仅评价提示词本身的质量，也非仅评价下游作品。下游作品可作为补充指标，但不替代主要评价。

### 4.2 评分量表（以“输出质量”为例，待确认后细化）

**专家评分量表（1–7分）**：

| 维度 | 1分（极差） | 4分（一般） | 7分（极好） |
|---|---|---|---|
| 相关性 | 输出与任务需求几乎无关 | 输出部分相关，有明显偏离 | 输出高度相关，精准回应任务 |
| 完整性 | 遗漏大量关键信息 | 覆盖主要信息，有少量遗漏 | 全面覆盖所有关键信息 |
| 准确性 | 存在严重事实错误 | 有少量不准确之处 | 信息准确可靠 |
| 可操作性 | 无法直接使用 | 需较多修改后方可使用 | 可直接使用或仅需微调 |

**用户满意度量表（1–7分）**：

- “我对最终输出结果的满意程度”（1=非常不满意，7=非常满意）
- “我认为增强后的提示词帮助我更好地完成了任务”（1=完全不同意，7=完全同意）
- “我愿意在未来使用这种方式来增强我的提示词”（1=完全不愿意，7=非常愿意）

### 4.3 评价者与盲法

- **专家评价者**：`[待确认]` 人数（建议≥3人）及资质要求（如领域经验年限）。
- **盲法设计**：评价者不知道每个输出来自哪个组（单盲）。用户无法被盲（他们知道自己是否回答了问题），但用户自评部分需在数据分析时注意期望偏倚。
- **评分者间信度**：计算ICC（组内相关系数）或Krippendorff's α，若信度不足（如ICC < 0.6），需讨论原因并考虑增加评价者或修订评分标准。


## 5. 公平比较设计

### 5.1 随机分组

- 参与者按1:1比例随机分配至问答增强组或直接增强组。
- 随机化方法：分层区组随机化。`[待确认]` 分层变量（候选：任务类型、用户经验水平）。
- 随机序列生成：使用计算机生成的随机数，分配方案隐藏（如使用密封信封或中央随机化系统）。

### 5.2 盲法

- **参与者**：无法对干预方式设盲（用户知道自己是否回答了问题）。在招募时使用中性描述（如“研究提示词增强的不同方式”），不透露具体研究假设。
- **评价者**：对分组状态设盲（单盲）。
- **数据分析者**：在主要分析完成前对分组编码设盲。

### 5.3 控制信息量差异

- 如第3.4节所述，直接增强组收到与问答增强组内容相同的确认信息，确保两组接触到的信息内容相同。
- 记录两组实际接收和使用的信息量，作为协变量纳入敏感性分析。

### 5.4 控制其他混淆因素

- **任务难度**：`[待确认]` 控制方式（候选：参与者自带任务并在两组间匹配难度；或使用标准化任务集）。
- **用户经验**：在基线问卷中测量用户的提示词编写经验和领域经验，作为协变量。
- **LLM版本与参数**：两组使用相同的LLM（版本、温度、最大token数等参数完全一致）。
- **时间投入**：记录两组用户的总用时，在分析中作为协变量或进行亚组分析。


## 6. 统计分析

### 6.1 样本量估算

`[待确认]` 在主要评价指标和预期效应量确认前，样本量估算**暂停**。

**估算方法**（待参数确认后执行）：

- 基于两组独立样本t检验（或Mann-Whitney U检验，视数据分布而定）
- 参数设定：显著性水平α = 0.05（双侧），统计功效1-β = 0.80
- 预期效应量（Cohen's d）：`[待确认]`（需基于预实验或领域经验设定，不得编造）
- 预期脱落率：`[待确认]`（建议基于招募渠道的历史数据设定）

**计算公式**（待参数确认后代入）：

每组所需样本量 n = 2 × [(z_{1-α/2} + z_{1-β}) / d]²

### 6.2 主要分析

**主要比较**：问答增强组 vs. 直接增强组在主要评价指标上的差异。

- 若数据满足正态性和方差齐性假设：使用**独立样本t检验**。
- 若不满足：使用**Mann-Whitney U检验**或**Welch's t检验**。
- 效应量报告：Cohen's d（或秩双列相关）及其95%置信区间。

**关键统计原则**：方法收益由**对应组间比较**判断。即直接比较两组的结局指标差异。**不得**使用“问答增强组内前后比较显著、直接增强组内前后比较不显著”来推断两组效果不同。如需判断两组差异，必须使用交互效应检验或直接组间比较。

### 6.3 次要分析

- **协变量调整分析**：ANCOVA或多元回归，纳入基线特征（如用户经验、任务难度评分）作为协变量。
- **亚组分析**（探索性）：按任务类型、用户经验水平分层分析。
- **过程指标分析**：比较两组的总用时、跳过率（问答增强组）、用户对过程的满意度。

### 6.4 敏感性分析

- 排除未完成全部流程的参与者后的完整案例分析。
- 使用多重插补后的意向性分析。
- 排除极端值（如输出质量评分在均值±3SD之外）后的分析。

### 6.5 统计软件

- 使用R（版本≥4.0）进行统计分析。
- 分析代码与数据（脱敏后）在研究报告中公开。


## 7. 缺失数据与偏倚控制

### 7.1 缺失数据处理

| 缺失类型 | 处理策略 |
|---|---|
| 参与者中途退出 | 记录退出原因；主要分析采用意向性分析（ITT）；缺失结局数据使用多重插补（MICE），插补模型包含分组、基线特征和可用过程数据 |
| 用户跳过关键问题 | 记录跳过数量；在分析中作为协变量；进行“跳过≥2题”的亚组分析 |
| 评分者未完成评分 | 若某输出的评分者数<2，该输出在主要分析中标记为缺失；使用多重插补或排除（敏感性分析） |
| 问卷条目缺失 | 若量表缺失条目<20%，使用该量表其他条目的均值插补；否则标记为缺失 |

### 7.2 偏倚控制

| 偏倚类型 | 控制措施 |
|---|---|
| 选择偏倚 | 随机分组 + 分配隐藏；报告招募流程和拒绝参与率 |
| 评价者偏倚 | 盲法评分；多位评价者；评分标准预先注册 |
| 期望偏倚（参与者） | 招募时使用中性描述；不告知具体研究假设；用户自评作为次要指标 |
| 研究者偏倚 | 分析计划预先注册；分析代码公开；数据分析者设盲 |
| 报告偏倚 | 预先注册所有结局指标；报告所有预设分析的结果 |
| 沾染偏倚 | 两组参与者独立完成，不交流；线上实验时通过技术手段隔离 |


## 8. 可复现性

### 8.1 数据收集流程（标准化操作步骤）

**阶段0：预注册**

- 在研究开始前，将研究方案、假设、主要结局指标、分析计划提交至开放科学框架（OSF）或ClinicalTrials.gov（如适用）。

**阶段1：招募与筛选**

1. 发布招募信息（含中性研究描述）。
2. 参与者填写筛选问卷（含基线特征、任务类型、经验水平）。
3. 研究者确认参与者符合纳入标准。
4. 参与者签署知情同意书。

**阶段2：随机分组**

1. 使用预先生成的随机序列将参与者分配至两组。
2. 记录分组时间和执行者。

**阶段3：实验执行**

1. 参与者登录实验平台。
2. 填写基线问卷。
3. 提交原始任务描述。
4. 按分组执行对应流程（见第3节）。
5. 使用增强提示词调用LLM，获得输出。
6. 填写用户满意度问卷。
7. 记录总用时。

**阶段4：专家评分**

1. 收集所有输出结果，去除分组标识。
2. 随机排序后分配给评价者。
3. 评价者按评分标准独立评分。
4. 收集评分数据，计算评分者间信度。

**阶段5：数据清理与分析**

1. 按预注册的分析计划执行分析。
2. 生成分析报告。

## 9. 方法适用条件与局限性

### 9.1 适用条件

- 本方案适用于用户有**真实任务需求**且愿意投入时间参与研究的场景。
- 本方案假设提示词增强方法本身是有效的（即增强后的提示词优于原始提示词）。如果增强方法本身无效，则本研究的比较意义有限。
- 本方案的结果解释受限于所选择的任务类型和用户群体，外推至其他场景需谨慎。

### 9.2 已知局限性

- **无法对参与者设盲**：用户知道自己是否回答了问题，可能产生期望偏倚。
- **确认信息对照的局限性**：直接增强组收到的确认信息是“被动接收”的，与问答增强组“主动回答”的认知加工深度不同，这一差异是干预的固有特征，无法完全消除。
- **关键问题生成方式的影响**：如果关键问题由LLM生成，其质量可能影响干预效果；如果由人工生成，则限制了可扩展性。
- **时间投入差异**：问答增强组需要额外时间回答问题，如果“有用性”未考虑时间成本，可能高估干预效果。
