# 研究设计方案（建议稿）

> 说明：以下为**候选研究设计建议**，不是已确认或已实施的方案。文中凡涉及样本量、效应量、具体量表阈值、平台参数等，均标注为“待定”或“建议”，不得视为既成事实。未提供可核实来源的数据、文献和结果一律不编造。

---

## 1. 研究问题与操作化定义

### 1.1 核心研究问题

**RQ**：在提示词增强任务中，让用户先回答几个关键问题再增强提示词，是否比直接增强更有用？

可拆为两个层次：

- **RQ1（方法收益）**：在**同等信息**条件下，先问答再增强与直接增强相比，是否提升提示词质量与任务完成效果？
- **RQ2（自然使用效果）**：在**自然使用**条件下，允许问答流程按需获取额外信息时，其整体效果如何？
- **RQ3（机制/调节）**：问答流程的效果是否受任务类型、用户背景、提示词初始长度、问题数量等调节？

### 1.2 两种条件的操作化定义

#### 条件 A：先回答关键问题再增强（Q-A-Enhance）

流程建议如下：

1. 用户提交初始提示词 \(P_0\) 与任务说明。
2. **由系统/研究者指定的一组关键问题**（不是模型自行生成计划）向用户提问。问题数量建议固定为 \(k\)（如 3–5 个，待定），内容围绕：目标、受众、输出格式、约束、评价标准、示例等。
3. **由用户回答**这些问题，形成用户确认信息 \(U\)。
4. 将 \(P_0\)、任务说明与 \(U\) 一并交给增强方法，生成增强提示词 \(P_A\)。
5. 用 \(P_A\) 执行任务，得到输出 \(O_A\)。

关键点：**谁提问 = 系统/研究者预设问题集；谁回答 = 用户；答案如何使用 = 作为增强输入的一部分，不得由模型自行编造或替代用户回答。**

#### 条件 B：直接增强（Direct-Enhance）

流程建议如下：

1. 用户提交同一初始提示词 \(P_0\) 与任务说明。
2. 不进行用户问答。
3. 将 \(P_0\) 与任务说明交给增强方法，生成增强提示词 \(P_B\)。
4. 用 \(P_B\) 执行任务，得到输出 \(O_B\)。

### 1.3 “同等信息对照”的操作化定义

公平比较的核心不是“字数相同”，而是**两组在增强阶段可获得的确认信息内容相同**。

建议设置：

- **同等信息对照（信息对齐条件）**：将条件 A 中用户回答 \(U\) 的内容，以**相同内容**提供给条件 B 的增强方法。即条件 B 也获得 \(U\)，但不经过“用户先回答”的交互流程。
- 这样，A 与 B 的差异主要在于**是否经历问答流程**，而不是信息量差异。
- 若研究关注“问答流程本身是否有用”，则 A 与 B 的信息内容应一致；若研究关注“问答带来的额外信息是否有用”，则应另设信息量差异条件，并将其作为被研究的因素，而不是混淆。

> 注意：不能用“限制其中一组可用信息”或“仅让字数相同”来替代同等信息对照。

## 2. 候选研究设计（建议）

以下均为**建议**，需根据实际资源与伦理审查结果选择。

### 2.1 设计一：组间对照设计（建议）

- **自变量**：增强条件（A：先问答再增强；B：直接增强但信息对齐）。
- **因变量**：提示词质量、任务完成效果、用户主观评价、流程成本。
- **适用条件**：任务可标准化、用户可随机分配、样本量足够。
- **优点**：无顺序效应、污染较小。
- **缺点**：个体差异需靠随机化平衡。

### 2.2 设计二：组内对照设计（建议）

- **自变量**：同一用户在不同任务上分别经历 A 与 B。
- **因变量**：同上。
- **适用条件**：任务可配对、学习效应可控、用户愿意完成多轮。
- **优点**：控制个体差异。
- **缺点**：顺序效应、疲劳效应、需求特征明显。
- **控制建议**：拉丁方平衡顺序；任务间设置填充任务；分析时纳入顺序与轮次。

### 2.3 设计三：混合设计（建议）

- **组间因素**：用户背景（如提示词经验高/低）。
- **组内因素**：增强条件（A/B）。
- **适用条件**：既想看方法收益，又想看调节效应。
- **优点**：可估计交互。
- **缺点**：样本量与实施复杂度更高。

### 2.4 设计四：多臂设计（建议，用于区分信息量）

- A：先问答再增强（用户回答，信息进入增强）。
- B：直接增强 + 同等信息（信息对齐）。
- C：直接增强 + 无额外信息（自然直接增强）。
- D（可选）：模型自行生成问题并自答（仅作为对照，不替代用户问答流程）。

> 若研究问题聚焦“问答是否有用”，A vs B 是主比较；A vs C 可估计自然使用效果；B vs C 可估计额外信息本身的作用。

## 3. 公平比较方案

### 3.1 信息对齐

- A 与 B 在增强阶段获得**内容相同**的确认信息 \(U\)。
- 不以“字数相同”作为公平标准。
- 不限制任何一组可用信息。
- 若无法做到完全信息对齐，需明确记录差异，并将其作为协变量或单独因素分析。

### 3.2 需控制的混淆变量

建议控制或记录：

- 任务类型（写作、代码、数据分析、规划等）
- 任务难度
- 初始提示词长度与质量
- 用户背景（经验、领域知识）
- 增强方法版本
- 模型版本与解码参数
- 问题数量与问题内容
- 时间与疲劳
- 顺序效应（组内设计）
- 评分者严格度

### 3.3 随机化与匹配策略

- 组间设计：用户随机分配到 A 或 B；任务可分层随机。
- 组内设计：任务与条件顺序用拉丁方或随机平衡。
- 匹配：若无法随机，可按初始提示词质量、任务类型、用户经验进行匹配。
- 盲评：评分者不知道条件归属；若无法完全盲评，至少做到条件标签去标识化。

## 4. 问答流程说明（保留谁提问、谁回答、答案如何使用）

- **谁提问**：系统或研究者预设的关键问题集。问题集需事先固定并记录版本。
- **谁回答**：用户。不得由模型代替用户回答。
- **答案如何使用**：用户回答 \(U\) 作为增强方法的输入之一，与 \(P_0\) 和任务说明共同生成增强提示词。
- **不得改为模型自行生成计划**：问答流程不能替换为模型自问自答或模型自行生成增强计划。
- **问题数量与内容**：建议固定 \(k\) 个问题；若研究问题数量效应，可设不同 \(k\) 作为因素。
- **记录**：保存问题集、用户回答、增强提示词、最终输出，保证可复现。

## 5. 评价指标与评估步骤

### 5.1 提示词质量（主要评价对象之一）

建议维度：

- **目标明确性**：是否清楚说明任务目标。
- **约束完整性**：是否包含必要约束、格式、受众等。
- **可执行性**：是否可直接用于生成输出。
- **信息充分性**：是否包含足够上下文。
- **无歧义性**：是否存在明显歧义。
- **结构清晰性**：组织是否合理。

评分办法（建议）：

- 采用 1–5 或 1–7 Likert 量表，由至少两名评分者独立评分。
- 评分者培训与校准：先试评，计算一致性；若一致性低，讨论后修订评分手册。
- 报告评分者间一致性（如 ICC 或 Krippendorff’s α）。
- 可辅以自动指标，但自动指标不能替代人工评分作为唯一依据。

### 5.2 任务完成效果

建议维度：

- **正确性**：是否满足任务要求。
- **完整性**：是否覆盖必要内容。
- **有用性**：对目标用户是否有实际帮助。
- **格式符合度**：是否符合指定格式。
- **效率**：完成任务所需时间或轮次（若适用）。

评分办法（建议）：

- 人工评分 + 任务特定检查表。
- 若任务有客观答案，可用准确率、F1 等。
- 若任务开放，采用多评分者 Likert 评分。
- 评分者盲于条件。

### 5.3 其他指标

- 用户主观满意度、信任度、认知负荷。
- 流程成本：时间、问题数量、用户操作步骤。
- 增强提示词长度、可读性等描述性指标。

### 5.4 评估步骤（建议）

1. 预注册或事先固定分析计划。
2. 收集数据并去标识化。
3. 评分者独立评分。
4. 计算一致性。
5. 进行统计比较。
6. 报告效应量与置信区间。
7. 进行敏感性分析与缺失数据处理。

## 6. 数据分析方法

### 6.1 方法收益判断规则

- **主比较**：A vs B（同等信息下，是否经历问答流程）。
- 判断标准：看 A 与 B 的**组间差异**及其效应量、置信区间。
- **不得**用“A 显著、B 不显著”直接证明两组效果不同。正确做法是直接比较两组差异，或检验交互。
- 若使用显著性检验，应报告效应量（如 Cohen’s d、η²、OR 等）与 95% 置信区间。
- 若使用贝叶斯方法，报告后验分布与贝叶斯因子，并说明先验。

### 6.2 统计方法（建议）

- 连续变量：线性混合模型（组内设计含随机截距）。
- 有序变量：累积链接混合模型。
- 二分类：逻辑回归或混合逻辑回归。
- 多评分者：多层模型或先聚合再分析。
- 调节效应：加入交互项。
- 多重比较：预注册主要比较；探索性分析需校正并标注。

### 6.3 效应量报告

- 组间均值差、标准化均值差。
- 比值比、风险比（若适用）。
- 置信区间。
- 若样本小，报告不确定性，避免过度解释。

### 6.4 缺失数据

- 记录缺失原因。
- 若缺失随机，可用多重插补或最大似然。
- 若缺失非随机，需敏感性分析并说明局限。
- 不默认删除缺失样本而不报告。

---

## 7. 自然使用效果与同等信息下方法收益的区分

- **自然使用效果**：A vs C（C 为直接增强、无额外信息），反映真实使用中问答流程带来的整体差异，其中包含信息量差异。
- **同等信息下方法收益**：A vs B，信息内容对齐，反映问答流程本身的作用。
- **信息量差异**：若研究关注问答是否有用，需明确信息量差异是控制变量还是被研究因素。
  - 若作为控制变量：A 与 B 信息对齐。
  - 若作为被研究因素：设多臂设计，分别估计信息量与流程的作用。
- 不得把自然使用效果直接等同于方法收益。

## 8. 伦理与局限性说明

### 8.1 伦理

- 知情同意：说明研究目的、流程、数据用途、退出权利。
- 隐私：用户回答可能含敏感信息，需去标识化与安全存储。
- 风险：避免让用户回答高风险或隐私问题。
- 补偿：合理补偿，不因退出而惩罚。
- 审查：建议提交伦理审查（若机构要求）。

### 8.2 局限性

- 样本代表性有限，结论外推需谨慎。
- 任务类型有限，可能不覆盖所有场景。
- 评分主观性，需多评分者与一致性报告。
- 问答流程可能引入需求特征与社会赞许偏差。
- 增强方法版本与模型版本变化会影响可复现性。
- 同等信息对照在实施上可能难以完全对齐，需记录差异。
- 效应量可能受任务难度、用户经验调节。
- 若样本量不足，统计功效低，需报告不确定性。

## 9. 已定与未决参数

### 已定（本方案建议中明确固定的部分）

- 研究问题：先问答再增强 vs 直接增强。
- 两种条件的操作流程。
- 同等信息对照的定义：内容相同，不以字数相同替代。
- 问答流程：系统/研究者提问，用户回答，答案用于增强。
- 方法收益由 A vs B 组间比较判断。
- 不得用一组显著另一组不显著直接证明组间差异。

### 未决（需用户或后续确认）

- 具体任务类型与数量。
- 问题数量 \(k\) 与问题内容。
- 样本量、样本来源、用户背景分布。
- 增强方法具体实现与模型版本。
- 评分量表与阈值。
- 统计模型与主要比较。
- 是否预注册、是否多臂、是否设信息量因素。
- 伦理审查要求与数据存储方案。

## 10. 可复现性清单（建议）

- 固定问题集版本。
- 保存初始提示词、用户回答、增强提示词、最终输出。
- 记录模型版本、解码参数、时间戳。
- 评分手册与评分者培训材料。
- 分析代码与数据字典。
- 预注册或分析计划。
- 缺失数据处理与敏感性分析记录。

## 11. 结论性说明

本方案为**建议性研究设计**，未冒充已确认或已实施。核心建议是：

1. 用 A vs B 在**同等信息**下比较问答流程的方法收益。
2. 用 A vs C 估计自然使用效果。
3. 保留“系统/研究者提问、用户回答、答案用于增强”的流程。
4. 评价对象包括提示词质量与任务完成效果，不只评答案质量。
5. 方法收益由对应组间比较判断，不误用显著性差异。
6. 所有未定参数需后续确认，不编造数据、文献或结果。
