# 研究设计：先回答关键问题再增强提示词 vs. 直接增强提示词

> 状态说明：本文件为**拟议研究设计**，不表示研究已实施、已获数据或已有结果。文中“已定”指本设计建议固定并可据此执行；“未决”指需在预注册或启动前由研究团队确认，本文不默认取值。

## 1. 研究问题与操作化定义

### 1.1 主研究问题
在给定同一原始任务和同一份实际确认信息的前提下，**先由增强器提出关键问题、用户回答后，将有效回答融入提示词增强**，是否比**直接增强、不主动追问**产生更高质量的增强后提示词？

### 1.2 次要研究问题
1. 两组增强后提示词在哪些质量维度上差异最大？
2. 问答轮次中“有效回答”的比例、类型与提示词质量之间是否存在描述性关联？
3. 在何种任务类型、用户信息完整度或增强器能力条件下，问答式增强更可能优于直接增强？

### 1.3 操作化定义
- **原始任务**：用户最初提交的任务描述，未经增强器改写。
- **实际确认信息**：研究材料中预先提供给两组、可被两组使用的同一份需求与确认信息。它可来自用户先前确认、任务背景说明或研究设定的确认清单。
- **增强器**：执行提示词增强流程的系统或人员。两组使用同一增强器配置、同一基础模型版本、同一系统指令框架，仅增强流程不同。
- **问答式增强组**：增强器先提出关键问题；由用户回答；增强器识别有效回答；将有效回答融入增强后提示词。问答不得替换为模型自行生成执行计划。
- **直接增强组**：增强器不主动发起关键问题轮次；直接基于原始任务和同一份实际确认信息进行增强。该组仍可正常使用已提供的需求与确认信息。
- **增强后提示词质量**：对增强后提示词本身的结构、完整性、约束明确性、可执行性、与原始任务一致性等进行评价。下游作品质量可作为补充指标，但不替代提示词质量评价。
- **有效回答**：用户回答中可被合法用于增强提示词、且不违背原始任务或确认信息的内容。无效回答包括离题、重复、与确认信息冲突且未说明、无法核实的事实断言等。

### 1.4 已知事实、用户确认信息与必要假设
- **已知事实**：本研究设计所规定的流程、分组、评价对象和比较逻辑。
- **用户确认信息**：研究中提供给两组的同一份实际确认信息；问答组中用户对关键问题的回答。
- **必要假设**：若开展实际研究，需假设增强器能稳定区分有效回答与无效回答；需假设评分者能按统一量表评价提示词质量。这些假设需在预注册中明确并检验一致性。

## 2. 实验条件与分组说明

### 2.1 设计类型
建议采用**两组同信息对照设计**，可配合任务内配对或分层随机分配。

### 2.2 实验条件
| 条件 | 名称 | 增强器是否主动提问 | 用户是否回答 | 可用信息 | 增强流程 |
|---|---|---|---|---|---|
| A | 问答式增强组 | 是 | 是 | 原始任务 + 同一份实际确认信息 + 用户对关键问题的回答 | 提问 → 用户回答 → 识别有效回答 → 融入提示词 |
| B | 直接增强组 | 否 | 不因本研究流程回答 | 原始任务 + 同一份实际确认信息 | 直接增强，不主动追问 |

### 2.3 关键公平条件
1. **同一原始任务**：两组接收完全相同的原始任务文本。
2. **同一份实际确认信息**：两组接收完全相同的确认信息，且均可使用。
3. **同一增强器基础配置**：模型版本、解码参数、系统指令、可用工具、时间限制一致。
4. **不额外增加修订轮次**：除问答组规定的提问-回答-融入流程外，两组均不增加额外修订轮次。
5. **不改写回答**：问答组用户的回答按原始记录保留；增强器只能识别和融入有效回答，不得替用户改写回答。
6. **不替换为模型执行计划**：问答组的关键问题必须由增强器向用户提出，回答必须来自用户；不得改为模型自行生成执行计划再作答。
7. **评价对象一致**：两组均评价增强后提示词质量；下游作品仅作补充。

### 2.4 分配与对照方式
- **分配单位**：若任务彼此独立，可按任务随机分配至 A 或 B；若同一任务可形成配对，建议同一任务分别进入 A 和 B，形成任务内配对。
- **随机化**：若采用随机分配，需记录随机种子、分配顺序和隐藏方式。
- **对照方式**：A 与 B 直接比较。不得用“A 显著、B 不显著”直接推断两组效果不同；方法收益由 A 与 B 的组间比较判断。

## 3. 公平比较的操作步骤

### 3.1 准备阶段
1. 确定任务池、原始任务文本、同一份实际确认信息。
2. 预注册已定参数与未决参数。
3. 固定增强器配置、评分量表、评分者培训材料。
4. 为每个任务生成唯一 ID，并记录任务类型、领域、复杂度等分层变量。

### 3.2 问答式增强组操作步骤
1. 增强器接收原始任务和同一份实际确认信息。
2. 增强器提出关键问题。问题应针对增强提示词所需但尚未明确的信息。
3. 用户回答。回答记录需保留原始文本、时间戳、用户 ID 或匿名编号。
4. 增强器识别有效回答。识别规则需预先定义，并记录每条回答被判定为有效/无效及理由。
5. 增强器将有效回答融入增强后提示词。
6. 保存：原始任务、确认信息、关键问题、用户回答、有效性判定、增强后提示词、增强器日志。

### 3.3 直接增强组操作步骤
1. 增强器接收同一原始任务和同一份实际确认信息。
2. 增强器不主动发起关键问题轮次。
3. 增强器直接生成增强后提示词。
4. 保存：原始任务、确认信息、增强后提示词、增强器日志。
5. 若增强器内部产生隐含假设或计划，不得将其等同于用户问答；不得将模型自行生成执行计划作为用户回答纳入分析。

### 3.4 信息一致性检查
- 两组任务文本哈希一致。
- 两组确认信息文本哈希一致。
- 两组增强器配置版本一致。
- 两组可用时间、工具、上下文长度一致。
- 问答组额外获得的用户回答，应作为该组流程的组成部分记录；直接组不因未提问而失去使用确认信息的权利。

### 3.5 问答记录方式
建议字段：
- 任务 ID
- 组别
- 增强器 ID / 版本
- 关键问题文本
- 用户回答文本
- 回答来源标识（用户）
- 有效性判定
- 判定理由
- 融入位置或融入方式
- 是否改变原始任务意图
- 时间戳
- 备注

## 4. 评价指标与评分方案

### 4.1 主要评价对象
**增强后提示词质量**。不得改为只评答案质量或只评下游作品质量。

### 4.2 建议质量维度
以下维度为建议框架，具体量表与权重需预注册确认：
1. **任务一致性**：提示词是否忠实于原始任务。
2. **信息完整性**：是否覆盖完成任务所需关键信息。
3. **约束明确性**：输出格式、范围、禁止项、边界条件是否明确。
4. **可执行性**：下游执行者能否据此稳定执行。
5. **结构清晰度**：组织、分段、优先级是否清晰。
6. **歧义与风险控制**：是否减少歧义、避免无依据假设。
7. **有效利用确认信息**：是否合理使用同一份实际确认信息。
8. **问答信息融入质量**（仅问答组适用，用于描述性分析，不直接作为组间主比较的唯一依据）。

### 4.3 评分方案
- **评分者**：建议至少两名评分者独立评分；若资源允许，可增加第三名仲裁。
- **盲评**：评分者应不知道组别，或至少不知道研究假设。
- **评分尺度**：**未决**。需在预注册中确认是 1–5、1–7、0–100 还是其他尺度。
- **分母**：**未决**。需确认各维度得分如何汇总、是否加权、总分分母是多少。
- **权重**：**未决**。需确认各维度等权还是不等权。
- **评分者一致性**：建议报告组内相关系数或 Krippendorff's alpha；具体阈值**未决**。

### 4.4 下游作品指标
下游作品质量可作为补充指标，例如任务完成度、事实准确性、格式合规性、用户偏好。但：
- 不得替代增强后提示词质量评价。
- 若使用，需说明下游执行者配置、评价量表和盲评方式。
- 下游作品指标与提示词质量指标应分开报告。

### 4.5 已定与未决参数
| 类别 | 参数 | 状态 |
|---|---|---|
| 已定 | 两组同信息对照 | 已定 |
| 已定 | 评价对象为增强后提示词质量 | 已定 |
| 已定 | 问答由增强器提出、用户回答 | 已定 |
| 已定 | 不得改为模型自行生成执行计划 | 已定 |
| 已定 | 方法收益由组间比较判断 | 已定 |
| 未决 | 评分尺度 | 未决 |
| 未决 | 总分分母 | 未决 |
| 未决 | 维度权重 | 未决 |
| 未决 | 样本量 | 未决 |
| 未决 | 任务类型与数量 | 未决 |
| 未决 | 评分者人数与一致性阈值 | 未决 |
| 未决 | 是否使用下游作品指标及其权重 | 未决 |

## 5. 统计比较方法与适用条件

### 5.1 主要比较
比较 A 组与 B 组的增强后提示词质量得分。

### 5.2 建议方法
- **若任务内配对**：使用配对 t 检验或 Wilcoxon 符号秩检验，取决于差值分布与量表性质。
- **若独立分组**：使用独立样本 t 检验或 Mann–Whitney U 检验。
- **若存在分层变量**：可使用线性混合模型或广义线性混合模型，将任务、评分者、任务类型作为随机效应或固定效应。
- **若评分者多且评分嵌套**：建议使用多评分者一致性模型或交叉随机效应模型。

### 5.3 适用条件
- 独立样本 t 检验：观测独立、近似正态或样本量足够、方差齐性可检验。
- 配对 t 检验：配对差值近似正态。
- 非参数检验：分布假设不满足或量表为序数时。
- 混合模型：需正确设定随机效应结构，样本量足够，模型收敛。

### 5.4 解释规则
- 方法收益由 A 与 B 的组间比较判断。
- 不得用“A 显著、B 不显著”直接证明两组效果不同。
- 若使用显著性检验，需报告效应量、置信区间和不确定性。
- 若采用贝叶斯方法，需预注册先验、模型和决策规则。

### 5.5 多重比较
若检验多个维度或多个次要问题，需预注册多重比较校正方法，如 Holm、Benjamini–Hochberg 或分层检验策略。

## 6. 可调整处与替代方案

### 6.1 可调整处
- 任务领域、难度、语言、长度。
- 增强器类型：人工、模型或混合。
- 用户类型：真实用户、模拟用户或专家用户。若用模拟用户，需说明其局限。
- 评分者数量与培训强度。
- 是否增加下游作品评价作为补充。
- 是否按任务类型分层分析。

### 6.2 替代方案
1. **三臂设计**：增加“直接增强 + 模型自行生成执行计划”作为对照，但需注意该臂与用户问答不同，不能混淆。
2. **交叉设计**：同一任务在不同时间分别进入 A 和 B，控制任务差异，但需防止顺序效应。
3. **多中心设计**：不同站点独立执行同一预注册方案，检验可复现性。
4. **定性补充**：对问答记录进行编码，分析哪些问题类型与高质量提示词相关。

## 7. 缺失数据、偏倚、不确定性和可复现性说明

### 7.1 缺失数据
- 可能缺失：用户未回答、回答无效、增强器日志缺失、评分者未完成评分。
- 处理策略需预注册：完整案例分析、多重插补、最大似然、敏感性分析等。
- 不得默认删除缺失数据而不报告。

### 7.2 偏倚
- **选择偏倚**：任务分配或用户分配不随机。
- **实施偏倚**：两组增强器配置不一致。
- **测量偏倚**：评分者知道组别或受研究假设影响。
- **报告偏倚**：只报告显著结果。
- **问答组特有偏倚**：用户回答可能受提问方式引导；需记录问题生成规则。
- **直接组特有偏倚**：若确认信息不足，直接组可能被迫假设；需记录假设。

### 7.3 不确定性
- 增强器能力、用户能力、任务难度、评分量表均带来不确定性。
- 需报告置信区间、效应量、评分者一致性。
- 若样本量小，需明确结论为探索性。

### 7.4 可复现性
- 预注册研究问题、假设、分组、评价指标、统计方法。
- 保存原始任务、确认信息、问答记录、增强后提示词、评分表、分析代码。
- 记录模型版本、解码参数、随机种子、时间戳。
- 提供数据字典和复现脚本。
- 若涉及用户数据，需说明伦理审查、知情同意和脱敏方式。

## 8. 结论性说明
本设计建议以两组同信息对照比较“先回答关键问题再增强”与“直接增强”。核心公平条件是两组接收同一原始任务和同一份实际确认信息，问答组保留增强器提问、用户回答、有效回答融入的流程，直接组不主动追问但仍可使用确认信息。评价对象为增强后提示词质量，下游作品仅作补充。方法收益由组间比较判断，不得用一组显著另一组不显著直接证明差异。评分尺度、分母、权重、样本量等未确认参数保持未决，需在预注册中确认。
