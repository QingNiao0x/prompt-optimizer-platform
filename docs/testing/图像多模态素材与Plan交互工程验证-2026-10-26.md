# 图像多模态素材与 Plan 交互工程验证

日期：2026-10-26。范围为用户本次授权的多模态双轨素材、结构化替换、Plan 问题显著性和自主补充卡开发。当前 v6 工程检查通过；真实调用已按 [42/100 次闭批](./图像多模态素材与结构化替换真实评测-2026-10-26.md)，逐题语义和保留失败另行记录。本文不提供下游成品质量或正式发布结论；V42／V43 均未执行。

## 实现范围

- 关闭 Plan 保留单 JPEG/PNG 的描述性还原和访客体验。开启 Plan 支持独立选择图片、视频或 PPT 提示词作为交付目标。
- 参考素材提供借鉴内容，替换素材提供新主体／新内容；支持保留、替换、移除、融合关系，定位具体素材、选中页／帧、对象、属性及作用范围。也可只用文字描述新内容。
- 新素材通过独立私有异步解析接口上传；预览、选择范围与遮挡后，另行确认模型外发。图片／视频派生 PNG、PPTX 可见静态页使用真实解析，不依赖独立 OCR 服务。
- 黑色遮挡应用于真正的 PNG 字节；对应单位的结构文字清空。下载供下游使用的 PNG 与模型收到的遮挡版本使用相同转换路径。
- 多媒体依据统一模型目录的实际 `maxImages` 分批识别，最终生成复用来源证据。全部实际尝试包含协议修复，任务上限 28 次；180 秒后不再开启新阶段，多素材前端等待 270 秒并保留操作恢复机制。
- Plan 问题置于设置栏顶部，显示必答／选答和完成进度；主动取得计划后一次定位标题，窄屏显示待回答／待确认状态。只填有效自定义文字同样可满足必答，零问题／全选答仍可确认。
- 自主补充卡复用创作构想、逐字文案、项目上下文，未新增一套问卷。素材、选区、关系及输入变化继续使旧计划失效。
- 历史保留成品类型、素材来源、选页／时间戳、遮挡范围、覆盖说明、用户关系与实际题答；复制正文附下游素材对照说明。原件不进入长期历史。

### 过程中的失败与处理

- 初次受限浏览器访问本机 Vite 被沙箱网络策略拒绝；使用获准的本机浏览器执行后继续验证，未改业务授权。
- 初版新增浏览器用例定位了 Element Plus 隐藏原生输入，且窄屏首次导航缺少页面就绪等待；改为用户可点击的组件和明确就绪条件后复验通过。
- 视觉核对发现缺答后补齐仍遗留全局红色校验提示；改为 Plan 卡片内的同源缺答反馈，完成后自动消失，真实模型错误继续保留。
- 1280px 双行导航实测约 104px，原固定 90px 偏移可能遮住标题；改为读取本页导航实际边界，并先撤就绪提示、等待 DOM 稳定后定位。新增断言曾捕获“定位后移除提示条导致卡片上移”，修复后最终 20 项通过。非零问题答完可用“回到问题顶部”，不新增问答规则或自动抢焦点。
- 初次新增 MVC 夹具的 ByteBuddy attach 被本机沙箱管道权限阻塞；改用 `CurrentActor` 函数式夹具消除动态 attach，生产身份逻辑未改变，随后 14 项媒体／接口测试通过。

## 当前范围与运行要求

- 每任务新旧素材合计最多 6 份、选中单位合计最多 12 个，规范化图像合计 30 MiB。单素材最多 50 MiB，图片仍为 10 MiB；每单位最多 20 处归一矩形遮挡。
- 视频支持选定不超过 30 秒的片段，最多 12 个采样帧。音轨不发送，未覆盖片段、音乐节拍及完整精细运动保持未知；FFmpeg/ffprobe 缺失时明确显示不可用。
- PPTX 最多 100 页，处理可见静态页；不支持旧 `.ppt`、宏、ActiveX、OLE 或外部图像资源。字体和复杂图形可能影响实际页面渲染，不承诺与 PowerPoint 像素一致。
- 图片／视频解析后清理原件；PPTX 为按需选页渲染保留至临时一小时有效期，撤销后立即失去访问权。多实例需要共享私有临时目录，未新增对象存储适配。
- 新增 V42／V43 只前向更新图像历史 JSON、模式和独立来源风险的数据库注释；旧 Flyway 未回改。本次所有隔离实例明确关闭 Flyway，未执行迁移。
- 42 次真实调用已闭批。工程通过不能写成所有视觉模型、所有媒体、下游成品或正式发布质量通过，具体结论见真实报告。

## 同日后续修复：素材审阅裁切与范围状态提示

用户报告的弹窗裁切已在修复前用受控浏览器复现：预览 SVG 四角命中检查返回 false。素材栏的 `overflow: hidden` 与 `backdrop-filter` 使嵌套弹窗受三栏容器裁切。修复只调整图像素材弹窗：挂载到 body，以视口限制弹窗高度、正文滚动、保留页脚；预览按实际图片像素比例整体缩放，图片与 SVG 共用容器，手机使用单列。没有修改全局玻璃面板或其他页面弹窗样式。

状态链核查区分了两个口径：后端异步解析将 `decoded.units()` 连同 READY／PARTIAL 写入素材状态；前端 `asset.units` 是可选页／帧，`SelectedMedia.units` 是用户审阅后保存的外发范围。后者为空时继续禁用符合既有授权边界；原提示未说明这一步，且弹窗裁切妨碍完成选择。现在卡片显示可选／已选数量与下一步，禁用原因明确指出具体素材及操作。

同时修复两处状态缺陷：已有 READY 资产点击刷新原先没有重新 GET 元数据，现在实际查询且保留选区／遮挡；前端原先只检查已选数量，现在还校验 unit ID 属于当前资产。READY／PARTIAL 但无画面时允许刷新，不打开空审阅框。取消已有资产刷新不会撤销仍保留在草稿中的来源。不会因解析成功自动全选或代替用户同意模型外发。

## 同日后续修复：预览 409 的错误展示与再次预览

用户再次报告预览 GET 返回 409，随后确认重新进入页面后恢复。本轮确认并修复两项前端缺陷：

- `responseType: blob` 使 JSON 业务错误也作为 Blob 返回，同步错误处理原先读不到中文说明。现在仅对媒体预览与导出请求解码不超过 64 KiB 的 JSON 错误，保留原 AxiosError、状态码、业务码及 requestId；非 JSON、损坏或超限正文使用固定提示。共享 HTTP 拦截器未改变。
- 再次点击当前已经选中的页／帧原先只赋同一个 `unitId`，不会触发 watch，也不会重新加载。现在该点击主动重新请求私有预览，失败后可直接恢复；没有新增自动重试或模型调用。

本轮复用原合成账号，对正在运行的本机 9000 服务分别上传合成 PNG、JPEG，轮询均达到 READY，私有 PNG 预览均返回 HTTP 200，随后撤销所建测试素材。凭据仅在内存使用，未创建账号或读取用户图片正文。该结果证明当前服务的新图片路径可用；首次截图缺少业务错误正文，不能仅凭 409 断定当时是过期、处理中或文件丢失。

验证结果：API 12＋store 29＝41 项通过；实际媒体服务与 MockMvc 合同共 14 项通过，包含 MP4／MOV／WebM 真实解码且无跳过；受影响桌面／手机浏览器 6 项通过，覆盖中文 409、同一页手动重试、保存恢复、原双轨输入及长横图触摸遮挡；生产构建与类型检查通过。这些结果独立记录，不与此前的 50 项浏览器快照累计。新增 API 用例先出现 7 项失败，修复后通过。

本轮未修改后端业务或数据库，未新增真实模型调用，原 42 次闭批记录保持不变。

## 同日交互优化：勾选范围与隐私确认的视觉引导

审阅弹窗将“选择识别范围”提升为带主色边框、背景、提示图标及“待勾选／已勾选”状态的独立卡片。第一步明确要求勾选，第二步提示检查隐私并按需遮挡；预览不会自动勾选。选中行提供背景、边框及文字反馈，复选框整行至少 44px 高，支持键盘选择。精确遮挡区域另说明填写后需点击“添加遮挡”，避免把输入数值误认为已经应用。

底部始终解释未选、超限、加载或预览错误对应的保存条件。未勾选时可用“前往勾选识别范围”主动定位并聚焦标题；不代替用户选择，滚动尊重减少动画设置。保存条件与原有四项禁用条件等价。页面上的唯一隐私同意框继续位于生成按钮上方，增强边框、状态图标、独立点击区域和勾选提示；弹窗提示保存后仍需到页面确认，不添加第二份授权或自动同意。

视觉复核发现初版在 375×667 CSS 像素下说明和页脚占用过多高度，第一项复选框被挤出可视正文。新增实际命中检查先失败，随后精简说明和页脚，最终确认首次打开即可直接点击第一项，底部操作仍可用。手机正文保持可滚动，图片与 SVG 的比例和遮挡坐标规则不变。

验证分开记录：两份图像 spec 初轮桌面／手机共 30 项通过；最后精简后，深浅主题引导及长横图几何／鼠标／触摸的定向 6 项再次通过，不与 30 项累计。新用例验证初始无预选、首项可点击、定位与标题焦点、空格键勾选、保存后隐私仍未确认、生成按钮与单独授权联动、44px 点击区域及无横向溢出。独立类型检查、最终生产构建和差异格式检查通过。

## 同日功能调整：两种模式均可上传多媒体参考素材

本节记录当前 v7 工程结果；前文“关闭 Plan 仅单图”的描述属于当时快照。正式账号现在无需先开启 Plan，即可添加、解析和审阅 JPEG／PNG、PPTX、MP4／MOV／WebM。普通 JPEG／PNG 沿用原快捷单图流程；PPTX 和视频主动上传到平台后，选择页／帧并保存遮挡，再单独确认模型外发。访客继续保持原单图试用范围，未扩大额度或权限。

关闭 Plan 的请求只携带 `REFERENCE` 轨道的所选范围，不携带构想、指定文案、项目上下文或替换关系。后端复用 `ImagePromptMediaService` 的本地解析和既有私有资产机制；该服务没有 Plan 依赖，无需修改解析器。生成编排新增 `ANALYZE → GENERATE` 直接还原路径，不调用 `PLAN`，不生成创作问题。多批识别遵守模型登记的 `maxImages`，最终阶段只消费已识别证据，不再次发送像素。原纯单图 `EXTRACT` 路径保持可用。

模式切换保留 Pinia 草稿中的全部临时资产、`assetId`、所选 `units`、`masks` 和替换关系。关闭时替换素材隐藏且不参与还原；重新开启后可继续使用，无需重复上传。模式或模型变化会撤销本次外发同意，需重新核对。这里的保留不代表跨刷新持久化，私有资产仍遵守原有效期、撤销和身份隔离规则。

直接还原沿用协议 `outputType=IMAGE` 的兼容值，但指导明确要求逐个描述所选页面／时间点，不融合成不存在的场景或另行设计分镜／PPT。素材尾注按业务模式区分还原范围与创作借鉴范围。历史继续保存页码、时间戳、遮挡和覆盖说明；非 Plan 多媒体记录显示“素材描述”，题答及创作关系为空，不请求历史原件。
