# 本地索引数据库批次写入优化

日期为 2026-11-17，基线提交为 `b6cb3454`。本轮实现用户批准的数据库写入优化，完成范围限于源码本地索引写入及受影响回归。

## 实现

- 检索旧键查询由逐片段查询改为按文件的本批片段范围查询。只读取键，空范围直接插入，已清空的替换范围直接插入。已有片段继续沿用数字键。判断发生在同一个读写事务内，不依据 FULL 模式推测为空。重复提交继续覆盖已有记录，新增记录由唯一索引防止冲突。
- 文件覆盖先合并删除键，再统一维护删除和新增涉及的映射块。暂存删除键达到 4096 个时先刷新，控制大文件删除的临时内存。保留同块内其他文件及其他项目的映射。
- 纯元数据批次仅打开 files，带检查点时增加 projects。正文、词表、映射和检查点仍在一个事务中提交或回滚。
- 在现有 200 文件、300 片段、约 4 MiB 估算数据之外，增加 64,000 条检索词关联的批次阈值。阈值在片段追加后检查，允许多一个片段的余量。该值是初始有界参数，尚未证明是最佳吞吐参数。全文与搜索词不裁剪。
- 稀疏更新时游标直接跳到下一目标键，避免字符串编号范围包含大量无关旧片段。

未变更数据库格式版本，旧 v3 迁移与当前 v4 记录继续兼容。现有读取、目录筛选、权限和恢复入口继续用于本轮验证。

## 自动化验证

- 61 项相关单元测试通过，覆盖索引、存储连接、异常摘要和隔离配置。新增高密度词表分批测试，核对 100 文件的全文、检索词及 READY 状态。
- 最终代码 Chrome 和 Edge 各 8 项浏览器检查通过，覆盖容量、完整词表、旧库迁移、覆盖、检索顺序、原子回滚、配额异常恢复、真实 Worker 继续索引和独立项目隔离。
- 新增请求计数回归中，60 片段以 3 次文件范围查询代替 60 次逐片段旧键查询，两个文件覆盖的共享映射块只写入一次。重复提交后条数仍为 2，其他文件的 20 片段完整保留。纯检查点批次事务范围为 files 和 projects。
- 新增 4,200 片段回归，覆盖超过删除暂存上限、稀疏更新，以及检索更新后检查点序列化失败的整体回滚。成功覆盖后旧词关联清除，同块其他文件保留。
- TypeScript 检查及前端生产构建通过。构建仍有既有依赖注释及大产物提示。

首次浏览器执行因沙箱内本机网络受限导致动态模块加载失败，允许本机测试服务访问后通过。大文件新增夹具首次未保存文件元数据，并错误把检索兜底候选当作精确词命中，修正夹具及判断后通过。首次单测命令误在仓库根目录运行，改在 apps/web 执行。以上准备失败均不计为通过结果。

## 性能与完整性证据

[原始对照及打包文件](./evidence/index-write-batch-2026-11-17/)保存本轮初版候选的 Chrome 前后交错结果。沿用上一轮冻结的 622 文件、8,397,198 字节输入，基线→候选→候选→基线。

| 阶段 | 基线两轮 | 候选两轮 |
| --- | --- | --- |
| 索引总耗时 | 11.097 / 13.259 秒 | 11.045 / 11.037 秒 |
| 写入链路耗时 | 9.449 / 11.713 秒 | 9.590 / 9.408 秒 |

四轮均保存 622 个完整文件、800 个片段、4,779,107 个字符。逐文件重组正文及尾部均为 622/622。正文、路径、片段序号、全部检索词、符号与导入信息规范化后的 SHA-256 全部一致，为 `5a7c3a24602b66f3b1e1254b870c20b11b3f2572b209742d9c429978837c0c38`。

平均总耗时约下降 9.3%，但基线两轮自身相差约 2.16 秒，且本轮部分构建和浏览器检查有并行资源干扰。不能据此认定稳定提速。测量包是加入稀疏游标跳转之前的初版，最终代码的该跳转已完成双浏览器功能回归，尚未重新采完整性能对照。该差异、包哈希和范围已记录在 provenance.json。

本轮样本使用内存 File、生产索引引擎和真实浏览器数据库，未包含原生文件夹遍历和用户磁盘读取，未进行用户两万余文件整目录复验。采用结论是减少可确定的重复操作并通过受影响功能验证；大目录速度改善保持待验收。
