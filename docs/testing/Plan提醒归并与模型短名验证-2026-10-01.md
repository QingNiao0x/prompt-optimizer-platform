## 提醒合并

| 模块 | 职责 |
| --- | --- |
| `PlanAmbiguityMerger` | 按绑定问题 ID 和冲突字段、成对来源及取值登记已有事项；先保留新冲突和未决原问题，再判断模型补充 |
| `ConfirmedDecisionSet` | 保留决定解析、检索查询及明确冲突选择；移除已经被新合并器替代的文本去重方法 |
| `OptimizationResultAssembler` | 验证提醒关联，使用合并后的唯一列表同步 API 和 `CLARIFICATIONS`；最后应用 8 项展示限额并提示未展示数量 |
| `EnhancementProviderResponse` / `AmbiguityReference` | 保持旧构造器兼容，增加可选内部问题关联 |
| OpenAI 兼容 Provider | 同一次响应可附带问题 ID；校验类型、长度、数量及关联正文，不新增独立模型请求 |

内部可选输出示例：

```json
{
  "ambiguities": ["数据来源未确认。"],
  "ambiguityReferences": [
    {"message": "数据来源未确认。", "questionId": "data-source"}
  ]
}
```

`ambiguityReferences` 默认空列表，省略或 `null` 兼容旧端点；最多 8 项。`message` 必须与提醒数组中的一条非空文本相同，最多 500 字符；`questionId` 为 1—64 个英文字母、数字、下划线或连字符。该字段不进入浏览器请求或公开结果，也不改变计划所有权。

关联只能作为线索。未知 ID 不参与绑定判断；有效 ID 仍需核对文本是否增加业务信息。旧端点没有关联时，按常见维度与剩余文本作保守匹配，仅唯一匹配时归并。新金额、工具版本、人员范围、退款授权、不同来源、比较符差异均不能仅凭相似主题被删除；无法判定时保留。
