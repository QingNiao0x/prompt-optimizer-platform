# 规则保真与复制正文完整性

记录日期：2026-10-03。实现与回归发生于 2026-10-02 至 2026-10-03。

## 1. 范围与复现

本批实现两项改进：关键规则保真、复制正文完整性。依据是 [三方业务评测](./Prompt优化三方业务评测-2026-10-02.md) 的失败类型，不把历史模型输出等同于当前部署结果。

修改前，通过生产 `OptimizationResultAssembler` 入口新增 10 项定向检查，其中 8 项失败，复现了明确规则漏保留、取消行为反转、填充空字段变为清空字段、研究报告允许编造文献、报告字数上限变化，以及寿命表或新冲突未进入正文等问题。既有模型校验以结构、安全和答案补回为主；补回原句不能消除草稿中已存在的相反指令。

复制问题来自结果契约：`renderPrompt` 跳过 `CLARIFICATIONS`，前端编辑也跳过该段落；主复制、平台复制和历史均使用 `optimizedPrompt`。仅将关键未决条件放在提醒列表，会让另一位 Agent 看不到它们。

## 2. 实现

| 路径 | 变化 |
| --- | --- |
| `RequirementFidelityGuard` | 提取原始需求与明确执行答案中的规则，保留完整条件、否定和例外；拦截能够确定的反向要求与同对象数值边界变化。已绑定业务选择替代原规则时，不丢弃同句中其他独立约束。 |
| `OptimizationPlanningServiceImpl.requestValidatedPlan` | Plan 的选项答案、标签、说明和推荐理由进入规则校验；校验发生在 Provider 共用修复预算内、计划注册之前。 |
| `OptimizationResultAssembler` | 先检查执行段落，再补遗漏原句、来源事实、确认答案及平台约束。资料事实提取在一次组装中复用；沿用既有相关性、用途和敏感信息过滤。 |
| `PlanAmbiguityMerger` | 应用内部区分最多 8 项的展示列表与完整执行前提；展示上限不再截断复制正文的未决条件。 |
| `AmbiguityDetector` | 已明确“按高、中、低风险等级排序”的业务报告不触发编程排序问题；缺少比较规则的开发任务仍提问。 |
| OpenAI 兼容 Provider | 加强规则保真、选项文案一致性与未决前提指令；`RULE_CONFLICT` 与结构、安全校验共享原有最多 3 次调用预算。 |

对外请求/响应字段、模型选择、权限、身份隔离和历史表结构均未修改。前端生产代码不需要另拼提醒，所有复制入口继续读取后端生成的同一份正文。

规则检查示例：

- “取消时保持原值”不能变成“移除保持原值的逻辑”。
- “只向 null 或空字符串的字段填值，保留 0 和 false”不能变成“清空字段”。
- “不得编造参考文献”不能变成“可以编造参考文献”。
- 同一对象的“不超过 1000 字”不能改成“不超过 2000 字”，“大于”不能改成“大于等于”。
- 附件字数与正文篇幅、邮件重试与站内信重试、历史引用与本次执行分别处理，不仅凭几个词相似就拦截。

对于可确定的反转，先让模型在现有预算内修复；仍不合格时返回 `RESULT_INVALID`，不把错误草稿当作成功结果。日志只记录固定原因与字段路径，不包含触发错误的正文。

## 3. 复制契约示例

用户要求计算 YLL，但参考寿命表尚未确定时，结果的约束部分包含：

```markdown
## 约束
不得编造研究结果或参考文献。

执行前须确认（仅涉及下列未决条件的步骤需等待确认；不得自行假定答案）：
- 计算 YLL 使用哪份参考寿命表？该选择会改变计算结果。
```

同一内容同时进入 `sections.CONSTRAINTS` 和 `optimizedPrompt`。提醒列表仍展示该问题；没有未决条件时不增加此段。已解决的问题和通用占位提醒继续过滤，不能只为正文完整而复制所有旧提醒。新冲突继续保留；完整归并结果超过 8 项时，列表提供数量提醒，正文包含全部归并条件。

编辑其他段落后约束仍保留；取消未保存的编辑不会改变复制结果；再次增强提交当前已保存正文。用户主动编辑业务要求仍被允许，平台权限红线继续强制补回。

## 5. 限制与后续验收

- 规则检查采用有限且保守的文本与作用域判断，不是任意语言、专业方法或复杂改写的完整语义证明。明确规则原句的保留和模型指令能降低遗漏风险，仍不能承诺任意输出绝不反转。
- 同义改写无法证明完整覆盖时，正文可能额外保留原句，长度略有增加；确定存在规则冲突时可能消耗剩余重试预算。正常输出不新增独立模型轮次，最多 3 次的既有预算不提高。
- 原始资料的检索范围、摘要覆盖和冲突检测能力沿用现有实现；本批不保证发现全部跨文档专业冲突。已识别冲突保留出处与提醒，不将双方同时设为必需执行规则。
- Store 的撤销恢复通过测试，但当前结果面板没有撤销按钮。本轮不扩展界面交互；页面实际验证的是保存和取消编辑，撤销入口另记待办。
- 没有启动真实外部模型调用、Qoder 新一轮对照、真实数据库验收或生产部署。原有历史 PASS/FAIL/PENDING 不因本地回归改变。
- 真实验收需用当前开放模型和最终代码重跑软件、科研、机关报告、数据分析等反例，记录遗漏、误拦、重试率、Token 与延迟；仍需领域评审及既有双人上线门禁。
