# 模型并发控制验证（2026-10-02）

本文件记录先前受控上游验证。随后经用户授权完成的真实 DeepSeek 付费测试，见 [模型并发真实压测](./模型并发真实压测-2026-10-02.md)；两次验证的范围与证据分别保留。

## 1. 本次实现

默认全平台最多同时执行 **50 个上游模型 HTTP 调用**；同一服务端认证账号最多同时执行 **3 个模型相关业务请求**。两个限制分别计数，账号限制从 `CurrentActor.userId` 取身份，跨标签页、Session、设备和工作区共享。

- 全局名额覆盖所有模型路由、提示词增强、Plan、文档摘要、Embedding 及每次结构修复调用。从实际发送 HTTP 请求前占用，到响应体读取并关闭后释放；连接异常也释放。
- 账号名额覆盖增强、Plan、上下文分析/准备及历史再次增强的整次 POST 请求，包括请求内的修复重试。Plan 等待用户确认时不占名额，登录、历史读取和健康检查不占名额。
- 账号第 4 个并行请求返回 HTTP 429 / `USER_MODEL_CONCURRENCY_LIMIT`；平台第 51 个并行模型调用返回 HTTP 503 / `MODEL_CONCURRENCY_LIMIT`。采用立即拒绝策略，不增加等待队列。
- 错误沿用统一响应结构，包含 `retryable=true`、`details.retryAfterSeconds=1` 和 `Retry-After: 1`。一秒是建议等待时间，不保证一秒后一定有名额，也不表示客户端会自动重试。
- 生产默认 Redis 原子脚本计数，租约五分钟、每三十秒续租，正常和异常结束释放；进程终止后遗留名额按租期回收。存储失败时拒绝新增调用，不自动降级成各实例独立计数。
- 保留现有前端按钮加载和禁用交互。本次未修改数据库结构、模型密钥、付费配额或用户额度。

## 2. 配置与生效

配置位于 `services/api/src/main/resources/application.yml`，环境变量示例位于 `.env.example`：

```dotenv
MODEL_CONCURRENCY_GLOBAL_LIMIT=50
MODEL_CONCURRENCY_USER_LIMIT=3
MODEL_CONCURRENCY_STORE_MODE=REDIS
MODEL_CONCURRENCY_KEY_PREFIX=prompt-optimizer:model-concurrency
```

重新构建并重启后端后生效。多 API 实例必须使用同一 Redis 数据库、同一前缀和相同限制；不同部署环境使用不同前缀。`local-mock` 与默认自动测试显式使用 `MEMORY`，该模式只保证单实例内的限制。本次未重启已有开发服务或执行生产发布。

## 3. 并发验证

新增四个测试类，共 **14 项测试通过**：

| 测试类 | 数量 | 验证内容 |
| --- | --- | --- |
| `ModelConcurrencyLimiterTest` | 3 | 100 个并发竞争者仅 50 个获得名额；同账号上限 3 且不影响其他账号；共享存储异常时拒绝调用。 |
| `ModelConcurrencyHttpInterceptorTest` | 3 | 收到响应头及读取正文时仍持有名额；关闭响应后释放；连接和关闭异常不会泄漏名额。 |
| `ModelConcurrencyHttpIntegrationTest` | 4 | 50 个真实本机 HTTP 连接同时等待响应正文，第 51 个被拒绝且未到达上游；同一账号三个独立 Session 混合调用增强和 Plan，第 4 个被拒绝，其他账号可用；上游错误、无效 JSON、参数校验后恢复；身份伪造和缺少 CSRF 仍被拦截。 |
| `RedisModelConcurrencyStoreIntegrationTest` | 4 | 两个独立限流器共享真实 Redis，100 次竞争仅允许 50 个；账号上限跨实例共享；续租覆盖初始租期；遗留令牌过期后回收，重复释放不能误删新请求名额。 |

最后一轮后端全量回归退出码为 0：**85 个测试类、495 项测试，493 项通过，0 项失败，0 项错误，2 项跳过**。跳过的是需要显式开启的 `AnalyticsPerformanceAcceptanceTest` 和 `AnalyticsRealBrowserAcceptanceTest`；本次四个 Redis 并发测试均实际执行。统计仅采用本轮更新的报告，未把报告目录中旧包结构留下的历史 XML 纳入结果。`git diff --check` 通过。

HTTP 并发测试使用真实 Spring Security 身份适配、MVC 拦截器和生产 `RestClient`，上游为随机本机端口上的受控 HTTP 服务。入口通过 MockMvc 驱动，业务编排替换为测试夹具，以确定性地控制请求生命周期；该测试不评估真实模型输出质量。Redis 测试只创建本轮随机前缀的键并清理明确归属本轮的键，不扫描或清空已有业务数据。

## 4. 复现与环境

本轮环境为 Windows、Java 21.0.12、Maven 3.9.14，本机 Redis 版本为 3.2.100。Redis 脚本在旧版本中显式启用命令效果复制，以支持使用服务端 `TIME` 后写入租约；Redis 7 默认使用该复制方式，见 [Redis Lua API](https://redis.io/docs/latest/develop/programmability/lua-api/)。本轮未在项目规划的 Redis 7 部署环境重新执行。

从仓库根目录进入 `services/api` 后，在 PowerShell 执行后端全量回归：

```powershell
mvn -q -s ../../.mvn/settings.xml `
  '-DmodelConcurrency.redisIntegration=true' `
  '-DargLine=-Djdk.net.unixdomain.tmpdir=E:/MyProject/prompt-optimizer-platform/services/api/target -Dfile.encoding=UTF-8' `
  '-Dmaven.test.redirectTestOutputToFile=true' `
  '-DreuseForks=false' '-DforkCount=2' test
```

只验证本次并发控制时，在命令中增加：

```text
-Dtest=ModelConcurrencyLimiterTest,ModelConcurrencyHttpInterceptorTest,ModelConcurrencyHttpIntegrationTest,RedisModelConcurrencyStoreIntegrationTest
```

- 真实 Redis 测试默认关闭，显式设置 `modelConcurrency.redisIntegration=true` 才运行；默认地址 `127.0.0.1:6379`，可通过 `modelConcurrency.redisHost` 和 `modelConcurrency.redisPort` 指定专用测试实例。
- 当前 Windows 的短临时目录路径导致 JDK Selector 初始化失败，因此本轮将测试 JVM 的 Unix-domain 临时目录指向实际存在的 `target` 目录。复现时替换为自己的绝对路径；没有修改系统 Java 配置。
- 全量测试中其他测试会修改 JVM 日志级别，因此本轮采用独立 fork，避免日志断言受前一个测试影响。无数据库启动测试同时补齐三个数据库验收 Mapper 的 Mock，保持该测试显式关闭数据库的设计。
- 测试报告保存在 `services/api/target/surefire-reports`。

## 5. 验证边界

本次验证了 50/3 的服务端并发边界、跨实例共享计数及名额释放。未向真实 DeepSeek 发送 50 并发付费请求，未对部署服务器的 CPU、内存、网络及持续吞吐进行压测，不能据此承诺真实模型在该并发下的时延和成功率。本次也不替代 Plan Mode 的真实 Provider 业务验收或正式上线验收。
