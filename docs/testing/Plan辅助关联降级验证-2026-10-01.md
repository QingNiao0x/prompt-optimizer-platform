## 原因与代码调整

先前 OpenAI 兼容适配器和结果组装器把辅助关联错误当作必需结构错误。即使 `sections` 和 `ambiguities` 有效，辅助字段格式错误或正文不匹配仍触发 `INVALID_RESPONSE`，最多调用三次后失败，直接增强也受到影响。

| 文件 | 本次处理 |
| --- | --- |
| `provider/domain/AmbiguityReference.java` | 统一规范化首尾空白、校验 ID/正文/长度；超量关联弃用，同一正文指向多个问题时弃用该组 |
| `provider/infrastructure/openai/OpenAiCompatiblePromptEnhancementProvider.java` | JSON 辅助字段形状错误仅降级；有效条目继续处理；不改变必需结构错误的重试策略 |
| `enhancement/service/impl/OptimizationResultAssembler.java` | 其他 Provider 也接受相同检查，辅助字段不能拖垮有效结果；最终提醒与 `CLARIFICATIONS` 保持同步 |
| `enhancement/service/impl/PlanAmbiguityMerger.java` | 逐子句核对复合提醒，保留追加的新问题；兼容没有关联字段的认证方式提醒 |

公开请求和响应字段没有新增或修改。内部关联仍为可选列表，默认 `[]`，缺省或 `null` 均兼容旧 Provider。最多 8 条；规范化首尾空白后，`message` 为与已有提醒匹配的非空字符串，最多 500 字符；`questionId` 为 1—64 个英文字母、数字、下划线或连字符。不会推断或重写问题 ID。

错误类型、超长、正文不匹配等条目被丢弃；非数组或数组超过 8 条时整体弃用。正文含新条件时，即使模型提供有效关联也不能自动消除。无法可靠拆分复合提醒时保留整条，因此可能仍有重复半句，但不会为追求去重而主动删掉新问题。

日志事件为 `model.response.optional_references_ignored`：包含 `requestId`、`stage=provider/assembly` 和 `ignoredCount`。不写入关联正文、问题 ID、原始提示词或凭据；可通过请求标识关联既有模型调用日志。没有新增浏览器警告或待确认占位文案。
