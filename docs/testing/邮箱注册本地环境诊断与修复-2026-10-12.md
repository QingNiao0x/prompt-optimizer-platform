## 修复前固定信号

初始 41 项既有邮件/注册回归通过，但缺少真实 `local-mock` HTTP、投递与清理同时失败、SMTP 缺失配置分阶段诊断的覆盖。

新增复现测试：

- `LocalMockRegistrationHttpTest`：随机端口的真实 Tomcat + Security + Cookie/Header CSRF；`local-mock` 排除了 Controller/Service。携带有效 CSRF 的发码和注册均得到 500，而应明确说明 Mock 不支持注册。该测试没有复现用户原日志的 401，不能把 500 与 401 称为同一条已确认故障；缺失路由的错误处理是确认的 Profile 缺陷。
- `EmailRegistrationServiceTest.shouldPreserveDeliveryFailureWhenRedisCancellationAlsoFails`：投递抛出 `DELIVERY_UNAVAILABLE` 后，Redis 清理又抛出 `SERVICE_UNAVAILABLE`；修复前后者覆盖前者，用例失败。
- `SmtpVerificationEmailSenderTest`：客户端/From 缺失的固定诊断断言修复前失败；真实 `JavaMailSenderImpl` 的 Host、用户名、密码缺失测试触达禁止发送切面，说明缺少网络前配置检查。网络发送由禁止访问的测试实现替代，未连接 SMTP。

首轮 HTTP 测试曾缺少 DispatcherServlet 自动配置，不能算业务复现；补齐隔离测试装配后再确认上述 500 信号，测试装配问题未通过修改生产代码解决。

## 实施

1. 所有模式保留注册协议 Controller；仅 `local-mock` 注入 `LocalMockEmailRegistrationService`，以 `503 REGISTRATION_SERVICE_UNAVAILABLE` 明确拒绝发码与建号，不伪造成功。完整模式继续注入原服务。
2. SMTP 发送前检查实际客户端的 Host，以及要求 SMTP 认证时的用户名/密码；自定义投递客户端和明确免认证 SMTP 保持兼容。缺失客户端、From、协议调试、禁用投递均记录有限原因码，不含配置值、验证码、地址或完整异常。
3. 存储初始化只记录类型、Redis 是否必需与客户端是否存在；不做隐式网络探测，不修改 Redis 故障拒绝规则。缺失客户端有稳定诊断。
4. 邮件失败后的 Redis 撤销失败单独记录，保留原始投递失败，仍不返回成功；未完成的撤销保留既有限流/TTL 状态，不额外重置计数。
5. 增加实际 Spring 配置装配回归，核对 `verificationStore` 确实为容器中的 Hybrid 存储；核对完整 SMTP 模式无 Redis 必须失败，以及显式本地日志+内存模式的冷却规则。

生产 `application.yml`、`application-aliyun-smtp.yml`、其他 Profile YAML、Compose、Flyway 和真实环境变量均未修改。原 SMTP TLS、隐私保护、CSRF 和身份唯一性规则继续保留。
