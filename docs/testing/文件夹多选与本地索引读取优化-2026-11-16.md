# 文件夹多选与本地索引读取优化

日期：2026-11-16。基线：`e18a117106c91e4ecdc33389114b47c9c6d6fd3e`。候选为包含本报告的提交；不引用其他会话的测试作为本轮通过依据。

## 范围与结论

本轮完成工作台文件/文件夹多选、完整索引的多根来源支持、小文件重复读取优化及发现的路径/授权取消缺陷。没有调整增强、Plan、动态约束、后端解析、账号或历史数据。办公文档仍需要确认后上传；源码索引仍在当前浏览器。

局部性能改善有同输入证据；截图中的 23,431 文件整目录，以及其他设备/浏览器的长期性能没有在本轮重新验收，不能宣布“大目录慢已全部解决”。

## 诊断与实现

| 问题 | 修改 | 保持的保护 |
| --- | --- | --- |
| 小文件已经预读，仍包装 Blob、重新采样并读流 | `projectIndexer` 将预读字节直接用于分类和正文解码 | 六路、每份 ≤64 KiB；大文件流式；完整正文、词表、符号、分块边界不变 |
| 原生目录窗口每次只能返回一个目录 | 新增 Element Plus 清单，连续加入、移除、取消后统一开始；纯目录拖入使用同一入口 | 用户主动选择；单根路径兼容；办公文档上传确认 |
| 多根同名文件可能覆盖，忽略规则不能共用 | 固定根前缀；同名根编号；每根先过滤再加前缀 | `.gitignore` 不跨根；敏感/生成目录仍过滤；共用总预算 |
| File 自定义路径跨 Worker 丢失 | 主线程单独传递逻辑路径，Worker 恢复后继续安全校验 | 不改变内容、不忽略路径校验；主线程兼容回退保留 |
| 多根恢复授权时取消，可能继续请求下一根 | 每次权限查询/申请前后检查任务有效性 | 真实拒绝继续报错；取消后的迟到结果不启动 Worker |

浏览器限制依据：[MDN showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)。多文件夹操作采用累积清单，不声称系统原生窗口支持 Ctrl 一次选多个目录。支持目录句柄时完整索引；不支持时 FileList 入口仍受既有 1,000 个候选文件及字符预算约束，超限必须提示。

`TemporaryDocumentIndexService` 属于确认后的文档上传/解析链路；截图“正在建立本地项目索引”发生在前端 Worker 和 IndexedDB。本轮不靠提高模型额度、HTTP 分片数量来解释或修复该阶段耗时。

## 同输入性能与完整性

证据目录：[folder-selection-index-2026-11-16](./evidence/folder-selection-index-2026-11-16/)。冻结 622 份仓库文件（500 JSON、122 TypeScript），共 8,397,198 字节，每份 ≤64 KiB；使用真实浏览器 File、生产索引实现及真实隔离 IndexedDB。每个浏览器执行基线→候选→候选→基线，禁止中途改变文件清单。

| 浏览器 | 基线总耗时，两轮（秒） | 候选总耗时，两轮（秒） | 平均处理阶段（秒） | 平均总耗时变化 |
| --- | --- | --- | --- | --- |
| Edge | 22.901 / 13.083 | 15.043 / 12.238 | 2.859 → 1.630，约 -43% | 17.992 → 13.640，约 -24% |
| Chrome | 13.615 / 12.533 | 12.179 / 11.829 | 2.832 → 1.814，约 -36% | 13.074 → 12.004，约 -8% |

总耗时包含存储提交，未包含系统目录选择、原生文件夹遍历和从用户磁盘读取文件。输入为冻结源码组成的 File 对象；不是实际整个大目录首导速度。Edge 首轮写入比最后一轮慢约一倍，不能把平均总耗时差异全部归因于本次代码；处理阶段减少重复读取的收益更直接。写入仍占主要时间，不能承诺每台设备都提速同一百分比。

八轮均：622 文件完整索引、0 失败、800 个片段、4,779,107 个正文字符；逐文件重组后全文与输入一致，622 份尾部一致。完整片段正文、路径、序号、搜索词、符号与导入信息的规范化 SHA-256 均为 `5a7c3a24602b66f3b1e1254b870c20b11b3f2572b209742d9c429978837c0c38`。只归一化随机项目 ID，不删除搜索词来制造一致。

原始 `baseline.json` 曾报告尾部 618/622：检测器仅检查最后一块、要求包含最后 100 字符，末块不足 100 字符时误报。全文校验一直为 622/622；修正为重组正文后检查尾部，保留原文件不改判。另有脚本打包别名缺失与冻结文件哈希漂移的准备错误，修正后从基线提交恢复输入；这些不计为产品性能失败。

## 验证

- 127 项相关单测通过：索引、目录来源/过滤、文件读取、多根权限取消/拒绝、准备阶段。
- `npm run build` 通过，包含 TypeScript 检查。构建仍提示依赖注释与大于 500 kB 的产物，不代表没有打包优化空间。
- Edge：桌面和手机尺寸各 4 项多选/恢复测试；7 项共享导入、进度、配额异常恢复、文档确认测试；3 项旧工作台索引/暂停/重开页面测试；2 项检索、复制与历史测试。
- Chrome：桌面和手机尺寸各 4 项多选、同名根、取消、恢复测试通过。与 Edge 及共享回归合计 28 项浏览器检查通过（重复复跑不另计）。
- 多根真实 Worker 暂停后继续：两个根、600 文件，同一路径前缀、全部正文/末尾一致，已提交文件复用；未把模拟权限/延迟当作真实磁盘耗尽。
- 文件多选使用实际 filechooser；兼容目录使用两份磁盘合成目录，断言最终分析请求路径与全文。原生目录选择返回 OPFS 原生句柄，后续 Worker、IndexedDB 为生产实现。身份、模型、HTTP 返回受控，不是后端解析或真实模型质量验收。手机为浏览器尺寸/设备模拟，非实体手机系统选择器验收。

失败与修复记录：兼容同名根测试首次丢失第二根路径，定位为 Worker 结构化克隆，不是少等几秒；修复后实际请求四份内容与独立根规则一致。权限单测先 4 失败，再 7 通过。共享检索测试另发现旧提示文案和旧共享库定位已过时；更新为当前隔离库读取，并停止向历史冻结目录回写本轮结果，未降低检索或复制断言。

## 使用与后续

刷新工作台后，在“选择文件”窗口多选；“选择文件夹”首选一个目录，再用“继续添加文件夹”累积，最终点击“开始处理 N 个文件夹”。取消清单不开始索引。页面刷新仍按原产品规则清空当前选择，不自动恢复旧授权到面板。

下一步性能工作应以真实大目录分阶段耗时为依据，优先研究占主要时间的 IndexedDB 写入，保持完整正文/检索词及失败恢复。真实硬配额耗尽、旧库清理无反馈、跨刷新恢复和复杂文档全格式兼容均未由本轮关闭。当前存储也不跨浏览器同步，不能承诺浏览器、设备与会话变化后绝无延迟。
