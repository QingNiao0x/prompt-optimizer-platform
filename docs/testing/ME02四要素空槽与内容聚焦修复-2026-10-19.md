# 四要素空槽与内容聚焦修复（2026-10-19）

本轮处理截图暴露的公共生成与呈现机制，不为“AI 使用最多的行业”新增领域模板。平台仍只生成优化提示词。以下记录区分本地实现、实际链路和下游作品，不以正文更短或评审偏好代替质量验收。

## 证据与共同根因

原题为“请帮我查询全球使用AI最多的职业/行业”。截图中口径、来源和资料局限在任务、输出、背景及约束反复出现，具体职业和用途不足。截图没有完整模型响应；固定测试账号、租户、工作区下的精确历史查询为零条，未扩大查询其他用户。因此不能断言每一处重复均来自平台，也不将截图转录冒充原生复制正文。

1. `OpenAiCompatiblePromptEnhancementProvider` 与 `OptimizationResultAssembler.collectSections` 共同强制四类正文非空。没有独立背景的简单任务也得填满背景，形成“用户希望……”复述；自然模式只是串联这些段落，无法消除生成阶段的内容重复。
2. `PromptOptimizationGuidance`、`PromptRewriteStrategy` 和 Provider 协议对分段职责、补缺与局限有重叠指导，缺少明确的内容先后：先回答用户要什么，再以方法、证据和边界支撑。`DraftDeliveryContract` 又要求 TASK／OUTPUT 双份交付声明。
3. Mock 无额外上下文时直接复制原题作背景，同样制造重复，但截图标明真实 DeepSeek，不能把截图归因于 Mock 路由。
4. `RequirementFidelityGuard` 的裸“最多”会把比较目标识别为原文规则，进入保守追加路径。本轮尝试数字／单位绑定后，独立审查发现会漏掉符号、预算关系与截止时间上限，已撤回生产改动并保留反例测试。未通过增加问法列表或扩大删除来追求短文本；该保守追加局限仍开放。
5. `EffectiveTaskViewFactory` 与当前任务意图解析把该原题归为 GENERAL，未误识别为研究设计；截图 Plan 关闭，“先明确口径”是正文指令，不是已发生的用户问答。没有证据要求修改 `PlanQuestionFilter` 或另建一条增强链路，相关路径用反例和真实 Plan 验证保护。

## 实现与兼容边界

- `PromptSectionType.allowsEmptyContent()` 统一协议：四类仍必须各出现一次，TASK 必须非空；BACKGROUND／OUTPUT／CONSTRAINTS 可为空字符串；缺字段、null、重复、空标题及空其他可选段继续拒绝。
- 初始生成、协议重试及 SECTION_INVALID 修复说明一致；不增加调用次数。共享指导合并重叠表达，要求按内容价值组织，不用模块齐全证明增强。
- Assembler 保留内部四槽直到来源、原文规则、Plan 确认、未决和平台保护全部组装、复查完成，再过滤空节。正文与 API sections 共用最终投影，历史直接保存该结果，不改写旧记录。
- 显式要求“写提示词”仍须由 TASK 承载，非空 OUTPUT 继续检查交付层级；空 OUTPUT 不再被强制要求复述。
- Mock 保留真实上下文，不再无依据复制原题当背景。前端按实际段落数组显示和编辑，无需放宽编辑非空校验。

采用面向读者的检查：能否迅速看懂要回答什么、哪些条件真正影响执行、最终交付什么；背景和验收必须有独立价值。参考 [Qoder 官方实践](https://docs.qoder.cn/qoderwork/practical-tutorial/cue-word-enhancement) 对具体任务、相关背景及交付形式的说明。用户给的 [CSDN 文章](https://blog.csdn.net/2301_80863610/article/details/153263932) 和 Qoder 文案仅作表达参考，不把宣传效果当测试结论，也不把“依赖度最高”自动升级为原题已确认目标。

## 验证方案

使用同一合成账号、本机源码与服务。限定最多24次：两次自然 Plan 含既有协议修复6次；原题两态及两条 Plan 后增强含修复12次；四份同资料作品4次；Flash／Pro 两次独立 AI 辅助评审2次。不重采七题旧基线，不做作品质量重试。

原题作品比较为原始提示词／最新自然复制正文／最新结构化复制正文；用户提供的 Qoder 文案单列参考臂。四臂使用同一模型、参数和冻结来源摘记。现有 API 没有联网工具，这验证同资料条件下的组织、理解和交付，不等同于截图中实时网页检索；不让脚本给平台正文补遗漏答案。

留出任务为交接记录整理，重要选择反例为课程改线上或延期。观察普通组织是否少打扰、重要方案是否保留确认；原生复制和新历史逐字比较。旧安全、评分和领域作品失败不因本轮变短而关闭。

以下结果对应候选四十三原批次；后续 r1 的实现和验证不混入本批统计。

## r1 定向复验与最终采用决定

第二次只检验同一公共假设：自然正文集中生成，能否减少多段拼接与复述；同时修复 472 引用格式错误的恢复分类。冻结前独立审查发现，强制 BACKGROUND／OUTPUT 为空与这些位置的合法确认引用冲突，已先补齐引用例外及集成测试，未用真实调用试错。未激活的旧快照仅留在私有目录，真实运行冻结为 `8007d45e`，见 [r1 源码清单](./evidence/me02-candidate43-concise-output-2026-10-19/candidate43r1-source.json)。

`BoundRequirementProjection` 对未知引用、目的段错误、条件／否定／引用范围中的非法引用继续拒绝；将此类模型可改正的格式错误归为 `REQUIREMENT_REFERENCE_INVALID`，进入原有最多三次的修复机制。真实用户确认缺失、固定元数据及上下文错误仍不可由模型重写，没有自动拆行、强行展开或放宽安全条件。新增 14 项恢复测试包含 472 原件回放、非法引用持续拒绝、次数上限和不可恢复反例；无需数据库迁移或前端枚举调整。

在用户既有自行决定授权下，明确将原批关闭的 8 次重分配给 r1：Plan 1、增强 6、作品 1、评审 0，正式上限仍为 500／80／420。实际 **482—485 共 4 次**：原题增强、交接 Plan、交接增强及固定复制正文作品各一次。两个增强均首次成功，交接 Plan 零问题，两个原生复制／API／新历史一致，无新账号、无质量重试。实际成功不意味着本次模型恰好触发了引用修复；该恢复路径由失败原件离线回放证明。完整归档见 [r1 结果](./evidence/me02-candidate43-concise-output-2026-10-19/r1/archive-manifest.json)。

**r1 内容与作品质量仍失败，集中 TASK 指导最终撤回。** 482 原始模型响应的 BACKGROUND／OUTPUT 已为空，但额外 ACCEPTANCE 又重复“分职业与行业、标口径、来源、不虚构”；平台还因原题中的“最多”把原题作为权威来源再放入约束。484 交接正文、来源规则与验收再次重复相同依赖。不能把这些重复全部归为平台追加，也不能因安全投影完整而视为紧凑性通过。
