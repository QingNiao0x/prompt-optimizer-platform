# 提示词增强质量修复与真实盲评（2026-10-12）

本轮实施三类修复：推断必须有依据、按实质缺口选择增强幅度、按任务组织紧凑正文。代码已修改并通过相关回归，使用同一个测试账号完成两款真实模型的最终两轮请求。**整体作品质量未通过，上线阻断；不能把本报告理解为三个问题均已解决。**

## 1. 冻结输入与可复核链路

- 七个固定样例：收入单指标分析、模糊邮件、充分邮件、模糊研究设计、充分研究方法、两行纯译文、严格 JSON。原题、合成附件、空确认答案、Plan 关闭、示例关闭及权限开关均在修改前冻结。
- Q01 附件仅有合成公司收入 100→120。历史 Pro 将其推成份额／需求未下降的失败另存；本轮旧版本基线没有再次出现完全相同的断言，因此不声称“本轮先复现了原断言，再用四次成功证明永久消除”。另以真实原件形成确定性回归。
- 使用正常验证码／密码登录后的同一普通测试账号；经真实 HTTP、编排、模型路由、PostgreSQL 历史写入及读取，再将**平台可复制正文原样**提交下游。评测脚本不补答案、不替换模型输出、不润色作品。
- 后端候选在专用 9001 实例，前端在 5177，经 Vite `/api` 代理。没有替换日常 9000 实例，没有提交、推送或发布。
- 归档完成后已核对并停止本轮专用后端和 Vite 进程；日常 9000 仍监听，浏览器保持打开。
- 源码与编译结果按 baseline、各中间版本、candidate4、candidate5 分别冻结；初次失败不覆盖。candidate4 双评审发现问题后再修复，并将 candidate5 作为最终候选完整重跑。每题每模型重新增强两次，并分别执行一次；这验证两次完整链路波动，不等同于对同一份固定提示词重复执行两次。
- 基线每题每模型一次。初次 Flash 使用无效目录标识的请求在平台被拒，修正为目录实际标识后采集基线；失败仍保留。Pro 的模糊研究基线未成功交付，按失败计，不伪造对应作品。有效基线 13 份作品，最终候选 28 份；两轮对照重复使用同一份对应基线，不是 28 个独立任务。
- 本轮胜／平／负比较的是**旧版本增强与本轮增强**及其作品；没有新增“原始提示词直接执行”对照组，因此不能据此声称增强普遍优于原始提示词。

实际路由是 `deepseek-flash`、`deepseek-v4-pro`。冻结协议里的 `deepseek-pro` 是当时的简称，真实请求以归档 JSON 的 `model` 为准。下游固定 temperature=0.2、max_tokens=8192、thinking disabled；增强端保留平台路由参数和既有最多三次总尝试，没有增加在线裁判调用或无限重试。

证据入口：[冻结样例](./evidence/enhancement-quality-2026-10-12/cases.json)、[机械检查和用量](./evidence/enhancement-quality-2026-10-12/mechanical-audit.json)、[源码差异](./evidence/enhancement-quality-2026-10-12/change-from-frozen-baseline.patch)、[全部文件校验和](./evidence/enhancement-quality-2026-10-12/manifest-sha256.json)。`traces/` 保存供应商请求与回答正文；各版本目录保存 `input.json → platform.json → copied.md → work.md` 及历史核对。登录凭据、环境值和运行时账号文件不归档。

## 2. 根因与已实施改动

| 问题 | 根因 | 本轮实现与边界 |
| --- | --- | --- |
| 收入被推成份额／需求 | 泛化的“区分事实和假设”没有约束具体推断关系；文末免责声明不能撤销前句断言 | 新增 `EvidenceInferenceContract`，区分来源事实、直接计算、条件候选及不可判断项，约束随生成和最终复制正文保留；确定的无证据收入跨指标断言在组装前拒绝，复用原有限修复。校验器仅覆盖已知高风险表达，**不是通用事实核验器**，不能证明所有行业、语言、年份／对象组合都已覆盖 |
| 充分性判断僵硬 | 原策略依赖中文关键词／标题，不能说明缺什么；策略只放在被视为资料的载荷中，执行优先级不足 | 同一次模型调用返回有界 `TaskEnhancementAssessment`：充分性、具体缺口、补全动作与依据、呈现方式；策略明确引用有效任务视图，并进入系统指导。充分需求保留原句，模糊需求给候选方法和适用条件；不新增独立模型调用。此判断仍来自增强模型，不能视为独立、已校准的语义裁判 |
| 专业建议又被退回问卷 | 科研指导把所有未给定设计细节都当作待确认参数；同一真实响应的 assessment 只列专业补全，ambiguities 却又把设计方法、评分等列为必须确认 | 修改科研画像，要求有依据的拟议主方案及适用条件。新增缺口／待确认一致性校验：需要补全但没有 USER_DECISION，却产生模型待确认项时，拒绝该矛盾响应并走原有限修复；不静默删问题，服务端发现的冲突与原始未决条件仍独立保留。这只是元数据一致性，不能证明模型分类全部正确 |
| 研究对象变成交付物 | 研究中出现“增强提示词”被误识别为最后要交付另一份提示词 | 修正 `DraftDeliveryContract` 的研究流程／最终交付识别，保护真正要求写提示词的任务；研究步骤可以描述增强流程，最终仍交付研究设计 |
| 问答被换成自规划 | 增强模型把 Plan 习惯性理解为先写执行计划；原文重述和尾注都未阻止错误操作化 | 针对明确用户问答的需求增加主体边界：增强器提问、用户回答、答案用于增强；生成前提供正向定义，组装拒绝已复现的“模型／研究者先写计划”替换。进一步明确直接增强不追问仍可使用已有答案，同信息对照不能换题、改单组答案或只增加某组修订轮次。显式自规划研究不受影响；窄校验不能覆盖所有改写，更不能控制外部执行模型 |
| 短任务强制多卡片 | 四要素内部结构与公开展示绑定 | 新增 `COMPACT/STRUCTURED`，翻译优先紧凑，其余结合任务画像和同次评估；四要素仍用于校验和编辑。复制、编辑、撤销及历史元数据保持呈现方式；旧记录缺省分节。**去标题不等于消除语义重复**，普通充分文本尚不能保证全部逐字保留 |
| 重复的平台规则 | 模型已有指导，平台又补一次；新推断标题被当成独立业务范围而保护重复句 | 合并本次完整等价平台规则，识别平台“推断依据”标题；具名对象、条件、例外、代码和表格继续保护。没有用相似度删除独立条件，开放表达的语义重复仍待处理 |
| 禁例失效 | “不加标题或示例”未被否定表达识别，反而被“输出…示例”误判为请求示例 | 修复 `ExampleContract` 中“不加／不添加／不举例”，覆盖开关开／关反例；最终翻译正文不再追加相反示例要求 |
| 篇幅约束漏识别 | “800至1200个汉字”中的“个”导致既有长度契约未生效 | 修复范围识别，保留字数与附表边界。不将组织建议升级为固定段数验收；实际作品仍有超长，不把解析修复等同于作品字数达标 |
| 正确结果被误拒绝 | “未使用假设数据”被局部解析为允许使用；部分坏 JSON／歧义类型缺少可修复原因 | 修正否定作用域及固定修复原因，保留“未使用…但可使用虚构数据”的拒绝；歧义仍必须为有界字符串数组，没有放宽结构契约 |

历史元数据增加 `promptFormat`。新增前向迁移 `V14__document_prompt_presentation_metadata.sql` 只更新 JSONB 字段注释，不改旧迁移或历史正文；本轮专用实例关闭 Flyway，**此迁移尚未执行**。

## 4. 两位独立盲评

两位评审是**独立 AI 辅助评审，不是人工专家**。每位仅看到原需求、资料、开关、随机 A/B 提示词及作品，不能访问源码、版本映射或另一位结果；分别评准确性、完整性、清晰度、可执行性，严重错误单列，最后再解盲。候选未成功交付按失败处理，不能补造作品。两轮候选各与同一基线对照，重复基线造成相关性，不宣称统计显著。

## 6. 用量、未完成项与放行决定

全程实际 DeepSeek 接口调用 **295 次**：增强160、下游135；Flash148、Pro147。含所有首次失败、修复候选与重试，全部留档；没有把中间失败剔出成本。供应商累计返回输入1,001,749、输出219,402、合计 **1,221,151 Token**。最终候选单独为256,824 Token。这些数值不包含开发及 AI 辅助评审的内部推理用量。没有已核对账单或价格，金额记为未知，不伪造人民币费用。请求上限由140、180、250调整为310的原因及范围记录在三个追加协议中；没有耗尽预算后挑选成功样本。

仍需继续的开发与验收：

1. **研究公平对照与任务主体保真**：本轮拦住明确的问答替换，但需覆盖开放改写、分组信息流、评审对象和同信息对照真正成立的条件；独立未知与合法候选继续区分。
2. **充分需求真正少改**：缺口判断已替换关键词计数，但模型自报“缺口”和实际新增指令仍需一致核对。Flash 将用户已委托执行者说明的随机化、评分等设计工作又判为提示词缺口；Pro 即使判为充分，仍会扩写普通自然段。应区分“需要执行的工作”与“缺少且影响执行的用户决定”。当前普通自然段仍依赖模型保留原句；确定性恢复仅覆盖可识别的完整四段结构，不冒称跨语言、跨格式已全面稳定。
3. **最终正文与内部四要素进一步解耦**：当前紧凑展示已打通，四段合并后仍可能重复。下一步核对每条执行要求的唯一责任位置与来源，在保留条件、例外及授权的前提下压缩；不能只继续隐藏标题或追加禁令。
4. **下游违约单列门禁**：额外数值例子、补造邮件职责、翻译截止范围和字数上下限违约不等同于平台已给错指令；分别检查提示词可执行性和执行模型表现。不能宣称平台可以控制任意外部 AI 永不违约，也不能用这一点免除作品验收。
5. **未覆盖组合**：本轮真实样例全部为直接增强、示例关闭；真实 Plan 确认会话、示例开启、多文件／长资料、多语言与行业迁移仍需独立验证。本轮单位回归不替代这些真实组合；没有人工领域专家验收。

**决定：保持整体上线门禁未通过。** 代码改动、有限链路通过和局部作品改善分别记录；ME-03／ME-04／ME-06 总项继续开放，不用平均分、HTTP 200 或静态构建替代用户要求的实际质量提升。
