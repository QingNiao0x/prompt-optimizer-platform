# 本地项目索引性能与清空测试

## 1. 测试目标

本测试用于确认以下行为：

1. 选择项目目录后，页面立即显示初始化或统计状态；
2. 索引阶段持续显示已处理文件数、总数、百分比、处理速度和预计剩余时间；
3. 大目录处理期间页面仍可滚动和输入，不出现长时间无响应；
4. 增量更新只重新解析新增或发生变化的文件；
5. 点击“清空”后页面状态立即清除，浏览器本地数据在后台完成删除；
6. 刷新、关闭或重新打开页面后，不恢复之前上传的单个文件或项目索引摘要；
7. IndexedDB 旧版本遗留的“当前项目”指针会被清理，不再把旧项目回填到左侧面板。

## 2. 自动化验证

在 `apps/web` 目录执行：

```powershell
npm.cmd run test
npm.cmd run test:e2e
npm.cmd run benchmark:index
npm.cmd run build
```

各命令用途：

- `test`：验证目录统计、有界并发、分块、增量索引、检索和清空状态职责；
- `test:e2e`：在 Chromium 中验证目录句柄、Worker、IndexedDB、进度交互、暂停继续、清空和页面重载后的状态隔离；
- `benchmark:index`：验证 100 万条未变化文件元数据的增量扫描循环不会出现明显退化；
- `build`：执行 TypeScript 类型检查并生成生产构建。

> 百万文件基准使用内存仓库和合成元数据，不代表真实磁盘与 IndexedDB 的最终耗时。它用于发现算法复杂度、批次查询和内存占用的明显回归。

## 3. 真实大项目手工测试

建议分别准备约 1 万、10 万和 16 万文件的项目目录。目录中可以包含 `node_modules`、`.git`、`target`、`dist` 和日志，用于验证忽略规则，但不要使用包含真实密钥或客户数据的项目作为测试样本。

操作步骤：

1. 使用 Edge 或 Chrome 打开工作台；
2. 点击“选择本地项目文件夹”；
3. 授权后观察页面是否立即显示“正在统计文件”；
4. 进入正式索引后记录总文件数、处理速度、预计剩余时间和完成耗时；
5. 索引期间尝试滚动页面、编辑原始提示词并切换页面，确认主线程没有明显卡顿；
6. 修改一个源文件、新增一个文件、删除一个文件，然后点击“增量更新”；
7. 核对页面显示的新增、更新、未变化和删除数量；
8. 点击“清空”，确认索引摘要和上下文文件立即从页面消失；
9. 打开开发者工具的 Application → IndexedDB，确认对应项目的数据最终被删除。
10. 重新上传一个普通文件或选择项目目录，刷新页面，确认左侧列表为空且没有错误提示。

## 5. 当前验收标准

- 授权目录后无需等待正文解析，先显示文件统计进度；
- 正式索引具有可计算的百分比、速度和预计剩余时间；
- 文件元数据读取并发数不超过 6，避免低性能设备上出现磁盘争用和内存突增；
- 每批最多累计 200 个文件记录、300 个代码块或约 4 MB 普通待写数据；
- 单个代码块最多保留 40 个检索词，降低 IndexedDB 多值索引的写放大；
- 点击“清空”后页面索引状态应在 1 秒内消失；物理删除失败时页面给出可操作提示；
- 页面刷新或重新打开后，普通上传文件和之前选择的项目索引摘要均不再显示；
- 真实 16 万文件和真实 IndexedDB 的性能数据必须单独记录，不能用合成百万文件基准代替。

## 6. 出现性能回退时的定位顺序

1. 先区分耗时发生在“统计文件”还是“建立索引”；
2. 再检查是否集中在某个超大源码文件、未知文本检测或代码分块；
3. 在 Application 面板查看 IndexedDB 占用和浏览器剩余配额；
4. 对比首次完整索引和第二次未改动的增量索引；
5. 如果页面状态已清空但磁盘删除仍慢，重点检查 IndexedDB 事务，而不是恢复逐条操作页面状态。
