# 扫描缓存与文档传输恢复

## 第五阶段

预统计收集有界轻量句柄清单，所有根目录共享最多50000条预算。完整清单在索引时消费，消费后释放；超过上限、扫描上限或暂停时回退原有流式遍历。清单固定本次枚举范围，新文件在下次刷新纳入。未缓存正文或全部File对象，getFile仍在消费时进行。

索引格式版本升至5，复用条件包含固定分段内容摘要、大小和修改时间。小文件复用已有预读字节，大文件使用256KiB分段摘要后汇总，以有界内存检查变化。同大小同时间正文变化会更新，旧版本首次刷新会重建，未变化的新版本复用已有分块和检索记录。过滤规则在每轮重新加载，完整扫描后才清理消失文件。

本轮大文件需要额外读取一次来完成缓存内容验证，首次导入及修改后的大文件可能因此增加读取耗时。指纹核验提供确定性失效保护，稳定提速尚未证明。后续可以在同一次流式解析中进一步融合摘要和暂存提交。

106项索引单测及Chrome五项真实Worker/工作台回归通过，包含同大小同时间变化、单次目录枚举复用、千文件长正文、进度及配额失败恢复。第六阶段已继续实施。

固定真实 API src 目录前后各一轮，1115文件、1113全文。两轮全文及尾部全部一致，1661片段、656109词关联和符号/引用摘要相同，代表路径查询全部命中。观察耗时15.182→14.250秒，单轮对照仅用于完整性与诊断，stableImprovement=false。目录供给等待约1186→428毫秒。最终增加单文件限制到缓存指纹，并避免为大型二进制计算全文摘要，相关48项索引器回归重新通过。该实测未重跑整项目目录，也未覆盖最终两项补充的性能收益。

## 第六阶段

服务端状态新增 receivedChunks，只在现有拥有者/工作区验证后返回落盘确认的零起始分片编号。前端每片传输退避重试耗尽后，只进行一次清单核对及缺失分片补传，核对路径、文件大小和分片大小。新旧响应兼容，缺少清单时仍按原失败路径处理。

当前页面多个文档共享最多三路分片请求，排队取消释放许可，退避期间不占用许可，失败等待兄弟请求退出再清理会话。最终网络失败返回中文重试说明。原分片大小继续由服务端协商。保留服务端512MiB/100文档准入和既有有限解析线程及阶段耗时日志。

恢复范围为本次上传操作中的临时网络故障，不支持刷新浏览器或重启服务后的跨会话续传。持续失败、身份错误和取消沿用清理策略，重新选择会重新上传。传输故障注入使用受控HTTP响应，未模拟真实公网故障或证明生产网络吞吐提升。

回归发现第三阶段把普通TXT参考材料误走源码入口，导致独立方案替换已有项目。已收窄为源码及工程配置使用项目索引，普通参考文档保持独立用途、确认上传及原项目共存。首次失败断言为方案文件未出现在材料列表，两条失败用例及原因记录在本报告。原始截图未另行备份，后续Playwright复跑可能覆盖；修复后原测试通过，未放宽原断言。

最终137项相关前端单测通过。Chrome五项验证普通文档上传、混合文件夹、源码与参考方案共同参与Plan/最终增强、千文件及工作台。Edge四项包括三次503后仅补传缺片并核对全部8字节，以及文档与Plan交互。后端45项通过，包含28项临时文档服务、2项控制器和15项复杂文档兼容测试，覆盖真实50MiB文本尾部、Office/PDF解析、乱序分片、不重复计数和权限。前端类型检查及生产构建通过，构建保留既有依赖注释与大产物警告。最后的摘要策略补充另经索引器48项及类型检查通过。

后端实测中50MiB夹具处理约6.9秒，主要耗时为提取阶段。这是本机夹具处理数据，不作为真实业务文档的速度保证。浏览器使用受控后端协议响应，Java测试使用真实本地解析与MockMvc，未启动生产后端、未调用付费模型。证据见 evidence/index-scan-cache-2026-11-18。

后续仍需整目录新版多轮验收、增量刷新实际耗时评测，若有跨刷新断点续传需求，应另设计用户身份、文件内容校验、分片保留与恢复入口。
