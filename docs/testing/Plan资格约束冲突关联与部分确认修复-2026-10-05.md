## 5. 首轮失败及新增发现

- R1 的法务结果把同一机构的审批金额和“退款标准尚未提供”构造成假冲突，退款提醒另有改写重复。补修未知取值排除及对象分组后，R4 没有该假冲突，剩余退款只显示一条。
- R2 地区 Plan 两次请求分别耗尽三次预算，返回 502／`RULE_CONFLICT`；拒绝字段含 `questions.hint` 和 `questions.options.recommendationReason`。没有保存拒绝草稿，不能断言每次都属于安全表述误拦。离线已复现并修复“仅符合条件的记录才可补值”“禁止用户选择”“不能直接被作为候选”等合法表述误拦。
- R3 接口成功但保留“提示地区无法核验，由用户自行决定是否继续确认”的不合格候选。新增明确反例及只读核对对照后，R4 三个选项均合规；不将 R3 的 HTTP 200 当作业务通过。
- R2／R3 医院状态提醒的完整技术代码曾因标点清理失去词边界。改为保留原分隔符核对后，另一医院及新增状态值仍独立保留，R4 同一状态缺口不再显示两条。
- **仍未修复**：R4 地区提醒改为“地区信息缺失、无法核验……的候选应如何处理，目前尚未决定（依据……）”，与绑定原题重复；长改写关联缺少完整语义身份，不扩大关键词删除范围来强行归并。
- **既有问题继续复现**：医院仍询问已知“共享未获批准”并提供“已获批准”选项；法务约束仍复制“当前尚未确认采用哪版”的旧状态；医院、法务分类仍为 TESTING／FEATURE_DEVELOPMENT。分别进入 NR-04、NR-05、NR-06。
- 医院直接增强的待确认列表为空，但正文仍完整写出乙医院格式、字段和状态缺口。上一轮同题的直接增强也为空，不能认定由本轮新增修复造成；正文与列表一致性仍应纳入后续验收。
