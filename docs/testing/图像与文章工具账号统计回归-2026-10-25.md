# 图像与文章工具账号统计回归（2026-10-25）

## 范围与口径

本轮补齐 `/image-to-prompt` 与 `/text-polish` 的登录账号操作采集与管理员展示。原有真实图像、文章 Provider 已接入匿名模型调用对账；本轮保留该链路，并补齐文章 Mock Provider 的对账记录。未新增页面访问采集、数据库迁移、生产配置或模型付费调用。

| 审计事件 | 采集点 | 计数含义 |
| --- | --- | --- |
| `IMAGE_PROMPT_SUBMITTED` | 图像还原、计划准备、确认生成、历史再次优化的幂等预留及输入/资源校验通过后、模型调用前 | 新操作提交尝试，包含后续失败；一个新计划再确认生成对应两次提交 |
| `IMAGE_PROMPT_PLAN_CREATED` | 有效计划已保存到私有短期状态后 | 计划问题生成事实，不算最终提示词结果 |
| `IMAGE_PROMPT_GENERATED` | 有效提示词生成且完成状态可恢复后 | 最终提示词结果，包含历史暂未保存的可恢复结果 |
| `TEXT_POLISH_SUBMITTED` | 新原文、原文重生或当前稿继续润色通过来源/模型校验及幂等预留后 | 新操作提交尝试，包含后续失败 |
| `TEXT_POLISH_GENERATED` | 结果通过事实保护校验、来源复核且完成状态可恢复后 | 有效润色结果，包含历史暂未保存的可恢复结果 |

账号身份取自 `CurrentActor`，包含管理员；访客试用不产生上述账号事件。浏览器不另外上报生成次数，已有请求 UUID 由服务端用于去重。稳定事件 UUID 包含固定命名空间、租户、工作区、账号、事件类型与操作 UUID；原始操作 UUID 和任何正文不写入审计明细或指标标签。

相同请求重放、模型内部协议修复、查询结果、补存历史均不增加业务提交/生成次数。新的显式操作使用新的请求 UUID。取消或断开浏览器连接本身不回滚服务端已发生的事实；最终完成以服务端有效结果为准。生成失败保留提交，不产生生成事件；历史写入失败但正文可恢复时仍计生成结果。

提交和生成各按自己的 UTC 发生时刻、仪表盘统计时区和左闭右开时间区间查询，可能跨日。因此不能用某日“生成数 ÷ 提交数”推断当日提交成功率。

## 查询与展示

`GET /api/v1/admin/analytics/dashboard` 增加 `toolUsage`，包含四个非负整数：

```json
{
  "toolUsage": {
    "imagePromptSubmittedCount": 2,
    "imagePromptGeneratedCount": 1,
    "textPolishSubmittedCount": 1,
    "textPolishGeneratedCount": 1
  }
}
```

示例表示一次图像计划准备及确认生成、一次文章润色。仪表盘新增四张指标卡，与现有时间、账号 ID、登录邮箱和显示名称筛选一致；操作日志新增五类中文筛选。账号使用排行、实际使用账号、小时/月操作量只加入两个提交事件，结果和图像计划生成不再重复累加操作次数；所有新账号事实均参与活跃统计。旧直接增强和 Plan 完成指标不混入这两个独立工具。

聚合 SQL 使用 MyBatis XML 参数绑定、同一只读快照和账号筛选；邮箱身份以 `EXISTS` / `IN` 匹配，多个邮箱不放大计数。工具汇总单独扫描四种事件，空区间返回四个零，不读取完整 `details`、正文或历史表。此功能不推算上线前缺失的工具事件。

查询仍限平台管理员，未登录 `401`，普通用户 `403`。浏览器事件白名单保持原范围，不能伪造上述五种服务端事件。模型对账仍只归属租户，`actor_user_id` 为空，Token 数据不复制进账号操作事件。

页面访问继续停用：不采集、不写 journal、不入库、不进入统计和操作日志。`APP_VISIT` 仅保留旧协议/journal 解码兼容；旧页面统计响应字段保持零。

## 可靠性与隐私

新事实复用现有持久 journal、独立入库事务、数据库主键幂等与失败恢复；永久统计以数据库为准，异步补写期间页面保留积压提示，补写后查询刷新。IP/会话等可选元数据异常时降级为空元数据，仍可靠投递已确认的账号事实。审计异常使用稳定事件代码和安全异常类别诊断，不回显正文、图片或凭据。

未新建 Redis 缓存；沿用图像计划 1 小时、操作结果 24 小时的短期私有状态 TTL。持久审计明细不自动清理。数据库 `audit_event.event_type` 为模块定义的字符串，无数据库 CHECK 枚举，本轮无需变更表结构或回改 Flyway。

## 本轮验证证据

- 后端最终各类 Surefire 报告合计 168 项：165 通过、3 项专用 Redis 试用测试未启用，失败和错误均为零。结果为本轮各受影响批次及修正后定向重跑的合并，不将重复运行累加为新测试。
- `AnalyticsClientEventServiceTest`：稳定事件主键、账号/租户/工作区隔离、元数据白名单、非 HTTP 调用、元数据故障仍投递、异常不阻断主业务、页面及非法事件拒绝。
- `ImagePromptServiceTest`、`TextPolishServiceTest`：计划与最终结果分开、直接还原和再次优化、原文/当前稿来源、模型失败和无效结果、重复请求、状态恢复、历史保存失败与补存、访客不计入账号数据。
- 两个 OpenAI 兼容 Provider 的本地受控 HTTP 测试：成功、协议修复逐次审计、截断/超时/锁定内容失败、失败响应已报告的 Token 保留；不向实际模型发送请求。文章 Mock 对账验证独立事件 ID、`mock=true` 和未知 Token，不伪造零用量。
- `AdminAnalyticsAggregationRegressionTest`：真实 PostgreSQL 的重复写入、空数据、多租户与管理员账号、ID/邮箱/名称组合筛选、跨日完成、左闭右开边界、上海与纽约夏令时；新结果事实不放大排行榜或小时/月操作量。
- `AnalyticsLocalDatabaseAcceptanceTest`：真实 BCrypt/会话登录 → 图像计划/确认与文章润色 → PostgreSQL 审计 → 管理员 API；图像提交 2 / 生成 1，文章提交 1 / 生成 1；重放、状态查询及补存后不变。模型对账恰为 3 条匿名 Mock 记录，权限 `401/403` 和页面事件不入库通过。此测试显式使用内存短期状态，Mock 模型准入为测试替身；审计写入使用事务内适配器，夹具全部回滚，不代替真实 Redis、异步投递或浏览器全链路验收。
- 模型对账数据库测试通过显式 `-Dmodel.reconciliation.database-test=true` 启用，3 项真实 PostgreSQL 聚合通过；审计持久投递故障恢复 18 项回归通过。
- 前端单测 44 项通过，覆盖统计队列/页面访问停用、展示转换和两个工具 store；TypeScript 类型检查、Vite 构建通过。
- Chrome 布局/筛选/投递提示共 40 个场景完成：首轮 38 通过，空数据断言因新增四张卡片需从 7 改为 11，修正后桌面与手机 2 项重跑通过。包含中文新事件筛选、账号条件透传、页面不上报事件，以及 1920/1440/1024/768/390/320 宽度和主题切换。浏览器用例使用模拟 API，不替代完整服务链路。
