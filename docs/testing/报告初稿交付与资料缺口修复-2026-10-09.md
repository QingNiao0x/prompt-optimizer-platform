# 报告初稿交付与资料缺口修复

日期：2026-10-09。范围：直接增强把“撰写报告”降为分析方案、补材料问卷或大片空模板的问题，以及共享链路兼容性。本轮不处理登录、统计日志、数据库或 TokenHub。

## 1. 问题与处理原则

截图原文为“我想要撰写2015-2025年某地区心脑血管疾病死亡率特征分析”，列出趋势、分组、YLL 和 Arriaga 四个方向。按截图转录为 141 字符；未额外给原例追加“先交报告”、篇幅、数据或答案。

问题不能归咎于用户没有一次给齐所有参数。优化器应保留写作目标，帮助组织任务；资料不全只影响依赖它的事实、数值与实证结论，不应阻断整份初稿。常规组织和有适用条件的方法建议可以由执行者完成，建议不得冒充用户确认。

没有真实数据时不能交付已完成统计计算的实证报告，但可以交付背景、方法说明、结果边界、讨论、局限与结论均连贯的可修订初稿。要求只写方案、先问再写、禁止占位等明确限制仍优先。

## 2. 代码定位与修复

## 5. 剩余问题与归因

1. **平台仍需精简。** 模型在不同段落仍会复述资料缺口；确定整行去重不能覆盖所有开放改写。普通缺资料提示与真正的执行前业务决定需要继续区分，不能简单清空所有提醒。
2. **下游仍会扩写未给事实。** 最终机关报告的优化提示词准确保留台账三项问题并禁止虚构既有成效，作品却增加“部分居民反映参与不便”“两个点位到场人次存在差距”等材料外陈述。原始组也有事实扩写；必须保留失败，不把它归为平台已知事实。
3. **专业假设仍可能被执行模型写成已定。** 原例最终作品直接采用“常住人口”作为研究总体，原需求没有确认这个范围；优化正文要求专业建议标前提，仍不足以保证下游遵守。未进行医学方法正确性认证。
4. **篇幅没有闭合。** R2、R3 等作品仍存在超出目标范围的风险；整份字符计数包括标题、附录等，不能直接代替正文验收。代码任务继续单列完整交付与运行验证，本轮没有把生成脚本运行成功当作已完成事实。
5. **完整流程仍待验。** 此轮只验证真实组件链和下游作品，未做新一轮正常账号、文件夹上传、浏览器复制、历史编辑和多模型回归。此前动态约束通过的范围不能自动替代这一轮的完整流程验收。

因此，本轮交付是已实施并复验的机制修正，**不是“所有报告无需数据即可成稿”“所有专业场景已解决”或上线放行**。下一步应优先减少普通资料提示对正文的干扰，再用新样例复核已知资料扩写及最终正文的实际可用性；不通过放松事实边界或删除独立冲突来缩短文字。
