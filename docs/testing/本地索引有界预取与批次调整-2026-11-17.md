# 本地索引有界预取与批次调整

日期为 2026-11-17，基线提交为 `50c8347e`。本轮按用户批准的第二优先级实施读取与写入重叠、批次调整和提交进度保护。

## 实现范围

- 在每组最多 200 个来源文件的处理过程中，当前六份小文件交给分块及写入消费前，启动下一组六份文件的读取。每份不超过 64 KiB，预取字节最多 384 KiB，当前组加预取组最多 768 KiB。上限仅指这两组字节缓冲，不代表整个 Worker 的堆内存。
- 保持一个串行写入调用链。大文件继续流式读取，未变化文件、受保护文件及排除路径继续在小文件预读前检查。目录扫描、来源批次边界及增量元数据查询仍沿用现有流程，本轮未实现整个目录扫描与数据库写入的流水重叠。
- 以成功的数据批次提交耗时反馈后续批次规模。初始保留 200 文件、300 片段、4 MiB 估算数据、64,000 词关联上限。连续两次数据提交超过 1,000 ms 缩小一半，低于 250 ms 时恢复原上限的 12.5%，下限为原上限的 25%。阈值是本轮初始工程参数，尚未证明适合所有硬件。
- 空检查点只计时，不参与批次规模调节，避免它的快速提交抵消上一批慢写入的反馈。正文和词表仍完整保存，阈值检查允许当前完整片段的余量。
- 已完成文件数、分类计数、百分比及吞吐以成功提交的检查点为依据，读取和预取不会提前算作完成。发现数及当前读取字节仍提供过程反馈，最后完成须等待最终状态提交。
- 观察到暂停后锁定暂停状态，丢弃未消费的预取结果，保存已完成文件检查点。已启动的文件读取可自然结束，其结果不再转为新的正文写入。恢复继续复用已提交文件。

## 验证与问题修复

63 项相关单元测试通过，包含新增的重叠、暂停和自适应批次检查。重叠用例让下一组六份文件的读取等待写入开始，证明读取完成确实发生于写入等待期间；核对读取并发不超过六、预取领先量有界、暂停后的迟到结果不追加记录，恢复后 100 文件正文完整。慢写入夹具验证后续批次缩小、快速提交逐步恢复，以及写入最大并发为一。

初版反馈策略在单次提交超过 500 ms 时立即减半，Edge 真实对照中调用从基线 21 次增至候选 33/29 次，未证明吞吐收益。最终策略改为连续两次超过一秒才缩小，以避免偶发抖动过度拆批。初版数据保留。

旧进度测试曾将读取完成视为处理完成，本轮改为核对已提交文件数，同时继续检查读取期间的发现数更新。旧暂停夹具按回调调用次数触发，改为在实际提交 200 文件后触发，以适配预取中的多次状态检查，继续核对恢复复用 200 文件。测试曾发现空检查点使缩小后的批次立即恢复，已经修复并由回归锁定。

Chrome 与 Edge 的存储、恢复、进度、隔离及多根暂停恢复检查各 11 项通过。覆盖多根真实 Worker 暂停后 600 文件的全文及尾部一致、复用实际已提交数量、真实 Worker 的百分比及增量更新、配额异常恢复、旧库迁移、全文词表、稀疏覆盖和提交回滚。工作台身份及业务 HTTP 响应采用受控夹具，Worker 和浏览器存储使用生产实现。类型检查与前端生产构建通过，构建仍提示既有依赖注释和大于 500 kB 的产物。

## 性能证据

初版性能结果按同一冻结 622 文件、8,397,198 字节输入，在两个浏览器中各执行基线→候选→候选→基线。最终参数复验使用同输入，Chrome 按基线→候选，Edge 按候选→基线执行，各一对。索引计时使用真实生产引擎与浏览器数据库。完整性校验在计时之外完成，正文、尾部、全部检索词、符号、导入信息分别核对。

[原始对照、测量包与来源记录](./evidence/index-overlap-2026-11-17/)保留两版全部结果，合计 12 轮。初版 Chrome 基线 6.011 / 12.109 秒，候选 5.166 / 11.712 秒；Edge 基线 6.135 / 11.968 秒，候选 12.932 / 11.995 秒。初版未证明稳定收益，调节条件已收紧。

全部 12 轮均为 622 个完整文件、800 个片段、4,779,107 个字符，失败数为零，全文与尾部均 622/622，完整规范化摘要均为 `5a7c3a24602b66f3b1e1254b870c20b11b3f2572b209742d9c429978837c0c38`。Chrome 在每轮校验后删除项目，最终 Edge 在临时浏览器结束时整体清理，均使用独立项目，只在各自浏览器内部比较。

最终参数减少了本次观察到的过度拆批。最终每个浏览器仅一对，且初版多轮已显示明显波动，单对照较大的耗时差异仍不能作为稳定提速幅度。初版测量期间有一次短单测与构建测量包操作，最终四轮期间未并行执行本任务构建和浏览器回归。样本由内存 File 提供，尚未覆盖原生目录遍历、用户磁盘读取或用户真实大目录。

采用范围为有界预取、保守批次调节、提交进度与暂停保护的工程实现，受影响功能检查通过。大目录稳定性能继续保持待验收。

## 后续待验收

真实用户大目录首次导入、原生文件夹遍历及磁盘读取尚需独立对照。小样本结果不能关闭大目录慢问题，也不能作为跨设备性能保证。后续按真实提交耗时和事务数量评估参数，不直接增加读写并发。
