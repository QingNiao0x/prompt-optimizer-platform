# 直接增强的任务／约束分离与输出保真修复

日期：2026-10-19。范围为本次两项直接增强缺陷；保留 Plan、安全、权限、原始输入及优化记录的现有契约。最终产品提交为 `435dacc9`，初版为 `1f4a8838`。

## 结论与证据边界

- 已修复原题“请帮我查询全球使用AI最多的职业/行业”因“最多”被识别为硬限制、再次投影到约束的问题。
- 增加显式输出声明的来源保护。模型遗漏明确要求的表格、字段、口径与格式时，平台补回输出部分；不凭主题添加字段或把交付降成约束。
- 真实复验发现初版把“输出要求：”标签也作为正文比较，造成完整声明重复补入；普通去重又拆碎补回块，随后触发恢复。已用第488次模型段落原件建立失败回放并修正。最终490中，完整输出声明在 OUTPUT 内仅一次，所有明确字段保留，复制／API／历史一致。
- **不声称整体增强质量已通过。** 模型仍跨节复述，最终响应仍有空泛背景与不够合适的口径候选。初版复制正文的实际作品发生跨样本排序违约；最终版本未新增作品或双评审，这些失败及旧门禁继续保留。

截图中的原始提示词只有一句话，未明确指定“排名表”；数据来源、统计口径在截图结果中仍存在。因此不能把缺少强制排名表直接判成“删除了原文已有要求”。本轮分别核验原题与明确增加输出声明的输入，不把两题混为同信息作品对照，也不借此统计产品胜率。

## 根因和代码路径

### 原任务误入约束

`RequirementFidelityGuard.collect` 原先把任意含“最多”的句子提取为完整明确规则。`BoundRequirementProjection.entries` 将其注册为 CONSTRAINTS 来源引用；`OptimizationResultAssembler` 展开引用或在缺少引用时保守补回。因此模型已经改写任务后，平台仍把整句原题再次放进约束。

修复在规则识别入口区分相对比较“最多的对象”和上限，不增加行业／职业关键词。符号、关系、时间和名词赋值上限仍保留，例如 `最多提交limit份报告`、`最多消耗剩余额度的一半`、`最多运行到用户指定的截止时间`、`最多的请求次数：MAX_REQUESTS`。含真实禁令的复合原句继续整体保护；不为减少文字而拆掉对象、条件、否定或例外。

这是一项有限语法修复，不宣称能够自动理解全部自然语言。来源保留与最终事实／规则校验未取消。

### 明确输出要求缺少确定性保护

真实 Provider 的 `rawPrompt` 与 `EffectiveTaskView.effectivePrompt` 没有在本题中截断或丢字段。四次增强上游载荷均逐字符合冻结原题，见 [请求范围](./evidence/me02-candidate44-direct-contract-2026-10-19/request-scope/490.json)。已有补回机制集中处理显式规则、Plan 决定和未决信息；普通交付声明可能既不含规则触发词，也不产生 Plan 决定，模型遗漏后缺少确定性兜底。

新增 `ExplicitOutputRequirements`，识别用户明示的“输出／输出要求／期望输出／交付／交付要求”块，原样保留字段、条件、嵌套标题、JSON／代码及顺序。没有显式声明时不强加排名表或通用字段。参考资料、原文、示例、输入、翻译材料及未来条件不升级成当前交付；凭据与越权内容复用既有保护。

声明进入同一 `BoundRequirementProjection`，目的段为 OUTPUT；模型使用合法引用时由服务端展开，未使用或遗漏时由组装器补回。输出块中的原规则沿用同一覆盖记录，不再另抄到约束。原始提示词、全部来源及历史原文仍保留。

### 第488次暴露的重复与最终修复

488模型 OUTPUT 已完整写出用户要求的正文，只省略“输出要求：”标签。初版把带标签的来源与无标签正文比较，误认为缺失并补入。随后 `ExecutionRuleCompactor` 按句去重，可能移除补回块的一部分；最终保真检查又补一遍完整块，形成新增重复。这属于本轮初版的平台缺陷，不能归咎下游。

最终实现将来源标签与正文分开：标签只用于识别职责，引用及覆盖比较使用完整正文。多句正文通过现有独立引用作用域校验整体核对，不把逐句拆分后的片段冒充整块证据。普通去重只保护完整已知输出来源所覆盖的行，不把用户内容用作删除字典，也不扩大删除范围。缺项补回放在输出开头，避免继承模型后续未知标题或条件范围。

修复涉及 `RequirementFidelityGuard`、`BoundRequirementProjection`、`ExplicitOutputRequirements`、`OptimizationResultAssembler` 和 `ExecutionRuleCompactor`；没有改写任务模板、增加重试次数或另建模型链路。

`MockPromptEnhancementProvider` 仍将完整有效原文放入 TASK，默认 OUTPUT 使用模板指导。它本身没有删除排名表或来源字段；截图也明确为真实 DeepSeek，不能归因 Mock。新保护在公共组装器执行，Mock 对应的字段保真测试已通过。本轮没有修改 Mock 路由或让真实调用失败后切回 Mock。
