# 直接增强与 Plan 使用次数追踪

## 本次实现与统计口径

本次在既有可靠审计投递、管理员查询和统计页上增加细分计数；充值继续延期。原有通用优化提交、上下文、登录与访问事件继续保留，没有数据库结构迁移，也没有反推旧事件的使用路径。

| 事件 | 何时计一次 | 时间归属 | 去重与失败边界 |
| --- | --- | --- | --- |
| `DIRECT_OPTIMIZATION_SUBMITTED` | 通过认证、CSRF 与请求参数校验的直接增强提交，包括工作台、结果再次增强、历史再次优化 | 服务端 UTC 提交时刻，与原 `OPTIMIZATION_SUBMITTED` 相同 | 每次提交计一次；后续生成失败仍计数，Provider 内部重试不增加提交事件 |
| `PLAN_COMPLETED` | 有效 Plan 最终生成成功，且优化历史保存成功 | 服务端 UTC 完成时刻 | 固定命名空间、租户、账号、规范化 Plan UUID 派生事件主键；同一计划并发、重试和恢复重放只保存一条 |

全部登录账号（包含平台管理员）参与统计。创建计划、准备上下文、确认答案、取消或过期本身不增加 Plan 完成次数；无文件、零问题计划最终成功时也计一次。

### 数据与可靠性边界

- 服务端从 `CurrentActor` 派生租户与账号归属；客户端上报仍只允许页面访问和结果导出，不能伪造新增事件。
- 新增明细使用原有元数据白名单，包含审计关联、IP、可空所在地与设备，不包含原始提示词、答案、文件正文或原始 Plan ID。
- 事件先进入不可变文件 journal，再由 `AuditEventDatabaseWriter` 在 `REQUIRES_NEW` 事务中参数化写入 PostgreSQL；`ON CONFLICT (id) DO NOTHING` 防止补写重复。
- `optimization.feature.uses` 只有一个 `event` 标签，预注册上述两个固定代码。首次插入且事务提交后才增加运行期计数；回滚、零行重放不计数。计数器异常只输出安全事件代码、requestId 和异常类型，不阻断审计确认。
- Micrometer 是运行期观测，重启后可重置，也可能因遥测故障缺少增量；管理员永久统计以审计数据库为准。
- 统计和原始审计明细继续永久保留。双存储同时失败的既有告警边界保留，本次不宣称零丢失或完成生产灾备验收。

## API 与页面

`GET /api/v1/admin/analytics/dashboard` 的顶层及 `dailyMetrics[]` 均增加非负整数 `directEnhancementCount`、`planCompletedCount`，空日为零。原时间、账号 ID、邮箱及名称筛选继续生效。查询沿用管理员权限：未登录 401，普通用户 403。

融合 SQL 复用既有原始表扫描、统计时区及左闭右开区间，仅增加两个事件标记和日计数。组装器校验非负、溢出、日期骨架和日合计／总量一致性。原六类关键操作集合不增加细分事件，因此排行榜、小时和月份操作数不会被重复放大；任一事件仍构成活跃行为。

管理员页面增加两张指标卡及每日双序列 ECharts 折线图，新增事件的操作筛选与日志名称使用中文。页面明确提示：细分次数自功能启用后记录，旧通用优化记录无法区分路径。延续已有主题、加载、空状态、失败恢复及响应式布局。

## 验证方式

本轮验证结果以同目录下的 [验收摘要](./evidence/analytics-feature-usage-2026-10-06/acceptance-summary.json) 为准。关键测试入口：

| 验证项 | 2026-10-06 本轮结果 |
| --- | --- |
| 后端相关回归 | 26 个测试类、210 个用例：208 通过，2 个按开关跳过；跳过的真实浏览器及性能用例已分别启用并通过 |
| 前端单元测试 | 23 个文件、124 个用例全部通过 |
| 类型检查及构建 | `vue-tsc` 与 Vite 构建通过；保留现有大包体积提示，没有升级依赖 |
| 统计页浏览器回归 | 桌面及手机 Chrome 项目共 34 个用例通过，覆盖桌面、平板及手机宽度 |
| 真实本地链路 | 最终直接增强 3 次、Plan 完成 2 次；同一计划四次重复生成均为 200，完成数仍为 1；数据库、API、卡片、图表及运行期计数校验通过，测试数据回滚无残留 |
| 性能 | PostgreSQL 16.14；每次查询可见 10 万合成事件，单路仪表盘 p95 1029.91 ms，四路同步并发各路 p95 1498.08–1765.25 ms，均低于 2000 ms，查询错误为 0 |

性能目标仅针对仪表盘应用服务查询，报告中的八组独立查询组合耗时不是该目标。四个并发连接分别使用隔离且未提交的合成夹具；本轮没有验证共享已提交数据下的写入竞争或生产容量。

- `AnalyticsEventServiceTest`：通用／直接事件时刻一致、服务端归属、稳定主键、计划 UUID 校验及敏感字段排除。
- `PlanQualityMetricsImplTest`、`AuditEventDatabaseWriterTest`：有界标签、首次提交、重复投递、回滚、提交失败、遥测失败诊断。
- `AuditEventDeliveryTest`：四线程重复接收、数据库故障、确认失败及新投递器恢复后只保留一次 Plan 完成事实。此处 writer 为替身，真实数据库主键行为由数据库回归另验。
- `OptimizationControllerTest`：直接成功或失败均采集提交，Plan 仅在生成及历史保存成功后采集完成；非法请求不采集。
- `AnalyticsLocalDatabaseAcceptanceTest`：真实 PostgreSQL／认证／Controller 链路、无文件零问题、伪造／跨账号拒绝、同计划重复完成、新计划另计、六种时间范围及历史再次优化；夹具事务回滚。
- `AdminAnalyticsAggregationRegressionTest`：多租户、匿名排除、邮箱／名称交集、边界、跨日完成、夏令时重复小时、空日、主键去重、融合与独立查询全等，以及旧操作维度不放大。
- `PlanningSessionServiceTest`：计划所有权、过期、绑定答案及上下文版本校验继续回归。
- `analyticsPresentation.test.ts` 与统计页 Playwright：两个序列的数据、单日点、空日、中文筛选、卡片、主题切换及 1920／1440／1024／768／390／320 宽度。
- `AnalyticsRealBrowserAcceptanceTest` 与 `scripts/analytics-real-browser-acceptance.mjs`：真实 Chrome、Vite 代理、Spring Boot、Redis 和 PostgreSQL；使用 Mock Provider 完成取消、逐题确认、最终生成、两路并发重复生成两轮、零问题计划及历史再次优化，对照 DB／API／卡片／图表与运行期计数。
- `AnalyticsPerformanceAcceptanceTest`：每个读者可见 10 万条合成事件（包含新增代码）、4 路预热后同步查询、365 自然日；仪表盘 p95 ≤ 2 秒、查询错误为零，并检查夹具全部回滚。

## 可复跑命令与限制

从 `services/api` 使用项目 Maven settings，所有数据库验收关闭 Flyway；先启动已有本地 PostgreSQL 和 Redis。禁止为测试读取 `.env`、密钥或生产配置。

```powershell
$env:MAVEN_OPTS = '-Xmx256m -XX:MaxMetaspaceSize=192m -XX:ActiveProcessorCount=2'
mvn -s ..\..\.mvn\settings.xml '-Dspring.flyway.enabled=false' '-Dtest=com.promptoptimizer.analytics.**.*Test,PlanQualityMetricsImplTest,OptimizationControllerTest,OptimizationHistoryControllerTest,PlanningSessionServiceTest,DefaultEnhancementOrchestratorTest,MybatisOptimizationHistoryServiceTest,OptimizationRecordScopeDatabaseTest' '-DargLine=-Xmx384m -XX:MaxMetaspaceSize=256m -XX:ActiveProcessorCount=2' test
mvn -s ..\..\.mvn\settings.xml '-Dspring.flyway.enabled=false' '-Danalytics.browser.enabled=true' '-Dtest=AnalyticsRealBrowserAcceptanceTest' '-DargLine=-Xmx384m -XX:MaxMetaspaceSize=256m -XX:ActiveProcessorCount=2 -Djdk.net.unixdomain.tmpdir=E:\MyProject\prompt-optimizer-platform\tmp' test
mvn -s ..\..\.mvn\settings.xml '-Dspring.flyway.enabled=false' '-Danalytics.performance.enabled=true' '-Dtest=AnalyticsPerformanceAcceptanceTest' '-DargLine=-Xmx384m -XX:MaxMetaspaceSize=256m -XX:ActiveProcessorCount=4' test
```

从 `apps/web` 执行 `npm.cmd test`、`npm.cmd run build`，再设置 `PROMPT_OPTIMIZER_E2E_PORT=5193` 并运行三份统计页用例：`analytics-layout.spec.ts`、`analytics-delivery-status.spec.ts`、`analytics-pagination.spec.ts`。浏览器验收与性能采样分开执行，避免本机资源争用。

真实浏览器验收使用测试专用共享外层数据库事务，实际 SQL 执行，但物理 commit 被包装阻止，最后核对回滚；它不证明断电持久化、跨实例部署或生产容量。运行期指标提交回调另有受控事务测试。手机为 Chrome 设备模拟，GeoIP 仅验收不可用时保留 null，未验真实城市库、生产代理、真实 AI Provider 或生产发布。
