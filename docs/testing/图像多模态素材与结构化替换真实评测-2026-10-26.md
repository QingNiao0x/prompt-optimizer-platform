## 共用机制修复

1. ANALYZE 使用独立来源指导与载荷，不发送创作构想、指定文案、上下文、替换关系或题答；后续 Plan 不把新创作要求并回源观察。
2. 附录仅列素材、选择范围、遮挡与实际回答，不机械拼回原始关系。历史把原卡明确标为初始要求；同一事项以实际确认和当前正文为准，未修改的独立要求继续有效。
3. masks 是隐私处理元数据，不是原设计；不采用“删掉所有黑色元素”的词面规则，真实未遮挡深色元素仍可借鉴。
4. `Document.evidenceWarnings` 独立随现有 JSON 历史持久化，编辑、撤销与修订均保留，并进入生成／修订上下文。旧 JSON 缺字段或 null 只恢复可确定来源风险；显式空数组保持为空。
5. `batchCoverage` 区分任务选中单位和本批单位。视频的解析预览总数、任务选中数量和模型单批数量分别说明；不因批次大小推断全任务缺口。

## 保留的失败、局限与工具归因

- **来源判断尚不稳定**：C01 把 768×512 横图判断成竖图；M02 把页脚的坐标误归给表格，最终提示词未采用错误表格坐标。解析器当时没有提供表格坐标，模型错误绑定了相邻文本框信息，不能声称精确元素定位已验收。
- **提问仍有冗余**：C01 对已委托装饰继续必问；M01 来源分析因看不到创作关系而写“未提供组合关系”，不能把来源识别阶段的局部未知当整个任务缺口。v6 批次范围改善，但重复风险提示、内部来源 ID 和不必要的无音轨说明仍影响可读性，未以新增词面过滤掩盖。
- **旧风险只能有限恢复**：v6 之前的记录及原单次识别兼提问 Plan 没有独立风险字段，混合 warnings 无法可靠区分来源风险与旧待答状态。原记录不改写，不能保证所有旧 warning-only 风险都无损恢复。
- **复制核验**：phase2 两次严格字符比较为 false，原判据和结果保留。零模型调用诊断确认 DOM／历史、原生 writeText 参数逐字一致，写入成功；读取长度 388→396，仅 CRLF→LF 后完全相同，证据支持本机 Windows 换行转换，未发现正文删改，不修改产品复制逻辑。
- **评测脚本错误**：phase3 的 Node 会话在冻结前启动，未重载冻结时更新的 R02 本地来源守卫。该守卫在 reserve／外发前拒绝 R02，未新增调用；原脚本差异与失败记录保留。关闭后重载已封存脚本，只执行原定 R02 一次，没有重跑 M03；此前 4 次仍计入总账。
- **使用边界**：短视频只验证采样帧，不理解音轨或完整连续运动；PPTX 是静态可见页与有界结构文本，不承诺字体、复杂图形、动画与 PowerPoint 像素一致。没有自动识别／遮挡所有敏感信息，外发前仍需用户审阅和明确同意。
- **验收边界**：本轮不生成下游图片、视频或 PPT 成品，不能据此声称替换精度、逐字成图或成品可编辑性已由下游验证；也未完成其他视觉模型、照片、模糊小字和专业材料的系统评测。
