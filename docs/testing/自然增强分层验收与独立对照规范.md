# 自然增强分层验收与独立对照规范

本规范用于自然增强与 Plan 的开发验证和候选选择。执行前读取 [AGENTS.md](../../AGENTS.md) 的授权、预算与停止条件；产品边界及正式发布门禁见[主方案](../14-提示词增强与Plan最小干预优化方案.md#acceptance)。本规范不改变已冻结的历史协议、评分或失败结论，也不代表当前候选已通过。

## 1. 先确定要完成哪一层

| 层次 | 完成证据 | 不能据此声称 |
| --- | --- | --- |
| 工程完成 | 修改落实到目标路径，受影响测试和必要集成检查通过，保留来源、题答、条件、权限及历史兼容；未验证项列明 | 模型语义已正确、提示词质量提高或候选已上线 |
| 候选采用 | 工程修复证明目标故障消失、受影响路径无新增严重退步，可独立采用；正文策略证明同信息实际作品有目标收益且无新增严重退步。两者均须处置相关已知失败，记录成本及采用范围 | 工程修复自动证明正文收益，或所有职业、措辞、模型和场景均有效 |
| 正式发布 | 按拟开放模型／能力执行主方案 G1—G8，部署与回退可审查，并取得发布授权 | 局部候选通过即可绕过身份、安全、浏览器或发布检查 |

报告分别给出三层状态。工程修复通过后可以独立收口、独立采用，不必等待整体作品优于旧版；采用仍须记录实际启用位置和回滚办法。若修复同时夹带新的正文策略，应拆分变更验证，或按全部目标验收整个候选。未采用、撤回、未验证和延期分别记录；充分需求少改或不改可计为保真通过或持平，不计为实质增强收益。

MVP 每轮事先声明主要任务、模型、上下文来源、Plan 路径及交付边界，用代表性真实需求验证该范围。新增跨领域或多模型承诺时扩展对应发布矩阵，不把全矩阵用作每次小修前置条件。身份、安全、用户明确硬约束及复制／历史一致性继续强制检查；缩小已承诺能力须明确同步产品说明，不能默默关闭现有能力。

## 2. 按假设冻结指标，不给所有改动套同一胜率

每个候选先写一个可证伪假设、影响路径、对照版本和判据，再生成结果。阈值、样本量和允许的设计空间写在该批协议；历史“六题至少三胜”等条件只约束原批次，不自动推广到别的修复，也不事后回改旧批次。

| 修改目标 | 主判据与必要证据 | 共同回归 |
| --- | --- | --- |
| 生成门控／材料承载／状态表达 | 已知失败能够复现；修复后合法请求执行应有阶段，正文不再堆贴无关材料，状态准确反映实际处理；核对页面、复制和历史。故障消失就是本项工程收益 | 阅读等待、明确报告／复述、充分需求、材料缺失及 Plan 已回答按受影响范围验证；不能用调用成功替代交付检查 |
| 响应协议／解析 | 首次有效率、最终交付率、误拒／错误放行、协议修复次数；用保存的合法与非法原件检查受影响阶段，必要时做真实定向调用。服务端已知元数据的归属调整不得丢失原始来源、实际题答和正文覆盖 | 正文、复制及历史一致；来源／阶段语义仍受保护。仅 HTTP 200 或减少必填字段不能算修复收益 |
| 实质补全 | 以任务完成情况、严重错误和用户必要修改量为主要判据；说明每项补充解决了哪个执行缺口，比较同信息实际作品。准确性、完整性、清晰度及可执行性作为诊断维度，允许说明非严重的取舍，不机械要求所有主观评分同时上升 | 充分输入不强扩写；保留受托设计空间，不新增事实、授权、交付物或必填问卷。更多细节和更长正文不算胜 |
| 信息状态／要求保真 | 对确定错误检查修复率，对正确表达检查误报与误改；逐项比对来源、对象、属性、条件、否定及确认状态，并验证相关错误是否继续传播到作品 | 输入未提供、现实不存在、用户不知道、拟议方案与已实施分别判断。保留合法变体和独立例外，不以原句完全匹配或模型自评代替语义核对 |

同一候选兼有多个目标时分别报告，不用协议成功抵消保真失败，也不要求局部协议修复凭空创造新的内容收益。已确认的严重目标、事实、授权或硬约束错误仍阻断对应能力；未定归因保留待核实，不依模型风险标签直接定罪或放行。

Plan 修改另核对三条路径：无需重要提问、确有重要未知、实际回答后生成。问题须同时满足：现有上下文不能回答，需要用户提供其掌握的信息或作出其保留的决定，不同答案会实质改变结果。原任务内的检索、阅读和已委托设计不转交给用户；全部实际题答仅作用于各自对象和条件。提问准确率／召回率只描述冻结并标注的题集，报告分子、分母及分歧，不推断为所有未来输入的保证。

## 3. 隔离开发、回归与留出材料

| 集合 | 用途与访问时机 | 报告边界 |
| --- | --- | --- |
| 开发集 | 分析根因、调整指导和代码，可反复离线查看 | 调优成绩，不作为未见题泛化证明 |
| 回归集 | 保存历史失败及允许的正常变体，候选冻结后检验受影响机制 | 旧失败换词仍是已见机制压力测试，不能冒充完全独立留出 |
| 留出集 | 在候选与判据冻结前独立封存题目、材料和答案卡；实现者不预览、不用于挑版本 | 记录作者及是否接触过开发信息。同一开发系统代理编题是内部留出，不是外部用户或领域专家评测 |

冻结清单记录题目 ID、集合归属、原始字节 SHA-256、代码／指导版本、评测脚本、模型、参数、调用分配和访问记录。候选冻结后才开启留出；题目被查看或用于修复后转入回归，后续质量采用另用新的留出。原件保留，不清除失败或沿用“未见”标签。

答案卡只规定用户硬要求、适用事实、重要未知、允许设计空间及可检查行为，不预设唯一范文。出题人与实现者分离有助于减少偏向，但不能凭不同代理名字宣称统计独立。跨行业发布样本比例及多模型轮次继续执行主方案；局部修复只选受影响题型。

题目还需标明验证用途：充分需求用于检查误改；有实际执行缺口的真实模糊需求用于验证有用补充；含项目与材料的任务用于验证完整使用流程。原始臂已经完成任务的题目可以证明不退步，不能单凭持平认定补全无效或已创造收益。

## 4. 运行相同信息的对照

1. **产品收益**比较原始提示词与候选优化提示词的实际作品；**修复回归**比较已采用版本与候选。协议或局部保真修复可先做原件回放与对应回归，不自动重采整套产品基线；结论只覆盖实际完成的对照。
2. 各作品臂使用同一份资料、实际题答、工具权限、执行模型、参数和足够的输出预算。Plan 同信息组只增加逐字真实题答及归属，不由脚本补入平台遗漏答案或候选的推理。自然问答收益另轨记录。
3. 固定随机执行顺序和匿名编号，保存原始输入、模型首次响应、平台结果、复制正文、历史及作品。仅执行协议允许的有界修复，每次都计数；不用质量重试挑作品。
4. 失败、截断、超时与缺少作品计入对应阶段完成率；不把对手没有返回当作候选语义胜出。费用未知就记录未知，不以短缺作品证明成本更优。
5. 上下文选择修复另做完整流程验证：选择项目、定位目标文件、增强、复制、历史和下游使用；保存实际选择的材料及未命中状态。同信息对照用于隔离正文改写收益，不能代替端到端检索验证，也不能把候选多拿到资料的收益全算成改写收益。
6. 简洁链路与复杂链路对照须保持相同输入、执行条件和必要保护，并记录调用次数、延迟与失败。不以删掉来源、实际题答或权限保护换取速度；增加模型阶段或内部字段应有对应质量／可靠性收益证据。

## 5. 先确定性检查，再匿名审阅

按用户要求选择独立检查：JSON/schema、明确字数和字段、数值复算、代码编译与行为、文件格式、复制／历史一致性。检查器的预期值来自原始要求和独立计算，不来自待评作品自报；检查器错误单独修正并保留旧判定。确定性检查覆盖不到的语义继续审阅。

人工审阅先只提供原始要求、相同资料／答案和匿名 A/B 作品，隐藏候选名、策略和模型品牌。记录每个判断的原句、实际编辑负担及胜／平／负／双方失败，区分事实错误、授权变化、要求遗漏与文风偏好；再解盲核对增强、组装和下游的责任。正式广度发布按主方案执行两名独立评审与分歧裁决；小范围验证可结合确定性检查和实际用户评阅，事先冻结方式并披露证据局限。

真实人工尚未参与时，结果标为“内部评估，人工复核待完成”；AI 可辅助匿名整理和复核，但须披露模型及是否参与过开发，不冒称用户、人工或专家。未决分歧保留，不能取更有利评分。充分输入的持平是允许结果，双方失败或缺失作品则不能并入持平。

## 6. 收口与证据保留

依据冻结判据决定采用、不采用、撤回或待验证，注明适用范围；工程完成、候选采用和实际启用分别记录。工程修复采用时列出故障复现、修复后证据、正常变体及回滚位置；内容策略采用时另列实际作品收益。规则调整仅用于后续冻结的验证，不重判旧失败、不自动切换默认或授权发布；已有明确的采用决定按用户当前授权执行。停止同一假设采样后按 AGENTS 复核原因，不靠换版本号续跑，也不把停止记为目标达成。

<a id="budget-accounting"></a>

预算结算在本批协议指向的任务总账中维护授权依据、总上限、已用、预留和剩余额度，避免多个文档重复记账。新批次按实际消耗计任务总额，阶段预留在关闭时结算，原件与执行入口随即锁定；未用预留的释放只适用于预算新规则生效后冻结的批次，既有闭批余额不追溯恢复。任何文档或实验计划都不新增调用授权；本次规则整理不改写已有总账和结算。

每批保留以下一份结果摘要即可；原件、检查与审阅明细链接到对应文件，不在多个文档重复维护相同统计：

| 字段 | 内容 |
| --- | --- |
| 任务与假设 | 用户授权范围、修改目标、旧／新版本、冻结判据 |
| 样本与公平性 | 各集合题数与作者、访问边界、同信息核对、实际模型及参数 |
| 工程与质量 | 受影响检查、目标指标、正常变体和充分需求、作品收益及编辑负担 |
| 失败与归因 | 首次原件、平台／增强／下游／工具或混合归因、已知未决问题 |
| 实际投入 | 各阶段调用及修复、失败、耗时和有返回的用量；未知项单列 |
| 处置 | 三层状态、采用／撤回位置、未验证范围及人工审阅状态 |

需要纠正金标、工具或归因时另存更正及依据，保留原协议、原响应与旧结论；更正不授予修改冻结门槛或抹除失败的许可。
