# 页面访问事件停用回归（2026-10-24）

## 本次口径

页面进入、刷新、重新打开首页不再采集 `APP_VISIT`，也不计入活跃账号、平均日活和排行活跃天数。登录和仍在使用的关键操作继续按账号 ID 统计，包含平台管理员。

历史数据库记录保留，但所有账号统计和操作日志查询均排除 `APP_VISIT`，不做物理删除或数据库迁移。直接增强提交、Plan 完成、设备分布、模型调用对账继续采用各自事件口径。

## 采集与恢复

- `AnalyticsEventServiceImpl.record` 在解析 IP 和创建会话前忽略页面事件。
- 浏览器协议仍可识别旧 `APP_VISIT`。通过身份、账号归属及时间校验的请求返回原成功响应，随后忽略，不创建位置快照或持久队列；非法输入沿用原错误处理。
- `AuditEventDelivery.accept` 阻止页面事件写入 journal，`AuditEventDatabaseWriter.write` 在 Mapper 前再次保护，避免内部调用绕过采集入口。
- 升级前已持久接收的页面事件，在 journal 重放时只写原事件 ID 的确认状态，不补写 PostgreSQL、不增加成功投递计数。原 journal 文件仍保留，其他操作沿用独立事务、幂等和退避恢复机制。
- 前端不再安装路由采集。旧安装函数保留空实现，避免旧调用恢复页面监听。
- 浏览器队列只生成 `RESULT_EXPORTED`；合法旧页面事件在所属账号激活时确认退役，不再发送。使用存储键快照遍历，避免移除旧页面键时漏掉相邻的导出事件；其他账号及损坏记录仍按原隔离规则处理。

## 查询与页面

`AdminAnalyticsMapper.xml` 的期间汇总、融合仪表盘、独立每日序列、排行和日志计数／分页统一排除历史页面事件。小时、月份和设备查询本来就使用关键操作或登录白名单，不包含页面访问。

为兼容既有 API，以下字段保留但固定为数字 `0`，SQL 已移除页面次数和访问账号的聚合，不从其他行为推算页面访问：

| 响应 | 停用的兼容字段 |
| --- | --- |
| dashboard | `accessCount`、`uniqueVisitorCount` |
| 每日序列 | `accessCount`、`uniqueVisitors` |

管理员显式按 `eventType=APP_VISIT` 查询操作日志时，返回空列表且总数为零。前端移除页面访问／去重访问卡片、页面事件筛选和两条访问曲线，每日图表只展示活跃、实际使用及新增账号。权限保护仍沿用现有管理员拦截。

## 本轮验证

修改前执行三项定向测试，确认旧代码会采集、排队并写入页面访问；修改后这些测试通过。

| 检查 | 实际结果 |
| --- | --- |
| 后端定向回归 | 10 类共 80 项通过，失败／错误／跳过均为零 |
| 其中真实 PostgreSQL 与 MockMvc | 3 类共 23 项通过，禁用 Flyway，夹具事务回滚 |
| 前端 Vitest | 队列、路由、图表口径共 19 项通过 |
| Chrome 页面回归 | 桌面／手机两项目共 34 个场景：32 项首轮通过；2 项空状态旧卡片数量断言修正后复跑通过 |
| 布局 | 覆盖宽屏、平板、手机宽度、主题切换、表格长内容、空状态和失败恢复 |
| 前端类型与构建 | `npm run typecheck`、`npm run build` 通过 |
| 历史真实浏览器验收入口 | 已将重试和代理检查改用导出事件，保留页面上报忽略检查；`node --check` 通过，本轮未执行该完整浏览器→真实后端→数据库脚本 |

## 生效条件

发布前后端新版本后生效；后端重启即可阻止旧客户端继续保存页面事件，前端更新后连自动请求也不再产生。本轮仅做本机开发与验证，未执行生产部署。
