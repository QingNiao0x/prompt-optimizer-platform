## 残留缺陷与修复方向

### P0：条件式被提升为已确认事实

原始研究需求是“若我只确认完整性指标分母包含所有有效出院记录，不能据此推断……”，直接增强没有 Plan 回答。Flash 最终提醒却写成“用户已确认完整性指标分母包含所有有效出院记录”。同份资料仍表示该口径未定，导致最终正文内部不一致。

证据：[直接增强结果](../../tmp/prompt-comparison/latest-recheck-20261006-01/RC-RESEARCH-L-deepseek_deepseek-flash-direct.json)。这是最终增强链路仍未拦截的事实失真，不能仅通过删除提醒掩盖。

修复应在事实／决定表示中保留断言、条件、引用和实际确认状态；只有服务端绑定的实际答案或明确断言可以建立确认事实。条件句说明某个选择的影响，不表示该选择已发生；其他对象和新的确认仍须保留。

### P1：同一未决决定跨题或改写后重复

- Flash 研究最终结果同时保留“是否插补、适用指标和方法均未决定”和同义改写的第二条插补提醒。
- Pro 把完整性分母题中保留的一致性分母未决子项，与独立的一致性分母题再次保留；同一覆盖度说明还在“用户说明”与“补充说明”复写。
- 医院两院各自的四个决定正确保持独立；不能为去重而把两院窗口或阈值合并。

证据：[Flash 最终结果](../../tmp/prompt-comparison/latest-recheck-20261006-01/RC-RESEARCH-L-deepseek_deepseek-flash-plan-final.json)、[Pro 最终结果](../../tmp/prompt-comparison/latest-recheck-20261006-01/RC-RESEARCH-L-deepseek_deepseek-v4-pro-plan-final.json)。

继续按业务对象、属性、条件、版本、来源取值及未决子项核对；不同题 ID 可以描述同一未决决定，不能只按题 ID 或大类别判断。归并时保留新条件和真正新增冲突；完整正文中仍需压缩任务、约束、规则补回与验收间的重复表达。

### P1：实际作品仍可能不符合交付要求

独立检查与匿名评审见下一节。新闻精确长度尚不稳定，代码有首次编译失败，部分法律表格仍把未绑定内容填入具名格。这些问题不能靠平台接口成功、删除未知信息或提高评分解决。平台仍只生成提示词，不因此执行用户代码；本轮代码运行限于获授权的合成、无文件／网络访问的评测程序。

## 下一步与冻结条件

1. 优先修复条件句确认状态；加入“若／假设／引用中确认”与真正确认的成对反例，复验直接增强及 Plan 共享链路。
2. 按未决子项合并跨题提醒，补充同对象跨题、同题新条件、不同医院／年份和部分确认反例；缩短正文时守住否定、严格比较符和必要未知。
3. 继续减少新闻发布主体等低价值追问，复验推荐依据的对象与适用范围；不要删掉专业口径等真正决定。
4. 对新闻实际正文和代码实际编译继续做多轮、同信息对照。核对法律具名格，不能只检查正文中是否出现“未核实”。
5. 明确现有未跟踪动态约束测试的范围，取得真实候选的全量回归结果；再完成每个拟开放 DeepSeek 模型既定跨行业样例、多轮作品、完整文件／目录及编辑复制历史流程、目标规模和两名独立基础业务评审。

所有已执行反例、首次失败和本轮新样例保持可追溯。**以上缺陷与基础门禁未关闭前不冻结上线候选。** 领域人员专业核验仍按用户已确认安排在上线后；本轮未将其重新设为上线前人工阻塞条件，也没有省略上线前由 Codex 执行的专业场景评测。

本地管理脚本首次健康等待曾超时，随后确认服务实际启动并健康返回，才开展真实采集；该启动探针问题与生成结果分别记录，不用模型接口成功证明管理脚本或邮件服务完全可用。临时验收浏览器在采集结束后关闭，本地后端保留运行。
