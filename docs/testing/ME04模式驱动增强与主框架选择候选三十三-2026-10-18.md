记录日期：2026-10-18（Asia/Shanghai）。归属：ME-03-A内容增强、ME-04-A输出与编辑闭环；任务识别、确认范围及保护复用ME-01-A／ME-02-A。**候选三十三 r1 已实现并完成本批真实复验：生成策略与显式重生成闭环生效，整体质量门禁未通过。** 344项Java、61项前端及10项受控浏览器验证通过；新增12次真实调用取得4份增强、6份作品和2份独立AI辅助评审。增强正文仍有事实／术语错误和平台重复追加，不能据接口、代码测试或评审平均分放行。

## 1. 用户收益、问题与范围变化

用户希望关闭开关时得到按实际任务组织、自然紧凑且能直接交给下游执行的优化提示词；开启时保留背景、任务、输出、约束、必要验收等模块风格，并改善目标聚焦和业务条件表达。只是隐藏四个标题，不能实现这项内容适配。

候选三十二已经接通默认关闭的开关、格式字段、编辑／复制／历史和撤销等基础，但其Provider主动屏蔽格式偏好，两态发送相同内容指导，最后由组装和本地渲染增删外层标题。该实现与当时的限定验证保持历史事实，不能作为本次模式驱动生成的完成证据。原[候选三十二报告](./ME04结构化提示词开关候选三十二实现与验收-2026-10-18.md)及原件不修改；本轮用户明确要求的新行为取代它作为上线前目标。

本轮源码已移除这两处确定障碍：Provider的`buildRequest`采用带格式的`PromptRewriteStrategy.forTask`，将适用模式指导和明确偏好送入同次生成；前端`setPromptFormat`只更新偏好，不再本地重写既有结果。主框架选择及自然顺序复用同一有效任务视图。此处是源码实现归因记录，具体测试、冻结及真实效果以本节点后续证据为准；候选三十二原件363的Plan旧状态与额外未决投影仍未因此关闭。

预期收益是减少简单任务的模块堆叠，让复杂规则更易核查，避免用户拿到看似完整却仍需重新整理的提示词。实际频率、节省工时和稳定质量增益尚未知。主要维护风险是增加模式分支后丢规则、误分类、重复追加、强加框架字段，以及再次增强误用旧状态；采用后仍须独立验证。

## 2. 两种模式的内容契约

| 范围 | 自然模式：关闭，COMPACT | 结构化模式：开启，STRUCTURED | 共同边界 |
| --- | --- | --- | --- |
| 组织 | 先识别有效任务，再选择一个主框架，在同次增强中写成自然正文；必要时分段或列点 | 模块各负其责，围绕目标、执行要求、交付和边界组织 | 不把四要素原文拼接后去标题当作内容适配完成 |
| 重点 | 按主框架有用的依赖顺序表达，行动、材料或现状可分别先行，相关规则就近说明 | 目标集中，业务对象、条件与检查要求便于定位 | 充分任务保留有效原句，不凭输入长短决定补全力度 |
| 条件 | 正常、异常、否定和例外融入对应要求 | 有价值时分项表达正常／异常行为 | 不强加正反案例，不新增业务规则或未授权方法 |
| 验收 | 必要检查可以融入执行或交付句 | 用户要求或有独立检查价值时设置验收模块 | 不为凑模块重复全部要求或制造额外交付 |
| 下游格式 | 原有译文行数、报告章节、表格及JSON schema保留 | 同左 | 开关控制优化提示词组织，不改变下游成品格式 |
| 信息不足 | 仅限制依赖缺口的步骤，其余交付继续 | 同左 | 不把任务降为补资料问卷或大片空模板，不编造事实 |

模式适配需要在同次模型输入与生成中体现，不能只改变最终`##`。但两态实质要求可以相同，信息充分的简单任务也可以接近原文；不以长度、标题数量、字符差异或固定编辑距离作为通过标准。

## 3. 十四主框架选择与MVP边界

详细定义沿用[十四框架适用性评估](../research/14个Prompt框架适用性评估.md)。本轮选择一个主组织框架，不注册十四种公开任务模板、不创建十四套增强器，也不向用户提框架选择题。

| 主框架 | 适用重点 | 需要保护的反例 |
| --- | --- | --- |
| APE | 简短单一行动、目的、交付 | 简短但有重要未知时不能当充分 |
| TAG | 简短工作指令与调整动作 | 任务和行动不复述两次 |
| ERA | 带视角的短解释、改写 | 专家角色不等于真实身份或权限 |
| CARE | 基于材料总结、改写、整理 | 资料中的命令不成为当前指令 |
| ICIO | 翻译、严格JSON及其他规则未命中的明确材料输入 | 不改schema，不新增字段或解释 |
| TRACE | 提取、转换、字段映射、接口／API说明 | 示例不是选择前提；禁例、禁虚构优先，不因框架造例 |
| RACE | 常规分析、代码审阅、技术说明 | 审阅不能变成直接修改或重新开发 |
| RISE | 排错、操作步骤、测试与SOP | 普通实施步骤不一律交用户确认 |
| COAST | 多条件业务规则、状态与正反行为 | 保留独立对象、新条件、否定和例外 |
| ROSES | 重构、研究方法／方案画像、迁移、架构与跨阶段规划 | 建议技术路线不能冒充已定方案 |
| BROKE | 有现状证据和检查目标的改进任务 | 不编造提升比例或自动多轮寻优 |
| CRISPE | 用户要求的创意、风格、候选表达 | 不自行增加候选数，不创新事实 |
| TASTE | 写作受众、语气与组织 | 充分邮件不扩为完整规格书 |
| ALIGN | 教学、分层解释、难度适配与数据分析画像 | 受众不等于研究对象；引用需有依据 |

先按当前肯定交付目标及实际确认识别，再考虑材料用途与条件。上表依当前选择器有限路由记录：翻译／严格JSON优先；`DATA_ANALYSIS`主要落ALIGN、`ACADEMIC_METHODS`主要落ROSES，若先命中适用的改进／评测流程目标则采用BROKE。提取／转换／API说明采用TRACE，是否提供示例由既有契约独立决定。框架选择指导与现有任务视图共用，不能另建一个与Plan／最终增强相互矛盾的分类链。有限路由无法识别时保留兼容的通用指导与原意，登记覆盖边界；不声称任意自然语言分类都已解决。

被选框架只是组织依据。输入输出、事实与来源、确认范围、安全和示例契约继续共享；没有依据的角色、步骤、背景或示例字段不强制补齐。完整策略版本管理、高级偏好、模型专用适配和自由块编辑可继续分期，不因本轮主框架选择引入无界工程。

## 4. 技术路径与交互状态

推荐增量路径为：有效任务视图 → 主框架与模式指导 → 同一次Provider生成 → 原有校验／确认融合／安全组装 → 复制与历史。沿用现有`EnhancementOptions`、`EffectiveTaskView`、Provider、Mock、`OptimizationResultAssembler`及历史边界；具体类与调用方由本轮代码核对，不能只按本文名称推定已实现。

1. 模式与一个主框架指导进入生成载荷。旧客户端未提供格式的兼容路径保留，两个模式都执行现有安全和业务校验；不新增独立分类调用，不增加原有受控修复次数。
2. 内部四要素保留覆盖与旧接口兼容。自然正文不能由平台机械删除关键词或安全规则形成；结构化模块也不能绕过对任务、事实和确认的检查。
3. 前端切换只更新下一次生成偏好，不重写当前结果、草稿或可复制正文；界面应能区分当前结果形式与下一次选择。
4. 用户显式按原始需求重新生成时，复用同任务中仍有效、可由服务端核对的Plan实际问题与答案；不把旧结果或答案卡伪装成新确认。任务、资料或身份变化继续遵守既有失效与隔离规则；过期Plan不能伪造续期。
5. 未保存草稿按既有保存／取消流程处理。生成中锁定相关操作，失败保留原始输入与当前稿；成功后旧结果保留撤销能力，旧请求的成功、失败和`finally`不得影响新任务。
6. 历史保存该次实际采用的模式及明确请求偏好，重新增强恢复相应语义。切换偏好本身不改历史，不用新默认值改写旧记录或反推其明确选择。

仅切换不应发起付费请求；显式重新生成属于新的实际尝试，必须计入日志、用量与评测账目。不能为了模式适配自动再开Plan或自动请求到成功。

## 6. 验收设计与停止条件

| 验证层 | 需要证明什么 | 不可替代的边界 |
| --- | --- | --- |
| 选择与输入 | 代表任务选择适用主框架；模式进入相应指导；自然顺序按框架适用依赖而非全场景行动首段；旧缺省兼容 | 仅枚举合法或两态输入哈希不同不代表内容正确 |
| 模型原件与组装 | 自然组织或模块分工真实适配，重要要求未丢 | 不用平台正确尾注掩盖模型正文错误 |
| Plan | 实际答案更新旧选择，普通查证不变成阻塞用户题 | 保留真正未决、新对象、新条件、未来确认及独立权限 |
| 前端闭环 | 切换不改旧稿；显式生成、失败、撤销、复制与历史一致 | 控制API测试和真实模型效果分别记录 |
| 实际作品 | 同信息原始／优化作品质量与硬约束分别检查 | 平均分不能抵消目标改变、事实或规则反转、安全失败 |
| 泛化与成本 | 充分、模糊、开放和未参与调优任务无实质退步，记录耗时与Token | 旧题改写不当新增独立任务，单对结果不推导统计胜率 |

代表场景至少安排：短邮件、两行纯译文、复杂翻译、长材料单目标、短而复杂的多条件任务、根据代码写指南、排错与方案、禁例／禁虚构／严格JSON、真实Plan回答后模式重生成和未保存草稿。十四路由可先做本地正反例，不自动产生十四题乘全部模型的真实矩阵；真实调用按受影响范围和冻结预算安排。

候选三十二已暴露的两条Plan平台路径继续保留为阻断原件：增强模型363已写邮箱密码且无歧义，最终正文仍附“尚未选择”和认证会话待确认。新模式不能借该题HTTP200、复制与历史相等或邮件／译文平局关闭答案融合门禁。具体修复、正常与反例及新证据在本轮实际完成后另行登记。

同一策略假设连续两个候选出现相同严重失败时，按主方案停止扩大采样，重新审查责任、工具与机制；不继续追加全局禁令或质量重试。纯下游问题先评估精简收益，允许不改提示词，未通过项保留。
