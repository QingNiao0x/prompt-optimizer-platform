# 自然增强需求表达指导与题答衔接实现

## 第一步 正文指导

新增`EXPRESSION → core-expression-v1`，从正常服务端配置入口选择。正文优先明确动作、对象、指代、顺序和条件归属，普通设计以任务和上下文为依据保持拟议状态，已有事实与用户确认继续要求真实依据。充分需求允许少改或正确保留。

指导采用新的完整正文原则，消除了旧指导对原任务内部设计的宽泛限制。模型本次交付优化提示词，原始工作由下游执行。v5完整响应协议、来源、正文引用及题答规则继续复用，第一步的范围准备与Plan指导逐字复用现有版本，用于后续对照。

`NaturalExpressionProviderTest`通过正常Provider传输核对实际system、原始输入、范围与正文阶段，并覆盖错误正文引用经一次协议修复后继续拒绝。测试中模型响应为受控夹具，其原文保留结果仅用于验证路由与保护。

定向5套共81项通过，分别为表达Provider5、配置10、Plan上下文19、范围来源修复8、自然服务39。首次沙箱运行在Java动态代理加载后停滞并中止，原日志保留在本机tmp。相同离线检查在本机权限下通过，未改变断言。

服务端可用`NATURAL_ENHANCEMENT_PROFILE=EXPRESSION`选择本路径。当前源码默认为`PROTOCOL_SCOPE_REPAIR → core-repair-v5`。本轮尚无真实模型、作品或工作台采用验证，运行服务未重启，生成质量和日常启用待验证。
