## 后端证据

- **用量保留**：正常成功、JSON 内容解析失败、截断修复、最终 `INVALID_RESPONSE` 以及 HTTP 429/502。HTTP 错误有数字 usage 时保留；没有 usage、超限错误体和损坏 JSON 保持未知。逐次尝试有不同 UUID，不将上一次用量带到下一次。
- **输入边界**：缺失/null、零、负数、浮点、数字字符串、long 最大值、long 越界与不一致合计。非法遥测不伪造为有效整数，不影响原本有效的模型业务结果。
- **匿名与安全**：模型事件操作者必须 null，旧业务事件仍要求账号；安全请求关联号和流程指纹，不采集用户/邮箱/IP/会话/正文/凭据。API 不返回整个 JSON，供应商错误正文不进入对账投影。
- **可信范围**：真实 MVC 拦截器使用服务端 CurrentActor 租户，客户端 tenantId 不能覆盖；请求结束后恢复范围。真实文档异步处理测试覆盖向量化时的租户范围、流程指纹和范围清理。
- **权限**：两个新管理员接口均验证未登录 401、普通账号 403、管理员放行，以及当前角色撤销后拒绝；参数格式、租户范围、日期、周期、分页、Top N 越界返回参数错误。
- **幂等恢复**：模型匿名事实在数据库故障、journal 重读、进程级投递对象重建、重复接收后仍保留一个事件 ID；真实数据库同 UUID 插入只影响一行。复用原审计恢复/ack/事务后计数回归。
- **真实 PostgreSQL**：失败的已报告 Token 保留，Mock 与 NOT_SENT 排除排行；完整/部分/未知/无效与缓存覆盖计数一致。租户与全局范围、来源分组、Top N、请求号和操作过滤、分页总数、空数据、起点包含/终点排除、跨时区边界验证通过。
- **精度与旧指标**：两条 Long.MAX_VALUE 的有效事实聚合返回精确字符串 `18446744073709551614`；损坏 JSON 数字不触发 CAST 错误。匿名模型事实不会增加旧账号活跃/实际用户或使用排行；旧直接增强/Plan 事件采集代码保持原样。
- **日历范围**：DAY/WEEK/MONTH 展开完整自然周期；测试包含 America/New_York 夏令时开始日 23 小时，采用两端当地午夜，没有固定 24 小时假设。

## 复现命令

在 `services/api`，使用 JDK 21 与已安装依赖执行：

```powershell
$modelReconciliationTests = @(
  'ModelCallReconciliationTest', 'ModelCallAuditServiceTest', 'ModelCallLoggerTest',
  'ModelTokenUsageReaderTest', 'ReportedTokenCountDeserializerTest', 'MapperXmlConfigurationTest',
  'AdminModelCallAnalyticsServiceTest', 'AdminAnalyticsControllerSecurityTest', 'ModelCallAuditWebConfigurationTest',
  'ModelCallAnalyticsDatabaseTest', 'OpenAiCompatiblePromptEnhancementProviderTest',
  'OpenAiCompatibleDocumentSummaryModelTest', 'OpenAiCompatibleTextEmbeddingModelTest',
  'TemporaryDocumentIndexServiceTest', 'AuditEventDeliveryTest', 'AuditEventDatabaseWriterTest',
  'ModelConcurrencyHttpInterceptorTest'
) -join ','
mvn -s ../../.mvn/settings.xml -o "-Dmodel.reconciliation.database-test=true" "-Dtest=$modelReconciliationTests" test
mvn -s ../../.mvn/settings.xml -o '-Dtest=AnalyticsEventServiceTest,AnalyticsClientEventServiceTest,AnalyticsPeriodResolverTest,PlanQualityMetricsImplTest' test
mvn -s ../../.mvn/settings.xml -o '-Dtest=AdminAnalyticsServiceTest' test
```

真实库测试只有显式开关为 true 时执行；读取允许的开发配置与进程变量，不读 `.env`，仅允许 localhost/127.0.0.1 的开发数据库。没有正确的本机开发数据源时应报告真实连接失败，不能当作数据库验收通过。

在 `apps/web`：

```powershell
npm test -- src/features/analytics
npm run test:e2e -- analytics-layout.spec.ts
npm run build
```

本轮 Windows 沙箱阻止了 javac 编译资源访问、Vite realpath 和本机连接，使用已批准的本机执行完成相同命令；未通过修改依赖或弱化测试规避问题。

## 未覆盖与数据限制

- 新事件仅从功能启用后产生，不反推 10 月 10 日或其他历史业务事件的模型请求数/Token。
- 本轮没有真实供应商调用和账单逐小时核对，也没有新增模型对账 SQL 的生产规模、并发容量或生产部署验收。
- 供应商时区、记账时刻、API Key 范围、超时是否计费及缺失 usage 仍需供应商证据；本地已报告 Token 不保证等于完整账单。
- journal 接收与入库之间可能存在可见延迟；磁盘与数据库同时故障、终态采集前强制退出的调用不能宣称零遗漏。
- 测试没有修改既有用户数据、运行数据库迁移或升级核心依赖；充值功能继续延期。
