## 3. 代码与接口

| 模块 | 改动及作用 |
| --- | --- |
| `TaskIntentResolver` / `TaskIntent` | 从肯定目标与有效整体交付答案解析主辅交付，区分显式、原始目标、用户确认及默认；排除否定、引用和当前状态 |
| `TaskDeliveryProfile` / `PromptTemplateRegistryImpl` | 集中交付指导；新闻、教学、指南、机关报告、论文、分析、会议及专业材料采用相应输出、验收和提问指导 |
| `DefaultEnhancementOrchestrator` | 使用服务端 `knownDecisions()` 细化最终模板；明确辅助代码追加局部工程检查 |
| `ConstraintCompleterImpl` | 主软件任务保留原工程约束；写作不因为附件含 Java 就要求接口/事务/Redis；明确复现代码仍检查输入、异常和必要边界 |
| `OptimizationPlanningServiceImpl` / Mock Planning / OpenAI Provider | 使用共同分类依据；内部载荷含画像与提问范围，系统指令强调目标、材料边界和只输出限制 |
| `AmbiguityDetector` / `RoutineWritingPresentation` | 按任务限定兜底；只分流已有写作成品的纯排版问题，术语冲突、新权限及复合业务条件仍保留 |
| `ResolvedPlanState` | 整体交付已绑定并明确选择后，修正对应旧“交付形式请先确认”；同句不执行开发/部署限制和原始证据保留 |
| 前端 `optimization.ts` | 自动 Plan 的最终请求继续 `AUTO`，不把初期推断锁定成用户显式选择；API 显式模板优先仍有效 |

公开 `TemplateCode` 保持 `AUTO/GENERAL/RESEARCH_ANALYSIS/FEATURE_DEVELOPMENT/BUG_FIX/REFACTORING/TESTING`。未新增前端必填字段、客户端确认标记、数据库迁移、依赖或独立分类模型调用。四要素、验收段落、权限红线、所有权、历史及最多三次受控修复预算保持原契约。

详细字段、调用顺序和流程图见[实现教学](../development/任务模板适配实现教学.md)及[Plan 接口文档](../12-内置Plan-Mode交互与接口.md#75-按交付目标适配模板2026-10-05)。本节点不是版本化领域 Skill、专业认证或任意语言语义分类器。

## 5. 真实增强与 Plan

增强器使用后台当前默认的 **DeepSeek-V4.1-Flash**，`mock=false`。通过正常浏览器登录、CSRF 和实际 API，执行上下文准备 → Plan → 提交完整回答 → 最终增强，同时保留直接增强对照。回答由 AI 辅助的合成用户角色填写，不冒充真实医院、律师或研究人员。

## 6. 两模型实际作品对照

### 6.1 冻结协议

新闻稿、开发、论文、指南四题，各五臂，每臂同一模型执行一次，共 **40 次真实下游调用**：

| 组 | 执行输入 | 信息轨道 |
| --- | --- | --- |
| raw | 原始提示词＋相同资料 | 原始信息 |
| direct | 直接增强提示词＋相同资料 | 原始信息 |
| plan | Plan 增强提示词＋相同资料 | 原始信息＋实际确认答案 |
| raw_matched | 原文＋相同资料＋实际确认答案 | 与 Plan 同信息 |
| direct_matched | 直接增强＋相同资料＋实际确认答案 | 与 Plan 同信息 |

执行模型为后台已发布的 DeepSeek-V4.1-Flash、GLM-5.3-FlashX；温度 0.2，最大输出预算 8192，无自动重试，独立会话、相同材料。评分卡未发送给执行模型。调用在独立验收工具内进行，平台产品本身仍不执行用户任务。

### 6.2 技术结果及预算限制

| 执行模型 | 调用 | 完整作品 | 部分正文 | 空正文/失败 |
| --- | ---: | ---: | ---: | ---: |
| DeepSeek-V4.1-Flash | 20 | 20 | 0 | 0 |
| GLM-5.3-FlashX | 20 | 5 | 1 | 14 |

40 次均得到 HTTP 200，但 GLM 的 15 次 `finishReason=length` 不能当作完整成功；其中 14 次无正文，1 次指南正文半途结束。原始和增强各组均受影响，涉及推理内容消耗输出预算；这不是“GLM 输出准确性必然低”或“增强组失败率更高”的证据。需按模型记录推理设置、可见正文及总输出预算，另开公平校准批次，保留本轮首次失败（NR-08）。

### 6.3 内容评审和量化结果

已阅读 25 份完整作品，并用项目量表记录准确性 35%、完整性 25%、规则保真 25%、可用性 15%，0—4 分转换为 100 分；严重错误优先于总分。评审为一位已见输入来源的 AI 辅助评审，**非盲评、非独立专业双人验收**。部分正文保留 `PENDING`，不评分为通过。

| DeepSeek 题目 | raw | direct | plan | raw_matched | direct_matched |
| --- | ---: | ---: | ---: | ---: | ---: |
| 新闻稿 | 87.5 | 96.25 | 100 | 96.25 | 100 |
| 开发 | 53.75（严重错误） | 92.5 | 92.5 | 96.25 | 83.75 |
| 论文 | 93.75 | 96.25 | 96.25 | 100 | 81.25 |
| 指南 | 90 | 85 | 81.25 | 91.25 | 100 |

按同题、同模型、同重复、同信息配对，直接增强对原文为 3 胜 1 负；Plan 对同信息原文为 1 胜 3 负；直接同信息对同信息原文为 2 胜 2 负。GLM 仅新闻题有完整的五臂作品，三个增强配对均持平，其余不可比较。样本数很小且每臂只有一次，**不能计算显著性、推导总体胜率或承诺全部任务增益。**

具体作品证据：

- 开发原文作品在未知地区核验口径时直接给出执行分支，构成严重错误；直接增强保留 `PENDING_DECISION`，改进实际执行前提。Plan 已落实确认答案，但步骤、事实、测试和安全重复使作品更长，弱于同信息原文。
- 新闻稿增强更明确“内测”与能力边界，没有变成接口开发；原文已经充分时，GLM 的增强作品并未观察到额外收益。
- 论文增强提供较完整的公平比较与评分组织；部分同信息增强又把“待确定评分尺度”固定为未标候选的 0—4，暴露细节补充越界风险。不能以章节和字数增加作为成功。
- 指南没有被 Java 资料带成代码任务，但“材料未证明有自动撤销”在部分作品中变成“不提供该能力”；Plan 还把内部证据说明带进面向新手的正文，阅读负担增加。

## 7. 时延、安全及后续计划

直接/最终增强在主批次的返回 `latencyMs` 为 2099—19506 ms；不将其替代完整浏览器总耗时，也不把跨阶段嵌套计时相加。独立执行中，截断的 GLM 请求约 47—60 秒，属于本轮模型/预算观察。组装热点和完整计时 NR-07 仍开放；未通过减少事实、关闭校验或缩短上下文假装修复时延。

证据只归档合成需求、材料片段、公开请求标识、模型、Token/时延及白名单事件；移除 `planId/contextId`、会话、CSRF、Cookie、认证及密钥字段，不存浏览器认证请求。追加组件补验仅绑定普通应用中的模型配置和标准进程环境，不启动Spring应用、数据库或管理员引导，也不读取管理员凭据。管理员模型配置和生产数据库未改；局部能力验证不替代完整目录、身份隔离、专业双人及各开放 Provider/模型 11 题门禁。
