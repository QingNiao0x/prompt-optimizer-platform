# 直接增强正文目标保护与真实复验（2026-10-11）

本轮修复“要求正文却被模型改成方案，平台仍追加正确尾注并放行”的确定缺口，并调整缺资料时的写作指导。**确定反例与共享回归已通过，真实作品质量仍未全部通过；不关闭 ME-03／ME-04／ME-06。** 本软件仍只增强提示词，报告生成仅用于离线质量评测。

## 1. 输入、现状与根因

科研用例按本轮用户截图逐字转写，保留反斜线、换行、小写 `yll` 和原标点；用户要求“请分析并解决”，本例登记为 `USER_PROVIDED_SCREENSHOT`，不伪称合成资料。原文为：

```text
我是一名科研工作者,我想要撰写2015-2025年某地区心脑血管疾病死亡率特征分析,我需要从以下几个方面进行分析:
1.时间序列的长期趋势和季节性趋势
2.分性别\地区\分人群\分亚类去进行比较
3.进行减寿分析:年度的\性别的yll和yll率
4.采用Arriaga分解方法去分析
```

上下文、文件、会话为空；Plan 与示例关闭。当前 `TaskIntentResolver` 已识别 `DATA_ANALYSIS`，原 `DraftDeliveryContract.active` 也已启用，不能归因于没有“报告”两个字。`OpenAiCompatiblePromptEnhancementProvider` 的系统指导、请求中的交付画像及正文契约本已要求保持正文目标，但 `OptimizationResultAssembler` 缺少对模型 TASK／OUTPUT 主交付变化的实际拒绝：错误“分析方案”与正确“可修订初稿”尾注可以同时存在。

本轮真实基线两款模型均要求正文，没有随机重现截图中的方案目标。确定复现来自实际 Provider＋Assembler 回放截图错误段落；真实基线则复现了缺口重复、空表及下游无依据扩写。两类证据分别记录，不写成同一轮模型先失败后通过。

## 2. 实现范围

- `DraftDeliveryContract` 分开“仍要求正文”与“允许缺资料先起草”。禁止占位、起草前确认不会授权改成方案；明确只要方案、提纲或有效 Plan 更改整体交付时仍尊重选择。
- 组装器在追加平台条款**之前**校验 TASK／OUTPUT，明确的方案／提纲降级或整篇等待补齐资料抛出既有 `RULE_CONFLICT`，进入 Provider 首次加两次修复的共享预算。修复直接针对错误段落；预算耗尽仍失败，不拼接正确尾注伪装成功。
- 保留正文中的候选方法、否定、引用、局部计算条件、JSON 正文、附带代码／表格及并列方案。发现“报告＋附录方案”误拒后补充红绿用例；再纠正“另外本轮只交方案”被附带交付判断提前跳过的问题，最终 guard 为 v3。
- 替换原有短起草条款，强调直接交付、缺口集中说明、不先发补材料问卷。`TaskDeliveryProfile.DATA_ANALYSIS` 将写作任务指向分析目的、指标含义、比较逻辑和解释依据；无数据不主动铺空结果表，一般规律不能冒充本研究结果。

只修改四个生产 Java 文件和四份对应测试；没有修改公开 API、前端、数据库迁移、身份／历史链路，也没有修改其他会话的模型审计工作。Provider 的 `SYSTEM_PROMPT` 没有再次叠加一组同义规则；新的交付画像经原有 Prompt 组装路径进入模型请求。新拒绝器是有限的高置信中文指令校验，**不是通用语义判定，也不保证全部语言和改写均被识别**。

## 3. 自动化验证

- 初始实际组装与 Provider 回放：22 项、5 失败，分别证实错误 TASK、错误 OUTPUT、整篇等待及有界修复未触发，见 [红测试摘要](./evidence/direct-report-delivery-2026-10-11/tests/initial-red-summary.json)。
- 最终正文契约边界 77 项通过，包括正文＋独立方案、正文＋附录、方案在前而正确尾注在后等边界；最终四类定向测试 105 项通过，退出码 0。
- 共享增强／Plan／Provider／模板／权限回归合计 **113 类、1609 项：1603 通过，0 失败，0 异常，6 条件跳过**，见 [最终逐项摘要](./evidence/direct-report-delivery-2026-10-11/tests/shared-final-v3-summary.json)。这是整组、环境修正后三类补验及最终四类回归的合并结果，不冒称整组首次一遍通过。
- 六项跳过为真实模型并发、并发归档重放及 Redis 并发集成；没有本轮通过证据。并行会话未完成的 `ModelCallAnalyticsDatabaseTest` 与 Mapper 临时签名不一致，仅在隔离构建 POM 中排除编译，不修改该测试；全仓库测试没有通过声明。

使用独立构建目录、实际 JDK `E:\Delelop\Java\jdk-21`，不覆盖共享 `services/api/target`。Oracle Java 路径编译资源关闭失败、动态 Byte Buddy 代理管道权限导致测试启动等待，分别通过实际 JDK 和预加载测试代理处理。共享运行首次另有两项相对夹具路径错误及本地 HTTP 回环权限错误；保留 [首次共享摘要](./evidence/direct-report-delivery-2026-10-11/tests/shared-first-summary.json)，修正测试工作目录并在获准环境重跑三类 71 项，退出码 0。没有以基础设施失败代替断言失败，也没有将失败原件覆盖为成功。

## 4. 真实模型协议与版本

直接调用生产编排、上下文分析、模板、OpenAI 兼容 Provider、校验和组装；身份与目录为冻结夹具，**不经过正常账号 HTTP 登录、数据库历史或浏览器**。两个路由为 `deepseek:deepseek-flash`、`deepseek:deepseek-v4-pro`，实际返回型号、参数、耗时、usage 与每次原文均留档。目录是本地配置投影，不代表管理员发布目录已验收。

每个版本、每款模型固定科研题及合成邮件／Python 控制题三次增强；科研原始与增强各执行一次。执行模型在同款内相同，资料相同，温度 0.2、输出预算 8192、thinking disabled、无执行重试。增强和下游作品均未接受额外评审模型加工。

- 基线：冻结 379 个生产文件；6 个增强流程＋4 份作品，实际 12 次有响应调用，含两次科研 JSON 格式修复。见 [基线审计](./evidence/direct-report-delivery-2026-10-11/baseline-summary.json)。
- 候选 v1：从基线复制，仅覆盖上述四文件；同样 12 次有响应调用。原始输入、工具、参数一致；邮件／Python 发给模型的首轮请求逐值一致。见 [候选审计修订版](./evidence/direct-report-delivery-2026-10-11/candidate-v1-summary-v2.json)，文件名末尾 v2 指审计修订，不是生产版本。
- v2：相对 v1 只修 guard 的并列交付误拒。独立编译后以本地真实响应离线重放 6 流程／8 响应，所有请求正文和 `optimizedPrompt`、`sections`、`appliedConstraints`、`ambiguities` 与 v1 完全一致。见 [v2 离线重放](./evidence/direct-report-delivery-2026-10-11/replay-v2/summary.json)。最终 v3 仅调整显式交付限制的判断顺序，另行冻结、编译和[重放](./evidence/direct-report-delivery-2026-10-11/replay-v3/summary.json)后，6 流程／8 响应的请求与上述字段仍全部一致，当前四份生产源码与 v3 冻结哈希一致。无网络、数据库、历史或新作品，不能写成增加了真实模型轮次。

合计 **24 次有响应模型调用、8 份科研作品**，input 70316 tokens、output 29697 tokens；另有最初沙箱 DNS 失败六次，未获得上游响应，见 [环境记录](./evidence/direct-report-delivery-2026-10-11/infrastructure-summary.json)。不报告未取得的实际账单费用。单轮存在随机波动，尤其 Pro 原始组两版本表现不同，不能计算稳定胜率或把原始组变化归因于代码。

## 6. 待办与交付边界

ME-03 保留“普通用户的模糊需求得到实质补全”，但正文目标保护不等于专业口径完整，也不以更长的通用限制当成增强成功。ME-04 继续处理相同缺口和规则的共享覆盖及复制精简；ME-06 保留无依据新增、重复、范围扩张等未通过样本，后续按节点验证实际作品。Plan 决定整合、示例开关、旧附件隔离、保存失败保稿仍是独立未完成项，本轮不能据直接模式测试将其关闭。

缺研究数据时，增强目标仍是原定报告：交付有依据的实质初稿，仅保留受限的实证数值／结论；不能假装数据齐备，也不能把用户任务变为方案或大面积待填模板。本轮未重启本地服务、提交、推送或发布，运行中的实例不会自动取得源码改动。
