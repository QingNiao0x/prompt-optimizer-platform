## 2. 错误提示与失败恢复

确认的缺陷：空 DOMException 信息直接传给页面；失败状态持久化的二次异常可覆盖原始错误；启动清理删除所有 FAILED 索引；失败页没有继续入口，已保存的文件无法复用。

修复：统一配额、权限、文件移动、事务中断及未知错误提示；完整文件批次和检查点原子提交，当前事务回滚不扩大成功计数；保留失败任务至原定过期时间，继续时使用同一项目编号并按指纹校验，不重复索引已完整保存的文件；残缺文件重读。失败页明确显示检查点，清空与页面离开仍撤销当前任务，晚到响应不会复活状态。

定向验证：

- 81 项索引、目录、Worker 与相关组合式函数单元测试通过；初次空异常反例失败原因为 `expected '' to contain '存储空间'`，修复后通过。
- 真实 Chromium 的 450 文件样例在第 201 个文件写入时注入空 `QuotaExceededError`；200 个文件检查点及正文保留，清理不删除它们，继续后 450 个文件完整、200 个复用，末尾可检索。
- 桌面与手机使用生产 Worker、原生 IndexedDB 和 OPFS 文件，页面出现可读提示及继续按钮；点击后完成剩余 250 个文件。该异常是受控注入，不是占满用户磁盘的真实配额耗尽试验。
- TypeScript 检查通过；原有暂停、增量、隔离及正文完整性相关回归继续保留。

边界：刷新后仍不自动恢复页面选择；到期或用户主动删除后需要重新选择目录；不承诺所有浏览器/任意目录永不中断。真实浏览器硬配额不可依赖 CDP 覆盖值验收，本轮以真实事务异常注入验证失败分支，不伪称强制限额探针通过。

## 3. 文件数量、内容完整性与实际速度

已完成数量、正文与性能测量，并修复本轮实际发现的根文件漏召回；没有把未证明整库收益的存储候选合入。当前继续使用第四版 IndexedDB 存储，不减少源码、词表、扫描范围或原有容量保护。

真实本项目目录在数字词键候选下处理 21,578 个文件：21,316 个完整全文、16 个仅元数据、246 个按现有规则忽略、0 个读取失败。数据库 21,332 条文件元数据、39,630 个片段、260,032,407 个字符与引擎统计一致；23 份原始文件的正文 SHA-256 与尾部逐一一致，无提前显示 100%。这是已选范围及既有过滤规则下的核对，不等于磁盘所有文件或所有二进制内容都进入源码索引。

三次整库高层检索中，两条带目录的源码路径召回正确，`README.md` 却被同名提及挤出。因此原件 `passed:false` 原样保留，不能改成整库全部通过。定位发现普通文件候选要求至少一层目录，根目录文件名没有进入精确路径召回。本轮允许根文件名成为候选，仍必须被当前项目索引精确证实才收紧范围；未知文件继续普通检索，URL 查询参数、邮箱和外部路径不会成为本地目标。新增 450 个同名干扰文件的真实 IndexedDB 回归及边界测试；完整 84 项相关单测通过，浏览器结果见下方原件。

候选将全文词的原生索引键变成数字散列，保留原词并核对碰撞；迁移、强制碰撞、事务回滚等检查通过，但整库收益尚不稳定，故撤回生产修改、保留补丁与原件。当前不引入第五版数据库升级。后续性能优化需冻结同一完整目录、排除并行验收负载、测量原生写入和存储整理；达到完整性不退步且整库收益成立后再采用，不以减少词或正文达标。

最终第四版生产代码的 84 项相关单测、8 项真实浏览器回归通过，覆盖根文件、未知文件回退、跨项目隔离、增量覆盖、旧库迁移和失败恢复。根文件在 450 个同名正文干扰下仍准确召回；该次检索耗时约 7.7 毫秒，不作为全目录延迟承诺。

原件在 [storage-candidate](./evidence/file-workflow-2026-10-31/storage-candidate/)；其中数字词键补丁仅作未采用的实验记录，不能视为当前实现。根文件修复采用定向反例复验，未重新把整个目录索引一次；旧失败与本轮未验证范围均保留。

## 4. 复杂文档兼容性

已修复本轮复现的结构提取缺陷，并完成真实上传复验。

| 格式／路径 | 原问题 | 本轮修复及验证 |
| --- | --- | --- |
| Excel（XLSX、XLS，上传与内联共享） | 空列丢失后数值可能对应错误字段，隐藏数据与公式缓存语义不清 | 输出原单元格坐标、合并范围及隐藏标记；保留公式与“缓存值未重算”说明，无缓存的 XLSX 不冒充值为 0；不计算公式、不刷新外链或执行宏 |
| Word OOXML 流式上传 | 任意 XML 文字会混入正文，包含删除修订、域指令等 | 保留当前可见文字、插入修订、脚注、表格坐标及跨列标记；排除删除／移出修订和域指令；含未解析对象时明确部分解析 |
| PPTX | 按 slide 文件编号排序可能颠倒实际页序；分组、表格、备注缺失 | 流式入口依照 presentation 关系表顺序读取并关联备注；内联入口补分组、表格和备注；包内路径校验，缺页、外链或重复关系不冒充完整文稿 |
| 旧 PPT | 仅顶层文字，漏分组及表格 | 两个入口共享显式栈遍历，保留原顺序和表格坐标 |
| PDF／ODF／WPS XML 路径 | 需要区分可读文字和未识别画面；部分解析页面却标为全文已索引 | 保留 PDF 文字首尾和逐页覆盖提示；ODF/WPS XML 不在中文 run 之间插空格，图片及嵌入对象给出覆盖提示；前端徽标改为“已建文档索引”，未解析部分仍显示来源及警告 |

错误处理：加密 PDF／表格提示先解密；损坏、扩展名不符等保留解析原因并给出检查或另存操作建议。XML 禁止 DTD 和外部实体；PPT 关系元数据单项 4 MiB、累计 16 MiB，正文维持已有 256 MiB 展开和 10,000 项限制，不因兼容性放宽安全边界。

验证证据：

- 修改前先用 6 项定向反例复现，4 项失败（XLS、XLSX、Word、PPTX），未以旧成功样本代替本次症状。
- 最终 53 项不同的相关后端测试通过：首轮 49 项共享回归通过，随后只重跑新增嵌入对象反例所在类（15 项，其中新增 4 项），不把重复运行加成 64 项。覆盖上传分片、50 MiB 文本尾部、配额、取消、所有权、视觉授权与部分覆盖；新增测试位于 `ComplexDocumentCompatibilityTest`。
- 前端类型检查和构建通过，构建仍有既有体积告警；本次只更改文档徽标文字，没有更换布局或设计体系。
- 独立 19000 后端、真实 Chrome、实际 HTTP 和固定合成账号完成 7 份文件从选择、上传确认、分片、解析、索引到上下文片段检索。5 份 READY；混合 PDF、含图片 ODT 正确为 PARTIAL；正文、单元格、公式、页序和尾部断言全部通过。
- 加密 PDF、缺页 PPTX、外部页面 PPTX 3 个反例均 FAILED 且错误可操作；未下载外部资料。确认上传前没有文档请求，模型与付费视觉调用为 0。桌面 1440×1000、手机 390×844 的警告、索引徽标和滚动可见性已核对，页面错误为 0。
- 本轮使用真实上传与解析服务，Provider 配为 Mock 仅避免模型调用；没有用 Mock HTTP 代替上传验收。日常 9000 后端未重启，验收进程和新建的合成文档按本轮范围清理。

原件、源码摘要、截图和去重测试数量见 [complex-documents](./evidence/file-workflow-2026-10-31/complex-documents/)。Word/ODF 等使用可控合成 XML 包验证解析机制，PPT/Excel/PDF 使用库生成文件，不等于全部办公软件版本的互操作认证。

范围限制：扫描图片、图表语义、复杂公式版式、SmartArt 和嵌入对象不承诺完整还原；现有视觉识别仍需用户明确授权，本轮未使用它填补文本提取缺口。旧专有 WPS、复杂 ODF 重复单元格／版式、不同厂商密码格式仍需真实样本覆盖。大目录速度、16 万文件与跨设备硬配额压力仍未关闭，不因本轮确定缺陷修复通过而宣布全部文件能力上线验收完成。
