## 2. 错误提示与失败恢复

确认的缺陷：空 DOMException 信息直接传给页面；失败状态持久化的二次异常可覆盖原始错误；启动清理删除所有 FAILED 索引；失败页没有继续入口，已保存的文件无法复用。

修复：统一配额、权限、文件移动、事务中断及未知错误提示；完整文件批次和检查点原子提交，当前事务回滚不扩大成功计数；保留失败任务至原定过期时间，继续时使用同一项目编号并按指纹校验，不重复索引已完整保存的文件；残缺文件重读。失败页明确显示检查点，清空与页面离开仍撤销当前任务，晚到响应不会复活状态。

定向验证：

- 81 项索引、目录、Worker 与相关组合式函数单元测试通过；初次空异常反例失败原因为 `expected '' to contain '存储空间'`，修复后通过。
- 真实 Chromium 的 450 文件样例在第 201 个文件写入时注入空 `QuotaExceededError`；200 个文件检查点及正文保留，清理不删除它们，继续后 450 个文件完整、200 个复用，末尾可检索。
- 桌面与手机使用生产 Worker、原生 IndexedDB 和 OPFS 文件，页面出现可读提示及继续按钮；点击后完成剩余 250 个文件。该异常是受控注入，不是占满用户磁盘的真实配额耗尽试验。
- TypeScript 检查通过；原有暂停、增量、隔离及正文完整性相关回归继续保留。

边界：刷新后仍不自动恢复页面选择；到期或用户主动删除后需要重新选择目录；不承诺所有浏览器/任意目录永不中断。真实浏览器硬配额不可依赖 CDP 覆盖值验收，本轮以真实事务异常注入验证失败分支，不伪称强制限额探针通过。

## 3. 文件数量、内容完整性与实际速度

真实本项目目录在数字词键候选下处理 21,578 个文件：21,316 个完整全文、16 个仅元数据、246 个按现有规则忽略、0 个读取失败。数据库 21,332 条文件元数据、39,630 个片段、260,032,407 个字符与引擎统计一致；23 份原始文件的正文 SHA-256 与尾部逐一一致，无提前显示 100%。这是已选范围及既有过滤规则下的核对，不等于磁盘所有文件或所有二进制内容都进入源码索引。

## 5. Edge 一直显示“正在统计 · 已发现 0 个文件”

用户在 Edge 中反馈选择目录后始终显示 0。本轮从 `9f06ab47` 的干净工作区开始，只处理本地索引启动和进度，不重跑完整导入或修改后端。

### 已确认的缺陷和现场证据

- `useProjectIndex.runIndex` 在调用旧库清理、保存目录授权和创建 Worker 之前，将页面状态设为 `SCANNING`。因此等待 IndexedDB 打开、升级或清理时也显示“正在统计 0 个文件”；此时实际上没有统计本次目录。
- 定向反例在旧库准备 Promise 未返回时运行真实组合式函数，修复前失败：`expected 'SCANNING' to be 'PREPARING'`。不是用构建成功替代故障复现。
- 只读查看用户 Edge 的 `localhost:5173` 索引目录文件元数据：12:53 约 6,131,898,083 字节，12:55 约 6,241,315,370 字节；LevelDB 日志持续出现写入、压缩整理及 memtable 等待。没有读取、导出或删除该浏览器数据库内容。该现象与旧库准备耗时一致，但未取得原页面 JavaScript 调用栈，不能据此断定所有等待都由某一步迁移造成。
- 原被其他页面阻塞的数据库打开请求报错后仍可能迟到成功，重新占据缓存连接。同步修复失败请求的晚到升级／连接处理，避免重试背后留下新连接。

### 修复行为

1. 增加独立准备状态：打开旧索引、升级旧索引、清理到期索引、保存目录授权、申请存储、启动 Worker、读取筛选规则分别报告。真正开始枚举后才显示文件统计。
2. 旧库迁移报告已转换片段／总片段，最后显示“正在提交本地存储”；不会将读取到最后一条等同于事务已成功，不伪造整体百分比。未放宽容量保护，正文、词表和迁移原子性保持不变。
3. 准备与目录枚举等待期间更新已用时间、当前位置，计数只来自真实进度。定时器在完成、出错、取消和页面离开时解除。
4. 尚未写入自身数据的新任务可立即取消，不再排队等待删除不存在的本次索引；不会删除旧项目，晚到准备完成也不再启动 Worker。共享旧库的兼容事务可能继续，不把取消当前目录任务描述为强制中止所有数据库操作。
5. 多标签占用时明确提示关闭／刷新其他同站页面并继续；失败请求的晚到升级回滚、晚到连接关闭，不覆盖重试连接。

### 验证和边界

- 88 项不同的相关单测通过：87 项索引／Worker／组合式函数回归，随后补验目录心跳类 13 项（其中新增 1 项），不重复累计。
- `PLAYWRIGHT_BROWSER_CHANNEL=msedge` 下 6 项真实浏览器检查通过：准备中取消与再次选择、450 文件失败恢复、旧库升级后的完整正文／全部词表／隔离及事务回滚。界面慢准备通过受控等待稳定复现；迁移和存储检查使用原生 IndexedDB。登录与模型目录使用现有 UI 测试夹具，没有进行真实账号或模型业务验收。
- 独立 Edge 实例取得实际本项目目录的原生授权句柄，约 199 毫秒首次发现非零文件，约 51.1 秒完成当前规则下 21,596 个文件的统计，随后进入索引并在 200 个文件检查点主动暂停。此检查只证明目录启动、统计和进入索引，不声称再次完成全目录索引；当时有原 Edge 磁盘写入及并行检查，不作为单独性能基线。
- 类型检查和构建通过，保留既有包体积告警。没有停止用户 Edge、删除其缓存、扩大文件排除范围或修改 9000 后端。

原件见 [index-startup](./evidence/file-workflow-2026-10-31/index-startup/)。旧页面已经在执行的请求不会自动换成新回调；刷新该页面后才使用新准备流程。用户原有大型旧库迁移耗时仍未完成专项验收，不能以独立 Edge 检查通过宣称它已提速或绝不会等待。

## 6. 新目录被共享旧索引阻塞：修复与完整目录复验

用户本次实际选择的是“智能流调”目录，截图在准备阶段已等待 13 分 49 秒，尚未开始统计。第 5 节只是阶段显示与局部恢复通过，不能用于宣称这个性能故障已经解决。

### 定位证据

- 基线提交 `948baeb7` 的 `runIndex` 在启动 Worker 前等待 `cleanupProjects`；这会打开并按第四版升级共享旧库，再读取所有旧项目并清理到期数据。新导入被无关旧项目的工作串行阻塞。
- 在用户正在使用的 Edge、同一 `localhost:5173` 站点执行本地诊断：普通旧库打开、普通新空库打开均长期不返回，站点存储估算约 7.28 GB；迟到的元数据返回旧库版本为 3。没有读取旧库源码，也没有删除、复制或重建用户原索引。尚未取得原页面 JS 调用栈，因此不将所有等待唯一归因于某条迁移请求。
- 同时创建的独立存储桶约 275 毫秒打开成功。接入真实生产仓库入口后，100 个合成片段准备、写入、末尾检索约 140 毫秒完成，默认存储仍在等待。诊断只清理自身的合成数据。
- 确定性回归先失败：旧库清理不返回时，新目录的 Worker 启动次数为 0。修复后新目录不再调用这个前置全库维护。

### 实现与保护边界

1. 新项目 ID 固定存储路由。支持 Storage Buckets 时，每个项目独立存储；不支持时使用独立命名的 IndexedDB。已使用桶的项目不能静默切换到默认空库。旧项目 ID 继续走原仓库，旧格式迁移与读取兼容代码保留。
2. 直接导入、暂停继续、增量刷新、上下文检索、取消及设置页清理共用路由。全文、全部检索词、原子检查点和项目隔离继续保留，跨项目混合批次拒绝写入。
3. 新导入不等待全局旧库维护；普通到期清理在完成后启动。独立桶按原保留期限设置过期时间，只有显式刷新才续期，持久保存设置落实到该桶。独立存储保持严格持久性提示，不靠降低耐久性换取提速。
4. 无响应的打开阶段 20 秒后明确报错，可重试；晚到的失败请求不覆盖有效连接。已经开始的旧版迁移继续保留原子性和真实进度，20 秒并非对整个迁移或整个导入的耗时保证。
5. 设置页仍能清理新旧索引，只作用于本功能命名空间；部分失败会明确报错。没有删除用户已有索引、放宽配额、扩大目录排除规则或缩短正文。无后端与模型协议改动。

依据：[Chromium 同站 IndexedDB 存储隔离说明](https://developer.chrome.com/blog/maximum-idb-performance-with-storage-buckets)、[Storage Buckets 保留期与持久策略](https://wicg.github.io/storage-buckets/explainer.html)。普通数据库改个名字仍可能共享底层存储队列，因此现场先验证桶隔离，而不是仅凭换库名宣称解决。
