# 文档上传并发与跨浏览器稳定性验收（2026-10-31）

本轮基于 `779a3d8c`，只修改文件上传及临时文档索引的调度、重试与清理机制。没有修改正文提取、分块、词表、摘要范围、模型配置或用户授权规则；没有调用付费模型。源码冻结摘要及结果见 [evidence](./evidence/file-workflow-2026-10-31/upload-stability/README.md)。

## 1. 根因与实现

| 已核实的问题 | 修复 | 保持的边界 |
| --- | --- | --- |
| 前端逐片等待响应，长往返时间累积；一份文档解析结束后才发送下一份 | 每份最多 3 个分片并发；普通文档最多 2 份流水处理。结果恢复用户选择顺序，进度固定显示最早未完成的文件 | 本批最多 6 个在途分片，不无限并发；含视觉审阅的批次仍串行，不叠加确认窗口 |
| 完成响应丢失后重发会被拒绝；单次轮询断网导致删除后台任务 | 同一文档的完成接口幂等，只返回原任务状态；分片、完成和状态请求仅对传输故障或 408/502/503/504 最多重试 2 次 | 创建和视觉确认不盲目重放；401/403/格式/容量/冲突不靠重复请求解决；用户取消仍停止所有在途分片，等待结束后清理 |
| 每个状态查询都同步清理所有过期文档；旧文档会话锁/磁盘操作拖住无关请求 | 单独维护线程每 60 秒清理；请求只判断当前文档归属及有效期；锁内复核期限后删除 | 过期立即不可访问，不以异步清理延长授权；不同用户、租户及工作区不能访问 |
| 并发创建的容量检查和登记不原子；索引/摘要阶段仍保留原件，却提前释放字节预算 | 原子检查并登记；原件实际删除后释放预算 | 50 MiB 单文档、512 MiB 活跃原件、100 文档限制不放宽 |
| 页面时钟被后台标签页节流后，固定总时限可能误判；长时间无进展仍高频查询 | 先获取服务端状态，再判断连续 10 分钟无进展；有实际阶段/字符/片段进展时更新期限；无变化轮询逐渐退避至 2 秒 | 有限重试与无进展时限仍存在，不承诺断网永不失败；排队、解析、索引和摘要的阶段耗时分别记录 |

后端线程池仍是原来的 2–4 个解析线程，没有通过放大并发或缩减正文提速。后台文档身份绑定服务端用户/租户/工作区，不绑定浏览器名称或 Cookie 会话编号。

## 2. 先失败、再验证

- 后端修改前 2 个新增反例均失败：READY 后再次 complete 被拒绝；旧过期会话锁被占用时，另一个文档的状态查询超过 500 毫秒。候选通过。
- 前端修改前复现串行上传、完成响应丢失失败、403 被重复发送；保留原件。首份测试夹具漏配删除请求返回值，产生额外 TypeError，修正夹具后再次复现目标错误，未把工具错误算作产品缺陷。
- 49 项不同后端检查通过：47 项共享检查，加 2 项定向追加检查。覆盖 50 MiB 文本/尾部、复杂文档、视觉授权、跨用户拒绝、乱序分片逐字节一致、同一分片重传不重复计数，以及 20 路同时预留 50 MiB 时仅允许 10 份。
- 42 项不同前端检查通过：40 项共享检查，加 2 项后台计时器暂停/取消并排空请求检查。并发文档乱序完成后仍按选择顺序返回；视觉审阅保持逐份执行。
- 12 次浏览器配置用例通过：Edge 桌面 6 次，Chrome 桌面/手机各 3 次。涵盖上传百分比、混合目录授权、视觉审阅及本地旧索引阻塞隔离。首次 2 个旧界面夹具因未隔离接口落到真实认证而失败；补齐测试隔离后通过，没有修改产品登录逻辑。
- TypeScript 与构建通过；保留既有大包体积告警。本轮不是全仓库回归或所有浏览器认证。

## 3. 同输入真实 HTTP 性能对照

固定 12 MiB 合成文本，包含首尾标记；每次核对上传字节数、提取字符数及尾部检索。使用同一个隔离后端，关闭付费向量/摘要模型，调用真实上传、解析和索引接口。旧前端取自 `779a3d8c`；因此下面隔离比较的是前端调度收益，不宣称测出了旧后端所有问题的改善比例。

每个浏览器按旧、新、新、旧的顺序运行。每个分片响应额外延迟 80 毫秒，模拟有往返延迟的链路；不修改实际文件字节或服务端结果。

| 浏览器 | 旧版上传均值 | 新版上传均值 | 旧版上传至索引完成均值 | 新版上传至索引完成均值 |
| --- | ---: | ---: | ---: | ---: |
| Chrome | 2,056 ms | 869 ms | 3,397 ms | 2,240 ms |
| Edge | 2,108 ms | 921 ms | 3,490 ms | 2,568 ms |

所有 8 份字节数及字符数均为 **12,582,912**；READY、尾部检索全部通过；旧版最多 1 片、新版最多 3 片在途。受控场景的上传阶段减少约 56%–58%。这是小样本调度证据，不是生产网络 SLA。

补充无人工延迟的本机 HTTP 单轮：Chrome 上传 874 → 503 ms、总计 2,197 → 2,118 ms；Edge 上传 1,016 → 664 ms、总计 2,343 → 2,294 ms。总耗时仅小幅下降，说明网络往返短时解析占比更大，不能宣称所有文件索引成倍提速。

## 4. 故障、跨浏览器与工作台

- Chrome/Edge 分别通过一次完成响应丢失、一次状态轮询连接重置：4 次独立故障注入均完成，无整份重传。真实服务处理请求，仅在返回通道注入故障。
- 首轮同时安排两种故障，但完成重试直接返回 READY，未触发状态轮询；原件 `passed:false` 保留。补充批次分别触发两种故障后 `passed:true`，不能用后续成功覆盖首轮未覆盖事实。
- 使用固定合成账号在两个浏览器分别正常登录；Edge 可读取 Chrome 创建的同一临时索引，两者刷新页面后仍可按文档 ID 获取 READY。没有复制 Cookie，也没有关闭身份隔离。这验证服务端索引不依赖浏览器会话，**不等于页面自动恢复文件选择**。
- 真实工作台完成 Word、XLS、XLSX、PPT、PPTX、PDF、ODT 共 7 份文件的选择、上传确认、解析、索引、引用分析。5 份 READY、2 份正确 PARTIAL；单元格、公式、修订、页序、尾部断言通过。加密 PDF、缺页/外部页面 PPTX 3 个反例正确 FAILED。桌面/手机的警告、徽标与滚动展示通过，页面异常和付费调用均为 0。
- 旧版 TypeScript 对照模块首次未转换，验收脚本加载失败；修复工具后才执行正式对照，保留工具失败原件，不记作产品性能失败。

## 5. 完成范围与后续边界

本轮关闭有证据的串行等待、暂时传输失败处理、无关过期清理阻塞及并发容量检查缺陷。未改变本地源码索引内容；上一轮按项目独立存储的修复继续保留，并补验 Chrome 的原生 IndexedDB 隔离路径。

不能承诺任意环境耗时完全相同或永不超时：磁盘、CPU、浏览器节流、网络和文档复杂度仍有影响。普通网页没有跨浏览器共享本地 IndexedDB 的能力；新浏览器首次读取本地源码仍需用户重新授权和建索引，不能为绕开它自动上传源码。

临时文档仍是当前后端进程持有、按现有期限保留的数据；服务重启会失效。关闭/刷新页面不会自动恢复选择列表；长时间断网超过有限重试、过期、主动撤销后仍可能需要重选。跨页面恢复入口、可靠断点续传、跨实例持久任务队列及更广泛硬件压力测试属于后续工作，没有标为本轮通过。

保留期、权限和内容完整性优先于性能数字。后续若继续优化，先依据 queueDurationMs 和各阶段日志区分排队、解析、索引、摘要耗时，再以相同完整文件比较；不直接提高并发、关闭安全检查或减少读取范围。
