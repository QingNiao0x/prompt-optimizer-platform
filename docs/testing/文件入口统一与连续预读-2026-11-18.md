# 文件入口统一与连续预读

## 第三阶段

文件多选和拖入的源码、普通文本及混合材料使用项目索引生产 Worker。保留 File 与显式路径快照，复用范围规则、敏感过滤、全文分块、词表、容量预算与检索。二进制文档保留确认流程。多次选择沿用现有项目来源替换语义，文件快照的增量刷新检查已选择内容，重新读取磁盘新版本需重新选择文件。

真实 Chrome 回归完成 1005 个源码文件及重复名、根忽略规则、敏感文件夹具。长源码全文/尾部一致，超过旧千文件限制，Worker 克隆后路径与根忽略规则有效，索引来源快照可从数据库恢复。113 项受影响单测通过。其他来源如手工粘贴仍使用既有入口。

## 第四阶段

200 改为未消费槽位上限，最多六路读取，预读字节上限 4 MiB。前面文件就绪即可消费，在数据库提交期间继续补读；数量或字节满时停止补充。来源批次仍为 200，读写重叠发生在批次内部。消费保持来源顺序，大文件流式读取，暂停停止补充并等待在途读取结束，写入队列仍串行。预读字节和待写批次各自有界，各自约 4 MiB，解码和词表另占内存，该值不是整个进程内存上限。

114 项相关单测通过，新增近 64 KiB 文件的字节背压全文回归，重叠测试验证首批写入前无需读完 200 文件、写入等待期间读取继续、最大六路、暂停后无迟到写入及恢复完整。Chrome 的文件入口、性能、进度和恢复六项回归通过，补充普通工作台文件多选入口回归通过。Edge 文件入口、进度及恢复五项通过。类型检查和生产构建通过，构建保留既有依赖注释和产物体积警告。

发现文件来源快照会在 Worker 识别前保存，补齐敏感路径与含凭据 .npmrc 在持久化之前排除，并计入范围排除数量。工作台回归加入合成敏感夹具。文件来源仍遵守用户配置的保留期，暂不自动跟踪磁盘变化。

真实 Edge 对 services/api/src 进行旧→新→新→旧四轮。1115 文件、1113 全文、2 二进制跳过。四轮逐文件全文及尾部 1113/1113，完整词表、符号和引用规范化摘要一致，656024 词关联、1661 片段，失败及容量限制均为零。旧版 18.965 / 25.310 秒，新版 17.069 / 15.797 秒，均值约 22.137 → 16.433 秒，本样本下降约 25.8%。新版首批提交约 0.995 秒，旧版约 1.103–1.131 秒。实际预读峰值 172/179 槽位、1,642,191 字节，未超过上限。

第一轮与构建结束的时间可能重叠，第四轮旧版也有较大写入波动。脚本 stableImprovement=true 仅表示该小样本数值达到判据，不证明更广目录的稳定提速。新版没有重新执行整个项目根目录，上一阶段整目录完整性结论仍属于当时版本。证据见 evidence/index-pipeline-2026-11-18，固定源码目录输入未变化。重放应冻结候选源码，输出到独立 tmp 目录。

下一阶段可按阶段计时继续优化扫描及增量缓存，当前任务在第三、第四阶段交付后停止。
