## 根因与修复

1. 旧字段过滤只匹配“哪些字段”等固定问法，随后“是否”被当作新的选择；复合句又被统一保留。因此“已经选定整组字段，是否仅选部分”会漏过。新的 `PlanningDecisionPolicy` 从本次需求和合格来源建立 `PlanningKnownDecision`，同时供模型输入和服务端过滤使用，按作用对象、条件和效果分别判断。
2. 字段集合必须有本次选择与真实源码声明；声明冲突、缺席、测试示例或用户重开选择时不认定已知。只填空值、取消不写表单、排序、无匹配弹窗等分别建立规则，不能用“字段范围已知”回答脱敏、源数据缺失、后端回滚等独立问题。
3. 已有工程的地区判定算法和测试层属于核查职责，不升级为已经实现的事实；明确要求用户选择算法、测试策略任务、迁移、性能阈值等问题继续保留。范围未确定时继续提问。
4. Plan 原来只为相关 Java/XML/SQL 源码附详细摘录，TS/JS/Vue 可能只留下摘要。现在在原有最多六份相关源码摘录预算内覆盖前端类型；文件选择、长度、来源用途及凭据过滤继续生效，不读取额外文件。
5. 已声明的研究未实施状态、未来按数据分布选择检验、公平对照确认信息一致，不再变成可省略的确认题；具体评分维度、操作性定义、检验阈值和随机化等仍可提问。
6. 原始需求限定地区范围、资料明确服务端过滤职责时，不再复核同一个范围或职责。已要求补测试的业务分支不能再次成为可省略选项；只有每个候选均逐条对应已有规则时才过滤，包含新权限、缓存、超时、其他模块等条件的问题继续保留。
7. “覆盖到哪一层”属于工程测试层；“先查询详情再填充”是写入前提，不能提供跳过详情的方案。新的地区空值问题可保留，但不能提供忽略已定地区条件的候选；这类违约候选按 `RULE_CONFLICT` 使用原有调用预算修复，持续违约仍明确失败。
8. “只填 null 或空字符串”逻辑上已排除覆盖所有其他非空值，不仅保护 `0 / false`。处理非空值的换一种问法不再重新开选择；来源标注、校验、审计、反馈等独立规则继续保留。测试覆盖同时包含地区、双键、排序和写入时逐维度核对；缺项提示或新建记录等新效果不能借已有规则被静默过滤。
9. “不做地区范围过滤”“不限定地区”等仍是绕过已定范围的候选，使用同一 `RULE_CONFLICT` 校验；禁止这些行为的表达不会误拦。接口、交互和组件测试也属于工程测试层，但新增权限、负载、预算或测试数据要求继续保留。短动作标签如“不查询”必须连同答案的条件和对象取得完整证据，不能把姓名缺项条件借给地区缺失条件；完整同条件的推荐仍有效。
10. `TEST_TARGET_LOOKUP` 区分本次修改影响的测试对象与新的测试范围选择。执行 Agent 核查调用关系并验证受影响模块，不把文件存在写成所有模块都属于本次业务，也不让用户将已要求的影响路径验证缩减成仅一个模块。用户明确要求选择覆盖范围、其他业务模块、成本或新指标时继续提问。
11. 论文原文要求盲评时，评审不获知实验条件是已定要求，不再重开为“知道条件但独立评分”。具体匿名编码、展示顺序和评分维度继续保留。公平对照可以选择呈现方式，但相同轮次不能替代同样确认信息；各自生成内容的候选必须明确保证信息一致。禁止披露的句子不会被当作披露，原文未规定或主动重开这些要求的研究继续保留选择。
12. 泛指“每个任务”“哪些模块”等语法不作为其他业务对象。测试选项的模块名与中文别名不同，只有项目文档明确列出本任务类别的模块及共同调用文件、该调用文件确实属于已提供项目源码时，才复用这项影响路径核查职责；退款等其他类别及新权限、指标仍保留。不把文档中的调用说明升级为已经验证的实现。
13. 测试题同时列出影响模块、接口层、界面层和既定边界时，逐项核对工程职责与证据；包含新的缺项反馈或其他接口时保留整题。枚举中的“无匹配不弹窗”不能被误关联为“缺项需要弹窗”。“不新增判定方式”属于沿用工程，不作为新增需求；“确认信息内容”与“确认内容”均须遵守已有的信息一致规则。
14. “未提供的工程细节先核查”是明确的条件化工程指令，不能让前面已选择的阈值整题回退为未确认；具体版本、生效日期或业务口径尚未确定仍保持未决。回放验证 50000 元取代旧 30000 元后，新 80000 元材料应与已选 50000 元比较。
15. 原始研究对象明确为 Plan 问答时，基础条件继承为交互澄清后生成，不再把“不交互的静态计划模板”作为同义候选。操作性定义、示例、提问轮次及终止方式等真实参数继续保留。已限定论文方法提纲时，不强迫用户再选择是否加入背景、意义或文献综述；主动重开定义或交付范围时不复用旧决定。
16. 修改目标同时指定两个业务对象，且文档提供同类别模块映射并对应已上传源码时，将该修改范围作为内部已定维度，不让用户再次缩减为一个模块。单一业务目标、冲突声明、缺少引用源码、主动重开及额外行为继续保留问题；不将文件夹中所有模块都算作本次范围。“前端两个模块”等工程分类不误识别为另一业务名称，地区测试复述按已定成员范围核对。
17. 地区空值的处理仍可问，但“不附加地区条件”是放宽既定范围的候选，须使用原有预算修复。前端不携带地区查询参数、服务端仍按当前用户地区过滤的正常工程实现不误拦；禁止放宽地区条件的句子也不误拦。
18. 题干中的“是否还需要覆盖”和候选中的“补测试覆盖”是工程动词，不作为接口或模块名字。候选逐项核对，真实退款对象和缺项反馈保持可问。题干泛问其他字段时，独立校验或业务判断仍保留，但不能以该用途为理由扩充已定填充集合；已定 null/空字符串条件的复述仍正常去重。
19. 已定地区需求的前后端改动层交由执行 Agent 核查实际影响，而非让用户按文件有无选择。仅识别纯工程层候选；新增业务、跨租户权限、字段来源、性能参数和用户主动要求选择前后端范围时继续保留问题。该规则不宣称服务端已实现所需业务。
20. 公平对照已明确两组获得同样确认信息时，不允许将确认信息省略；信息可以预先写入而无需再次交互，但仅保证初始提示词或轮次相同不能替代信息一致。
21. 缺失答卷的状态和分母是否纳入是不同维度。逐个映射动作核对最近的作用对象与否定，允许“不得将缺失答卷视为未完成或零值”，但前一句禁止不能保护后一句正向混同。为研究设计与缺失状态添加条件化模型指令，并沿用共享三次修复预算；未提供的数据不产生计算结果。
22. 原文要求填充前确认时，“匹配后直接填充、用户可撤销”不能替代事前确认。确定的直接填充候选触发 `RULE_CONFLICT`，事前确认和禁止直接填充的合法句子不误拦。未知的提示界面仍可询问，不全禁交互选项。
23. 已定匹配范围和匹配成功后提示构成同一条件时，提示继承该范围；不把本级与下级重新作为选择。不同人群、确认粒度、反馈、重试、来源及用户主动重开仍是独立问题。对象识别不跨过“模块、接口”等后缀拼接连续文案，泛指“一个/两个模块”不冒充新业务；退款等具体新对象继续保留。首次回放与保护反例的失败均留档。
24. 论文方法提纲已限定且设计明确时，组织研究设计、实验条件、评审流程、分析原则及研究边界属于写作职责，不将既定部分再变成可省略选项。只有这些部分的依据均存在才分流；新数量、阈值、具体评分尺度、抽样与用户主动重开继续保留。禁止编造效应量的边界说明不是一个新的效应量参数，不能因同一关键词误保留整题。
25. 测试范围的“如何界定验收”问法与覆盖哪些模块属于同一工程职责，不再提供仅测核心逻辑、忽略已有填充路径的默认选择。逐个候选核对范围与新维度；退款、负载、字段来源、日志与测试数据仍保留。仅在泛指受影响对象前拆开“本次改动涉及的全部”语法，不删除具体业务名字。
26. 原文要求根据未来数据分布选择检验时，候选不能将预先定案主要或具体检验替代该前提。合法的候选列表、仍依据未来数据选择实际方法的条件方案、禁止提前定案的表述均保留；未规定该选择原则的预注册任务不套用本规则。按动作邻近否定核对，不让“不得编造数据”保护后一句提前定案。
27. 工程范围分类保留逗号、顿号等语法边界，先拆独立分支，再归一化动作。此前“无匹配不弹窗、接口异常”可能被拼成虚构接口名，导致已定测试范围误留。只有已明确查询详情前提时才识别相应流程修饰语；退款等真实新流程不借用该证据。测试题包含响应时间、吞吐量、并发数、覆盖率等新指标时，先保留这些独立维度，不能按一般测试职责过滤。
28. 已定地区条件不能被“只要姓名和身份证号匹配即算当前地区记录”替代；地区缺失题的候选同样必须遵守该前提。条件化分步查询、查询后服务端按地区过滤、禁止放宽范围、其他业务对象和用户主动重开仍保持可用。此为带作用范围的候选校验，不代表穷尽所有语义改写。

决定清单是内部模型输入，不是用户确认答案，不持久化为新的业务事实，也不能由客户端传入以绕过过滤。绑定 Plan 与最终确认的外部请求字段保持兼容。

## 论文 502：已知与无法确认的部分

历史请求 `464500fe-728a-4bae-a78c-0caaa90be907` 的旧控制台日志未保留，无法确定那次是结构、业务规则、截断或其他校验失败。不得将后续成功当成该次失败根因已经修复。

已复现诊断缺口：非法 Plan JSON、缺少问题数组、非法题型、空模型正文、输出截断原来只有通用错误，无法记录固定校验原因。现在使用 `ProviderResponseValidationException`，实际兼容适配器记录 `event=model.response.validation_failed` 的 `reason`、`field`、`attempt`，失败响应保留 `502 / RESULT_INVALID`。

`error.details` 可追加：

| 字段 | 类型与范围 | 含义 |
| --- | --- | --- |
| `validationReason` | 固定服务端枚举，条件返回 | 如 `PLAN_JSON_INVALID`、`PLAN_QUESTION_INVALID`、`RESPONSE_EMPTY`、`RESPONSE_TRUNCATED`；不含模型值 |
| `validationField` | 最长 120 字符的代码定义路径，条件返回 | 如 `plan.json`、`questions.type`、`response.finishReason`；不是用户文件路径 |
| `modelAttempts` | 已附加核实次数时返回，当前 1—3 | 本次失败真正执行的模型请求次数；无法提供核实次数时省略，不推测次数 |

验收脚本只保存上述白名单字段，不整体保存错误详情、原始模型正文、认证头或解析异常消息。解析与业务校验继续共享最多三次上游调用；没有增加独立语义评判调用，也没有取消安全或保真校验。
