# 提示词执行目标与上下文补全修复

日期：2026-10-12。针对用户的股票分析助手截图实施修复，保留此前 P0、P1、需求保真边界及其他未提交修改；未提交、推送或生产发布。

**结论：已修复本轮确定的交付层级、已知信息重问、空上下文盘点和角色启动分支缺口。本地后端已加载修复。真实作品能够交付分析，但仍有无依据推断和冗余，整体增强质量不通过，ME-02／03／04／06 及 G1—G8 不关闭。**

## 1. 分层定位

| 现象 | 核实结果与根因 |
| --- | --- |
| 角色指令变成另一份提示词 | 截图中 TASK 要求“整理为一份……提示词”，OUTPUT 要求“交付……提示词文本”。这是增强输出改换下游任务，不是单纯下游不服从。原有 `DraftDeliveryContract` 主要保护正文目标，角色／通用任务会提前退出，错误层级能被组装放行。 |
| Mock 只包装任务说明 | `buildTask` 在原文外加“落实为任务说明”的元指令；无上下文时背景采用缺失信息说明。Mock 是确定性实现，不能据此假定截图使用了 Mock，也不能把修改 Mock 当作修复真实供应商。 |
| 已给信息继续进入待确认项 | 直接增强和 Mock 原先没有复用 Plan 已有的事实、常规组织过滤。模型候选中的已知地区、语言或普通章节组织仍可能被组装为执行前提。 |
| 背景盘点未上传材料 | 本轮第一份真实 Flash 结果仍列出未提供项目文件、代码和历史。模型请求直接暴露完全空的辅助快照，已有 system 指导未阻止其变成任务背景。保留该失败，不把首次 HTTP 成功算作通过。 |
| 角色启动变成四项问卷 | v3 已修正执行目标，但真实 Flash 只收到角色时仍套用报告格式，要求市场、标的、问题类型和时间范围。system 中的启动分支没有落实到复制正文。角色本身没有本次具体问题，简短请用户提出问题合理，不能臆造股票或强制用户先填四项。 |
| 分析中出现无依据推断 | 原始提示词与优化提示词都没有提供市场份额、成本或应收变化事实；真实 Pro 却从收入增长推断市场份额或需求没有萎缩。这是下游推断越界；末尾再写资料有限，不能抵消前文断言。 |

上一轮需求边界修复覆盖的是虚构数据例外、检验条件变禁令、方法确认扩大到参数；没有证明上述任务层级与角色启动行为已解决。本轮分别定位，不能将上一轮局部通过称为整个增强功能完成。

## 2. 本轮实现

- `DraftDeliveryContract` 对非提示词创作任务统一检查 TASK／OUTPUT，阻止把执行改成编写另一份提示词；显式写提示词、否定和引用正例继续通过。`DELIVERY_LEVEL_CONFLICT` 使用既有最多三次总尝试修正错误段，不增加预算。
- `PromptOptimizationGuidance` 和真实 Provider 的 system 区分平台产物与下游交付，正向要求补充输入使用、执行步骤、普通边界和结果检查。具体地区、技术栈、参数须有适用依据，不能将专业候选当作用户选择。
- `PlanQuestionFilter.unresolvedFindings` 供直接增强、Mock、组装共用已知事实和常规组织判断。使用本次安全上下文及已筛选事实卡；未决绑定和用户明确保留的问题仍独立处理。语言识别不再把否定、未来条件或示例中的技术名称视为当前选择。
- Mock 的任务直接保留有效执行指令；无额外描述时从原始提示词提取背景，避免缺项套话。
- 真实 Provider 仅省略完全空的辅助上下文和空历史。已有描述、文件、覆盖信息、解析失败和脱敏提醒继续保留；没有改变公开 `ContextSnapshot` 或前端资料状态契约。
- 最终组装为直接角色指令增加有条件的输出分支：已有问题或材料就执行；仅有角色时简短进入角色，不生成空分析章节或启动问卷。限于识别到的通用角色任务，显式提示词创作、先问、禁问及严格输出不被覆盖。

本轮没有以猜定地区、默认编程语言、选定未知统计口径来消除待确认项；已知地区与独立寿命表选择、冲突地区、新范围、用户明确先确认章节都有正反例。规则覆盖仍有限，不能声称所有语言、表达和专业场景都已语义理解。
