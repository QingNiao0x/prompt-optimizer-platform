# 使用 PostgreSQL 作为主数据库、Redis 作为短时基础设施

状态：accepted。项目选择 PostgreSQL 存储租户、工作区、优化历史和用量事件，选择 Redis 支撑限流、短时上下文、幂等键和会话元数据。模型供应商凭据与默认路由由平台运行环境管理，不保存为用户业务数据。理由是业务数据具备明确关系和事务需求，同时上下文摘要需要 JSONB 的演进能力；Redis 数据可过期且不承担主数据职责。

## 考虑过的选项

- MySQL：可行，但 PostgreSQL 的 JSONB、全文检索和扩展能力更贴合上下文/元数据场景。
- MongoDB：灵活，但会削弱租户、用量和计费数据的关系约束，首发阶段收益不足。
- 仅使用数据库缓存：无法同时满足高频限流和短 TTL 状态的低延迟需求。
