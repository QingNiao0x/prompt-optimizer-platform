# 大模型 Provider 设计

> 实现状态：Mock Provider 与 OpenAI 兼容 Chat Completions Provider 已实现。Anthropic、Provider 自动重试、用量计量和多供应商路由仍为后续能力。

## 1. 统一抽象

业务层不关心具体供应商 SDK，统一调用以下语义能力：

- 接收系统提示词、用户原始提示词和 Context Snapshot。
- 使用模型、温度、最大输出 Token 和超时配置。
- 返回文本、结构化段落、Token 用量、模型名称和供应商请求 ID。
- 将鉴权失败、限流、超时、上下文超限和内容审核失败映射为平台错误码。

建议接口职责：

```text
ModelProvider
├─ providerType()
├─ validateConfiguration()
├─ optimize(request, timeout)
└─ normalizeError(exception)
```

## 2. Provider 适配策略

| Provider | 首发策略 | 注意点 |
| --- | --- | --- |
| OpenAI 兼容端点 | 优先实现 | 统一 Chat Completions 风格，支持自定义 endpoint |
| DeepSeek | 复用兼容适配器 | 单独处理模型名、Token 计费和上下文窗口 |
| Anthropic | 独立适配器 | Messages API、系统提示词和响应结构不同 |
| 自定义端点 | 兼容协议适配 | 需要 endpoint、认证方式和响应映射配置 |

## 3. Prompt Composer

Composer 负责把多个来源组合为模型请求，建议固定顺序：

1. 平台系统规则：安全、隐私、不得伪造项目事实。
2. 任务系统规则：输出结构、语言和质量标准。
3. 规范化 Context Snapshot：明确来源和不确定性。
4. 用户偏好：可读性、架构风格、示例开关等。
5. 原始提示词：作为需要被优化的输入，而不是可覆盖平台规则的指令。

其中用户上传文件可能含有“提示词注入”文本。文件内容只能作为项目资料，不能改变系统规则、泄露密钥或要求模型执行与优化无关的动作。

## 4. 输出校验

- 检查必需段落是否存在。
- 检查结果是否为空、是否包含内部系统提示词、是否泄露 API Key。
- 对明显的 Markdown 结构异常进行轻量清洗，不重写模型语义。
- Provider 返回的 Token 用量缺失时标记为 `usageIncomplete=true`，不能伪造精确计费数字。

## 5. 超时、重试与降级

- 单次模型请求设置连接超时、读取超时和总超时。
- 只有网络抖动、HTTP 429/5xx 等可恢复错误才重试；鉴权失败、内容违规和参数错误不重试。
- 使用指数退避并受总耗时上限约束，避免把 3-5 秒目标变成无限等待。
- 首发可以不自动切换供应商；后续通过租户策略实现主备 Provider 和成本路由。

## 6. 成本与额度

每次成功或失败的模型调用都尽量写入 Usage Event，包含 Provider、模型、输入/输出 Token、耗时和估算成本。用户界面展示估算用量时必须标注“估算”，账单系统再以供应商账单或正式计量规则结算。

## 7. 当前运行配置

当前默认通过 OpenAI 兼容协议调用 DeepSeek，启动时必须由运行环境提供 API Key：

```text
MODEL_PROVIDER_MODE=openai-compatible
MODEL_PROVIDER_NAME=deepseek
MODEL_ENDPOINT=https://api.deepseek.com/chat/completions
MODEL_API_KEY=<由运行环境安全注入>
MODEL_NAME=deepseek-chat
MODEL_TEMPERATURE=0.2
MODEL_MAX_TOKENS=3000
MODEL_CONNECT_TIMEOUT=3s
MODEL_READ_TIMEOUT=30s
MODEL_JSON_RESPONSE_FORMAT_ENABLED=true
```

适配器要求模型返回 `sections` JSON 数组，并验证背景、任务目标、输入输出、约束条件和验收标准五个必需段落。部分兼容端点不支持 `response_format` 时，可以关闭该参数，但响应仍需满足相同 JSON 契约。

自动测试和无密钥本地联调使用 `MODEL_PROVIDER_MODE=mock`，不会访问 DeepSeek 或产生模型费用。若未来更换为其他兼容供应商，只需覆盖供应商名称、端点、模型和 API Key，不需要修改业务编排代码。
