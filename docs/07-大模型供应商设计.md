# 大模型 Provider 设计

> 实现状态：Mock Provider 与 OpenAI 兼容 Chat Completions Provider 已实现。结构化响应无效时的有限修复重试、服务端模型白名单和 DeepSeek/TokenHub 多供应商路由已内置；Anthropic 与用量计量仍为后续能力。

## 1. 统一抽象

业务层不关心具体供应商 SDK，统一调用以下语义能力：

- 接收系统提示词、用户原始提示词和 Context Snapshot。
- 使用模型、温度、最大输出 Token 和超时配置。
- 返回文本、结构化段落、Token 用量、模型名称和供应商请求 ID。
- 将鉴权失败、限流、超时、上下文超限和内容审核失败映射为平台错误码。

建议接口职责：

```text
ModelProvider
├─ providerType()
├─ validateConfiguration()
├─ optimize(request, timeout)
└─ normalizeError(exception)
```

## 2. Provider 适配策略

| Provider | 首发策略 | 注意点 |
| --- | --- | --- |
| OpenAI 兼容端点 | 优先实现 | 统一 Chat Completions 风格，支持自定义 endpoint |
| DeepSeek | 复用兼容适配器 | 单独处理模型名、Token 计费和上下文窗口 |
| Anthropic | 独立适配器 | Messages API、系统提示词和响应结构不同 |
| 自定义端点 | 兼容协议适配 | 需要 endpoint、认证方式和响应映射配置 |

## 3. Prompt Composer

Composer 负责把多个来源组合为模型请求，建议固定顺序：

1. 平台系统规则：安全、隐私、不得伪造项目事实。
2. 任务系统规则：输出结构、语言和质量标准。
3. 规范化 Context Snapshot：明确来源和不确定性。
4. 用户偏好：可读性、架构风格、示例开关等。
5. 原始提示词：作为需要被优化的输入，而不是可覆盖平台规则的指令。

其中用户上传文件可能含有“提示词注入”文本。文件内容只能作为项目资料，不能改变系统规则、泄露密钥或要求模型执行与优化无关的动作。

## 4. 输出校验

- 检查必需段落是否存在。
- 检查结果是否为空、是否包含内部系统提示词、是否泄露 API Key。
- 对明显的 Markdown 结构异常进行轻量清洗，不重写模型语义。
- Provider 返回的 Token 用量缺失时标记为 `usageIncomplete=true`，不能伪造精确计费数字。

## 5. 超时、重试与降级

- 单次模型请求设置连接超时、读取超时和总超时。
- 只有网络抖动、HTTP 429/5xx 等可恢复错误才重试；鉴权失败、内容违规和参数错误不重试。
- 使用指数退避并受总耗时上限约束，避免把 3-5 秒目标变成无限等待。
- 用户选择的模型通过服务端模型目录路由到对应供应商；当前不做失败后的隐式跨供应商切换，避免用户不知情地改变成本、数据流向或输出行为。

## 6. 成本与额度

每次成功或失败的模型调用都尽量写入 Usage Event，包含 Provider、模型、输入/输出 Token、耗时和估算成本。用户界面展示估算用量时必须标注“估算”，账单系统再以供应商账单或正式计量规则结算。

## 7. 当前运行配置

当前通过 OpenAI Chat Completions 兼容协议调用 DeepSeek 与腾讯云 TokenHub。TokenHub 的服务地址、API Key 和模型白名单均由 API 服务端持有：

```text
MODEL_PROVIDER_MODE=openai-compatible
MODEL_MULTI_PROVIDER_ENABLED=true
MODEL_DEFAULT_PROVIDER=tokenhub
MODEL_TOKENHUB_ENDPOINT=https://tokenhub.tencentmaas.com/v1/chat/completions
MODEL_TOKENHUB_API_KEY=<仅在 API 服务运行环境中安全注入>
MODEL_TOKENHUB_NAME=deepseek-v4-pro-0813
MODEL_TOKENHUB_MODELS=deepseek/deepseek-flash,deepseek-v4-pro-0813,kimi-k3,kimi-k2.8-preview,kimi-k2.7-code,glm-5.3,glm-5.3-flashx,hy4-preview,hy3,minimax-m3
MODEL_CATALOG_HIDDEN_IDS=deepseek:deepseek-chat,deepseek-chat
MODEL_DEEPSEEK_ENDPOINT=https://api.deepseek.com/chat/completions
MODEL_DEEPSEEK_API_KEY=<可选；仍保留旧 DeepSeek 路由配置>
MODEL_DEEPSEEK_NAME=deepseek-chat
MODEL_DEEPSEEK_MODELS=deepseek-chat
MODEL_TEMPERATURE=0.2
MODEL_MAX_TOKENS=10000
MODEL_CONNECT_TIMEOUT=3s
MODEL_READ_TIMEOUT=60s
MODEL_JSON_RESPONSE_FORMAT_ENABLED=true
```

`application.yml` 已提供 TokenHub 模型 ID 列表的默认值，因此未单独设置 `MODEL_TOKENHUB_MODELS` 时，只需在 API 服务运行配置中提供 `MODEL_TOKENHUB_API_KEY`。默认使用 `deepseek-v4-pro-0813`（DeepSeek-V4-Pro）；若 IDEA 或部署环境显式设置了 `MODEL_TOKENHUB_NAME`，该值会覆盖默认模型。服务端会将十个产品模型按下表顺序固定展示；额外配置的 TokenHub 模型保留在这十项之后，不会打乱它们。模型是否能成功调用仍取决于该 TokenHub Key 是否已开通相应模型。TokenHub 以 `deepseek/deepseek-flash` 调用 DeepSeek-V4.1-Flash；旧的 `deepseek-chat` 路由配置仍可保留，但默认从用户目录和模型选择校验中隐藏。

TokenHub 模型的客户展示名与上游调用 ID 分开维护：

| TokenHub 官方展示名 | 服务端调用 ID |
| --- | --- |
| DeepSeek-V4.1-Flash | `deepseek/deepseek-flash` |
| DeepSeek-V4-Pro | `deepseek-v4-pro-0813` |
| Kimi K3 | `kimi-k3` |
| Kimi K2.8 Preview | `kimi-k2.8-preview` |
| Kimi K2.7 Code | `kimi-k2.7-code` |
| GLM-5.3 | `glm-5.3` |
| GLM-5.3-FlashX | `glm-5.3-flashx` |
| Hy4 preview | `hy4-preview` |
| Hy3 | `hy3` |
| MiniMax-M3 | `minimax-m3` |

展示名以官方模型列表为准；模型下拉框只显示展示名，不把供应商路由标识拼在名称右侧。

DeepSeek-V4.1-Flash 的 TokenHub 调用默认启用思考。由于本项目的 Plan 与最终增强请求都要求 `json_object` 结构化响应，适配器仅对该模型的这类结构化请求发送 `thinking.type=disabled`，以符合 TokenHub 关于思考模式与 JSON 输出的兼容建议；其他模型和非 JSON 请求不受此规则影响。关闭显式思考可能降低多步复杂任务的推理深度，若后续评测显示质量下降，应针对该模型单独做保留思考与结构解析方案的 A/B 验证。

适配器要求模型返回 `sections` 和 `ambiguities` JSON 数组，并验证背景、任务、输出和约束四个必需段落；验收标准可由结果组装器补充。`ambiguities` 是模型在同一次调用中联合分析原始需求、实际上下文和启用的会话历史后得到的具体未决问题，允许为空，最多 8 条、每条不超过 500 字符。输入中的规则候选必须重新核验，不得机械照搬。部分兼容端点不支持 `response_format` 时，可以关闭该参数，但响应仍需满足 JSON 契约。

工作台通过认证接口读取模型目录形成模型选择器；多供应商模式返回 `tokenhub:deepseek/deepseek-flash`、`tokenhub:kimi-k3` 这类带路由前缀的模型 ID。用户提交的模型 ID 会随计划请求和最终增强请求传到业务层，并在适配器中再次按服务端白名单校验。只有公开模型 ID 会出现在浏览器请求中，端点和 API Key 仍由 API 服务环境变量持有。启用 DeepSeek 与 TokenHub 时设置 `MODEL_MULTI_PROVIDER_ENABLED=true`，并分别配置 `MODEL_DEEPSEEK_*` 与 `MODEL_TOKENHUB_*` 变量。

旧模型只返回 `sections` 时仍兼容：应用层从 `CLARIFICATIONS` 读取问题，无该段时才采用保守规则候选。显式返回 `ambiguities: []` 表示无歧义，不触发兜底；类型错误、超限和敏感内容则返回 `RESULT_INVALID`，不会伪装成功。完整流程见[直接增强中的上下文感知歧义检测](./12-内置Plan-Mode交互与接口.md#61-直接增强中的上下文感知歧义检测)。

自动测试和无密钥本地联调使用 `MODEL_PROVIDER_MODE=mock`，不会访问 DeepSeek 或产生模型费用。新增 OpenAI 兼容供应商时，只需增加服务端路由配置，不需要修改业务编排代码；失败后的隐式跨供应商降级仍需显式产品策略。
