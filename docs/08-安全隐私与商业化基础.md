# 安全、隐私与商业化基础

## 1. 威胁模型

- 未授权用户读取其他租户的历史或 Provider 配置。
- 用户上传恶意压缩包、路径穿越文件或超大文件。
- 项目源码中包含 API Key、私钥和数据库密码。
- 用户文件内容对模型发起提示词注入。
- Provider API Key 出现在日志、错误响应、前端状态或历史记录中。
- 恶意用户刷模型额度、绕过限流或伪造工作区 ID。

## 2. 必须执行的控制

- 所有查询按认证主体和 `tenant_id` 过滤，不能只相信客户端传入的工作区 ID。
- API Key 使用 AES-256-GCM 加密，主密钥来自环境变量或 KMS；数据库只存密文和密钥版本。
- 日志采用结构化脱敏，禁止记录完整请求体、源码、Authorization、API Key 和 Cookie。
- 上传文件使用白名单、大小上限、扩展名与 MIME 双重校验、路径规范化和病毒/敏感信息检测。
- Redis 限流按 IP、用户、租户和 Provider 多层限制；优化接口使用幂等键。
- 生产环境启用 TLS、CORS 白名单、CSRF 策略、Secure/HttpOnly Cookie（如使用 Session）和安全响应头。
- 所有外部 URL 访问禁止由用户任意控制，防止 SSRF；自定义 Provider endpoint 必须经过协议、域名和网络策略校验。

## 3. 认证路线

### MVP

当前已实现 Spring Security 邮箱密码登录、服务端 Session、CSRF 与 `CurrentActor` 身份抽象。`contextId` / `planId` 按认证用户绑定所有者；无匿名固定身份降级。仅显式 `local-mock` profile 使用受密码保护的本地固定账号。初始化方式和仍未覆盖的权限边界见[最小认证与 Plan 会话所有权](./development/最小认证与Plan会话所有权.md)。

### 商业化

采用 Spring Security。浏览器优先考虑短时 Access Token + HttpOnly Refresh Token 或安全 Session；IDE 插件使用可撤销的 Personal Access Token。JWT 不应被当作可撤销的长期会话存储，Redis 用来保存 Refresh Token 状态、黑名单和会话元数据。

## 4. 数据生命周期

建议配置化：

- 短时上下文：请求结束即删除，异常情况下由 Redis TTL 兜底。
- 未保存优化结果：仅在内存/短时缓存中存在。
- 用户历史：按租户保留期限自动清理。
- 审计事件：按合规与套餐策略保留，不能与源码一起无限保存。
- 用户删除/注销：异步清理数据库、缓存、对象存储和备份中的可识别数据。

## 5. 商业化基础能力

数据模型和服务接口预留：

- 订阅套餐、试用期和账期。
- 优化次数、Token 或金额额度。
- BYOK 与平台统一 Key 两种计费路径。
- 团队工作区、成员角色和管理员审计。
- 企业版的数据驻留、私有部署和供应商白名单。
