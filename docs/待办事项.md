### 已完成排查：大目录文件上传的性能问题

问题现象：选择包含约 16 万文件的项目后，界面约 5 秒无响应；点击上传后约 1 分钟才出现读取进度；最终仅加入不到 200 个文件。

根因与处理结果：

- [x] 根因 1：候选扫描同步遍历完整 `FileList`，每个文件还执行 `split('/')`，主线程长时间被占用，页面无法绘制。
- [x] 处理：增加 `MAX_SCAN_FILES = 50_000` 的有界扫描；去掉 `split`，改为手动遍历路径分隔符判断 `node_modules`、`.git`、`target` 等忽略目录。
- [x] 根因 2：前端与后端文件数量上限不一致，前端曾限制 200 个文件。
- [x] 处理：前端 `MAX_FILES = 1_000`、字符总预算 2,000,000；后端 `ContextAnalysisRequest` 同步改为最多 1,000 个文件、总预算 5MB。
- [x] 根因 3：文件内容读取占用主线程，读取阶段界面卡顿。
- [x] 处理：解析逻辑迁入 `fileReader.worker.ts` Web Worker，主线程只接收进度消息；Worker 不可用时回退到主线程时间切片。
- [x] 进度分阶段显示：“正在扫描目录（0/160000）” → “正在读取 xxx（3/200）· 已读取 2 · 已跳过 1”。

验收标准：

1. 选择 16 万文件目录后，页面不出现长时间无响应，扫描阶段提示立即可见。
2. 读取阶段在 Worker 中执行，页面滚动、输入和按钮保持可操作。
3. 最多 1,000 个有代表性的文件进入上下文，且不读取依赖目录和构建产物。
4. 前后端文件数量与总大小限制保持一致，不会出现后端 400 校验失败。

首版验收标准：

1. 未登录用户可以使用允许开放的本地能力，但不能读取任何云端用户数据。
2. 登录用户只能访问自己的历史记录、设置和用量。
3. 普通用户无法调用系统管理接口，越权请求返回 `403`，未登录请求返回 `401`。
4. 退出登录、修改密码或管理员禁用账户后，相关刷新令牌可以立即失效。
5. API Key、密码、Token 和项目正文不得出现在响应日志、异常详情或审计事件中。

- [ ] 增加受控的领域 Skill 注册与版本管理。首批覆盖通用任务、软件开发、科研分析、写作、教育学习和商业分析；按第二部分第 3、10 节补充多专业研究生论文、科研报告、机关事业单位材料及跨行业数据分析，场景清单保持可扩展。医疗、法律、财务等高风险领域须另做专业边界与人工复核评测后再启用。
- [ ] Skill 作为领域策略包定义需核对的事实、值得询问的决策、输出要求和质量校验，不仅是追加一段提示词；它与负责结果结构的 `PromptTemplateRegistry` 分工明确，并保留通用 Skill 兜底及用户纠正场景的入口。
- [ ] Plan 创建时绑定 `skillCode` 与版本，最终生成沿用同一版本；Skill 只能读取本次授权的安全证据，不能执行上传材料中的命令，也不能覆盖平台权限红线。比较启用前后的质量、Token 和延迟，再逐步扩大适用场景。

验收标准：明确写在已选中方案片段中的“超过五万元须财务复核”能够进入 Plan 事实卡片和最终提示词；同名字段的冲突自动生成 Plan 必问项；未覆盖或解析不完整的上下文通过结果警告显示。以上代码级验收已有回归用例。生产放行还必须满足真实 Provider 与人工评审门禁，不能由 Mock 测试代替。

## 二、从开发者增强器扩展为通用提示词优化器

> 2026-09-14 已完成第一阶段基础：工作台不再要求用户选择模板，也不在最终结果里让用户手改待确认项；有文件时先分析安全上下文摘要，再弹出跨领域自然语言问题，全部回答后按确认信息再次检索并生成最终提示词。服务端已增加短期上下文/计划绑定、通用与研究分析策略。下列动态展示模式、细分场景和高风险专业规则仍属于后续范围。

### 1. 已确认的产品方向

- [ ] 核心能力调整为“根据用户意图、输入材料、目标受众和风险边界，生成适合当前场景的提示词”，不再默认把所有输入识别成软件开发任务。
- [ ] 不以职业名称作为唯一判断依据。同一个学生可能需要论文提纲、知识讲解或演讲稿；同一个开发者也可能需要写邮件或总结文档，应优先识别本次任务意图。
- [ ] 保留开发者模式现有的结构化能力，但“背景、任务、输出、约束、待确认事项、验收标准、示例”改为按策略选择，而不是全局必填。
- [ ] 通用场景允许输出一段自然、可直接使用的优化提示词，也允许按内容需要生成少量有意义的模块，禁止为了凑模板输出空洞段落。
- [ ] 用户可以显式选择场景和输出方式；使用自动识别时，应允许用户在结果页查看并更正识别结果。

### 2. 场景识别与动态输出计划

- [ ] 新增“场景（Scenario）”“任务意图（Task Intent）”“展示模式（Presentation Mode）”三个相互独立的概念，避免把职业、任务和界面结构混为一体。
- [ ] 场景识别输入至少包括：原始提示词、用户显式选择、会话历史、附件类型、附件提取结果、用户偏好和风险等级。
- [ ] 将专业领域、任务阶段、使用对象、资料完整程度和目标交付物共同用于识别；不能只凭职业或“论文”“报告”等词套模板。例如同一论文主题需区分开题、方法设计、已有结果写作、全文修改与摘要润色，未知专业任务保留通用策略与用户纠正入口。
- [ ] 任务意图首批支持：创作、改写、总结、分析、学习辅导、规划、信息提取、软件开发和问题排查。
- [ ] 展示模式首批支持：`STRUCTURED`（多段结构化）、`GUIDED`（少量引导模块）和 `NATURAL`（自然完整提示词）。
- [ ] 初始选择规则按主要交付物唯一决策：软件开发、多步骤执行方案或明确要求验收标准的正式交付使用 `STRUCTURED`；其他任务存在附件，或需要分别控制受众、素材、语气、格式等两个及以上维度时使用 `GUIDED`；其余单一且无需分块复用的请求使用 `NATURAL`。
- [ ] 自动识别结果需要返回规则命中、模型分类和置信度。初始阈值暂定：`>= 0.75` 自动采用；`0.50—0.74` 采用通用策略并提示用户确认；`< 0.50` 使用 `NATURAL` 通用模式并最多提出三个关键问题。阈值必须通过评测集校准，不能直接使用模型未经校准的自报置信度。
- [ ] 多任务冲突时按“强制安全规则 → 用户显式选择 → 主要交付物 → 附件用途 → 次要风格偏好”的顺序决策，并在结果中说明主要任务判断。
- [ ] 用户选择的场景和展示模式优先于自动识别。风险等级不改变展示模式，而是独立强制加入内部安全规则和 `reviewNotice`；医疗、法律、财务、隐私和危险操作等规则不能被用户选择覆盖。

### 3. 首批场景能力

产品入口可以按用户熟悉的人群或职业展示，但内部策略必须按本次任务建模：

- [ ] **软件开发**：新功能、Bug 修复、重构、测试、代码审查、数据库设计和接口设计。
- [ ] **学习与教学**：知识总结、学习计划、错题分析、复习提纲和课程材料整理。加入引用要求和学术诚信提示，避免代写、作弊和伪造引用。
- [ ] **写作与表达**：文案、文章、邮件、演讲稿、通知和报告，支持正式、简洁、口语等输出风格。
- [ ] **办公与资料整理**：会议纪要、表格字段整理、流程说明、信息提取和文档摘要。
- [ ] **多专业研究生论文与科研报告**：覆盖医学、工学、教育学、经济学、管理学及其他专业，按选题、开题、研究设计、分析方案、已有结果写作、全文修改与摘要润色分别组织要求。核对研究问题、材料来源、方法、学校或投稿要求；区分拟开展工作和已完成工作，遵守学术诚信、署名与引用要求，不伪造数据、结果和参考文献。专业列表用于组织评测，不作为用户任务的封闭白名单。
- [ ] **机关事业单位材料**：支持工作总结、调研报告、请示、情况说明等，明确用途、报送对象、时间范围、事实依据和格式要求；区分事实陈述、问题分析、建议及拟开展工作，不编造政策依据、工作业绩或统计数字，保护材料中的个人信息和敏感内容。
- [ ] **跨行业数据分析**：结合实际目标区分描述、比较、预测及因果问题，核对数据字段、统计口径、时间范围、缺失值、方法和交付形式。只有数据字典或方案时，不假定实际数据已提供；工具偏好与是否需要代码按任务确定，不将所有分析强制转成软件开发。
- [ ] **产品与运营**：需求澄清、用户故事、竞品分析、活动方案、用户反馈归纳和数据解读。
- [ ] **医疗、法律、财务等高风险能力**：只在低风险场景稳定后实施，单独设计专业边界、免责声明、人工复核和敏感数据保护规则。

### 4. 动态输出策略

| 场景或任务 | 推荐展示模式 | 按需出现的内容 | 不应默认强制出现 |
| --- | --- | --- | --- |
| 软件开发、Bug 修复、接口和数据库设计 | `STRUCTURED` | 背景、任务、输出、约束和验收标准固定出现；待确认事项与示例按需出现 | 无关的行业话术、为凑数量生成的可选段落 |
| 文案、文章、邮件、演讲稿 | `NATURAL` 或 `GUIDED` | 目标、受众、主题、语气、篇幅、核心观点、素材使用方式、事实与引用要求 | 工程化验收标准、无实际意义的权限约束 |
| 学习辅导、知识讲解、复习计划 | `GUIDED` | 学习目标、当前水平、材料范围、讲解深度、练习与反馈方式、引用要求 | 软件测试式验收标准 |
| 附件总结、改写和信息提取 | `GUIDED` | 材料范围、保留与忽略内容、事实忠实度、引用位置、目标格式 | 虚构背景、与附件无关的通用约束 |
| 医疗、法律、财务等高风险内容 | 按主要交付物选择模式 | 信息来源、适用范围、隐私要求、不确定性和 `reviewNotice` 始终生效 | 把模型结果表述为最终专业结论 |
| 无法归类的通用需求 | `NATURAL` | 一段完整优化提示词，必要时追加一到三个关键待确认问题 | 固定六段式模板 |

- [ ] “约束”作为内部规划概念可以始终存在，但只有对用户有帮助时才显示为独立段落；语气、篇幅、事实准确性等要求可以自然融入提示词。
- [ ] `NATURAL` 固定为一个完整提示词块；`GUIDED` 建议为 2—6 个实际需要的模块；`STRUCTURED` 建议为 4—7 个模块。数量是展示约束，不是质量目标。
- [ ] “待确认事项”只保留答案会改变主要交付物、目标受众、材料范围、展示模式或安全边界的问题，最多三个；其他低影响信息可以采用可撤销、明确标注的默认值。
- [ ] “验收标准”只在可验证交付、计划执行、软件开发、正式业务交付或用户明确要求时出现；普通创作类请求不默认生成。
- [ ] “示例”只在用户要求、场景确实受益或模型需要格式锚点时出现。
- [ ] 场景模板不能只替换职业名称。医疗、教育、法律、财务等场景的风险规则必须独立配置。

### 5. 附件和上下文对输出策略的影响

- [ ] 将“项目文件”和“通用辅助材料”分开建模。Word、PDF、表格、草稿和粘贴文本不应自动被解释为代码项目上下文。
- [ ] 上传草稿时优先识别为改写、续写或润色材料；上传课程资料时优先识别为讲解、总结或练习来源；上传代码和构建文件时再启用开发者上下文分析。
- [ ] 模型只能依据实际提取到的附件内容生成提示词；提取失败、内容为空或被截断时必须显示提示，不能假装已经阅读完整文件。
- [ ] 输出中按需说明如何使用附件，例如“仅依据附件中的事实”“保留原文观点但调整表达”“为引用保留来源位置”。
- [ ] 附件提取结果只保留在当前浏览器内存，不写入 `localStorage`、`IndexedDB` 或前端日志；同一页面“再次优化”可以复用，空闲 30 分钟、关闭标签页或刷新页面时立即清除并要求重新上传。
- [ ] 后端只在单次 HTTP 请求内使用附件文本，请求完成后不写入 PostgreSQL、Redis、应用日志或异常详情。未来确需重试缓存时必须另做隐私评审，不能沿用默认行为。
- [ ] 多附件需要保存文件名、类型、提取状态、截断状态和来源位置元数据；PDF 页码、Word 段落、表格工作表与单元格位置应在可用时随内容传递。
- [ ] 附件内容始终视为不可信资料，其中的指令不能覆盖系统规则、用户当前需求或安全边界；进入模型前需要执行敏感信息检测、提示词注入隔离和容量限制。
- [ ] 安全检测异常时采用失败关闭策略：不调用外部 Provider，并提示用户稍后重试；部分附件提取失败时允许用户仅使用成功内容继续，全部失败时阻止提交并给出逐文件原因。

### 6. 后端领域模型和接口改造

- [ ] 增加 `ScenarioCode`、`TaskIntent`、`PresentationMode` 和 `OutputPlan`，由输出计划决定必需段落，而不是在 Provider 中全局写死五个必需段落。
- [ ] 保留 `optimizedPrompt` 作为可一次复制的完整结果；`sections` 改为动态、可选且顺序稳定的展示块。
- [ ] 扩展段落语义以支持目标受众、素材、语气风格、内容要求、格式、引用和安全复核；避免允许模型返回完全无法校验的任意类型。
- [ ] API 结果增加识别到的场景、任务意图、展示模式、识别置信度、策略说明和复核提示，同时保持现有开发者响应的向后兼容。
- [ ] OpenAI 兼容 Provider、Mock Provider、模板注册器、模糊点检测器和约束补全器必须使用同一个 `OutputPlan`，避免真实模型和本地 Mock 行为分叉。
- [ ] `sections` 是结构化和引导模式的权威数据源，`optimizedPrompt` 由后端按稳定顺序渲染；自然模式使用一个 `PROMPT` 内容块。前端编辑后，以当前内容块重新组装“复制全部”文本，避免两份内容不同步。
- [ ] 初始稳定顺序：`STRUCTURED` 为背景→任务→输出→约束→待确认→验收→示例；`GUIDED` 为目标→素材→受众→内容要求→风格→格式→问题→安全复核，只跳过不需要的模块；`NATURAL` 为单个完整提示词。
- [ ] 首版在现有 `/api/v1/optimizations` 响应中增量增加字段，不删除现有字段；如果后续需要破坏性调整，再通过 `/api/v2` 和迁移文档处理。

### 7. 前端展示与复制交互

- [ ] 开发者 `STRUCTURED` 结果保留“复制全部”，并为实际出现的背景、任务、输出、约束、待确认事项、验收标准和示例分别提供独立复制按钮。
- [ ] `NATURAL` 结果默认突出显示一份完整、自然的优化提示词，不展示无意义的 Template、段落数量或工程元数据。
- [ ] `GUIDED` 结果只展示实际生成的模块，每个模块支持单独复制和编辑。
- [ ] 优化成功后弹出提示：“优化已完成，请仔细检查目标、事实、数字、引用、限制条件和待确认内容，并按实际需要选择全部或分段使用。”
- [ ] 弹窗不能自动提交提示词；用户关闭弹窗后仍可编辑、撤销、再次增强、复制全部或复制单个模块。
- [ ] 结果页显示系统识别的场景与输出方式，并提供“切换为自然输出 / 引导输出 / 开发者结构化输出”的重新优化入口。

### 8. 评测样例与验收标准

- [ ] 将用户本次提供的长文本作为“产品需求整理”回归样例：结果应自然整合目标用户、动态模板、竞品研究边界和实施要求，不应机械生成无意义的工程验收段落。
- [ ] 开发任务样例必须生成背景、任务、输出、约束和验收标准；存在关键歧义或请求示例时再增加对应模块，所有实际出现模块均可单独复制，完成后出现人工检查提示。
- [ ] 文章和文案样例在未要求交付验收时，不生成独立“验收标准”和“权限约束”。
- [ ] 演讲稿样例应优先补充受众、场合、时长、语气和核心观点；若上传草稿，应说明如何保留或改写原材料。
- [ ] 学生学习样例应补充年级或当前水平、学习目标和讲解方式；涉及作业和论文时显示学术诚信提示。
- [ ] 医疗、法律和财务样例即使使用自然输出，也必须保留隐私、信息来源和人工复核规则。
- [ ] 自动分类错误时，用户可以一次操作切换场景或展示模式并重新生成，不需要重新上传附件。
- [ ] 建立“自然度、意图保真、上下文忠实、必要约束覆盖、无臆造、可直接使用”六项 1—5 分人工评测指标；首批发布门槛暂定为平均分 `>= 4.0`，且意图保真、上下文忠实、无臆造三项不得低于 4 分，不以段落数量作为质量指标。
- [x] 将用户本次提供的完整需求保存为后续评测夹具：`test-fixtures/prompt-evaluation/general/product-requirement.txt`。
- [ ] 已完成的 Excel/WPS 兼容表格提取必须纳入附件分类、来源元数据和动态输出回归测试。

### 9. Qoder 竞品研究边界

- [ ] 只把 Qoder 官方文档确认的“一键增强、结合上下文、结果可编辑/撤销”等能力作为事实。
- [ ] 官方资料已确认 QoderWork 支持写作、办公、研究、教学、PPT 和表格等非开发者场景，但这不能证明 Qoder IDE 的一键增强与 QoderWork 使用同一套内部引擎。

## 五、浏览器插件：在 ChatGPT 和 DeepSeek 网页内一键优化

### 1. 产品目标

后续提供 Chrome/Edge 浏览器插件。用户在 ChatGPT 或 DeepSeek 网页版的聊天输入框中输入原始需求后，可以点击输入框附近的“一键优化”按钮，在不离开当前网页的情况下调用本项目的提示词优化服务，并将优化结果放回输入框供用户审阅和修改。

该插件只负责网页交互和请求转发，不负责保存用户的模型 API Key，也不自动发送最终消息。

### 2. 可实现性判断

- [ ] 技术上可实现：使用 Manifest V3、Content Script、Service Worker 和 Options Page。
- [ ] 通过 Content Script 识别 ChatGPT、DeepSeek 的输入框，在输入框附近挂载独立的优化按钮。
- [ ] 通过 Shadow DOM 隔离插件样式，避免污染宿主网页。
- [ ] 用户点击按钮后，将输入框内容、用户选择的场景、项目上下文摘要和优化选项发送到本项目后端。
- [ ] 优化完成后提供“替换输入框内容”“复制结果”“取消”三个操作，默认不自动点击宿主网页的发送按钮。
- [ ] ChatGPT、DeepSeek 分别实现独立的页面适配器，不能依赖单一 CSS 选择器。

### 3. 推荐技术结构

```text
browser-extension/
├─ src/content/             # 注入输入框按钮、读取和回填文本
├─ src/background/          # Service Worker，请求转发和消息协调
├─ src/options/             # 后端地址、登录状态、场景和隐私设置
├─ src/adapters/            # ChatGPT、DeepSeek 页面适配器
├─ src/components/          # 优化按钮、预览弹窗、友情提示
└─ manifest.json            # Manifest V3 配置
```

### 4. 隐私和安全边界

- [ ] 只有用户主动点击“一键优化”后才读取和发送输入框内容。
- [ ] 默认不读取聊天历史、网页其他内容、Cookie、密码和登录凭证。
- [ ] 默认不自动发送模型消息，必须由用户审阅后自行点击宿主网页的发送按钮。
- [ ] 插件不保存 DeepSeek、OpenAI 或其他模型 API Key；模型密钥只由本项目后端受控管理。
- [ ] 项目上下文默认只发送用户明确选择的摘要或文件片段，不读取用户电脑任意路径。
- [ ] 插件请求本项目后端时使用 HTTPS、登录态或短期令牌，并配置明确的 CORS 和扩展来源校验。
- [ ] 发布前核对 Chrome Web Store、Edge Add-ons 以及 ChatGPT、DeepSeek 网站的使用条款和商店审核要求。

### 5. 兼容性和风险

- [ ] ChatGPT、DeepSeek 可能随版本调整 DOM 结构，页面适配器需要版本化、健康检查和降级提示。
- [ ] React/Vue 等受控输入框不能只修改 DOM 的 `value`，需要触发符合宿主框架预期的 `input`/`change` 事件。
- [ ] 网站 CSP、iframe、Shadow DOM 和富文本编辑器可能导致按钮挂载或回填失败，需要分别测试。
- [ ] 页面识别失败时显示“暂未识别当前输入框，可使用复制优化结果”，不能静默修改页面内容。
- [ ] 插件网络异常、后端未登录、模型不支持对应文件类型或模型超时时，需要展示与 Web 端一致的错误提示。

### 6. 推荐实现顺序

1. [ ] 先实现仅支持本地测试页面的插件原型，验证按钮注入、读取、预览和回填流程。

3. [ ] 增加 DeepSeek 页面适配器和独立回归测试。
4. [ ] 接入本项目后端的登录态、场景选择、上下文摘要和 Provider 错误提示。
5. [ ] 增加插件设置页、服务地址配置、快捷键和启用站点管理。
