# 模块与目录设计

## 1. 后端模块

| 模块 | 职责 | 首发优先级 |
| --- | --- | --- |
| Identity / Tenant | 用户、租户、工作区、成员和权限边界 | P1，先做简化用户 |
| Optimization | 接收请求、编排分析、组装和模型调用 | P0 |
| Context | 文件安全、项目结构、技术栈、依赖和上下文预算 | P0 |
| Prompt | 系统提示词模板、输出结构和质量校验 | P0 |
| Enhancement | 一键增强、模糊点识别、四要素补全和约束补全 | P0 |
| Conversation | 当前会话历史、澄清项和再次增强上下文 | P1 |
| Policy | 权限红线、敏感操作提示和人工确认要求 | P0 |
| Template | 内置和自定义模块化 Prompt 模板 | P0 |
| Provider | 多模型配置、适配、超时、重试和错误映射 | P0 |
| History | 优化记录查询、删除、重载和保存策略 | P1 |
| Settings | Provider 配置、参数校验、密钥密文存储 | P0 |
| Quota / Usage | 限额、Token 用量、成本估算和计费接口 | P1，接口先留出 |
| Audit | 安全事件、配置变更和管理操作审计 | P2 |

建议 Java 包结构：

```text
services/api/src/main/java/com/promptoptimizer/
├─ common/                    # 错误模型、响应信封、时钟、ID、脱敏
├─ identity/                  # 用户、租户、工作区、权限
├─ optimization/              # 优化用例、编排器、领域对象
├─ context/                   # ContextAnalyzer、扫描器、摘要器
├─ prompt/                    # PromptComposer、模板与输出校验
├─ enhancement/               # 一键增强、模糊点识别和结构化结果
├─ conversation/              # 会话消息、上下文拼接和版本
├─ policy/                    # 权限红线和风险策略
├─ template/                  # 模块化 Prompt 模板
├─ provider/                  # ModelProvider、适配器和客户端
├─ history/                   # 历史记录查询与保存策略
├─ settings/                  # Provider 配置和密钥管理
├─ quota/                     # 配额、用量和成本
├─ audit/                     # 审计事件
└─ infrastructure/            # Web、Persistence、Redis、Security
```

每个业务模块内部建议保持：`api`、`application`、`domain`、`infrastructure` 四层；模块之间通过应用服务和接口交互，不直接访问别的模块的 Repository。

## 2. 前端模块

```text
apps/web/src/
├─ app/                       # 路由、全局 Provider、错误边界
├─ layouts/                   # 主布局、认证布局
├─ views/
│  ├─ optimizer/              # 主优化工作台
│  ├─ history/                # 历史记录
│  └─ settings/               # Provider 与账户设置
├─ components/
│  ├─ context/                # 上传、目录选择、文件预览
│  ├─ prompt/                 # 输入、输出、复制、差异视图
│  └─ common/                 # 空状态、错误、加载、确认框
├─ stores/                    # auth、workspace、optimizer、settings
├─ services/                  # API client 和错误映射
├─ types/                     # API 类型和视图模型
└─ styles/                    # Design Tokens 与主题
```

## 3. 页面边界

### 优化工作台

左侧是上下文配置：目录/文件选择、已识别技术栈、文件摘要、用户补充描述；右侧是原始提示词和优化结果。顶部展示工作区、额度和当前 Provider，底部展示上下文警告和模型用量。

### 历史记录

支持按工作区、时间、标签和 Provider 筛选；记录详情允许复制优化提示词、重新载入原始请求、删除记录。默认不提供全量源码回放。

### 设置

分为模型配置、优化偏好、隐私策略、账户与团队四个区块。API Key 只显示掩码和更新时间，不支持回显明文。

## 4. 共享契约

`packages/contracts` 存放 OpenAPI 文档、JSON Schema 和错误码说明。前端和后端都应从该契约生成或校验类型，避免手工维护字段名称。
