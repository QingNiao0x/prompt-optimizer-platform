# 访客免费体验与访问限制

本次在已有三个工作台上增加访客访问边界，没有重做工具、改变提示词增强策略或开放匿名 Plan。本文描述代码能力，不代表已经部署到生产，也不替代各工具的真实模型质量验收。

## 开放范围

| 功能 | 未登录访客 | 注册登录后 |
| --- | --- | --- |
| 图像转提示词 | 单图直接还原，共 1 次 | 保留既有直接还原、创作 Plan、编辑及历史 |
| 提示词优化 | 文字直接增强，共 3 次 | 保留既有资料、Plan、增强及历史 |
| 文章祛AI味 | 提交原文或当前稿，共 3 次 | 保留既有来源关联、编辑及历史 |
| 全部历史列表、详情、恢复、修改和删除 | 不开放；界面引导注册登录，正式 API 继续要求认证 | 继续按原有用户、租户及工作区隔离 |

三个额度独立，以服务端受理的**生成尝试**计数，不是每日额度。刷新页面、切换工具和新建任务都不会补充次数。格式/身份/模型准入检查在预占前进行；已经受理后的模型失败、网络超时不自动退次数，因为它们不能证明下游未计费。

额度耗尽后保留当前结果的查看、编辑和复制，不自动跳转、不清空输入。首页与顶部导航保留三项工具入口，各工作台展示剩余次数及注册/登录按钮。历史链接进入注册引导而不先拉取历史数据。

正式账号不受上述访客次数影响，仍受系统其他既有权限和资源规则约束。`persistentHistory=false` 仅表示非数据库持久化：正式账号在本机演示环境中的内存历史，仍使用原编辑、读取及来源关联接口，不能误判为访客。

## 服务端边界

- 独立 `/api/v1/trial` 白名单处理三项试用；没有对正式历史、Plan 或管理员路径设置匿名放行。
- `POST /api/v1/trial/session` 在通过 CSRF 后签发随机 `PO_TRIAL` Cookie。它使用 HttpOnly、SameSite=Lax，Secure 复用正式 Session Cookie 配置；浏览器保留期一年。
- Cookie 格式正确并不代表有效：后端还要求私有 Redis 账本存在。前端只读取额度，不在 localStorage 计数或自行扣减。Cookie 未建立、Redis 故障或额度未知时拒绝生成。
- `TrialFeature` 固定三项总额；Redis 原子预占同时核对身份、已有操作、功能余额、并发和来源预算，跨页面/并发请求不能越过总额。
- 每次增强携带 `X-Trial-Request-Id`；图像与文章使用既有请求编号。相同编号和输入只能读取原结果，不能再次执行模型；编号复用到不同输入返回冲突。
- 访客没有正式账号、租户或工作区，不伪造 `CurrentActor`。独立入口复用原生成实现与管理员启用的模型目录，跳过账号历史写入，而非跳过身份/历史保护。
- 结果原件仅保存在私有短期操作缓存中，最长 24 小时，只能由同一访客恢复；不提供访客历史列表。页面上的临时编辑不写回账号历史，也不在注册后自动合并到新账号。
- 图片仍执行原大小、解码、像素和元数据保护；访客预览与撤销按访客身份隔离，不可引用正式用户或其他访客的资产。
- 访客调用保留独立计数账本和安全模型日志，不冒充正式账号写入其用量/审计记录；现有账号统计不等于完整访客成本报表。

## 配置及部署

没有增加依赖、数据库迁移或改变原有 SMTP/SMS 环境变量。新增默认配置：

```yaml
app:
  trial:
    enabled: ${TRIAL_ENABLED:true}
    store-mode: ${TRIAL_STORE_MODE:REDIS}
```

- 正常开发及真实模型环境默认使用 Redis；不可用返回 `503 TRIAL_UNAVAILABLE`，不能以临时内存放行。
- `local-mock` 显式使用 `MEMORY`，并要求模型供应商模式是 `mock`。该模式只用于演示/自动化测试，进程重启会清空其内存，不可用于真实模型试用。
- 真实环境应保持现有 Redis 私网访问、认证和持久化配置。访客总额账本不按自然日过期；清空或丢失整个 Redis 数据集无法保留既有计数，因此不能将清库当作普通重启步骤。
- `TRIAL_ENABLED=false` 可关闭新增试用，不影响正式账号功能；需要重新加载后端配置才能生效。正式 HTTPS 环境继续启用 Session Cookie 的 Secure 设置。
- 部署时前后端须一起更新。前端没有独立“放行次数”的构建开关，生产服务器是否已运行新代码需部署后另行确认。

辅助防刷规则为每来源每小时最多建立 10 个访客身份、每日最多受理 30 次生成、全平台访客每日最多 1000 次生成；同一访客同时只受理一个生成请求。来源地址沿用可信代理解析并使用后端私有随机盐 HMAC，不把原始 IP 放入额度键。这些是额外资源上限，不会每天恢复单个访客的 1/3/3 总额。

匿名身份不能证明“同一个自然人”。清 Cookie、换浏览器或换网络仍可能创建新身份，来源预算只能提高滥用成本，不能宣称绝对防刷。使用公网真实模型时仍需结合供应商预算告警、网关流量防护及实际成本观察。

## 主要实现位置

- `apps/web/src/types/trial.ts`、`services/trialApi.ts`、`stores/trial.ts`：额度契约、身份初始化及接口分流。
- `apps/web/src/components/auth/GuestTrialBanner.vue`：统一额度与注册提示。
- `apps/web/src/pages/ImageToPromptPage.vue`、`TextPolishPage.vue`、`PromptWorkbenchPage.vue`：各工具入口、受理前检查、临时结果与历史引导。
- `apps/web/src/router/index.ts`、`pages/LoginPage.vue`：仅放行三个工作台，保护全部历史路由。
- `services/api/src/main/java/com/promptoptimizer/trial/`：访客凭据、Redis 原子计数、幂等原件、独立控制器。
- `services/api/src/main/java/com/promptoptimizer/identity/security/SecurityConfiguration.java`：按 HTTP 方法和路径列出试用白名单，保留 CSRF。

## 验证边界

本轮自动化使用合成身份和模拟模型，不创建正式账号、不发送短信/邮件、不调用付费模型。浏览器验证包含桌面与窄屏、入口、独立次数、耗尽后复制、历史零请求、429/503、正式用户不走试用接口；后端验证覆盖原子配额、幂等、CSRF及账号/访客隔离。

### Standards

独立规范审阅发现的 3 项已修复并复核关闭：上传预算必须原子核对账本存在、底层异常保留 cause 但不对外泄露、私有凭据/快照方法补齐安全边界注释。未为减少重复而改写正式身份命名空间。非阻断的存储机械代码去重建议未扩展实施。

### Spec

独立需求审阅发现的 1 项正式账号内存历史回归已修复：`persistentHistory=false` 不再被当作访客身份。新增 3 项测试先复现失败再验证通过，恢复正式账号编辑、保存重试和当前稿来源关联。

审阅汇总：Standards 3 项确认问题已关闭，Spec 1 项确认问题已关闭；已知测试差异和首次导航偶发超时仍按下述及上表保留，不以审阅通过覆盖测试边界。

另外运行原有自然正文编辑测试时，`naturalOptimization.test.ts` 一项仍要求自动补回平台固定约束，但提交版本的 `restoreNaturalBoundaries()` 已明确只恢复用户追加的权限。这是原有断言与当前规则差异，本轮没有修改该语义或把该断言改成通过。不能把本轮定向通过写成全仓测试全部通过。
