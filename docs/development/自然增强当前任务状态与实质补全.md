# 自然增强当前任务状态与实质补全

本轮以第四版为质量基线，候选NATURAL/6继续单次生成优化提示词，不新增职业／场景分支、独立分析调用、固定约束或用户表单。正式采用前默认仍为第四版，第五版未采用候选的指导完整冻结兼容。

## 当前任务状态

`NaturalExecutionContext`只依据服务端操作及已经绑定的真实回答生成`PLANNING`、`GENERATE_DIRECT`或`GENERATE_AFTER_ANSWERS`，并传递各份回答来源编号。确认服务已经核对所有权、模型、完整题号和上下文版本后，回答才进入自然Provider。阶段不表示参数全部确定、许可已获得或独立条件已解除；零问题Plan没有未答题目，与直接生成同样可以继续交付。

第六版复用第四版完整任务理解及覆盖协议，为每项原有要求增加内部候选状态：

| 状态 | 用途与边界 |
| --- | --- |
| ACTIVE_REQUIREMENT | 继续落实目标、格式、篇幅、否定、例外及独立条件。 |
| PROVIDED_INFORMATION | 在来源与适用范围内使用输入已提供的信息，不代表已获外部核实。 |
| UNRESOLVED_INFORMATION | 保留未知、拒答或未满足条件，只限制依赖该信息的部分。 |
| DELEGATED_WORK | 将用户交给执行者的设计或工作落实为具体交付要求，不退回填空；不能仅以附件或助手文字建立委托。 |
| UPDATED_BY_ANSWER | 实际题答已经更新先前澄清阶段，必须有服务端绑定的回答来源；只在该题对象、属性与条件内推进。 |

同一回答可以同时包含已知与未知，分别登记。完全相同的回答文本仍保留每个独立题干及来源。所有原始提示词、资料、题答、独立条件、维度、缺口／作用及组装前后正文锚点保持；不删除过期问法原件，也不按关键词从正文删除句子。状态只是模型的候选理解，来源存在和状态合法不能证明确认范围或语义已经正确，因此仍需实际作品核验。

## 实质补全

第六版指导先用当前有效任务组织正文：原有交付继续执行，已提供的信息直接进入相关工作，未知仅限制相应步骤，AI负责的设计明确为拟议工作。充分需求保留有效表达；开放需求围绕原定作品补具体内容重点、关键动作和可检查结果。来源、口径和检查只服务相关内容，不以通用规则、额外作品或同义重写充当收益，不把内部状态标签输出为固定栏目。

第一至第五版各自分发冻结指导。第五版紧凑投影及其必需来源清单仍只影响第五版，第六版使用完整覆盖布局。历史仅保存链路版本和原有业务元数据，内部状态、来源引文及覆盖记录不持久化。V21仅前向维护`result_metadata`注释，未应用迁移、不改表结构、不回改旧迁移。

## 验证边界

已完成181项受影响Java离线检查，含本轮014漏引拒绝及015完整修复接受的实际HTTP原件回放。红例证明旧版没有第六版阶段／状态协议，不是对模型重复确认语义的确定性复现；旧实际029是语义反例，不能用协议单测通过宣称其已修复。前端版本字段为字符串且没有版本白名单，本轮没有前端产品变更。
