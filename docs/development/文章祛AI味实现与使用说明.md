# 文章祛AI味：实现与使用说明

更新：2026-10-25。该工具接收用户主动提交的已有正文，输出润色正文，与提示词增强、图像转提示词及其 Plan 独立。工程验证、真实样本和质量限制见[本机验证报告](../testing/文章祛AI味实现与真实评测-2026-10-25.md)。

## 使用方式

1. 从顶栏打开“文章祛AI味”（`/text-polish`），粘贴原始文本。只有点击润色按钮才提交正文和设置；切换文体、改写幅度或模型不会调用模型。
2. 选择文体。三档说明在桌面和窄屏设置分区直接显示：正式清晰“适合报告、商务邮件和正式说明。”；自然流畅“默认，适合一般文章和日常沟通。”；轻松交流“适合社交内容和面向大众的介绍。”。首次进入和新建文章默认自然流畅。
3. 可填写需要原样保留的文字，每行一段，必须来自本次原文。高级设置包括改写幅度、读者和补充要求；轻度润色与允许调整句式和段落均须保留原意。文体不是质量等级或 AI 检测分数。
4. 点击“开始润色”，核对原文、润色正文及差异提示。已有自然表达允许原样返回，不以改动数量代表收益。正文中的指令、引文和链接只作为材料处理。
5. 可以编辑并保存正文，再复制；复制编辑稿时明确提示尚未保存。剪贴板被浏览器拒绝时提供手动复制窗口。编辑冲突保留当前编辑稿，不覆盖他处已保存版本。
6. “基于原文重新生成”使用当前可见原文；原文仍与当前记录一致时，服务端绑定该记录的原始输入。“以当前稿继续润色”使用服务端已保存的当前正文与修订号，生成独立新记录；结果左侧同步显示此次实际输入。未保存编辑稿须先保存或取消。
7. “返回上一稿”恢复本页上一份结果；“文章历史”打开总历史页的“文章祛AI味”分类（`/history?type=text-polish`）。登录用户成功润色的记录直接展示生成时间、文体、模型、原文和润色正文，支持分页、详情对照、复制、载入与逻辑删除。“载入”恢复记录当时的原文、文体、幅度、要求和当前已保存正文，不再次调用模型；已有未保存编辑稿或待确认结果时先保护当前稿。提示词、图像和文章历史分别查询，刷新后保留分类；旧 `/text-polish?history=1` 入口转到该分类。接入与验证见[历史页报告](../testing/文章祛AI味历史页接入与验证-2026-10-25.md)。

模型失败保留输入、设置和上一稿。网络结果不明时先“查询处理结果”，不会自动重放付费请求。历史保存失败时仍展示已生成正文，可以单独重试保存或复制。等待期间编辑内容，迟到结果进入“查看新结果”，不直接覆盖当前稿。

浏览器草稿只在内存中；刷新、关闭标签页会丢失未保存输入和编辑稿。页面内离开时对未保存编辑提供确认，身份切换清空旧身份私有状态。输入超过上限仍完整保留，提示精简后再生成，不静默截断。

## 统一模型管理

管理员进入现有“模型管理”，点击“文章润色模型”，勾选模块可用模型并设置本模块默认模型。模型名称、供应商路由、端点、密钥、排序和全局启停仍来自同一个平台目录；此处只管理模块准入和独立默认项，不产生另一份模型注册表，不改变提示词增强或图像模块的默认模型。

迁移初次执行时，将当时全局启用的模型及全局默认项作为初始配置。之后新增模型须显式加入文章模块。实际列表与全局可用模型取交集，全局停用、删除和路由失效优先；失效的模块默认项不继续调用，服务选取仍可用项。将模块允许列表清空即可暂停文章模型调用，其他功能保持原配置；已有记录仍可读取、编辑和删除。页面可手动刷新模型列表。

只有平台管理员可读取或保存该配置；普通用户只能获取可选模型。模型密钥始终在服务端。演示模型明确标记并回传原文，不能作为真实润色效果证据。

## 前后端与接口

前端链路为 `TextPolishPage.vue → stores/textPolish.ts → services/textPolishApi.ts`，沿用 Pinia、Element Plus、`base.css` 的玻璃主题、现有顶栏和 Vite `/api` 代理。页面采用原始文本、润色设置、润色结果三栏；窄屏沿用分区切换。差异采用有界行比较和纯文本展示，不把文章当 HTML 执行。

后端 `textpolish` 包以 `TextPolishController → TextPolishService → TextPolishProvider` 编排，复用 `CurrentActor`、平台模型目录、受限 HTTP 客户端、账号并发限制和模型审计。业务不调用 `NaturalEnhancementService`，不生成润色提示词或 Plan 问卷。受控操作码为 `text.polish`，管理员调用统计可按此筛选。

| 接口（前缀 `/api/v1`） | 用途 |
| --- | --- |
| `GET /text-polish/capabilities` | 可用模型、长度限制及历史持久化状态 |
| `POST /text-polish` | 生成；携带 UUID `requestId`、`input`、`sourceMode`，可选 `sourceRecordId`、`expectedRevision` |
| `GET /text-polish/operations/{id}` | 查询已提交请求的处理状态与当前正文 |
| `POST /text-polish/operations/{id}/save` | 单独重试保存已生成正文，不再调用模型 |
| `GET /text-polish/history` | 独立历史分页，`current`、`size=10/20/50` |
| `GET /PATCH /DELETE /text-polish/history/{id}` | 私有详情、乐观修订、逻辑删除 |
| `GET /PUT /admin/models/text-polish` | 管理员模块准入与独立默认项 |

文体有限值为 `FORMAL / NATURAL / CONVERSATIONAL`，幅度为 `LIGHT / RESTRUCTURE`；未传分别默认 `NATURAL`、`LIGHT`，未知字符串及数字枚举均拒绝。`RAW` 是新原文；`ORIGINAL / CURRENT` 必须绑定同身份的未删除记录和最新修订号，服务端读取实际正文，不信任客户端声称的来源。

## 资源、数据与保真边界

- 输入最多 12000 字符，输出最多 24000 字符；读者 300、补充要求 1500，保护文字最多 20 段、每段 1000 字符。字符口径为前后端字符串长度。未实现长文分块、跨段一致性或个人风格学习。
- 正常一次模型调用；仅 JSON 协议错误允许最多一次修复。截断、拒绝、网络故障、锁定内容变化均不自动质量重试。最大输出 Token 为服务端配置与 8000 的较小值，温度及 HTTP 超时沿用受限兼容路由配置；页面生成请求超时 180 秒。模型用量缺失保持未知，费用未接入结算。
- 确定性校验保护原句、空格标点和出现次数，缺失或额外重复即拒绝；数字片段变化仅作为审阅线索。数字相同、锁定句通过及 HTTP 200 均不证明其他语义完整。观点、计划、承诺、否定、例外、责任强度和引用仍须结合原文检查。
- 疑似密钥或令牌阻止发送与保存；普通日志和统计不记录原始正文。用户提交的正文及必要设置会发送给所选模型的服务端路由，不需要额外部署 GPU，不会访问文中的外部链接。
- Flyway `V40__text_polish_records_and_model_policy.sql` 新建 `text_polish_record` 和模块模型配置。已应用迁移不回改；SQL 位于 `mapper/textpolish/TextPolishMapper.xml`。表、字段、JSON 和范围注释与映射类型一并维护。
- PostgreSQL 保存原始输入、生成快照、当前编辑正文、来源、模型、文体和修订号。原始生成正文不可被编辑覆盖；更新使用修订号比较。关闭历史持久化的演示模式才使用进程内记录，界面明确提示重启丢失。
- Redis 处理状态和幂等结果以用户、租户、工作区共同隔离，暂存 24 小时，含输入和生成结果，不是永久文章仓库。正常模式缓存不可用时明确失败，不静默退化为不共享的私有内存状态。重复请求不会再次付费生成。
- `local-mock` 配置显式使用 `app.text-polish.store-mode: MEMORY`，适用于无 Redis 的演示；普通配置仍为 `REDIS`，不会因故障自动切换。
- 历史查询、操作查询、再次生成来源、编辑和恢复均校验用户、租户、工作区及 `deleted_at`。删除采用逻辑删除；已删除记录不能通过操作缓存或重试保存恢复。管理员统计权限不授权读取他人文章。

本轮完成的是工程实现与限定本机验证。没有 AI 作者概率、检测通过率或“真人度”承诺；专业材料、长文、更多模型和正式部署的验证边界以报告为准。
