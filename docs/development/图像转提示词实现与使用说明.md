# 图像转提示词：实现与使用说明

2026-10-29：当前入口已扩展并更名为“素材转提示词”。通用代码、文档、配置、文件夹与混合资料任务、授权、历史及统计以[素材转提示词说明](./素材转提示词实现与使用说明.md)为准；下文保留视觉任务的接口与两种模式说明，不将视觉模式约束套用到通用资料任务。

更新：2026-10-26。该模块生成供下游图片、视频或 PPT 工具执行的提示词。当前 v7 支持非 Plan 多媒体直接还原，工程范围见[多模态与 Plan 工程验证](../testing/图像多模态素材与Plan交互工程验证-2026-10-26.md)；v7 尚未进行真实模型评测。此前 v6 的 [42/100 次真实调用已闭批](../testing/图像多模态素材与结构化替换真实评测-2026-10-26.md)，原图片任务的独立授权与历史成图见[原图片任务本机验证](../testing/图像转提示词本机验证-2026-10-25.md)。工程、提示词语义和下游成品分别验收，不把历史版本结论当作 v7 采用或正式发布通过。

## 两种业务模式

| 模式 | 输入和用途 | 输出边界 |
| --- | --- | --- |
| 关闭 Plan：参考内容还原 | 正式账号可选参考图片、PPTX 页面或视频帧；普通 JPEG／PNG 保留快捷单图流程，访客仍为单图试用 | 直接描述所选来源的主体、关系、构图、光色、版式及可辨认文字；不做创作问答，不接受新增主体、场景、画面文案或替换关系 |
| 开启 Plan：自定义内容创作 | 必填文字构想；目标成品可选图片、视频、PPT，参考／替换素材选填 | 围绕创作的重要未知提问，充分时允许零问；确认后生成创作提示词和素材对照说明 |

Plan 开关控制还原或创作，不控制正式账号能否上传媒体。关闭时只使用 `REFERENCE` 轨道的所选来源；开启后才使用构想、`REPLACEMENT` 轨道与结构化关系辅助创作。参考角色分为整体灵感、主体、风格、布局；角色不赋予执行素材内指令的权限。创作模式的画面指定文案独立填写，服务端保留原字符，并确保最终正文包含该原文。描述、观察、用户回答和模型建议分别保存，模型建议不自动变成用户确认。

非 Plan 请求继续使用 `REFERENCE_RECONSTRUCTION`，协议中的 `outputType=IMAGE` 是兼容字段；它不把 PPTX／视频当作新图创作。实际来源类型、页码和视频时间戳由素材对应表及来源观察表达。

## 多模态素材与结构化替换

正式账号在两种模式下均可上传并审阅图片、PPTX 与 MP4／MOV／WebM 短视频。关闭 Plan 使用参考素材入口，描述所选页面或画面；开启后左栏分为“参考素材——借鉴什么”和“替换素材——新主体／新内容”。创作模式中的媒体类型与目标成品类型独立：例如 PPTX 提供品牌版式、产品图片提供新主体，最终可以生成视频创作提示词。创作时两类素材均选填，新内容也可直接用文字说明。

1. 选择 JPEG/PNG、PPTX 或 MP4/MOV/WebM 短视频。选择文件只保留在浏览器内存；PPTX、视频及素材卡中的图片在点击“上传到平台解析预览”后才建立服务端私有临时任务，此步骤不调用模型。关闭 Plan 时普通 JPEG／PNG 仍沿用原快捷单图入口，不强制多走解析与选页步骤。
2. 视频选择源文件内不超过 30 秒的片段。平台进行本地抽帧，保留时间戳，并明确报告抽样与未覆盖范围；音轨不发送，不承诺完整运动或音乐节拍识别。视频解码需要部署 FFmpeg 与 ffprobe。
3. PPTX 读取可见页的文本及元素位置，并按用户预览／选择的页面渲染静态图片。隐藏页、备注、动画和内嵌媒体不作为已识别内容。复杂图形及字体可能影响预览，请用户核对。旧 `.ppt` 请先另存为 `.pptx` 或图片。
4. 解析完成后，素材卡显示“可选 N 个／已选 M 个”。点击“选择页／帧与遮挡”，勾选实际识别范围并点击“保存选择与遮挡”；仅打开预览或解析到 READY／PARTIAL 不等于已保存外发范围，不会自动全选。可拖动添加黑色遮挡或使用百分比数值设置。黑色遮挡施加到实际外发图片；存在遮挡的单位，其全部结构原文也不外发，避免文字层绕过遮挡。弹窗完整缩放长图与横图，手机端使用单列和可滚动正文，底部保留保存操作。
5. 仅在开启 Plan 时添加保留、替换、移除或融合关系，指定原对象、新内容、来源页／帧、属性和作用范围。关系是用户要求，视觉观察不是用户确认；不上传替换文件时仍可填写新内容文字。关闭 Plan 不需要构想、关系或问答。
6. 审阅所选范围和接收模型后，单独勾选模型外发同意。关闭 Plan 点击“提取参考素材提示词”，分批识别后直接生成描述性提示词；开启时点击“梳理创作意图”，由图像 Plan 组织必要问题。模型调用只接收当前模式参与的所选画面和允许的结构文字，按已登记 `maxImages` 分批分析。
7. 核对生成的优化提示词与素材对照表，在下游工具重新上传对应文件。平台内部素材 ID 不能让下游直接读取文件；有遮挡时，下游也应使用相同遮挡版本。

若仍无法开始，按钮下方会指出具体素材是尚未上传、解析中、未解析出画面、尚未保存范围，还是旧选区已失效。空解析结果可用“刷新解析状态”重新查询，不重复上传；刷新保留已有选择和遮挡，但失效单位需重新选择并保存。完成所有素材的范围选择后，仍需单独勾选模型外发同意。

模式切换保留当前 Pinia 草稿和仍有效的私有临时资产，包括 `assetId`、所选 `units` 和 `masks`。关闭时替换素材隐藏保留，不参与本次还原，也不携带创作关系；再次开启后可继续使用。切换模式或模型后，需重新核对并勾选外发同意。这不是跨刷新持久化：刷新、关闭页面或资产过期后不保证恢复这些文件和选区。

新旧素材合计最多 6 份，包含暂时隐藏保留的替换素材；本次参与识别的快捷图片和选中页／帧合计最多 12 个，规范化图像合计不超过 30 MiB。原始素材单文件最多 50 MiB，图片仍为 10 MiB，PPTX 最多 100 页。解析与模型图片准入分别校验；多媒体任务不会抬高单次模型图片上限。多批识别、Plan、最终生成及协议修复都计入任务调用上限，识别超时或失败不自动重放模型请求。

历史保留目标成品类型、素材轨道与名称、已选页面／时间戳、遮挡范围、覆盖说明，以及创作时的替换关系和实际题答；非 Plan 还原的题答为空，不保存原件或 Base64。有实际回答时，原卡标为“初始保留与替换关系”，当前要求以实际确认和当前正文为准；生成附录不重新追加已被确认撤销的原卡。恢复历史可以继续复制、编辑和基于已有文字优化；需要重新分析素材时重新上传，创作关系按需重新绑定。原件过期不能靠历史摘要伪装成重新识别。

## Plan 问题与自主补充卡片

开启 Plan 后，“自主补充创作要求”卡片组织现有创作构想、逐字文案和项目上下文；构想必填，其余选填，示例不会自动填成用户要求。修改这些内容或素材、选区、关系、输出设置后，旧 Plan 按原规则失效，不自动重新调用。

Plan 返回后，问题卡位于设置栏顶部，以主题主色边框和较实背景显示。必答进度仅统计 `required=true` 的题；选择任意选项或填写非空自定义回答均可完成必答题，选答可跳过，零问题仍需明确确认后生成。单选、多选、文本与补充答案继续共同保留。

主动取得新 Plan 时仅定位一次，焦点落在标题，不直接弹出手机键盘。定位先稳定就绪提示的布局，再按导航实际高度避让，兼容双行桌面导航；标题、首个缺答题与返回补充卡使用同一定位方式。用户转而编辑或打开历史弹窗时保留焦点，通过“前往回答”入口引导；手机分区显示待回答／待确认状态。动效尊重系统减少动画设置，输入答案时不反复滚动。

新增展示沿用图像 Plan 接口，未合并文字增强的问答链路；新增多模态素材协议及 `ANALYZE` 识别阶段只服务本模块。

## 如何使用

1. 打开 `/image-to-prompt`，先按目标选择模式。关闭 Plan 选择要还原的参考图片或多媒体；开启时填写创作构想，可不提供素材。多媒体上传和审阅不要求先开启 Plan。
2. 选择文件不自动上传。普通单图在核对隐私并勾选同意后，点击提取才上传和调用模型；PPTX、视频及素材卡中的图片先主动上传至本平台解析并审阅，这一步不调用模型。完成范围选择和遮挡后，在生成按钮上方单独勾选“我已检查图片隐私”才可发给所选模型。确认区未勾选时显示暖色边框与“待确认”，勾选后显示“已确认”。已选视觉模型但未完成该项时，按钮仍禁用；按钮下方会说明缺少的操作，不需要因此更换模型。
3. 模型列表与提示词增强共用同一平台目录，名称、排序和启停由模型管理统一维护；两个工作台各自保留本次选择。图像页面始终显示全部已发布模型，不因附图或切换模式隐藏文字模型。附图必须选择已开放视觉能力且图片数量满足限制的模型；能力不足时说明原因并阻止提交，纯文字 Plan 可以使用可用的文字模型。管理员修改配置后可点击“刷新模型”。演示结果会明确标记，不代表识图成功。
4. Plan 出题后，选择选项并填写必要补充；两者同时保留。零问时也可明确确认生成。修改模式、构想、图片、角色或输出设置会使旧计划失效，不自动重新调用。
5. 核对观察来源、识别不确定项和最终正文；可以编辑、取消编辑、撤销同一记录的上次编辑，再复制。剪贴板写入失败时提供手动复制正文。
6. “基于已有文字优化”使用服务端已保存正文及分析摘要，不重新看图。需要重新识图时，重新选择图片并发起相应模式的生成；历史不恢复原图。
7. 生成成功后自动保存图像提示词记录；保存失败时可单独重试保存。历史页面的“图像转提示词”分类直接展示当前用户的记录，支持按参考图还原／Plan 新图创作筛选、分页、查看详情、复制、载入图像工作台及逻辑删除。详情保留构想、指定文案、项目上下文、视觉分析和原始 Plan 题答；载入不重新识图或调用模型，原图不从历史恢复。图像工作台内的“图像历史”入口继续可用，两处读取相同记录；图像与文本记录的接口、状态和恢复目标独立。

关闭标签页或刷新会丢失浏览器内存中的未保存构想、文件和编辑稿。页面内路由离开会保留当前内存草稿；已提交请求保留操作编号，返回后查询结果，不自动重放付费调用。发生版本冲突时保留编辑稿，先读取最新记录再处理。

## 前后端链路

前端为 `ImageToPromptPage.vue → stores/imagePrompt.ts → services/imagePromptApi.ts`，通过现有 Vite `/api` 代理访问后端 `imageprompt` 模块。`ImagePromptHelp.vue` 保留模式定义及使用指南；模型管理页面只有一份模型目录，在对应模型行点击“图像能力”，由 `ImagePromptModelSettings.vue` 编辑视觉准入。已停用模型也可以先配置能力，配置本身不发布或启用模型。

后端由 `ImagePromptService` 编排，复用 `CurrentActor`、平台模型目录、服务端路由、受限 HTTP 客户端、模型并发和调用审计。不会更改原文本直接增强、Plan 或历史协议。`OpenAiImagePromptProvider` 将图片作为 `image_url` 内容块中的 Base64 data URL 发送给兼容多模态模型；不需要独立 OCR 或图片公网地址。v7 的非 Plan 多媒体通过 `extract → extractMaterials` 执行分批 `ANALYZE → GENERATE`，最终生成复用来源证据，不经过 `PLAN` 或确认问答，也不重新发送像素。旧单图继续使用 `EXTRACT`；创作多媒体使用 `ANALYZE → PLAN → 用户确认 → GENERATE`。`ImagePromptMediaService` 的上传、解析和私有预览本身不绑定 Plan 模式，不调用模型。

仅 JSON 协议失败允许一次修复，网络失败、超时和内容拒绝不自动重试；整任务最多 28 次实际尝试，180 秒后停止开启新阶段。带 `materials` 的直接提取和多素材 Plan 前端等待上限均为 270 秒，异常仍通过操作查询恢复，不能因超时自动重放。普通单图和纯文字请求保持原等待配置。

视觉观察采用图片 UUID、类别、描述与 `OBSERVED / INTERPRETATION / UNCERTAIN` 状态。ANALYZE 只接收来源内容、选择范围和批次元数据，不接收创作构想、新文案、关系或题答；Plan 不把目标要求追加为新观察。遮挡是隐私处理，不属于原始风格或布局。接口中的最终 `Document.questions/answers` 是已确认的原始题答档案，不表示生成阶段又要求用户答题。可复制正文为 `optimizedPrompt`，包含下游所需的素材对照及实际确认说明。

新结果独立保存 `evidenceWarnings` 来源风险，编辑、撤销和基于文字修订继续保留，并交给生成／修订模型。旧 JSON 缺字段或 null 时，仅从素材静态风险及 UNCERTAIN 观察有限恢复；显式空数组保持为空，不能从旧混合 warnings 无损还原所有风险。V42／V43 维护此前的 JSON 列注释；本次 V44 仅前向补充非 Plan 多媒体还原的模式与 JSON 语义注释，不改结构或历史数据，本次未执行 V44。

## 模型统一配置与 Plan 复用边界

统一的是模型目录和配置入口。`ImagePromptModelService.models()` 与文本增强都以 `PlatformModelCatalog.available()` 为来源，按目录原顺序返回模型；视觉准入是同一公开模型标识上的附加能力，不是另一套模型注册表。管理员读取 `PlatformModelCatalog.all()`，因此能配置已停用项；逻辑删除项继续排除。模型发布、停用或移除同时影响两处，视觉开关只影响带图调用。

配置步骤：在“模型管理”新增或编辑目录项，维护名称、启停、排序与默认模型；需要识图时，在该行打开“图像能力”，登记允许图片输入、最多图片数及官方文档或受控验证依据。带图任务同时受全局启用状态与视觉准入约束，前端提示不能替代服务端再次校验。文字模型可以保持在列表中供无图 Plan 使用，不因统一目录而被视为支持识图。

**图像 Plan 与文本增强 Plan 当前是独立业务链路。**两者都采用“梳理重要未知 → 用户回答 → 生成优化提示词”的流程，但没有复用同一个 Plan 编排器或问答协议：

| 环节 | 提示词增强当前 V2 入口 | 图像转提示词 |
| --- | --- | --- |
| 业务目标 | 围绕原始提示词保留报告、代码、方案等交付物，澄清实质未知 | 围绕用户构想定制图片、视频或 PPT，参考素材按角色提供来源 |
| 发起 Plan | `/api/v2/optimizations/plan` → `NaturalEnhancementService.plan` → `NaturalPromptProvider.plan` | `/api/v1/image-prompts/plans` → `ImagePromptService.plan` → `ImagePromptProvider.invoke(PLAN)` |
| 输入和会话 | 原始提示词、安全项目上下文、会话历史；`PlanningSessionService` 绑定原题与上下文版本 | 构想、逐字文案、参考角色和视觉观察；`ImagePromptStateStore` 保存 `BoundPlan`、输入指纹和图片有效期 |
| 回答后生成 | `/api/v2/optimizations` 携带 `planConfirmation`；自然正文进入 `NaturalEnhancementService.optimize`，结构化正文进入原编排器 | `/api/v1/image-prompts/plans/{id}/confirm`；核对实际选项与自定义回答，进入 `invoke(GENERATE)` |
| 确认阶段是否重新看图 | 文本链不接收此模块的图片资产 | 不重新发送像素，使用已绑定的视觉分析、输入及实际题答 |

旧 V1 文本 Plan 接口仍由 `OptimizationPlanningServiceImpl` 处理，也不是图像 Plan 的实现。两条链路共享服务端身份、模型目录、供应商路由、受限 HTTP 客户端、并发控制和调用审计；不共享 Plan 会话、提示词指导、问答 DTO 或业务历史。文本 Plan 的优化不会自动应用于图像 Plan，本次没有合并两套业务链路或更改其产品语义。

| 接口（均在 `/api/v1` 下） | 作用 |
| --- | --- |
| `GET /image-prompts/capabilities` | 可用模型、图片限制、历史持久化状态 |
| `POST /image-prompt-assets` | Multipart 主动上传、解码及元数据清理 |
| `GET /image-prompt-assets/{id}`、`DELETE` 同路径 | 私有预览、撤销资产 |
| `GET /image-prompt-media/capabilities` | 媒体限制及实际视频解码可用性 |
| `POST /image-prompt-media` | Multipart 私有解析任务，视频可附 `startMs/endMs` |
| `GET /image-prompt-media/{id}`、`DELETE` 同路径 | 查询解析状态或撤销临时素材 |
| `GET /image-prompt-media/{id}/units/{unitId}` | 当前完整身份下的私有页／帧 PNG 预览 |
| `POST /image-prompt-media/{id}/units/{unitId}/export` | 按提交的归一遮挡矩形导出供下游使用的 PNG 静态画面，不调用模型 |
| `POST /image-prompts` | 参考图片／所选 PPT 页面／视频帧的描述性直接还原，不进入 Plan |
| `POST /image-prompts/plans` | 新图创作 Plan，可无图 |
| `POST /image-prompts/plans/{id}/confirm` | 服务端绑定计划与实际题答生成 |
| `GET /image-prompts/operations/{id}` | 查询已提交操作，不再次调用模型 |
| `POST /image-prompts/operations/{id}/save` | 单独重试保存已生成结果 |
| `GET /image-prompts/history` | 分页查询，`current`、`size=10/20/50`、可选 `mode` |
| `GET /PATCH /DELETE /image-prompts/history/{id}` | 当前正文、乐观修订、逻辑删除 |
| `POST /image-prompts/history/{id}/re-optimize` | 基于已保存文字再次优化 |
| `GET /PUT /admin/image-prompt-models` | 管理员读取与登记能力；PUT 的 `modelId` 为查询参数，兼容包含斜杠的模型标识 |

## 配置、存储与权限

- 新媒体私有目录配置为 `app.image-prompt.media-directory`，默认 `${java.io.tmpdir}/prompt-optimizer-media-assets`。资产默认一小时有效；图片／视频产生派生 PNG 后清理原件，PPTX 为按需渲染保留至临时有效期结束。共享部署仍需共享私有临时目录；没有对象存储自动适配。
- 视频使用 `app.image-prompt.ffmpeg` 和 `app.image-prompt.ffprobe` 指定可执行文件，默认从 PATH 查找。可通过对应环境变量 `APP_IMAGE_PROMPT_FFMPEG`、`APP_IMAGE_PROMPT_FFPROBE` 注入；缺少工具时能力接口与页面明确提示，不伪造解析成功。仅部署到本机验证目录的工具不代表其他部署已配置。

- 原 JPEG/PNG 资产及旧 `images` 接口沿用每张 10 MiB、1500 万像素、单边 8192 和协议最多三张的限制；没有 `materials` 的直接还原仍只接受单图。两种模式的 `materials` 接口均采用上文新旧素材合计六份／本次识别十二个单位的任务限制，规范化图像总量仍为 30 MiB，并按管理员登记的 `maxImages=1..3` 分批；未经视觉准入登记不接受图片。
- 先验证实际格式和尺寸再分配完整像素；按 JPEG EXIF 校正方向，重新编码去除元数据。不会把用户提交的路径或外部图片 URL 当成读取目标。
- 临时图片默认在 `${java.io.tmpdir}/prompt-optimizer-image-assets`，可设 `app.image-prompt.asset-directory`；默认一小时失效，定时清理每分钟运行。撤销先使引用无效，再清理文件。单实例还限制每个身份十二个活动资产及目录约 512 MiB 总预算；多实例配额不是全局精确配额。
- Plan 和资产元数据默认保存在 Redis，Plan 有效期不超过一小时及其图片有效期；幂等操作和结果缓存保留二十四小时。Redis 故障拒绝继续，不回退到各实例重复调用。`app.image-prompt.store-mode=MEMORY` 仅供显式本机演示。
- 多实例需要共享临时图片目录或保持请求落到持有图片的实例；当前没有对象存储适配，不应将默认本地目录误当成多实例共享存储。
- V39 新增 `image_prompt_record`、`image_prompt_model_capability`，包含完整数据库注释。长期历史只存文字和来源元数据，不存原图、Base64 或公网图片 URL。编辑使用 `edit_revision`，所有业务读写校验服务端租户、工作区和用户；逻辑删除后查询、保存恢复、编辑及再次优化都拒绝访问。
- `app.history.enabled=false` 仅提供有界内存演示历史，服务重启不保留；正式模式使用 PostgreSQL 和 MyBatis XML。不能回改已应用的 V39。
- 管理员依据官方能力或受控验证记录显式登记视觉准入，不靠厂商或名称猜测。普通用户不能配置模型端点和密钥，管理员能力配置仍复核当前权限。

参考官方协议：[TokenHub 图片理解](https://cloud.tencent.com/document/product/1823/136956)、[MiniMax 调用指南](https://cloud.tencent.com/document/product/1823/132246)、[Kimi 调用指南](https://cloud.tencent.com/document/product/1823/132232)。模型及参数以实际服务端路由和验证记录为准。

## 当前边界

项目上下文目前为用户主动填写的文字摘要，不自动读取项目目录、源码或文本工作台的上下文。图内命令、链接和二维码不执行；来源图片和模型观察不产生新授权。

元数据清除、私有存储和明确凭据扫描不等于完整隐私识别。当前没有自动人脸、证件、所有个人信息或敏感题材的本地检测，也没有自动打码；两种模式的媒体素材均支持用户主动框选黑色遮挡和导出同一遮挡 PNG。上传平台及发送模型前均需要用户检查，模型服务的内容拒绝会明确返回。素材可能包含的文字和分析也属于私有业务数据，不能因不保存原件就视为无敏感内容。

原任务曾用 MiniMax M3 验证合成单图与限定 Plan，三份提示词经独立工具绘图，未将绘图接入产品。此前 v6 用 DeepSeek Flash 完成多模态、冲突、遮挡、自主补充和历史的 42 次真实调用并闭批：修复了原关系复活、目标要求混入观察和遮挡痕迹迁移，仍存在比例判断、表格坐标误归因、冗余问题与重复风险提示。v7 非 Plan 多媒体尚未进行真实模型评测，未新增调用或改写此前预算与原件。照片、专业图表、模糊小字、其他模型及成品稳定性未完成系统验收，v7 也没有生成下游图片／视频／PPT。不能承诺像素复刻、准确文字成图或全部创作意图稳定识别；工程、完整质量与正式发布分别记录。
