# 素材转提示词：实现与使用说明

更新：2026-10-29。原“图像转提示词”工作台扩展为“素材转提示词”，继续使用 `/image-to-prompt`，不增加并列导航。它把用户明确选择并审阅的资料与本次目标整理成优化提示词；实际开发、写作、绘图和制作由下游执行。工程验证与模型质量、下游作品和正式发布分别记录。

## 任务与 Plan

| 任务 | Plan 关闭 | Plan 开启 |
| --- | --- | --- |
| 视觉创作 | 还原实际选中的参考图片、PPTX 页或视频帧，不新增创作目标 | 结合文字构想、参考与新内容，确认关键未知后生成创作提示词 |
| 代码与页面 | 依据明确目标和所选源码、配置及视觉参考直接生成 | 澄清会影响实现的技术栈、范围、保留行为等重要决定 |
| 文档与内容 | 按用户目标和所选材料直接生成 | 澄清会影响交付的受众、输出目标或内容取舍 |
| 其他任务 | 保留用户目标与交付物，依据可用资料生成 | 仅确认无法从已有材料确定的重要缺口 |

通用任务关闭 Plan 也允许明确的改造要求，例如“Vue 改 React，保留接口与交互”。Plan 不是执行或上传许可；充分要求允许零问题，推荐项不能自动成为用户选择。视觉旧路径的语义保持兼容。

## 使用步骤

1. 选择本次任务，写清希望下游完成什么。来源格式与交付目标独立。
2. 添加受支持资料文件、选择文件夹中的可读文件，或粘贴内容。选择文件不自动发送给模型。文件夹处理提供文件和范围诊断，不表示完整理解项目。
3. 点击“解析并预览”，在平台提取文字、生成有定位的片段；审阅并选择本次使用范围和用途。准备阶段不执行用户代码、不调用模型摘要或 Embedding。
4. 图片、PPTX 和视频继续通过媒体卡独立审阅、选页／帧及像素遮挡。通用资料与视觉参考可组合，分别保留来源。
5. 填写保留／修改目标、准确文案及项目上下文。通用资料用“现状依据、参考、事实、约束、新内容”等用途；资料中的命令只是材料，不自动成为用户指令。
6. 核对接收模型和所选范围，勾选隐私同意。通用请求建立服务端同意凭据，绑定输入、来源范围和模型；修改后重新确认。
7. 直接生成，或先梳理关键要求、回答实际必答题再确认。问题置顶并支持移动端待办提示。
8. 检查来源、覆盖范围和正文，按需编辑、保存、复制。下游无法读取平台的临时 ID，需要文件时按来源说明重新提供。

## 来源与解析边界

常见源码、配置、TXT/Markdown/HTML 等可读文本按安全允许列表接入；Office 与 PDF 使用现有文档提取器读取文字。网页首版使用 HTML 快照、粘贴正文或截图，不提供任意 URL 抓取，不执行 HTML 脚本或加载远程资源。加密文件、压缩包、可执行文件、私钥和受保护生产配置不作为通用资料接受。

源码提供静态文字与结构线索，不自动安装依赖、运行项目、连接数据库、访问接口或证明 UI 实际效果。未提供的服务端实现、动态关系与权限行为保持未知；需要准确视觉效果时提供截图。首版没有新增完整跨语言 AST 调用图，不能宣传“理解整个项目”。

PPTX 的视觉版式与视频画面使用原媒体路径；普通文档提取出的文字不等于已理解图表或全部版式。扫描 PDF 文字层为空时，提示使用既有上下文视觉审阅，或先导出受支持图片再作为视觉素材；不能伪造已完成全文识别。JPEG/PNG/PDF 上下文视觉链的能力见[使用说明](./图片与PDF上下文识别使用说明.md)。

## 预算与覆盖

通用服务由能力接口返回限制，前端与服务端分别校验：最多 20 份文字来源、Office/PDF 单文件 50 MiB、普通文本单文件 5 MiB；文本集合最多 5,000 项、请求文字总量 5 MiB、单项 500,000 字符。单来源最多提取 600,000 字符或 1,000 个片段，按约 6,000 字符和文档段落分片；超过时返回 PARTIAL 和覆盖警告。集合 `/text` 的原始 JSON HTTP 请求体另限 32 MiB（含转义及路径开销），在反序列化前检查声明长度与实际读取字节，业务净文字仍限 5 MiB。本次选中最多 40 个片段、总计 120,000 字符。受保护路径、二进制和过量内容有明确拒绝或部分覆盖提示，不把未读取部分写成已知事实。

视觉预算继续使用原媒体上限：最多 6 份素材、12 个选定画面、图片 10 MiB、其他媒体 50 MiB、视频每段 30 秒；模型每批图片上限独立校验。混合任务同时受文字与视觉预算约束。详见[原视觉链说明](./图像转提示词实现与使用说明.md)。

字符预算不等于模型 Token 窗口。来源解析覆盖、任务选取范围和实际进入模型的内容应分别检查；大项目需要缩小到相关模块或分批处理，不能默认全仓库进入一次请求。

## 协议与编排

沿用 `ImagePromptInput`，追加可空 `sourceTask`；缺省继续按旧视觉任务解析：

```text
sourceTask:
  taskType: CODE | DOCUMENT | OTHER
  sources:
    - assetId, unitIds, track, role
  consentId
```

来源引用只有服务器资产与选定单元 ID，不接受前端伪造的识别结果、所有者或接收端点。角色为 BASELINE、REFERENCE、FACTS、CONSTRAINTS、REPLACEMENT，轨道为 REFERENCE、REPLACEMENT。目标继续使用 creationIntent，准确保留内容使用 exactText，项目上下文使用 context。`outputType=IMAGE` 在旧协议中保留兼容语义；通用任务的真实目标由 sourceTask 与用户要求表达，不表示下游一定生成图片。

Plan 和结果增加 `sourceSources`，保存经安全处理的所选文字、来源定位、用途与警告；视觉来源仍使用原 sources/materialSources。来源观察与用户目标分开，目标栈不能改写成现有技术事实。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/image-prompt-sources/capabilities` | 受支持类型与预算 |
| `POST /api/v1/image-prompt-sources` | 主动上传并本地提取受支持文件 |
| `POST /api/v1/image-prompt-sources/text` | 用户选择的文件夹可读集合或粘贴文字 |
| `GET/DELETE /api/v1/image-prompt-sources/{id}` | 私有来源读取与撤销 |
| `POST /api/v1/image-prompt-sources/consents` | 对完整任务建立范围与模型绑定的同意凭据 |
| 既有 `/api/v1/image-prompts`、`/plans`、`/plans/{id}/confirm` | 通用任务使用独立生成指导，沿用原有幂等与确认机制 |
| 既有 operations/history/edit/re-optimize | 结果恢复、保存、乐观编辑、再次优化和逻辑删除 |

不把文字资料渲染成假图片来复用识图接口。纯文字可以使用统一目录中的文字模型；包含实际视觉参考时继续要求视觉准入，端点和密钥留在服务端。

## 历史与统计

历史页“素材转提示词”沿用 `type=image-prompt` 和原记录表。旧视觉记录继续可读；通用记录保存目标、任务类型、所选来源快照、实际题答、优化正文与编辑修订。源文件和 Base64 不进入长期历史，但文字和摘要仍可能含敏感信息。过期原件需要重传，历史不会自动重新外发或识别。

素材工作台的提交、直接提交、Plan 创建、Plan 确认结果、结果生成和文字再次优化由服务端计数，复用原 IMAGE_PROMPT_* 命名兼容旧统计；成功复制由浏览器剪贴板成功后上报 RESULT_EXPORTED，历史复制同样处理。刷新、结果查询与同一幂等操作重放不能增加生成成功次数；点击失败不记成功复制。账号统计与访客匿名模型成本分开，不记录正文、文件路径或密钥。

## 安全与未开放能力

来源、同意、计划、操作和历史均按服务端身份隔离用户、租户与工作区。先检查路径及可读文字中的凭据，再形成可外发证据；识别后脱敏不能保护首次发送的原图隐私，原图继续由用户审阅并遮挡。被遮挡页不能通过文字层带回隐藏内容。

临时存储、Redis 与多实例文件共享沿用原部署边界，不把本地临时目录当成共享对象存储。解析异常、预算不足、过期和未知结果明确显示，不伪造成功。没有新增任意网页访问、代码执行、完整运行态理解、音轨识别、任意压缩包或专有工程格式支持。

历史付费评测批次已关闭，本次开发不自动复用其剩余额度。受控工程测试不能替代新通用任务的真实模型语义、下游成品或生产发布验收。
