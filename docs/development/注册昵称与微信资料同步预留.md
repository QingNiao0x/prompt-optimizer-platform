# 注册昵称与微信资料同步预留

更新日期：2026-10-27。

## 当前交付

统一邮箱/手机号注册表单增加“昵称（选填）”，使用现有 Element Plus 与主题。输入去除首尾空白，长度限制与现有 `user_account.display_name VARCHAR(80)` 保持一致，支持中文和表情，禁止换行及控制字符；昵称不要求唯一，不参与登录、权限或账户归属判断。

注册请求增加可选 `displayName`。旧客户端不传该字段仍可注册；空白视为未填写，邮箱注册沿用邮箱本地部分默认名，手机注册沿用“新用户”。用户自填昵称在原有创建账户事务中保存，登录响应继续返回账户的 `displayName`。更改昵称不重新发送验证码，也不使有效的邮箱/手机挑战失效；复用已经完成的手机注册挑战不会改写原昵称。

昵称只在注册表单显示。切换登录、关闭弹窗和重新打开注册会清空未提交昵称。新增字段增加了弹窗高度，注册弹窗现在在桌面低窗口和手机上均可内部滚动，已有账号入口与提交按钮可达。

## 微信接入扩展点

本轮没有接入实际微信OAuth或调用微信接口。未来完成服务端授权核验、查询微信资料并确认已有绑定关系之后，回调编排可调用：

```java
wechatNicknameSynchronizer.syncVerifiedNickname(appId, verifiedSubject, verifiedNickname);
```

`appId`、主体标识和昵称必须来自服务端核验后的第三方资料，不能接受浏览器自行声明的微信身份。该方法没有公开HTTP入口，也不创建身份、迁移或合并账户。

微信昵称同步到已绑定 `WECHAT` 身份的 `user_identity.provider_profile`，属于该身份关联账户的资料。默认结构为 `{}`，同步后的已知键为：

```json
{
  "nickname": "第三方昵称",
  "nicknameSyncedAt": "2026-10-27T00:00:00Z"
}
```

JSONB顶层必须是对象，键集合允许扩展，例如未来可增加头像资料。本次更新合并现有对象，保留其他扩展键；数据库不强制具体键及值类型。资料同步只匹配同一应用和主体的活动微信身份，并要求所属账户为 `ACTIVE`。缺少绑定、已撤销身份或锁定/禁用账户不能通过资料同步恢复资格。

平台自填昵称与第三方昵称分开保存，因此后续微信昵称变化不会静默覆盖注册时的选择。资料字段不能作为认证或角色依据；空微信昵称不清空已有资料。正式微信接入时，身份核验与展示资料更新的失败处理仍需分别实现，不能用昵称同步成功代替登录核验。

## 迁移与部署

新增前向迁移 `V45__identity_provider_profile.sql`：增加非空JSONB资料列、顶层对象CHECK和准确字段注释。已应用的旧迁移保持原样，账户原昵称及登录键不变。

部署前后端新版本时需执行V45。常规启用Flyway的后端启动会应用它；如果环境显式关闭了Flyway，需要在新代码使用新列前执行受控迁移。本轮仅在独立测试库应用迁移，没有更新业务数据库或生产环境，不需要修改SMTP、短信或本地环境变量名。
