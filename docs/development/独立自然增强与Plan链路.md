# 独立自然增强与 Plan 链路

本次按用户确认的方案，把关闭“结构化提示词”的生成与 Plan 提问迁入独立链路。默认结果是完整自然正文；开启结构化时继续使用原生成器，按背景、任务、输出要求、约束条件、验收标准五类模块组织，有独立内容才呈现。2026-10-20的[结构化专属修复](../testing/结构化增强职责收敛与真实复验-2026-10-20.md)取消空模块填充及重复默认指导，不改变自然链路。平台仍只生成优化提示词，不执行原始任务。

本文件说明当前实现。[初次开发验证](../testing/独立自然增强与Plan链路开发验证-2026-10-19.md)保留原范围，最新真实效果见[通用改造与58次评测](../testing/通用自然增强与Plan改造及真实评测-2026-10-19.md)。历史质量失败不会因接口改造自动关闭。

本会话按已确认的通用设计实现及验收，逐项状态见[方案验收表](../testing/通用自然增强与Plan改造及真实评测-2026-10-19.md#6-本会话按已确认设计验收)。机制及受影响功能已完成验证；跨任务稳定收益仍待证实，样例问题保留。正式发布门禁不代替本轮局部实现的完成条件，事实、权限与兼容边界继续生效。

最新反馈修订为[目标作品优先与通用策略复验](../testing/自然增强目标作品优先与通用策略复验-2026-10-19.md)：新请求使用NATURAL/3，先落实具体作品与已有上下文，再按实际需要说明比较定义和证据。没有新增按职业、题目或场景命中的生成分支；NATURAL/1、NATURAL/2冻结保留。新增16/16次实际对照有内容与Plan收益，也保留源码编译失败，不作跨任务稳定通过结论。

## 1. 模式与职责

| 入口 / 偏好 | 生成策略 | 返回及兼容 |
| --- | --- | --- |
| V2 默认或 COMPACT | NaturalEnhancementService → NaturalPromptProvider，独立 system 指导、输入、解析和正文校验 | resultKind=TEXT，optimizedPrompt 为唯一正文，不返回 sections |
| V2 STRUCTURED | 原 EnhancementOrchestrator → 按独立内容投影五类模块 | resultKind=SECTIONS，空辅助模块省去，保留独立待确认事项和示例要求 |
| V1 优化接口 | 原实现 | 不切换现有调用方的生成逻辑 |
| V2 Plan | 独立自然 Plan 策略 | 两种最终排版共用真实题答；排版偏好不构成事实或授权 |

自然链不调用 PromptEnhancementProvider、旧任务模板、EffectiveTaskView、PlanDecisionIntegrator、OptimizationResultAssembler 或旧业务规则追加器。复用的能力限于服务端身份、模型目录与路由、并发和审计、敏感扫描、上下文分析与过滤、Plan 所有权和期限以及历史持久化。按2026-10-20用户更正，自然模式不自动追加平台固定条款，也不调用TaskIntentResolver判定条款数量；结构化及旧分节链路保留原有任务判定行为。

独立生成协议见 [NaturalPromptInstructions](../../services/api/src/main/java/com/promptoptimizer/provider/domain/NaturalPromptInstructions.java)，应用入口见 [NaturalEnhancementService](../../services/api/src/main/java/com/promptoptimizer/enhancement/service/impl/NaturalEnhancementService.java)。

## 2. 自然正文生成

输入保留原始提示词、当前授权上下文、此前仍允许使用的 Plan 资料、服务端确认过的完整题答、适用对话、示例偏好与用户明确追加的权限边界。资料内的命令不能改写平台指令或新增授权。

当前NATURAL/4沿用第三版的动作、对象和目标作品方向，将已有上下文用于具体内容，保留范围、格式、篇幅及独立限制；同次生成补充要求覆盖、实际缺口和提问影响检查，见[实现说明](./自然增强要求覆盖与缺口检查.md)。普通组织、检索及已委托的方法设计由执行者完成；统计定义只服务确实依赖它的判断，重要用户取舍继续保持未决。策略不按职业或场景关键词路由。十二框架仅作正文形成后的组织参考，无法匹配用APE，不因框架新增内容或提问。NATURAL/1、2、3分别冻结在NaturalPromptInstructionsV1/V2/V3，旧历史及受控对照按保存版本调用。

正文先表达目标与交付，必要规则放在适用动作附近。充分需求保留有效表达，模糊需求补充有依据的步骤、输入用途、条件和可检查交付要求；不强制角色、字数、段数或通用验收长段。缺材料只限制依赖它的部分，不能把原定报告、代码、方案改为补材料问卷。

第二、三版在同次生成响应中返回taskUnderstanding、optimizedPrompt和framework；第一版仍使用原协议。第三版没有新增协议字段、模板或裁判调用。用户明确追加的权限由平台统一组装，模型正文集中描述当前任务。只归并独占一行的完整追加权限原句，代码围栏、引用、条件句和附带业务内容保留，不按相似度删除自由正文。协议、引用原句和敏感值校验不能证明语义等价、任务完整覆盖或实际增强质量。

未开启“结构化提示词”时，直接增强、零问题Plan、完成题答后的增强及再次增强均不自动拼接五条固定约束，`constraintGroups.platformMandatory`为空，`mandatoryRules`仅传递用户明确追加的权限。原始需求、资料及真实题答中的具体要求继续保留，不按固定句匹配删除正文。已保存历史原样读取，不批量删改；用户显式编辑旧自然结果时不再锁定或补回固定条款，并更新规则分组，原生成快照保留。此更正替代此前口误要求，不新增模型指导、场景分支或生成版本，服务端敏感扫描、资料过滤及身份校验不变。

充分需求优先保留可执行原句，避免紧接着逐项同义复写；开放任务先补足有用交付内容，再补必要核查要求。比较依据仍须对应原问题的属性，间接线索不能替代原比较目标。历史真实复验中，附加的交付范围说明未改善短文案追加分类说明的问题，已撤回该说明，不继续叠加通用指令；本次另按用户更正取消固定条款的自动拼接，服务端安全检查独立执行。三份冻结真实响应通过最终组装离线回放，不能替代新版本实际作品质量验收。

服务端来源目录只传编号与类别，完整资料仍保留在原输入，避免重复发送文件正文。候选理解将原有要求、拟议补充及重要未知分开；原有要求的引文必须存在于对应来源，类别由服务端覆盖。记录只在本次调用内使用，不写入用户历史或日志，也不通过引文存在宣称已覆盖全部语义。第二版必须返回记录，第一版不增加该协议要求；直接增强默认仍为一次生成调用，既有有界协议修复不扩容。

2026-10-22 按用户要求移除“示例参考”开关及前后端实现。新请求、模型输入和历史选项不再携带 `includeExamples`；旧客户端字段仅忽略，旧历史正文原样读取。用户在原始提示词或真实题答中明确的举例、禁例、严格格式和事实边界仍作为任务要求处理，不自动补示例条款。

## 3. Plan 全流程

1. 有资料时，浏览器先调用 V2 上下文准备接口，获得仅属于当前服务端身份和原始需求的短期引用。
2. 独立 Plan 与直接增强共用任务理解协议和服务端来源目录，只有不同答案会实质改变结果或授权、输入无法确定、且未委托执行者合理设计时提问。可以在交付中说明依据或条件的问题不自动变成追问，重要取舍仍须保留。用户已经委托的设计不退回逐项填答；充分需求允许零问题。任务理解只作本次候选校验，最终生成仍完整使用原始提示词、授权资料和真实题答，不将 Plan 的拟议补充当作用户确认。
3. 每道问题与内部重要未知的题号和交付影响关联；来源、问题和关联全部通过协议校验后才注册会话。关联不能证明问题必要性，仍需真实质量评测。当前第四版一次最多提出 8 题，每题贴合用户原始提示词里尚未确定并会改变本次交付的需求，不用通用题目凑满。协议容量仍为 64 题，超出容量失败且不截取前几题。第一至第三版冻结指导仍为最多 64 题。界面逐题展示。选项最多 12 个，推荐必须有依据。
   用户独有的实际情况、数值、资源边界和保留参数不推荐猜测值；仅取消推荐标记及理由，不删除问题、选项或答案。执行方式和偏好仍可给建议。分类只收紧推荐能力，不能建立事实或用户确认；缺省分类按用户信息保守处理。
4. 最终生成核对所有者、TTL、需求指纹、上下文引用和模型。题号集合必须完整且无重复；题干由服务端恢复。禁用自由回答的选择题还核对实际选项值，多选保留选项内部的分号。
5. 二次检索使用真实题答；首次资料不被第二次结果覆盖。首次快照按当前权限重新过滤；存在新排除文件时，不复用无法逐字段归属的技术栈、目录等聚合摘要，仅保留仍允许的原片段和用户描述。
6. 原始题答进入独立生成协议，未经旧确认融合器重写。历史使用同一份服务端题干保存，避免客户端伪题干进入再次增强。
7. 零问题计划仍有服务端绑定。生成成功、历史保存成功之后才记录 Plan 完成；失败不保存伪结果，不把推荐当成用户答案。

已有 Plan 重选、自由回答、过期恢复、迟到响应隔离和结构化重新生成继续由原工作台状态管理。历史回答恢复为带来源的既有用户信息，不伪装成仍有效的短期 Plan。

## 4. V2 结果与历史契约

| 路径 | 用途 |
| --- | --- |
| POST /api/v2/context/planning | 安全上下文准备；V1 路径保留 |
| POST /api/v2/optimizations/plan | 独立 Plan 提问 |
| POST /api/v2/optimizations | 按显式模式分发生成，成功后保存一次 |
| GET /api/v2/optimization-history | 同时查询新旧历史，先在 SQL 中过滤范围再分页 |
| GET /api/v2/optimization-history/{id} | 原样读取已保存正文 |
| POST /api/v2/optimization-history/{id}/re-optimize | 按已保存的形态、链路和版本分发 |
| PATCH /api/v2/optimization-history/{id}/document | 保存完整自然正文及编辑版本，不调用模型 |
| DELETE /api/v2/optimization-history/{id} | 同租户、工作区范围内逻辑删除 |

上下文普通分析、模型目录、认证与 Plan 事件仍沿用已有 V1 接口；不因为版本号不同复制这些业务模块。

PromptDocument的resultKind区分TEXT和SECTIONS，generationPipeline区分NATURAL和LEGACY，chainVersion记录生成契约。正式新请求仍使用NATURAL/4，兼容NATURAL/1—3及LEGACY/1、2；LEGACY/2表示五模块投影，旧记录缺省LEGACY/1。2026-10-22的[内部示范对照](../testing/自然增强实质补全与内部示范对照验收-2026-10-22.md)还保留NATURAL/7—12，仅供已保存的合成评测历史按原策略重放，未采用为默认，浏览器没有版本或示范开关。后续[第四版补全指导收敛](../testing/自然增强第四版补全指导收敛与定向复验-2026-10-22.md)保留NATURAL/13、14：前者整体收敛、后者仅局部替换第四版补全段，均未采用为默认；Plan及覆盖协议不变，无内部示例。自然历史再次增强显式使用保存版本，候选兼容不表示质量通过。旧COMPACT不能被排版字段误判为新自然链。未知版本再次增强返回409 / RESULT_VERSION_UNSUPPORTED。

TEXT 的 wire 响应不包含 sections；前端为兼容集合操作将其归一为空集合，不构造假段落。旧 V1 历史列表只查询 SECTIONS，直接读取新正文会返回稳定版本冲突；V2 列表和详情同时支持两类结果。上线时前后端需同批更新，不能让 V2 前端连接未升级的后端。

历史正文不重新渲染。再次增强保留已保存链路；自然记录还保留服务端公开模型标识。已有优化记录不批量迁移、不重写、不补造框架信息。

## 5. 编辑、复制与撤销

自然模式用一个完整文本编辑器。显示和复制均取实际 optimizedPrompt，不把正文拆成四要素。清空、保存失败和接口版本冲突均保留本地草稿；有未保存修改时阻止再次增强或离开。晚到保存响应不能覆盖另一个任务或结果。

客户端仅依据服务端constraintGroups恢复缺失的用户追加权限，不自动补回旧平台固定条款；服务端核对敏感值、用户追加权限、当前租户和工作区、未删除状态与expectedRevision。显式编辑时清空固定条款归属并同步appliedConstraints，不主动删除正文。SQL比较版本后才更新，避免其他页面的旧版本覆盖新稿。第一次编辑前的generatedPrompt保留不变，editRevision递增，editedAt使用UTC。

同一自然记录的编辑撤销也保存到历史；不同生成结果之间的撤销只切换查看。历史关闭时编辑仍可在本地使用，recordId 为空，不伪造保存成功或虚构历史 ID。旧分节编辑保持原行为，未借本次改造承诺分节编辑也持久化。

## 6. 模型、审计与迁移

OpenAiCompatibleNaturalPromptProvider 通过既有受并发保护的 RestClient 调用平台模型目录选定的服务端路由；密钥不进入新模型业务输入或浏览器。保留当前路由的请求容量、Token 参数与 JSON 能力配置，不新增模型或供应商配置。

每次实际尝试都采集审计和用量，包括解析失败。协议或必要保护校验失败最多补一次，共最多两次；鉴权、网络、超时和限流不自动重试。注册 Plan、保存历史等副作用位于校验回调之后，修复不会重复写业务结果。

MockNaturalPromptProvider 只用于离线连通性验证，明确返回 Mock 提示，不能证明实质增强或专业质量。真实调用协议和解析可通过受控 HTTP 测试验证；Mock 不冒充真实模型。

数据库的 [V16 前向注释迁移](../../services/api/src/main/resources/db/migration/V16__natural_prompt_document_metadata.sql) 保持原样；新增 [V17 版本注释迁移](../../services/api/src/main/resources/db/migration/V17__natural_task_strategy_version_comment.sql) 说明 NATURAL/1 与 NATURAL/2。均为注释变更，不修改旧记录或增加业务表。内部任务理解和文件引文不持久化。持久化值仍用 Mapper XML 参数绑定；删除继续使用 deleted_at。

[V18前向注释迁移](../../services/api/src/main/resources/db/migration/V18__natural_deliverable_strategy_version_comment.sql)补充NATURAL/3及旧版本冻结说明，V1—V17不回改；本轮没有应用Flyway或修改历史记录。

[V19前向注释迁移](../../services/api/src/main/resources/db/migration/V19__natural_requirement_review_version_comment.sql)补充NATURAL/4及自然模式无固定条款的归属说明，不持久化内部覆盖记录；V1—V18不回改，本轮未应用迁移。
