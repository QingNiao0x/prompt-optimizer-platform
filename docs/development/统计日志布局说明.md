# 统计日志布局说明

本文主体记录 2026-09-28 的布局调整。当前统计语义与交互已在 [2026-10-02 审查修复](../testing/统计日志审查修复-2026-10-02.md) 中补充：每日五项指标、统计时区、正值峰值、补零空状态、单日标记、就近日志筛选和币种分组；历史说明中的“后端未变更”仅指当时批次。

本次调整面向 `/admin/analytics`，只处理展示布局与响应式体验。统计口径、日期边界、后台权限校验、接口字段以及查询、排行和分页行为保持原有实现。

后续本地库验收补充了筛选状态修复：只有成功提交的查询条件才用于分页与排行；丢弃旧明细响应，明细失败单独显示错误。接口及统计口径不变，详见 [统计日志本地库验收](../testing/统计日志本地库验收.md)。

## 布局方案

- 页面按“标题 → 查询条件 → 核心指标 → 趋势图表 → 使用频率排行 → 关键操作日志”纵向组织。
- 统计页使用完整可用宽度，解除应用外层 `1180px` 的居中宽度限制。桌面两侧保留 `16–28px`，手机两侧保留 `12px`，其他页面仍使用原容器规则。
- 查询条件独立成组，时间范围、起止日期和登录账号都有可见标签。窄屏纵向排列，查询按钮占满一行；筛选值修改不会自动发起查询。
- 指标在宽屏显示 7 列，中等屏幕显示 4 列，手机显示 2 列。数字使用等宽数字排版，极长数值允许换行，不缩略或改变数值。
- 图表在宽屏采用三列栅格，每日趋势占两列；月份、设备、充值各占一列。`1100px` 以下切换为两列，`680px` 以下切换为单列。
- 排行和操作日志分别占满一行，不再让两个宽表格争用横向空间。数值列右对齐，表头、正文、说明文字分层；超长名称、账号及所在地保留全文，通过溢出提示查看。
- 表格自身支持横向滚动，手机上提示“左右滑动表格可查看完整字段”。排行最高 `440px`，日志最高 `560px`，多行记录在表格内纵向滚动，分页仍在表格下方。
- 空数组显示明确的空状态；充值数据源未启用时保留原提醒，不用模拟值补齐。图表配色读取现有主题变量，切换深浅主题时更新画布，不重新请求数据。
- 手机上的自定义日期弹层使用纵向双月面板，可在弹层内滚动。样式只作用于统计页专属弹层类，不影响其他页面日期组件。
- 统计页在 `1100px` 以下将品牌/账号和六个管理员导航入口分成两行，避免窄屏互相覆盖；手机导航显示图标和文字。通过路由专属类隔离，不改变其他页面导航布局。

## 核心实现

应用容器按路由选择宽度，而不是取消所有页面的宽度限制：

```ts
const isAnalytics = computed(() => route.name === 'admin-analytics');
```

```vue
<main class="app-main" :class="{ 'app-main--analytics': isAnalytics }">
  <RouterView />
</main>
```

```css
.app-main--analytics { width: 100%; max-width: none; padding: 0; }
.admin-analytics { padding: 24px clamp(16px, 1.5vw, 28px) 48px; }
.data-grid { display: grid; grid-template-columns: minmax(0, 1fr); }
.charts-grid { display: grid; grid-template-columns: repeat(3, minmax(0, 1fr)); }
.chart-wide { grid-column: span 2; }
@media (max-width: 1100px) {
  .charts-grid { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}
@media (max-width: 680px) {
  .admin-analytics { padding-inline: 12px; }
  .charts-grid { grid-template-columns: minmax(0, 1fr); }
  .chart-wide { grid-column: auto; }
}
```

表格以展示约束限制高度，服务端分页参数和记录数不变：

```vue
<ElTable :data="operationPage?.records ?? []" :max-height="560"
  stripe empty-text="所选范围内没有关键操作日志。">
  <ElTableColumn label="账号 ID" min-width="280" show-overflow-tooltip>
    <template #default="scope"><code>{{ scope.row.userId }}</code></template>
  </ElTableColumn>
</ElTable>
```

以上为关键片段；完整代码保留原有所有字段、加载状态、查询和分页处理函数。

## 接口与样式契约

| 接口 | 请求与响应 |
| --- | --- |
| `GET /api/v1/admin/analytics/dashboard` | `range`、可选 `fromDate`/`toDate`/`userId` 不变；继续使用 `AnalyticsDashboard` |
| `GET /api/v1/admin/analytics/usage-ranking` | `period`、`date`、`limit=20`、可选 `userId` 不变；继续使用 `AnalyticsRanking` |
| `GET /api/v1/admin/analytics/operations` | `fromDate`、`toDate`、`current`、`size`、可选 `userId`/`eventType` 不变；继续使用 `AnalyticsOperationLogPage` |

- 每页默认 `10` 条，可选 `10`、`20`、`50`；修改每页条数回到第 1 页。
- 日期范围仍由后台响应的 `period` 决定日志查询边界；本次不改变时区或日期计算。
- 新增局部 CSS 变量 `--analytics-gap`：桌面默认 `16px`，`680px` 以下为 `12px`，不作为外部可配置参数。
- `analytics-date-range-popper` 是统计页日期弹层的隔离标记，不是全局控件类。
- `topbar--analytics` 只传给统计页顶部导航作为样式标记，未增加组件属性或修改导航路由。
- 图表配色复用 `--accent`、`--success`、`--warning`、`--pink`、`--text-secondary`、`--glass-border` 等现有变量。响应式宽度、主题切换不修改数据序列或发起统计请求。

| 场景 | 检查点 |
| --- | --- |
| 正常展示 | 7 项指标、5 张图表、排行和日志均可见，排行及日志分行满宽 |
| 多屏宽 | `1920/1440/1024/768/390/320px` 下页面不横向溢出，边距受控，图表画布随容器缩放；顶部品牌、导航、账号不互相覆盖 |
