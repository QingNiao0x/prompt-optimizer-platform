## 后续清理步骤及复核

1. **先固定范围。** 记录工作树状态及文件集。目录遍历包括被忽略项目，读取每份原始字节计算哈希，再分配主要类别。
2. **筛选低价值候选。** 分别检查本机可再生缓存、同一执行产生的重复格式、孤立临时文件。对疑似重复的原件标出对应事件、来源、阶段及替代路径。
3. **先查消费者。** 检查 Markdown 相对链接、代码及归档脚本、运行期拼接路径、冻结清单和压缩清单。保留有独立来源身份、引用不确定或仅有单份的材料。目录规模、文件年龄和失败状态不单独决定删除。
4. **按文件删除。** 在确认路径、内容哈希和保留副本后删除列出的文件。记录原始字节数与处置。已跟踪文件可从清理提交的父版本恢复；忽略的 Python 缓存可重建。
5. **复核完成条件。** 本次对清理前后文件集做了集合比对，逐一重算 22,132 份保留文件的 SHA-256、核对大小，确认清单中 19 个删除路径均不存在。ZIP 内 TSV 经过解压字节校验。本轮未重跑历史模型调用或各批次的完整业务验收。

下次优先从 844 项待复核中选择实际占用较大且有明确归档负责人的批次，按上述步骤评估。若目标是大幅减少仓库体积，需要另外设计可恢复的归档及引用迁移，并验证从归档能重放相应批次。仅删除活动工作树文件不会释放旧 Git 对象。
