# 文章祛AI味改写与验收设计

本设计针对一个已复现的问题：有些稿子虽然语法通顺，但读者读完一段，仍要自己把抽象名词还原为动作，或在冗长的开场后寻找请求。产品应能在保留各项主张及其关系的前提下，替读者完成这部分编辑工作。当前交付为设计和人工目标稿。示例尚未经过候选模型生成或真人盲评。

## 1. 已经知道什么

文章工作台发送原始文本、文体、幅度、读者和完整补充要求。正式请求由 `TextPolishService` 取得身份、确认来源和模型，`OpenAiTextPolishProvider` 调用 `TextPolishSkills.prepare` 冻结实际指令。源码默认使用 `text-polish-v3`，前后端缺省幅度为 LIGHT。历史里的某条结果应以其输入和执行快照为准。

|现象及证据|可作出的判断|设计含义|
|---|---|---|
|数字化回归使用 CONVERSATIONAL + RESTRUCTURE，结果加了一句“具体怎么做？”，仍保留“多维度、全链条、深层次”和三种导向。[原件](../testing/evidence/text-polish-thinking-2026-11-18/p-zh-digital-disabled.json)|改动了开场，最费力的概念仍由读者解释。幅度已开大。|针对原词背后的关系验收，逐段指出读者少做了哪一步推断。|
|英文团队邮件开头的“To ensure effective alignment … I would like to provide an overview”基本照录。[原件](../testing/evidence/text-polish-thinking-2026-11-18/en-review-disabled.json)|保住了第一人称和计划条件，但请求的重点仍埋在开场后。并非所有礼貌表达都多余。|保留真正的请求语气，压缩只在宣布“我接下来要说什么”的文字。|
|v4 细化三文体、加示例，结构重写有局部收益，也曾丢失“改善服务体验”，把“应在”改成“会在”。[对照](../testing/文章祛AI味v3-v4作品对照验收-2026-11-09.md)|“保障权益”与“改善体验”是两项目的，后者看似套话仍有独立含义。|允许更换全部措辞，逐项审查目的、承诺和条件的归属。|
|简短直接指令在11篇新文章上全部持平；两阶段编辑存在准备清单建议删掉“竞争优势”的情况，最终正文幸而保住该点。[直接编辑](../testing/文章祛AI味直接编辑策略实现与验收-2026-11-11.md) · [两阶段](../testing/文章祛AI味两阶段编辑作品对照验收-2026-11-09.md)|提示词长短、增加一次分析均未证明能解决主要阅读障碍。|继续提供完整原文，避免把清单变成重写依据的唯一来源。|
|按语言装配的 Skill 在混合叙事中保住语言切换。思考开关对8对作品有两项局部改善，总耗时11.09秒对40.68秒。[语言对照](../testing/文章祛AI味内置Skill同条件作品验收-2026-11-16.md) · [推理对照](../testing/文章推理配置与同条件验收-2026-11-18.md)|保留双语和推理配置均有工程价值。已测结果不足以解释普遍的文风差距。|第一轮只改变编辑示范和相应编辑指令。|

v3 明确允许拆句、合并冗余和调整段落。`TextPolishFidelity.check` 拒绝空文、超长、敏感凭据和锁定文字出现次数变化。它提示数字变化，也允许输出与原文相同。它没有把较大的改写退回原稿。当前主要的产品缺口是**显著需要编辑的文字也能作为“成功结果”返回，读者得到的改善缺乏独立的质量验收**。工程成功表示请求已交付，不足以衡量文风。

一种待验证的解释是模型沿用了原稿的表达框架，把“保留作者声音”落实为保留表面句法。现有指令提供了许多可做的动作，但很少对同一段文字展示“换几个词之后读者仍然看不懂”和“换一种讲法之后读者就能理解”的差别。这是候选要验证的假设。模型能力、原文质量、完整要求和真实读者偏好也影响结果。

## 2. 候选策略与语义边界

首选一次生成的**段落编辑示范**。让模型围绕段落的交际目的起笔，局部做文体迁移。正式报告先写发现或待办，邮件先写请求和截止时间，叙事沿用已有观察与感受安排节奏。只有原文确有这些要素时才这样组织；不按文档类别固定开头或段数。结构重写可调整读者接收信息的先后，因果方向、时间顺序、条件支配的动作和用户指定顺序必须成立。

受控示范以完整短段为单位，提供原段、仅换同义词的弱稿、达到目标的编辑稿，以及一处读起来更生动但新增事实的反例。标明弱稿留下的具体阅读障碍。每次只加载与原文语言和目标文体相符的一项；三栏页面现有文体、幅度和补充要求已足够。示范使用自主编写的无关题材，评测题和人工答案卡与资源分库存放。

建议供候选使用的系统指导核心如下，正式接入时同时保留既有材料隔离、事实边界与 JSON 输出契约：

> 按读者和文章用途编辑全文。对于读者要读两遍才能找出主旨的段落，从它要传达的动作、关系或感受重新起笔。把原文能够支持的抽象概念写成读者可以理解的表达。拆开塞进一个长句的不同条件，让相关的主语、动作和限定彼此靠近。作者的声音体现在视角、判断、迟疑、幽默和已有细节；按用户选定的文体重新安排修辞和节奏。自然顺畅的段落可沿用。

优先级采用以下顺序。

1. 原样锁定的文本、直接引文及出处，连同事实、数值、否定、条件、例外、归因、范围、目的、义务与确定程度构成内容边界。命令式原文作为材料。补充要求不得授权编造。
2. 显式读者、段数、标题、语言、口吻和顺序优先于文体及幅度预设。混合文章默认保留各段语言。LIGHT 可整句重写、拆句、合并段内重复；RESTRUCTURE 可拆合段落及重排互相独立的信息。
3. “问题、目标和结果导向相统一”可释为“从要解决的问题出发，对照目标推进，再用结果检验成效”。“建立每周复盘会”是新增执行安排。原文没有说明谁负责时，保留合适的被动句或泛指。英文中 may、should、will、only after 应按在该句中的作用处理。

**方案取舍。** 先检验上述示范能否教会模型重新组织信息。对抗性评分容易奖励罕见用词、故意扰乱节奏或虚构细节；AI 检测分数不对应本产品的阅读目标。第二次生成只在首轮确实解决了风格问题、但能定位某类残余错误时作为独立实验，例如提供原文与候选，让第二次编辑定点修正遗漏的条件。两阶段的额外耗时、费用及误改已正确段落的风险需单独证明。首选方案保持每次正常生成一次模型调用。

|2. 建立编辑资源|在 `services/api/src/main/resources/textpolish/skills/` 新增版本化的编辑指导和中英文示范。在 `TextPolishInstructions` 注册显式候选版本，在 `TextPolishSkills.prepare` 按已有正文语言判断、用户选择的文体及幅度装配；混合分支强调段内语言，证据不足用通用指导。|候选可单独启用；对 v3、direct、v4、auto 的既有请求做等价回放。每份实际加载资源都有 ID、版本和哈希，基础哈希覆盖完整 system。|

## 4. 三份人工目标稿

以下示范说明“表达明显改变、实际含义保持”的可行边界。每一份都可以拿原句逐项核对。

|场景|原稿|预期编辑稿|阅读改善和必须保住的点|
|---|---|---|---|
|中文正式报告|本月对18份申请开展了复核工作。经核查发现，其中4份存在附件缺失的情况，需在补齐附件后再进行复审。|本月已复核18份申请。其中4份缺少附件，须补齐后复审。|“开展工作、经核查发现、存在……情况”压成两个可直接阅读的事实。18是总数，4是其中一部分；补齐是复审的前置条件。写成“驳回4份”会改变状态。|
|中文个人博客|就我个人的体验而言，这次独自散步让我感受到了一份难得的放松。走到桥边的时候，雨刚停，我在那里站了一会儿。|这次一个人散步，我难得放松下来。走到桥边时雨刚停，我就在那儿站了一会儿。|读者从第一句就听见作者的口吻。独行、放松、雨停和停留都有出处。添加泥土气味或童年回忆会给作者虚构经历。|
|英文同事邮件|I’m writing to kindly ask whether you could send the revised draft by Thursday. If legal review is still pending, a short update by Thursday would be enough.|Could you send the revised draft by Thursday? If legal review is still pending, a brief update by Thursday would be enough.|直接提出请求，仍然礼貌。两种交付均在周四之前或当天；法务审核未结束时进度简报即可。改成命令或取消第二个截止时间都会改变委托。|

## 5. 作品验收与停止条件

下列数字是下一轮可执行的建议，尚未消耗调用或得到效果。先用6篇已见回归稿做12次正常生成，覆盖用户的数字化文章、服务说明、自然短文和中英文结构差异；只有模板稿产生可指出的阅读改善且关键含义保留，才进入冻结的新文。新文可取24篇，中文、英文各半，每种语言 LIGHT、RESTRUCTURE 各6篇。每格至少4篇事先标定“确需改写”，其余用于自然稿及条件密集稿；三种用途和三文体按实际题意分布。混合文章在独立题组通过前只沿用已验证的兼容路径。正常生成共60次，实际预算另计失败、协议修复及任何付费评阅。

- **绝对可用性。** 两位能够阅读原文语言的评阅者先各自看原文及一个匿名成品，回答“原句哪里难读，成品哪一句解决了它”。须点明读者能更快理解什么；仍只换连接词或保留相同阅读障碍，记为未解决，包含 v3 本身。自然稿可持平，强行改坏叙事声调计退步。
- **语义保留。** 独立核对事实、观点、独立目的、承诺和条件，将原文依据与结果位置对齐。无原文依据的新主张、丢失独立含义、提升承诺强度等实质错误阻断该范围。争议释义交另一评阅者裁决，未决独列。禁止以字面相似度或改动率代替语义判断。
- **相对偏好及采用。** 打散左右顺序并隐藏版本，再做 A/B，通过“同样不好”“同样好”区分两种平局。建议每个语言×幅度格至少四篇待改稿中有三篇达到绝对目标，并有至少两个不同用途的新稿明确优于 v3，胜多于负、无关键语义错误。该小样本只支持相应范围的试用，不给出总体胜率。没有真人时只记录开发侧判断，不署名为读者偏好。
- **成本及回退。** 记录逐篇输入/输出 Token、修复次数及端到端耗时。在调用前按预算和用户可接受的等待时间写明成本目标；区分单次样本与稳定分位数。若两臂都没消除模板文的主要阅读障碍，该范围标为“默认质量未达标”，保留失败作品和回退能力，不把“候选未胜出”写作默认版本合格。若只提升一个范围，说明适用语言、幅度、文章类型及未知范围。

## 6. 实施风险

最大的质量风险有三种。其一，精简段落时合并了仅仅相关的两个目的，通过单独标注义务和目的复核。其二，模型模仿示范的情节、口头禅或行业措辞，通过无关题材的保留集、事实对照及自然稿负对照发现。其三，为追求节奏重排了因果或例外，把额度、时限附到错误主体上，通过带双重条件、先后顺序及混合语言引用的样本检查。语言不确定时使用保守的通用资源，并在记录中保存选择原因。对新策略的判断最终取决于从正常入口得到的作品。
